# 문제 해결

자주 막히는 자리를 증상별로 원인과 해결과 함께 모았습니다.
wirebound 서버를 운영하거나 쓰는 사람 누구나 대상입니다. 명령은 Docker 배포를 전제로 저장소 뿌리에서 실행합니다.

## 로그인이 «이메일 또는 비밀번호가 올바르지 않습니다» 로 실패한다

비밀번호가 틀렸을 때와 계정이 없을 때 같은 문장이 나옵니다.

- **계정이 아직 없습니다.** 시딩 계정은 `SEED_USER_EMAIL` 과 `SEED_USER_PASSWORD` 가 있을 때만 만들어집니다.
  `migrate` 서비스의 출력을 보세요:

  ```bash
  docker compose logs migrate
  ```

  «계정 시딩 건너뜀» 이 있으면 `.env` 에 두 값을 적고 `docker compose up -d` 를 다시 실행하세요. 이미 있는 계정은 바뀌지 않습니다.
- **비밀번호가 틀렸습니다.** [비밀번호를 잊었다](#비밀번호를-잊었다)를 보세요.

## 로그인은 되는데 에디터가 다시 로그인 화면을 보인다

다른 기계에서 맨 HTTP 로 열었습니다. 세션 쿠키가 `Secure` 라서 브라우저가 버립니다.
HTTPS 리버스 프록시를 거쳐 열거나, 서버 자신에서 `http://localhost:8080` 으로 여세요. [Docker 로 배포하기](how-to/deploy-with-docker.md)를 보세요.

## «로그인 시도가 너무 많습니다 — N분 뒤 다시 시도하세요»

15분 안에 한 이메일이 10번, 한 주소가 30번 넘게 시도하면 옳은 비밀번호도 막힙니다.

- 문장의 시간만큼 기다리거나 막힘을 푸세요:

  ```bash
  docker compose exec api node --import tsx src/auth/unlock-login.ts <EMAIL>
  ```

  그래도 같은 문장이면 클라이언트 주소가 막힌 것입니다. 같은 명령에 `--address <IP>` 를 붙이세요.
- 모두가 이 문장을 본다면 서버가 클라이언트를 가르지 못하는 것입니다.
  리버스 프록시의 주소를 `.env` 의 `TRUSTED_PROXIES` 에 적고 `docker compose up -d` 를 실행하세요.

## 비밀번호를 잊었다

스스로 되찾는 길은 없습니다. 아래 가운데 하나를 쓰세요:

- **인스턴스 관리자가 재설정 링크를 만듭니다.** **사용자** 에서 그 사람 줄의 **…** 메뉴를 열고 **재설정 링크 만들기** 를 고른 뒤 링크를 보내세요. 24시간 동안 한 번 쓸 수 있습니다.
- **서버에 손이 닿는 사람이 바꿉니다.** 명령이 새 비밀번호를 화면에 안 보이게 두 번 묻습니다:

  ```bash
  docker compose exec api node --import tsx src/db/reset-password.ts <EMAIL>
  ```

  명령은 그 사람의 세션을 전부 끝냅니다. `wireb login` 으로 만든 API 토큰은 남깁니다.
  옛 비밀번호가 샜다면 토큰도 거두세요: 로그인해 **계정** 을 열고 **API 토큰** 절에서 **전부 폐기** 를 누릅니다.

## PPTX 에 화면 이미지가 없는 슬라이드가 있다

슬라이드에 «화면 이미지가 실리지 않았습니다» 가 보입니다. 내보내기 자체는 성공합니다.
까닭은 에디터의 **프로젝트 내보내기** 에서 PPTX 를 고르면 보입니다. 미리보기가 실패한 페이지와 까닭을 늘어놓습니다.

| 미리보기의 까닭 | 해결 |
| --- | --- |
| 서버에 한글 글꼴이 없음(«한글 글꼴이 없어») | Docker 이미지에는 `fonts-noto-cjk` 가 듭니다. 직접 지은 이미지라면 한글 글꼴을 설치하세요. |
| 브라우저를 못 띄움(«브라우저를 띄우지 못했습니다») | Docker 이미지에는 Chromium 이 듭니다. 직접 세운 환경이라면 `SCREEN_CHROMIUM_PATH` 에 Chromium 실행 파일을 적으세요. |
| 페이지가 너무 큼(«페이지가 너무 커») | 그리드 200행 남짓보다 긴 페이지는 일부러 건너뜁니다. 페이지를 나누세요. |

`wireb export --format pptx` 는 빠진 이미지 수를 경고로 찍고 종료 코드 0 으로 끝납니다.

## 캔버스로 끈 컴포넌트가 안 놓인다

주소 끝에 `?debugDrag=1` 을 붙여 에디터를 다시 열고, 컴포넌트를 한 번 끈 뒤 브라우저 콘솔의 `[wb-drag]` 줄을 전부 복사해 이슈에 붙이세요.
그 줄이 어느 단계에서 멈췄는지 보여 줍니다. 읽는 법은 개발 안내 [`docs/guides/drag-debug.md`](../../guides/drag-debug.md)에 있습니다.

## `wireb` 가 종료 코드 2 로 끝난다

저장소가 연결되지 않았거나 토큰이 없습니다. 저장소 뿌리에서 `wireb init` 을, 그다음 `wireb login` 을 실행하세요.
`.wirebound.json` 의 서버 주소를 바꿨다면 `wireb login` 을 다시 하세요. 토큰은 주소에 매입니다.

## MCP 도구가 «[wireb 코드 2] .wirebound.json을 찾을 수 없습니다» 로 답한다

MCP 서버가 연결한 저장소 밖에서 떠서 `.wirebound.json` 을 못 찾았습니다.
저장소 뿌리에서 서버를 등록하거나, MCP 호스트 설정에서 작업 디렉터리를 정하세요.
