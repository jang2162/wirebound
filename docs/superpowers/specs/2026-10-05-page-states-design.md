# 페이지 화면 상태 — 설계

같은 페이지가 상황(권한 · 로그인 여부 · 데이터 유무 등)에 따라 다른 화면을 보일 때, 기본 페이지에서 영역을 골라 상태마다 다르게 그리고, 나머지는 기본을 따라가게 한다.

이 문서는 발행 시점의 기록(spec)이다. 구현이 병합되면 정본 설계서(`docs/superpowers/specs/2026-08-03-wirebound-design.md`)의 「페이지 스키마 노드」 · 「컴포넌트 카탈로그」 · 「상호작용」 · 「설계서 화면 구조」 · 「HTML 정적 번들」 · 「MCP 도구」와 `apps/api/README.md` 가 지금 참인 것을 갖는다.

---

## 목적과 범위

**목적:** 설계서를 읽는 사람(개발자 · 기획자)에게 «이 페이지는 이런 상황에서 이렇게 갈린다»를 보여 준다. 예: 관리자에게만 보이는 승인 단추 · 비로그인 때의 안내 영역 · 빈 목록 화면. 실제 권한 판정 로직을 실행하는 기능이 아니다.

**사용자가 고른 것**

- 고른 영역만 상태마다 다르고 나머지는 기본을 따라간다(통째 복사 · 노드 보임 조건이 아님).
- 읽는 사람은 상태 전환기로 고르고, 내보낸 설계서에 모든 상태가 든다.
- 상태는 한 축(페이지마다 상태 목록 하나)이다. 조합이 필요하면 그 조합을 상태 하나로 만든다.
- 저장 방식은 «문서 안의 상태 영역 노드»(A)다. 별도 덮어쓰기 표 · 패치 목록이 아니다.

**이름:** «변형(variant)»은 테마의 컴포넌트 모양을 뜻하므로 이 기능은 **화면 상태**(줄여 «상태»)라 부른다.

**범위 밖:** 여러 축의 상태 조합 · 상태별로 다른 상호작용 실행 규칙 · 상태 조건 표현식(«role == admin»처럼 실행 가능한 식) · 상태를 프로젝트 전체에서 공유하는 목록.

## 데이터 모델

### 상태 목록

- 페이지 문서(`PageDocument`)에 선택 필드 `viewStates: { id: string, name: string }[]` 를 둔다. 루트 노드가 아니라 문서에 두는 까닭은 둘이다. 카탈로그의 `states`(컴포넌트의 불리언 상태 — `define.ts`)와 이름이 겹치지 않게 하려는 것, 그리고 상태 목록 편집이 루트 노드 잠금(페이지 안의 어떤 잠금과도 조상 관계)에 막히지 않게 하려는 것이다.
  - 이름은 앞뒤 공백을 걷은 1 ~ 30자다. 받지 않는 글자는 별칭과 같은 집합(`packages/schema` 의 별칭 글자 판정)으로 정한다. 한 페이지 안에서 이름이 겹치지 않는다.
  - 상태는 많아야 20개다.
  - id 는 노드 id 와 같은 규칙으로 화면이 짓는다. 이름을 바꿔도 id 는 그대로다.
- «기본»은 목록에 없고 늘 있다. 목록이 비거나 없으면 지금 페이지와 같다. 옛 문서는 그대로 읽히고 마이그레이션은 없다.
- 봉투 검증(서버 저장 경계 · 가져오기 · 클립보드 · 프리셋 · MCP)이 같은 검증기를 쓴다.

### 상태 영역 노드

카탈로그 구조 갈래에 둘을 더한다.

| 타입 | 이름 | 자식 | 필드 |
|---|---|---|---|
| `StateSwitch` | 상태 영역 | `StateCase` 만 | 없음 |
| `StateCase` | 상태 가지 | 평범한 노드 | `props.state`: `"default"` 또는 상태 id |

- **검증(스키마)**
  - `default` 가지는 정확히 하나여야 하고, 한 상태에 가지는 많아야 하나다. 어기면 오류다.
  - `StateCase` 는 `StateSwitch` 의 자식으로만 선다.
  - 페이지 목록에 없는 상태를 가리키는 가지는 경고(lint)이고, 그 가지는 그려지지 않는다.
- **그리기:** 렌더러가 직접 다루는 투명 노드다. 테마 뷰가 없으며, 테마 manifest · 시스템 테마는 바꾸지 않는다.
  - `StateSwitch` 는 지금 상태의 가지 하나를 그린다. 그 상태의 가지가 없으면 `default` 를 그린다.
  - `StateCase` 는 자식만 그린다.
- 상태 영역 안의 상태 영역은 허용한다. lint 정보로만 알린다.
- 요약(트리 줄): `StateSwitch` 는 «가지 N», `StateCase` 는 그 상태의 이름(기본이면 «기본»)이다.

### 상호작용 · 별칭

- 어떤 상태의 가지 안 노드는 그 상태에서만 있다. 상호작용 문장 · 대상 고르개 · 내보낸 목록은 그 노드 이름에 상태를 붙인다: «'승인 버튼'(관리자 상태)».
- 이름을 짓는 함수(`nodeDisplayName` 계열)가 노드의 «속한 상태»를 받아 붙인다. 상태 영역 밖이면 붙이지 않는다.

### 상태 삭제

- 상태를 지우면 그 상태를 가리키는 가지를 모두 함께 지운다. 확인 상자에서 «가지 N개의 내용이 함께 삭제됩니다»라고 알린다.
- 그 삭제는 편집 하나(JSON Patch 묶음)라 개인 되돌리기 한 번에 돌아온다.

## 편집 화면

### 상태 전환기

- 에디터 머리의 페이지 이름 옆에 `[기본 ▾]` 를 둔다. 항목은 상태 목록 · «상태 추가» · «상태 관리…».
- 지금 고른 상태는 사람 · 탭마다 다르다. 서버에 안 가고 남의 화면을 바꾸지 않는다. 페이지를 옮기면 기본으로 돌아간다.
- «상태 관리…» 대화 상자에서 추가 · 이름 바꾸기 · 순서 바꾸기 · 삭제를 한다(삭제는 위 확인).

### 영역 나누기 · 풀기

- **나누기:** 구조 트리 줄 `…` · 캔버스 선택 · Cmd+K 의 «상태별로 나누기».
  - 고른 노드를 `StateSwitch > StateCase(default)` 로 감싼다.
  - 지금 상태가 기본이 아니면 그 상태의 가지도 기본 가지의 복사로 함께 만든다.
  - 여러 노드를 골랐으면 같은 부모의 이어진 형제일 때만 한 영역으로 감싼다. 아니면 그 항목을 끄고 이유를 툴팁 · 접근 설명으로 단다.
- **풀기:** «상태 나누기 풀기»는 기본 가지만 남기고 벗긴다. 다른 가지는 지워지므로 확인을 받는다.
- 나누기 · 풀기는 각각 편집 하나다.

### 상태를 고른 채 편집

- 캔버스 · 구조 트리는 지금 상태의 화면을 보인다. 상태 영역 안에서는 그 상태의 가지만 보인다.
- 지금 상태의 가지가 없는 영역은 기본 가지를 흐리게 보인다.
  - 그 영역을 처음 고치면 그 상태의 가지를 기본 가지의 복사로 만들고 그 위에 편집한다. 기본 가지는 안 건드려 다른 상태는 그대로다.
  - «복사 + 편집»은 편집 하나라 되돌리기 한 번에 돌아온다.
  - 복사는 노드 id 를 새로 짓는다(붙여넣기의 id 다시 짓기 규칙).
- 영역 밖을 고치면 모든 상태에 반영된다(노드가 하나뿐이므로).
- 캔버스는 상태 영역에 얇은 테두리와 꼬리표(«관리자 · 기본에서 다름» / «기본과 같음»)를 단다. 배치 선처럼 셸 겹에 그리고 문서에는 아무것도 넣지 않는다.
- 구조 트리
  - `상태 영역` 줄 아래에는 지금 상태의 가지만 펼친다.
  - «모든 가지 보기»를 켜면 전부 펼친다.
  - 가지 줄 `…` 에 «이 상태 가지 지우기(기본으로 돌아감)»를 둔다.
- 잠금 · 실시간 · 되돌리기 · 붙여넣기 · 별칭은 지금 노드 규칙 그대로다. 가지는 노드이므로 남이 다른 상태를 보고 있어도 같은 잠금 판정을 받는다.

## 읽기 · 내보내기 · LLM

### 뷰 모드 · viewer

- 같은 상태 전환기로 고르고 그 상태의 화면을 그린다.
- 상태 영역에 작은 «상태에 따라 다름» 표지를 단다. 누르면 그 영역의 가지 목록이 나오고, 거기서 상태를 바꾼다.
- 주소에 `?state=<id>` 를 실어 상태 화면을 링크로 나눈다. 없는 id 면 기본이다.

### HTML 정적 번들

- 상태가 있는 페이지는 전환기와 상태마다의 화면을 담는다. 상태가 없는 페이지는 지금 모양 그대로다.
- 상호작용 목록은 상태를 붙인 문장이다.

### MCP · CLI · lint

- 트리 읽기는 `viewStates` 와 상태 영역을 그대로 보이고, 가지마다 상태 이름을 붙인다.
- 쓰기는 지금의 노드 편집(JSON Patch)으로 한다. 상태 전용 쓰기 도구는 더하지 않는다. MCP 스킬 문서에 꼴(StateSwitch · StateCase 규칙)을 적는다.
- lint
  - 목록에 없는 상태를 가리키는 가지 — 경고
  - 쓰이지 않는 상태 — 정보
  - 상태 영역 안의 상태 영역 — 정보

### 페이지 JSON · 프리셋 · 붙여넣기

- 상태 목록과 가지가 노드와 함께 간다.
- 다른 페이지에 붙일 때 그 페이지에 없는 상태를 가리키는 가지는 빼고 통지한다(지금 상호작용 «밖 대상» 규칙과 같은 꼴: «상태 "관리자" 가지 1개를 뺐습니다»).
- 프리셋 · 가져오기로 새 페이지를 만들면 원본의 `viewStates` 를 함께 싣는다.

## 테스트

- **schema:** 상태 목록 검증(30자 · 겹침 · 21개 · 받지 않는 글자) · 상태 영역 규칙 · 상태 삭제가 가지를 함께 지움 · 나누기 · 풀기 연산 · 붙여넣기 규칙 · 이름 짓기의 상태 붙이기.
- **renderer:** 상태마다 가지 · 기본으로 대체 · 상태 영역 안의 상태 영역 · 목록에 없는 상태의 가지를 안 그림.
- **api:** 저장 경계에서 `viewStates` · 상태 영역 검증(비튼 값 → 400 · 500 없음) · WS 편집 · 연쇄 삭제 · 스냅샷 복원이 상태를 싣는지.
- **실브라우저**
  - 상태 전환 · 상태를 고른 채 편집(복사 + 편집의 되돌리기 한 번) · 영역 밖 편집이 모든 상태에 반영
  - 두 사람이 다른 상태를 보며 같은 영역을 편집(잠금)
  - 상태 삭제 확인 · 뷰 모드 · `?state=` · 내보낸 번들의 전환기

## 진행 단계

| 트랙 | 무엇 | 리뷰 |
|---|---|---|
| K1 | schema(모델 · 검증 · 연산 · 이름 짓기) + renderer + api 저장 경계 | 리뷰어 |
| K2 | 에디터(전환기 · 상태 관리 · 나누기 / 풀기 · 상태별 편집 · 캔버스 표지 · 트리) | 리뷰어 |
| K3 | 뷰 모드 · 내보내기 · MCP / lint / 스킬 문서 · 붙여넣기 통지 | 스크린숏 |

K1 이 먼저 병합되고 K2 · K3 는 그 위에서 나란히 돈다. 지금 도는 J1 ~ J3 와 머리 · 트리 · 캔버스가 겹치므로 K 는 J 병합 뒤에 시작한다.
