# 공통코드 설계

## 목적

프로젝트마다 자주 쓰는 상태 코드 · 데이터 셋(«주문 상태», «회원 등급» …)을 **표로 한 곳에서 관리하고, 화면의 노드를 그 표에 참조로 묶는다.**

까닭은 하나다 — **코드가 바뀔 때 영향을 받는 화면이 어디인지, 어디를 고쳐야 하는지 파악하기 위해서다.** 지금은 같은 코드가 노드마다 글로 흩어져 있다(예제 주문 화면에서 «결제 대기»가 검색폼 `Select` 의 `options` 와 그리드 «상태» 칸의 `Affix.text` 에 따로 적혀 있다). 그래서 «이 코드를 쓰는 곳»을 찾을 길이 없다.

## 목표

- 프로젝트 단위의 코드 표(그룹 → 항목)를 만들고 고친다.
- 선택 위젯(`Select` · `CheckboxGroup` · `RadioGroup`)은 그룹을 가리켜 선택지를 표에서 받는다.
- **코드 이름이 화면에 찍히는 모든 컴포넌트**가 항목 하나를 가리켜 그 이름을 대표 글로 그린다 — 선택 위젯만이 아니다.
- 그룹 · 항목마다 **그것을 쓰는 페이지 · 노드 목록**을 보고, 눌러 그 자리로 간다.
- 표의 이름이 바뀌면 묶인 화면은 다시 그려질 때 새 이름을 쓴다.

## 하지 않는 것

- **변경 이력** — 코드 표에는 revision · 되돌리기 · «언제 무엇이 바뀌었나» 기록을 두지 않는다. 사용처는 «지금 이 순간»만 보인다. (스냅샷은 표를 담는다 — 아래 「따라가는 것」.)
- **코멘트 토큰 치환** — 코멘트 본문에서 공통코드 · 페이지 · 코멘트 번호를 치환하는 기능은 별도 설계다. 토큰 형식은 공통코드 말고도 여러 토큰을 함께 정해야 해서 미정이다. 이 설계는 그 토큰이 나중에 «그룹 키 · 코드값»으로 항목을 가리킬 수 있게만 둔다.
- **글 속 섞어 쓰기** — «상태: 승인대기»처럼 한 글 칸에 코드 이름과 다른 글을 섞지 않는다. 노드 둘(`Text` + `Affix`)로 나눈다.
- **계층 코드**(대분류 · 중분류), 다국어 이름, 항목의 추가 칸(색 · 톤 등), 그리드 열 단위 일괄 묶음.

## 반-목표 (돌아가도 실패인 것)

- **참조가 조용히 끊기는 것.** 끊긴 참조는 캔버스 · lint · 사용처 화면 어디서든 보여야 한다.
- 목업에 그룹 키 · 코드값 같은 날 식별자가 찍히는 것.
- 캔버스 · HTML 번들 · PPTX · CLI/MCP 의 `page get` 이 서로 다른 이름을 내는 것(어느 한 출력이 표를 안 푸는 것).

## 접근 방식

| 안 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A (고름)** | 노드 봉투에 코드 참조 칸을 둔다(`alias` · `weight` 와 같은 자리). 선택 위젯은 그룹을, 글을 보이는 컴포넌트는 항목을 가리킨다 | 참조가 구조라 사용처를 **빠짐없이** 센다. 검증 · lint 가 단순하다 | 글과 섞어 못 쓴다(노드를 나눈다) |
| B | 어느 글 칸에든 토큰(`{{ORDER_STATUS.WAIT}}`)을 넣는다 | 섞인 글 · 코멘트 토큰과 문법 공유 | 사용처를 찾으려면 모든 글을 해석해야 하고, 글이 나가는 자리(렌더러 · 내보내기 · 요약 · lint · CLI)가 하나라도 해석을 빠뜨리면 토큰이 날글자로 보인다. 선택지 묶음은 결국 구조 참조가 따로 필요하다 |
| C | 화면은 A, 코멘트는 B | 둘 다 | 코멘트 토큰 형식이 아직 미정이라 지금 정할 수 없다 |

**A 를 골랐다.** 목적이 «고칠 곳을 빠짐없이 찾기»이므로 빠뜨릴 길이 없는 구조 참조가 맞다. 코멘트 토큰은 별도 설계로 넘긴다.

## 결정된 것

### 코드 표

- 프로젝트마다 **코드 그룹** 여럿. 그룹은 `key`(예 `ORDER_STATUS`) · `name`(«주문 상태») · 차례를 갖는다.
- 그룹 안에 **코드 항목** 여럿. 항목은 `value`(코드값, 예 `WAIT`) · `name`(화면에 찍히는 이름, 예 «결제 대기») · 차례 · `active`(사용 여부)를 갖는다.
- 그룹은 한 단이다(계층 없음).
- 고치는 사람은 editor 이상, viewer 는 읽기만 한다 — 프로젝트 권한 모델(정본 설계서 「권한 모델」)을 그대로 따른다.

### 참조

- 참조는 DB id 가 아니라 **그룹 키 + 코드값**으로 건다. 모듈 · 붙여넣기 · 페이지 JSON 가져오기로 다른 프로젝트에 옮겨도 같은 키가 있으면 다시 이어지고, 없으면 끊긴 참조가 된다.
- 선택 위젯은 그룹을 가리키고, 선택지를 그 그룹의 항목(차례대로)에서 받는다. 사용 여부가 꺼진 항목은 선택지에서 빠진다.
- 그 밖의 컴포넌트는 항목 하나를 가리키고, 그 이름이 컴포넌트의 **대표 글** 자리에 찍힌다. 대표 글이 어느 prop 인지는 카탈로그 정의가 선언한다.

### 사용처

- 그룹 · 항목을 고르면 그것을 쓰는 페이지 · 노드 목록이 나오고, 누르면 에디터가 그 페이지를 열고 그 노드를 고른다.
- 쓰이는 항목 · 그룹을 지울 때는 영향 목록을 보이고 확인을 받는다.
- 끊긴 참조는 캔버스에 경고 표지로 보이고 lint 가 알린다.

## 제안 (빌더가 따를 기본값 — 메인 세션의 판단)

아래는 대화에서 사용자가 정한 것이 아니라 이 설계가 채운 것이다. 사용자 확인을 받았다는 뜻이 아니다.

### 저장

- 테이블 둘: `code_groups(id, project_id, key, name, sort_order, created_at, updated_at)` UNIQUE `(project_id, key)` · `code_items(id, group_id, value, name, sort_order, active, created_at, updated_at)` UNIQUE `(group_id, value)`. `project_id` · `group_id` 는 CASCADE.
- **`key` · `value` 는 만든 뒤 못 바꾼다.** 바꿀 수 있게 하면 모든 페이지의 참조를 함께 고치는 프로젝트 전역 편집이 되고(페이지마다 revision · 잠금 · 복원과 얽힌다), 이력을 안 두기로 한 결정과도 맞지 않는다. 바꾸려면 새 항목을 만들고 다시 묶는다(사용처 목록이 그 작업 목록이다). `name` · 차례 · `active` 는 자유롭게 고친다.
- 글자 규칙: `key` 는 `^[A-Z][A-Z0-9_]{0,39}$`, `value` 는 1 ~ 40 자에 별칭과 같은 받지 않는 글자 표(`packages/schema/src/alias.ts`), `name` 도 같은 표 · 1 ~ 60 자. 그룹당 항목 상한 200 · 프로젝트당 그룹 상한 500.

### 노드 봉투

- `WbNode` 에 선택 칸 `code?: { group: string; item?: string; selected?: string[] }` 를 더한다.
  - 선택 위젯: `group` 만 · 목업에서 고른 것은 `selected`(코드값 목록 — `Select` · `RadioGroup` 은 0 ~ 1 개). 이름이 바뀌어도 고름이 안 풀리게 값으로 가리킨다.
  - 대표 글 컴포넌트: `group` + `item`.
  - 받지 않는 타입에 `code` 가 있거나 꼴이 타입과 안 맞으면 검증 오류(새 코드 — 예 `invalid-code-ref`).
- 카탈로그 `ComponentDef` 에 선언 하나를 더한다: `code?: { kind: 'choices' } | { kind: 'label'; prop: string }`.
  - `choices`: `Select` · `CheckboxGroup` · `RadioGroup`.
  - `label`: `Button.label` · `Link.label` · `Text.content` · `Chip.label` · `Affix.text` · `Placeholder.label` · `TabPanel.label` · `Input.value`(읽기 전용 값 표시) · `KeyValue` 는 줄이 노드가 아니라 제외. 목록 확정은 빌더가 카탈로그를 훑어 정하되 «코드 이름이 찍힐 만한 대표 글 하나가 있는 타입»이 기준이다.
- **묶을 때 그때의 이름을 prop 에도 적어 둔다**(선택 위젯은 `options`, 대표 글은 그 prop). 그리기는 늘 표를 쓰고, prop 값은 참조가 끊겼을 때의 대체 글이다(경고 표지와 함께 그린다). 그래서 문서는 표 없이도 읽히고, 표를 모르는 옛 소비자도 깨지지 않는다. 이름을 바꿔도 문서들의 prop 을 일괄로 고치지는 않는다 — 끊겼을 때만 보이는 글이라 낡아도 화면에 안 나온다.
- 묶인 동안 속성 패널은 그 prop 칸(선택지 목록 · 대표 글)을 잠그고 «공통코드: 주문 상태 › 결제 대기 · 풀기»를 보인다. 풀면 `code` 를 지우고 prop 의 글은 남긴다.
- 문서 마이그레이션은 필요 없다(선택 칸 추가 · 옛 문서는 그대로 읽힌다). 스키마 버전을 올릴지는 빌더가 정본 「스키마 마이그레이션」 규칙에 맞춰 정한다.

### 묶인 선택 위젯의 선택지 · 고름

- **선택지 수**: 표의 그룹은 200 항목까지지만 선택 위젯의 `options` 는 1 ~ 30(`OPTIONS_MAX`)이다. 묶인 위젯은 사용 중인 항목을 차례대로 **앞 30 개까지** 그린다 — 테마의 칩 · 세그먼트 배치가 그 한도에 맞춰 있어 한도를 올리지 않는다. 넘치면 lint 경고 `code-choices-truncated`. 사용 중인 항목이 0 개면 `Select` 는 placeholder 만, 묶음 위젯은 빈 칸을 그리고 lint 경고 `code-choices-empty`. 묶을 때 거절하지 않는다(지역 · 은행 같은 긴 그룹을 셀렉트에 묶는 것은 흔하다).
- **고름의 정본은 `code.selected`(코드값)다.** 묶인 동안 패널의 선택지 목록은 편집 대신 «표의 항목 중 고르기» 위젯이 된다(하나 고르는 타입은 하나만). 고를 때마다 같은 편집 묶음이 `options` 의 대체 글과 `selected` 도 맞춰 적는다 — 둘이 어긋나면 `code.selected` 가 이긴다.
- 고른 값이 표에 없으면 그 값은 그리기에서 빠지고 lint 가 `broken-code-ref`(경고 — 노드 자체의 그룹 참조는 살아 있으니 오류가 아니다)로 말한다. 사용 안 함 항목을 고른 값은 선택지에서 빠지므로 같은 경고다.
- **풀기**는 그때 표에서 푼 이름(선택지 · 고름 · 대표 글)을 prop 에 다시 적고 `code` 를 지운다 — 한 편집 묶음이다. 그래야 풀었을 때 묶을 때의 옛 이름이 다시 나타나지 않는다. 끊긴 참조를 풀면 prop 의 대체 글이 그대로 남는다.

### 그리기

- 렌더러는 `RenderOptions` 로 풀린 표(그룹 키 → 항목들)를 받는다 — 그림(asset)을 받는 것과 같은 꼴. 풀기는 렌더러 한 곳(`packages/renderer`)에서 하고 캔버스 · HTML 번들 · PPTX(번들 렌더) · 갤러리가 같은 길을 지난다.
- 사용 안 함 항목을 가리키는 대표 글은 그대로 이름을 그린다(lint 가 알린다).
- 요약(`summary`) · 구조 트리 줄 · `nodeDisplayName` 도 풀린 이름을 쓴다 — 표가 없는 자리(표를 못 받은 소비자)는 prop 의 글을 쓴다.

### 실시간

- 코드 표 쓰기는 커밋 뒤 프로젝트의 열린 룸들에 `codes-changed { projectId }` 를 알린다(본문 없음 · 낸 연결 제외 — `comments-changed` 와 같은 꼴). 받은 화면은 표를 다시 읽고 캔버스를 다시 그린다.
- 코드 표는 소프트 잠금 대상이 아니다. 같은 항목을 둘이 고치면 나중 쓰기가 이긴다.

### 사용처 셈

- 서버가 센다: `GET /api/projects/:projectId/codes/usage?group=<key>[&item=<value>]` → `[{ kind: 'page' | 'layout' | 'module', id, title, nodes: [{ nodeId, name }] }]`. 페이지 · 레이아웃의 `schema` 와 프로젝트 모듈의 `nodes` 를 걷는다(개인 모듈은 남의 것이라 제외). 걷는 함수는 `packages/schema` 에 하나 두고 서버 · CLI · MCP · lint 가 함께 쓴다.
- 화면 상태로 숨은 노드도 센다(숨은 상태의 화면도 고칠 곳이다).
- 그룹 목록에는 그룹마다 사용 수를 함께 보인다.

### 화면

- **공통코드 화면**: `/projects/:projectId/codes` — 프로젝트 설정(`/projects/:projectId/settings`)과 같은 셸 밖 라우트다. 입구는 에디터 머리 메뉴의 «프로젝트 설정» 옆 «공통코드»와 프로젝트 카드 메뉴(작업 공간 사이드바에는 프로젝트별 칸이 없다). 왼쪽 그룹 목록(이름 · 키 · 항목 수 · 사용 수), 오른쪽 고른 그룹의 항목 표(차례 · 코드값 · 이름 · 사용 여부 · 사용 수 · 줄 «…»)와 그 아래 **사용처 목록**(페이지 › 노드 이름 — 누르면 에디터로 가 그 노드를 고른다). 주소에 고른 그룹을 싣는다.
- **에디터**: 속성 패널의 묶을 수 있는 타입에 «공통코드로 묶기»(그룹 고르기 → 대표 글이면 항목 고르기). 묶인 노드에 «이 코드를 쓰는 곳 N» 링크(공통코드 화면의 그 항목으로).
- 쓰이는 그룹 · 항목을 지우면 확인 상자에 사용 수와 첫 몇 곳을 보이고 «참조가 끊깁니다»를 말한다.
- 끊긴 참조의 캔버스 표지: 노드 위 경고 표지 + 속성 패널의 «끊긴 공통코드: ORDER_STATUS › WAIT · 다시 묶기 · 풀기».

### 따라가는 것

- **스냅샷**: payload 에 `codes`(그룹 · 항목)를 더하고 payload 판을 올린다. 옛 판(표 없음)의 복원은 표를 건드리지 않는다. 표가 든 판의 복원은 **표를 통째로 그 판으로 덮는다** — 복원은 페이지 · 메뉴까지 프로젝트 전체를 그 시점으로 되돌리는 동작이라 표만 지금 것으로 남으면 되돌린 페이지의 참조가 엇갈린다. 덮기 전 안전망 스냅샷(`restore-safety`)이 지금 표도 담으므로 복원을 되돌리면 표도 돌아온다. 표에 revision 이 없으니 patch 가 아니라 행 교체다. 복원 확인 상자는 «공통코드 표도 그 시점으로 돌아갑니다»를 한 줄 말한다. 잠금 순서에서 표의 자리 · 커밋 뒤 `codes-changed` 는 빌더가 정본 「스냅샷」 의 복원 잠금 차례에 맞춰 넣는다.
- **표 없이 도는 길**: 표를 받을 수 없는 소비자(서버 없이 페이지 JSON 만 읽는 도구가 있다면 그것)는 prop 의 대체 글로 그리고 묶인 노드를 표지한다. `wireb pull` 덤프는 코드 표를 함께 싣는다. 페이지 JSON 가져오기 · 내보내기 형식에는 표를 싣지 않는다(표는 프로젝트의 것이다).
- **모듈 · 클립보드 · 페이지 JSON 가져오기**: `code` 칸을 그대로 나른다(id 리매핑 대상이 아님). 대상 프로젝트에 키가 없으면 끊긴 참조로 들어오고, 붙인 뒤 «끊긴 공통코드 N» 통지를 한 줄 보인다. 모듈 저장이 걷는 칸(`marker` · 보임 등)에는 넣지 않는다.
- **HTML 번들**: 풀린 이름으로 그리고, 목차에 «공통코드» 장 하나(그룹마다 항목 표 + 사용처)를 싣는다.
- **lint**: `broken-code-ref`(오류 — 표에 없는 그룹 · 항목), `inactive-code-ref`(경고 — 사용 안 함 항목을 가리킴). `LintProject` 에 `codes` 를 더한다.
- **MCP · CLI**: 코드 표 읽기(`codes list`) · 사용처(`codes usage <key> [value]`) · 표 쓰기(그룹 · 항목 만들기 · 이름 · 차례 · 사용 여부 고치기 · 지우기). 노드를 묶는 것은 기존 편집 경로(JSON Patch 로 `code` 칸)를 쓴다. `get_page` · `page get` 은 묶인 노드에 풀린 이름을 함께 싣는다. `/llms.txt` · 스킬 문서에 반영.
- **정본 설계서**: 「도메인 모델」(엔티티 · 테이블) · 「페이지 스키마 노드」(`code` 칸) · 「컴포넌트 카탈로그」(묶이는 타입) · 「설계서 화면 구조」(공통코드 화면) · 「스냅샷」 · 「lint 규칙」 · 「MCP 도구」 를 지금 참인 설계로 고친다.

## 빌더에게 맡기는 것

- 대표 글 타입의 최종 목록(위 기준으로).
- 테이블 · API 의 세부 이름, 마이그레이션 번호, 에러 코드 문구.
- 공통코드 화면의 배치 세부 — 에디터 밖 화면(관리자 칸 · 프로젝트 칸)의 기존 꼴(위 줄 · 표 · 줄 «…» · 900px 아래 카드 접힘)을 따른다.
- 단계 나누기(예: 표 + 선택 위젯 → 대표 글 → 사용처 · lint → 내보내기 · MCP).
