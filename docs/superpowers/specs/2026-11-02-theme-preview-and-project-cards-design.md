# 테마 미리보기 두 보기 · 프로젝트 카드 정리 — 설계

날짜: 2026-11-02 · 상태: 사용자 승인 대기

## 왜

사내 공유를 앞두고 에디터 밖 화면을 다듬는다.

- **테마 미리보기가 좁고 단조롭다.** 프로젝트 설정 › 테마의 미리보기는 640px 고정 폭 iframe 에 컴포넌트 표본을 한 줄에 하나씩 쌓는다. 토큰 폼(최대 400px)이 왼쪽을 차지해 미리보기가 좁고, 토큰을 바꿨을 때 «실제 화면에서 어떻게 보이는지» 를 볼 길이 없다.
- **프로젝트 목록에서 들어가는 길이 작다.** 카드의 진입 수단이 이름 글자 링크뿐이고, «설정» 글자 링크가 그와 비슷한 무게로 서 있다. 새 프로젝트 단추는 머리 오른쪽에 떨어져 있다.

## 목표

1. 미리보기를 **두 보기**로 나눈다 — **«컴포넌트»**(지금처럼 컴포넌트마다) · **«예제 페이지»**(여러 장이 서로 이어진 관리자 화면).
2. **토큰 설정을 탭으로 나눠 위로 올리고**, 미리보기는 그 아래에서 내용 칸 폭을 다 쓴다.
3. «컴포넌트» 보기는 **카탈로그 그룹별**로 묶고, 그룹 안에서 **폭에 맞춘 격자**로 늘어놓는다(한 줄에 하나씩이 아니다).
4. 프로젝트 목록: 카드마다 **아이콘 + «열기» 큰 단추**, 설정은 **톱니 아이콘만의 작은 단추**, 격자 **맨 앞에 «프로젝트 추가» 카드**.

## 비목표

- 테마 SDK · 토큰 선언 · 저장 API(`PUT …/theme`)의 계약을 바꾸지 않는다. 토큰 편집기의 동작(초안 · 409 · 422 · 판 옮김 · 읽기 전용)은 그대로다 — 배치만 바뀐다.
- 미리보기에 기기 폭 전환(데스크톱 / 모바일) 을 넣지 않는다.
- 예제 페이지를 사용자가 고치거나 자기 프로젝트 문서로 미리 보는 기능은 없다.
- `wb-theme check` 의 판정 대상에 예제 페이지를 넣지 않는다(이번 범위 밖 — 이월 후보).

## 반목표 (돌아가도 실패인 것)

- 예제 페이지가 **사용자 데이터에 섞인다**(DB 의 프로젝트 · 페이지로 들어간다).
- 미리보기 안의 누름이 **바깥 화면을 움직인다**(설정 페이지를 떠남 · 브라우저 주소가 바뀜).
- 토큰 칸이 미리보기를 밀어내 **한 화면에서 토큰과 미리보기를 함께 못 본다**(창 900px 높이에서 미리보기가 안 보이는 판).
- 같은 미리보기를 쓰는 세 화면(프로젝트 설정 · 관리자 › 테마 · `wb-theme dev`)이 **서로 다른 미리보기**가 된다.

## 제약

- 미리보기는 테마 CSS 를 실은 **iframe** 안에서 그린다(`apps/web/src/settings/theme-preview.tsx` → `CanvasIframe` → `@wirebound/theme-gallery` 의 `ThemeGallery`). 갤러리 안의 틀은 **인라인 스타일로만** 칠한다 — 테마 CSS 와 한 문서다(`packages/theme-gallery/src/gallery.tsx` 머리말).
- `@wirebound/theme-gallery` 를 쓰는 곳 — 웹 `ThemePreview`(프로젝트 설정 · `routes/admin-themes.tsx`), 웹 팔레트 축소판(`apps/web/src/palette/palette-thumbs.tsx` — `GALLERY_SAMPLES` 의 타입마다 첫 표본 · `galleryItemDocument`), kit 의 `client/frame.tsx`(`wb-theme dev`), kit 의 `check.ts`(`wb-theme check`) · `shots.ts`(`wb-theme shots` — 갤러리 칸마다 창 폭 넘침 · 꺾임을 재 종료 코드를 가르는 관문). **`galleryItems` · `galleryItemDocument` 의 뜻과 타입마다 첫 표본은 바꾸지 않는다.**
- 갤러리 칸 표지 `data-wb-gallery-item="<타입>/<variant>/<표본 id>"` 를 세는 케이스가 있다(`apps/web/test/settings/token-editor.test.tsx` · `apps/web/build-test/theme-system-review.test.ts` · `packages/theme-kit/build-test/dev.test.ts`). 표지는 그대로 둔다.
- 예제 페이지 안의 이동 · 팝업은 문서의 상호작용(`navigate` · `openModal` · `closeModal`, 타겟은 `page: …` 꼴 — `packages/schema/src/page-target.ts`)으로 짓고, 렌더러의 알림(`RenderOptions.interaction` 의 `onEvent`)을 미리보기가 받아 장을 바꾼다. 번들처럼 다른 파일로 옮기지(`location.assign`) 않는다 — 미리보기 안의 상태만 바뀐다.
- **팝업은 `PopupLayer`(`packages/renderer/src/popup-layer.tsx`)에 `area` 를 줘 미리보기 상자의 보이는 구간에 세운다** — 미리보기 iframe 은 내용 높이만큼 자라(`apps/web/src/canvas/canvas-iframe.tsx`) 창 전체에 세우면 보이는 곳 밖에 뜬다(캔버스와 같은 꼴).
- **`Link` 기본 뷰는 `<a href="#…">` 다**(`packages/theme-sdk/src/default-views/action.tsx`) — 렌더러는 submit 만 막아 그대로 누르면 iframe 해시가 바뀌고 브라우저 기록이 쌓인다. 미리보기는 그 기본 동작을 막는다(반목표 «바깥 화면을 움직인다»). 케이스는 누른 뒤 `history.length` · 바깥 주소가 그대로인지 잰다.
- **레이아웃과 페이지를 합쳐 그리는 길은 `packages/renderer/src/compose.tsx` 의 `renderComposed` 하나다**(지금은 playground 만 쓴다 — 캔버스 · 번들은 페이지 문서만 그린다). 예제 페이지는 그것을 쓴다. 카탈로그에 메뉴 컴포넌트가 없고 `Tree` 항목은 글자라 이동을 못 거니, 왼쪽 메뉴는 `Link` · `Button` 노드로 짓는다.
- 예제 페이지 문서는 지금 카탈로그 검증(`@wirebound/schema` 의 문서 검증)을 지나야 한다 — 케이스가 잠근다.
- 좁은 창(720px 미만, 뼈대가 사이드바를 위로 접는 문턱)에서도 쓸 수 있어야 한다.

## 접근 (고른 것: A)

- **A · 공용 갤러리 패키지에 둔다 (고름).** `@wirebound/theme-gallery` 에 그룹 격자와 예제 페이지(문서 · 이동 처리)를 넣는다. 세 화면이 같은 두 보기를 얻는다 — 테마 작성자가 `wb-theme dev` 에서 본 것과 사용자가 설정에서 보는 것이 같다. 비용: kit 의 build-test(`dev.test.ts` · `shots.test.ts` — `test:build:serial` 갈래)가 칸 수 · 배치에 기대면 함께 고친다.
- **B · 웹 앱에만 둔다.** 빠르고 kit 을 안 건드리지만 작성 도구와 설정 화면의 미리보기가 갈린다. 반목표에 걸려 뺐다.
- **뺀 안 · 예제 페이지를 DB 프로젝트로 시딩.** 사용자 데이터에 가짜 프로젝트가 섞이고 서버 일이 생긴다. 반목표에 걸린다.

## 정한 것

### 테마 화면 배치 (프로젝트 설정 › 테마)

위에서 아래로:

1. **지금 테마 요약 카드** · «테마 바꾸기»(owner) — 지금 그대로.
2. **토큰 칸** — manifest 의 토큰 무리(`tokens.groups`, 기본테마는 색 · 모양 · 글자 · 밀도)를 **탭**으로. 무리 없는 키 · 선언에 없는 무리는 지금처럼 «기타» 탭. 고른 탭의 칸만 보이고 칸은 폭에 맞춘 **여러 열 격자**다. 탭 줄 오른쪽에 «전부 기본값으로» · «토큰 저장»이 늘 보인다. 칸의 사유 · «고칠 칸이 있습니다» 문장 · 409 나란히 보기 · 알림은 지금 동작 그대로다. **사유가 있는 칸이 다른 탭에 있으면 그 탭 이름에 표지가 선다**(안 보이는 칸의 문제가 숨지 않게).
3. **미리보기** — 내용 칸 폭을 다 쓴다. 머리에 «컴포넌트 / 예제 페이지» 전환. 상자는 창 높이에 묶여 안에서 스크롤한다(지금 `.wb-shell-settings-preview-frame` 의 성질을 잇는다). iframe 폭은 고정 640 이 아니라 **상자 폭을 따른다**.

읽기 전용(owner 아님)이면 탭 · 칸이 읽기로만 서고 저장 단추가 없다 — 지금과 같다. **관리자 › 테마**는 토큰 칸 없이 미리보기(두 보기)만 같은 부품으로 쓴다.

### «컴포넌트» 보기

- 카탈로그 그룹 차례로 묶는다 — 구조 · 데이터 · 입력 · 액션 · 문서(`packages/schema/src/component/group.ts` 의 차례 · `ComponentDef.group`). 그룹마다 머리(그룹 이름 · 칸 수).
- 그룹 안은 **폭에 맞춘 격자**(`repeat(auto-fill, minmax(<최소 폭>, 1fr))` 꼴). **넓어야 제대로 보이는 표본은 한 줄을 통째로 쓴다**(표 · 검색 폼 · 폼 표처럼 — 좁은 칸에서는 테마가 아니라 칸 폭 때문에 깨져 보인다). 어느 표본이 넓은지는 표본 정의(`GallerySample`)에 싣는다.
- 칸 하나는 지금 칸과 같은 내용(제목 · variant · 표본 이름 · 렌더 · 겹쳐 보기)이고 표지 `data-wb-gallery-item` 도 같다.

### «예제 페이지» 보기 — 주문 관리

모든 장이 **같은 레이아웃**(왼쪽 메뉴 · 위쪽 머리 · 가운데 Slot)을 쓴다. 장은 다섯이다.

1. **대시보드** — 요약 숫자들 · 최근 주문 표.
2. **주문 목록** — 검색 폼 · 표 · 페이지 나눔. 줄(또는 주문번호)을 누르면 **주문 상세**로.
3. **주문 상세** — 탭 · 정보 표 · «수정» · «삭제». «수정»은 **등록 · 수정 폼**으로, «삭제»는 **삭제 확인 팝업**을 연다.
4. **등록 · 수정 폼** — 여러 종류의 입력 칸 · «저장» · «취소» — 둘 다 **주문 목록**으로.
5. **삭제 확인 팝업** — «취소»는 닫고, «삭제»는 닫고 **주문 목록**으로.

왼쪽 메뉴는 대시보드 · 주문 목록 · 등록으로 간다. 미리보기 머리에 **장 이름 줄**이 있어 바로 고를 수도 있다(장 넷 — 팝업은 장 이름 줄에 없고 주문 상세에서 연다 · 코디네이터 판단). 다섯 장을 합치면 카탈로그 다섯 그룹이 모두 실린다(케이스가 그룹마다 하나 이상 실렸는지 잰다). 처음 여는 장은 대시보드다. 미리보기 안의 이동은 바깥 화면을 안 움직인다(반목표). 보던 보기 · 장은 그 화면에 있는 동안 남고(토큰을 바꿔도 처음으로 안 돌아간다), 저장은 하지 않는다.

### `wb-theme dev` · `shots` · `check` (코디네이터 판단)

- `wb-theme dev` 프레임은 웹과 같은 두 보기를 얻는다.
- **`shots` · `check` 는 지금처럼 «한 줄에 하나» 판을 잰다** — 갤러리가 배치를 고르는 값(목록 / 격자)을 받고, 두 도구는 목록 판을 고정으로 연다(질의 · 옵션). 격자에서는 칸 폭이 좁아 칸 폭 탓의 깨짐이 테마 실패로 잡히고, 칸을 넘어 이웃을 덮는 넘침은 창 폭을 안 넘어 놓친다 — 관문의 뜻이 바뀐다. 예제 페이지도 두 도구는 안 잰다(비목표 · 이월 후보). 보기 전환 UI 는 두 도구가 여는 판에 서지 않는다.

### 프로젝트 목록 카드

- 격자 **맨 앞에 «프로젝트 추가» 카드**(＋ · «프로젝트 추가»). 누르면 **그 카드 자리가 만들기 폼**(이름 · 슬러그 · 설명 — 지금 폼과 같은 칸 · 같은 검사 · 같은 오류)으로 바뀐다. 검색 · 거름이 걸려 있어도 늘 맨 앞에 남는다(결과 0 에서도 만든다). 머리 오른쪽의 «새 프로젝트» 단추는 걷는다. **목록을 불러오는 중 · 조회 실패 · 프로젝트 0 개에서도 추가 카드는 선다**(격자에 추가 카드 하나 — 지금은 이 셋에서 격자가 없고 머리 단추로만 만든다 · `routes/project-list.tsx`). 0 개의 빈 안내 문구는 추가 카드 옆 · 아래에 남기되 «새 프로젝트» 단추를 가리키지 않게 고친다. 실패 알림은 그대로 선다(코디네이터 판단).
- 카드 아래쪽에 **아이콘 + «열기» 큰 주색 단추**(카드 폭을 거의 다 쓴다) → 에디터(`/projects/:id`). 옆에 **톱니 아이콘만의 작은 단추** → 설정. 둘 다 접근 이름에 프로젝트 이름을 싣는다(«<이름> 열기» · «<이름> 설정» — 지금 «설정» 링크의 `aria-label` 과 같은 꼴). 아이콘은 셸 아이콘(`apps/web/src/shell/icons.ts`)에서 고른다.
- 카드의 프로젝트 이름은 지금처럼 에디터로 가는 링크로 남는다(주소 복사 · 새 탭).

## 빌더에게 남긴 것

- 격자의 최소 칸 폭 · 문턱 · 탭 · 단추의 정확한 모양과 간격.
- 예제 페이지의 글 · 숫자 · 어느 컴포넌트를 어느 장에 둘지(다섯 그룹이 다 실린다는 조건 안에서).
- 장 이동을 갤러리 패키지 안의 어느 부품이 쥘지, 레이아웃 · 페이지 문서를 어떻게 합칠지(번들 · 캔버스의 합치기와 같은 길을 쓸 것).
- «컴포넌트» 보기의 넓은 표본 목록.
- 트랙 나누기 — 프로젝트 목록 카드(웹만)와 미리보기(갤러리 패키지 · 웹 · kit)를 나란히 두 트랙으로 돌린다. 둘 다 `apps/web/src/shell.css` 를 고치니 병합 때 그 파일을 먼저 본다.
