# 코멘트 토큰 설계

## 목적

코멘트 본문에 **페이지 · 코멘트 · 공통코드를 가리키는 토큰**을 넣고, 읽는 사람이 그것을 눌러 **그 자리로 이동**하게 한다. 사용자가 정한 핵심은 이동이다 — 늘 지금의 번호 · 이름으로 읽히는 것은 이동이 정확하려면 따라오는 성질이다.

사용자가 든 넷(페이지 · 코멘트 번호 · 페이지 + 코멘트 번호 · 공통코드)은 토큰 셋으로 줄어든다 — «코멘트 번호» 와 «페이지 + 코멘트 번호» 는 둘 다 **번호 하나**(번호는 노드가 들고 같은 노드의 코멘트가 그 번호를 나눠 쓴다 — 스레드)를 가리키고, 보이는 꼴만 다르다(같은 페이지면 «#3», 다른 페이지면 «회원 목록 #3»). 토큰 종류는 앞으로 늘어난다(사용자 말) — 꼴은 종류를 더하기 쉽게 둔다.

## 목표

- 코멘트를 쓰거나 고칠 때 `#` 자동완성으로 페이지 · 코멘트 · 공통코드(그룹 · 항목)를 골라 넣는다.
- 읽는 자리(에디터 코멘트 패널 · 뷰 모드 · HTML 번들 · PPTX · MCP `get_page` · CLI `page get`)는 토큰을 **지금의** 번호 · 이름으로 풀어 보인다.
- 에디터 · 뷰 모드 · 번들에서 토큰을 누르면 그 자리로 간다.
- 재번호 · 이름 바꾸기 · 노드 옮기기 뒤에도 토큰은 같은 대상을 가리킨다.

## 하지 않는 것

- **칩 편집기** — 입력 칸은 지금의 글 상자 그대로다. 토큰은 고칠 때 원문(`[글](wb:…)`)으로 보인다. 칩 편집기는 이 꼴 위에 나중에 얹을 수 있다(접근 B).
- **사람 멘션 · 알림**, **역링크**(«이 코멘트를 가리키는 코멘트»), 이번 셋 밖의 토큰 종류.
- 코멘트 본문의 다른 서식(굵게 · 목록 · 일반 URL 링크) — 토큰만 푼다.

## 반-목표

- **엉뚱한 곳으로 이동하는 것** — 재번호 · 이름 바꾸기 뒤 토큰이 다른 대상으로 가는 것.
- **다른 프로젝트의 것을 보이는 것** — 토큰의 id 가 남의 프로젝트 것이어도 이름 · 번호 · 존재 여부가 새지 않는다. 풀기는 그 코멘트가 사는 프로젝트의 자료로만 한다.
- 출력마다 다르게 풀리는 것(패널 · 번들 · PPTX · MCP · CLI 가 다른 글).
- 날 id 가 사람에게 보이는 것(읽는 자리에서).

## 접근 방식

| 안 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A (고름)** | 자동완성으로 골라 넣고 본문에 «보이는 글 + id» 를 함께 저장 — `[회원 목록 #3](wb:comment/<id>)` | id 라 이동이 정확 · 입력 칸이 지금 글 상자 그대로라 한글 조합이 안전 | 고칠 때 원문이 거칠게 보인다 |
| B | 자동완성 + 칩 편집기(입력 칸에서도 칩) | 보기 좋음 | 입력 칸을 새로 지어야 하고 IME 처리에서 깨지기 쉽다 |
| C | 사람이 읽는 문법(`#3` · `@회원 목록`)을 보일 때 해석 | 가장 가볍다 | 재번호 · 이름 변경 · 같은 이름 페이지에서 엉뚱한 곳으로 간다 — 이동이 핵심인 목적과 맞지 않는다 |

**A 를 골랐다.** B 는 A 의 저장 꼴 위에 나중에 얹을 수 있다.

## 결정된 것(사용자)

- 핵심은 이동이다.
- 접근 A — 자동완성 + «보이는 글 + id» 저장.
- 토큰 종류는 앞으로 늘어난다.

## 제안 (빌더가 따를 기본값 — 메인 세션의 판단)

### 저장 꼴

- 토큰 = `[<보이는 글>](wb:<종류>/<대상>)`. 종류:
  - `wb:page/<pageId>`
  - `wb:comment/<pageId>/<nodeId>` — **코멘트 하나가 아니라 번호(그 노드의 코멘트 묶음)를 가리킨다.** 사용자가 «코멘트 번호» 로 불렀고, 번호는 노드에 붙어 같은 노드의 코멘트가 함께 쓴다(`apps/api/src/routes/comments.ts` 의 `markerPlanOf`). 코멘트 하나를 가리키면 같은 스레드의 코멘트가 모두 «#3» 으로 보여 보이는 글로 가를 수 없다. 노드 id 는 페이지 안에서만 유일해 페이지 id 를 함께 싣는다.
  - `wb:code/<GROUP_KEY>` · `wb:code/<GROUP_KEY>/<VALUE>`(값은 퍼센트 인코딩 — `/` · `)` · 공백이 든 코드값)
- 보이는 글은 대상이 끊겼을 때만 쓰는 대체 글이다. 저장할 때(달기 · 고치기) 웹이 지금 이름으로 다시 적는다 — 서버는 토큰을 고치지 않는다.
- 모르는 종류 · 꼴이 깨진 토큰은 그 원문 글자 그대로 보인다(그 꼴로 쓴 보통 글을 망가뜨리지 않는다).
- 본문 길이 한도(`COMMENT_BODY_MAX_LENGTH`)는 원문으로 센다. 서버 검증은 바꾸지 않는다 — 토큰은 글이다.
- 파서는 `packages/schema` 에 한 벌(`parseCommentBody(body): Segment[]` — 글 조각 · 토큰 조각)이고, 풀기(`resolveCommentTokens(segments, context)`)도 한 벌이다. 패널 · 번들 · MCP · CLI 가 같은 함수를 지난다.

### 풀린 모양

| 토큰 | 보이는 글 |
|---|---|
| 페이지 | 페이지 제목(메뉴 경로가 아니라 제목 — 같은 제목이 둘이면 «메뉴 › 제목») |
| 코멘트 · 같은 페이지 | `#3` |
| 코멘트 · 다른 페이지 | `회원 목록 #3` |
| 번호 없는 노드(코멘트가 다 지워져 번호가 걷힘) | `회원 목록 › <노드 이름>` — 누르면 그 노드로 간다 |
| 노드째 지워짐 | 끊김 |
| 공통코드 그룹 | 그룹 이름 |
| 공통코드 항목 | 항목 이름 |
| 끊김(대상이 없음 · 다른 프로젝트 · 권한 밖) | 대체 글 + 흐린 «찾을 수 없음» 표지 · 누를 수 없음 |

끊김의 까닭(지워짐 · 다른 프로젝트)을 가르지 않는다 — 가르면 남의 프로젝트 id 의 존재가 샌다.

### 이동

| 어디서 | 페이지 | 코멘트 | 공통코드 |
|---|---|---|---|
| 에디터 · 뷰 모드 | 그 페이지를 연다 | 그 페이지를 열고 그 노드를 고르고 코멘트 패널에서 그 번호의 묶음으로 굴려 잠깐 강조 | 공통코드 화면 `?group=<KEY>`(항목이면 그 줄 강조) |
| HTML 번들 | 그 페이지 장 | 그 페이지 장의 코멘트 칸 그 번호(닻) | 번들의 «공통코드» 장 그 그룹 · 항목(닻) |
| PPTX | 이동 없음 — 풀린 글만(슬라이드 사이 링크는 걸지 않는다 · 끊김은 대체 글) | | |
| MCP | 이동 없음 — 풀린 글 뒤에 대상을 괄호로 싣는다(`회원 목록 #3 (comment:<pageId>/<nodeId>)`) — 에이전트가 다음 호출에 쓴다 | | |
| CLI | 사람 출력은 풀린 글만 · `--json` 은 MCP 와 같은 꼴(대상 포함) | | |

뷰어(viewer)도 이동한다. 공통코드 화면은 viewer 도 읽기로 연다(지금 그렇다).

### 자동완성

- 코멘트 달기 · 고치기 상자에서 `#` 를 치면 후보 목록이 뜬다. 이어 친 글로 거른다. 후보 무리: 이 페이지의 번호(번호 · 노드 이름 · 첫 코멘트 앞머리) · 다른 페이지(제목) · 다른 페이지의 번호(«페이지 #번호») · 공통코드(그룹 · 항목).
- Enter · 누름으로 고르면 `#…` 자리를 토큰 원문으로 바꾼다. Escape 면 친 `#` 를 보통 글로 둔다. 한글 조합 중에는 열지도 고르지도 않는다(조합이 끝난 뒤에 거른다).
- 키 조작은 목록 상자의 기존 꼴(↑ ↓ · Enter · Escape)을 따른다.

### 풀 자료

- 웹은 프로젝트 전체의 «번호 색인»(페이지 id · 노드 id → 번호 · 노드 이름 · 첫 코멘트 앞머리)이 필요하다 — 지금은 페이지마다 코멘트를 읽는다. 서버가 색인을 짓는 조회 하나를 둔다(예 `GET /projects/:projectId/comments/index` — 번호는 페이지 문서의 노드가 들므로 서버가 문서에서 읽어 붙인다). 이름은 빌더가 정한다.
- 색인 · 페이지 목록(메뉴 트리) · 공통코드 표를 셸이 들고, `comments-changed` · 메뉴 변경 · `codes-changed` · 페이지 편집(번호가 바뀌는 편집)에서 다시 읽는다. 지금 시점 정확도가 목표다 — 조금 늦게 풀려도 이동은 id 라 정확하다.
- 번들 · MCP · CLI 는 내보내는 때의 프로젝트 자료로 푼다.

### 들이는 입구

- **스냅샷 복원**은 페이지 id · 노드 id · 코멘트 id 를 지킨다(`insertCommentWithId`) — 토큰이 그대로 산다.
- **페이지 JSON 가져오기**는 새 페이지 id · 새 코멘트 id 를 짓는다 — 가져온 본문의 토큰은 끊긴다(대체 글로 보인다). 가져온 페이지 안의 번호를 가리키는 토큰(`wb:comment/<옛 pageId>/<nodeId>`)은 노드 id 가 그대로면 새 페이지 id 로 다시 잇는다 — 가져오기가 노드 id 를 다시 지으면 빌더가 «끊김» 으로 남기고 보고에 적는다.
- 페이지 JSON 내보내기는 본문을 그대로 낸다.

### 따라가는 것

- 정본 설계서 「설계서 화면 구조」(코멘트 · 자동완성 · 이동) · 「HTML 정적 번들」(닻) · 「MCP 도구」(`get_page` 의 코멘트 글) · 「CLI」 를 지금 참인 설계로 고친다.
- `/llms.txt` · MCP 도구 설명 · 스킬에 토큰 꼴을 적어 에이전트가 `add_comment` 로 토큰을 쓸 수 있게 한다.
- lint: `comment-token-broken`(정보 — 끊긴 토큰). 이름은 빌더가 기존 규칙 꼴에 맞춘다.

## 빌더에게 맡기는 것

- 색인 조회의 이름 · 응답 꼴, 자동완성 목록의 배치, 강조의 모양 · 시간.
- 번들 닻의 id 이름.
- 단계 나누기(예: 파서 · 풀기 → 패널 표시 · 이동 → 자동완성 → 번들 · MCP · CLI → 정본).
