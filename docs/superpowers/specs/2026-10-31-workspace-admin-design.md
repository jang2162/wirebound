# 사내 공용 운영 — 에디터 밖 화면 뼈대 · 초대 링크 가입 · 인스턴스 관리자

## 왜

wirebound 를 사내 여러 사람이 쓰는 도구로 공유한다. 지금은 계정을 만드는 길이 서버의 `migrate` 시딩(`SEED_USER_*`) 하나라
사람을 들일 수 없고, 사람을 내보내는 길(계정 끄기)은 아예 없다. 관리자 권한(`users.is_instance_admin`)은 있지만 화면에서
하는 일은 테마 패키지 관리뿐이고 지정 · 해제도 CLI 다. 에디터 밖 화면(프로젝트 목록 · 프로젝트 설정 · 계정 설정 · 관리자
테마)은 저마다 가운데 고정 폭(720 – 1280px)이고 서로 잇는 길이 머리 오른쪽 «…» 메뉴뿐이다.

이 작업이 끝나면 관리자는 **초대 링크를 만들어 사내 메신저로 공유**하고, 받은 사람은 링크를 열어 스스로 계정을 만든다. 관리자는
화면에서 사람을 끄고 · 비밀번호 재설정 링크를 주고 · 관리자를 지정하고 · 주인 없는 프로젝트의 owner 를 넘긴다. 에디터 밖
화면은 왼쪽 사이드바 하나로 묶이고 폭 전체를 쓴다.

## 목표

1. **뼈대** — 에디터 밖 화면이 공통 왼쪽 사이드바 위에 서고 내용 칸은 화면 폭 전체를 쓴다.
2. **프로젝트 목록 개선** — 카드 격자 + 검색 · 역할 거름 · 정렬, 카드에 내 역할 · 멤버 수 · 최근 수정 시각.
3. **프로젝트 설정** — 절 넷을 내용 위 가로 탭으로.
4. **초대 링크 가입** — 관리자가 만든 링크로만 계정이 생긴다.
5. **인스턴스 관리자 화면** — 사용자 · 초대 링크 · 프로젝트 · 테마 · 기록.

## 비목표

- 메일 발송(초대 · 재설정 모두). 링크는 관리자가 직접 전한다.
- 이메일 도메인 제한(사용자가 «상관없다»고 했다).
- 초대 링크로 **프로젝트 멤버십**을 주는 것. 링크는 도구 계정까지만이다 — 프로젝트에 넣는 것은 지금처럼 그 프로젝트의 멤버 화면에서
  owner 가 이메일로 한다.
- 공개 가입 화면. **웹 · API 에서** 링크 없이 계정을 만드는 길을 두지 않는다. 서버 운영자의 `migrate` 시딩(`SEED_USER_*`)과 관리자 CLI
  (`db/admin.ts`)는 그대로 둔다 — 새로 설치한 서버의 첫 관리자를 세우는 길이다(내 판단). 계정을 만드는 길을 세는 케이스
  (`apps/api/test/user-creation-census.test.ts`)는 «시딩 + 초대 가입» 둘로 고친다.
- 계정 **삭제**. 내보내는 길은 비활성화뿐이다.
- SSO · 외부 인증.
- 에디터 셸(`/projects/:id`, `/projects/:id/pages/:pageId`)의 모양. 뼈대는 에디터 밖 화면에만 선다.

## 반목표 (돌아가도 실패인 것)

- **관리자 권한이 설계서 내용을 들여다보는 조용한 통로가 되는 것.** 관리자는 모든 프로젝트를 목록으로 보지만 멤버가 아니면 그
  내용(페이지 · 메뉴 · 스냅샷 · 내보내기)을 여는 API 를 지나지 못한다. 관리자가 하는 프로젝트 쓰기는 owner 넘기기 하나다.
  정상 기능으로 내용에 닿는 길은 둘 남는다 — 활성 owner 없는 프로젝트를 자기에게 넘기기, 남의 재설정 링크를 만들어 쓰기. 사용자는
  이 둘을 **막지 않고 기록으로 남기는 것**으로 정했다(관리자는 사내에서 믿고 맡기는 사람이다). 그래서 관리자 행동은 빠짐없이 기록에
  남고 관리자 화면에서 보인다(아래 «관리자 › 기록»).
- **비활성화한 사람이 무엇이든 계속 하는 것** — 열려 있던 세션 · WS 연결 · API 토큰으로. 비활성화는 즉시 먹어야 한다
  (`auth/admin.ts` 머리말이 관리자 판정에 대해 말하는 «세션에 얼려 두면 끝날 때까지 안 먹는다» 와 같은 잣대).
- **관리자가 0 명이 되는 것**, **활성 owner 없는 프로젝트를 아무도 못 고치는 것.**
- 초대 · 재설정 링크의 원문이 DB 에 남는 것(세션 · API 토큰처럼 해시만 둔다 — `auth/token-hash.ts`).

## 정한 것 — 화면

### 뼈대 (사용자가 «B · 왼쪽 사이드바»를 골랐다)

- 에디터 밖 화면 전부(`/`, `/account`, `/admin/*`, `/projects/:id/settings`)가 같은 뼈대 안에 선다: 왼쪽 사이드바 + 내용 칸.
- 사이드바: 머리에 `wirebound`(→ `/`), 그 밑에 «프로젝트» · «계정», 그 밑에 **관리자일 때만** «관리자» 묶음(사용자 · 초대 링크 ·
  프로젝트 · 테마 · 기록). 맨 밑에 로그인한 사람 이름과 로그아웃.
- 내용 칸은 화면 폭 전체를 쓴다(좌우 여백만 둔다). 지금의 `max-width` 1280 · 960 · 760 · 720 을 이 화면들에서 걷는다.
- 지금 머리 오른쪽 «…» 메뉴(`shell/page-head.tsx` — 계정 설정 · 테마 관리 · 로그아웃)가 하던 일은 사이드바가 맡는다.
- 로그인 · 가입 · 재설정 화면은 뼈대 밖이다(로그인한 사람이 아니다).

### 프로젝트 목록 (사용자가 «카드 격자»를 골랐다)

- 카드 격자. 폭에 따라 열 수가 는다(넓으면 4 – 5 열).
- 위 줄: 제목 «프로젝트» · 검색(이름 · 슬러그 · 설명) · 역할 거름(전체 / owner / editor / viewer) · 정렬(최근 수정 · 이름) ·
  «새 프로젝트».
- 카드: 이름 · 내 역할 표지 · 슬러그 · 설명 · 멤버 수 · 최근 수정 시각(상대 시각) · 설정 진입.
- 정렬 기본값은 «최근 수정»이다 — **이것은 내 판단이다**(자주 만지는 것이 위로).
- 새 프로젝트 만들기는 지금처럼 그 자리에서 여는 폼이다 — **내 판단**.
- 빈 상태 · 검색 결과 없음을 따로 말한다.

### 프로젝트 설정 (사용자가 «A · 내용 위 가로 탭»을 골랐다)

- 머리: «프로젝트 › <이름>» 빵부스러기, 제목 «<이름> 설정», 오른쪽에 «에디터 열기».
- 절 넷(일반 · 테마 · 멤버 · 위험 구역)이 내용 위 가로 탭이다. 주소의 `?section=` · 키보드 이동 · owner 가 아니면 «위험 구역»이
  없는 지금 규칙(`routes/settings.tsx` 의 `SettingsTabs` · `sectionOf`)은 그대로다 — `aria-orientation` 만 가로로 바뀐다.
- «테마» 절의 미리보기는 넓어진 폭을 쓴다.

### 계정 설정 · 관리자 › 테마

- 뼈대 안으로 옮기고 폭 제한을 걷는다. 내용은 그대로다.

### 관리자 › 사용자 (그림을 사용자가 «좋아»로 받았다)

- 표: 이름(관리자 표지) · 이메일 · 상태(활성 / 비활성) · 속한 프로젝트 수 · 가입 일시(초대 링크로 들어왔으면 그 링크 이름) ·
  마지막 접속(그 사람 세션들의 `last_seen_at` 중 가장 늦은 것).
- 위 줄: 이름 · 이메일 검색 · 상태 거름 · «초대 링크 만들기»(초대 링크 칸의 만들기 상자를 연다).
- 줄 «…» 메뉴: 비밀번호 재설정 링크 만들기 · 관리자로 지정 / 해제 · 비활성화 / 다시 활성화.

### 관리자 › 초대 링크

- 표: 이름(메모) · 종류(한 번 / 여러 명) · 만료 일시 · 그 링크로 가입한 수 · 상태(사용 중 / 만료 / 거둠 / 다 씀) · 만든 사람.
- 줄 행동: 링크 복사(아래 «링크 원문») · 거두기.
- «초대 링크 만들기» 상자: 이름 · 종류 · 만료(기본 7 일). 만들면 링크를 보이고 «복사» 단추를 준다.

### 관리자 › 프로젝트

- 표: 이름 · 슬러그 · owner(들) · 멤버 수 · 최근 수정. 위에 «활성 owner 가 없는 프로젝트 N» 경고와 거름.
- 줄 행동: «owner 넘기기» — **활성 owner 가 없는 프로젝트의 줄에만 있다**(사용자가 정했다). 활성 사용자 하나를 골라 그 프로젝트의
  owner 로 만든다(멤버가 아니면 owner 로 넣고, 멤버면 owner 로 올린다). **자기 자신도 고를 수 있다.** 비활성 owner 행은 그대로 둔다
  (그 사람을 다시 켜면 돌아온다). 서버도 같은 조건을 판정한다 — 그 사이 활성 owner 가 생겼으면 409.
- 관리자가 멤버가 아닌 프로젝트는 이름을 눌러도 열리지 않는다(반목표).

### 관리자 › 기록 (사용자가 «넘기기 좁힘 + 행동 기록»을 골랐다)

- 관리자 묶음의 다섯째 칸. 사이드바 순서: 사용자 · 초대 링크 · 프로젝트 · 테마 · 기록.
- 남는 것: 초대 링크 만들기 · 거두기, 재설정 링크 만들기, 비활성화 · 다시 활성화, 관리자 지정 · 해제, owner 넘기기, 테마 패키지
  올리기 · 숨기기. 줄마다 언제 · 누가 · 무엇을 · 누구에게(대상 사용자 · 프로젝트 · 링크 이름).
- **그 행동과 같은 트랜잭션에서** 남긴다 — 행동이 커밋됐는데 기록이 없거나, 되돌려졌는데 기록만 남는 판이 없게.
- 기록은 화면에서 고치거나 지울 수 없다. 관리자 누구나 전부 본다. 최신이 위, 행동 종류 · 사람으로 거른다.
- 가입(초대 링크로 계정이 생김)과 재설정 링크 사용도 같은 기록에 남긴다 — 그 링크를 누가 만들었는지와 이어 보이게(내 판단).
- CLI(`db/admin.ts`)로 한 지정 · 해제도 남긴다. 누가 했는지는 «서버 명령»으로 적는다(내 판단).

### 가입 화면 (링크를 연 사람)

- 주소는 `/invite/<원문 토큰>`. 뼈대 밖, 로그인 화면과 같은 꼴.
- 칸: 이메일 · 이름 · 비밀번호(8 자 이상 — `auth/credentials.ts` 의 `RawPassword` 와 같은 자) · 비밀번호 확인.
- 가입하면 곧바로 세션이 서고 `/` 로 간다.
- 링크가 만료 · 거둠 · 다 씀 · 없음이면 네 경우 모두 **같은 문장** «이 초대 링크는 더 쓸 수 없습니다 — 관리자에게 새 링크를
  받으세요» 를 낸다(링크 유무를 가르지 않는다).
- 이미 있는 이메일이면 가입을 거절한다. 문장은 «이미 계정이 있는 이메일입니다 — 로그인하세요».

### 비밀번호 재설정 화면

- 주소는 `/reset/<원문 토큰>`. 뼈대 밖. 새 비밀번호 · 확인 두 칸.
- 성공하면 그 사람의 세션을 전부 끊고(지금 재설정 명령 `db/reset-password.ts` 와 같은 결과) 로그인 화면으로 보낸다.
- 만료 · 이미 씀 · 없음은 같은 문장이다.

## 정한 것 — 규칙

### 초대 링크

- 만드는 사람: 인스턴스 관리자만.
- 종류: **한 번**(가입 하나로 다 씀) / **여러 명**(만료 · 거둠까지 몇 명이든).
- 만료: 만들 때 고른다, 기본 7 일. 만료 뒤 링크는 못 쓴다.
- 거두기: 언제든. 거둔 링크로는 가입 못 한다. 그 링크로 이미 만든 계정에는 아무 일도 없다.
- 저장: 원문은 저장하지 않고 sha256 해시만 둔다(세션 · API 토큰과 같은 `auth/token-hash.ts`).
- **링크 원문**: 원문을 저장하지 않으므로 «복사»는 만든 직후 한 번만 된다 — **이것은 빌더가 정할 수 있게 열어 둔 것이 아니라,
  해시만 둔다는 반목표에서 따라 나온다.** 목록의 «복사»는 만든 직후 그 화면에서만 보이고, 뒤에는 «새로 만들기»만 있다.
  (목업에는 목록에 «복사»가 늘 있었다 — 이 차이를 사용자에게 알린다.)
- 가입과 «한 번» 소모 · 만료 · 거둠 판정은 한 트랜잭션에서 그 링크 행을 잡고 한다 — 한 번짜리 링크로 둘이 동시에 가입하면 하나만
  선다.
- 가입한 사용자 행에 어느 링크로 들어왔는지를 남긴다(사용자 표의 «초대 «디자인팀»»).

### 비활성화

- `users` 에 비활성 표시를 둔다(가령 `deactivated_at`).
- 비활성화하면 같은 트랜잭션에서: 그 사람의 세션 전부 삭제 · API 토큰 전부 삭제. 커밋 뒤 그 사람의 WS 연결을 닫는다(비밀번호
  바꾸기의 `closeSessionConnections` 와 같은 길).
- 로그인은 비활성 사용자를 거절한다 — 문장은 틀린 비밀번호와 **같은** 401 이다(«꺼진 계정»을 바깥에 가르지 않는다).
- 비활성 사용자는 새 세션 · 토큰을 못 얻으므로 요청마다 표시를 다시 읽을 필요는 없다. 다만 «세션을 지운 뒤 · 커밋 전에 선 로그인»
  같은 겹침이 없어야 한다 — 로그인의 `createLoginSession` 이 해시를 `FOR SHARE` 로 확인하는 것처럼 비활성 표시도 같은 문장에서
  확인한다.
- 다시 활성화: 표시를 지운다. 비밀번호는 그대로다(잊었으면 재설정 링크).
- 자기 자신은 비활성화할 수 없다.
- 비활성 사용자는 프로젝트 멤버 행을 그대로 가진다(이력 · owner 복귀를 위해). 프로젝트의 멤버 화면에는 «비활성» 표지로 보인다.
- **마지막 활성 owner 를 비활성화하면** 막지 않고 경고한다: «이 사람이 마지막 활성 owner 인 프로젝트 N 개 — 관리자 › 프로젝트에서
  owner 를 넘기세요». (`LastOwnerError` 의 «마지막 owner» 불변식은 멤버 **행** 의 것이라 그대로다 — 비활성 owner 도 행은 owner 다.)
- 멤버 화면의 «이메일로 추가»가 비활성 사용자를 받는지: **받지 않는다**(내 판단 — 꺼진 사람을 새로 들이는 것은 실수일 공산이 크다).
- **비활성화하면 관리자 표시도 지운다**(내 판단). 다시 활성화한 사람은 일반 사용자로 돌아온다 — «다시 켜기»가 관리자 권한까지 말없이
  되살리지 않게. 그래서 «활성 관리자»는 곧 `is_instance_admin` 인 사람이고, 비활성 관리자라는 상태는 없다.
- **비활성화 · 관리자 해제는 그 사람이 만든 아직 쓸 수 있는 초대 링크 · 재설정 링크를 같은 트랜잭션에서 거둔다**(내 판단). 링크 원문을
  본 사람이 그 사람이다 — 퇴사한 관리자가 쥔 «여러 명» 링크로 새 계정을 만드는 길을 닫는다. 화면은 거둔 수를 함께 말한다.

### 비밀번호 재설정 링크

- 만드는 사람: 인스턴스 관리자만. 대상은 활성 사용자.
- 24 시간 유효, 한 번 쓰면 끝. 같은 사람에게 새로 만들면 앞 링크는 못 쓴다.
- 원문은 해시만 저장하고 원문은 만든 직후 한 번 보인다.
- 쓰면: 비밀번호를 바꾸고 그 사람의 세션을 전부 끊는다. 잠금 차례는 지금 재설정(`db/reset-password.ts`)과 같다 — «사용자 행 →
  세션» (`auth/admin.ts` 머리말 «사용자 행 → 자격 차례다»).

### 관리자 지정 · 해제

- 화면에서 한다. CLI(`pnpm --filter @wirebound/api admin …`)는 그대로 둔다(관리자가 0 명일 때 되살리는 길).
- 자기 자신은 해제할 수 없다. 활성 관리자가 하나 남으면 그 사람을 해제 · 비활성화할 수 없다.
- 비활성 사용자는 관리자로 지정할 수 없다.

### 관리자 쓰기 일반

- 모든 관리자 쓰기는 지금 테마 관리 라우트와 같은 꼴이다: 핸들러 첫 줄 `requireInstanceAdmin`, 쓰기 트랜잭션 안 쓰는 문장 뒤
  `recheckInstanceAdmin`(`auth/admin.ts`). 세션 전용(API 토큰으로는 못 한다).
- 사용자 행을 고치는 관리자 쓰기(비활성화 · 지정 · 해제)는 대상 사용자 행과 **요청자 사용자 행**을 함께 잡는다 — 잡는 차례를
  정해야 한다(아래 «빌더에게 남긴 것»의 첫 줄).

## 정한 것 — 데이터 · API (모양만)

- 새 표: 초대 링크(이름 · 종류 · 만료 · 거둔 시각 · 만든 사람 · 해시), 재설정 링크(대상 · 만료 · 쓴 시각 · 만든 사람 · 해시),
  관리자 기록(시각 · 행위자 · 행동 · 대상들 · 세부).
- `users` 에 비활성 표시 · 들어온 초대 링크.
- 프로젝트 목록 응답(`GET /api/projects`)에 멤버 수 · 최근 수정 시각을 싣는다. `projects` 에는 `updated_at` 이 없다 — «최근 수정»을
  무엇으로 정할지는 빌더 몫(아래).
- 관리자 API 는 `/api/admin/*` 아래(지금 `/api/admin/theme-packages` 와 같은 접두).
- 가입 · 재설정은 로그인하지 않은 요청이 부른다 — 로그인과 같은 시도 한도(`auth/login-limit.ts`)를 거는지 빌더가 정한다. 거는 것을
  기본으로 한다(링크 원문을 맞혀 보는 판을 막는다).

## 접근 — 고른 것과 버린 것

| | 내용 | 판정 |
|---|---|---|
| A | 작업자 하나가 뼈대 → 계정 API → 관리자 화면을 차례로 | 가장 단순하지만 가장 느리고 검토가 한 덩어리로 커진다 |
| **B** | **뼈대(웹)와 계정 API(서버 + 가입 · 재설정 화면)를 동시에, 둘을 합친 뒤 관리자 화면** | **사용자가 골랐다.** 두 트랙이 웹 / 서버로 갈려 겹침이 적고, 관리자 화면이 실제 API 위에서 선다 |
| C | 가짜 API 로 화면을 끝까지 만든 뒤 API 를 붙인다 | 버렸다 — 이 저장소는 가짜 API 로 잰 것이 실물에서 갈린 이력이 있고(지침 «가짜 api 로 세운 판»), 비활성화의 «즉시 끊김»은 실서버로만 잰다 |

트랙:

1. **뼈대 트랙(웹)** — 사이드바 · 폭 · 프로젝트 목록 · 설정 가로 탭 · 계정 / 테마를 뼈대 안으로. 목록에 필요한 멤버 수 · 최근 수정은
   **서버 응답에 싣는 작은 변경까지 이 트랙**이 한다(계정 API 트랙과 파일이 안 겹친다 — `routes/projects.ts` 의 목록 응답).
   사이드바의 관리자 묶음은 링크만 두고, 아직 없는 화면(사용자 · 초대 링크 · 프로젝트)은 다음 트랙이 채운다.
2. **계정 트랙(서버 + 뼈대 밖 화면)** — 마이그레이션 · 초대 링크 · 가입 · 비활성화 · 재설정 링크 · 관리자 지정 · owner 넘기기 ·
   관리자 기록 API(테마 패키지 라우트의 기록 포함), 가입 화면 · 재설정 화면.
3. **관리자 화면 트랙** — 1 · 2 를 합친 뒤. 사용자 · 초대 링크 · 프로젝트 · 기록 칸.

## 빌더에게 남긴 것

- **잠금 차례.** 비활성화 · 지정 · 해제 · 재설정 · 가입 · owner 넘기기가 잡는 행(대상 사용자 행 · 요청자 사용자 행 · 세션 · API 토큰
  · 프로젝트 멤버 행 · 초대 링크 행)의 차례. 지금 있는 차례(`auth/admin.ts` «사용자 행 → 자격», `repos/members.ts` 의 owner 행 잠금,
  `api-tokens.ts` 의 id 순 잠금)와 고리가 서지 않게 정하고, 지침 «교착을 잴 때»대로 잰다.
- **«최근 수정»의 정의** — `revisions` 의 가장 늦은 시각 · 프로젝트 행 변경 등. 목록이 프로젝트마다 무거운 질의를 돌리지 않게.
- 마지막 접속을 세션 `last_seen_at` 로 읽는지, 세션이 지워진 사람(비활성 · 재설정)의 마지막 접속을 따로 남기는지.
- 가입 · 재설정 라우트의 시도 한도 수치.
- 사이드바의 좁은 창(모바일 폭) 동작 — 접기 · 서랍.
- 링크 원문의 길이 · 꼴(지금 `randomTokenValue`).
- 표 · 카드의 빈 상태 · 불러오기 실패 문장.
