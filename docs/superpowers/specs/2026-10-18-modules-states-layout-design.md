# 모듈 · 상태 트리 · 배치 몫 — 설계

사용자 요구(2026-10-18) 여덟을 한 설계로 묶는다. 셋은 서로 다른 축이다 — **배치**(SearchForm 열 · 모든 컴포넌트의 weight) · **넣기**(구조 트리 추가 걷기 · 하단 «모듈» 탭 · 프리셋 걷기) · **화면 상태**(상태 트리 · 노드별 보임 · `StateSwitch` 걷기).

이 문서는 발행 시점의 기록(spec)이다. 구현이 병합되면 정본 설계서(`docs/superpowers/specs/2026-08-03-wirebound-design.md`)의 해당 절과 `apps/api/README.md` 가 지금 참인 것을 갖는다. 앞 설계 `2026-10-05-page-states-design.md` 의 «사용자가 고른 것 — 통째 복사 · 노드 보임 조건이 아님»을 이 설계가 **뒤집는다**(사용자 결정 2026-10-18: 노드 보임 조건으로).

**제안했던 결정은 모두 사용자가 확인했다(2026-10-19 «진행해줘»).**

---

## 사용자 요구(원문 요지)

1. SearchForm 에 grid 처럼 열 지정.
2. 모든 컴포넌트에 weight — grid · flex 안에서 몫을 정한다.
3. 구조 트리에서 컴포넌트를 골라 추가하는 기능을 걷는다 — 하단 컴포넌트 목록에서만 넣는다.
4. 하단 «컴포넌트» 탭 옆에 «모듈» 탭.
5. 모듈 = 컴포넌트를 묶은 집합. 구조 트리에서 고른 구조를 모듈로 저장한다.
6. 프리셋을 걷는다 — 모듈이 대신한다.
7. 상태는 페이지에 더하고 트리로 다룬다 — 메뉴 트리의 페이지 줄 아래에 상태가 트리로 선다.
8. 컴포넌트가 상태에 따라 보이거나 숨는다. 이 설정은 모듈에 저장하지 않는다. `StateSwitch` 는 걷는다.

## A. 배치 — weight · SearchForm 열

### A1. weight 는 노드 필드다

- `WbNode.weight?: number` — 정수 **1 ~ 12**. 없으면 테마 · 기본 배치 그대로(지금 문서는 바뀌지 않는다).
- 카탈로그 prop 이 아니라 `alias` · `variant` 와 같은 노드 필드로 둔다. 까닭: 19개 정의에 같은 prop 을 덧붙이지 않고, `setProp` 상호작용 대상이 되지 않고, 패널이 부모를 보고 칸을 보일지 정할 수 있다.
- 뜻(부모에 따라):

  | 부모 | weight 의 뜻 |
  |---|---|
  | `Flex` | `flex-grow: <weight>` (형제끼리 남는 폭을 몫대로 나눈다) |
  | `Grid` | `grid-column: span <weight>` — 부모 `columns` 를 넘으면 `columns` 로 자른다 |
  | `SearchForm`(열을 정한 판) | 필드 칸의 `span` (Grid 와 같다) |
  | 그 밖 | 아무 일도 없다(값은 남는다 — 옮겨 다시 Flex 안에 들면 다시 먹는다) |

- **거는 자리는 SDK `Root` 하나다.** 렌더러는 노드마다 감싸는 요소가 없고 테마 뷰가 `Root` 로 제 뿌리를 그린다. `Root` 가 뷰의 `style` 과 **합쳐서** `--wb-node-weight` 를 싣고, SDK 기본 CSS(`defaultViewsCss`)에 특이도 0(`:where(…)`) 규칙을 둔다. 테마 다섯은 Flex · Grid 자식을 겨냥하는 규칙이 없어 그대로 먹는다. SDK 는 테마 번들 밖(external)이라 **테마 체크섬은 안 바뀐다.**
- **상속을 끊는다** — 커스텀 프로퍼티는 자손에 물려진다. weight 를 준 노드 안의 Flex 자식이 그 값을 물려받지 않게 모든 노드 뿌리에서 `--wb-node-weight` 를 초기화하고(인라인이 이긴다) 그 노드만 싣는다.
- 렌더러 계약 속성(`data-wb-*` 여섯)은 늘리지 않는다 — `render.tsx` 머리말 «일곱째 속성이 필요하면 만들기 전에 묻는다». weight 는 속성이 아니라 `Root` 가 받는 바인딩 값으로 넘긴다.
- 패널: 속성 패널 고정 칸(별칭 곁) «몫(weight)» — **부모가 Flex · Grid · 열을 정한 SearchForm 일 때만** 보인다. 비우면 필드를 지운다.
- 캔버스 · HTML 번들 · PPTX 가 같은 렌더러 · 같은 기본 CSS 를 쓰므로 셋에 같이 반영된다.

### A2. SearchForm 열

- 카탈로그 prop `columns?: 1 | 2 | 3 | 4`(선례 `KeyValue.columns` 1 ~ 4). **없으면 지금 배치**(테마마다의 flex-wrap) — 지금 문서 모양을 지킨다.
- 정했으면 `fields` 조각을 `grid-template-columns: repeat(<columns>, 1fr)` 로 깐다. 필드 자식의 weight 가 칸 `span` 이다(A1).
- 테마 CSS 가 `fields` 를 높은 특이도의 `display: flex` 로 덮으므로 **테마 다섯의 CSS 를 모두 고친다** — 열을 정한 판(`data-wb-*` 표지 · 또는 노드 변수)에서만 grid 로. 좁은 창의 «한 줄로 쌓기» media 는 열을 정한 판에도 그대로 선다(열을 1로).
- 테마를 고치므로 **다섯 테마의 판을 올린다**(`1.1.0` → `1.2.0`) · `checksums.json` 에 새 줄을 더한다(옛 줄은 고치지 않는다). 기본 뷰 · 표지(`marks.ts`)도 같이.

## B. 넣기 — 구조 트리 추가 걷기 · 모듈 · 프리셋 걷기

### B1. 구조 트리의 추가 입구를 걷는다

- 걷는 것: 툴바 · 줄 `+` · 뿌리 `+` 의 «안에 추가» · «아래 추가» · «페이지에 추가» · «패턴 넣기» · «프리셋», 타입 고르개 · 패턴 고르개 · 프리셋 고르개, 단축키 Alt+Shift+I / Alt+Shift+P(도움말 줄 포함).
- 남기는 것: 옮기기 · 들여쓰기 · 내어쓰기 · 삭제 · 복사 · 붙여넣기 · 복제 · 별칭 · 끌어 놓기(트리 줄 위로 놓는 것은 하단에서 끌어온 카드도 받는다).
- 팔레트 · 붙여넣기가 쓰는 판정(`placeableGroups` · `STRUCTURE_WHY_DISABLED.addInside/addAfter` · `StructureAbilities.addInside/addAfter`)은 남긴다.
- 넣는 자리는 지금 팔레트 규칙 그대로다(`palette/palette-add.ts` 의 `paletteAddTarget`): 고른 것 없음 · 뿌리 → 페이지 끝, 자식을 받는 노드 → 그 안 끝, 잎 → 바로 뒤. 끌어 놓으면 놓은 자리.

### B2. 하단 판에 «컴포넌트 | 모듈» 탭

- 하단 판(`palette/component-palette.tsx`)에 위층 탭을 더한다 — «컴포넌트»(지금 내용: 갈래 탭 · 검색 · 카드) · «모듈». 하단 바의 여는 단추는 하나로 두고 판 안에서 탭을 고른다. 마지막에 고른 탭은 사람 · 탭마다 기억한다(브라우저 저장소 · 실패해도 «컴포넌트»).
- «모듈» 탭은 세 묶음이다:
  1. **프로젝트 모듈** — 사람이 저장한 것(B3). 카드: 이름 · 노드 수 · «넣기» · 삭제(editor 이상).
  2. **기본 모듈** — 지금 내장 프리셋 셋(`search-list` · `detail` · `entry-form`)의 내용. 읽기 전용.
  3. **테마 패턴** — 지금 테마의 `patterns`(슬롯이 있는 레시피). 읽기 전용. 넣으면 지금 패턴 넣기처럼 첫 슬롯을 고른다.
- 넣기: 카드의 «넣기»(Enter) → B1 의 자리 · 끌기 → 놓은 자리. 넣은 노드들을 고른다. 한 편집(되돌리기 한 번).
- 검색 칸은 탭마다 따로다.

### B3. 모듈

- **저장 단위는 프로젝트다**(지금 프리셋과 같다 — 같은 프로젝트의 모든 페이지에서 쓴다).
- 모양: `{ id, projectId, name(1 ~ 60자), nodes: WbNode[], createdBy, createdAt, updatedAt }`. 설명 칸은 두지 않는다(프리셋의 `description` 은 옮길 때 버린다).
- **저장:** 구조 트리에서 고른 노드(여럿이면 문서 차례 · 조상과 자손이 함께 고른 것은 조상만 — 지금 복사와 같은 정규화) → 줄 `…` «모듈로 저장…» → 이름 칸 상자. 뿌리는 고를 수 없다(뿌리 줄에는 항목이 없다).
- **저장할 때 걷는 것:** 번호(`marker`) · **상태 보임(`visibility`)**(요구 8) · 모듈 밖 노드를 가리키는 상호작용(지금 붙여넣기의 `prepareNodesForPaste` 와 같은 거름 — 뺀 수를 상자에 말한다). 코멘트는 노드에 없으므로 따라가지 않는다.
- **넣을 때:** id 를 새로 짓는다(`remapNodeIds`). 상태 보임이 없으니 넣은 노드는 모든 상태에서 보인다 — **지금 고른 상태와 무관하다**.
- 고치기: 이름 바꾸기 · 삭제만. 내용을 바꾸려면 새로 저장하고 옛것을 지운다.
- 실시간: 목록은 탭을 열 때와 저장 · 삭제 뒤에 다시 읽는다(방송 없음 — 지금 프리셋과 같다). 남이 지운 모듈을 넣으려 하면 404 → «이 모듈은 지워졌습니다» 통지와 목록 다시 읽기.
- 권한: 목록은 viewer, 저장 · 이름 · 삭제는 editor 이상. 프로젝트 삭제는 모듈 행을 CASCADE 전에 잡는다(지금 `lockProjectPresets` 자리 · 순서 그대로 — AGENTS.md «자기 행을 잡고 → 재확인» 절).

### B4. 프리셋을 걷는다

- 걷는 것: `presets` 테이블 · 라우트 셋 · repo · 웹 고르개 · 툴바 · 상태 문구 · 클라이언트 · 타입 · 스타일 · README 표 · 내장 프리셋의 «페이지 통째로 바꾸기».
- **옛 데이터를 옮긴다**: 마이그레이션이 `presets` 행마다 같은 이름 · 같은 노드의 모듈을 만든다(`viewStates` 는 버리고, 노드 안의 상태 영역은 **기본 가지만 남겨** 푼다 — 모듈에는 상태가 없으므로 «기본 화면의 내용»이 모듈의 내용이다. V2 · V3 사이에 저장된 모듈도 V3 의 마이그레이션이 같은 규칙으로 푼다). 그 뒤 `presets` 를 지운다. 내려가기(`down`)는 모듈에서 프리셋을 다시 짓지 않고 빈 `presets` 를 만든다.
- 다른 곳이 쓰는 것은 옮긴다: `stripMarkers`(붙여넣기 · 상태 연산이 쓴다) · `renameStatesByName` · `renameCaseStates`(붙여넣기가 쓴다 — C 가 다시 짓는다).
- «페이지를 통째로 바꾸기»는 따로 두지 않는다 — 비우려면 지우고 모듈을 넣는다.

## C. 화면 상태 — 상태 트리 · 노드별 보임

### C1. 상태 목록이 트리다

- `PageDocument.viewStates?: { id, name, parent?: string }[]` — 평평한 목록에 부모 id 를 단다(목록 편집이 지금처럼 `/viewStates/…` JSON Patch · 잠금과 무관 · `guardViewStateOps` 그대로). 형제 차례는 목록 차례다.
- 규칙: 지금 규칙(이름 1 ~ 30자 · 받지 않는 글자 · 페이지 안 이름 유일 · 전체 20개 · id 는 노드 id 규칙 · `default` 금지)에 더해 `parent` 는 목록의 다른 상태 id · 고리 없음 · **깊이 3 이하**.
- «기본»은 목록에 없고 늘 있다(지금과 같다). 트리의 뿌리가 아니라 «상태를 고르지 않은 화면»이다.
- **부모-자식의 뜻: 물려받는다** — 자식 상태는 부모 상태의 경우를 좁힌 것이다(«로그인 > 관리자»). 보임 판정(C2)에서 «S 에서 보임»은 S 와 그 자손 상태에서 보임을 뜻한다.

### C2. 노드마다 상태 보임

- `WbNode.visibility?: { mode: 'only' | 'except', states: string[] }`
  - `only` — 나열한 상태(와 그 자손)에서만 보인다.
  - `except` — 나열한 상태(와 그 자손)에서 숨는다.
  - `states` 에 `'default'` 를 넣을 수 있다 — «기본» 화면(상태를 안 고른 화면). 자손이 없다.
  - 없으면 모든 상태에서 보인다. `states` 는 1개 이상 · 겹침 없음 · 목록에 있는 id 또는 `'default'`.
- **부모가 숨으면 자손도 숨는다**(그리지 않으니 당연하다). 자식의 `only` 가 부모를 되살리지 않는다.
- 판정은 schema 의 순수 함수 하나: `isVisibleIn(node, viewState, viewStates): boolean` — 렌더러 · 에디터 · exporter · MCP 가 같이 쓴다.
- 상태를 고른 채 편집해도 노드는 하나다 — «복사 + 편집» · 흐린 가지 · «모든 가지 보기» · 숨은 가지 편집 거절은 모두 걷는다.
- 새로 넣은 노드(팔레트 · 모듈 · 붙여넣기)는 보임 없이 들어간다 — 지금 고른 상태가 저절로 붙지 않는다.

### C3. 화면

- **메뉴 트리(좌측):** 페이지 줄이 접히는 줄이 되고 그 아래에 상태 줄이 트리로 선다.
  - 상태 줄을 누르면 그 페이지를 열고 그 상태를 고른다(이미 열려 있으면 상태만 바꾼다). 지금 고른 상태 줄이 켜짐(`aria-current`).
  - 상태 줄 `…`(editor 이상 · 편집 모드): 하위 상태 추가 · 이름 바꾸기 · 위로 · 아래로 · 삭제. 페이지 줄 `…` 에 «상태 추가».
  - 열린 페이지의 상태 줄은 열린 문서(실시간)에서, 다른 페이지는 트리 응답에서 짓는다 — **트리 응답에 페이지마다 `viewStates` 를 싣는다**(`routes/tree.ts`). 다른 페이지의 상태가 남에 의해 바뀐 것은 트리를 다시 읽을 때(`menu-changed` · 페이지 옮김) 따라온다.
- **머리 전환기** `[기본 ▾]` 는 **고르기만** 남긴다 — «상태 추가» · «상태 관리…» 항목과 상태 관리 상자를 걷는다(관리는 메뉴 트리에서). 좁은 창의 `…` 접기 · 뷰 모드 · viewer 의 고르기 · `?state=` 는 그대로. 항목은 트리 차례로 들여 써 보인다.
- **상태 삭제:** 확인 상자 — 그 상태와 하위 상태 이름, 보임이 걸린 노드 수. 지우면 (1) 하위 상태째 목록에서 빼고 (2) 모든 노드의 `states` 에서 그 id 들을 빼고 (3) `only` 인데 `states` 가 빈 노드는 **지운다**(그 상태에서만 보이던 내용 — 지금 «가지째 지움»과 같은 뜻), `except` 인데 빈 것은 보임을 걷는다. 편집 하나 · 되돌리기 한 번. 연 뒤 바뀌면 지금처럼 id 집합으로 견줘 다시 선다.
- **속성 패널:** 고정 칸 «상태 보임» — 없음 / 이 상태에서만 / 이 상태에서 숨김 + 상태 고르기(트리 차례 · 여럿 · «기본» 포함). 상태가 없는 페이지에서는 칸 대신 «메뉴 트리에서 상태를 더하세요» 한 줄.
- **구조 트리:** 모든 노드를 그린다. 지금 상태에서 숨은 노드는 흐리게 + «이 상태에서 숨김» 표지 — 고르고 고칠 수 있다(보임을 바꾸려면 골라야 한다).
- **캔버스:** 지금 상태에서 숨은 노드는 그리지 않는다. 숨은 노드를 고르면 캔버스에는 외곽선이 없고 구조 트리 · 패널로 다룬다. 영역 테두리 · 꼬리표(편집 모드) · «상태에 따라 다름» 단추(뷰 모드)는 걷는다.

### C4. 옛 문서 옮기기 — `StateSwitch` 를 걷는다

- 문서 판을 올린다(`PageDocument.version` 1 → 2). schema 에 `migratePageDocument(doc): PageDocument` 하나를 두고 **문서가 들어오는 모든 경계**가 부른다 — DB 마이그레이션(모든 `pages.schema`) · 스냅샷 복원 · 페이지 JSON 가져오기 · 클립보드 봉투 읽기(봉투 판도 올린다) · 프리셋 → 모듈 옮기기.
- 옮기는 규칙(상태 영역 하나마다, 안쪽 영역부터):
  - 기본 가지의 자식 → 영역 자리에 차례로 꺼내고, 다른 가지가 있으면 `except [그 가지들의 상태]`.
  - 상태 S 가지의 자식 → 그 뒤에 차례로 꺼내고 `only [S]`.
  - 바깥 영역의 가지 안에서 꺼낸 노드는 두 조건을 **합친 집합**을 명시 목록(`only [...]` — `'default'` 포함)으로 적는다(옮길 때 상태는 평평하므로 집합이 유한하다).
  - 꺼낸 노드가 이미 다른 데서 같은 id 를 쓰지 않는다(가지 복사가 새 id 였다) — 그래도 겹치면 마이그레이션이 실패로 멈추고 그 페이지 id 를 낸다.
- 걷는 것: 카탈로그 `StateSwitch` · `StateCase` · `THEMELESS_TYPES` 의 두 타입 · 상태 영역 연산(`view-state-ops.ts` 의 나누기 · 풀기 · 가지 복사 · 복사 + 편집) · `view-state-touch.ts` · 렌더러의 투명 노드 · 캔버스 영역 · 배지 · 풀기 상자 · lint `view-state-nested` · 422 `state-cases-left`(새 뜻: «편집이 목록에서 뺀 상태를 노드 보임이 가리킴»으로 바꾼다).

### C5. 읽기 · 내보내기 · LLM

- 렌더러: `RenderOptions.viewState` 그대로 — 그 상태에서 숨은 노드를 안 그린다(`hiddenByOverlay` 자리). 판정에 상태 트리가 필요하므로 렌더러는 문서의 `viewStates` 를 받는다.
- HTML 번들: 지금처럼 문서 전체를 싣고 셸의 상태 고르개(`<select>` — 트리 차례로 들여 쓴 이름) · `#state=`. PPTX 는 지금처럼 기본 상태만.
- 이름: 상호작용 문장 · 대상 고르개 · 번들 코멘트의 «'X'(관리자 상태)» — `only` 이고 상태 하나면 그 이름, 여럿이면 «'X'(관리자 · 손님 상태)», 그 밖은 붙이지 않는다.
- MCP: `get_page` 의 `nodes[].viewState` → `nodes[].visibility`(그대로) · 상태 목록에 `parent`. 스킬 문서(`packages/mcp/skill/SKILL.md` «화면 상태를 다룰 때»)를 새 꼴로 다시 쓴다. CLI `page-get` 의 상태 한 줄은 트리 차례.
- lint: `view-state-unknown`(보임이 목록에 없는 상태를 가리킴 — 저장 경계는 422 라 가져온 문서에서만) · `view-state-unused`(어느 노드도 안 가리키는 상태 — 정보).
