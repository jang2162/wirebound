# 컴포넌트 드래그 배치 — 설계

에디터 하단에 테마로 그린 축소판이 붙은 컴포넌트 목록을 두고, 카드를 구조 트리나 캔버스로 끌어다 놓아 새 노드를 넣는다. 캔버스에서는 고른 노드의 손잡이를 끌어 기존 노드도 옮긴다.

이 문서는 발행된 시점 기록(spec)이다. 구현이 병합될 때 정본 설계서(`docs/superpowers/specs/2026-08-03-wirebound-design.md`)의 「설계서 화면 구조」 절 — «캔버스 직접 드래그 편집은 지원하지 않는다» 문장과 하단 바 · 중앙 캔버스 문단 — 을 이 문서에 맞춰 고친다. 앞 과제: `docs/superpowers/specs/2026-09-30-editor-shell-design.md`(C — 하단 바 · 포인터 드래그 부품 · 트리 끌어 놓기).

---

## 목적과 범위

**목적:** 새 컴포넌트를 넣으려면 지금은 노드를 고르고 `+` → 타입 고르개에서 이름으로 고른다 — 무엇이 어떤 모양으로 설지 넣기 전에는 안 보인다. 테마로 그린 모양을 보며 원하는 자리에 끌어 놓게 한다. 캔버스에서 보이는 자리 그대로 옮길 수 있게 한다.

**범위 안:**

- 하단 컴포넌트 목록(열고 접는 판 · 갈래 탭 · 이름 검색 · 테마로 그린 축소판 카드)
- 카드를 구조 트리 · 캔버스에 끌어 놓아 새 노드 넣기 · 카드 클릭(Enter)으로 «고른 노드 뒤에» 넣기
- 캔버스에서 고른 노드의 손잡이를 끌어 옮기기
- 트리와 캔버스가 함께 쓰는 놓을 자리 판정

**범위 밖:**

- 테마 패턴 · 페이지 프리셋을 목록에 싣기 — 지금처럼 `+` 메뉴의 고르개에 남는다.
- 캔버스 노드를 아무 데서나 눌러 끌기(손잡이로만).
- 여러 노드를 한꺼번에 끌기 · 복사해 놓기(Alt 끌기 등).
- 터치 끌기 — C 의 드래그 부품이 터치에서 끌기를 세우지 않는 대가(C 이월 N6)를 그대로 둔다.

## 하단 컴포넌트 목록

### 열고 접기

- 하단 바에 «컴포넌트» 토글 단추(`aria-expanded`). **편집 모드이고 `canEdit` 일 때만** 선다.
- 펼치면 캔버스와 하단 바 사이(셸 그리드의 하단 영역 — `grid-template-areas` 에 `palette` 줄을 더한다)에 판이 선다. 다시 누르면 접힌다.
- 판 높이는 판 위쪽 손잡이(`ShellResizer` · `orientation="horizontal"`)로 끌어 조절한다 — 끌기 · 화살표 · Home/End · 두 번 눌러 기본값. 높이와 열림 여부는 사람마다 `localStorage` 에 기억한다(사이드바 폭과 같은 장치 · 접근이 던지면 기본값).
- 뷰 모드로 바꾸거나 권한이 viewer 로 내려가면 판이 닫힌다(기억한 열림 여부는 그대로 — 편집 모드로 돌아오면 다시 열린다).
- 판 높이의 최소 · 기본 · 최대와 캔버스 몫(캔버스 칸이 줄어드는 하한)은 구현이 실브라우저로 재서 정하고 머리말에 다시 재는 법과 함께 적는다.

### 목록 모양

- 위 줄: 갈래 탭(카탈로그의 `group` — 구조 · 데이터 · 입력 · 액션 · 문서) · 이름 검색 칸(한국어 이름 · 영문 타입명을 함께 찾는다).
- 아래: 고른 갈래의 카드가 가로로 늘어선 줄(넘치면 가로 스크롤). 검색어가 있으면 갈래를 가리지 않고 맞는 카드만.
- 카드: 축소판 + 한국어 이름(`ComponentDef.label`). 마우스를 올리거나 포커스가 오면 설명(`description`)과 영문 타입명이 툴팁으로 선다.
- 카드는 단추다(접근 이름 = 한국어 이름) — Tab 은 목록에 한 번 들어오고 화살표로 카드 사이를 옮긴다(로빙 탭 인덱스).

### 축소판

- 카드마다 그 컴포넌트의 갤러리 표본(`@wirebound/theme-gallery` 의 `GALLERY_SAMPLES` · `galleryItemDocument`)을 **프로젝트 테마(지금 바인딩 · 지금 토큰)** 로 그려 줄여 보인다.
- **판 하나에 iframe 하나** — 카드마다 iframe 을 두지 않는다. 그 iframe 은 캔버스와 같은 시트 차례(기본 뷰 CSS → `theme.css` link → 토큰 style)와 같은 테마 정의(번들 로더 캐시)로 표본들을 그리고, 카드는 그 iframe 의 해당 표본 자리를 보인다(잘라 보이는 방법 — 표본마다 그린 상자를 재서 카드에 맞춰 줄여 보이는 겹 — 은 구현이 고르고 적는다).
- 테마 · 토큰이 바뀌면(남의 저장 · `theme-changed`) 축소판도 따라간다 — 캔버스와 같은 공급자를 쓴다.
- 테마 번들을 못 실으면 캔버스처럼 SDK 기본 뷰로 그린다. 표본이 없는 컴포넌트는 그 컴포넌트를 카탈로그 기본 props 로 그린 노드 하나를 표본으로 쓴다.
- 축소판은 그림이지 조작 대상이 아니다 — 안의 단추 · 입력이 눌리거나 포커스를 받지 않는다(`inert`).

### 끌기와 클릭

- 카드를 끌어 구조 트리나 캔버스에 놓는다 — C 의 `usePointerDrag`(시작한 포인터만 · 4px 문턱 · Escape 취소 · 가장자리 스크롤). 끄는 동안 포인터 곁에 카드 이름표가 따라온다.
- **카드를 누르거나 Enter 를 치면 «고른 노드 뒤에» 넣는다.** 고른 노드가 자식을 받는 컴포넌트면 그 안 끝에, 고른 것이 없거나 뿌리를 골랐으면 페이지 끝에. 넣을 수 없으면(잠김 · 자식을 안 받는 자리) 카드 곁에 이유 문장을 세우고 요청을 안 보낸다.
- 넣은 새 노드는 고른 상태가 된다(트리 · 캔버스 · 속성 패널이 그 노드로).

## 캔버스에 놓기 · 옮기기

### 놓을 자리 판정

1. 끄는 중 포인터 아래 캔버스 노드를 찾는다 — 캔버스 iframe 문서의 `elementFromPoint`(호스트 좌표를 iframe · 줌 · 스크롤로 환산)에서 가장 가까운 `[data-wb-id]` 조상.
2. 그 노드의 그려진 상자를 셋으로 나눈다: 앞쪽 25% → 앞 형제 · 뒤쪽 25% → 뒤 형제 · 가운데 → 자식(자식을 받는 컴포넌트일 때만 — 아니면 앞 · 뒤 반씩).
3. **앞 · 뒤의 축은 부모의 배치를 따른다** — 부모 요소의 계산 스타일이 가로로 늘어놓는 배치(`display: flex` · `flex-direction: row`/`row-reverse`, `display: grid` 이고 형제 둘이 같은 줄에 선 판)면 왼 · 오른쪽, 아니면 위 · 아래. 테마마다 뷰가 달라 카탈로그가 아니라 그려진 결과로 읽는다. `row-reverse` 는 눈에 보이는 앞 · 뒤를 문서 차례로 뒤집는다.
4. 자식이 없는 빈 컨테이너는 상자 전체가 «안으로». 노드가 없는 바탕(페이지 끝)은 «페이지 끝».
5. 못 놓는 자리: 자기 · 자기 자손 안 · 남이 잡은 노드와 그 안 · 자식을 안 받는 컴포넌트 안 — 표시를 안 세우고 놓아도 아무 일도 없다.

판정의 끝(«대상 노드 + 구역 → 부모 id + 차례 | null»)은 트리와 캔버스가 **같은 함수**를 쓴다 — C 의 `edit/structure-drop.ts` 의 `structureDropTarget` 을 넓혀 «옮길 노드 id» 와 «넣을 새 타입» 둘을 받게 한다(새 타입은 카탈로그의 자식 허용 · 잠금 판정은 지금처럼 `blockedBy` — 서버와 같은 `lockConflictOfOps`).

### 표시

- 셸이 캔버스 iframe 위 겹에 그린다(지금 선택 외곽선 · 번호 마커와 같은 자리 · `pointer-events: none`) — 형제 자리는 가는 선, 자식 자리는 그 노드 상자 강조. C 의 `DropIndicator` 를 캔버스 좌표로 쓴다.
- 줌 · 캔버스 칸 스크롤을 반영한다. 캔버스 칸 끝 가까이 가면 칸이 저절로 스크롤한다.
- 끄는 동안 iframe 안의 노드는 그대로다(자리를 미리 비우거나 미리 넣어 보이지 않는다).

### 기존 노드 옮기기 — 손잡이

- 노드를 고르면 선택 외곽선의 왼쪽 위 모서리에 손잡이(⠿)가 선다 — 편집 모드 · `canEdit` 일 때만, 남이 잡은 노드 · 뿌리(페이지)에는 안 선다.
- 손잡이는 셸 겹의 단추다(접근 이름 «<이름> 옮기기» · 테마 CSS 가 덮지 못한다). 겹은 `pointer-events: none` 이므로 손잡이 단추만 `pointer-events: auto`.
- 손잡이를 끌면 그 노드를 옮긴다 — 위 판정 · 놓으면 `moveNodeOps`(트리 끌어 놓기와 같은 편집). 클릭만 하면 아무 일도 없다.
- 키보드로 옮기는 길은 트리 줄 `…` 의 위로 · 아래로 · 들여쓰기 · 내어쓰기다(C).

### 편집

- 새로 넣기: `insertNodeOps(document, parentId, index, node)` — 새 노드는 카탈로그 기본 props · 새 id. 지금 «추가»(타입 고르개)가 짓는 노드와 같은 함수로 짓는다.
- 옮기기: `moveNodeOps(document, nodeId, parentId, index)`.
- 둘 다 지금 편집 전송 길을 탄다 — 되돌리기 · 실시간 방송 · 잠금 판정 · 거절 수습(409 리베이스 · 423 통지). **놓는 순간 판정을 다시 한다** — 끄는 사이 남이 대상을 지우거나 잡았으면 편집 0.
- 끄는 중 페이지가 바뀌거나 캔버스 iframe 이 새로 서면 끌기를 취소하고 표시를 걷는다.

## 부품 경계

| 부품 | 하는 일 | 기대는 것 |
|---|---|---|
| `edit/structure-drop.ts`(넓힘) | «끄는 것(노드 id \| 새 타입) + 대상 + 구역 → 부모 id + 차례 \| null» | 카탈로그 · `lockConflictOfOps` |
| `canvas/canvas-drop.ts`(신규) | 캔버스 좌표 → «대상 노드 + 구역 \| 페이지 끝» — 줌 · 스크롤 환산 · 부모 배치 축(순수 함수 + 얇은 DOM 층) | 캔버스 iframe 문서 |
| `canvas/canvas-drag-handle.tsx`(신규) | 선택 외곽선의 손잡이 · 캔버스 끌기 표시 | `usePointerDrag` · `DropIndicator` |
| `palette/component-palette.tsx`(신규) | 하단 판 — 탭 · 검색 · 카드 · 열고 접기 · 높이 | `ShellResizer` · 카탈로그 |
| `palette/palette-thumbs.tsx`(신규) | 표본을 테마로 그린 iframe 하나와 카드별 잘라 보이기 | `theme-gallery` · 번들 로더 · 프로젝트 테마 공급자 |

C 의 `usePointerDrag` 는 손대지 않는다. 한 끌기가 트리 · 캔버스 두 대상 위를 지나가므로 «포인터 아래가 어느 대상인가» 를 고르는 얇은 층(트리 영역이면 트리 판정, 캔버스 칸이면 캔버스 판정)을 둔다.

## 테스트

- **jsdom:** 판정 순수 함수(구역 · 축 · 새 타입 · 자손 · 잠금 · 빈 컨테이너 · 페이지 끝) · 판 열고 접기와 권한 · 카드 클릭 추가(고른 것 없음 · 컨테이너 · 잎 · 잠김 · 뿌리) · 검색 · 로빙 탭 인덱스.
- **실브라우저(`apps/web/build-test/`):**
  - 목록 → 캔버스 · 트리에 놓기 → 서버 문서 · 되돌리기.
  - 손잡이로 옮기기 → 서버 문서 · 되돌리기 · 클릭만은 편집 0.
  - 두 클라이언트 — 끄는 중 남이 대상을 잡음 · 지움 → 편집 0 · 표시 걷힘.
  - 시스템 테마 다섯에서 가로 배치(카드 그리드 · 가로 무리) 안의 왼 · 오른쪽 판정.
  - 줌 0.5 · 1 · 1.5 · 스크롤된 캔버스에서 표시가 포인터 아래 노드에 맞음.
  - 축소판: 테마를 못 실음 · 남이 토큰을 저장함 → 따라감.
  - 끄는 중 캔버스 iframe 위 · 트리 영역 사이를 오감 · 끄는 중 페이지 옮김(취소).
- 게이트: `pnpm typecheck` · `pnpm build` · `pnpm test` · `pnpm test:build` · `pnpm test:browser` · `EDITOR_STACK_BUNDLE=build pnpm test:browser`.
