# 개인 모듈 · 기본 모듈 걷기 — 설계

사용자 요구(2026-10-20): **기본 모듈을 걷고, 하단 «모듈» 탭을 개인 모듈 · 프로젝트 모듈 · 테마 패턴 셋으로 구성한다.** 개인 모듈과 프로젝트 모듈 사이의 복사 길도 넣는다.

이 문서는 발행 시점의 기록(spec)이다. 구현이 병합되면 정본 설계서(`docs/superpowers/specs/2026-08-03-wirebound-design.md`)의 §9 «하단 판의 탭» · §9 «트리의 줄 행동» · §11.1 과 `apps/api/README.md` 가 지금 참인 것을 갖는다. 앞 설계 `2026-10-18-modules-states-layout-design.md` 「B3. 모듈」 의 «기본 모듈 셋을 내장한다» 를 이 설계가 걷는다.

---

## 왜

사용자의 말: 개인 모듈은 **다른 프로젝트에서, 또는 프로젝트와 별개로 나에게 맞춘 방식으로 화면 설계를 진행할 때** 쓴다. 프로젝트 모듈은 그 프로젝트 멤버가 함께 쓰는 묶음이고, 개인 모듈은 사람이 프로젝트를 옮겨 다니며 들고 다니는 도구함이다. 기본 모듈 셋(검색 + 목록형 · 상세 조회형 · 등록/수정 폼형)은 그 자리를 개인 모듈이 갖는다 — 남길 이유가 없다.

## 사용자가 정한 것

1. **기본 모듈 셋을 통째로 걷는다.** 그 자리를 다른 내장 묶음으로 채우지 않는다.
2. **«모듈» 탭의 묶음은 셋이고 차례는 «개인 모듈» · «프로젝트 모듈» · «테마 패턴»** 이다.
3. **개인 모듈은 사람이 소유한다** — 그 사람이 여는 모든 프로젝트에서 보이고, 같은 프로젝트의 다른 멤버에게는 안 보인다.
4. **저장 상자는 하나다** — «모듈로 저장…» 상자에서 «개인 / 프로젝트» 를 고른다.
5. **다른 프로젝트에 넣을 때 끊기는 연결은 뺀다** — 넣는 페이지에 없는 노드 · 그 프로젝트에 없는 페이지를 가리키는 동작을 빼고 그 수를 정보 통지로 말한다(지금 모듈 넣기의 거름 그대로).
6. **viewer 도 개인 모듈을 저장한다** — 내 것이라 프로젝트 권한과 무관하다. 페이지에 넣는 것은 지금처럼 editor 이상이다.
7. **복사 길을 넣는다 — 양쪽 다.** «프로젝트 모듈로 복사»(개인 → 이 프로젝트) · «개인 모듈로 복사»(이 프로젝트 → 내 것). 옮기기는 없다 — 원본은 그대로 남는다.

## 목표 · 아닌 것 · 실패

**목표**
- 개인 모듈을 저장 · 이름 바꾸기 · 삭제 · 넣기 · 복사할 수 있다.
- 기본 모듈의 흔적(코드 · 테스트 · 화면 묶음 · 문서)이 남지 않는다.

**아닌 것(이번에 안 한다)**
- 개인 모듈을 특정 남에게 나누기 · 공개하기.
- 옮기기(복사 뒤 원본 지우기는 사람이 한다).
- 모듈 내용 고치기 · 폴더 · 태그 · 설명 칸 — 모듈의 모양(`{ id, name, nodes, … }`)은 지금 그대로다.
- MCP · CLI 의 개인 모듈 길(지금 MCP 에도 모듈 도구가 없다).
- 실시간 방송 — 지금 프로젝트 모듈처럼 탭을 열 때와 쓰기 뒤에 다시 읽는다.

**실패로 치는 것(동작해도 실패)**
- **남의 개인 모듈이 보이거나 닿는다** — 같은 프로젝트 멤버든, 프로젝트 API 토큰이든, id 를 아는 사람이든.
- **프로젝트를 지우거나 프로젝트에서 빠지면 개인 모듈이 사라진다.**
- 복사가 원본을 바꾸거나 지운다.
- viewer 가 복사 길로 프로젝트에 쓴다(«프로젝트 모듈로 복사» 는 editor 이상).

## 동작

### 소유와 수명

- 개인 모듈은 **사용자 하나가 소유**하고 프로젝트에 매이지 않는다. 프로젝트 삭제 · 멤버에서 빠짐 · 역할 바뀜이 개인 모듈을 건드리지 않는다.
- 프로젝트 모듈은 지금 그대로다 — 프로젝트가 소유하고 프로젝트와 함께 지워진다.
- 읽기 · 쓰기 모두 **소유자 본인만** 한다. 남의 개인 모듈 id 로 온 요청은 «없다»(404)와 같은 답을 낸다 — 있는지를 알리지 않는다.

### 저장

- 구조 트리 줄 `…` «모듈로 저장…» 상자에 **«개인 모듈» / «프로젝트 모듈»** 고르기가 선다. 담을 노드 · 이름 칸 · 문장(«노드 N개를 모듈로 저장합니다 …»)은 지금 그대로다.
- 편집할 수 없는 판(아래 «편집할 수 없는 판의 입구»)에서도 «모듈로 저장…» 을 연다 — 고르기에는 «개인 모듈» 만 서고 프로젝트 쪽은 없다(아예 안 선다 — 빌더 재량으로 «꺼진 채 이유를 말함» 도 된다).
- **거름은 하나다** — 개인 저장도 서버에서 `@wirebound/schema` 의 `moduleNodesForSave` 를 지난다(번호 · 상태 보임 · 묶음 밖 노드를 가리키는 동작을 걷는다). 페이지를 가리키는 동작은 남는다 — 다른 프로젝트에 넣을 때 넣기의 거름이 뺀다.
- `Page` 는 담을 수 없다(422 `nested-page`) — 프로젝트 모듈과 같다.

### 넣기

- 개인 모듈 카드의 «넣기» · 끌어 놓기 — 자리 · 미리 그림 · 고르기 · 되돌리기 한 번 · 넣기 직전 다시 읽기(지워졌으면 «이 모듈은 지워졌습니다»)가 프로젝트 모듈과 같다.
- 노드 `id` 를 새로 짓고, 넣는 페이지에 없는 노드 · 이 프로젝트에 없는 페이지를 가리키는 동작을 빼고 그 수를 정보 통지로 말한다. 개인 모듈은 다른 프로젝트에서 저장됐을 수 있어 이 거름이 흔히 선다.

### 복사

- **개인 모듈 카드 → «프로젝트 모듈로 복사»** — 지금 연 프로젝트에 같은 이름 · 같은 노드로 프로젝트 모듈을 만든다. editor 이상만 선다.
- **프로젝트 모듈 카드 → «개인 모듈로 복사»** — 내 개인 모듈로 만든다. viewer 이상(목록을 읽을 수 있는 사람 모두)이 선다.
- 복사는 새 모듈이다 — 새 `id` · 새 `createdBy`(복사한 사람) · 새 시각. 원본과 이어지지 않는다(원본을 고치거나 지워도 사본은 그대로).
- 복사도 저장과 같은 거름 · 같은 한도 · 같은 검증을 지난다 — 복사는 «그 노드로 새로 저장»이다.
- 복사가 끝나면 그 목록을 다시 읽고, 결과를 정보 통지로 말한다(«'이름' 을 프로젝트 모듈로 복사했습니다»).

### 편집할 수 없는 판의 입구(사용자 결정 — 두 입구를 연다)

지금은 트리 줄 `…` 와 하단 판이 «편집 모드이고 editor 이상» 일 때만 선다(정본 §9 «트리의 줄 행동» · «하단 판의 탭», `apps/web/src/routes/editor.tsx` 의 `paletteEditable = mode === 'edit' && canEdit`). **편집할 수 없는 판 — viewer, 그리고 editor 이상의 뷰 모드 — 에도 두 입구를 연다.**

- **트리 줄 `…`** — 편집할 수 없는 판에서는 «모듈로 저장…» 한 항목만 선다(고르기는 «개인 모듈» 만). 그 밖의 줄 행동은 지금처럼 편집할 수 있는 판에서만 선다.
- **하단 판** — 편집할 수 없는 판에서는 «모듈» 탭만 선다(«컴포넌트» 탭은 없다). 그 판에서 «넣기» 단추와 끌어 놓기는 없다 — 문서를 바꾸지 않는다. 개인 모듈의 이름 바꾸기 · 삭제 · 프로젝트 모듈 카드의 «개인 모듈로 복사» 는 선다. 프로젝트 모듈의 이름 · 삭제 · «프로젝트 모듈로 복사» 는 editor 이상이므로 viewer 에게는 없다(editor 의 뷰 모드에서는 그 역할대로 선다 — 모듈 쓰기는 문서 편집이 아니다).
- 지금의 «편집할 수 있는가» 한 값을 **«판이 보이는가»** 와 **«넣을 수 있는가»** 둘로 나눈다. 역할을 읽는 자리는 `apps/web/test/role-access.test.ts` 의 경로 표를 따른다.
- 정본 §9 의 «viewer 에게는 없다» · «editor 이상일 때만 선다» 문장, 그 성질을 단언한 케이스(jsdom · 실브라우저)를 이 결정에 맞춰 고친다 — 고치기 전에 그 단언을 `git grep` 으로 센다.

**프로젝트 밖의 관리 화면은 두지 않는다(사용자 결정).** 개인 모듈은 에디터의 «모듈» 탭에서만 다룬다. 프로젝트가 하나도 없는 사람은 그동안 볼 수 없지만 데이터는 남는다.

### «모듈» 탭

- 묶음 차례: **«개인 모듈» · «프로젝트 모듈» · «테마 패턴»**. «기본 모듈» 묶음은 없다.
- 개인 모듈이 없으면 «구조 트리에서 노드를 골라 '모듈로 저장'에서 '개인 모듈'을 고르면 여기에 섭니다» 한 줄이 선다. 프로젝트 모듈 · 테마 패턴의 빈 문장은 지금 그대로다.
- 개인 모듈 카드: 이름 · «노드 N개» · «넣기»(editor 이상) · «이름 바꾸기» · «삭제» · «프로젝트 모듈로 복사»(editor 이상). 이름 바꾸기 · 삭제는 viewer 도 한다(내 것).
- 프로젝트 모듈 카드: 지금 그대로 + «개인 모듈로 복사».
- 검색 칸 «모듈 찾기» 는 세 묶음을 함께 거른다(지금과 같다).
- 목록은 탭을 열 때와 저장 · 이름 · 삭제 · 복사 뒤에 다시 읽는다.

## 기본 모듈 걷기

- `packages/schema/src/module/builtin.ts` · 그 export(`BUILTIN_MODULES`) · `packages/schema/test/builtin-modules.test.ts` 를 걷는다.
- 화면의 `builtin` 갈래(`apps/web/src/palette/module-tab.tsx` 등)와 그 케이스 · `shell.css` 의 그 묶음 꾸밈을 걷는다.
- 정본 설계서 §9 · §11.1, `apps/api/README.md`, 그 밖에 «기본 모듈» 을 말하는 지금 문서를 고친다. 이력 문서(`docs/superpowers/plans/*` · 날짜 붙은 앞 spec)는 그대로 둔다.
- 기본 모듈은 서버 데이터가 없으므로 마이그레이션이 없다.

## 제약

- **인증은 세션만이다.** API 토큰은 프로젝트 단위 스코프라(`apps/api/src/db/migrations/0011-api-tokens.ts`) 개인 모듈 길에 닿지 않는다 — 토큰으로 온 요청은 개인 모듈을 읽지도 쓰지도 못한다. 막는 장치는 이미 있다(`apps/api/src/auth/session-only.ts`). (제 결정 — 사용자가 정한 «MCP · CLI 길 없음» 과 맞물린다.)
- 개인 모듈의 소유자 칸은 사용자 행에 `ON DELETE CASCADE` 로 매인다. 지금 사용자를 지우는 길은 없다(`deleteFrom('users')` 0 곳). 프로젝트 모듈의 `created_by` 는 지금처럼 `RESTRICT` 다.
- 저장 한도(이름 1 ~ 60자 · 노드 수 · 본문 크기 등)는 프로젝트 모듈의 것을 그대로 쓴다. 개수 상한은 프로젝트 모듈에 없으므로 개인 모듈에도 두지 않는다.
- «이 프로젝트에 없는 페이지» 는 지금 넣기의 거름(`matchPageTargets`)이 정한다 — 페이지를 id 가 아니라 메뉴 경로 / 제목으로 견주므로, 다른 프로젝트에 같은 경로의 페이지가 있으면 그 동작은 남는다. 그대로 따른다.
- 프로젝트 모듈로 복사하는 쓰기는 지금 저장(`POST …/modules`)의 «프로젝트 행 잠금 → 삽입 → 재확인» 차례를 따른다.
- 마이그레이션은 이 저장소의 `apps/api/src/db/migrations/` 차례를 따르고 `down` 을 둔다.
- 화면에 역할을 보이는 자리를 새로 세우면 `apps/web/test/role-access.test.ts` 의 경로 표를 따른다(`.role` 읽기는 `projectAbilities(…)` 자리만).

## 빌더에게 맡기는 것

- 저장소 모양 — `modules` 에 소유자 칸을 더해 «프로젝트 하나 또는 사용자 하나» 를 CHECK 로 가르든, 표를 따로 두든.
- 엔드포인트 경로 · 본문 모양(예: `/api/me/modules`) · 복사를 서버 엔드포인트로 둘지 «읽고 새로 저장» 으로 화면이 할지. 다만 «남의 것은 404» · «viewer 는 프로젝트에 못 쓴다» 를 서버가 지켜야 한다.
- 저장 상자의 고르기 꼴(라디오 · 탭)과 기본값.
- 카드 행동이 늘어 넘칠 때의 배치(`…` 메뉴로 접기 등).

## 확인할 것(게이트)

- 실패로 치는 넷을 서버 케이스로 잠근다 — 남의 개인 모듈 404(세션 · 다른 멤버 · 프로젝트 토큰), 프로젝트 삭제 · 멤버 빠짐 뒤에도 개인 모듈이 남음, 복사 뒤 원본 그대로, viewer 의 «프로젝트 모듈로 복사» 거절.
- 화면은 묶음 차례 · 빈 문장 · 역할마다 · 모드마다(편집 / 뷰) 서는 단추와 탭을 jsdom 으로, 편집할 수 없는 판에서 넣기 길(단추 · 끌어 놓기 · 키)이 문서를 안 바꾸는 것을 실브라우저로, 다른 프로젝트에 넣었을 때 빠진 동작 수 통지를 실브라우저(`apps/web/build-test/module-tab.test.ts`)로 잰다.
- «기본 모듈» · `BUILTIN_MODULES` 를 `git grep -nwF` 로 세어 지금 문서 · 코드에서 0 임을 보인다(이력 문서는 셈에서 뺀다고 적는다).
