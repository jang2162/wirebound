# 상호작용 «화면 상태 바꾸기»(`setViewState`) 설계

## 왜

화면 상태(`viewStates`)는 «같은 페이지가 상황에 따라 다른 화면» 을 그리는 장치인데, 뷰 모드 · HTML 번들에서 그 상태로 **가는 길이 뷰어의 «화면 상태» 고르개 하나뿐**이다. 관리자 화면의 흔한 흐름 — 목록 행을 누르면 그리드 아래에 상세가 열리고 [취소] 로 닫힌다 — 를 설계서로 옮기면, 상세는 상태로 숨겨 두는 수밖에 없고 행 · 버튼으로는 열 수 없다. `setVisible` 은 상태가 숨긴 노드를 드러내지 못한다(렌더러가 그 노드를 그리지 않는다). SKALA LMS 관리자 프로젝트에서 39 페이지가 이 꼴이다.

## 무엇

상호작용 액션에 일곱째 `setViewState` 를 더한다.

```jsonc
{ "type": "setViewState", "target": "s_detail" }   // 그 문서의 viewStates id, 또는 "default"
```

- `target` 은 **그 상호작용이 든 문서**(페이지 · 팝업 페이지)의 `viewStates` 안 id 이거나 글자 `"default"`(상태를 고르지 않은 화면 — 상태 id 는 `default` 일 수 없으므로 겹치지 않는다).
- 뷰 모드 · HTML 번들에서 누르면 그 문서의 지금 화면 상태가 그 값이 된다. 상태가 바뀌면 그 상태에서 숨은 노드는 그리지 않고 보이는 노드를 그린다(지금의 `isVisibleIn` 판정 그대로).
- 한 상호작용의 액션 여럿은 차례대로 돈다 — `setViewState` 뒤의 노드 액션(`setProp` · `setVisible` · `switchTab`)은 바뀐 상태의 트리를 대상으로 판정한다.

## 어디서 도나

- **렌더러 런타임(`packages/renderer/src/interaction/runtime.ts`)은 상태를 들지 않는다** — `navigate` · `openModal` 처럼 **요청**(`InteractionRequest`)으로 내보낸다. 받는 쪽이 상태를 바꾼다.
- **웹 뷰 모드:** 받는 쪽은 그 페이지의 화면 상태 고르개와 같은 상태(`useViewState`)다 — 누르면 셸의 고르개도 그 상태를 보인다. **뷰 모드를 나가면 들어가기 전 고른 상태로 돌아간다**(「실행」의 «모드가 리셋» — 시연이 편집 화면의 고름을 바꾸지 않는다).
- **HTML 번들:** 받는 쪽은 번들 뷰어의 상태 고르개(`packages/exporter/src/browser/mount.tsx` 의 `setViewState`)다.
- **팝업 층:** 팝업 안의 `setViewState` 는 **그 팝업 겹의 상태**를 바꾼다. 팝업 겹은 제 상태를 들고(처음엔 기본), 닫으면 사라지고 다시 열면 기본이다 — 팝업 겹의 다른 런타임 상태와 같은 수명. 연 화면의 상태는 안 바뀐다.
- 편집 모드에서는 지금처럼 상호작용이 돌지 않는다.

## 판정 · 문장

- **검사(`packages/schema/src/interaction/check.ts`):** 대상이 `"default"` 도 그 문서 `viewStates` 의 id 도 아니면 이슈 `view-state-missing`(warning — 상태를 지우는 편집이 422 가 되지 않게 끊긴 노드 대상과 같은 무게). 런타임도 같은 함수로 판정해 누를 때 같은 문장을 낸다. 레이아웃 문서(상태 목록이 없다)의 `setViewState` 는 `"default"` 밖이면 같은 이슈다.
- **문장(`describe.ts`):** «② 화면이 ‘상세 열림’ 상태로 바뀝니다» · 기본이면 «② 화면이 기본 상태로 바뀝니다». 상태 이름은 다른 사람 글과 같이 방향 제어를 가둔다(`isolateBidi`). 끊겼으면 끊긴 노드 대상과 같은 꼴로 말한다.
- **lint · 저장 경계:** 봉투(`envelope.ts`)와 노드 타입(`node.ts`)의 액션 합에 더한다 — 서버 저장 · 편집 · 가져오기 · 스냅샷이 같은 판정을 받는다. 상태를 지우거나 id 가 바뀌는 편집은 없으니(id 는 이름을 바꿔도 그대로) 끊기는 길은 상태 삭제뿐이다.

## 에디터

- 상호작용 패널의 액션 고르개에 «화면 상태 바꾸기» 를 더한다. 대상 고르개는 그 페이지의 상태 트리(기본 + 목록 차례 · 깊이 들여쓰기)다. 상태가 없는 페이지에서는 «기본» 하나만 있고 «상태를 먼저 만드세요» 를 보인다.
- 상태를 지우면 그 상태를 가리키는 액션은 끊긴 대상으로 남는다(지우지 않는다 — 지금의 노드 대상과 같다).

## 하지 않는 것

- **다른 페이지로 가면서 그 페이지의 상태로 열기**(`navigate` + 상태) — 이번 범위가 아니다.
- **`setVisible` 이 상태가 숨긴 노드를 드러내는 것** — 두 장치의 우선순위를 섞지 않는다.
