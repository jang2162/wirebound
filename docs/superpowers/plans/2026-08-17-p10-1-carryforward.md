## 1. **받는 쪽을 무엇으로 재나** — 먼저 읽어라

### 1.1 자가 셋이고 **서로를 대신하지 않는다**

| 자 | 무엇을 보나 | 어떻게 부르나 | 아무 기계에서나 도나 |
|---|---|---|---|
| `test/pptx-package.test.ts` 의 *"파일이 열리는 조건"* | **파트·관계·콘텐츠 타입의 닫힘** — 규격이 요구하는 것 | `pnpm test` | **그렇다** |
| macOS **Spotlight**·**QuickLook** (`build-test/dist-pptx.test.ts`) | **빌드된 `dist` 가 낸 파일**을 Apple 의 OOXML 구현이 읽고 그리는가 | `pnpm test:build` | macOS 만. 없으면 **건너뛰고 그렇다고 말한다** |
| **Microsoft PowerPoint 16.112** | *"사람이 두 번 눌러 열면 열리는가"* | **§1.2 의 절차 — 사람이 손으로** | 아니다 |

**세 번째 것이 이 슬라이스의 결정적 자리였다.** 앞 판은 앞의 둘만 쓰고 *"받는 쪽이 열었다"*
로 읽었는데, **PowerPoint 는 그 파일을 거절했다** — 리뷰어가 찾았다(귀속: 리뷰 §1).
계획서 D6 이 *"「우리가 만든 규칙에 우리가 맞춘 것」과 「받는 쪽이 열었다」는 다르다"* 고 적은
자리가 정확히 이것이다.

**앞의 둘이 놓치는 것을 값으로 안다**(귀속: 리뷰 §1·§2 · 이쪽에서 재확인):

| 되돌린 것 | 우리 케이스 | Spotlight | QuickLook | **PowerPoint** |
|---|---|---|---|---|
| 테마 파트를 두 마스터가 나눠 쓴다 | **닫혔다**(새 자) | 통과 | 통과 | **복구 대화상자** |
| 매체 `png` 의 `Default` | **닫혔다**(새 자) | 통과 | **통과** | **복구** |
| 슬라이드 → 레이아웃 관계 | **닫혔다**(새 자) | 통과 | 상한에 걸린 정지 | **복구** |
| 매달린 `r:id` | **닫혔다**(새 자) | 통과 | 상한에 걸린 정지 | **복구** |

**둘째 줄이 가장 나쁘다 — 받는 쪽 둘 다 못 본다.** 그래서 규격을 재는 자(첫 줄)를 받는 쪽으로
대신할 수 없다.

### 1.2 **PowerPoint 를 자로 쓰는 절차** — 다음 사람이 쓸 수 있다

**앞 판의 이월은 *"자로 못 썼다"* 고 적었고 그것이 틀렸다.** 리뷰어가 우회를 찾았고
(귀속: 리뷰 §0) 이쪽에서도 같은 절차로 썼다.

```
1. 파일을 샌드박스 컨테이너 안에 둔다 — 여기서는 대화상자를 안 띄운다
   ~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/<아무 디렉터리>/
2. open -a "Microsoft PowerPoint" <그 파일>
3. osascript 로 값을 읽는다
   tell application "Microsoft PowerPoint" to count of presentations
   tell application "Microsoft PowerPoint" to count of slides of presentation 1
   tell application "System Events" to tell process "Microsoft PowerPoint"
     └ 창 이름 · 정적 텍스트 · 버튼 이름 → **복구 대화상자를 값으로 잡는다**
4. 쓰고 나서: close every presentation saving no · quit · **컨테이너 디렉터리를 지운다**
```

**주의 둘.**

- `tell application "Microsoft PowerPoint"` 블록 안에서 **`out` 을 변수 이름으로 쓰면
  `-10003 접근이 허용되지 않습니다`** 가 난다(PowerPoint 사전의 낱말과 부딪힌다).
  귀속: 리뷰 §0 — 그쪽이 15분을 잃고 적어 두었다.
- **`open -a` 뒤에 기다려야 한다.** 앱이 뜨고 파일을 여는 데 몇 초 걸리고, 그 전에
  `count of presentations` 를 부르면 0 이 나온다.

**대조군을 함께 돌려라.** 이 자는 *"안 열린다"* 와 *"절차가 안 돈다"* 가 같은 모양이다 —
그것을 가르는 유일한 길이 **열려야 하는 파일을 같은 절차로 먹이는 것**이다. 이쪽에서는
**앞 판의 패키지를 되만들어**(python 치환 + `finally`) 그 자리에 썼다.

### 1.3 그 절차로 **이쪽에서 잰 값**

| 파일 | PowerPoint 16.112 | 재현 |
|---|---|---|
| **고친 pptx**(슬라이드 셋 · 여러 줄 코멘트 · 상호작용) | `RESULT=OPENED presentations=1 slides=3` | **2/2** |
| **고친 pptx + 진짜 PNG 하나** | 같은 값. 첫 슬라이드 도형이 `제목 / **화면** / 설계 노트` | 1/1 |
| **앞 판을 되만든 것**(테마 파트 공유 · 대조군) | `RESULT=NOT_OPENED` · `TEXT[…내용에 문제가 있습니다…] BTN[취소] BTN[복구]` | 1/1 |

**PowerPoint 가 읽은 값 둘 더:**

- 오른쪽 칸 문단 **열** — `p3=첫째 줄 p4=둘째 줄 p5=셋째 줄` 로 갈린다(발견 3 이 닫혔다.
  앞 판은 `첫째 줄둘째 줄셋째 줄` 이었다 — 귀속: 리뷰 §3).
- 노트 페이지 도형 하나 · **147자 · 문단 열넷**. 곧 노트가 **파일에 들어 있고 PowerPoint 가
  읽는다** — 다만 **노트 창에서 잘리는지는 여전히 안 쟀다**(§4.2).

### 1.4 여전히 안 잰 것

- **노트가 사람 눈에 다 보이는가.** PowerPoint 가 글자를 읽는 것은 값으로 확인했지만
  노트 **창**에서 잘리는지는 화면을 봐야 안다.
- **글꼴 대체.** OOXML 테마가 `맑은 고딕`·`Calibri` 를 든다(`pptx/theme.ts`) — 그것이 없는
  기계에서 무엇으로 바뀌는지 모른다. 이 기계에는 둘 다 비슷한 것이 있어 가를 수 없다
  (귀속: 리뷰 §7 이 같은 이유로 못 쟀다).
- **끝에서 끝까지 한 번 돌린 것은 고침 **전**이다** — 진짜 api(3099)와 빌드된 `wireb` 로
  `.pptx` 를 받아 macOS 파서 둘에게 먹였다(보고서 §6.4). 고침 뒤에는 **같은 파트를 만드는
  `dist` 를 직접 불러** PowerPoint 로 쟀다(§1.3). 조립 결과는 같은 자리에서 나오지만
  **사슬 전체를 고침 뒤에 다시 돌린 것은 아니다.**

## 2. **D8 — ②가 정할 것.** 값으로 든다

### 2.1 이 슬라이스가 만든 **이미지 자리의 계약**

**②는 이 계약만 채우면 된다.** 그 밖은 안 건드려도 pptx가 나온다.

```ts
// @wirebound/exporter
export interface PptxScreen {
  fileName: string   // 확장자만 본다 — **png 뿐이다**
  bytes: Uint8Array
  width: number      // 화소. **비율에만 쓴다**
  height: number
}

exportPptx({ pages: [{ …, screen: PptxScreen | null }] })
```

| 무엇 | 값 | 어디가 강제하나 |
|---|---|---|
| **형식** | **PNG 하나** | `pptx/ooxml.ts`의 `MEDIA_TYPES`. 다른 확장자는 `exportPptx`가 **던진다** — `[Content_Types].xml`에 `Default`가 없으면 그 pptx가 **통째로 안 열린다** |
| **개수** | **페이지마다 0 또는 1** | `PptxPage.screen`이 값 하나다. 슬라이드 하나에 그림 둘을 놓는 자리는 없다 |
| **놓이는 자리** | `x=457200 y=1143000 w=6858000 h=5257800` EMU = **7.5in × 5.75in** | `pptx/geometry.ts`의 `SCREEN_BOX` |
| **크기** | **아무 크기나 된다.** 자리 안에 **비율을 지켜** 들어가고 가운데 정렬된다(`fitInto`) | 〃 · `pptx/index.ts` |
| **권하는 화소** | 자리를 꽉 채우려면 96dpi에서 **720×552**, 2배에서 **1440×1104**, 3배에서 **2160×1656** | 위 EMU를 나눈 값이다 |
| **이름** | **호출자가 준 이름을 안 쓴다** — 패키지 안에서 `image<N>.png`로 다시 붙인다. 두 페이지가 같은 이름을 주면 뒤엣것이 앞엣것을 덮어 **슬라이드 둘이 같은 그림을 그린다** | `pptx/index.ts`의 `mediaName` |
| **없을 때** | 슬라이드가 점선 상자에 *"화면 이미지가 실리지 않았습니다"*(`NO_SCREEN`)를 그리고, `ExportedPptx.screenless[]`가 그 페이지 이름을 낸다 | `pptx/index.ts` |
| **화소가 0·NaN 이면 비율을 버린다** | `fitInto`가 `!(width > 0)`에서 **자리를 그대로 쓴다** — 곧 이미지가 `7.5in × 5.75in`로 **늘어난다.** ②가 크기를 못 읽는 경로(스트림 등)로 오면 여기로 떨어진다. **그 갈래를 재는 케이스가 없다**(오늘 표본은 1600×900·1×1·8×8뿐이다) | 귀속: 리뷰 §6.1 |
| **크기 상한이 없다** | `zipParts`가 `Uint8Array` 하나를 내므로 **pptx 하나가 통째로 메모리에 올라간다.** 720×552 PNG 하나가 수십 KB라도 페이지 200장이면 자릿수가 달라진다 — **몇 장까지 재 봤는가를 아무도 안 쟀다** | 귀속: 리뷰 §6.1 · §4.2가 소유 |
| **`Default` 를 지키는 자** | **생겼다** — 매체가 있는 패키지에 그 확장자의 `Default`가 있는지 잰다(`pptx-package.test.ts`). ②가 형식을 하나 더하면 `MEDIA_TYPES`에 한 줄이고, 안 더하면 **거기서 죽는다** | `pptx/ooxml.ts` · 리뷰 §2 N3이 이 자를 요구했다 |

**바이트가 진짜로 실리는 것을 쟀다** — 진짜 PNG를 넣어 `ppt/media/image1.png`가 되고
**바이트가 그대로**인 것 · 슬라이드가 `a:blip r:embed`로 그것을 가리키는 것 · 비율이 유지되는
것이 케이스에 있다(`packages/exporter/test/pptx.test.ts`의 *"이미지 자리"* 절).

### 2.2 **그 이미지를 누가 만드나** — 후보 셋과 대가

**설계서가 이것을 안 정했다**(계획서 사실 2). §2의 *"렌더러 재사용으로 비용이 거의 없음"*은
**HTML을 만드는 이야기**이고(§11.3이 그 재사용이며 P8이 이미 했다) **래스터를 만드는 자리는
어디에도 안 적혀 있다.**

**아래는 재고이지 실측이 아니다.** 이 슬라이스가 실제로 잰 것은 표 아래의 **오늘의 사실
셋**뿐이고, 그 위는 그 사실 위에서 세운 판단이다. **P10-2는 고르기 전에 자기 손으로 재라.**

| 후보 | 얻는 것 | 대가 |
|---|---|---|
| **① 서버가 헤드리스 브라우저를 띄운다**(Playwright/Puppeteer + Chromium) | **충실도가 가장 높다** — `exportPage`가 이미 만드는 HTML을 그대로 열면 되고, 화면·번들·PPTX가 **같은 렌더러 한 벌**로 남는다(§2가 기대한 그림이다) | **새 바이너리와 새 배포 조건이다.** Chromium이 수백 MB이고 컨테이너 이미지·메모리·기동 시간이 전부 는다. **이 저장소에 오늘 Dockerfile이 없다**(쟀다) — 배포 형태를 정하는 판정이 이 후보에 딸려 온다. 내보내기 하나가 브라우저 프로세스를 띄우므로 **동시성과 타임아웃**을 정해야 하고, 그것은 `apps/api`가 오늘 갖고 있지 않은 부류의 상태다 |
| **② 이미 그 화면을 그리는 `apps/web`이 만든다**(브라우저에서 캔버스를 PNG로) | **새 바이너리가 0이다.** 그리는 브라우저가 이미 사람 앞에 떠 있고, 그 화면이 **정답 그 자체**다 | **서버가 pptx를 못 만든다** — 라우트가 이미지를 받아야 하므로 `GET .../export?format=pptx`가 **오늘의 모양을 잃는다**(브라우저가 이미지를 올린 뒤 조립을 요청하는 흐름이 된다). CLI(`wireb export --format pptx`)와 MCP는 **브라우저가 없으므로** 영영 이미지를 못 얻는다. `apps/web`에 DOM→PNG 라이브러리가 새로 든다(오늘 그런 의존이 **0개**다 — 쟀다) |
| **③ 순수 JS로 그린다**(레이아웃을 우리가 계산해 PNG를 만든다) | 의존이 작고 서버·CLI 어디서나 돈다 | **충실도가 관건이다.** §2.1이 도형 변환을 포기한 이유가 *"배경 그라디언트와 이미지가 들어온 이상 도형 변환은 성립하지 않는다"*였는데, **순수 JS 래스터라이저도 같은 벽을 만난다** — CSS를 다시 구현하는 일이고 §6의 테마가 그 위에 얹혀 있다. **렌더러가 하나뿐이라 결과가 어긋날 수 없다**(§11.3)는 문장이 **여기서 거짓이 된다** |

**오늘의 사실 셋 — 이건 쟀다:**

1. **이 저장소에 브라우저 의존이 0개다.** `playwright`·`puppeteer`·`canvas`·`html-to-image`·
   `satori`·`resvg` 중 어느 것도 `package.json` 어디에도 없다.
2. **`Dockerfile`이 없다.** 배포 형태가 아직 안 정해졌으므로 ①의 *"새 배포 조건"*이 얼마나
   비싼지는 **아직 아무도 모른다.**
3. **`exportPage`가 이미 페이지 한 장의 완전한 HTML을 값으로 낸다.** ①이 그것을 그대로 쓴다 —
   ②·③에는 그 지렛대가 없다.

**갈림을 좁히는 물음 하나:** *"CLI·MCP도 이미지가 실린 pptx를 받아야 하는가."* **그렇다면
②는 탈락이다.** 오늘 `wireb export --format pptx`가 서 있으므로 그 답을 아무도 안 정하면
②를 골랐다가 CLI가 영영 반쪽이 된다.

**표에 빠진 대가 넷**(귀속: 리뷰 §6.2 — 그쪽이 세어 지목했다):

| 빠진 대가 | 어느 후보 | 왜 판정에 필요한가 |
|---|---|---|
| **글꼴** | ① | 서버가 그리면 **그 기계에 한글 글꼴이 있어야 한다.** 없으면 목업이 통째로 두부가 되고 그것은 *"눈으로는 그럴듯한 한 장"*보다 나쁘다. §1.4의 *"글꼴 대체를 안 쟀다"*는 **OOXML 테마** 이야기이고 이것은 **래스터** 이야기라 다른 줄이다 |
| **내보내기 한 번이 페이지 N장을 그린다** | ①·③ | 비용은 프로세스가 아니라 **N번의 렌더**다. 페이지 수가 곧 슬라이드 수이고, §11.3 번들은 이미 페이지 수의 제곱이라는 관측이 있다(P8-2 이월 §4) |
| **무엇을 찍는가** | ② | *"그 화면이 정답 그 자체"*라고 적었는데 **화면은 뷰포트에 따라 달라진다.** 스크롤이 있는 페이지에서 뷰포트를 찍을지 전체를 찍을지가 안 정해지면 ②는 *"사람마다 다른 pptx"*가 된다 |
| **만든 것을 저장하나** | 전부 | 요청마다 다시 그리는지, 스냅샷처럼 저장해 두는지가 표에 없다. **①을 골라도 이 판정이 남고**, 저장한다면 그것은 `pages` 표 밖의 새 저장소다 |

### 2.3 P10-2가 함께 열어야 하는 자리 둘

1. **미리보기가 *"그 페이지의 이미지를 못 만들었다"*를 말해야 한다.** 오늘 pptx 미리보기는
   `screenless`만 내는데 그 값은 *"아직 아무도 안 만들었다"*이지 *"만들려다 실패했다"*가
   아니다. HTML 번들의 `errors`가 그 자리에 있다 — pptx도 그것에 해당하는 값이 생긴다.
2. **`screenless`가 오늘은 늘 전부라 정보가 없다.** ②가 서면 값이 되고, 그때 화면이 그것을
   그린다.

## 3. 이 슬라이스가 남긴 것

### 3.1 지도 갱신 — 무엇이 어디 있나

```
packages/exporter
```

**지켜야 하는 방향 셋:**

0. **테마 파트를 마스터끼리 나눠 쓰지 마라.** 아끼려고 되돌리면 **PowerPoint 가 파일을
   거절한다** — 값과 근거가 `ooxml.ts` 의 `SLIDE_MASTER_THEME` 머리말에 있고, 지키는 자가
   `pptx-package.test.ts` 의 *"마스터마다 테마 파트가 하나다"* 다. **글자는 여전히 한 벌**
   (`THEME_XML`)이라 색이 갈릴 길이 없다.
1. **`packages/exporter/src`는 zip 도 파일 시스템도 모른다.** `test/public-api.test.ts`가
   `src/**`를 훑어 그것을 센다. **`build-test`는 그 검사를 안 지난다** — 거기는 받는 쪽에게
   먹일 진짜 파일을 만들어야 해서 `fflate`를 쓴다(그래서 devDependency 로 들어왔다).
2. **코멘트 줄과 상호작용 문장을 만드는 자리는 하나다.** 지키는 자가 둘이고
   (`pptx-parity`는 값, `duplicate-census`는 소스) **후자는 부름의 개수를 센다** — 파일만
   세면 같은 파일 안의 두 벌을 못 본다(실측으로 반증됐다. 보고서 §4.3).
3. **압축하는 코드는 `export-zip.ts`의 `zipEntries` 하나다.** `zipBundle`과 `zipParts`는
   이름 짓는 규칙만 다르게 준다 — pptx에 뿌리 폴더를 씌우면 **파일이 통째로 안 열린다.**

### 3.2 바로 걸리는 자리

| 무엇 | 어디 | 왜 |

### 3.3 설계 문서와 어긋난 자리 하나 — **판정했고 문서는 안 고쳤다**

**§12.3이 `wireb export --format html -o dir`이라고 적었다.** 이 슬라이스가 `pptx`를 더했다.

**판정: §12.3의 그 줄은 그때의 값이지 닫힌 어휘가 아니다.**

- **§15가 그 값을 더하는 줄이다** — *"P10 PPTX 내보내기"*.
- **`--format`이라는 인자 자체가 P10을 위해 만들어졌다**(P9-3 D9 — *"다른 값은 사용법
  오류다"*). `html` 하나만 영원히 받을 것이면 그 인자가 있을 이유가 없다.
- **선례가 있다.** §11.3의 파일 목록도 *"예시이지 닫힌 목록이 아니다"*로 판정된 적이 있고
  (P8-2가 `assets/shell.css`를 더하며), 그때도 문서를 안 고쳤다.

**다음 사람에게:** 설계서를 손보는 판정이 서면 §12.3과 §11.3을 **함께** 보라 — 둘 다 같은
부류의 예시다.

## 4. **미결 장부** — P9-5 이월 §3을 갱신한다

**소유하는 문서로 가라.** ✱는 이 슬라이스가 값이나 사정을 더한 것이다.

### 4.1 이 슬라이스가 **닫은 것** — 하나

| 무엇 | 소유 | 상태 |
|---|---|---|
| **`export`가 바이너리 항목을 못 다룬다** | P9-3 이월 §6 · P9-5 이월 §3.2 | **닫혔다.** `Io.files.write`가 `string \| Uint8Array`를 받고, `zipParts`가 바이트를 그대로 담는다. P9-3 리뷰 N9가 *"P10(PPTX)·이미지 자산이 그 자리다"*로 예고했고 **그 예고가 정확했다** |

**✱ 그 *"닫혔다"*는 절반이다**(귀속: 리뷰 §5.4). P9-3 이월의 문장은 *"`export`가 zip의
바이너리 항목을 못 다룬다"*였고 **html 갈래는 여전히 못 다룬다** — 오늘 그것을 막는 것은
`BundleFile.content: string` **타입 하나뿐**이다. 장부에 적을 정확한 문장은
**"pptx 갈래는 닫혔고 html 갈래는 `BundleFile.content: string`이 막고 있다"** 다.
`PptxPart`를 따로 둔 판정(보고서 §2)이 그 타입을 지키므로 오늘은 정합적이다 —
리뷰어가 그 판정을 타당하다고 확인했다(귀속: 리뷰 §5.3).

**같은 줄의 앞엣것은 안 닫혔다** — *"`export`가 zip을 통째로 메모리에 올린다"*. ✱ **오히려
넓어졌다**: pptx도 통째로 올린다(`zipParts`가 `Uint8Array` 하나를 낸다).

### 4.2 이 슬라이스가 **더한 것**

| 무엇 | 상태 |
|---|---|
| ~~**PowerPoint로 못 쟀다**~~ | **닫혔다.** 리뷰어가 절차를 찾고(귀속: 리뷰 §0) 이쪽에서 같은 절차로 다시 쟀다 — §1.2·§1.3. **고친 pptx 가 열린다**(2/2, 이미지 실은 것도) |
| **노트의 상한을 안 쟀다**(재라 #7) | 열림. ✱ **PowerPoint 가 읽는 것까지는 값으로 확인했다**(노트 페이지 도형 하나 · 147자 · 문단 열넷 — §1.3). 그래도 *"노트 **창**에서 잘리는지"*는 화면을 봐야 안다 — 리뷰어도 같은 이유로 못 쟀다(귀속: 리뷰 §7) |
| **화소가 0·NaN 이면 비율을 버린다** | 열림. `fitInto`가 자리를 그대로 쓰므로 이미지가 늘어난다. **그 갈래를 재는 케이스가 없다**(귀속: 리뷰 §6.1) |
| **`describeInteraction` 아래로 더 내려가는 길** | 열림(관측). 센서스가 이제 `describeInteraction`을 분모에 든다 — 그런데 그 아래(`COMPONENT_NOUNS`·`propLabel`)로 또 내려가면 같은 부류의 사각이 다시 생긴다. **원시를 표에 더하는 것이 그때의 한 줄이다** |
| **형식 어휘가 두 자리에 있고 재는 자가 없다** | 열림. `packages/cli/src/commands/export.ts`의 `EXPORT_FORMATS`와 `apps/api/src/routes/export.ts`의 같은 이름. **다른 물음에 답하므로 같을 필요는 없는데**(보고서 §5.2) **`?format=`에 실리는 글자 하나는 같아야 한다.** `CLIENT_KIND_HEADER`가 같은 부류인데 그쪽은 `actor-census`가 두 소스에서 글자를 읽어 맞댄다(P9-5 이월 §4.5) — **이쪽은 그 자가 없다.** `apps/*`와 `packages/*`가 서로 의존하지 않는 것이 같은 사정이다 |
| **pptx가 슬라이드 사이 링크를 안 만든다** | 열림. §8.1의 `navigate`가 HTML 번들에서는 링크가 되는데 pptx에서는 **문장으로만** 실린다. OOXML은 슬라이드 하이퍼링크를 지원하므로 못 하는 것이 아니라 **안 한 것**이고, `duplicateTargets`·`brokenLinks`가 pptx 미리보기에 없는 이유이기도 하다. 만들면 그 넷을 다시 판정해야 한다 |
| **pptx 미리보기가 `errors`에 해당하는 값을 안 낸다** | 열림. §2.3-1이 이 줄이다 — **P10-2가 함께 연다** |
| **`screenless`가 오늘은 늘 전부다** | 열림(관측). §2.3-2 |
| **`packages/exporter`에 `fflate` devDependency가 생겼다** | 열림(관측). `build-test` 전용이고 `files: ["dist"]`라 배포에 안 실린다. `src`가 그것을 부르지 않는 것은 `public-api.test.ts`가 지킨다 |
| **`apps/web`이 pptx를 모른다** | 열림. 라우트가 섰고 화면은 그 뒤다(계획서가 슬라이스 밖으로 뒀다). 미리보기의 `format` 갈래와 `screenless`가 화면이 쓸 값이다 |
| **글꼴 대체를 안 쟀다** | 열림. OOXML 테마가 `맑은 고딕`(`a:ea`)·`Calibri`(`a:latin`)를 든다. 그 글꼴이 없는 기계에서 받는 쪽이 무엇으로 바꾸는지 모른다 — **줄바꿈이 달라지면 오른쪽 칸의 잘림도 달라진다** |
| **`createdAt`이 ISO 문자열 그대로 실린다** | 열림(관측). 슬라이드에 `2026-08-17T07:33:49.745Z`처럼 나온다. **HTML 번들도 같으므로 갈리지는 않는다** — 두 산출물을 함께 고치는 자리이고 `bundle/comments.ts`의 계약(`BundleComment.createdAt`이 문자열이다)이 그 뿌리다 |

## 5. 흔들리는 api 케이스 둘 — **이 브랜치의 관측**

**소유는 여전히 P9-4 이월 §3.1(ⓐ~ⓓ)이다.** 여기 적는 것은 이 브랜치가 그 그림을 어떻게
바꿨는가뿐이다.

| 축 | 값 |
|---|---|
| 코드 | `routes/export.ts`가 두 갈래로 갈렸다. **비-`GET` 라우트를 안 늘렸고** 편집 파이프라인·잠금·actor 자리는 안 건드렸다 |
| 부하 | api 테스트가 **파일 하나·케이스 열다섯** 늘었다(`export-pptx-route.test.ts`). **이름 순으로 `comments-concurrency.test.ts`보다 뒤다**(8번째 vs 13번째) — P9-5가 더한 둘은 앞이었으므로 **이 브랜치는 그 축에 다르게 얹힌다.** `pool: 'forks'`+`singleFork`라 앞엣것이 먼저 돌고, 곧 이 브랜치의 부하는 **그 케이스 뒤에 온다** |

**관측**(보고서 §7.1에 표가 있다):

| 축 | 실행 | 빨강 |
|---|---|---|
| 브랜치 · `pnpm test` | **6**(고침 전) + **1**(고침 뒤) | **1** |
| 브랜치 · `--project api` | **5** | **0** |
| `main`(0a55515, 분리된 HEAD 워크트리) · `pnpm test` | **3** | **0** |
| `main` · `--project api` | **3** | **0** |

**이 표본으로는 브랜치와 `main`을 못 가른다** — 1/6과 0/3은 같은 비율에서도 나온다.
**원인을 단정하지 마라.**

**P9-5가 남긴 갈림이 이어진다.** *"빨강이 `--project api` 축에서 0이고 `pnpm test` 축에서만
난다"*(ⓒ-1과 어긋나는 관측)가 **이 판에서도 같은 모양**이다. 두 판이 같은 방향을 가리키지만
사건이 둘이라 여전히 못 가른다 — 다음 사람은 **두 축을 갈라서** 세라.

| **슬라이드 사이 하이퍼링크** | §4.2가 이름 붙였다. 만들면 pptx 미리보기의 필드 넷을 다시 판정해야 한다 |
| **스냅샷의 *"그때"*를 pptx로 내는 것** | 출처가 라이브 프로젝트다(P8-4 D1). 수집이 한 자리(`export-source.ts`)이므로 **그것 하나를 payload에서 읽게 바꾸면 두 형식이 함께 따라온다** |
| **PPTX 테마를 §6의 테마와 잇는 것** | §2.1이 도형 변환을 포기했으므로 슬라이드의 화면은 래스터다 — 그 이미지가 이미 테마를 담고, 여기서 다시 칠하면 **같은 색이 두 자리에서 다르게** 나온다 |
| **PowerPoint 를 게이트에 넣는 것** | GUI 앱을 띄우고 자동화 권한을 요구하는 것은 게이트가 할 일이 아니고 `pnpm test:build`는 아무 기계에서나 돌아야 한다. **절차를 §1.2에 값으로 적어 사람이 돌리게 했다** — 파트나 관계를 건드린 사람은 그것을 한 번 돌려라 |
| **`.pptx`를 `wireb`가 여러 개 받는 것** | `-o`는 디렉터리이고 파일 하나가 떨어진다. 여러 프로젝트를 한 자리에 받는 흐름이 필요해지면 그때 판정한다 |
