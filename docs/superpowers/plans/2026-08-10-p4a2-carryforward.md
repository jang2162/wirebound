## 이 사이클이 닫은 것

### P0 이월 #7 — 구조가 inline style을 방출해 테마가 캐스케이드에서 진다

구조 구현체의 일반 선언이 **전부** 커스텀 프로퍼티로 바뀌었다(Flex·Grid·Tree·Media·Placeholder).
구조가 서기 위한 선언은 `packages/renderer/src/structure-css.ts`가 소유하고 `var()`로 읽는다.

```
구조 기본 CSS (renderer 소유)   ← 먼저 깔린다
theme JSON ─resolve─> ─compile─> 테마 CSS   ← 나중에 깔려서 이긴다
                                   ↓
                         apps/web <style> 둘 → 캔버스
```

**무엇이 이 판정을 지키는가 — 이것을 먼저 알아 둬라.**

| 지키는 것 | 어디 |
|---|---|
| **테마가 캐스케이드에서 이긴다** (판정 그 자체) | `apps/web/test/theme/cascade.test.tsx` — 같은 문서를 테마 둘로 그려 계산된 스타일이 갈리는 것. **옛 inline 선언을 되살리면 죽는다**(여러 웨이브에서 반복 확인) |
| 시트 **순서**가 곧 우선순위 | 같은 파일의 *"시트 순서를 뒤집으면 테마가 진다"* — 이것이 없으면 나머지가 "특이도 덕에 이겼다"로도 설명된다 |
| 구조가 일반 선언을 **안 낸다** | `packages/renderer/test/structures.test.tsx` — 등록된 모든 구조를 **비기본 props**로 전수 렌더 |
| `!important`가 **없다** | `cascade.test.tsx` · `structure-css.test.ts`. **`!important`를 쓰면 판정 자체가 사라진다** |

> **`style` 가드와 `data-*` 가드는 같은 순회(`forEachVariation`)를 쓴다.** 갈라 두었더니
> 한쪽만 비기본 props로 고치고 다른 쪽은 기본 props로 남는 사고가 실제로 났다 —
> 조건부 조각에 inline `color:red`를 심어도 944 케이스가 통과했다. 갈라 두지 마라.

### P0 이월 #8 — 6속성 계약 밖의 data 속성 3종

`data-wb-role`·`data-control`·`data-direction`이 전부 **`variantFrom`**으로
`data-wb-variant`에 접혔다. §5.1이 이미 갖고 있던 채널(boolean prop → `data-wb-state`)의

가드가 **둘이고 서로의 사각을 덮는다** — 원문 스캔(`contract-attrs.test.ts`)은 렌더되지

**한쪽만으로는 뚫린다는 것을 실측했다**(아래 "배운 것").

| **`bgGradient`+`bgImage`** | 선언이 **둘 나가고 문서 키 순서가 이긴다.** 이슈로 내지 않는다 | 같은 프로퍼티를 두 번 적는 것은 CSS 관용구다. 진짜 문제는 저장이 순서를 지우는 것이고 **그것은 P4a-3의 맥락**이다 |
| **`@media` vs `states`** | **`@media`가 이긴다.** 순서를 바꾸지 않는다 | 실제 브라우저에서 상태 0.5 vs 반응형 0.9 → **0.9**. `pushResponsive`가 맨 뒤이고 두 셀렉터가 둘 다 `(0,2,0)`이다. 상태가 반응형을 이겨야 한다는 요구가 설계에 없다 |
| **`assets.fonts`** | 여전히 **`@font-face`를 내지 않는다** | P4a-1의 근거(P8이 URL을 다시 쓴다)에 더해 **§6.8에 `fontFamily`가 없어** 내도 걸 방법이 없다 |
| **`url()`의 대상** | 검증하지 않는다(그대로 나간다) | 브라우저가 **실제로 요청을 보낸다**(Chromium에서 `ERR_NAME_NOT_RESOLVED`). **막을 CSP가 이 앱에 없다** |
| **이슈 폭포** | 사용자에게 쏟지 않고 **콘솔에만** | 토큰 하나를 어긋내니 이슈 **6건**(근원 1 + 그것에 기댄 5). 화면에 뿌리면 근원을 나머지가 가린다 |

### `ignored-variant` — 새 `ValidationCode`

`variantFrom`을 가진 컴포넌트에 `node.variant`가 있으면 **그 값이 버려진다.** 고치기 전에는
갈리는 입력 둘이 **하나는 거짓 양성, 하나는 침묵**이었다:

| 입력 | 고치기 전 | 지금 |
|---|---|---|
| `variant:'없는변형'` + `role:'h1'` | `unknown-variant` — 아무 영향 없는 값 때문에 문서가 무효 | `ignored-variant` |
| `variant:'caption'` + `role:'h2'` | **이슈 0건** — 조용히 사라진다 | `ignored-variant` |

- **`variantFrom`이 있으면 `unknown-variant`를 내지 않는다.** 선언된 값이든 아니든 똑같이
  무시되므로 "정의되지 않았다"가 원인을 잘못 가리킨다.
- **문안은 `schema`가 소유한다**(`ignoredVariantMessage`). `themes`의 `checkPatterns`가 같은
  문장을 쓰고, 두 문자열이 글자까지 같은 것을 케이스가 대조한다. **코드는 일부러 갈랐다** —
  `themes`에 평행한 유니온을 만들면 따로 썩는다.

## 어느 쪽도 아닌 것

- **재라 #8 — `@media`가 캔버스 폭이 아니라 창 폭을 본다.** 실측했다: 프레임이
  `width:400px`+`scale(0.5)`인데 창 1200px에서 `(max-width:768px)`가 안 맞고, **프레임은
  그대로 두고 창만 700px로 줄이니 맞았다.** **§6.4의 문장이 성립하지 않는다.**
  고치려면 컨테이너 쿼리로 가야 하는데 그것은 §6.11의 컴파일 계약과 P5 내보내기를 함께
  건드린다(`@container`도 재봤는데 `container-type` 조상이 없어 아무것도 안 맞았다).
- **CSP가 없다.** `apps/web`·`apps/api` 어디에도 `Content-Security-Policy`를 세우는 자리가
  없어 `url()`의 대상을 막을 것이 아무것도 없다. P5 내보내기·배포가 정할 일이다.
- **브라우저 측정이 자동 회귀에 없다.** jsdom이 `var()` 치환과 `@media`를 못 재서 Chromium으로
  **한 번** 쟀다(계획서의 §측정 결과). 다른 엔진에서는 재지 않았고, 그 측정은 다시 돌지 않는다.
- **에디터를 실제로 띄워 보지 않았다.** 테스트와 정적 페이지 측정까지다.

## 이 사이클에서 배운 것

### 구분력 실증이 **무음으로 실패할 수 있다** — 이 프로젝트의 검증 관행 전체에 걸린다

**변이를 심었다고 믿었는데 안 심어졌고, 그 결과 초록인 것을 "구분력이 없다"로 읽을 뻔했다.**

수정 웨이브에서 메시지 문안을 바꾸는 변이가 **전부 초록**이었다. 구분력이 없다고 보고하려던
참에 치환에 `assert`를 붙여 보니 **대상 문자열이 없었다** — `str.replace`가 조용히 원본을
그대로 쓴 것이다. 고쳐 다시 재니 케이스가 죽었다.

> **"변이를 심었더니 안 죽었다"와 "변이가 안 심어졌다"가 겉으로 구별되지 않는다.**
> 둘 다 초록이다. 그리고 이 저장소는 **구분력 실증을 품질의 근거로 삼는다** — 그 근거가
> 무음으로 비는 경로가 있다는 뜻이다.

**How to apply: 변이를 심을 때 심어졌는지부터 확인한다.** 치환에 `assert`를 붙이거나,
심은 뒤 `grep`으로 눈으로 본다. 이 사이클의 마지막 웨이브에서 그 습관이 **또 한 번**
잡았다 — `shell.css`에 `:root {`가 없는데 그것을 찾아 치환하려 했다.

리뷰어도 같은 교훈을 적용해 이번 웨이브의 실증 여덟을 **assert로 다시 심어** 8/8을 확인했다.

### `git checkout --`으로 변이를 되돌리면 **커밋 전 작업이 함께 날아간다**

Task 3의 구분력을 확인하며 `git checkout -- <file>`로 되돌렸는데 그 파일의 **구현이 아직
커밋 전이라** 함께 사라졌다. 알아채고 다시 적용했고 오염된 측정 하나를 다시 쟀다.
**이후로는 python 치환/복원만 썼다.**

### 계획서가 확정해 적은 산문이 **다섯 자리에서 반증됐다**

D3의 이름 규칙 · `--wb-tree-indent` 손잡이 · `id: 'system:admin'` · `useThemeCss(): void` ·
Grid 트랙 어휘. **P4a-1에서 둘이었던 것이 이번에 다섯이다.**

> **"재라"로 넘긴 자리는 매번 걸렸고, 확정해 적은 것은 구현 중에야 드러났다** — P4a-1의
> 관찰이 그대로 반복됐다. 계획서는 **계약과 테스트를 상세히 쓰되 구현의 세부는 재게 남기는**
> 편이 낫다.

### 두 가드가 있어도 **사각의 교집합이 비어 있지 않을 수 있다**

`data-*` 계약을 원문 스캔과 렌더 결과 스캔 둘로 지키고 있었는데, 조건부 조각에
`{...{ 'x://y': '', 'data-wb-bad': '1' }}`를 심으니 **둘 다 통과했다** — 원문 쪽은 문자열
안의 `//`를 주석으로 보고 그 줄을 지우고, 렌더 쪽은 기본 props라 그 조각을 안 그린다.

> **가드가 둘이라는 사실이 사각이 덮인다는 뜻은 아니다.** 각자가 무엇을 못 보는지 적고,
> **그 교집합에 실제로 심어 봐야** 안다.
