## 결정과 이유

- **판 2 → 3 옮기기는 DB 마이그레이션 안에 얼린다** — 브리프 «판 2 를 읽는 코드를 런타임에 남기지 않는다» 와 설계 Q1 (가) «`liftStateRegions` 옆 단계» 가 갈려 `q-ns2.md` 에 물었고, 코디네이터가 기본값(브리프)으로 답했다. 런타임 `MIGRATIONS` 에 2 → 3 단계가 없다 — 판 2 문서(가져오기 · 클립보드)는 «버전 2에서 올릴 마이그레이션이 없습니다» 로 거절된다. 옮기는 자리: `pages` · `layouts` · `modules` · `personal_modules`(코디네이터가 더함) · `snapshots.payload` 의 페이지 · 레이아웃. `revisions` 는 안 옮긴다.

- **기본 내용은 노드로 든다 · 서버는 짓지 않는다** — 설계 그대로(`createNode` 가 카탈로그 `initial` 을 짓는다). MCP · REST 로 만드는 쪽은 `/llms.txt` · MCP 스킬의 «함께 넣으라» 를 읽는다.
- **카드의 «소제목 + 오른쪽 단추» 줄 = 테두리 없는 변형** — 사용자 결정 Q4 (가). 기본테마 manifest 의 `Card` 변형에 `borderless`(«테두리 없음»)를 더했다.
- **구조 트리 구역 줄은 보이기만 한다** — 고르기 · 넣기의 대상 · 빈 구역 칸(Q2) · 펼쳐 보이기(Q3)는 구현 B 몫이라 안 지었다.
- **놓을 자리 판정에 받는 타입 · 설 자리를 넣었다** — 원래 B 의 «받는 타입 제약의 이유 문장» 과 이웃하지만, 판 3 이 탭 몸통을 좁혀 캔버스가 거절될 미리보기를 세우는 회귀가 실브라우저 오라클에서 났으므로 이번에 판정만 넣었다(이유 문장은 B). 진단 이유는 `not-accepted` 하나.
- **번들 바이트 해시를 새로 지었다** — 바뀐 바이트의 출처를 갈라 적었다(아래).
