P4b-3이고, 그때 이 판정을 열려면 **먼저 `src`·`family`의 값 규칙을 세워야 한다.**

### #2 — §6.8 대조 케이스 → **둘로 갈랐다**

### #4 — `variant`를 패널에 어떻게 여는가 → **A안(패널이 특수 취급)**

**코디네이터에게 물어 확인받았다.**

| | |
|---|---|
| **관찰** | `defineComponent`의 66–75줄이 *"editor가 스키마에 없는 prop을 가리킵니다"*로 던진다 — 계획서 D3이 맞다. `Button`·`Link`·`List`·`Section`·`Card`의 변형 **열넷**이 UI에서 하나도 닿지 않았다 |
| **원인** | `EditorField.prop`은 props의 키인데 `variant`는 노드 봉투의 필드다(§4.3) |
| **결정** | A안. 패널이 읽는 것이 **전부 카탈로그의 값**(`def.variants`·`def.variantFrom`)이고 새로 갖는 지식은 *"variant는 봉투의 필드다"* 하나인데 그것은 §4.3·§6.11이 정한 **모델의 사실**이다. B안이 담을 정보는 **라벨 하나**뿐이라 §5.1의 계약을 넓힐 값어치가 없다 |
| **자리** | `apps/web/src/panels/property-panel.tsx`의 `variantFieldOf` 머리말 |

**코디네이터가 지목한 넷을 전부 처리했다:**

1. **경로를 가르는 자리를 하나로 모았다** — `edit/ops.ts`의 `variantOps`. `/props/variant`가
   아니라 `/…/variant`다.
2. **게이트가 UI에서 도달 불가인 것을 카탈로그 전수로 실행해 확인했다** — 선택지가
   `def.variants` 그대로라 `unknown-variant`가, `variantFrom`이 있으면 컨트롤이 안 나와
   `ignored-variant`가 닿지 않는다. **음성 대조 둘**로 그 검사가 살아 있는 것도 고정했다.
3. **비우기는 `remove`다** — `WbNodeSchema.variant`가 `z.string().optional()`이라 `replace
   null`은 봉투 검증을 통과하지 못한다. 빈 칸이 없으면 한 번 고른 변형에 갇힌다.
4. **undo가 그 경로를 지난다** — `invertOps`가 `/variant`를 props와 다르게 다루지 않고,
   세 갈래(`add`/`replace`/`remove`)의 왕복이 원본으로 돌아온다.

### #5 — 커스텀 프로퍼티 채널의 소유자 → **갈랐다**

| 무엇 | 소유 | 왜 |
|---|---|---|
| 어휘 이름(`treeIndent`)과 그것이 내는 CSS 이름 | `themes` | 테마 문서를 검증하는 것이 이 패키지다 |
| 그 CSS 이름을 **읽는 규칙** | `renderer`(`TREE_INDENT_VAR`) | 손잡이는 구조 구현체의 것이다 |
| 두 문자열이 같은지 | **`apps/web`의 케이스** | `themes`는 `renderer`를 볼 수 없다(§3.3) — 둘 다 보는 자리가 거기뿐이다 |

**임의 커스텀 프로퍼티는 열지 않았다.** 열면 §6.8 화이트리스트가 무의미해진다 — 무엇이든
`--x`로 내보내고 그것을 읽는 규칙이 저쪽에 있으면 우회로가 된다. **손잡이마다 별칭 어휘
하나**가 그 제한을 지키고 값 규칙(토큰 참조·리터럴·함수 금지)도 그대로 쓴다.

`schema`로 옮기면 대조가 필요 없어지지만 §5.1의 `ComponentDef`에 손잡이 필드가 없어
**계약을 넓히는 일**이 된다 — 전역 제약이 금지하는 부류다.

**Chromium 실측 — 손잡이가 실제로 살아났다:**

| 테마 | level 0 | level 1 | level 2 |
|---|---|---|---|
| `Tree.base.treeIndent: '40px'` | `0px` | **`40px`** | **`80px`** |
| 그 어휘를 안 씀(대조군) | `0px` | `16px` | `32px` |

jsdom은 **커스텀 프로퍼티 상속을 계산하지 않아**(조각에서 빈 문자열) 두 조각으로 나눠
자동 회귀에 담고 마지막 한 걸음만 브라우저로 했다. **그 측정은 다시 돌지 않는다.**

### #7 — `--wb-container-max` → **예시가 줄여 쓴 것이다**

**근거를 같은 예시 안에서 실행으로 셌다** — §6.11 `:root` 블록의 변수 넷 중 **셋은 규칙과
정확히 일치하고 그 하나만 어긋난다.** 규칙이 틀렸다면 넷이 다 어긋나야 한다.

예외를 두지 않는 이유 둘: `cssVarName`은 경로 → 이름의 순수 규칙이고 예외 하나가 표가 되면
`primitives`가 늘 때 낡는다. 그리고 예외를 두면 작성자가 `container.max`를 쓸 수 있다고
읽는데 규격은 `maxWidth`라 그 문서는 `unknown-token`이 된다.

### #8 — `Grid.props.gap` → **더하지 않는다. §6.6 예시가 틀렸다**

| | |
|---|---|
| **관찰** | 그 예시를 그대로 테마 패턴에 넣으면 `bad-pattern-node`(severity `error`)로 **테마 전체가 해석되지 않는다.** 페이지 노드에 넣으면 `invalid-props`다 |

### #9 — 새 어휘가 구조 기본 CSS와 다투는 자리 → **테마가 이긴다**

계산된 스타일로 쟀다. 테마가 `Grid.base.gridColumns: 5`를 선언하면
`grid-template-columns`가 `repeat(5, 1fr)`이고 노드가 나른 `--wb-node-grid-columns`는

> **`Grid`에서 그 조합은 침묵이다** — 사용자가 캔버스에서 정한 열 수가 화면에 안 나타나는데
> 이슈가 하나도 나지 않는다. 컴파일 시점에 노드를 모르므로 신호를 낼 자리가 없다.

> `Grid`는 노드 prop이 이미 있어 테마가 덮을 이유가 없다.

## 5. 설계 문서와 어긋난 것 (설계는 고치지 않았다)

**이 슬라이스가 새로 만든 것 셋** — §6.8에 없는 어휘를 더했다:

|---|---|

**`STYLE_PROPERTIES_BEYOND_SPEC`에 근거와 함께 등록했고, 대조가 양방향으로 지킨다.**

**앞서부터 있던 것 넷을 판정했다:**

| 자리 | 판정 |
|---|---|
| §6.6 예시의 `Grid.props.gap` | **예시가 틀렸다** — `gap`은 테마의 어휘이고 노드 props는 토큰 해석기를 지나지 않는다 |

| §5.1의 *"editor에서 자동 생성"* vs `variant` | **패널이 `variants`도 읽는다** — 그 절이 말하는 *"컴포넌트 **정의**에서 자동 생성"*은 그대로 성립한다 |

**P4a-1이 세운 원칙 그대로 규격이 이기고 예시·산문이 틀린 것으로 봤다.**

## 7. P4b-2·P4b-3으로 넘길 것

### P4b-2(구조 구현체 26개)가 **구조를 만들기 전에** 알아야 할 것

| 무엇 | 왜 |
|---|---|
| **`Media.kind`의 답을 P4b-2가 낸다** | `MediaVideo`가 `MediaImage`와 다르게 그리면 `kind`는 구조와 중복이라 지우는 것이 맞고, 구조들이 `kind`를 읽을 일이 있으면 남는다. **오늘은 죽어 있고 그것이 케이스로 고정돼 있다** — 구조가 그 값을 읽기 시작하면 `kind를 바꿔도 렌더 결과가 글자까지 같다`가 먼저 죽는다 |
| **`kind`는 "조용히 틀린다" 부류다** | 속성 패널에 `종류` 컨트롤이 **있고** 사용자가 `video`를 고르면 문서에 저장되고 검증도 통과하는데 **화면은 아무것도 안 바뀐다.** 노드가 `video`인데 `data-wb-structure="image"`가 나가고 이슈는 0건이다 |
| **part 이름 계약이 이제 조건부 조각을 본다** | 구조를 만들 때 카탈로그에 없는 part 이름을 내면 **그 자리에서 죽는다.** 전에는 조용했다 |
| **`defineComponent`가 도달성을 검사한다** | 컴포넌트를 늘릴 때 `states`의 항목과 `variantFrom`이 가리키는 prop이 `editor`에 없으면 **import가 던져 저장소 전체가 멈춘다**(파일 65개 실측) |
| **`List:cardGrid`를 만들면 `gridColumns`가 처음 쓰인다** | 오늘 그 구조에는 기본 CSS 규칙이 **없다**. 트랙을 테마가 정하는 것이 D1이 닫은 구멍이다 |
| **테마가 `Grid.base.gridColumns`를 쓰면 노드의 열 수가 침묵으로 무시된다** | 계산된 스타일로 쟀다. 시스템 테마가 그것을 쓰지 않는 것으로 피하는 것이 오늘의 답이고, 이슈를 낼 자리가 없다 |
| **`Section`·`Card`의 `variants`가 이제 UI에서 고를 수 있다** | 어느 테마도 그 이름을 정의하지 않으므로 **고르면 아무 일도 일어나지 않는다.** 검증은 통과한다(선언된 값이다) |

## 8. 재지 않은 것 — 알고 남긴다

- **에디터를 실제로 띄워 보지 않았다.** 테스트와 Chromium 정적 페이지 측정까지다.
  속성 패널이 커진 뒤의 화면이 쓸 만한지는 **재지 않았다**.
- **Chromium 측정은 자동 회귀에 없다.** `--wb-tree-indent`의 상속과 `calc` 치환은 한 번만
  쟀고 다시 돌지 않는다(P4a-2·P4a-3과 같은 제약).
- **`admin` 컴파일 결과의 크기를 다시 재지 않았다.** 새 어휘를 쓰지 않아 그대로다.
- **api를 기동해 스모크를 돌리지 않았다.** 이 슬라이스가 api 소스를 건드리지 않았고,
  전체 회귀에 api 케이스가 전부 포함돼 통과했다(`.env`는 `.env.example`에서 만들었다).
- **성능 벤치(`inverse-bench.test.ts`)가 한 번 흔들렸다.** 부하 때문이고 재실행에서 통과했다 —
  그 파일도 `invertOps`도 이 슬라이스가 건드리지 않았다(diff 0).
