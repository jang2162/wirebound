- `node.ts` · `envelope.ts` — 액션 합 일곱째 `{ type: 'setViewState', target }`(봉투는 `strictObject` — 다른 키를 받지 않는다).

- 노드를 옮기는 자리 — 대상이 상태 id 라 노드 id 로 다루면 안 된다.
  - 붙이기(`prepareNodesForPaste`): 붙일 페이지에 그 상태가 없으면(`keep.state`) 액션을 빼고 센다 · 기본은 늘 남는다. 웹의 이름 맞춤(`apps/web/src/edit/paste-states.ts` 의 `renameVisibilityStates`)이 보임처럼 대상도 같은 이름의 상태 id 로 옮긴다.

## 결정

1. **상태 id `default` 는 이미 못 만든다** — 봉투 `ViewStateSchema` 가 `id !== DEFAULT_VIEW_STATE` 를 거절한다(`envelope.ts`). 이 트랙에서 더할 막음이 없다.
2. **lint 규칙을 새로 두지 않고 ③ 줄을 넓혔다** — «대상 노드가 삭제된 상호작용 규칙» → «대상 노드 · 화면 상태가 삭제된 상호작용 규칙». 상태 대상이 끊긴 것은 같은 부류(할 일이 같다 — 대상을 다시 고르거나 규칙을 지운다)이고, 규칙을 갈라 두면 그 절에 줄이 하나 는다.
4. **요청 모양은 브리프의 `{ kind: 'viewState', target }` 이 아니라 기존 요청과 같은 `{ type: 'setViewState', target, sourceNodeId }` 다** — 받는 자리(`canvas-popups` · 번들 `mount` · 갤러리)가 `request.type` 으로 가른다. 한 합에 판별 키가 둘이면 받는 자리마다 두 키를 본다.
5. **같은 누름의 뒤 액션** — 브리프 기본값 그대로다. 런타임은 상태를 몰라 `setViewState` 뒤 `setProp` 은 지금 숨은 노드여도 겹layer에 얹힌다(대상 판정은 «문서에 있는가» 뿐). 설계서 「무엇」 의 «바뀐 상태의 트리를 대상으로 판정한다» 는 «그 노드가 그 상태에서 보이는지는 묻지 않는다» 와 같은 뜻으로 읽었다 — 설계서 사본의 그 문장을 고쳤다(태스크 7).
6. **레이아웃 노드의 `setViewState`(대상은 기본만 맞다)도 같은 요청을 낸다** — 받는 쪽은 그 요청이 레이아웃에서 왔는지 모르므로 페이지의 상태를 기본으로 바꾼다. 레이아웃에는 상태가 없어 «그 문서의 상태» 가 따로 없다.
7. **뷰 모드를 나가면 들어가기 전 고름으로 되돌리는 것은 «뷰 모드 동안의 상태를 따로 든다» 와 같은 결과를 되돌림으로 짓는다** — 브리프 기본값은 뷰 모드 동안의 상태를 따로 들고 전환기가 그것을 보이게 하는 쪽이다. `useViewState` 를 읽는 자리(전환기 · 캔버스 · 구조 트리 · 속성 패널 · 주소)가 다섯이라 따로 든 값을 다섯 곳이 갈라 읽게 하는 대신, 들어갈 때 적고 나갈 때 되돌린다. 뷰 모드 동안 전환기로 고른 것도 나가면 되돌아간다(시연의 일부다).
8. **웹의 팝업 겹 요청은 두 겹으로 막힌다** — 층이 요청에서 빼고, 캔버스의 팝업 쪽 처리(`onPopupEvent`)는 애초에 상태 요청을 안 받는다. 그래서 층의 거름을 뗀 변조(W4)는 번들 판에서만 죽는다(번들은 페이지와 팝업이 같은 `handle` 을 지난다).
3. **붙이기 · 모듈 · id 재발급을 계획 밖에서 고쳤다** — 셋 다 `isPageTargetAction` 이 아니면 노드 대상으로 읽어, 고치지 않으면 붙인 `setViewState` 가 «붙일 문서에 그 노드가 없다» 로 빠졌다(대상이 상태 id 라 늘 빠진다). 설계서 「하지 않는 것」 에 없는 회귀라 들였다.
