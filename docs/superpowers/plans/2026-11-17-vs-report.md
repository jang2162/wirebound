## 바꾼 것

### 태스크 1 — 스키마

- `node.ts` · `envelope.ts` — 액션 합 일곱째 `{ type: 'setViewState', target }`(봉투는 `strictObject` — 다른 키를 받지 않는다).
- `interaction/check.ts` — `isViewStateAction` · `checkViewStateAction(viewStates, action)`. 기본(`default`)은 늘 맞고, 빈 대상은 «아직 고르지 않았습니다», 목록 밖은 «페이지의 상태 목록에 없습니다». 코드 `view-state-missing`.
- `validate.ts` — `ValidationCode` 에 `view-state-missing`(경고). `validateTree` 가 문서의 `viewStates` 를 받아 상호작용 검사에 넘긴다. 레이아웃 · 프리셋 묶음은 목록이 없어 기본만 맞다.
- `interaction/describe.ts` — «화면이 ‘상세 열림’ 상태로 바뀝니다» · «화면이 기본 상태로 바뀝니다» · 지운 상태는 «사라진 상태» · 안 고른 것은 «아직 고르지 않은 상태». 이름은 `isolateBidi`.
- lint — `view-state-missing` 은 «대상 노드 · 화면 상태가 삭제된 상호작용 규칙»(`interaction-target`) 으로 나른다. 정본 「12.4 lint 규칙」 의 그 줄과 `lint/rules.ts` 의 `spec` 을 같은 커밋에서 고쳤다(`lint-rules.test.ts` 대조).
- 노드를 옮기는 자리 — 대상이 상태 id 라 노드 id 로 다루면 안 된다.
  - 붙이기(`prepareNodesForPaste`): 붙일 페이지에 그 상태가 없으면(`keep.state`) 액션을 빼고 센다 · 기본은 늘 남는다. 웹의 이름 맞춤(`apps/web/src/edit/paste-states.ts` 의 `renameVisibilityStates`)이 보임처럼 대상도 같은 이름의 상태 id 로 옮긴다.
  - 모듈 저장(`moduleNodesForSave`): 기본이 아닌 상태로 바꾸는 액션은 뺀다(보임을 걷는 것과 같은 까닭 — 상태는 페이지마다 따로다).
  - id 재발급(`remapNodeIds`): 상태 대상은 노드 id 표로 옮기지 않는다.

## 결정

1. **상태 id `default` 는 이미 못 만든다** — 봉투 `ViewStateSchema` 가 `id !== DEFAULT_VIEW_STATE` 를 거절한다(`envelope.ts`). 이 트랙에서 더할 막음이 없다.
2. **lint 규칙을 새로 두지 않고 ③ 줄을 넓혔다** — «대상 노드가 삭제된 상호작용 규칙» → «대상 노드 · 화면 상태가 삭제된 상호작용 규칙». 상태 대상이 끊긴 것은 같은 부류(할 일이 같다 — 대상을 다시 고르거나 규칙을 지운다)이고, 규칙을 갈라 두면 그 절에 줄이 하나 는다.
3. **붙이기 · 모듈 · id 재발급을 계획 밖에서 고쳤다** — 셋 다 `isPageTargetAction` 이 아니면 노드 대상으로 읽어, 고치지 않으면 붙인 `setViewState` 가 «붙일 문서에 그 노드가 없다» 로 빠졌다(대상이 상태 id 라 늘 빠진다). 설계서 「하지 않는 것」 에 없는 회귀라 들였다.
