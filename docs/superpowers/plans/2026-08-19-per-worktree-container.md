# 워크트리마다 컨테이너 구현 계획 — 이름 고정 해제, 포트를 `.env`로

> **에이전트에게:** 태스크 단위로 실행한다. 실패하는 케이스 → 최소 구현 → 통과 → 커밋.

**사용자가 정한 것.** *"컨테이너 고정 해제 하고 개방 포트 `.env`에서 설정 가능하도록"* ·
그리고 **"워크트리마다 완전 별개(컨테이너·포트·데이터 전부)"**.

**목표.** 워크트리마다 자기 Postgres를 띄운다. 그리고 **부딪히거나 엇갈리면 조용하지 않다.**

**이것은 앞 슬라이스(`2026-08-19-worktree-isolation`)의 판정을 뒤집는다.** 그때는
*"컨테이너는 하나를 공유하고 DB 이름만 가른다"*였고 사용자가 그것을 다시 정했다.
**앞 슬라이스가 세운 것을 부수지 말고 무엇이 남고 무엇이 낡는지 판정하라.**

**스택.** `docker-compose.yml` · `apps/api/.env.example` · 문서 · 케이스.

---

## 전역 제약

- **워크트리 안에서만 작업한다.**
- **게이트는 넷이다.** `pnpm test` · `pnpm typecheck` · `pnpm build` · `pnpm test:build`.
  전부 0이어야 하고 **종료 코드를 파이프 없이 따로 찍어라.**
- **사용자의 데이터에 손대지 마라. 이 슬라이스에서 가장 중요한 줄이다.**
  - 지금 설계서가 사는 볼륨은 **`feat-p1-api_wirebound-pgdata`**(14 users·16 projects·358 pages)다.
    **읽지도 쓰지도 지우지도 마라.**
  - **`docker compose down -v` 절대 금지.** **`wirebound-postgres` 컨테이너를 지우거나
    다시 만들지 마라** — 그것은 메인 세션 소유다.
  - 검증은 **전부 임시 프로젝트 이름·임시 볼륨·임시 포트**로 하고 끝나면 지워라.
  - **볼륨을 옮기는 일은 메인 세션이 병합 때 한다.** 네가 하지 마라.
- **`git checkout --`을 쓰지 마라.** python 치환 + `finally`로 원본 전문 되쓰기.
- **0 사망이 나오면 그렇다고 보고해도 된다. 원인을 단정하지 마라.**
- **자를 구현 파일에 두지 마라.** **수를 산문에 적지 마라.**
- **설계 문서(`docs/superpowers/specs/*`)는 고치지 않는다.**
- **남이 잰 값은 귀속을 붙여 옮긴다.**

## 확정한 결정

### D1. **이름을 풀고 포트를 연다 — 그러나 방어를 걷어내는 값을 치러야 한다**

사실 1·3이다. `container_name`을 지우면 compose가 `<project>-postgres-1`로 짓고, 포트를
`${…:-5433}`으로 열면 워크트리마다 다른 포트를 쓸 수 있다.

- **판정: 둘 다 한다.** 사용자가 정했다.
- **그 대가:** 사실 3의 방어가 사라진다. **누가 포트만 바꾸고 데이터를 옛 볼륨에 두고
  왔다고 착각하는 길**이 열린다. **그것을 조용하지 않게 만드는 것이 D3이다.**
- **기본값은 오늘과 같아야 한다**(5433). **아무것도 안 바꾼 사람이 안 깨진다.**

### D2. **포트가 두 자리에 있으면 자가 잡는다 — 이것이 이 슬라이스의 급소다**

**compose가 읽는 값**(호스트 포트)과 **`apps/api/.env`의 `DATABASE_URL` 안에 박힌 포트**가
**어긋나면 API가 남의 컨테이너에 붙는다.** 앞 슬라이스가 프록시에서 닫은 것과 **정확히 같은
부류**이고, 이번엔 DB다.

- **한 자리에서 오게 하라.** 사실 6을 재고(재라 #1), `apps/api/.env` 하나로 모을 수 있으면
  모아라(`docker compose --env-file …`).
- **한 자리로 못 모으면 어긋남을 자가 잡아라** — `DATABASE_URL`의 포트와 compose가 쓸 포트가
  같은지 재는 케이스. **산문으로 "맞춰라"라고 적지 마라.**
- **앞 슬라이스의 인구조사 셋이 이 부류를 어떻게 잡았는지 읽고 같은 결로 만들어라**
  (`stripComments`를 지나고, 배선이 가리키는 자리까지 잰다).

### D3. **빈 DB로 시작한 것이 조용하면 안 된다**

사실 3의 방어가 사라지므로, **새 볼륨으로 뜬 컨테이너**를 사람이 *"데이터가 사라졌다"*로
읽는 길이 열린다. **완전 별개를 고른 이상 빈 DB는 정상이다** — 다만 **말해야 한다.**

- **무엇으로 말할지 정하고 케이스가 들게 하라.** 후보: 서버가 뜰 때 자기가 붙은 포트·DB와
  **마이그레이션이 0건인지**를 말하는 것.
- **`docker volume ls`로 옛 볼륨을 찾는 길**이 문서에 이미 있다(README §6.3). **그 절이
  이제 "충돌이 막아 준다"를 전제하므로 고쳐야 한다.**

### D4. **앞 슬라이스가 세운 것 중 무엇이 낡는지 판정하라 — 부수지 마라**

사실 5다. 이제 **포트가 갈리므로 DB 이름까지 가를 필요가 없을 수 있다.**

- **판정하라:** `DATABASE_URL`·`TEST_DATABASE_URL`의 DB 이름 가르기가 **여전히 필요한가.**
  필요 없으면 **기본값을 단순하게 되돌리되 그 메커니즘을 지우지 마라**(한 컨테이너를
  공유하고 싶은 사람이 여전히 쓸 수 있다).
- **인구조사와 케이스를 지우지 마라.** 앞 슬라이스의 자들이 아직 지키는 것이 있는지 재고,
  낡은 것만 정확히 걷어라.
- **사실 4가 값을 하나 준다** — 볼륨이 매번 새로 생기면 `01-test-db.sql`이 **다시 돈다.**
  그러면 `wirebound_test`를 손으로 만드는 걸음이 사라질 수 있다. **재고 판정하라.**

### D5. **문서가 계약이다 — 두 벌을 만들지 마라**

- **README §3.1(절차)·§6.3(볼륨 함정)·§6.4(테스트 DB)가 전부 바뀐다.**
- **`CLAUDE.md`의 워크트리 절도 바뀐다** — *"컨테이너는 워크트리마다 띄우지 않는다"*가
  뒤집힌다. **README가 소유하고 CLAUDE.md가 가리킨다**(앞 슬라이스가 그렇게 정했다).
- **오늘 이 기계의 컨테이너가 `feat-p1-api` 프로젝트로 떠 있다는 것**과 **설계서 데이터가
  그 이름의 볼륨에 있다는 것**을 문서가 계속 들어야 한다 — **메인 세션이 병합 때 옮길
  것이므로 "옮긴 뒤의 이름"으로 적지 말고, 옮기는 일이 있다는 것과 찾는 법을 적어라.**

### D6. **되돌릴 수 있어야 한다**

- **아무것도 안 바꾼 사람이 오늘처럼 돌아야 한다** — 포트 5433, 같은 접속 문자열.
- **케이스가 그 기본값을 든다.**
