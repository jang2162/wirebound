## 1. 중앙 디렉터리 판독기 대 fflate `unzipSync`

fflate 0.8.3 `unzipSync`(`lib/node.cjs` 2693–2733)와 `readCentralDirectory`(`packages/themes/src/wbtheme/read.ts:167`)를 한 줄씩 대조했다. 갈리는 자리 셋:

| 자리 | 판독기 | fflate |
| --- | --- | --- |
| 항목 수 | EOCD `+10`(전체 항목 수) | EOCD `+8`(이 디스크의 항목 수) |
| zip64 | 표지 `0xFFFF…` 가 있으면 거절, **로케이터는 안 본다** | EOCD 앞 20 바이트에 로케이터(`0x07064b50`)가 있으면 zip64 EOCD 의 수 · 오프셋을 믿는다 |
| stored 항목의 크기 | 원래 크기(`+24`)를 더한다 | 압축 크기(`+20`)로 자른다(`slc(data, b, b + sc)`) — 원래 크기는 안 본다. deflate 만 원래 크기로 버퍼를 잡는다 |

### 넣은 입력 · 답 · 실린 것

| 입력 | 판독기 | 실린 것(`readWbtheme` 의 `files`) |
| --- | --- | --- |
| 1a EOCD disk=3 · total=2, 셋째가 `theme.js`(`/*UNCHECKED*/`) | 통과 | `themeJs = '/*UNCHECKED*/'` |
| 1a' 같은 판, 셋째가 `assets/../../evil.html` | 통과 | `assets` 에 `assets/../../evil.html` |
| 1b 선량한 zip 끝에 zip64 EOCD + 로케이터, 그것이 앞의 다른 중앙 디렉터리(`theme.js` · `../outside.txt`)를 가리킴 | 통과 | `themeJs = '/*ZIP64-EVIL*/'`, fflate 는 `../outside.txt` 도 풂(허용 목록 밖이라 `files` 에는 안 들어감) |
| 1c stored · 원래 크기 0 · 1 MB 로컬 하나를 항목 63 개가 가리킴 | 통과 | 자산 61 MB |
| 로컬 머리 이름 `../../evil.js`, 중앙 이름 `theme.js` | 통과 | fflate 도 중앙 이름을 쓴다 — 같음 |
| `theme.js` 둘 | `bad-path`(같은 경로 둘) | — (fflate 는 뒤 것 `second` 를 실었을 것) |
| 주석 속 가짜 EOCD | `missing-manifest` · `missing-theme-js` | fflate 도 가짜를 골라 `{}` — 같음 |
| `assets\..\x.png` · `assets/a\0.png` | `bad-path` | — |
| `assets/．．/x.png` | 통과 | `assets/．．/x.png` — 1e |
| `．．/theme.js` | `not-allowed` | — |
| `assets/` · `theme.css/` 디렉터리 항목에 데이터 | 통과 | 둘 다 `filter` 가 걸러 안 풂 — 같음 |
| 압축 방식 99 | `bad-zip`(fflate 가 던짐) | — |

- **판정:** 1a · 1b · 1c 결함, **높음**(입력 경계를 넘음 — 경로 · 허용 목록 · 풀린 크기 검사를 비켜 간다). 업로드가 관리자 세션만이라 쏠 사람은 좁지만, 이 검증은 받은 패키지를 믿지 않으려고 둔 것이다.
- **빨강 케이스**(`wbtheme-reader-divergence.test.ts`):
  - «EOCD 의 «이 디스크의 항목 수» 가 …» → `expected '/*UNCHECKED*/' not to be '/*UNCHECKED*/'`
  - «같은 판에서 판독기가 안 본 허용 밖 경로가 …» → `expected [ 'assets/../../evil.html' ] to not include …`
  - «zip64 로케이터가 가리키는 …» → `expected '/*ZIP64*/' not to be '/*ZIP64*/'`
  - «stored 항목의 원래 크기를 0 으로 …» → `expected 56623115 to be less than or equal to 52428800`
  - 단언은 성질이다 — 거절하면 초록, 통과했으면 실린 것이 판독기가 본 것이어야 한다.
- **원인:** 판독기가 fflate 와 **다른 칸**을 읽는다(항목 수 · zip64 · stored 크기). `read.ts:44-47` 머리말의 전제 «fflate 는 원래 크기만큼만 버퍼를 잡는다» 는 deflate 에만 참이다.
- **고칠 방향:** 판정을 fflate 가 실제로 읽는 것에 맡긴다 — `unzipSync(bytes, { filter })` 에서 `filter` 가 늘 `false` 를 돌려 풀지 않고 fflate 의 항목 목록(이름 · `size` · `originalSize` · `compression`)을 받고, 그 목록이 판독기 목록과 이름 · 차례까지 같은지 본다(다르면 `bad-zip`). 크기 합은 항목마다 `max(size, originalSize)` 로 센다. 덧붙여 EOCD `+8 ≠ +10` 과 로케이터가 있는 zip 을 거절한다. CLAUDE.md «손 판독기를 피할 수 없으면 물을 점만 고르게 하고 판정은 실물에 맡긴다» 의 꼴이다.
- **잰 방법의 한계:** fflate 0.8.3 한 판만 쟀다. zip 은 손으로 지었다(`zipSync` 는 이런 머리를 안 쓴다). 1e 는 뒤에 자산 이름으로 파일을 쓰거나 URL 로 내는 소비자가 서면 다시 잰다(지금 `readWbtheme` 을 부르는 곳은 `theme-kit build` 와 테스트뿐).

## 2. 토큰 값 → `tokensCss`

`checkTokenValue`(`packages/themes/src/manifest/tokens.ts:49`)는 `font` · `shadow` 에서 `; { } <` 만 막는다. `color` 는 꼴(`COLOR_FN` 은 안쪽에 `(` · `*` · `"` 를 못 담는다), `length` 는 꼴, `number` 는 유한수, `select` 는 선택지 목록으로 닫혀 있다.

### 실 Chrome 값

시스템 Chrome(`/Applications/Google Chrome.app`, `editor-stack.ts` 의 `chromeCandidates` 첫 판)을 playwright-core 로 헤드리스로 띄우고, 로컬 http 서버의 페이지에 `tokensCss` 출력을 한 `<style>`, 테마 규칙을 다른 `<style>` 로 실었다. 토큰 넷(`a.font` · `b.shadow` · `c.color` · `d.color`) 가운데 첫째에 값을 넣었다. «선언 수» 는 `:root` 규칙의 `style.length`(정상 4), 요청은 `page.on('request')` + 서버 로그.

| 값(모두 `checkTokenValue` 통과) | `:root` 선언 수 | 효과 |
| --- | --- | --- |
| `Arial /*` | 1 | 뒤 토큰 셋이 사라짐 |
| `Arial (` · `Arial [` | 0 | 제 것 포함 전부 사라짐 |
| `Arial "` · `Arial '` | 2 | 제 것과 바로 뒤 선언(`--wb-b-shadow`)이 사라짐 |
| `Arial \` | 3 | `;` 가 이스케이프돼 뒤 선언을 제 값으로 삼킴(`"Arial \;\n  --wb-b-shadow: none"`) |
| `Arial )` | 3 | 제 선언만 무효 — 밖 효과 없음 |
| `Arial \7d  #b \7b color: red` | 4 | 이스케이프는 식별자 글자일 뿐 — 밖 효과 없음 |
| `Arial !important` · `Arial\nx` · `@import url(…)` · `expression(alert(1))` · `var(--wb-c-color)` · 1 MB 값 | 4 | 밖 효과 없음, 요청 없음 |
| `url(http://…/font-url)` | 4 | 테마가 `font-family` · `box-shadow` 에 쓰면 요청 없음 · **`background-image: var(--wb-a-font)` 에 쓰면 `/font-url` 요청** |
| `image-set("http://…/shadow-imageset" 1x)`(shadow) | 4 | 같은 꼴 — 이미지 속성에 쓰면 `/shadow-imageset` 요청 |

토큰 CSS 와 뒤 규칙이 **한 시트**면(`css-concat.mjs` — `tokensCss(...).css + '#x { background-color: rgb(7,7,7) }'`): `Arial /*` · `Arial (` 에서 시트 규칙 수 2 → 1, `#x` 배경이 `rgba(0,0,0,0)` — 뒤 규칙까지 죽는다. 따옴표 · `\` 는 규칙 경계를 넘지 않았다.

- **판정:** 2a 결함, **중간** — owner 가 고친 값 하나가 다른 멤버 캔버스 · 내보낸 번들에서 다른 토큰을 무너뜨리고, A4 가 토큰 CSS 를 테마 CSS 와 한 시트로 합치면 테마 규칙까지 죽인다(`checkTokenValue` 머리말의 «규칙 밖으로 새는 글자만 막는다» 가 안 선다). 2b 결함(조건부), **중간** — 테마가 `font` · `shadow` 토큰을 이미지 속성에 쓰는 판에서 owner 가 모든 멤버 · 번들 열람자의 브라우저에 임의 URL 요청을 내게 한다(주소 노출, spec 「스킬」 의 «내보낸 번들이 오프라인에서 깨진다»).
- **빨강 케이스**(`token-input-boundary.test.ts` «tokensCss — 뒤 선언을 삼키는 값을 받지 않는다», 8 건): `font` 6(`/*` · `(` · `[` · `"` · `'` · `\`) + `shadow` 2(`/*` · 짝 없는 `rgb(`) → 모두 `expected [] to include 'values.<키>'`. url 요청(2b)은 케이스로 안 잠갔다 — 막을지(글자 `url(` · `image-set(` 금지)가 설계 판단이다.
- **원인:** 거르개가 «선언을 끝내는 글자» 만 보고 «뒤를 삼키는 구문(주석 · 괄호 · 문자열 · 이스케이프)» 을 안 본다.
- **고칠 방향:** `font` · `shadow` 를 허용 글자 목록으로 닫거나(따옴표는 짝 · 괄호는 균형 · `/*` · `\` 금지), 값을 CSS 토큰으로 나눠 «선언 하나로 끝나는가» 를 본다. 이 판정도 자가 된다 — 고친 뒤 위 표를 실 Chrome 으로 다시 돌린다(이 표는 스크래치 `css-probe.mjs`).
- **잰 방법의 한계:** Chrome 한 판(헤드리스). 캔버스 iframe · 내보낸 번들의 실제 `<style>` 구성은 A4 에서 선다 — 그때 한 시트인지 본다. 1 MB 값은 받는다(길이 한도 없음) — 저장 한도는 A4 api 가 정한다.

## 3. manifest 이름 입력

`validateManifest` · `tokensCss` · `tokenValues` · `resolveVariant` 에 `__proto__` · `constructor` · `toString` 을 넣었다(`__proto__` 는 업로드와 같게 `JSON.parse` 로 자기 속성으로).

| 입력 | 결과 |
| --- | --- |
| 토큰 키 `constructor` · `toString` | 통과, `--wb-constructor` · `--wb-toString` 정상 |
| 토큰 키 `__proto__` | 통과 — **키가 사라진다**(`:root { }`) |
| 참조 `{toString}` · `{__proto__}` · `{constructor}` | `token-ref-type` 으로 거절(`items[ref]` 가 프로토타입 값을 집어 «타입이 다르다» — 문장은 엉뚱하지만 거절) |
| `components.__proto__`(defaultVariant 가 variants 에 없음) | **통과** — 선언이 사라져 검사가 안 돈다 |
| `components.constructor` · `toString` | `unknown-component` |
| variant id `__proto__` · `constructor` | 통과, `resolveVariant` 정상(`some(v => v.id === …)` 라 안전) |
| `patterns.__proto__` | 통과 — 사라짐. `patterns.constructor` 는 `pattern` 이슈 |
| `tokensCss(m, { constructor, toString, __proto__ })`(선언 없음) | **이슈 0** — `unknown-token` 이 안 난다 |
| 선언한 `toString` 에 값 없이 `tokensCss(m, {})` | **거짓 이슈** `token-default-type @ values.toString`(«값 undefined 을 버리고») |
| 토큰 키 `a.b` + `a-b` · `.` + `-` | 통과 — CSS 는 `--wb-a-b` 두 번 · `--wb--` 두 번 |

`Object.prototype` 오염은 어느 판에서도 없었다(`Object.keys(Object.prototype)` = `[]`). 던짐 없음.

- **판정:** 3a 결함 **낮음**(뒤 선언이 앞을 덮어 앞 토큰을 고쳐도 화면이 안 바뀌고, `tokenValues`(`useToken`)와 CSS 가 갈린다). 3b 결함 **낮음**(`effectiveValues` 의 `key in items` · `key in values`). 3c 결함 **낮음**(저장되는 `manifest.json` 원문에는 검사 안 된 선언이 남는다 — 그 원문을 zod 없이 읽는 소비자가 생기면 다시 잰다).
- **빨강 케이스**(`token-input-boundary.test.ts`): «두 키가 같은 CSS 변수가 되면 …» → `expected {…} to be null` · «선언에 없는 constructor · toString 값도 …» → `expected [] to deeply equal [[unknown-token …]…]` · «toString 토큰을 선언하고 값을 안 주면 …» → `expected [ Array(1) ] to deeply equal []` · «components 의 __proto__ 키는 …» → `expected {…} to be null`.
- **원인:** `tokenVar` 가 `.` 를 `-` 로 바꾸는데 키 규칙(`[a-zA-Z0-9.-]`)이 둘을 함께 받는다 · `in` 연산자 · zod record 가 `__proto__` 를 떨군다.
- **고칠 방향:** `checkTokens` 에서 `tokenVar(key)` 가 겹치면 이슈 · `Object.hasOwn` · 모양 검사 전에 원문 객체의 `__proto__` 키를 이슈로(zod 앞).
- **잰 방법의 한계:** 렌더러는 `resolveVariant` 만 불렀다 — 캔버스 전체 렌더는 안 쟀다.

## 4. `readWbtheme` 의 순서

코드상 크기 · 항목 수 · 경로 · 허용 목록 · 링크 판정은 전부 `unzipSync`(`read.ts:103`) 앞(`read.ts:50-99`)에 있다 — 순서는 옳다. 그러나 1 의 세 갈래로 판정이 재는 것과 fflate 가 푸는 것이 달라 막지 못한다. 1c 판의 메모리(`mem-probe.mjs`, 9.94 MB stored 로컬 하나를 원래 크기 0 인 중앙 항목 N 개가 가리킴, zip 은 언제나 10 MB 상한 안):

| N | 판독기 | 실린 바이트 | RSS 앞 → 뒤 | `arrayBuffers` 뒤 |
| --- | --- | --- | --- | --- |
| 0 | 통과 | 0 | 85 → 86 MB | 20 MB |
| 5 | 통과 | 52.1 MB(상한 50 MB 넘음) | 85 → 137 MB | 70 MB |
| 50 | 통과 | 521 MB | 84 → 584 MB | 517 MB |
| 150 | 통과 | 1.56 GB | 84 → 1579 MB | 1511 MB |
| 497(항목 상한 500 − 3) | 통과 | **5.18 GB** | 85 → 3758 MB | 4959 MB |

- **판정:** 결함(1 과 같은 뿌리), **높음** — 10 MB 업로드 하나로 api 프로세스에 5 GB 를 잡게 한다. deflate 항목은 1a · 1b 의 «판독기가 안 본 항목» 이면 원래 크기 검사도 비켜 `new Uint8Array(originalSize)`(최대 4 GB)를 잡는다 — 이 판은 재지 않았다.
- **빨강 케이스:** 1 의 «stored 항목의 원래 크기를 0 으로 …»(54 MB 판).
- **고칠 방향:** 1 과 같다(항목마다 `max(size, originalSize)`, 목록 대조).
- **잰 방법의 한계:** macOS 의 RSS 는 압축 메모리로 줄어 보인다(497 판에서 RSS < arrayBuffers) — `arrayBuffers` 와 실린 바이트를 함께 적었다. 한 프로세스 · Node 24.21.0.

## 5. `wb-theme dev` 의 파일 경계

`startDev`(`packages/theme-kit/src/dev.ts:81`)를 빌드한 `dist` 로 두 판에 띄웠다 — A: 저장소 안(`packages/theme-kit/.tmp/rv-probe`, 픽스처 복사), B: 어느 워크스페이스에도 안 든 스크래치(`rv-a2/proj-b`). 표지 파일은 스크래치의 `outside-marker.txt`. 요청은 날것 TCP 로 보냈다(`fetch` 는 `..` 를 접는다).

| 요청 | A | B |
| --- | --- | --- |
| `/@fs<표지>` · `?raw` · `?raw??` · `?import&raw??` · `?url` | 403 | 403 |
| `/@fs<root>/../../…<표지>` · `/../../…<표지>` · `/..%2f..%2f…<표지>` | 200 셸 HTML(표지 없음) | 같음 |
| `/@fs<저장소>/README.md`(`?raw`) | **200 — 읽힘** | **200 — 읽힘** |
| `/@fs<저장소>/apps/api/.env` · `.env.example` | 403(vite 기본 `fs.deny`) | 403 |
| `/@fs<저장소>/.git/config` | 200 셸 HTML(파일 아님) | 같음 |
| LISTEN | `127.0.0.1` 만 | 같음 |
| 다른 Origin 의 `fetch` | 200, `Access-Control-Allow-Origin` 없음(브라우저가 못 읽음) | 같음 |
| Host `evil.example` — `/frame.html` · `/@fs/…` | 403 | — |
| Host `evil.example` — `/` · `/__wb/project` | **200**(`/__wb/project` 는 manifest 를 준다) | — |

- **판정:** 5a 재현 안 됨. 5b **낮음** — `fs.allow` 에 `searchForWorkspaceRoot(root)` · `searchForWorkspaceRoot(client)` 가 들어 A 판은 저장소 전체를 준다(B 판이 저장소를 주는 것은 kit 을 저장소에서 링크해 `client` 의 워크스페이스 뿌리가 저장소라서다 — 설치된 kit 이면 작성자 프로젝트의 뿌리일 것이다, 안 쟀다). 작성자 프로젝트가 더 큰 워크스페이스 안에 있으면 그 워크스페이스 전체가 열린다. 5c 결함 **낮음** — DNS 재바인딩으로 남의 페이지가 `/__wb/project`(manifest · 설정 이슈)와 SSE 를 읽는다. 셸 미들웨어가 `configureServer` 에서 vite 의 host 검사보다 먼저 걸린다. 5d 재현 안 됨(`bin.ts` 에 `--host` 가 없고 기본 `127.0.0.1`).
- **빨강 케이스:** `packages/theme-kit/build-test/dev.test.ts` «다른 Host 로 온 요청은 셸 경로(/ · /__wb/project)도 거절한다 — vite 의 경로와 같게» → 카나리아 `/frame.html` 403 통과 뒤 `expected { shell: '200', project: '200' } to deeply equal { shell: '403', project: '403' }`.
- **고칠 방향:** 5c — 셸 미들웨어에서 Host 가 `localhost` · `127.0.0.1` · `[::1]` 가 아니면 403. 5b — 워크스페이스 뿌리를 빼고 `[client, root]` 만 두되, 작성자 프로젝트가 워크스페이스의 `node_modules` 를 hoist 해 쓰는 판(SDK · react 가 뿌리 밖에서 풀림)이 깨지는지 dev 판으로 잰다.
- **잰 방법의 한계:** vite 6.4.3 한 판. 설치된 kit(템플릿 zip 에서 푼 프로젝트)으로는 안 쟀다 — 5b 의 B 판은 저장소 링크의 판이다.
