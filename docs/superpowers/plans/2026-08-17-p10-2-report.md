## 2. T1 — 재라 여덟을 쟀다

### 2.1 #2가 첫 관문이었다 — **막히지 않았다**

계획서가 *"안 되면 이 슬라이스가 통째로 막힌다"*고 적은 자리다.

| 무엇 | 값 |
|---|---|
| `~/Library/Caches/ms-playwright`에 이미 있는 것 | `chromium-1234`(356MB) · `chromium_headless_shell-1234`(196MB) · 1228 판 둘 · `INSTALLATION_COMPLETE` 표시가 있다 |
| `playwright-core@1.62.1`이 요구하는 리비전 | **1234** — `browsers.json`에서 읽었다. **이미 있는 것과 같다** |
| 그래서 내려받은 바이트 | **0.** 네트워크를 안 탔다 |
| 띄우는 시간 | **100~172ms**(반복 측정) |

**이 기계에 이미 있던 이유는 이 저장소와 무관하다** — 다른 도구가 깔아 둔 캐시다.
**다음 사람의 기계에는 없을 수 있다**(이월 §3).

### 2.2 #1 — 무엇을 들이나. **`fflate`를 고를 때와 같은 축이 갈랐다**

| 재고 본 것 | 전이 의존 | 자기 크기 | 설치 스크립트 | 브라우저를 내려받나 |
|---|---|---|---|---|
| **`playwright-core`** | **1개(자기뿐)** | **13.4MB** · 파일 111 | **없다** | **아니다** — 실행할 때 기계의 것을 찾는다 |
| `playwright` | 2 | 5.1MB + 위 | **postinstall이 있다** | **그렇다** — `pnpm install`이 수백 MB를 탄다 |
| `puppeteer-core` | **25개** | 5.8MB | 없다 | 아니다 |

전이 의존 수는 `npm install --package-lock-only`로 잠금 파일을 만들어 세었다.

**의존이 0인 것이 갈랐다** — `export-zip.ts`의 *"fflate를 고른 이유"*와 같은 판정이다.
`puppeteer-core`의 스물다섯은 그 표가 `jszip`의 넷을 두고 물러났던 것보다 크다.

**실제 설치는 1초에 `+1` 하나였고 브라우저를 안 내려받았다.** 그러므로 계획서 재라 #1의
*"크면 판정을 다시 하라"*는 **발동하지 않는다** — D1을 그대로 둔다.

**대가는 저장소가 아니라 배포에 있다.** 브라우저 바이너리는 여전히 수백 MB이고 이
저장소는 그것을 안 들고 있다(이월 §3).

### 2.3 #4 — **글꼴을 무엇으로 묻나. 계획서가 기억한 API는 답이 아니다**

계획서: *"브라우저 안에서 글꼴 유무를 물을 수 있다 — 그런 API가 있다고 **기억**한다."*

| 물음 | `document.fonts.check`의 답 |
|---|---|
| `12px sans-serif` | `true` |
| `12px "Apple SD Gothic Neo"` (이 기계에 있다) | `true` |
| `12px "Malgun Gothic"` (이 기계에 없다) | **`true`** |
| `12px "Noto Sans KR"` (이 기계에 없다) | **`true`** |
| `12px "Zzzz No Such Font 12345"` (아무 데도 없다) | **`true`** |

**그 API는 이 물음에 답하지 않는다.** 그리고 애초에 물음이 틀렸다 — 알아야 할 것은
*"이 이름의 글꼴이 있는가"*가 아니라 ***"한글에 글리프가 있는가"***다. 이름을 물으면
글꼴이 바뀔 때마다 목록을 고쳐야 하고, 대체 글꼴로 잘 그려지는 기계를 두부라고 부르게 된다.

**대신 쓴 자 — 두부를 그려서 맞댄다.**

캔버스에 **사용자 영역 두 글자**(U+E000·U+E001)를 그린다. 어느 글꼴에도 없는
코드포인트라 **반드시 두부**다. 같은 자리에 한글 두 글자를 그려 픽셀 해시를 맞댄다.

| 잰 것 | 값 |
|---|---|
| PUA 두 벌(U+E000·E001 과 U+E010·E011)이 같은 해시인가 | **같다** — 두부는 무엇이든 같은 그림이다. **그러므로 「같으면 두부」가 성립한다** |
| 한글이 그것과 다른가 | **다르다** — 이 기계에는 글꼴이 있다 |
| 같은 입력이 같은 값인가 | **그렇다**(결정적) |

**함수가 아니라 글자로 넘겨야 한다.** 이 저장소의 TS는 esbuild를 지나고 그것이 함수에
이름 표시(`__name`)를 심는데, 그 함수가 브라우저 안에서 실행되면 그 이름이 없어
`ReferenceError: __name is not defined`로 죽는다(실측).

### 2.4 #5 — **화소를 읽을 수 있다. 그리고 읽어야만 한다**

| 잰 것 | 값 |
|---|---|
| PNG 서명·`IHDR`이 고정 자리에 있나 | 그렇다 — 서명 8바이트, 길이 4, `IHDR` 4, 그 다음 폭·높이가 빅엔디언 4+4 |
| 배율 1배 | **720×552** · 64KB |
| 배율 2배 | **1440×1104** · 149KB — **P10-1이 권한 2배 화소와 정확히 같다** |
| 배율 3배 | **2160×1656** · 215KB |
| **화면 전체를 찍으면** | 내용이 길수록 높이가 는다 — 같은 뷰포트에서 **1104 · 1760 · 1124** 가 나왔다 |

**추론으로는 알 수 없다.** 뷰포트는 우리가 정하지만 높이는 내용이 정하고 배율이 곱해진다.
그래서 낸 바이트의 머리를 읽는다(`readPngSize`). **못 읽으면 성공이 아니라 실패다** —
0이 `fitInto`로 흘러가면 슬라이드가 조용히 찌그러진다(D8).

### 2.5 #3·#6·#7 — 나머지

| # | 문장 | 잰 값 |

### 2.6 D7 — **N장의 비용.** 프로덕션 렌더러로 쟀다

동시 4장 · 배율 2배 · 화면 전체 · 바깥 요청 차단 — **오늘 서는 그 설정 그대로**다.

| N | 그리는 시간 | 장당 | PNG 합계 | 만들어진 pptx |
|---|---|---|---|---|
| 1 | 0.27s | 272ms | 0.1MB | 0.1MB |
| 5 | 0.54s | 107ms | 0.7MB | 0.6MB |
| 20 | 1.54s | 77ms | 2.9MB | 2.4MB |
| 50 | 3.55s | 71ms | 7.2MB | 5.7MB |
| **200**(상한) | **14.26s** | 71ms | **28.7MB** | **24.0MB** |

**하나짜리로 재면 272ms/장으로 보이고 그것은 거짓이다** — 브라우저 띄우는 값이 한 장에
전부 실린다. 스무 장부터 71~77ms/장으로 평평해진다.

**동시성을 정한 근거**(별도 측정, 같은 기계):

| 동시 | 장당 |
|---|---|
| 1 | 104ms |
| **4** | **69ms** |
| 8 | 58ms |

4에서 8로 가면 16% 더 빠른데 **동시에 열리는 페이지가 두 배**다. 4를 고른다.

**브라우저를 장마다 새로 띄우면** 다섯 장에 1012ms(202ms/장)였다 — 한 번 띄워 쓰는 쪽이
두 배 빠르다. 그래서 브라우저는 **`render` 한 번의 수명**이다.

### 3.1 계획서에 없던 대가 하나 — **바깥으로 나가는 요청**

테마의 `@font-face`·`url()`은 **사용자가 적은 문자열**이다(`themes/spec/assets.ts`가
`url()`·`local()`을 명시적으로 받는다). 서버가 그리면 **프로젝트 멤버가 적은 주소로 서버가
요청을 보낸다.**

**판정: 라우팅되는 요청을 전부 끊는다.** `data:`는 네트워크를 안 타므로 그대로 산다.

**대가:** 원격 웹폰트를 든 테마는 대체 글꼴로 그려진다 — **화면(`apps/web`)과 갈린다.**
오늘 시스템 테마는 글꼴 자산이 없어 갈림이 없고, 사용자가 만든 테마에서만 생긴다.
**이월이 그 갈림을 든다.**

## 4. 무엇이 섰나

```
apps/api
   src/services/screen-render.ts           **이음매** — 모양·실패의 값·PNG 머리 읽기
   src/services/screen-render-chromium.ts  진짜로 그리는 자 (여기만 playwright-core 를 안다)
   src/services/export-pptx.ts             그린 것을 계약에 넣는다 · screenless 와 실패를 가른다
   src/services/project-theme.ts           asResolvedTheme — **두 내보내기가 나눠 쓴다**
   src/main.ts                             **채우는 자리 하나**
   build-test/screen-chromium.test.ts      진짜 브라우저 (pnpm test:build)
   test/screen-render.test.ts              화소 읽기
   test/export-pptx-screens.test.ts        배선 — 가짜 렌더러로
   test/screen-renderer-census.test.ts     이음매를 안 지나는 길이 없는가
```

**지켜야 하는 방향 넷:**

1. **`packages/exporter`는 브라우저를 모른다.** `playwright-core`를 import하는 소스가
   **하나뿐**인 것을 census가 센다. 그 패키지에 넣으면 `public-api.test.ts`보다 먼저 여기서 죽는다.
2. **진짜 그리는 자를 만드는 자리는 `main.ts` 하나다.** `buildApp`이 스스로 만들면
   `pnpm test`의 케이스 전부가 브라우저를 띄운다. census가 양쪽을 다 센다.
3. **화소는 바이트에서 읽는다.** 뷰포트에서 추론하면 화면 전체를 찍는 순간 거짓이 된다.
4. **`screenless`와 `screenFailures`를 접지 마라.** 접으면 화면이 *"아직 아무도 안
   만들었다"*와 *"만들려다 실패했다"*를 같은 말로 한다.

## 5. T6 — 받는 쪽으로 쟀다

### 5.1 PowerPoint 16.112 — **그림이 실제로 그려진다**

P10-1 이월 §1.2의 절차 + **리뷰 §15의 빠진 다섯**을 지켰다(측정 사이 `취소`로 모달 닫기 ·
폴링 종료 조건 둘 · `open -a`의 0은 열림이 아니다 · 자동화 권한 · 시작할 때 떠 있었는지 확인).
**시작할 때 안 떠 있었으므로**(`pgrep`) 끝나고 종료했고 컨테이너 디렉터리를 지웠다.

| 파일 | 결과 | 재현 |
|---|---|---|
| **대조군(열려야 한다)** — 같은 코드, 이미지 없음 | `RESULT=OPENED` | 1/1 |
| **이 슬라이스** — 화면 이미지 셋이 실린 것 | `RESULT=OPENED` | **2/2** |
| **음성 대조군(안 열려야 한다)** — 매체 `png`의 `Default`를 지웠다 | `RESULT=NOT_OPENED` · `TEXT[…내용에 문제가 있습니다…] BTN[취소] BTN[복구]` | 1/1 |

**자가 양방향으로 선다** — 열려야 하는 것을 열고, 안 열려야 하는 것을 거절한다.
음성 대조군은 P10-1 리뷰 §2가 지목한 그 변이다(귀속: 리뷰 §2).

**PowerPoint가 읽은 값 — 그림이 그림이다:**

```
슬라이드 1의 도형 셋
  이름:      제목: 관리자 회원 목록1 / 화면 / 설계 노트
  shape type: text box / **picture** / text box
```

| 슬라이드 | 이미지 화소 | PowerPoint가 그린 크기 | 비율 |
|---|---|---|---|
| 1 | 1440×1104 | **540.0pt × 414.0pt** | 1.3043 ↔ 1.3043 |
| 2 | 1440×1760 | **338.7pt × 414.0pt** | 0.8182 ↔ 0.8182 |

`SCREEN_BOX`가 540pt × 414pt다. **첫 장은 자리를 꽉 채우고 둘째 장은 세로가 길어 좌우가
남는다** — `fitInto`가 진짜 값에서 도는 것을 받는 쪽이 확인해 준 것이다.

### 5.2 스모크가 **결함 하나를 찾았다** — 가짜로는 못 보는 갈래

첫 실행에서 `한 장이 죽어도 나머지가 산다`가 죽었다.

```
TimeoutError: page.setContent: Timeout 1ms exceeded.
 ❯ probeKoreanGlyphs .../screen-render-chromium.ts:253
 ❯ Object.render      .../screen-render-chromium.ts:168
```

**진단:** 글꼴 물음이 던지면 그 예외가 `render` 밖으로 그대로 새어 나갔다. 그러면
**내보내기 하나가 통째로 500**이 되어 pptx를 아예 못 받는다 — D5(*"하나 때문에 전부를
잃지 않는다"*)의 정반대다. 가짜 렌더러는 이 경로를 안 지나므로 `pnpm test`가 못 본다.

**고침:** 글꼴 물음의 답을 **셋**으로 넓혔다 — `'yes'` · `'no'` · `{ reason }`.
셋째는 `fontWarning`을 **안 세운다**: 못 문 것과 없는 것은 다르고, 브라우저가 잠깐
흔들린 것을 *"이 서버에 한글 글꼴이 없다"*로 내보내면 그것은 거짓말이다.

### 6.1 **0 사망이 둘 났고 둘 다 진단해 닫았다**

**M5 — 래스터를 테마 없이 그려도 아무도 안 죽었다.**

원인: 케이스가 `css`에 `--wb-`가 있는지 봤는데 **구조 기본 CSS가 이미 그 접두를 쓴다.**
값으로 확인했다 — 테마 있음 16963자 · 테마 없음 1809자, **둘 다 `--wb-`를 담는다.**
테마만 내는 것은 팔레트 선언(`--wb-palette-`)이다. 그것으로 바꾸니 **1 사망**.

**M13 — 바깥 요청을 안 막아도 아무도 안 죽었다.**

원인: **재는 자가 아예 없었다.** 차단은 관찰되는 값을 안 만든다 — 무엇이 *안* 일어났는지는
보이지 않는다.

**만든 자:** 라우팅되는 곳이 없는 주소(`http://10.255.255.1/x.css`)를 건 페이지를 그린다.
끊는 쪽은 **기다리지 않고** 그리고, 안 끊는 쪽은 `load`를 기다리다 타임아웃으로 죽는다.
실측: **30ms(차단) vs 2001ms 타임아웃(무차단)**. 그것으로 **1 사망**.

**그 자의 한계도 값으로 적는다:** 그 주소가 **빨리 거절되는** 망에서는 안 끊어도 통과한다.
그때 이 케이스는 **조용히 이빨을 잃는다**(빨강이 아니라 초록이 된다).
