## 1. 복원 흐름이 대화 상자로 옮겨도 같은가

**판:** 페이지 둘(«페이지» `원문`→`바뀐 글`, «둘째» `둘째 원문`→`둘째 바뀐`, 그 사이 스냅샷 v1). «페이지»의 행을 `holdRow` 로 쥐고 v1 복원을 보낸 뒤 줄에 섰는지 센다(`waitForWaiters(1)`) → 아래 조작 → 놓음 → 신호 뒤 2.5s. 창 1440×900. main 은 팝오버를 Escape 로 닫은 판 · 설정은 머리의 «설정» 링크.

| 조작 | HEAD | main |
|---|---|---|
| (a) 닫음 | 서버 `원문` · 캔버스 `원문` · 배너 0 · 답 200 → 신호(+6ms) | 같음(+10ms) |
| (b) 닫고 «둘째»로 | 캔버스 `둘째 원문`(P2) · 배너 0, 되돌아가면 `원문` · 배너 0 | 같음 |
| (c) 닫고 설정 → 뒤로 | 캔버스 `원문` · 배너 0 | 같음 |
| (d) 안 닫고 설정 → 뒤로 | **`…` 가 안 눌린다**(모달 — `click` 2000ms 초과) → Escape 뒤 같은 길 · 결과 (c) 와 같음 | 팝오버가 열린 채 «설정»이 눌린다 · 결과 같음 |

«누가 복원했나» 통지(몸체의 `role=status` «스냅샷이 복원됐습니다 …»)는 네 판 모두 **안 남는다** — 몸체가 상자와 함께 내려가서다. main 도 팝오버를 닫으면 몸체가 내려가 같다. 셸이 내려갔다 서는 판의 세대 거름(`shellGeneration`)은 옮긴 `editor-restore-signal-order` 의 «다른 프로젝트로 갔다 돌아옴» 넷이 대화 상자 판으로 잰다(그 판들은 상자를 **연 채** `popstate` 로 옮긴다 — 모달이 막지 않는 길이다).

**옮긴 build-test 넷의 단언** — diff 로 셌다. `editor-restore-own-signal` · `signal-order` 는 여는 길(`더 보기` → `스냅샷`)과 주석만 바뀌었다. `editor-restore-unanswered` 는 «Escape 로 닫고 누른다» 두 줄이 더해졌다 — 모달이 열린 동안 하단 바가 `inert`라 없으면 판이 안 선다(단언은 그대로). `canvas-iframe-host-events` 는 팝오버 둘 × (캔버스 누름 · 캔버스 안 초점의 Escape) 4 → `…` × 2, iframe 갈림 1 은 `…` 로.

**지운 2 케이스가 재던 성질:** 그 둘은 «떠 있는 상자의 바깥 누름 닫기(`usePopoverDismiss`)가 캔버스 iframe 의 `mousedown` · `keydown` 을 받는가»였다. 같은 훅을 `…` 메뉴가 쓰고 남은 2 케이스가 그대로 잰다 — **닫기 장치의 성질은 사라지지 않았다.** 대신 새로 생긴 성질 — «모달이 열린 동안 캔버스 iframe 이 누름 · 키를 **못** 받는다» — 을 재는 케이스가 없었다. 실브라우저 값: 둘째 노드 자리의 `elementFromPoint` = `DIALOG`(배경막), 실클릭 뒤 선택 그대로(«글 1»), 편집 단축키 여섯(Delete · Backspace · Ctrl/⌘+Z · Alt+↑ · Alt+Shift+→) 뒤 WS `patch` 0. 새 케이스로 잠갔다(아래 «새 케이스» 1).

## 2. 모달이 열린 동안

| 무엇 | 값(HEAD, Chrome) |
|---|---|
| 첫 포커스 | 상자의 «닫기»(`BUTTON.wb-shell-dialog-close`) |
| Tab 40 번 | «닫기» → 태그 칸 → «스냅샷 저장» → `BODY` → 다시 «닫기» … — 캔버스 iframe 에 한 번도 안 선다(`contentDocument.hasFocus()` 늘 거짓) |
| 캔버스 iframe 실클릭 | 누름을 배경막이 받는다 · 선택 그대로 · 상자 그대로 |
| 편집 단축키 | WS `patch` 0. 에디터에 전역 Ctrl+Z 는 없다(트리 단축키는 트리 요소의 `onKeyDown`, 캔버스 안에 키 처리 없음 — `git grep`) |
| 스크립트로 iframe 안 요소에 `focus()` | **들어간다**(iframe 에 `[inert]` 속성이 없다 — 모달의 inert 는 암묵이다, `hasFocus` 참). 그 뒤 Delete → `patch` 0, **Escape → 상자가 안 닫힌다**(키가 iframe 문서로 가 `cancel` 이 안 난다) — L4. 사람의 조작(누름 · Tab)으로는 이 자리에 못 닿아 정보로만 적는다 |
| 열린 동안 WS 로 온 남의 복원 · 권한 바뀜 | 둘 다 하단 바에 선다(상자 사각형과 겹침 0 · 창 안 · 배경막 35% 아래로 흐리게 보인다). `elementFromPoint` 는 `DIALOG` · «다시 불러오기» `click` 1500ms 초과(막힘) |
| 상자를 닫은 뒤 | «다시 불러오기»가 눌리고 캔버스가 서버 판(«글 1 …»)이 된다 |
| 한글 조합 중 Escape(CDP `Input.imeSetComposition` «한») | 문서에 `keydown Escape isComposing=true` → **`cancel` 이 난다** → 상자 **안 닫힘** · 칸 «한». 조합을 끝낸 뒤(`Input.insertText`) Escape → 닫힘. 보고의 이월 «조합 중 Escape 의 실브라우저 판»을 이 값이 닫는다 — Chrome 은 조합 중에도 모달에 `cancel` 을 내고, 막는 것은 `compositionstart/end` 로 든 조합 구간 가드다(새 케이스 2 · 변조 M2) |

편집 실패 통지(`EditAlert`)는 실제로 세우지 못했다(WS 편집의 거절은 리베이스로 다시 나가 통지 없이 풀린다 — 떠나야 선다). 같은 하단 바 줄에 서므로 남의 복원 · 권한 바뀜의 값이 그 자리의 값이다.

통지 · 도구 겹침은 0 이고 1280 · 1440 에서는 main 과 비슷하거나 낫다 — **1024 에서만 무너진다.**

- **원인:** `.wb-shell-footer` 는 접히지 않는 한 줄 flex 다. 도구(`.wb-shell-footer-tools` — `flex: 0 1 auto`, 뷰포트 고르개 + 줌 무리 341px)가 제 폭을 지키고 통지(`.wb-shell-footer-notices` — `flex: 1 1 0; min-width: 0`)는 남은 폭만 받는다. 창 1024 의 캔버스 칸은 444 → 통지 444 − 24(안쪽 여백) − 16(간격) − 341 = **63px**. 한 줄이 한두 낱말이라 통지마다 수십 줄로 자라고, 바의 줄 높이가 `auto` 라 캔버스 줄(`minmax(0, 1fr)`)을 먹는다.
- **고칠 방향:** 바를 접게 하고 통지 칸에 읽을 기본 폭을 준다 — `.wb-shell-footer { flex-wrap: wrap }` · `.wb-shell-footer-notices { flex: 1 1 320px }`(좁으면 도구가 다음 줄로 내려간다). 이 문장 그대로 `shell.css` 에 끼운 변조(F1-바접기, 17:34:49–17:34:54 · 17:35:04–17:35:14)로 쟀다: 새 케이스 4 → 초록(통지 폭 420 · 캔버스 516 · 바 창 안 · 도구 넷 눌림), `editor-shell-layout` 5/5 초록. jsdom 의 `shell-css-*` 자(좁은 폭 무리 `WRAPPING_GROUPS` 등)는 그 변조로 안 돌렸다 — 고치는 트랙이 돈다.
- **무게 중간:** 데이터는 안 잃지만 데스크톱 하한(1024)에서 통지 둘만으로 캔버스가 반이 되고, 다섯이면 캔버스 도구를 못 누른다.
