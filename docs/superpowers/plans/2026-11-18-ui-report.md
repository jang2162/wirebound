## 2. 로그인 — 자동완성 · 비밀번호 보기

**바꾼 것.** 로그인 이메일 칸 `autocomplete="email"`, 비밀번호 칸은 새 부품 `apps/web/src/account/password-input.tsx` 의 `PasswordInput`(`current-password`). 칸 안 오른쪽 «보기» 토글 — 누르면 `type` 이 `text` 가 되고 단추 글 · 이름이 «숨기기» · «<칸 라벨> 숨기기» 로 바뀐다. 새 비밀번호 두 칸(`account/new-password-fields.tsx` — 가입 · 재설정)도 같은 부품이다(토글 이름 «비밀번호 보기» · «비밀번호 확인 보기»).

**결정.**

1. 토글 상태는 **이름이 바뀌는 단추**로 말한다(`aria-pressed` 를 함께 두지 않는다 — 같은 사실을 두 번 말한다). 이름에 칸 라벨을 넣는 것은 새 비밀번호 화면에 칸이 둘이라 «보기» 둘을 가를 수 없어서다.
2. 그 결과 Playwright `getByLabel('비밀번호')`(부분 일치)가 토글에도 맞는다 — 칸을 찾던 실브라우저 케이스 일곱 줄에 `exact: true` 를 더했다(`admin-screens` 4 · `editor-logout-edits` 1 · `rv-ws-workspace` 2). jsdom `getByLabelText` 는 기본이 정확 일치라 안 걸린다(센 식: `git grep -n "비밀번호" -- apps/web/test apps/web/build-test | grep -i "label\|getBy"`).
3. «포커스는 칸에 남김» 은 **포인터 누름**에 건다(`mousedown` 기본 동작을 막는다). 키보드로 Tab 해 와서 누른 판은 포커스가 단추에 남는다 — Tab 차례를 되돌리지 않는다.
4. 초대(가입) · 재설정의 새 비밀번호 칸에도 둔다(브리프 기본값). 계정 설정의 «비밀번호 바꾸기»(`routes/account.tsx` — 지금 · 새 · 확인 셋)는 브리프 범위 밖이라 두지 않았다 — «남은 것».
5. 보이는 동안 `spellcheck=false` · `autocapitalize=off` — 글로 보인 비밀번호가 맞춤법 검사 · 자동 고침에 안 걸리게.

**잰 값.** jsdom: 로그인 autocomplete 두 값 · 토글이 `type` · 이름을 바꾸고 값을 지킴 · `mousedown` 이 막힘(`test/routes/login.test.tsx`), 가입 두 칸의 토글이 칸마다 따로(`test/routes/invite.test.tsx`). 실브라우저(`build-test/ui-login.test.ts`): «abc» 를 치고 토글을 실클릭 → `activeElement` 가 `login-password` · 이어 친 «def» 가 붙어 `abcdef` · 토글 상자가 칸 상자 안이고 칸의 안쪽 오른 여백(64px) 밖의 글 자리와 안 겹침.
