### 1. CLI · MCP 가 레이아웃을 싣는다

- **바꾼 것:** `packages/cli/src/read/page.ts` 의 `PageSummary` 에 `layout`(`pageLayoutOf` — 판 6 이하 문서는 뿌리에서 읽는다)을 더했다 — `list_pages` 가 이 값을 그대로 낸다. `commands/page-get.ts` 의 사람 줄은 이름 뒤에 «서브페이지» · «팝업» 을 붙인다. `packages/mcp/src/tools.ts` 의 `list_pages` · `get_page` 설명이 `layout` 을 말한다(`patch_page` 의 `/layout` 안내는 T1 이 이미 넣었다).
- **결정:** 빈 레이아웃(`blank`)은 줄에 아무것도 안 붙인다 — API 가 짓는 기본값이고 옛 «화면» 줄이 그대로다(`page-get.test.ts` 의 «화면 페이지 줄은 그대로다» 가 그 성질을 든다). 이름은 에디터 «레이아웃» 의 이름(빈 · 서브페이지 · 팝업)이다. `kind` 는 설계 그대로 남겼다.
- **결정:** `list_pages` 에도 `layout` 을 더했다 — 계획은 `get_page` 만 적었지만 스킬이 `list_pages` 의 `kind` 를 가르치고, 에이전트가 페이지를 고르는 자리가 목록이다. 목록의 키 모양을 글자로 견주는 케이스는 없다(`read-tools.test.ts` 는 `get_page` 의 키만 본다).
- **케이스:** `packages/cli/test/page-layout.test.ts`(사람 줄 · `--json` 의 `layout` · `kind` — 판 7 서브페이지 · 판 5 뿌리 `Popup` · 판 5 뿌리 `Page`) · `packages/mcp/test/page-layout.test.ts`(`list_pages` 의 `layout`).
