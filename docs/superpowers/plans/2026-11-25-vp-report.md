## 결정

1. **영역 열쇠 꼴은 api 라우트에 글자로 둔다**(`VIEW_PREF_KEY` — `^(blank|popup|subpage)\.[a-z][A-Za-z0-9]{0,31}$`). 레이아웃 셋(T1 `packages/schema`)과 영역 id 꼴(T4 manifest)이 main 에 없어서다. T1 · T4 가 서면 그 상수로 바꿀 자리다(라우트 머리말에 적었다). 웹 클라이언트는 꼴을 다시 보지 않는다 — 응답의 모양(글자 배열)만 본다.
2. **빈 목록 PUT 은 행을 지우지 않고 `[]` 를 둔다** — «행이 없으면 다 켠 것» 과 뜻이 같고, 지우는 갈래를 하나 덜 둔다. GET 은 둘 다 `[]` 다.
3. **GET 도 세션 전용이다** — 설계 「API」 표의 권한 칸이 두 줄 다 «viewer(세션)» 이다.
4. **PUT 은 프로젝트 행을 `KEY SHARE` 로 먼저 잡는다**(토큰 발급과 같은 차례). 행이 이미 있는 판의 upsert 는 FK 검사를 안 불러 프로젝트 행을 안 잡으므로, 먼저 잡지 않으면 «처음 쓰는 판만 복원 · 삭제 뒤에 선다» 가 된다. 먼저 잡으면 두 판이 같은 자리에 서고, 삭제 뒤에 깨면 500 이 아니라 404 다. 트리 잠금(`NO KEY UPDATE`) 뒤에는 안 선다 — `guard-in-lock` 의 줄은 `holders: ['restore']` 다.
5. **NUL · 홀로 선 서러게이트를 따로 거르지 않는다** — 열쇠 꼴이 ASCII 만 받아 둘 다 400 이다. 그 정규식이 유일한 방벽이다: 꼴에서 `$` 를 뗀 변조(M6)에서 NUL 열쇠가 jsonb 에서 500 이 됐다.
6. **소비자 표에 `getViewPrefs: []` · `putViewPrefs: []`** — 부르는 화면(«보기» 메뉴)은 T7 이다. 그 트랙이 줄을 채운다.
7. **정본 「테이블 정의」 는 안 고쳤다** — 계획 T5 는 적었지만 브리프가 정본 고침을 `ly2`/T10 몫으로 정했다. `project_view_prefs` 줄을 그 트랙에 넘긴다.
