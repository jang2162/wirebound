# P4c-3 테마 가져오기/내보내기 구현 계획

> **에이전트에게:** 태스크 단위로 실행한다. 각 태스크는 실패하는 케이스 → 최소 구현 →
> 통과 → 커밋의 순서를 지킨다.

**목표.** §6.10의 마지막 줄을 세운다 — *"테마는 JSON 한 벌로 내보내고 가져온다.
회사 디자인 시스템을 한 번 테마로 만들면 프로젝트마다 재사용한다."*

**그리고 그것이 P4c-2가 남긴 계약 공백 다섯을 한 몸으로 닫는다.** 이월 §12.1이
*"가져오기/내보내기가 정확히 이것이다 — P4c-3의 본문이다"*라고 지목한 자리다.

**스택.** `apps/web`(화면·파일 입출력) · `@wirebound/themes`(검증) · `apps/api`(저장) ·
vitest.

**이것이 P4c의 마지막 조각이다**(사용자가 셋으로 정했다): ① 엔진 → ② 저작 UI → **③ 입출력**.

---

## 전역 제약

- **워크트리 안에서만 작업한다.** 최상위 체크아웃을 만지지 않는다.
- `pnpm test` · `pnpm typecheck` · `pnpm build`가 마지막에 전부 통과해야 한다.
- **api 테스트는 Postgres 하나(호스트 포트 5433)를 공유한다.**
- **`git checkout --`을 쓰지 마라.** 변조는 python 치환으로 심고 복구한 뒤 `git status`로
  확인한다. **심을 때 심어졌는지 확인하되 `git diff`로 하지 마라** — 새 파일은 untracked라
  diff가 늘 비어 있다(P4c-2에서 두 워커가 그렇게 걸렸다). **파일 내용으로 확인하라.**
  **하네스는 원본 전문을 먼저 들고 `finally`에서 되쓴다**(③이 그 답을 냈다).
- **측정이 예상과 다르면 대상이 아니라 측정 장치를 먼저 의심하라** — **열한 번** 걸렸다.
  **그리고 의심했으면 같은 장치를 다시 돌리지 말고 다른 장치로 재라**(P4c-2 §3.2의 교훈).
- **jsdom과 실브라우저가 캐스케이드를 반대로 가른다** — jsdom은 `textContent`를 쓴 순서,
  **실브라우저는 DOM 순서**다(①·③이 각각 쟀다). 이 슬라이스는 CSS를 안 건드리지만
  **그 사실을 아는 채로 시작하라.**
- **설계 문서(`docs/superpowers/specs/*`)는 고치지 않는다.** 어긋나는 자리는 판정해 보고한다.
- **`apps/web`에 새 런타임 의존을 더하지 않는다**(P4c-2에서 사용자가 정했다).
- **표에 수를 적을 때 셋을 지킨다:** ① 세는 단위를 문장으로 못박고 ② 한 줄에 하나씩 번호를
  붙이고 ③ 검산 명령을 함께 적는다. **그리고 그 명령이 실제로 도는지, 그리고 *네가 세려는
  것을* 세는지 확인하라** — P4c-2에서 그 함정에 **두 번** 걸렸다(`*/`로 파일을 깨뜨린 것,
  `rg -l '\.css$'`가 파일 이름이 아니라 내용을 센 것).
- **남이 잰 값은 귀속을 붙여 옮긴다.**

## 확정한 결정

### D1. **봉투를 둔다** — `wireboundVersion`

§11.2가 페이지 JSON에 대해 이미 그 모양을 정했다:

```jsonc
{ "wireboundVersion": "1", "page": {...}, "schema": {...}, "comments": [...] }
```

*"`wireboundVersion`은 스키마 마이그레이션 진입점이다."*

**테마도 같은 모양을 쓴다:**

```jsonc
{ "wireboundVersion": "1", "theme": { "meta": …, "tokens": …, … } }
```

- **날 `Theme`을 그대로 내보내지 않는다.** 그러면 §13.1의 마이그레이션이 걸 자리가 없고,
  가져오기가 *"이게 테마 파일인가"*를 물을 방법도 없다.
- **`theme` 키 하나만 둔다.** 페이지 쪽은 `page`·`schema`·`comments` 셋인데 테마는
  문서 하나다. **없는 것을 흉내 내지 마라.**
- **값 `"1"`은 페이지 쪽과 같은 문자열이다.** 두 봉투가 같은 버전 축을 쓰는지 다른 축인지는
  **재라 #1**.

### D2. **파생 테마는 파생 문서 그대로 내보낸다** — 합치지 않는다

`extends: "system:admin"`인 테마를 내보내면 **그 문서 그대로** 나간다.

**근거:**

1. **§6.9가 파생을 권장 형태로 뒀다**(§6.10의 표: *"파생 테마 — 시스템 테마 상속 + 부분
   오버라이드 (권장)"*). 합쳐서 내보내면 **가져온 쪽에서 파생이 아니게 되어** 그 권장이 깨진다.
2. **시스템 테마는 내장이라 어느 wirebound에나 있다.** `extends`가 가리키는 대상이
   받는 쪽에 없을 위험은 **버전이 다를 때만** 생긴다.

**대가 — 적어야 한다.** 받는 쪽의 `admin`이 다르면 **같은 JSON이 다른 테마가 된다.**
§4.5가 스냅샷에 대해 *"참조 중인 테마 내용을 함께 저장한다"*로 그 문제를 다루는데,
**내보내기는 그 장치가 없다.** 그것을 어떻게 알릴지는 **재라 #2**.

### D3. **가져오기는 두 문이다 — 초안으로, 그리고 새 테마로**

| 문 | 어디서 | 무엇 | 왜 |
|---|---|---|---|
| **A. 초안으로** | 테마 편집 화면 | 읽은 문서를 `replaceDraft`로 넣는다. **저장은 기존 `PUT`이 한다** | 사실 1이 말한 그 자리. **저장 전에 갤러리로 확인할 수 있다** — 이것이 저작 UI가 있는 이유다 |
| **B. 새 테마로** | 고르개 옆 | `POST /:projectId/themes`로 만들고 그 편집 화면으로 간다 | §6.10의 *"프로젝트마다 재사용한다"*가 이것이다. **P4c-2가 만든 파생 만들기 경로와 같은 모양**이다 |

**A를 먼저 만들어라.** `replaceDraft`가 이미 있고, B는 A + 기존 생성 경로다.

**둘 다 검증을 지난다** — `resolveTheme`이 `error`를 내면 **넣지 않는다.** 경고는 넣고 보인다.

### D4. **`meta.id`(slug)를 가져오기가 다룬다** — 사실 4가 여기서 청구된다

가져온 문서의 `meta.id`가 그 프로젝트에 이미 있으면 **`POST`가 409를 낸다**
(`(project_id, slug)` 유일성 — P4a-3이 정했다).

- **B(새 테마로)에서 사용자가 slug를 정할 수 있어야 한다.** 409를 그대로 보이는 것은
  *"파일을 고쳐서 다시 가져오세요"*가 되어 도구가 아니다.
- **A(초안으로)에서는 slug가 안 바뀐다** — 편집 중인 테마의 정체는 **행 id**이고
  `meta.id`는 그 문서의 값이다. 다만 **저장할 때 slug가 바뀌면 409가 날 수 있다**(P4c-2 ①이
  그 이유로 slug 입력을 안 만들었다). **A가 slug를 바꾸는 경우를 어떻게 다룰지는 재라 #3.**
- **`meta.version`은 이 슬라이스가 안 만든다.** ①이 *"누가 언제 올리는지 규격이 없다"*고
  적었고 그 물음은 아직 안 풀렸다. **내보낸 JSON에 그대로 실려 나가고 그대로 들어온다.**

### D5. **되돌리기는 가져오기와 같은 문을 쓴다**

사실 1. `replaceDraft`가 **서버에서 마지막으로 읽은 문서**로 초안을 되돌린다.

- **가져오기와 같은 함수다.** 문이 하나여야 *"초안을 통째로 갈아 끼우는 것"*의 규칙이 하나다.
- **확인을 물을지는 재라 #4.** P4c-2가 *"저장 안 한 변경을 들고 나갈 때 알리되 막지 않는다"*로
  정했고 **되돌리기는 그것을 되돌릴 수 없게 만드는 유일한 버튼**이다 — 성격이 다르다.

### D6. **파싱 실패 계약을 스토어에 둔다** — 사실 2

**W2가 자리를 지목했고 ③이 동의했다:** *"이슈로 만들면 `ThemeIssueCode`에 **문서가 아니라
편집기의 상태**가 섞인다."* 그러므로 `ThemeIssue`가 아니라 **스토어의 상태**다.

- **스토어가 *"지금 파싱 실패인 절이 있다"*를 안다.** JSON 상자가 그것을 알려 준다.
- **`beginSave`가 그때 막는다.** ①이 만든 그 관문이 *"읽기 전용 · 겹친 저장 · 저장할 것
  없음"* 셋을 이미 한 자리에서 판정한다 — **넷째가 여기 붙는다.**
- **가져오기가 이 계약을 늘린다** — 읽은 파일이 JSON이 아닐 수 있다.

### D7. **두 이슈 상자를 눈으로 가른다** — 사실 3

`theme-issues.tsx`가 `title`을 `aria-label`로만 쓴다. **`<h2>` 한 줄이다.**

**③이 그 손해를 정확히 적었다:** *"오늘 둘이 안 갈리므로 손해가 없지만, 갈리는 날 사용자는
'왜 같은 알림이 두 번 뜨지'로 읽는다 — 그것이 정확히 D4가 보이려던 것의 반대다."*

### D8. **`inverse-bench`를 판정한다** — 사실 6

③이 원인까지 짚었다: 케이스 주석의 전제(*"부하가 걸리면 두 값이 함께 늘어나므로 비율이
안정적이다"*)가 **거짓이다.** 1회차에서 `move`만 3~4배로 튀고 `replace`는 그대로였다.

**고칠지, 상한을 올릴지, 격리할지, 아니면 주석만 고칠지 판정하라.** **주석만 고치는 것도
답이다** — 그러면 다음 사람이 같은 진단을 다시 안 한다. **다만 거짓 문장을 남기지는 마라.**

### D9. **화면이 안 바뀌어야 하는 것** — 캔버스와 갤러리

이 슬라이스는 **CSS를 안 건드린다.** 캔버스·갤러리의 렌더 결과가 바뀌면 그것은 고장이다.
**P4c-2 ③이 만든 DOM 순서 케이스가 그것을 지킨다** — 그 케이스가 죽으면 멈춰라.

## 태스크

### T1. 봉투와 직렬화

**Files:** `apps/web/src/theme/theme-io.ts`(새 파일) · 케이스

D1대로. **순수 함수로 만들어라** — 화면 없이 단위 테스트할 수 있어야 한다.

- `toExport(theme): ExportEnvelope`
- `fromImport(text): { theme } | { error }` — **파싱 실패 · 봉투 아님 · 버전 모름**을 가른다.

**`JSON.stringify`의 키 순서가 계약이다** — §6.11이 *"문서 순서가 곧 우선순위"*라고 못박았고
P4a-3이 저장 쪽에서 `json` 컬럼으로 지켰다. **내보내기가 그 순서를 보존하는지 케이스로
못박아라.**

### T2. 내보내기

**Files:** `apps/web/src/theme/…` · `routes/theme-editor.tsx` · 케이스

파일로 내려받는다. **새 의존 없이** — `Blob` + `URL.createObjectURL` + `<a download>`.

- **파일 이름**을 정하라(`<slug>.wirebound-theme.json` 같은). 근거를 적어라.
- **jsdom에서 내려받기를 어떻게 재는지**가 이 태스크의 어려운 부분이다.
  `URL.createObjectURL`이 jsdom에 없을 수 있다 — **재고 판단하라.**

### T3. 가져오기 A — 초안으로

**Files:** 위와 같음 · `theme-draft-store.ts`

D3-A · D5. **`replaceDraft`를 쓴다.** `error`가 있으면 안 넣는다.

### T4. 파싱 실패 계약

**Files:** `theme-draft-store.ts` · JSON 에디터 · 케이스

D6대로. **`beginSave`의 넷째 갈래다.**

**구분력:** 파싱 실패 중에 저장을 누르면 무엇이 죽는가. **고치기 전에 그것이 통과하는 것을
먼저 확인하라** — 그것이 사실 2의 실증이다.

### T5. 가져오기 B — 새 테마로

**Files:** 고르개 옆 · `api/client.ts`(기존 `createTheme` 재사용) · 케이스

D3-B · D4. **409를 사용자가 풀 수 있게 하라.**

### T6. 두 이슈 상자 (D7) · `inverse-bench` 판정 (D8)

둘 다 작다. **D8은 고치든 안 고치든 근거를 적어라.**

### T7. 회귀 · 커밋 · 보고

`pnpm test` 전체 · `typecheck` · `build`.

## 재라 — 이 계획이 정하지 않고 넘기는 것

1. **`wireboundVersion`이 페이지 쪽과 같은 축인가.** 같은 문자열 `"1"`을 쓰되 **뜻이 같은지**
   판정하고 근거를 적어라.
2. **파생 테마의 대가를 어떻게 알리는가**(D2). 내보낼 때 경고할지, 봉투에 base의 정보를
   적을지, 아무것도 안 할지.
3. **A(초안으로)가 `meta.id`를 바꾸는 경우**(D4). 막을지, 그대로 두고 저장에서 409를 받을지.
4. **되돌리기가 확인을 묻는가**(D5).
5. **내보낸 파일 이름.**
6. **가져오기가 `assets.fonts.src`의 URL을 어떻게 다루는가.** 오늘 검증만 되고 리소스를
   안 가져온다(`spec/assets.ts`) — 다른 기계에서 만든 테마의 `local()`은 **여기서 없을 수
   있다.** 알릴지 말지.
7. **B(새 테마로)를 어디에 두는가** — 고르개 옆인지, 프로젝트 목록인지.

## 계획이 재지 않은 것

1. **사람이 실제로 테마를 주고받아 본 적이 없다.** 잴 수 있는 것은 *"내보낸 것을 다시
   가져오면 같다"*까지다. **왕복 케이스를 반드시 만들어라** — 그것이 이 슬라이스의 중심 단언이다.
2. **다른 wirebound 인스턴스와의 호환.** 시스템 테마가 다른 버전이면 파생이 달라진다(D2).
3. **큰 테마의 성능.** 다섯 시스템 테마가 오늘 가장 큰 표본이다.
4. **P4c-2가 남긴 나머지** — 정렬 버튼(§12.1-3) · `onSelectPath`(§12.1-4) ·
   `assets.fonts.family`와 `tokens.typography.family`가 갈리는 것(§12.1-8) ·
   `suspicious-literal`의 severity(§3) · 벽 1·2 · `placeholder.style`.
   **전부 범위 밖이고 이월에 그대로 남는다.**
