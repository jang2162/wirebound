## 결정과 이유

### 1. «안» → «뒤» 물러섬은 받는 타입 · 설 자리 까닭에만

`zoneDropRefusal(document, placing, selected, BODY_ZONE)` 이 문장을 내는 판(곧 `fitRefusal`)만 물러선다. 잠금 · 문서에 없음으로 «안» 이 막힌 판은 그대로 막힌다 — «남이 쥔 셀 틀이라 그 열 뒤에 넣었다» 는 사람이 원한 자리가 아니다. 물러선 «뒤» 는 잎의 «뒤» 와 같은 판이라 고른 노드의 잠금(`lockedBy`)을 먼저 본다. 물러선 «뒤» 도 못 서면 «안» 의 까닭(지금처럼)이다. 모듈 넣기도 같은 함수라 같은 규칙이다.

**이 규칙이 바꾼 기존 판** — `git grep -l -E "paletteAddTarget|palette-add" -- apps/web/test apps/web/build-test` 11 파일을 고친 소스로 돌려 셌다: 단위 `apps/web/test/edit/zone-insert.test.ts` «고른 노드의 판도 받는 타입 밖이면 이유 문장이다 — 탭을 고르고 단추 넣기» 하나가 빨강(탭 뒤로 물러섬). 그 케이스를 새 규칙(탭 뒤 · 뒤도 못 서면 «안» 의 까닭)으로 고쳤다. 실브라우저 판 다섯 파일에는 «안» 거절을 «넣기» 단추로 단언한 판이 없었다(끌기 거절 판은 이 함수 밖).

### 2. «한 행 떼어 내기» — 앞 행이 원본 id

화면의 첫 줄이 원래 그 노드였다(둘째 줄부터 사본). 그래서 **앞 행(repeat 1)이 원본 id · 코멘트 번호 · 별칭 · 상호작용 · 상태 보임을 지키고**, 뒤 행(repeat n − 1)은 복제(Cmd+D)와 같은 사본이다 — `paste-ops.ts` 의 `sameDocumentCopies`(새 id · 번호 걷음 · 별칭 · 상호작용 · 상태 보임은 그대로 — 사본 줄들이 원본과 같은 상호작용으로 돌던 것이 떼어 낸 뒤에도 같다). 행이 제 칸을 가졌으면 칸째 사본. 고른 것은 그대로 앞 행. 묶음은 `test`(전제) · `remove …/props/repeat`(기본 1) · `add …/rows/<i+1>` 셋.

### 2'. «열 틀로 칸 짓기» — 지금 그린 꼴을 칸으로

렌더러와 같은 셈(`@wirebound/theme-sdk` 의 `gridLayout`)을 문서 노드로 돌려 그 행 첫 줄의 칸을 읽는다 — 셀 틀 칸 → 셀 틀 조각 사본, 번호 열 → 그 줄의 번호 글(`Text` — 제 칸 행은 번호를 안 세어 수가 굳는다 · 되풀이 줄도 같은 수), 합계 행 · 빈 열 묶음의 빈 칸 → 빈 칸, 위 행 세로 칸이 덮은 열 → 안 짓는다. 문서의 열 전부를 센다(화면 상태에서 숨은 열도 칸을 받는다 — 칸 폭 합이 잎 열 수와 같아야 lint `grid-row-cells` 가 안 선다). 생략 띠는 두 행동 다 못 한다.

### 2''. 잠금 · 전제

- 두 묶음은 `commitOps` 앞에서 서버와 같은 물음(`editBlockedBy`)을 묻는다 — 행 · 그리드를 남이 쥐었으면 막힘(줄 `…` 항목도 별칭과 같은 조건으로 꺼진다).
- **칸 짓기는 셀 틀을 베낄 열을 남이 쥐었어도 안 나간다**(`buildCellsReads` → `store.lockedBy`) — 묶음은 그 열을 안 써 서버는 막지 않지만, 남이 고치는 중인 셀 틀을 베끼지 않는다. 떼어 내기는 열을 안 써 나간다.
- **전제(`test`)** — «닿기 전» 판(아래 «잰 값»)에서 떼어 내기가 남의 «되풀이» 고침을 말없이 걷었다. 그래서 떼어 내기 묶음 앞에 `test …/props/repeat = 지은 판의 값`, 칸 짓기는 칸 배열이 이미 있으면 `test …/children = []`(배열이 없으면 첫 `add` 가 배열째 지어 리베이스의 전제 `premiseOf` 가 지킨다)를 둔다. 셀 틀 글은 전제로 안 묶는다 — 칸 짓기는 누른 때 본 셀 틀을 베끼는 것(붙여넣기와 같다)이고 셀 틀 자신을 안 고친다.

### 3. 사본 위 놓기 — «거절 + 첫 행의 칸에 놓으세요» 를 골랐다

브리프의 두 길(«원본으로 읽기» · «거절»)을 견주었다. **원본으로 읽으면 표시가 선 자리(사본 줄)와 놓이는 자리(첫 줄 · 셀 틀)가 갈린다** — 미리보기는 원본 요소 곁(첫 줄)에 서는데 포인터는 셋째 줄에 있다. 사본 줄의 «앞 · 뒤» 는 문서에 없는 자리(한 행의 되풀이 사이)라 원본으로 읽을 «앞 · 뒤» 가 없다 — 행을 끄는 판이면 «되풀이 2 와 3 사이» 가 그 행의 «앞» 인지 «뒤» 인지 정할 수 없다. 설계서의 «대표 행 + 같은 꼴» 은 사본이 그림이라는 뜻이고, 그림 위의 놓기는 남의 노드(그리드)에 놓이는 길을 연다(고치기 전 판이 그 꼴 — 그리드의 «안» 으로 읽혔다). 그래서 사본 위는 `{ copy: true }` 로 끊고 포인터 곁에 «되풀이된 줄에는 놓을 수 없습니다 — 첫 행의 칸에 놓으세요» 를 둔다.

**문장이 말하는 자리가 실제로 받게** 첫 줄 틀 칸(`td[data-wb-cell="template"]` · 사본 아님)의 빈 자리는 그 열 셀 틀의 끝(`{ zone: { parentId: <열>, zone: 'body' } }`)으로 읽는다 — 고치기 전에는 가장 가까운 노드가 행(칸만 받는다)이라 표시도 까닭도 없었다. 사본 안의 틀 칸도 `data-wb-column-of` 를 달아 «사본인가» 를 먼저 본다(`closest('[data-wb-copy-of],[data-wb-id]')`). 번호 칸은 셀 틀이 안 그려져 열로 안 읽는다.

### 4. 안내는 카탈로그의 `EditorField.hint`

화면 글을 카탈로그 한 자리에 두는 결(`label` · `description` 과 같은 검사 — 빈 말 · 두 줄 · 60자 넘음은 정의에서 던진다). 속성 패널이 그 칸 밑에 몫 칸의 «쌍 수» 안내와 같은 꼴(`.wb-shell-prop-note`)로 그린다(한 노드 · 여럿 고른 판 둘 다). 다섯:

| 칸 | 안내 |
| --- | --- |
| 행 «되풀이» | 이 행을 몇 줄로 그릴지 — 둘째 줄부터는 첫 줄과 같은 꼴입니다 |
| 칸 «가로 칸 수» | 이 칸이 덮는 열 수 — 행의 칸 수 합이 열 수와 같아야 합니다 |
| 칸 «세로 칸 수» | 아래로 덮는 줄 수 — 아래 행의 칸은 덮인 열을 건너뜁니다 |
| 그리드 «고정 열 수» | 가로로 굴려도 왼쪽에 남는 열 수 — 선택 · 번호 열도 셉니다 |
| 열 «열 폭» | 정하지 않으면 칸 글이 한 줄로 길어집니다 — 꺾으려면 폭을 정하세요(FX-GR M2 의 대가) |

문구를 글자로 찾는 기존 케이스: 낱말 다섯을 테스트 파일에서 파이썬으로 셌다(`git grep -F … -- 'apps/*/test'` 는 글롭이 경로 전체에 안 맞아 0 을 냈다 — AGENTS 의 그 함정). «고정 열 수» 8(그 칸을 이름으로 찾는 `property-panel.test.tsx` 5 · 상호작용 문장 2 · 렌더러 케이스 이름 1) · «열 폭» 6(주석) · «되풀이» 56(주석 · 케이스 이름 — 칸을 찾는 자리 0) · «가로 칸 수» · «세로 칸 수» 0. 칸 이름은 안 바꿨고 안내는 `label` 밖 `<p>` 라 이름으로 찾는 자리가 안 바뀐다 — 그 파일들 통과.

## 남은 것

- **행을 끄는 판의 사본 줄**(낮음) — 사본 위 거절은 끄는 것을 가리지 않아, 행(`GridRow`)을 옮기며 사본 줄 위에 서면 «첫 행의 칸에 놓으세요» 가 선다(행 사이에 놓으려면 원본 줄의 앞 · 뒤 띠 · 구조 트리). 행을 끄는 판의 문장을 갈라 «행의 첫 줄 앞 · 뒤에 놓으세요» 로 할지는 정하지 않았다.
- **칸 짓기의 번호 칸은 수가 굳는다**(설계 뜻) — 되풀이 2 이상인 행에 칸을 지으면 되풀이 줄이 같은 수를 보인다. 번호 셈은 문서의 행 전부로 한다 — 지금 화면 상태에서 숨은 행이 있으면 그 상태에서 보이는 번호와 갈릴 수 있다(재지 않았다).
- **칸 짓기가 베끼는 셀 틀은 누른 때 본 것**(설계 뜻 — 전제로 안 묶었다). 남의 셀 틀 고침이 닿기 전에 누르면 낡은 글을 베낀다(«닿기 전» 판의 `[A, B, C]`).
- **되돌리기 · 다시 실행이 섞인 이력의 새로고침 뒤 되돌리기**(재지 않음 — 원래 있던 길) — 첫 판(21:58)에서 «떼기 → 되돌리기 → 다시 실행 → 칸 짓기 → 되돌리기 → 다시 실행 → 새로고침» 뒤 둘째 되돌리기가 처음 문서에 안 닿았다. 값을 안 적었고 줄 행동과 무관한 서버 이력 채우기의 몫으로 보여 갈라 쟀다(줄 행동만 쓴 판은 통과). 다음 차수가 그 판을 `editor-page-version.test.ts` 꼴로 다시 잰다.
- **안내 줄은 칸에 `aria-describedby` 로 안 묶었다** — 몫 칸 «쌍 수» 안내와 같은 꼴이다. 보조 기술은 칸 이름만 읽는다. 둘을 함께 묶을지는 속성 패널 전체의 몫.
