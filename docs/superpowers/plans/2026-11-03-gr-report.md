## 결정과 이유

1. **칸 유무로 셈한다 — prop 을 두지 않는다.** 렌더러(`gridLayout` 의 «칸을 하나라도 가지면 제 칸만») · 서버 검증 · MCP · 내보내기 · lint `grid-row-cells`
   가 이미 이 한 판정으로 그린다. prop(`content: basic | custom`)으로 두면 «커스텀인데 칸 없음» · «기본인데 칸 있음» 두 모순 판이 생기고, 검증 규칙 · 칸을 가진
   기존 행을 커스텀으로 옮기는 마이그레이션 · MCP 스킬 문서 · 카탈로그 판(테마 manifest) 이 함께 바뀐다. 옵션은 속성 패널의 화면 명령(베껴 넣기 · 걷기)이라
   스키마 · 마이그레이션 · `packages/*` 변경이 없다. 칸을 가진 기존 문서의 행은 그대로 커스텀으로 읽힌다.
2. **첫 행은 늘 기본 — 패널 칸과 행 줄 «열 틀로 칸 짓기» 가 같은 판정**(`FIRST_ROW_WHY` — `q-gr.md` Q1 의 코디네이터 답). 판정은 `buildCellsRefusal` ·
   `buildCellsOps` 한 곳이다. **이미 칸을 가진 첫 행**(합계 행이 첫 줄인 기존 문서 · 칸을 가진 행을 끌기 · 위로 · 붙이기로 첫 자리에 옮긴 판)은 깨지 않는다 —
   화면은 그대로 그리고, 패널은 «커스텀» 으로 보이며 «기본» 으로만 돌릴 수 있다. 행 순서를 바꾸는 입구는 막지 않았다(«남은 것»).
3. **기본 → 커스텀 = 기존 «열 틀로 칸 짓기» 묶음 그대로.** 셀 틀 조각은 새 id(`sameDocumentCopies` — 노드 id 유일 · 코멘트 번호 걷음 · 칸 안을 가리키던
   상호작용은 사본을 따라감)이고, 칸은 `gridLayout` 을 문서 노드로 돌린 첫 줄 꼴 그대로다(열 묶음 · 빈 열 묶음 → 빈 칸 · 번호 열 → 번호 글 · 선택 열은
   그리드가 그린다 · 고정 열 자리 같음 · 위 행 `rowSpan` 이 덮은 열은 건너뜀). 화면이 바뀌는 판은 하나 — **되풀이 2 이상 행 + 번호 열**이면 제 칸 행은 번호를
   안 세어 둘째 줄부터 번호가 첫 줄 수로 굳는다(단위 케이스가 잠근다 · 기존 GR-B 설계 그대로).
4. **커스텀 → 기본 = 칸 배열 통째 걷기 + 전제 `test`(내가 본 칸 배열).** 잃을 것이 없으면(칸이 지금 열 틀로 지을 칸과 id · 번호 · 칸 안 대상 차례를 빼고 같다
   — `cellsMatchTemplate`) 곧바로 걷고, 다르면 인라인 확인 줄을 거친다. 모달이 아니라 인라인인 까닭: 셸의 다른 «그 자리 확인»(페이지 · 빈 메뉴 삭제 · 복원)과
   같은 꼴이고 속성 패널 칸 아래에서 끝난다. 확인을 누른 때 칸이 물은 때와 다르면(남의 고침 닿음) 걷지 않고 다시 묻는다.
5. **반복 행 표의 «행 하나 더» 입구는 이미 셋이다** — 행 줄 «한 행 떼어 내기»(프리셋은 행 하나 `repeat 2` 라 첫 걸음이 이것) · 행 줄을 고르고 복제(Cmd+D) ·
   «행» 구역 줄에 팔레트 «행». 실브라우저 흐름이 앞 둘로 행 셋을 짓는다. 새 입구는 안 더했다.

## 남은 것

- **행 순서로 커스텀 행이 첫 자리로 오는 길은 안 막았다**(코디네이터 답) — 끌기 · 위로 · 들여쓰기/내어쓰기 · 붙이기 · 첫 행 지우기로 칸을 가진 행이 «행» 구역의
  첫 자리에 서면 기본 행(셀 틀)이 첫 행과 다른 꼴이 된다. 그 행은 패널에서 «커스텀» 으로 보이고 «기본» 으로만 돌린다.
- **«확인을 누른 때 칸이 바뀌었으면 다시 묻는다» 는 케이스가 없다** — 남의 고침이 확인 줄이 선 동안 닿는 판을 jsdom · 실브라우저로 안 세웠다(변조 J-4 는 반대
  갈래 — 같을 때 걷는다 — 만 잰다). 전제 `test` 가 같은 판의 서버 쪽을 막는다(단위 «걷기 전제»).
- **되풀이 2 이상 + 번호 열 행을 커스텀으로 바꾸면 둘째 줄부터 번호가 굳는다**(«결정» 3) — 화면이 바뀌는 유일한 판이다. 막지도 묻지도 않는다(GR-B 의 칸 짓기와 같다).
- 커스텀 행의 칸이 열 틀과 따로 산다 — 열을 더하거나 옮기면 그 행은 lint `grid-row-cells` 로 어긋남을 말한다(기존 성질).
- 실브라우저 판은 `editor-stack` dev 번들로만 돌았다(운영 번들 `EDITOR_STACK_BUNDLE=build` 은 안 돎 — 이펙트 · 마운트 순서를 바꾸지 않았다).

  파일마다 센다.»
