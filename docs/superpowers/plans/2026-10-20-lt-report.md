## 결정과 이유

- **정적 파일로 낸다(api 라우트가 아니다).** 요청마다 같은 글이고 인증 · 인스턴스 데이터 · 비밀값이 없다. 입구가 이미 `dist/` 를 파일로
  내고 vite 가 `public/` 을 내므로 두 판이 배선 없이 같은 바이트를 낸다. api 를 거치면 api 가 죽었을 때 안 나가고 잴 길만 는다.
- **커밋된 산출물 + 대조 케이스.** 빌드 때 짓기(vite 플러그인)는 vite 설정이 `@wirebound/mcp`(MCP SDK · cli)까지 싣게 된다 — 그
  길은 재 보지 않았다. 커밋하면 그 무게가 없고 diff 로 리뷰되며, 정의를 바꾸면 케이스가 죽는다(`-u` 로 다시 짓는다).
- **생성기는 `apps/web/config/`, REST 표만 `packages/mcp`.** 처음에 생성기를 `packages/mcp` 에 두었다가 `packages/mcp/test/assembly-census.test.ts`
  «런타임 의존이 둘뿐이다 — 순수 패키지를 직접 의존하지 않는다» 가 죽었다 — 그 패키지는 `@wirebound/schema` 를 일부러 의존하지 않는다.
  REST 표는 api 케이스가 값으로 읽어야 하는데 앱끼리는 서로의 소스를 못 부른다(api tsconfig 의 `rootDir`) — 그래서 의존 없는 값으로 mcp 에 둔다.
- **영어 설명은 손으로, 키는 정의로.** 카탈로그 · 도구의 `description` 이 한국어라 영어 글에 못 싣는다. 키가 다르면 던져 «설명 없이 조용히
  나감» 을 막는다. 에디터의 한국어 이름은 `Editor label` 로 함께 싣는다(사람과 말할 때 쓰는 이름).
- **REST 요약은 고른 것이다** — 토큰으로 닿는 프로젝트 라우트 가운데 에이전트가 쓸 만한 11 줄. 모듈 라우트(`pm` 트랙이 바꾼다) · 테마 이름은
  싣지 않았다. 빠진 라우트는 안 잰다(완전성은 `apps/api/README.md` 「엔드포인트」가 갖는다).
- **한 파일** — 12.9KB 라 `/llms-full.txt` 로 나누지 않는다.

## 남은 것

- **병합 순서에 걸리는 것:** `pm` · `th` 가 카탈로그(`packages/schema/src/component/catalog/*`) · 노드 필드 · MCP 도구 표를 바꾸면 합친 판에서
  `apps/web/test/llms-txt.test.ts` 의 대조 케이스가 죽는다 — 의도한 동작이다. 합친 판에서 `pnpm vitest run apps/web/test/llms-txt.test.ts -u`
  로 다시 짓고 커밋한다(컴포넌트를 더했으면 `apps/web/config/llms-txt.ts` 의 `COMPONENT_SUMMARIES` 에 영어 한 줄도 더해야 짓기가 안 던진다).
  `pm` 이 REST 표의 라우트(프로젝트 · 트리 · 페이지 · ops · 이력 · 코멘트 · 덤프 · 스냅샷 목록 · 테마 · 내보내기)를 걷거나 역할을 바꾸면
  `apps/api/test/llms-rest-routes.test.ts` 가 죽는다.
- **못 재는 것:** REST 표에 빠진 라우트(요약이라 일부러) · 표의 줄마다 토큰이 실제로 닿는지(그 성질은 `token-route-census.test.ts` 가 `:projectId`
  라우트 전부로 재고, 토큰을 거절하는 프로젝트 라우트 — 토큰 관리 셋 · `/ws` — 는 표에 없다) · 영어 설명의 뜻이 정의와 맞는지(키만 잰다) ·
  손으로 쓴 머리글(붙이는 법)의 명령이 바뀌는 것.
- **브리프 전제 한 줄:** 브리프의 «토큰 발급 자리(웹 «API 토큰» 화면)» — 웹은 토큰을 **발급하지 않는다**(계정 설정 «API 토큰» 절은 목록 ·
  폐기뿐이다). 발급은 `wireb login`(세션으로 `POST /api/projects/:projectId/tokens`)뿐이라 글도 그렇게 적었다.

## 지침

- **무엇이 비었나:** web 프로젝트(jsdom 환경)의 케이스에서 `import.meta.url` 로 파일 경로를 지으면 조용히 틀린다 — `existsSync(new URL('../x',
  import.meta.url))` 가 있는 파일에 `false` 를 내고(오류 없음), `fileURLToPath(new URL(…).href)` 는 `The URL must be of scheme file` 로 던졌다.
  파일을 읽는 케이스는 `// @vitest-environment node` 로 두면 둘 다 선다(`apps/web/test/llms-txt.test.ts` · `api-proxy-target.test.ts`).
- **어느 문서 어느 절:** `.ruler/20-verification.md`(wirebound 「검증」) 「jsdom 값은 실브라우저 값이 아니다 …」 문단 끝.
- **넣을 문장:** «**web 프로젝트(jsdom)의 케이스에서 `import.meta.url` 로 파일 경로를 짓지 않는다** — `existsSync(new URL(…, import.meta.url))`
  는 있는 파일에 오류 없이 `false` 이고 `fileURLToPath` 는 file 이 아니라고 던진다. 디스크를 읽는 케이스는 `// @vitest-environment node` 로
  둔다(`apps/web/test/llms-txt.test.ts`).»
