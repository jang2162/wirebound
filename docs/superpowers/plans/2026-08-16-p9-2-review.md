## 판정: **병합 가능**

**오늘 뚫린 구멍은 하나도 못 찾았다.** 인증 표면의 위험 지점 여섯을 전부 독립적으로
다시 쟀고 구현자 보고와 갈리는 값이 **하나도 없었다**(§2).

지적 여덟은 전부 **"지금은 옳은데 그것을 지키는 자가 없다"** 부류다 — 프로덕션이
틀린 것이 아니라 **변조해도 아무것도 안 죽는다**. 이 저장소가 같은 부류로 이미 두 번
당했고(`GET /:projectId/theme`가 매트릭스에서 빠져 가드를 없애도 0건이 죽었다 ·
`restore-lock-census`의 아홉이 census가 아니라 손으로 고른 아홉이었다), **N1은 세 번째
자리다.**

**N1·N2·N5를 P9-3 전에 닫기를 권한다.** 셋 다 P9-3이 라우트와 명령을 더하는 순간
값이 오르는 자들이고, N1은 내가 이미 써서 실증한 30줄이다(§3.1).

## 2. 위험 지점을 다시 쟀다 — 구현자와 갈린 값은 없다

### 2.1 스코프 검사는 `:projectId` 라우트 **전수**에 대해 선다

구현자는 D4 스코프를 **라우트 하나**(`GET /api/projects/:projectId`)로 쟀다
(`api-tokens.test.ts:400`). 계획서가 *"하나짜리로 재지 마라"*고 못박은 자리이므로 **전수로
다시 쟀다** — `onRoute` 이음매로 등록된 라우트를 받아, 프로젝트 A에 묶인 토큰으로
**프로젝트 B의 모든 `:projectId` 라우트**를 쏘았다(부속 파라미터는 filler uuid).

**결과: 404가 아닌 것이 하나뿐이고 그것이 옳다.**

```
GET /api/projects/:projectId/ws → 401   (WS는 쿠키만 — 가드보다 앞에서 끊긴다)
그 밖의 모든 (메서드 × 경로) → 404
```

대조도 붙였다 — 자기 프로젝트에서는 같은 자격으로 `GET .../tree`가 200이다.
**구현자의 하나짜리 판정이 전수로도 참이다.**

### 2.2 세션과 토큰은 교차하지 않는다

둘이 `auth/token-hash.ts`의 해시 함수를 공유하므로 양방향으로 쟀다.

| 무엇 | 값 |
|---|---|
| 세션 쿠키 **원문**을 `Authorization: Bearer`로 | **401** |
| API 토큰 **원문**을 `wb_session` 쿠키로 | **401** |
| API 토큰 원문을 쿠키로 실어 `GET /api/auth/me` | **401** |

교차가 성립하지 않는 이유는 `token-hash.ts`의 머리말이 적은 그대로다 — 공유하는 것이
**해시 함수**이고 조회는 서로 다른 표(`sessions` · `api_tokens`)를 서로 다른 술어로 본다.
해시가 같아도 넣은 표가 달라 못 찾는다.

### 2.3 WS는 **101 이전에** 끊긴다 — 진짜 소켓으로 쟀다

`api-tokens.test.ts`의 WS 케이스는 `inject()`라 업그레이드를 태우지 않는다(401만 본다).
그래서 진짜 포트를 열고 `Authorization` 헤더를 실은 **진짜 WebSocket**으로 다시 쟀다
(`ws-client.ts`는 쿠키만 싣는다).

| 상태 | 첫 이벤트 | 이벤트 목록 | 받은 프레임 |
|---|---|---|---|
| **지금** | `error` | `["error"]` | `[]` |
| `requireSessionAuth`를 뺀 변이 | **`open`** | `["open","close"]` | `[]` |

**보고서 §8의 서술이 정확하다.** 가드를 빼면 *"101이 선 뒤 소켓 콜백이 닫는 어중간한
상태"*가 실제로 재현되고(`open` → `close`), 가드가 있으면 **`open`이 아예 오지 않는다.**
그 변이로 커밋된 api 스위트에서 1건이 죽는다(*"WS는 쿠키만이다"*).

### 2.4 토큰 원문은 로그에 안 남는다

`loggerStream`으로 가로채 `logLevel`을 `info`·`debug` 둘로 재고, 정상(200)·404·400 세
갈래를 태웠다. **토큰 원문도 세션 원문도 로그에 없다.** `buildLoggerOptions`의 redact에
`req.headers.authorization`이 이 슬라이스에서 더해졌다.

토큰으로 편집한 뒤 `revisions` 행도 훑었다 — 원문 없음.

### 2.5 폐기는 자격을 즉시 거둔다 · 남의 토큰은 404다

`api-tokens.test.ts`가 이미 둘 다 든다(폐기 직후 401 · 남의 토큰 폐기 404). §10의
*"비멤버에게 프로젝트 존재를 숨긴다"*와 맞고, **404를 403으로 바꾸는 변이가 1건을
죽인다**(MA5) — 그 판정은 지켜지고 있다.

### 2.6 `last_used_at` 매 요청 갱신은 부수 효과가 없다

브리프가 물은 자리다 — *"읽기 요청을 쓰기로 만든다"*.

복원 잠금(`lockProjectForRestore`)을 한 커넥션이 쥔 채 다른 커넥션에서 토큰 인증
읽기(`GET .../tree`)를 쏘았다:

```
TOKEN_AUTH_BLOCKED=false   STATUS=200
```

**안 막힌다.** 근거: `last_used_at` UPDATE는 FK 컬럼(`project_id`)을 건드리지 않으므로
Postgres가 부모 행에 `FOR KEY SHARE`를 걸지 않는다 — `POST .../tokens`(삽입)가 막히는
것과 갈리는 자리다. `restore-lock-census.test.ts`가 그 삽입/삭제 둘은 이미 표에 넣었고,
**인증 경로의 UPDATE는 그 표의 대상이 아니다**(비-`GET` 라우트를 세는 표다). 재 보니
막히지 않으므로 표를 넓힐 이유도 없다.

### 2.7 종료 코드 3·4·2가 실제로 갈린다

빌드된 `dist/bin.js`를 실제로 돌렸다. **3과 4는 같은 URL로 대조했다** — 서버를 띄운
채와 내린 뒤.

| 입력 | 코드 | 문장 |
|---|---|---|
| 인자 없음 | **1** | 쓰임말(stderr) |
| `--help` | **0** | 쓰임말(stdout) |
| `login --password hunter2` | **1** | `Unknown option '--password'` |
| `pull` (자격 없음) | **2** | *"`wireb login`을 먼저 실행하세요"* |
| `pull` (서버가 404) | **3** | *"서버가 거절했습니다 (404): 프로젝트를 찾을 수 없습니다"* |
| `pull` (같은 URL, 서버 내림) | **4** | *"서버에 연결할 수 없습니다: … (connect ECONNREFUSED …)"* |
| `pull` (DNS 실패) | **4** | `getaddrinfo ENOTFOUND …` |
| `WIREB_TOKEN`에 한국어 | **2** | *"authorization 헤더에 보낼 수 없는 문자가 있습니다"* |

`a3c6d12`의 수정이 실제로 선다 — 그 커밋 전이면 마지막 줄이 4였을 자리다.

**하나 섞인다(사소 — N7):** `.wirebound.json`의 `server`가 **스킴이 없거나 오타**면
코드 **4**가 나온다.

```
server="wb.example.com"     → 4  "서버에 연결할 수 없습니다: wb.example.com/api/… (Invalid URL)"
server="htp://wb.example…"  → 4  "서버에 연결할 수 없습니다: … (unknown scheme)"
```

`exit.ts`의 표가 4를 *"주소·네트워크·서버 기동을 본다"*로 적었으므로 **표 안에는 있다.**
다만 원인이 **사용자의 설정 파일 한 줄**이라 표의 2(*"설정·자격이 없다 → `wireb init`"*)에
더 가깝고, **`a3c6d12`가 고친 것과 정확히 같은 부류다** — 사용자가 쓴 값이 `fetch`를
던지게 만들어 *"서버 탓"*으로 옮겨지는 것. 그때의 수정(보내기 전에 검사)을 URL에는 안
걸었다. 문장이 URL을 그대로 찍어 주므로 사람이 원인을 볼 수는 있다. **막는 지적이 아니다.**

### 2.8 리포에 자격이 안 남는다 · 파일 권한은 실제로 좁다

빌드된 바이너리를 스텁 서버에 붙여 `init` → `login` → (하위 디렉터리에서) `pull`을 돌렸다.

| 무엇 | 값 |
|---|---|
| 자격 디렉터리 | `drwx------` (0700) |
| 자격 파일 | `-rw-------` (0600) |
| 리포 안에 토큰 원문 | **없다** (`grep -rl`) |
| 리포 안에 세션 원문 | **없다** |
| 하위 디렉터리에서 `pull` | 0. **리포 뿌리에** `wirebound-snapshot.json` |

**프로덕션은 옳다.** 그런데 그것을 지키는 자가 없다 — N2.

## 3. 지적 — 전부 "0 사망" 부류다

변이는 **구현자가 안 건드린 자리**로 골랐다. `git checkout --`을 쓰지 않고 원본 전문을
메모리에 들고 `finally`에서 되썼으며, **매 변이 뒤 `git status`가 clean인 것을 확인했다.**

### 3.1 N1 (권함 — P9-3 전에 닫아라) · `:projectId`를 갖지만 가드를 안 단 라우트를 지키는 자가 없다

**오늘 그런 라우트는 0개다**(§2.1이 전수로 확인했다). 물음은 *"앞으로 생기면 무엇이 먼저
죽는가"*였고 — **아무것도 안 죽는다.**

`routes/tree.ts`에 라우트 하나를 더했다. `:projectId`를 갖고 `app.requireAuth`만 단다:

```ts
app.get('/:projectId/probe-leak', { preHandler: app.requireAuth }, …)
```

| 무엇 | 값 |
|---|---|
| 그 변이로 돌린 **api 스위트 전체** | **1230건 전부 초록 · 죽은 케이스 0** |
| 프로젝트 A의 토큰으로 프로젝트 B를 부르면 | **200** `{"leaked":1,"titles":["B 의 비밀 메뉴"]}` |

**남의 프로젝트 내용이 그대로 나오는데 초록이다.** 인증 훅이 *"패턴에 `:projectId`가 있다"*만
보고 `currentUser`를 채우고(D4), 스코프 판정은 `requireProjectRole`에 있는데 그 함수를
부르는 자가 `projectGuard`뿐이기 때문이다 — 가드가 없으면 판정 자체가 안 돈다.

**왜 지금 있는 census 둘이 못 잡는가.** 이것이 요점이다:

| census | 분모 | 이 라우트가 드는가 |
|---|---|---|
| `token-route-census.test.ts` | 등록된 라우트 전부를 `:projectId` **유무**로 가른다 | **안 든다** — 전수 주장이 *"`:projectId`가 **없는**"* 쪽에만 있다 |
| `permission-matrix.test.ts` *"표의 완전성"* | 소스에서 **`projectGuard`가 걸린** 라우트를 정규식으로 뽑는다 | **안 든다** — 가드가 없어 정규식에 안 걸린다 |

**둘이 서로의 사각을 만든다.** 앞엣것은 `:projectId`가 **있는** 쪽을 `api-tokens.test.ts`에
넘기는데(그 파일 머리말의 표가 그렇게 적었다) 그쪽은 라우트 **하나**만 잰다. 뒤엣것은
가드가 있는 것만 센다. 그래서 *"`:projectId`가 있는데 가드가 없는 라우트"*는 **어느 분모에도
안 든다.**

**고칠 것 — `token-route-census.test.ts`에 셋째 갈래를 실행으로 만든다.** 그 파일의
머리말 표는 이미 그 줄을 적어 두었다(*"`:projectId`가 있다 → 채운다 → `api-tokens.test.ts`"*).
그 위임을 거두고 여기서 전수로 잰다:

```ts
it('토큰의 프로젝트 밖에서는 :projectId 라우트가 전부 404다', async () => {
  // 같은 사람이 A·B 둘 다 owner다 — 404가 '멤버가 아니다'가 아니라
  // '이 토큰의 프로젝트가 아니다'임이 드러난다.
  // 부속 파라미터(:pageId 등)는 filler uuid로 채운다 — 가드가 핸들러보다 먼저 돈다.
  // /ws 만 401이다(쿠키 전용이라 가드 앞에서 끊긴다).
})
```

**내가 그 자를 써서 양방향으로 실증했다:**

| 상태 | 결과 |
|---|---|
| 지금 트리 | **초록** (`LEAKED=[]`) |
| 위 변이를 심은 트리 | **죽는다** (`LEAKED=[["GET /api/projects/:projectId/probe-leak",200]]`) |

30줄이고, `withCensus` 하네스가 이미 그 파일에 있어 새로 만들 것이 없다.

**이 저장소의 세 번째 자리다.** `permission-matrix.test.ts`의 *"표의 완전성"* 머리말이
적은 사고(`GET /:projectId/theme`)와 `restore-lock-census.test.ts`가 적은 사고(손으로 고른
아홉)가 같은 부류다. 둘 다 *"새 라우트를 만들면 등록한다"*가 사람이 기억할 규칙이었고
기억이 빠졌다.

### 3.2 N2 (권함) · 자격 파일 권한 0600/0700을 지키는 자가 없다

D6이 *"파일 권한을 좁혀라(0600)"*를 명시했고 **프로덕션은 그렇게 한다**(§2.8에서 실측).

| 변이 | 죽은 케이스 |
|---|---|
| `mode: 0o600 → 0o644`, `dirMode: 0o700 → 0o755` | **0 / 71** |

**원인을 찾았다 — 자가 볼 수 없게 되어 있다.** `test/fake-io.ts`의 `files.write`가
**셋째 인자를 아예 안 받는다**:

```ts
write: async (path, content) => { fs.set(path, content) },   // options 가 없다
```

`Io`의 계약은 `write(path, content, options?: { mode?, dirMode? })`인데 가짜가 그것을
버리므로 **단위 케이스가 권한을 관찰할 수단 자체가 없다.** `build-test/dist-bin.test.ts`도
`login`을 돌리지 않는다. 그래서 이 성질을 확인한 것은 보고서 §6의 **수동 스모크 한 번**뿐이고,
그것은 다시 안 돈다.

**고칠 것:** `FakeIo`에 `modes: Map<string, { mode?: number; dirMode?: number }>`를 두고
`write`가 그것을 기록하게 한 뒤, `login.test.ts`가 `credentials.json`의 mode가 `0o600`,
디렉터리가 `0o700`인 것을 단언한다.

### 3.3 N3 · `last_used_at` 갱신을 지키는 자가 없다

| 변이 | 죽은 케이스 |
|---|---|
| `findApiTokenByValue`의 `last_used_at` UPDATE를 통째로 뺀다 | **0 / 1230** |

목록 응답이 내는 필드라 사용자에게 보이는 값이다. 내가 따로 재 보면 실제로는 채워진다
(`LAST_USED_AFTER=Sun Aug 16 2026 21:48:10`) — 보고서 §6의 스모크와 같은 값이다.

**고칠 것:** `api-tokens.test.ts`에 한 케이스. 발급 → 그 토큰으로 아무 읽기 → 목록 응답의
`lastUsedAt`이 `null`이 **아니다**. 이미 있는 *"목록 응답에 원문이 없다"*가 `lastUsedAt: null`을
단언하므로 그 짝이 자연스럽다.

### 3.4 N4 · io 인구조사를 우회하는 길이 둘 실측된다

`io-boundary.test.ts`의 `EFFECTFUL` 정규식을 실제 소스에 심어 재 봤다.

| 변이 (`src/commands/` 안에서 `io`를 우회해 파일을 읽는다) | 죽은 케이스 |
|---|---|
| `import { readFile } from 'fs/promises'` — **`node:` 접두사 없음** | **0 / 71** |
| `import { readFile } from "node:fs/promises"` — **큰따옴표** | **0 / 71** |

정규식이 `from '(node:fs|node:fs\/promises|…)'`라 **작은따옴표와 `node:` 접두사를 둘 다
전제한다.** 그 전제를 강제하는 것이 있는지 봤는데 — **이 저장소에는 린터도 포매터도
없다**(`eslint`·`biome`·`oxlint`·`prettier` 어느 설정도 없다). 그러므로 두 우회는 실재한다.

순수 술어로 더 훑었다. 못 잡는 것: 동적 `import('node:fs')` · `createRequire` ·
`node:dns` · `node:tls` · `node:dgram` · `node:worker_threads`.

**잘 잡는 것도 확인했다:** `globalThis.fetch(` — `(?<!io\.)` 뒤보기가 제대로 판다.

**고칠 것:** 따옴표와 접두사를 둘 다 선택으로 만들고 그물을 넓힌다.

```ts
/from ["'](node:)?(fs|fs\/promises|os|path|readline|child_process|http|https|net|dns|tls|dgram)["']/
/\bimport\(\s*["'](node:)?(fs|fs\/promises|os|path|child_process|http|https|net)["']/
```

*(`node:util`은 지금대로 빼 둔다 — 그 파일의 머리말이 *"효과가 있는 것만 센다"*로 근거를
적었고 그것이 옳다.)*

### 3.5 N5 (권함 — P9-3이 바로 밟는다) · D6 census는 **명령 셋만** 돈다

브리프가 물은 자리다 — *"새 파일이 하나 늘면 그 자가 먼저 죽는가"*. **반은 참이다.**

| 변이 | 죽은 케이스 |
|---|---|
| **이미 있는** 명령(`pull`)이 리포에 토큰을 담은 캐시 파일을 하나 더 쓴다 | **1** ✔ |
| **새 명령**(`wireb sync`)이 리포에 토큰을 쓴다 | **0 / 71** |

파일 목록은 진짜로 스스로 만든다(`io.fs`를 훑는다) — 그래서 앞 줄이 죽는다. 그런데
**어떤 명령을 돌릴지는 손으로 적혀 있다**:

```ts
await run(['init', …], io); await run(['login', …], io); await run(['pull'], io)
```

**P9-3이 명령 셋을 더한다**(`page get` · `lint` · `export` — §12.3). 그중 하나라도 리포에
쓰면 이 census는 조용히 지나간다.

**고칠 것:** 분모를 `run.ts`의 `COMMANDS` 표에서 만든다 — 그 표를 돌며 각 명령을
실행하고 그 뒤에 리포를 훑는다. 그게 무거우면 최소한
`expect(COMMANDS.map((c) => c.words.join(' '))).toEqual(['init','login','pull'])`를 그 파일에
두어 **명령이 늘면 여기가 먼저 죽게** 한다.

### 3.6 N6 (사소) · `Authorization` 스킴의 대소문자 무시를 지키는 자가 없다

| 변이 | 죽은 케이스 |
|---|---|
| `bearerValue`의 정규식에서 `i` 플래그를 뺀다 | **0 / 1230** |

RFC 7235가 스킴을 대소문자 무시로 정하므로 **`i`가 있는 지금이 옳다.** 다만 지우면
`authorization: bearer <값>`을 보내는 클라이언트가 조용히 401을 받는다. 이미 있는
*"망가진 Authorization 헤더는 조용히 무시된다"* 케이스의 배열에 `'bearer <진짜 토큰>'`
한 줄을 더해 200을 단언하면 닫힌다.

### 3.7 N8 (사소) · `node-io.ts`가 *"권한 오류를 올려 보낸다"*를 주장하는데 지키는 자가 없다

| 변이 | 죽은 케이스 |
|---|---|
| `isNotFound`가 항상 `true` (모든 읽기 오류를 *"없다"*로 접는다) | **0 / 71** |

그 파일이 주석으로 *"권한 오류 같은 것은 그대로 올려 보내야 `run`이 그 문장을 사람에게
보인다"*고 적었다. 접히면 `chmod 000`된 자격 파일이 *"`wireb login`을 먼저 실행하세요"*(2)로
나가 사람이 엉뚱한 곳을 본다. **보고서 §5가 이 파일을 *"케이스가 거의 못 덮는다"*고 이미
적었으므로 새로운 사실은 아니다.** 값이 필요하면 이월에 옮길 자리다.

*(N7은 §2.7에 값과 함께 적혀 있다 — 설정 오타의 URL이 코드 4로 나가는 갈래다.)*
