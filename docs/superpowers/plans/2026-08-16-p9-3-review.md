### ⑥ `lint [경로]`가 입력이 아니라 출력을 거르는가 — **거른다. 값으로 실증했다**

케이스가 재는 것은 *"전체 N건 중 M건"* 문장뿐이라 **직접적이지 않다.** 그래서 프로젝트 단위
규칙을 실제로 걸어 봤다: `관리자/회원/목록`의 버튼이 `page:관리자/회원/상세`로 이동하는
프로젝트를 만들고 **경로를 `목록`으로 좁혀** 돌렸다.

```
경로 필터: 관리자/회원/목록 — 전체 0건 중 0건
결함 없음                                            ← 코드 0
```

입력이 좁혀졌다면 ④가 *"대상 페이지가 없다"*를 냈을 것이다. **반대편도 쟀다** — `상세`를
지우면 같은 경로 필터에서 그 규칙이 정확히 뜬다:

```
warning  관리자/회원/목록 (go)  page-target-missing  navigate의 대상 페이지가 프로젝트에 없습니다: page:관리자/회원/상세
```

→ **입력은 프로젝트 전체다. D5가 지켜졌다.**

**다만 종료 코드가 함께 걸러진다** — 이것이 아무 데도 안 적혀 있다. → **N1.**

**R8은 지적이 아니다.** *"문장화가 같은 접두를 쓴다 — 자리가 셋이면 여기가 죽는다"* 케이스는
**상수를 함께 바꿀 때** 죽도록 짜였고(그 케이스 안 주석이 정확히 그렇게 적었다), 실증했다 —
`PAGE_TARGET_PREFIX`를 `'pg:'`로 바꾸고 `describe.ts`를 재인라인하니 그 케이스가 **죽었다**
(17건 중 하나). 다만 **케이스 제목이 과장돼 있다** → **N10**(정보).

### N3 (하) — 가짜 `io`가 **본문을 두 번 읽는 것**을 막지 않는다

진짜 `Response`는 본문을 한 번만 내주므로 그 코드는 실서버에서 즉시 깨진다.

### N4 (하) — `export`의 *"하나라도 있으면 멈춘다"*가 **첫 항목으로만** 재진다

충돌 검사를 `files.slice(0, 1)`로 좁혀도 **0건이 죽는다**(R20). 케이스가 심는 충돌 파일이
`/repo/dist/index.html`인데 그것이 압축의 **첫 항목**이기 때문이다.

**고치는 법:** 같은 케이스를 픽스처의 **마지막 항목**(`pages/관리자-회원-목록.html`)으로 한 번
더 재거나, 기존 케이스의 충돌 파일을 그것으로 바꾼다.

### N5 (하) — `stripCommonRoot`의 `segments.length > 1` 가드가 안 재진다

`>= 1`로 바꿔도 **0건이 죽는다**(R19). 그 가드가 막는 것은 **뿌리 폴더가 없는 한 파일짜리
번들**이다 — 없으면 `'index.html'.slice(len+1)`이 `''`가 되어 `-o` 디렉터리 자체에 쓰려 든다.
오늘 서버가 언제나 뿌리 폴더를 두므로 프로덕션은 맞지만, **그 계약이 서버 쪽에 있고 CLI는
믿지 않기로 한 자리**(zip 경로를 안 믿는 것과 같은 자세)이므로 자가 있는 편이 결이 맞는다.

**고치는 법:** `bundleZip(over, null)`(뿌리 없는 번들 — 픽스처가 이미 그 인자를 받는다)에
파일 하나만 담은 케이스 하나.

### N6 (하) — `-o`가 **기존 파일**을 가리키면 코드 70이다

실측: `readFile('<파일>/index.html')`과 `mkdir('<파일>/sub')`이 둘 다 **`ENOTDIR`**를 낸다.
`node-io.ts`의 `isNotFound`는 **`ENOENT`만** 접으므로 그대로 올라가고, `run.ts`의 마지막
갈래가 그것을 *"버그다"*(70)로 낸다. **사람이 고칠 수 있는 상태인데 고칠 수 없는 번호로
나간다** — P9-2 이월 §6이 *"읽을 수 없는 자격 파일이 70으로 나간다"*로 열어 둔 것과 **같은
부류**다.

`--force`도 같다(충돌 검사를 건너뛰고 `mkdir`에서 같은 오류가 난다).

**고치라고 하지 않는다** — 그 이월이 적은 대로 손대면 `client.ts`의 갈래 표에 줄이 늘고
N8이 막으려던 자리와 겹친다. **이월에 한 줄 더하는 것으로 충분하다**(그 항목에 `export`가
표면을 넓혔다는 것과 함께).

**물음 1 — P9-2 이월 §6이 막으려던 자리와 다른가. 다르다.**

그 이월이 막은 것은 *"읽기 **실패**를 다시 잡아 정상 갈래로 접는 코드"*다(자격 파일을
못 읽는 것을 *"자격이 없다"*로 접는 것). `Io.files.kind`는 **실패를 안 접는다** — 접는 것은
`ENOENT` 하나뿐이고 나머지는 그대로 올린다(`read`의 `isNotFound`와 **같은 술어**다).
그리고 이것은 실패의 재해석이 아니라 **쓰기 전에 자리를 묻는 새 물음**이다.
`client.ts`의 갈래 표에 줄이 늘지 않는 것도 확인했다(그 파일은 안 바뀌었다).

**물음 2 — 거짓 양성. 없다.** 진짜 파일 시스템에 여덟 모양을 만들어 `kind`와 `mkdir -p`를
나란히 쟀다.

| 자리 | `kind` | `mkdir -p` | `wireb export` |
|---|---|---|---|
| 멀쩡한 디렉터리 | `directory` | ok | **돈다** |
| 없는 경로 | `null` | ok | **돈다** |
| 심링크 → 디렉터리 | `directory` | ok | **돈다** |
| 기존 파일 | `file` | `ENOTDIR` | **1** (고친 자리) |
| 심링크 → 파일 | `file` | `ENOTDIR` | **1** (옳다 — 쓰면 어차피 깨진다) |
| **끊긴 심링크** | `null` | **`ENOTDIR`** | **70** ← 안 덮였다 |
| 권한 없는 부모 아래 | **`EACCES` 던짐** | `EACCES` | 70 (전과 같다 · 접지 않는다) |
| `-o 파일/하위` | **`ENOTDIR` 던짐** | `ENOTDIR` | 70 (구현자가 머리말에 적었다) |

세 개가 도는 쪽이고 둘이 새로 1이 된다 — **멀쩡한 자리를 막지 않는다.**

**덧 하나:** 구현자는 안 덮이는 자리로 *"`-o`의 **조상**이 파일일 때"* 하나만 적었는데
**끊긴 심링크가 둘째다** — `stat`이 `ENOENT`를 내므로 `kind`가 *"없다"*로 읽고 지나간 뒤
`mkdir`이 `ENOTDIR`을 낸다(실측). 같은 부류이고 같은 값(70)이라 **고치라고 하지 않는다** —
이월의 그 줄에 *"조상이 파일일 때"* 옆에 한 마디만 더하면 된다.

## D4. N1의 새 자가 진짜 자인가 — 그렇다

- **R21이 죽는다**(1건 — *"다른 페이지에 error가 있어도 경로를 주면 0이다"*).
- **두 판이 갈릴 표면이 오늘 없다** — `wireb lint`에 `--json`이 없다(`COMMANDS`의 옵션이
  `fail-on` 하나다. `--json`은 `page get`만 갖고 그쪽엔 요약 줄이 없다). **P9-4가 그
  표면을 만든다** — MCP `validate`의 응답이 같은 범위 표기를 실어야 한다.
- **두 줄이 안 부딪힌다.** 밖에 `error` 둘과 `warning` 하나를 둔 프로젝트로 재 봤다:

  ```
  경로 필터: 관리자/회원/목록 — 전체 3건 중 0건
  결함 없음 — 경로 필터 안에서다 (전체 3건)        ← stdout
  경로 밖에 error 2건이 더 있습니다 …               ← stderr
  ```

  분모가 둘(전체 이슈 3 · 밖의 error 2)이지만 **각각 이름이 붙어 있고**, 종료 코드를 만드는
  쪽(`error`)이 stderr에 선다. **CI가 초록을 보면서 아무 말도 못 듣는 상태**가 닫혔다.
