## 문서 경로 판정(K-D1 «문서 경로 편집»)

`/viewStates/…` 를 고치기 **전** 소스에서 길마다 쟀다. 판정: **문서 경로로 간다** — 흔들린 곳이 경로 술어 한 줄과 «통째 교체» 세 자리뿐이라 루트 노드 필드 + 루트 잠금 면제의 길은 고르지 않았다.

| 자리 | 고치기 전 | 고친 것 · 재는 케이스 |
|---|---|---|
| 적용 · 역연산(`patch/apply.ts` · `inverse.ts`) | 받는다 — 경로를 가리지 않는다 | 없음 · `view-state-lock.test.ts` «적용과 역연산» 6칸(고치기 전에도 초록) |
| 잠금 판정(`lockConflictOfOps` · `findLockConflict` · `selectionConflicts`) | 받는다 — 겹침은 세그먼트 접두라 `/viewStates` 는 `/root` 아래 어떤 잠금(뿌리 포함)과도 안 겹친다 | 없음 · `view-state-lock.test.ts` «잠금 판정»(고치기 전에도 초록) |

## 태스크마다

### Task 1 — 모델 · 검증 · 카탈로그(+ 렌더러)

- `PageDocument.viewStates?: ViewState[]` · `VIEW_STATE_NAME_MAX`(30) · `VIEW_STATES_MAX`(20) · `DEFAULT_CASE` · `THEMELESS_TYPES`.
- 봉투 `PageEnvelopeSchema` · `ViewStatesSchema` — 이름은 걷은 값만(앞뒤 공백 거절 — 별칭과 같은 결) · 받지 않는 글자는 별칭 표(`alias.ts`) · id 는 노드 id 규칙이고 `default` 금지 · id · 이름 겹침 금지.
- 검증 코드 넷(모두 error · lint 표 `VALIDATION_RULE` 은 `document-invalid`): `state-case-default` · `state-case-duplicate` · `state-case-outside` · `state-switch-child`. 목록에 없는 상태의 가지는 검증 오류가 아니다(lint 몫 — K3).
- 카탈로그 `StateSwitchDef` · `StateCaseDef`(구조 갈래 · `state` 는 기본값 없는 필수 — 빈 props 를 기본 가지로 읽으면 구조 판정과 갈린다).
- **팔레트 카드 없음**(기본값): 팔레트 · `+` 고르개의 거름(`placeableGroups` — `createNode` 노드를 빈 페이지에 넣어 검증)이 두 타입을 스스로 뺀다. 인구조사 `type-picker` · `create-node` 의 «페이지에 둘 수 없는 타입»이 `['Slot', 'StateSwitch', 'StateCase']`.
- «테마가 안 그리는 구조»: manifest 가 선언하면 `themeless-component` · 갤러리 표본 없음(인구조사가 `THEMELESS_TYPES` 를 빼고 견줌) · `prop-marks` 인구조사도 뺌.
- 렌더러: `RenderOptions.viewState` · `renderDocument` 는 문서 목록에 없는 id 를 기본으로(레이아웃은 늘 기본) · 영역은 고른 가지만 · 가지는 자식만 — 요소를 남기지 않는다 · 그릴 가지가 없으면 아무것도 안 그리고 `onNodeError`.
- 요약: `nodeSummary` — `StateSwitch` «가지 N» · `StateCase` 상태 이름(«기본» · «목록에 없는 상태»).
- 케이스: `packages/schema/test/view-state-model.test.ts`(33) · `packages/renderer/test/view-state.test.tsx`(12) · 인구조사 갱신(catalog · lint-mapping · node-display · gallery · prop-marks · create-node · type-picker · manifest) · exporter 패리티 «상태» 픽스처.

### Task 4 — 이름 · 요약 · 보이는 트리 · 붙여넣기

- `nodeViewState(doc, nodeId)` / `viewStateIndex(root)`: **가장 가까운 기본이 아닌 가지**의 상태(관리자 가지 안 영역의 기본 가지 노드는 관리자) · 기본 가지들 안에만 있으면 `default` · 밖이면 `null`.
- `nodeDisplayName(node, ctx?)` · `describeNode(node, ctx?)` — `ctx.viewStateName` 이 있으면 «'승인 버튼'(관리자 상태)». 상호작용 문장(`listInteractionSentences` · `describeInteraction`)은 문서에서 맥락을 지어 붙인다 — 영역이 없는 문서는 한 글자도 안 바뀐다(케이스). 기본 가지 노드는 «(기본 상태)», 목록 밖 상태는 «(목록에 없는 상태 상태)».
- `visibleTree(doc, viewState)` — 영역마다 서는 가지 하나(영역 · 가지 노드는 남김) · 목록 밖 상태는 기본.
- `prepareNodesForPaste(nodes, { …, state? }, generate)` → `droppedCases: { state, count }[]`. 없는 상태의 가지를 빼고, 기본 가지가 정확히 하나가 아닌 영역은 영역째 풀어 기본 가지(없으면 남은 첫 가지)의 내용으로(기본값), 맨 위에 선 가지는 내용으로 푼다. 뺀 가지 안 노드를 가리키던 동작은 밖을 가리키는 동작으로 빠진다. `state` 를 안 주면 다 남긴다(지금 부르는 셋 — 붙이기 · 복제 · 프리셋 — 은 그대로).
- 케이스: `packages/schema/test/view-state-names.test.ts`(28) · `node-display.test.ts` 의 두 타입 칸.

## 이월 후보

1. **K2 — 영역 · 가지는 DOM 요소가 없다.** 구조 트리에서 `StateSwitch` · `StateCase` 를 고르면 캔버스에 외곽선 · 손잡이를 둘 요소가 없다 — 가지 안 노드 요소들의 합 상자로 재야 한다(배치 선의 측정 길). 영역 테두리 · 꼬리표(K2 Task 4)와 같은 측정.
2. **K2 — `+`/«안에 추가» · 끌어 놓기가 영역 · 가지를 모른다.** 영역을 고르고 «안에 추가»하면 영역 아래에 평범한 노드가 들어가 `state-switch-child` 로 422, 가지를 끌어 영역 밖에 놓으면 `state-case-outside` 422 — 서버가 막지만 화면이 미리 끄지 않는다.
3. **K2 — 트리 줄 글.** 웹의 구조 트리 줄은 `nodeRowLabel(node)` 를 목록 없이 불러 `StateCase` 줄이 «목록에 없는 상태»로 읽힌다 — `page.viewStates` 를 넘겨야 한다. 상호작용 대상 고르개(`panels/interaction-panel.tsx` 의 `describeNode`)도 맥락을 안 넘긴다(문장은 이미 상태를 붙인다).
4. **K2 — `editInForkOps` 의 경계.** 기본 가지의 `children` 밖을 하나라도 건드리는 묶음(가지 자신의 필드 · 영역 밖과 섞인 묶음 · 영역 밖에서 들어오는 `move`)은 `null` — 화면은 그 묶음을 평범한 편집으로 보낼지 막을지 정해야 한다.
5. **K3 — 가지만 복사.** `readNodesEnvelope` 는 봉투의 노드를 임시 `Page` 뿌리 아래에서 검증해 맨 위에 선 `StateCase` 를 `state-case-outside` 로 거절한다(붙여넣기가 말없이 아무것도 안 함). `prepareNodesForPaste` 는 맨 위 가지를 풀 줄 알지만 봉투가 먼저 막는다.
6. **K3 — 통지의 상태 이름.** `droppedCases` 는 상태 id 만 센다 — 다른 페이지에서 온 가지의 상태 이름은 노드 봉투에 없다(봉투에 출처 `viewStates` 를 실을지 정해야 한다).
7. **K3 — lint 셋 · MCP · exporter 의 코멘트 이름**(`packages/exporter/src/bundle/comments.ts` 의 `describeNode` — 맥락 없음) · 프리셋 · 붙이기의 `keep.state` 연결.
8. **테마 `views` 의 키.** 테마가 `views.StateSwitch` 를 정의해도 조용히 무시된다(뷰 키를 검사하는 자리가 없다 — 테마 manifest 만 거절한다). 낮음.
9. **`lock-selection-oracle` 의 5s 한도.** 위 «게이트»의 시간 초과 — 케이스에 한도를 주거나(예: 15s) 판 수를 줄일지 정해야 한다. 낮음.

웹(`apps/web/src/store/anchored-ops.ts`): 리베이스 · 되돌리기가 `/viewStates/<i>(/…)` 를 **상태 id 로**, `add /viewStates/<i>` · `move` 의 `path` 를 **앞 · 뒤 상태 id 줄**로 붙잡는다(노드와 같은 규칙). 그 상태가 사라졌으면 못 얹음(`dropped` · `skipped`). 없는 목록을 만드는 `add /viewStates [상태]` 는 «목록이 없었다»가 전제라, 남이 먼저 목록을 만들었으면 못 얹는다(덮지 않는다). **K2 가 상태 관리 대화 상자를 세우면 이 길을 그대로 탄다** — K2 브리프에 «남이 순서를 바꾼 뒤 되돌리기 · 409 리베이스»를 실브라우저 케이스로 적는다(리뷰 R1 의 고칠 방향).
