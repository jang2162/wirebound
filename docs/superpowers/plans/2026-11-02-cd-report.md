## 결정과 이유

- **격자를 상태와 무관하게 한 자리에 둔다.** 상태마다 다른 자리에 그리면 불러오는 중에 연 폼이 목록이 닿는 순간 새로 마운트되며 친 글을 잃는다
  (`ProjectForm` 의 칸은 그 컴포넌트의 상태다). 그래서 `ProjectCards` 가 `projects: ProjectListItem[] | null` 을 받아 늘 그려진다.
- **연 추가 카드는 제 상자를 거두고 폼이 카드 상자를 그린다**(`[data-open='true']` 의 `border: 0`). 폼 규칙(`.wb-shell-project-form`)이 이미
  카드 꼴(테두리 · 바탕 · 안쪽 여백)이라 상자가 두 겹이 되지 않게. 결합자 선택자는 `test/shell-css.test.ts` 가 막아 폼 규칙 제자리에서 값을 고쳤다
  (폼을 쓰는 곳은 이 카드 하나다).
- **닫히면 포커스를 «프로젝트 추가» 단추로 돌린다** — 폼이 단추 자리를 대신하므로 취소 · Esc 뒤 포커스가 `body` 로 떨어진다(설계에 없던 것 · 워커 판단).
- **조작 실패 알림은 지금 자리(목록 위)** 그대로다. 폼 안으로 옮기지 않았다.
- **«열기» hover 색은 두지 않았다** — 저장소에 주색의 짙은 판이 없어 새 색을 짓지 않았다.
- **«요청이 나가 있는 동안 여는 버튼과 제출이 잠긴다»** 의 여는 단추 단언을 «여는 단추가 화면에 없다» 로 바꿨다 — 폼이 단추 자리를 대신하고 폼의
  «취소» 도 요청 중에 잠겨, 요청 중에 여는 단추가 다시 서는 판이 지금 없다. 단추의 `disabled={busy}` 는 남겼다(그 판이 생기면 막는다 — 주석).

- `shell.css` 는 트랙 P 도 고친다 — 이 트랙은 홈 묶음(`.wb-shell-home-*`) 안에 새 규칙을 두고, 밖에서는 `.wb-shell-project-form` 의 값 셋을 제자리에서
  고치고 `.wb-shell-project-create`(+`:disabled`) · `.wb-shell-project-settings` 두 덩이를 걷었다. 걷은 `.wb-shell-project-settings` 는
  «프로젝트 설정(`routes/settings.tsx`)» 머리 주석 바로 위다 — P 가 그 머리 근처를 고치면 병합 때 맞닿는다.

## 지침

1. **무엇이 틀렸나:** 넘침 표본 낱말 규칙이 «하이픈을 넣지 않는다» 만 말한다. 한글 긴 낱말은 Chrome 이 음절 사이에서 꺾어 `overflow-wrap` 이 없어도
   안 넘친다 — 한글로 지은 «끊을 자리 없는 긴 이름» 판은 꺾기 규칙을 뗀 변조(B1b)에 살았다.
   **어느 문서 어느 절:** `.ruler/20-verification.md` 「수를 셀 때는 두 번 세고 표본을 열어 본다 — 덧붙임」 의 «화면 넘침은 요소 상자로만 세지 않는다» 줄.
   **넣을 문장:** «넘침을 보일 표본 낱말은 끊을 자리 없는 **영문**으로 짓는다 — Chrome 은 띄어 쓰지 않은 한글도 음절 사이에서 꺾어, 한글 긴 낱말은
   `overflow-wrap` 을 뗀 변조에도 안 넘친다(`apps/web/build-test/project-cards.test.ts` 의 `LONG_NAME`).»
2. **무엇이 틀렸나:** 첫 요청만 끊는(`page.route` 에서 한 번 abort) 실패 판이 dev 번들에서 안 선다 — `StrictMode` 가 조회 이펙트를 두 번 돌려 둘째
   요청이 판을 메운다. 지금 지침은 StrictMode 로 «수가 두 배» 인 것만 말한다.
   **어느 문서 어느 절:** `.ruler/30-delegation.md` 「실브라우저 판은 `apps/web/build-test/` 에 케이스로 잠근다」 단락의 «dev 번들의 실브라우저 판은
   `StrictMode` 라 …» 문장 뒤.
   **넣을 문장:** «조회 실패 판을 `page.route` 로 세울 때 첫 요청만 끊지 않는다 — dev 번들은 마운트 이펙트가 두 번 돌아 둘째 요청이 판을 메운다. 그
   경로 · 메서드의 요청을 전부 끊고 끊은 수 > 0 을 카나리아로 적는다(`apps/web/build-test/project-cards.test.ts` «조회가 끊긴 판»).»
3. (틀린 것 아님 · 확인) `.ruler/30-delegation.md` «입구 · 단추를 걷거나 더하는 트랙은 … 실브라우저 전량을 게이트 전에 한 번 돈다» 가 맞았다 — C1 의 4 이름
   셈(«새 프로젝트» · «설정»)에 안 걸린 클래스 셈(`rv-ws-workspace.test.ts` 의 `.wb-shell-home-card` 수)을 실브라우저 전량이 잡았다. 이번에는 게이트 «전» 이
   아니라 게이트 안에서 잡혔다 — 브리프가 «게이트 전에 한 번» 을 적었는데 그 판을 게이트 체인과 합쳐 돌렸다.
