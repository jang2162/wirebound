# P8-1 exporter 코어 — 페이지 한 장 구현 계획

> **에이전트에게:** 태스크 단위로 실행한다. 각 태스크는 실패하는 케이스 → 최소 구현 →
> 통과 → 커밋의 순서를 지킨다.

**목표.** `packages/exporter`를 세우고 **페이지 문서 하나를 정적 HTML 한 장으로** 만든다.
이 슬라이스가 끝나면 *"서버에서 렌더한 것이 화면에서 그린 것과 같다"*가 **실측으로** 참이
된다.

**§11.3:** *"`exporter`가 `renderer`를 **서버에서 실행해** 정적 HTML을 만든다. (…)
**렌더러가 하나뿐이라 결과가 어긋날 수 없다.**"*

**P8을 셋으로 나눈다.** ① **exporter 코어 — 페이지 한 장**(이 슬라이스) → ② 번들 구조와
뷰어 셸(`index.html`·트리 네비·코멘트·여러 페이지) → ③ 상호작용 런타임과 내보내기 경로
(api·웹·내려받기).

**왜 이 순서인가.** P7-3 이월 §8.2가 P8을 겨냥해 남긴 규칙이 *"판정을 두 벌 두지 마라 —
화면·서버·번들이 같은 함수를 부르게 하라"*이다. **그 명제가 참인지부터 실측하지 않으면
②·③이 그 위에 쌓인다.** §11.3의 *"어긋날 수 없다"*는 설계의 주장이지 측정이 아니다.

**스택.** `packages/exporter`(신규) · `packages/renderer`·`packages/themes`(그대로 쓴다) · vitest.

## 전역 제약

- **워크트리 안에서만 작업한다.**
- `pnpm test` · `pnpm typecheck` · `pnpm build`가 마지막에 전부 통과해야 한다.
  **종료 코드는 파이프 없이 따로 찍어라.**
- **api 테스트는 Postgres 하나(포트 5433)를 공유한다.** **게이트를 돌리기 전에 다른 세션이
  돌고 있지 않은지 확인하라** — P7-3에서 두 세션이 동시에 돌려 타임아웃 셋으로 exit 1이
  났고, 원인이 경합이었다(`vitest`의 `singleFork`는 **서로 다른 프로세스에 적용되지
  않는다**. P7-3 이월 §10의 실측).
- **`git checkout --`을 쓰지 마라.** python 치환으로 심고 `finally`에서 원본 전문을 되쓴다.
  **`git diff`로 확인하지 마라** — 새 파일은 untracked라 늘 비어 있다.
- **0 사망이 나오면 그렇다고 보고해도 된다. 다만 원인을 단정하지 마라.** 못 죽였으면
  **겨냥을 바꿔 다시** 재라. **케이스가 구현과 무엇을 공유하는지 보라** — P7-3 이월 §9가
  두 방향을 다 적었다(같은 함수를 불러 **함께 움직이는** 것과, 로직을 베껴 **안 움직이는**
  것).
- **수를 산문에 적지 마라.** 세야 한다면 **케이스가 만들게 하라.**
- **단언을 주석에 적지 마라** — *"…하는 일이 없다"*는 **코드가 그것을 실제로 보장할 때만**
  참이다(P7-3 이월 §8.2 규칙 3).
- **머리말은 본문보다 늦게 고쳐진다.** 계약을 바꿨으면 **같은 커밋에서** 고쳐라.
- **소스에 날 제어 바이트를 넣지 마라.** P7-3이 그것 때문에 `grep`이 파일을 조용히 건너뛰는
  사고를 당했고 검사를 세웠다 — **그 검사가 이 패키지도 덮는지 확인하라.**
- **설계 문서(`docs/superpowers/specs/*`)는 고치지 않는다.** 어긋나면 판정해 보고한다.
- **남이 잰 값은 귀속을 붙여 옮긴다.**

## 확정한 결정

### D1. **`packages/exporter`는 파일 시스템을 모른다 — 값을 낸다**

내보내기 코어가 `fs`를 부르면 **소비자가 셋인데 자리가 하나**가 된다: api 라우트(P8-3) ·
CLI(P9) · 테스트. 그리고 테스트가 임시 디렉터리를 만들어야 한다.

**`exportPage(...)`는 `{ html, css }`를 값으로 돌려준다.** 파일로 쓰는 것은 P8-2·P8-3이
각자 한다.

### D2. **의존 방향은 `schema ← renderer ← exporter`이고 `themes`도 본다**

CLAUDE.md: *"의존 방향은 한 방향이다: `schema` ← `renderer` ← 나머지."* `exporter`는
*"나머지"*이므로 `renderer`·`themes` 둘 다 볼 수 있다.

- **`react-dom`을 이 패키지의 진짜 의존으로 더한다**(`renderToStaticMarkup`). `apps/web`에
  새 런타임 의존을 더하지 말라는 규칙은 **웹 앱의 것**이고 새 패키지에는 해당하지 않는다.
- **브라우저에서 돌 필요는 없다.** 다만 **Node 전용 API를 최소로** 쓴다 — P9의 CLI가 같은
  함수를 부른다.

### D3. **`renderDocument`만 쓴다 — 레이아웃 합성은 이 슬라이스가 하지 않는다**

사실 4가 재 둔 것이다: `renderComposed`는 노드 둘을 더하므로 **캔버스가 그리는 것과 다르다.**
이 슬라이스의 목표가 *"화면과 같다"*를 실측하는 것이므로 **같은 함수를 써야 한다.**

레이아웃을 번들에 넣을지는 **P8-2가 셸을 만들 때 판정한다** — P7-3 이월 §5가 *"번들이 첫
소비자"*라고 적어 둔 자리다.

### D4. **카탈로그 설치를 계약으로 둔다** — 사실 5

P5-3 이월이 이름을 붙여 넘긴 자리다. **`exportPage`가 카탈로그·구조가 설치되지 않은 채
불리면 조용히 지나가지 않게 하라.**

- 설치 여부를 **함수가 스스로 확인**하든, 설치를 **함수가 하든** 판정하고 근거를 적어라.
- **케이스로 고정하라** — *"설치 없이 부르면 무엇이 관찰되는가"*를 값으로 적어라.

### D5. **테마는 인자로 받는다 — 어디서 오는지는 호출자가 정한다**

P6-2 이월 §3이 *"P8은 테마를 payload에서 읽어야 한다 — 라이브 테마는 **그때**가 아니다"*라고
적었다. **그것은 스냅샷을 내보낼 때의 정책**이고, 라이브 페이지를 내보내면 라이브 테마가
맞다.

**순수 패키지가 그 정책을 갖지 않는다.** `exportPage`는 `ResolvedTheme`(또는 그것을 만들 수
있는 것)을 받고, **무엇을 넘길지는 P8-3의 라우트가 판정한다.**

**테마가 없는 프로젝트도 정상이다**(`layouts.theme_id`가 `NULL`을 받는다 — P6-1이 쟀다).
그때 CSS가 무엇이 되는지 케이스로 고정하라.

### D6. **이 슬라이스의 핵심은 *"같다"*를 실측하는 것이다**

§11.3의 *"렌더러가 하나뿐이라 결과가 어긋날 수 없다"*는 **설계의 주장**이다. 재라.

**같은 문서 · 같은 테마 · 같은 카탈로그로 두 경로를 돌려 DOM을 견준다:**

| 경로 | 무엇 |
|---|---|
| 화면 | jsdom에서 `renderDocument`를 React로 그린다(오늘 캔버스가 하는 것) |
| 번들 | `exportPage`의 `html`을 jsdom에 넣는다 |

- **견주는 단위를 문장으로 못박아라** — 태그·속성·순서 중 무엇을 보는가. §6.11의 여섯
  속성은 **반드시** 포함한다(사실 6).
- **다르면 원인을 판정해서 보고하라.** 고치는 자리가 exporter일 수도, renderer일 수도,
  *"원래 다른 것이 맞다"*일 수도 있다. **조용히 맞추지 마라.**
- **문서 하나로 재지 마라** — 카탈로그의 컴포넌트를 넓게 덮는 문서로 재고, **무엇을 덮었는지
  케이스가 세게 하라.**

### D7. **HTML 한 장의 모양은 최소로 둔다**

`<!doctype html>` · `<html lang>` · `<head>`(`<meta charset>` · `<title>`) · `<body>`.
**셸·네비·3분할은 P8-2다.** 여기서 미리 만들지 마라 — P8-2가 §9의 3분할을 판정한다.

- **CSS를 링크로 걸지 인라인할지도 P8-2다.** 이 슬라이스는 `css`를 **값으로만** 낸다(D1).
- **`<title>`에 무엇을 넣을지는 판정하라** — 페이지 제목이 자연스럽지만 `exportPage`가
  제목을 받는지부터 정해야 한다.

### D8. **HTML 이스케이프를 실측하라**

문서의 문자열은 **사용자가 적은 것**이다. `<script>`·`</`·따옴표가 props에 들어 있으면
번들이 깨지거나 더 나쁜 것이 된다.

- `renderToStaticMarkup`이 무엇을 이스케이프하고 무엇을 안 하는지 **재서 표로 적어라.**
- **케이스로 고정하라.** 이것은 번들이 남에게 전달되는 산출물이라 이 저장소의 다른 어느
  곳보다 이 축이 세다.
