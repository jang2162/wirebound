# 워크트리 격리 — 리뷰

> 대상: `fix/worktree-isolation` (df407f7, main d65f718 위 네 커밋) · 계획
> `2026-08-19-worktree-isolation.md` · 구현자 보고 `2026-08-19-worktree-isolation-report.md`

**한 줄. 병합 가능하다.** 조용한 둘을 **고치기 전·후 양방향으로 내 손으로 재현**했고
(전: B 에디터에서 B 계정 401·A 계정 200·B의 api 0건 / 후: 각자 자기 계정 200·남의 계정 401),
게이트 넷이 전부 **0**이며, 구현자가 낸 값들이 **재현된다.** 다만 **막지는 않지만 고치고 갈
자리가 셋**이고(문서가 든 값 하나가 틀렸다·수가 이미 낡았다·CLAUDE.md 가 두 벌이다),
**변이 아홉 중 넷이 살았다** — 살아남은 자리가 전부 **"순수한 규칙은 자가 있고 그 규칙을
꽂는 배선에는 자가 없다"** 한 꼴이다.

**이 기계.** macOS 26.6.1(Darwin 25.6.0) · Apple Silicon · Node **22.23.1** · pnpm **10.0.0** ·
vite **6.4.3** · vitest **3.2.7**. 아래 값은 전부 **이 기계에서 리뷰어가 잰 것**이고, 구현자의
값을 옮긴 자리에는 그렇다고 적었다.

**공유 자원.** 시작·끝 모두 `wirebound` = **14 users / 16 projects / 358 pages**. 남은 DB는
시작과 같은 다섯(`postgres`·`template0`·`template1`·`wirebound`·`wirebound_test`). 볼륨 넷을
하나도 만들지도 지우지도 않았고 컨테이너를 지우거나 다시 만들지 않았다. 포트 3001·5173·
3000(사용자 것)은 안 건드렸다. 검증용 DB **여섯**과 워크트리 **넷**을 새 이름으로 만들고
**전부 지웠다**(§9).

## 1. 조용한 둘 — **양방향으로 쟀다**

### 1.1 조용한 것 ① 에디터가 옆 워크트리의 API에 붙는다

**고치기 전**(main). B의 에디터(5175)로만 요청했다:

| 무엇 | 관측 |
|---|---|
| B 에디터 + **B 자신의 계정** | **401** `{"error":{"code":"unauthenticated","message":"이메일 또는 비밀번호가 올바르지 않습니다"}}` |
| B 에디터 + **A의 계정** | **200**, 그리고 `/api/auth/me`가 **A의 alice**(`alice@a.example`)를 돌려줬다 |
| **B의 api(3062)가 본 요청** | **0건** (로그 0줄) |
| **A의 api(3061)가 본 요청** | **3건** (로그 6줄, `req`·`res` 쌍 셋 — 401·200·200) |
| vite가 한 말 | **0줄** |

**고친 뒤**(fix, §6의 무대 그대로):

| | C 계정 | D 계정 | 그 api가 본 요청 |
|---|---|---|---|
| **C 에디터**(5174 → 3063) | **200** | **401** | C api 2건 |
| **D 에디터**(5175 → 3064) | **401** | **200** | D api 2건 |

각 DB의 `users`도 하나씩만 들어 있었다(`wb_revc: c@iso.example` / `wb_revd: d@iso.example`).
**§1.1의 전에서 200이 나오던 자리가 401이고, 0건이던 api가 자기 요청을 본다.**

### 1.2 조용한 것 ② 한 워크트리의 마이그레이션이 다른 쪽 스키마를 바꾼다

**고치기 전.** B의 `DATABASE_URL`을 A의 DB로 돌렸다(오늘 그것을 막는 것이 없다). A의 서버는
계속 떠 있었고 A는 아무것도 안 했다.

```
# B 에서
$ pnpm --filter @wirebound/api migrate:down
  ✓ Down 0011-api-tokens
마이그레이션 완료                                  ← 종료 코드 0. 어느 DB 인지 한 마디도 없다

# A 의 살아 있는 서버
$ curl .../api/projects/<id>/tokens
{"error":{"code":"internal","message":"서버 오류가 발생했습니다"}}   http=500
# A 의 로그에만 level:50 한 줄: relation "api_tokens" does not exist
```

같은 요청이 직전에는 `[] http=200`이었다.

**고친 뒤.** §3.1대로 값을 가른 상태에서 D가 `migrate:down`을 돌렸다 → 종료 0, 그리고
**C의 살아 있는 서버는 그대로 `http=200`.**

> **구현자의 §2.2·§2.3 값이 전부 재현된다.** 수치까지 같은 자리(401/200/0건/500/
> `relation "api_tokens" does not exist`)와, 판마다 달라지는 자리(로그 줄 수)를 구분해 적었다.

## 2. D1 — 포트 한 자리 · **"새 런타임 의존 0"은 참이다**

### 2.1 늘어난 것이 무엇인가 — 판정: **참**

| 어디 | 늘어난 것 |
|---|---|
| `apps/web/package.json` | **`"@types/node": "^26.1.2"` 한 줄, `devDependencies` 안** |
| `pnpm-lock.yaml` | 같은 것 **세 줄**(web importer의 devDependencies 항목) |

- **`dependencies`는 한 글자도 안 늘었다.** 타입 전용이라 번들·런타임에 안 들어간다.
- 그 버전은 저장소가 이미 네 곳에서 쓰는 것과 **같다**(`packages/mcp`·`cli`·`schema`·`apps/api`
  전부 `^26.1.2`).
- 읽는 수단은 `node:util`의 `parseEnv` — 이 기계의 Node **22.23.1**에서 `function`이고
  **stderr에 experimental 경고를 안 낸다**(따로 쟀다). 저장소 `engines`는 `>=22.9.0`.

**판정: *"새 런타임 의존 0"*은 참이다.**

### 2.2 재라 #2 — 셸이 이기는 순서를 **두 실행자에서** 쟀다

`apps/api/.env`에 `PORT=3063`이 있는 워크트리에서 셸에 `PORT=3065`를 걸었다.

| 실행자 | 관측 |
|---|---|
| **api 서버** (`pnpm --filter @wirebound/api start`) | `Server listening at http://127.0.0.1:3065` |
| **vite** (`pnpm --filter @wirebound/web dev`) | `➜  API 프록시:  http://127.0.0.1:3065` |

**두 실행자가 같은 답을 낸다.** 셸 값이 없을 때는 둘 다 `.env`의 3063(§6.1의 네 터미널).

**숫자가 아닌 값을 셸에 걸면 둘 다 시끄럽다.**

| 실행자 | 종료 코드 | 문구 |
|---|---|---|
| api | **1** | `Error: 설정을 읽을 수 없습니다: PORT: PORT은 숫자여야 합니다` |
| vite | **1** | `Error: 셸 환경변수 PORT이 숫자가 아닙니다: "삼천"` |

한쪽만 뜨는 상태가 안 만들어진다 — D1이 없애려던 *"둘이 다른 답을 낸다"*가 이 갈래에서도 닫혔다.

## 4. D2 — DB 가르기

### 4.1 만드는 절차가 정말 한 줄인가 — **참**

```
$ docker exec wirebound-postgres psql -U wirebound -d postgres -c 'CREATE DATABASE wb_revc;'
```

여섯 번(`wb_rev_a`·`wb_rev_b`·`wb_revc`·`wb_revc_test`·`wb_revd`·`wb_revd_test`) 전부 종료 0.
만들어진 DB는 `wirebound`와 **소유자·인코딩·콜레이션이 같다**:

| DB | owner | encoding | collate |
|---|---|---|---|
| `wirebound` | `wirebound` | UTF8 | en_US.utf8 |
| 새로 만든 것 전부 | `wirebound` | UTF8 | en_US.utf8 |

### 4.2 **DB가 없을 때 무엇이 보이나** — 사실 5의 함정 부류가 **아니다**

`TEST_DATABASE_URL`을 없는 DB로 걸고 api 테스트를 돌렸다 — **종료 코드 1**:

```
Error: 테스트 DB "wb_없는DB" 가 없습니다.
컨테이너 안에서 한 줄로 만든다:
  docker exec wirebound-postgres psql -U wirebound -d postgres -c 'CREATE DATABASE wb_없는DB;'
TEST_DATABASE_URL 은 셸 → apps/api/.env → 기본값 순서로 정해진다.
…
Caused by: error: database "wb_없는DB" does not exist
```

- **권하는 명령을 그대로 붙여 넣어 봤다** — 한글 이름이어도 `CREATE DATABASE`, 종료 0.
  (§10에서 지웠다.) 퍼센트 인코딩 버그를 잡은 것이 값으로 확인된다.
- **`3D000`이 아닐 때 원문이 사라지지 않는다.** 비밀번호를 틀리게 걸어 봤다 →
  겉면은 `Error: 테스트 DB 준비에 실패했습니다`이지만 **`Caused by: error: password
  authentication failed for user "wirebound"`가 그대로 나온다.** 감싸기가 원인을 안 가린다.
- **비밀번호가 출력 어디에도 안 나온다**(원본 경로 전부에서 확인).

**판정: 이유를 알기 어려운 접속 에러가 아니다. 지적할 것이 없다.**

## 8. compose 볼륨 — **안 잰 판단에 동의한다**

전부 읽기 명령으로 다시 쟀다.

| 무엇 | 관측 |
|---|---|
| compose 프로젝트 이름 | 저장소 루트에서 **`wirebound`**, 워크트리(`revc`)에서 **`revc`** — 디렉터리 이름을 쓴다 |
| 볼륨 키 | 양쪽 다 `wirebound-pgdata` → **프로젝트 이름이 앞에 붙어 갈린다** |

**판단에 동의한다.** 마지막 한 걸음(*"이름 충돌이 사라지면 빈 DB 가 뜬다"*)을 재려면 316MB
볼륨에 붙은 **유일한 링크를 끊어야 한다.** 사용자의 설계서가 그 볼륨에 있고, 브리프도 계획서도
그것을 금지한다. **안 잰 것이 옳다.**

**안 재고도 문서가 사람을 지키나 — 지킨다.** README §6.3이 ⓐ 계약(*"저장소 루트에서만
`up -d`"*) ⓑ 볼륨 셋의 이름·크기·LINKS ⓒ 오늘 그 길을 막는 것이 `container_name` 하나뿐이라는
것 ⓓ 사고가 나면 사람이 무엇으로 읽는지(*"데이터가 사라졌다"*)와 **실제로는 볼륨이 그대로라는
것** ⓔ 다루는 손잡이(`-p feat-p1-api`, `docker start/stop`)를 전부 든다. §10이 *"추론이다"*로
표시하고 CLAUDE.md 가 운영 규칙 한 줄을 든다. **여기서 더 필요한 것은 없다.**

**작은 보탬 하나:** 이미 그 자리에 빠진 사람을 위한 **복구 한 줄**(*"빈 DB 가 보이면 지우지
말고 `docker volume ls` 로 옛 프로젝트 이름의 볼륨을 찾아라 · `down -v` 금지"*)이 §6.3에 있으면

## D6. **"자가 전부 단위 수준이라 워크트리를 안 만들었다"** — **부분 동의**

**이 델타에 한해서는 동의한다.** 바뀐 것이 전부 **자와 문서**이고 런타임 동작을 바꾼 자리는
`helpers.ts`의 조립 한 줄뿐인데 그것은 위에서 행동으로 확인했다. 내가 살린 넷이 전부 단위
수준에서 죽으므로, 그 넷을 다시 재는 데 워크트리 둘은 필요 없었다. **판단이 옳다.**

**다만 *"이제 워크트리 무대가 필요 없다"*로는 안 읽힌다.** 앞 §1이 워크트리 둘로 잡았던 그
성질이 **단위 자로 다 덮이지는 않는다.**

| 앞 §1이 잰 성질 | 지금 무엇이 재나 | 단위 자로 덮이나 |
|---|---|---|
| **에디터가 옆 워크트리 API 에 붙는다** | 순수 규칙(행동) + **소스 인구조사**(글자) | **아니다.** W4·W6이 그 교차를 **게이트 넷 전부 초록인 채로** 되살린다 |
| **동시 `pnpm test`가 서로의 판을 지운다** | 순수 규칙 + **임시 파일**(행동) | **거의.** R4c 한 겹만 남았고 그것도 게이트 넷 초록으로 지나간다 |
| **한쪽 `migrate`가 다른 쪽 스키마를 바꾼다** | **아무 자도 없다** — 문서와 D4 기동 로그뿐 | **아니다**(장부 §3.8이 열린 것으로 정확히 든다) |

즉 **"단위 자가 있으니 무대가 필요 없다"가 아니라 "무대가 잡던 것 중 일부를 단위 자가
넘겨받았다"**가 맞다. 남은 셋(W4·W6·R4c)은 **프로세스가 둘이어야만 드러나거나, 주석을 걷는
자가 있어야 잡힌다.** 뒤엣것이 훨씬 싸다 — 그래서 아래 권고가 워크트리가 아니라
`stripComments` 다.
