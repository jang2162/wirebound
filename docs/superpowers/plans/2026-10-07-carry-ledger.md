## 범위 · 만든 방법 · 한계

- **범위.** `docs/superpowers/plans/2026-10-0*-*.md` 의 이월 · 남은 것 · 재지 않았다 · 산 변조 · 한계 · 후속 · 지침 보고를 다룬다 — 차수 D(`d-*`) · PJ · E(`e-*`) · F(`f-*`) · G(`g*`) · I(`i1`) · H(`h1`) · J(`j1`~`j4`) · K(`k-*`) · L(`l1`) · M(`m1`~`m3`) 보고 · 리뷰 마흔다섯 문서. **8월 carryforward 와 그 앞 차수(A · B · C)의 장부는 이 문서의 범위 밖이다.** C 장부의 항목은 10월 문서가 다시 적은 것만 들어 있다.
- **만든 방법.** ① 문서 마흔다섯을 여섯 추출 파일(A~F, 스크래치 — 저장소 밖)이 행 단위로 뽑았다(약 930 행). ② 이 장부가 같은 결함을 한 항목으로 합치고(합친 항목의 출처를 전부 적음) 새 ID(`L-001`…)를 주었다. ③ 닫힘 여부는 뒤 차수 보고의 «닫힘» 표기 · 같은 결함을 고친 커밋(`git log --oneline`) · 일부는 코드 한 번 읽기로 갈랐다. ④ 지침 보고(CLAUDE.md 문장 제안)는 현재 `CLAUDE.md` 에 같은 취지가 있으면 닫힘, 없으면 영역 «문서» 의 «열림(지침)» 으로 두었다. 맨 끝 「추출 ID 색인」이 추출 행 ID → `L-` ID 를 이어 준다.
- **한계.** 이 장부는 **아무것도 다시 재지 않았다**(테스트 · 빌드 · 서버 실행 0 — 읽기 · `git log` · `git show` · `grep` 만). 상태 «열림» 은 «뒤 차수 보고 · 커밋 제목에서 닫힘 근거를 못 찾았다» 는 뜻이고, 그 가운데 상태 칸에 «코드 확인» 이 적힌 32 건만 소스를 직접 읽었다(HEAD `acefc5aa` 기준). «코드 확인» 이 없는 열림은 코드로 확인하지 않았으니 이미 고쳐졌을 수 있다. 닫힘의 «코드 확인» 도 해당 변경이 소스에 있다는 확인이지 동작을 다시 잰 것이 아니다. 무게는 문서가 적은 대로이고 «미표기» 는 내용으로 추정해 낮음 · 정보로 적었다(합친 항목은 출처 가운데 높은 쪽). 추출이 놓친 행이 있을 수 있다(보고 마흔다섯 문서의 이월 절만 뽑았고 본문 속 한 줄 언급은 뽑지 않았다).
