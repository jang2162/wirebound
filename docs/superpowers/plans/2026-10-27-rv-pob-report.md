## 지침

1. **스크래치 실브라우저 탐침의 맨 이름 `import` 는 스크래치에서 안 풀린다 — `fflate` · `@testing-library/react` · JSX 런타임 셋을 겪었다.** `.ruler/20-verification.md` 「목 · 계측은 불린 수를 값으로 확인하고 …」 의 «스크래치 탐침이 체크아웃의 패키지를 직접 부르면(`kysely` 등) 맨 이름 `import` 는 스크래치에서 안 풀린다 — 체크아웃의 `apps/api/node_modules/<패키지>` 절대 경로로 동적 `import` 한다» 문장 뒤에 넣을 문장:
   > 실브라우저 · 렌더러 탐침도 같다 — `fflate` 는 `apps/web/node_modules/fflate/esm/index.mjs`, `@testing-library/react` 는 `packages/renderer/node_modules/@testing-library/react` 의 절대 경로로 싣고, 스크래치 `.tsx` 의 JSX 는 `react/jsx-dev-runtime` 을 못 찾아 수집에서 죽으니 `.ts` 로 두고 `createElement` · 렌더 함수가 낸 요소를 그대로 넘긴다(`docs/superpowers/plans/2026-10-27-rv-pob-report.md` 「잰 판의 수」).
2. **내보낸 번들(file://)의 시트는 CSSOM 으로 못 읽는다 — 테마 CSS 를 바꾼 판은 파일을 고쳐서 연다.** 같은 문서 「build 프로젝트에서는 `*.css?raw` 가 빈 글자다」 절 끝에 넣을 문장:
   > **번들 페이지에서 `document.styleSheets[…].cssRules` 는 file:// 시트에 `SecurityError` 를 던진다** — 감싼 `try` 가 조용히 넘겨 «규칙 0 개 걷음» 인 채 원래 테마로 잰다(1.7.0 근사 판이 두 번 그렇게 섰다). 테마 규칙을 걷거나 바꾼 판은 번들의 `assets/theme/theme.css` 를 열기 전에 파일째 고치고(postcss — 체크아웃 `node_modules/.pnpm/postcss@*/node_modules/postcss/lib/postcss.mjs`), 걷은 규칙 수 · 남은 셀렉터 수를 카나리아로 적는다.
3. **«두 사람이 같은 노드 목록을 고친다» 판은 고름 잠금 때문에 웹 두 탭으로 못 세운다** — 지침 문장이 아니라 이월 장부 한 줄: 구현 보고 «결정» 의 «늦게 닿은 쪽 목록 전체가 이긴다» 는 고름 잠금이 없는 길(같은 사람의 두 탭 · REST · MCP)에서만 선다. 고른 동안 남의 prop 고침 · 지움은 423 이다(이 보고 「3. 겹침」).
