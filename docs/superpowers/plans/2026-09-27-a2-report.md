## 계획과 달라진 것 — vite 6 · fflate · pnpm

- **vite 6 `build.lib` 을 쓰지 않는다.** vite 6.4.3 의 `shouldInline` 이 `if (environment.config.build.lib) return true` — 라이브러리 모드는 `assetsInlineLimit: 0` 과 무관하게 CSS 의 자산을 data URL 로 인라인한다. 계획대로면 `assets/**` 가 비고 CSS 가 `assets/` 를 못 가리킨다. 대신 일반 빌드에 `rollupOptions.output`: `format: 'iife'` · `entryFileNames: 'theme.js'` · `assetFileNames`(CSS → `theme.css`, 나머지 `assets/[name]-[hash][extname]`) · `globals` · `interop: 'auto'`, 그리고 `base: './'` · `write: false`. 계획의 `lib.cssFileName` 은 필요 없어졌다. CSS 의 url 은 `url(./assets/dot-<hash>.svg)` 로 나온다(케이스 «CSS 의 자산 url 은 패키지 안 assets/ 상대 경로다»).
- **fflate 의 `unzipSync` 필터는 외부 속성을 주지 않는다**(`UnzipFileInfo` = `name` · `size` · `originalSize` · `compression`). 그래서 `read.ts` 가 중앙 디렉터리를 직접 읽어 링크(외부 속성 위 16 비트 `& 0o170000 === 0o120000`) · 항목 수 · 경로 · 풀린 크기 합을 풀기 전에 본다. 링크 케이스는 바이트를 고치는 대신 fflate 의 `os: 3` · `attrs` 옵션으로 세웠다(fflate 가 그 값을 쓴다 — 케이스가 거절을 본다).
- **설정 적재**: esbuild 로 묶을 때 `@wirebound/theme-sdk` 를 항등 `defineManifest` 로 바꿔 끼운다(`SDK_SHIM`). 계획처럼 external 로 두면 `os.tmpdir()` 의 임시 파일에서 SDK 가 안 풀린다.
- **theme-kit 의 bin 은 `bin/wb-theme.js`(커밋되는 파일 → `../dist/bin.js`)** 다. `bin` 이 `dist/bin.js` 를 바로 가리키면 빌드 전에 install 한 체크아웃에서 pnpm 이 `wb-theme` 심을 만들지 않아(실측: dist 를 치운 채 install → `system-themes/admin/node_modules/.bin` 빔 → `pnpm exec wb-theme` = `Command "wb-theme" not found`) 새 워크트리의 `pnpm build` 가 system-admin 단계에서 죽는다. 바꾼 뒤 같은 절차에서 심이 서고 빌드 뒤 돈다. 잴 때 주의: pnpm 은 `node_modules/.pnpm-workspace-state.json` 이 있으면 «Already up to date» 로 링크를 다시 짓지 않는다(`--force` 도 마찬가지였다) — 그 파일을 지워야 다시 잰다.
- **`publishConfig.exports`**(theme-sdk · theme-kit): 저장소의 `exports` 는 `development` 조건이 `src/` 를 가리키는데 tarball 에는 `dist/` 만 든다. pnpm pack 이 이 필드로 덮는다 — 안 덮으면 작성자의 vite dev 서버(`development` 조건으로 푼다)가 없는 파일을 찾는다. 케이스 «tarball 의 exports 가 tarball 에 든 파일만 가리킨다».
- **템플릿의 `src/views/*.tsx` 는 저장소에 두지 않고 `packTemplate` 이 SDK 소스에서 짓는다**(`templateView` — 머리 주석과 `*CssBlocks` 함수를 걷고 상대 import 를 `@wirebound/theme-sdk` 한 줄로, SDK 가 안 내보내는 이름이면 던진다). 계획은 `template/src/views/*.tsx` 를 파일로 두는 것이었다 — 사본은 SDK 기본 뷰가 바뀔 때 조용히 갈라진다. 기본 뷰는 19 파일이 아니라 묶음 다섯(`structure` · `data` · `input` · `action` · `document`)이다. 템플릿의 `.gitignore` 는 `gitignore` 로 두고 zip 에서 이름을 바꾼다(pack 이 `.gitignore` 를 빼거나 바꾼다).
- **Task 9 케이스는 `.tsx`**(JSX)이고, 빌드는 자식 프로세스(`pnpm --filter @wirebound/system-theme-admin... build` — 루트 `pnpm build` 의 길)로 돈다. jsdom 환경에서 vite 가 부르는 esbuild 가 `Invariant violation: "new TextEncoder().encode("") instanceof Uint8Array" is incorrectly false` 로 죽는다. build 프로젝트 include 에 `system-themes/*/build-test/**/*.test.{ts,tsx}` 를 더했다. CSS 비교(주석 · 공백을 걷은 앞 200 글자)는 계획 그대로 통과했다 — 대체 단언은 필요 없었다.
- **kit 케이스의 픽스처 복사본은 `packages/theme-kit/.tmp/`(gitignore)** 에 둔다. `os.tmpdir()` 면 SDK · react 가 안 풀려, «SDK 를 밖으로 뺐는가» 변조가 값이 아니라 해석 실패로 죽는다.
- **이름 · 모양**: `ManifestIssueCode` 에 `unknown-token`(값의 키가 선언에 없음 — `tokensCss` · `tokenValues` 가 낸다), `WbthemeIssue` 에 `manifestCode?`(manifest 이슈의 원래 코드), kit 에 `RUNTIME_GLOBALS` · `BuildIssue` · `CONFIG_FILE` · `DEFAULT_ENTRY` · `TEMPLATE_ROOT` · `PackTemplateResult`, `packTemplate({ outFile?, build? })` 는 `{ file, bytes, tarballs }` 를 돌려준다. theme-sdk 는 schema 를 어디서도 import 하지 않아 의존 · tsconfig 참조를 걷었다. themes 의 공개 표면 계약(`public-api.test.ts`)을 새 이름으로 갱신하고 «theme-sdk 는 타입으로만 읽는다» 를 더했다. 계획 케이스의 `it.each` 행은 `[라벨, 코드, 입력]` 으로 바꿨다(그대로면 제목에 입력 객체 전체가 찍힌다).

## 이월 · 알릴 것

- **`theme.js` 에서 `import React from 'react'`(기본 가져오기)** 는 `interop: 'auto'` 로 푼다 — 이 판은 케이스가 없다(픽스처 · 템플릿 · system-admin 모두 자동 JSX 런타임만 쓴다).
- dev 서버는 `server.watcher` 에 설정 파일을 걸고 SSE 로 알린다. 설정을 고친 뒤 프레임은 vite 의 HMR(설정을 진입이 import 하므로 재적재)로 따라온다 — 진입이 설정을 import 하지 않는 프로젝트에서는 프레임이 안 따라온다(템플릿 · system-admin 은 import 한다).
- kit 의 Node 쪽(`dist`)은 상수 하나(`WB_RUNTIME_GLOBAL`) 때문에 `@wirebound/theme-sdk/runtime` 을 적재하고, 그것이 react 를 싣는다(작성자 프로젝트에 react 가 있으니 설치 판에서 돈다).
- A3 이 쓸 것: `readWbtheme` · `validateManifest` · `satisfiesSdk` · `packTemplate`(저장소 안에서만 — 저장소 빌드가 zip 을 지어 두고 라우트가 그 파일을 낸다).
