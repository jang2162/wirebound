## Task 1 — 몫 노드 필드와 SDK 배치

**바꾼 것**

- `WbNode.weight?: number`(정수 1 ~ 12 · `WEIGHT_MIN` · `WEIGHT_MAX`) — 봉투(`WbNodeSchema`) · `copyNode`(`stripMarkers`) · 패턴 규격(`PatternNodeSchema` — 같은 범위) · 패턴 전개가 옮긴다. `remapNodeIds` · 클립보드 봉투 · `prepareNodesForPaste` 는 전개(`...node`)라 원래 옮긴다(케이스로 잠금).
- **렌더러가 부모를 보고 몫을 정한다**(`weightRoom` · `weightIn`): `Flex` 안 → 몫 그대로, `Grid` · 열을 정한 `SearchForm` 안 → 부모 열 수로 자른 칸 수, 그 밖 → 안 싣는다. 상태 영역 · 가지(`StateSwitch` · `StateCase`)는 요소를 안 남기므로 자리를 그대로 넘긴다. 노드 캐시 열쇠에 몫 자리를 더했다(부모 `Grid` 의 열 수만 바뀌면 자식은 같은 객체다).
- `NodeBinding.weight` → `Root` 가 뷰의 `style` 에 `--wb-node-weight` 를 **더한다**(몫이 없으면 `style` 을 안 건드린다 — 몫 없는 문서의 DOM 이 그대로다). 노드 속성 `data-wb-*` 는 안 늘었다(`contract-attrs` 초록).
- SDK 기본 CSS(특이도 0) 셋: 모든 노드 뿌리 `--wb-node-weight: initial`(상속 끊기) · `Flex` 자식 `flex: var(--wb-node-weight, 0 1 auto)` · `Grid` 자식 `grid-column: span var(--wb-node-weight, 1)`. SDK `1.2.0`.

**Grid 자르기 — CSS 가 아니라 렌더러다(브리프 «어느 쪽인지»).** Chrome 155 에서 `grid-column: span min(var(--w,1), var(--cols,1))` 는 **선다**(3열에 2 → `span 2` · 600px, 5 → `span 3` · 900px · 열 셋 그대로 / `min` 없이 5 → `span 5` · 열 다섯 `300 300 300 0 0`). 그래도 렌더러에서 자른다 — CSS 는 열 수를 **상속으로만** 읽어, 자식이 `Grid` 면 제 뷰가 같은 변수에 제 열 수를 실어 **제 열 수로** 잘린다(4열 안의 2열 `Grid` 몫 3 → 칸 셋이어야 하는데 둘). 변조 B3(렌더러 자르기를 떼고 CSS `min` 으로)이 «Grid 안 Grid» 만 다섯 테마에서 죽인다.

**Flex 의 비는 내용 상자로 잰다.** `flex-grow` 만 바꾸면 남는 폭만 나눠 형제의 내용 폭이 다르면 비가 안 선다 — 그래서 몫이 있으면 `flex: <몫>`(바탕 폭 0). 그래도 안 여백 · 테두리는 항목마다 붙어 테두리 상자 비는 1 : 2 가 아니다(docs `Card` 433 : 831 — 여백 35). 설계서의 «남는 폭을 몫대로» 와 같은 뜻이라 케이스는 내용 상자로 잰다(변조 B2 — `flex-grow` 만 — 가 «Flex 1 : 2» 만 죽인다).

## Task 2 — SearchForm 열

**바꾼 것**

- 카탈로그 `SearchForm.columns`: `z.number().int().min(1).max(4).optional()`(기본값 없음) · editor «열 수»(number).
- **«열을 정했다» 는 루트 표지가 아니라 `fields` 조각의 속성이다** — 계획서는 `marks.ts`(SearchForm 표지)를 적었지만 `packages/renderer/test/prop-marks.test.tsx` 의 규칙이 수 prop 을 표지로 못 싣게 한다(«불리언 · enum 은 표지 · 상태 · 변형, 그 밖의 꼴은 셋이 아니다»). 그래서 SDK `searchFormFieldsAttrs(columns)` 가 `fields` 조각에 `data-wb-columns="<수>"` + `--wb-node-searchform-columns` 를 싣고(열을 안 정했으면 아무것도 없다), 인구조사 칸은 `var` 다. 기본 뷰와 commerce · portal 의 접히는 뷰가 그것을 편다.
- SDK 기본 CSS(특이도 0): `[fields][data-wb-columns]` 격자 · 그 자식 `grid-column: span var(--wb-node-weight, 1)`(필드 몫은 렌더러가 열 수로 자른다).
- 테마 다섯: 마지막 SearchForm 규칙 뒤에 `[data-wb-component="SearchForm"] > [data-wb-part="fields"][data-wb-columns] { display: grid; grid-template-columns: repeat(var(--wb-node-searchform-columns, 1), minmax(0, 1fr)) }` — 열을 안 정한 판의 규칙은 한 글자도 안 건드렸다. 좁은 창 media(admin · docs · portal · saas 640 · commerce 480 — 테마마다 가장 좁은 문턱)에 한 칸 · `grid-column: auto`.

## Task 3 — 패널 칸 · 정본

**바꾼 것**

- 속성 패널 «몫» 칸 — 별칭 바로 아래. **부모가 몫을 읽을 때만** 선다: 렌더러의 `weightRoom` 을 공개해 같은 함수로 가른다(판정이 두 벌이면 칸이 서는데 화면이 안 바뀌는 부모가 생긴다). 상태 영역 · 가지는 건너 위를 본다.
- 넣으면 `add` / `replace …/weight`, 비우면 `remove`(`weightOps` — `aliasOps` 와 같은 갈래). 1 ~ 12 정수 밖(`0` · `13` · `1.5` · `두` · `-1` · `1e1`)은 안 보내고 칸 아래 «몫은 1 ~ 12 의 정수입니다 — 보내지 않았습니다»(`.wb-shell-prop-why`). 바른 값을 보내면 걷힌다. 잠금 · 역할은 별칭 칸과 같은 `blocked`. 떠나기 전 바뀐 선택의 초안은 `commitLeftover`.
- **기본값이 없는 수 칸(«열 수»)은 비우면 그 prop 을 지운다** — 안 하면 한 번 정한 열을 «안 정한» 판으로 되돌릴 길이 없었다. `TextControl.clearable` → 빈 글 → 패널이 `undefined` 로 → `propOps(…, undefined)` 가 `remove`(키가 없으면 `null`). 다른 수 칸은 지금처럼 빈 값을 안 보낸다.
- 정본 설계서: §4.3 노드 몫 · §5 `SearchForm` 열 · §6.1 `data-wb-columns` · 몫 변수 · 수 prop 은 표지가 아님 · §6.2 패턴 템플릿 필드 · §9 속성 패널.
