## 항목별

### L-129 `aria-required` · `aria-invalid` 가 역할 없는 `div` 에 선다 — 재현됨 · 고침 · 닫힘

- **재현(실브라우저, CDP `Accessibility.getFullAXTree`):** 루트 `div` 에 단 `aria-required` 는 트리에서 **사라지고**(`generic` 의 속성에 `required` 없음) `aria-invalid` 만 남으며 이름은 빈 글이다. `role=textbox` + 이름을 단 조각으로 옮기면 `textbox "이름" required=true invalid="true"` 로 선다.
- **고침:** 기본 `Field` 뷰(`packages/theme-sdk/src/default-views/input.tsx`)가 `control` 조각에 입력 종류별 역할(`text` · `date` · `dateRange` · `textarea` → `textbox`, `number` → `spinbutton`, `select` → `combobox`(+`aria-expanded`), `checkbox` → `checkbox`(+`aria-checked`), `radio` → `radiogroup`)과 `aria-label`(= 라벨)을 달고 `required` · `invalid` 를 그 조각에 둔다. `Root` 에는 `undefined` 를 넘겨 루트 몫을 거둔다. **`file` 은 `aria-required` 를 받는 역할이 없어 루트에 그대로 둔다**(조각에 역할 · 이름 없음). `disabled` · `loading` 은 전역 속성이라 루트에 남는다.
- **값 확인(실브라우저):** 시스템 테마 다섯 모두 `textbox "접근성 이름"` 이 `required: true · invalid: "true"` 로 선다(`theme-prop-marks.test.ts` «Field 의 필수 · 오류는 접근성 트리에 선다»). 시스템 테마 CSS 는 `aria-*` 를 안 겨냥한다(`[data-wb-state~="invalid"]` 만 읽는다) — 화면 차 0(`[표지 화면 차]` invalid 칸 그대로).
- 문서: spec 「6.1 노드 속성」 표 · `marks.ts` 머리말 · 스타터 `SKILL.md`.

### L-128 `selectable` 은 표가 아닌 `List` variant 에서 안 그려진다 — Q28(나) 계약 · 닫힘

- **실브라우저 값(테마 × `List` variant 전부, 선언은 각 `.wbtheme` 의 `manifest.json` 에서 읽음):**

| 테마 | 표 구조 variant | 체크 칸(머리 1 + 행 2) | 표가 아닌 variant | 체크 칸 · 표지 |
|---|---|---|---|---|
| admin | `default` · `featured` · `compact` 전부 | 14×14 · border 1px · 배경 흰색 | — | — |
| commerce | **없음** | — | `mediaList` · `cardGrid` · `compact` · `featured` | 0 · `data-wb-selectable` 만 |
| docs | `table` | 14×14 · border 1px · 배경 투명 | `default` · `compact` | 0 · 표지만 |
| portal | `table` | 14×14 · border 1px · 배경 투명 | `stackedList` · `featured` · `compact` | 0 · 표지만 |
| saas-marketing | `table` | 14×14 · border 1px · 배경 투명 | `cards` · `featured` · `compact` | 0 · 표지만 |

  **장부 열의 «체크 칸은 admin 만 14×14» 는 틀렸다** — d p s 의 `table` variant 도 14×14 로 그린다(j2 보고는 «기본 variant 가 표가 아니라 칸이 없다» 만 맞다).
- **계약(spec 「6.1」 · `marks.ts` · 스타터 `SKILL.md`):** `List.selectable` 은 표 구조(`data-wb-structure="table"`)에서만 뜻이 있다 — 표 구조는 체크 칸을 그리고 줄 · 카드 목록 구조는 표지만 선다. 다섯 테마의 `List` 에 체크 칸을 새로 그리지 않았다.
- **잠금:** `theme-prop-marks.test.ts` «selectable 은 표 구조에서만 체크 칸을 그린다» — 테마 다섯 × 선언 variant 전부를 **DOM 의 구조로 가르고**(variant 이름이 아니라) 표 구조는 체크 칸 3 · 보이는 상자 3, 나머지는 0. `system-commerce` 는 표 variant 가 없다는 것도 카나리아로 못박았다(표를 더하면 이 줄이 알린다).

### L-130 테마 없는 판의 상태 기본 CSS — Q24(가) · 코드 변경 없음 · 닫힘

장부 열에 넣을 문장: «다섯 시스템 테마는 `disabled` · `invalid` · `loading` 을 모두 칠한다(`theme-prop-marks` 의 계산 스타일 차 — admin 2 · 3 · 16, commerce 1 · 3 · 1, docs 1 · 3 · 1, portal 2 · 4 · 1, saas-marketing 1 · 6 · 1). SDK 기본 CSS 는 `List` `loading` 의 `skeleton` 막대(`opacity: 0.2`)만 상태를 칠하고 `disabled` · `invalid` 는 칠하지 않는다. 결정(Q24 가): 상태 기본 CSS 를 SDK 에 두지 않는다.»

**정정할 값:** 장부의 «테마 없는 렌더는 테스트 경로뿐» 은 틀렸다. 테마 없이(SDK 기본 뷰 + 기본 CSS 만으로) 그려지는 **제품 경로가 둘 있다** — 에디터 캔버스가 테마 번들을 못 받았을 때의 폴백(spec 「캔버스 iframe」 «번들을 못 받으면 SDK 기본 뷰로 그리고 셸 머리에 한 줄로 알린다»), 내보내기 `theme: null`(`packages/exporter/src/bundle/index.ts`). 그 판에서 `disabled` · `invalid` 는 모양이 안 바뀐다(접근성 속성 · `data-wb-state` 는 선다). 결정은 그대로 두되 장부 문장에 이 두 경로를 적는다.

### L-131 테마가 `views.StateSwitch` 를 정의해도 조용히 무시 — 재현됨 · 고침 · 닫힘

- **재현(unit):** `wb-theme check`(`checkTheme`)에 `views: { StateSwitch, Ghost }` 번들을 주면 오류 `[]` — 둘 다 조용히 지나갔다(렌더러는 `views[노드 타입]` 만 읽고 상태 영역은 직접 다룬다).
- **고침:** `checkTheme` 가 정의의 `views` 키를 카탈로그와 견줘 `THEMELESS_TYPES` 키와 카탈로그에 없는 키를 `source: 'bundle'` 오류로 낸다(`packages/theme-kit/src/check.ts` 의 `findBadViewKeys`). 출력 줄은 `✗ [bundle] 번들: views.StateSwitch 는 …`. 서버(업로드)는 `theme.js` 를 실행하지 않으므로 그 자리는 작성자 도구(`wb-theme check`)다. spec 「3」 의 `wb-theme check` 문장에 적었다.
- **안 한 것:** 호스트(웹 · 내보낸 번들)의 런타임 경고는 안 더했다 — 아래 이월 1.

- **재현(실브라우저, 라벨 `a<U+202E>b`(RLO) · 탭 이름 `x<U+202E>yz`):** 글자 가운데 x 로 조각 차례를 쟀다.

### L-123 `wireb page get` 출력의 C1 — 재현됨 · 고침 · 닫힘(터미널 에뮬레이터 값은 아님)

- **재현(바이트):** 진짜 `createNodeIo().out` 으로 나간 글에 `ESC[2J`(화면 지움) · OSC 창 제목(`ESC]0;…BEL`) · C1 `U+009B`(CSI) · `\r` · 방향 제어가 **그대로** 실린다. `--json` 은 `JSON.stringify` 가 C0 만 이스케이프해 C1 · 방향 제어가 날 글자다. 못 찾은 경로의 되비춤(stderr)도 같다. 라벨 · 제목 · 설명 · 코멘트 본문은 입구가 막지 않는다.
- **고침:** `Io.out` · `Io.err`(`createNodeIo`)가 `\n` · `\t` 를 뺀 C0 · DEL · C1 · U+2028 · U+2029 · 방향 제어를 `\uXXXX` 글로 바꾼다(`packages/cli/src/terminal-safe.ts`). `--json` 은 그 글자가 든 자리가 JSON 문자열 안뿐이라 `\uXXXX` 로 바뀌어도 **읽은 값이 같다.** 파일에 쓰는 바이트(`files.write`)는 그대로. 명령마다 거르지 않고 입구 하나다 — `lint` · `pull` · `export` 의 출력도 같은 입구를 지난다.
- **못 쟀다:** 실제 터미널 에뮬레이터가 그 글자를 해석하는지는 이 기계에서 안 쟀다(터미널마다 다르다). 잰 것은 프로세스가 내보내는 바이트다.
