## 1. 상자 안의 키가 다른 단축키로 새는가

**키를 받는 자리를 먼저 셌다** — `git grep -n "addEventListener('keydown'" apps/web/src` 는 `shell/use-popover-dismiss.ts` 하나(팝오버가 열린 동안만). `git grep -nE "addEventListener\(\s*[\"']key|onkeydown|metaKey|ctrlKey" apps/web/src` 도 그 하나뿐이다 — **에디터에 되돌리기 · 다시 하기 단축키가 없다**(`store/editor-store.ts` 의 «단축키가 아예 없다 — 세어서 확인했다»와 같다). React `onKeyDown` 의 단축키 표는 두 트리의 `SHORTCUTS`(`panels/menu-tree.tsx` · `panels/structure-tree.tsx`)이고, 상자는 메뉴 트리의 단축키 상자 **형제**(`MenuTree` 의 `outside`)라 어느 쪽의 React 조상도 아니다.

**판** — 글을 고쳐 서버에 닿게 해 되돌리기를 켠 뒤(`headSeq 2` · 되돌리기 켜짐) «가져올 곳» 줄 `+` 로 상자를 열고, 상자 안 여섯 자리(머리 «닫기» · «JSON 직접 붙여 넣기» · 글상자 · 제목 칸 · 파일 입력 · «취소»)에서 열여덟 키(`Control/Meta+z` · `Control/Meta+Shift+z` · `Control/Meta+y` · `Delete` · `Backspace` · 화살표 넷 · `Alt+↑/↓` · `Alt+Shift+←/→` · `Alt+Shift+KeyI/KeyP`)를 쳤다. 판마다 삭제 확인 수 · 상자 수 · 셸 영역 글자(메뉴 트리 · 구조 트리 · 하단 바) · 되돌리기 켜짐 · 주소를 기준과 견줬다.

## 2. 파일을 끌어 놓는 칸 밖에 놓으면

CDP `Input.dispatchDragEvent`(`dragEnter` · `dragOver` · `drop` — `files: [<디스크의 .json>]` · `dragOperationsMask: 1`)로 놓았다. 브라우저 기본 동작까지 도는 길이다.

**판 카나리아** — 핸들러 없는 `data:` 페이지에 같은 놓기를 하면 Chrome(headless · headful 둘 다)은 **현재 탭을 옮기지 않고 그 파일을 새 탭으로 연다**(`context.pages()` 2 — 둘째가 `file:///…`). 그래서 «에디터를 잃는가»는 주소가 아니라 **새로 열린 탭 수 · 현재 탭 주소**로 잰다.

| 놓은 자리(워크트리) | `elementFromPoint` | 새 탭 | 현재 탭 | 상자 미리보기 |
|---|---|---|---|---|
| 상자 · 끌어 놓기 칸(대조) | `SPAN.wb-shell-pagejson-drop-lead` | 0 | 그대로 | «끌어 놓은 파일 — 노드 2개, 코멘트 1개» |
| 상자 · 폼 안 빈 자리(바닥 왼쪽) | `DIV.wb-shell-pagejson-foot` | 0 | 그대로 | 같음(폼 전체가 받는다) |
| 상자 · 머리(제목) | `H2.wb-shell-dialog-title` | **1**(`file:///…`) | 그대로 | 없음 |
| 배경막 | `DIALOG.wb-shell-dialog` | **1** | 그대로 | 없음 |

| 커밋 전 글(우측 칸에 친 채) · 캔버스에 놓기 | — | **1** | 그대로 · 서버 `headSeq` 1 → 1 · 서버 글 «원문» | — |

|---|---|---|

| 옛 패널 파일 칸 | 0 | 브라우저의 `<input type=file>` 이 놓기를 받아 글상자에 실린다 |
| 옛 패널 묶음 빈 자리 | 1 | |

**판정** — Chrome 에서는 에디터도 보내지 않은 편집도 잃지 않는다(새 탭이 하나 뜬다). 칸 밖 놓기가 새 탭을 여는 것은 **원래 있던 길**이다(main 의 캔버스 · 트리 · 패널 빈 자리). 상자의 머리 · 배경막은 그 길의 새 자리다 — 상자가 «몸체 전체가 받는다»고 말하지만 머리(`.wb-shell-dialog-head`)와 배경막은 폼 밖이다.

**못 잰 것** — Firefox · Safari 는 놓은 파일로 **현재 탭을 옮길 수 있다**(이 기계에서 안 잼). 그 판이면 머리 · 배경막 놓기가 에디터를 떠난다.

**주석이 실물과 다르다** — `panels/page-import-dialog.tsx` 머리말 «파일 칸 — OS 파일 끌어 놓기»의 «칸을 조금 비켜 놓은 파일을 브라우저가 열면 에디터를 떠난다»는 Chrome 에서 거짓이다(새 탭). 고칠 방향: 문장을 «Chrome 은 새 탭으로 열고, 브라우저에 따라 현재 탭을 옮긴다»로 고치고, 막으려면 `OpenDialog`(`shell/shell-dialog.tsx`)의 `<dialog>` 에 `Files` 끌기의 `dragover` · `drop` 을 `preventDefault` 하는 한 겹(머리 · 배경막)을 둔다 — 무게 정보.

## 3. 상자가 열린 동안 판이 바뀌면

픽스처: bob 이 프로젝트를 만들고 alice 를 editor 로 넣는다. alice 가 «가져올 곳» 줄 `+` 로 상자를 열고 파일을 실은(미리보기 «판 …») 뒤 bob 이 api 로 판을 바꾼다. 그 뒤 «가져오기»를 누를 수 있으면 누른다. 페이지 수는 DB(`select count(*) from pages where project_id = $1`)로 센다 — 픽스처의 페이지 2.

## 4. 가져오기를 두 번 보내는 길

판마다 가져오기 요청(`page.on('request')` 의 `/pages/import`) 수와 대상 메뉴의 페이지(DB)를 센다.

| 판 | 요청 | 대상 메뉴의 페이지 | 그 밖 |
|---|---|---|---|
| (4a) «가져오기» 단추 더블클릭 · 지연 0 | 1 | 1 | 둘째 누름은 닫힌 상자 자리 밑 `MAIN.wb-shell-canvas`(캔버스 iframe 밖 빈 자리)에 닿는다 — 고름 · 이동의 변화 없음 |
| (4a) 같은 판 · 가져오기 요청 400ms 지연(`page.route`) | 1 | 1 | 같음 |
| (4b) 제목 칸에서 `Enter` 다섯(요청 300ms 지연) | 1 | 1 | |
| (4b) «가져오기» 단추에서 `Enter` 다섯(요청 300ms 지연) | 1 | 1 | |
| (4c) 보내는 중(2.5s 지연) «취소» → 줄 `+` 다시 열기 | 1 | 1 | «가져오는 중…» 단추 1 · 줄 `+` 의 «JSON 에서 가져오기…» `aria-disabled="true"` · 강제로 눌러도 상자 0 |

**찾은 것 F4 — 보내는 중 «취소»가 가져오기를 멈추지 못한다** (4c). «취소»는 보내는 동안에도 같은 이름으로 켜져 있고, 누르면 상자만 닫힌다. 요청은 그대로 끝나 페이지가 생기고 **사용자를 새 페이지로 옮긴다**(`movedAfterCancel: true`) · 하단 바 «가져왔습니다: 취소한 가져오기 — 코멘트 1개».
- 원인: `PageImportBody` 의 «취소» 단추가 `commands.closeImport` 를 부른다 — 보낸 요청을 끊지 않고(`TreeCommands.closeImport` 머리말 «보내는 중에도 닫힌다»), 성공 갈래(`useTreeCommands` 의 `importJson` → `run` 의 `after`)는 상자가 닫혔어도 `navigate` 한다.
- 무게: 낮음 — 데이터를 잃지 않고 결과가 하단 바에 선다. «취소»라는 낱말이 하는 일과 다르다.
- 새 길(main 의 옛 패널에는 «취소»가 없었다).
- 고칠 방향: 보내는 동안 «취소»를 끄거나(머리 «닫기»와 Escape 도 같은 판정), «닫기»로 이름을 바꾸고 닫힌 상자의 성공은 옮기지 않고 통지만 남긴다.

| (5c) 연 뒤 bob 이 «둘째»를 «가져올 곳»으로 옮기고 이름을 «둘째(바뀜)»으로 | `둘째(바뀜).wirebound-page.json`(제목 「둘째(바뀜)」) | — | 그 줄의 페이지다 — 이름 · 자리는 서버의 지금 값 |

**그 줄의 페이지가 아닌 것을 내는 길은 없다** — 줄은 `key={page.id}` 이고 항목은 그 줄의 `props.page.id` 를 쥔다.

**찾은 것 F5 — 열린 페이지를 내보내면 방금 친 글이 빠진 파일이 받아질 수 있다** (5d). 우측 칸에 «커밋 전 글»을 친 채(blur 전) 열린 페이지 줄 `…` → «JSON 내보내기»:

| 트리 | WS(브라우저 → 웹) 지연 | 받은 파일의 글 | 서버의 글(끝) |
|---|---|---|---|
| 워크트리 | 0 | «커밋 전 글» | «커밋 전 글» |
| 워크트리 | 150ms(`startWsDelay`) | **«원문»** | «커밋 전 글» |
| main(옛 «페이지 내보내기» 단추) | 0 | **«원문»** | «커밋 전 글» |
| main | 150ms | **«원문»** | «커밋 전 글» |

- 원인: 누름의 blur 가 낸 커밋(WS)과 내보내기의 `getPage`(REST)가 서로 다른 연결로 겨룬다(`CLAUDE.md` 「검증」 «판을 다시 싣거나 상태를 갈아 끼우는 단추를 새로 세우면 …»). `usePageJsonExport` 는 서버만 읽는다(머리말 «서버에서 둘을 같은 순간에 읽는다»).
- 무게: 낮음 — 서버의 글은 맞고, 파일만 한 박자 낡는다.
- **원래 있던 길**이다 — main 은 누름 하나가 blur 와 내보내기를 함께 내 지연 0 에서도 빠졌다. 이 트랙은 `…` → 항목의 두 누름 사이만큼 창을 좁혔다(지연 0 에서 닫힘 · 150ms 에서 열림).
- 고칠 방향: 내보내기 전에 셸의 `settleEdits`(로그아웃이 쓰는 «보낸 편집의 답을 한도 있게 기다림»)를 지나게 한다 — 열린 페이지일 때만.
