# A2 — `.wbtheme` 형식 · manifest 검증 · theme-kit · 스타터 템플릿 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 이 저장소에서는 `CLAUDE.md` 「메인 세션은 디스패치·판정·병합만 한다」를 따른다 — 태스크는 워크트리의 Orca 워커가 한다.

**Goal:** 테마 작성자가 저장소 밖에서 스타터 템플릿으로 테마를 짜고(`wb-theme dev` 로 갤러리를 보며), `wb-theme build` 로 검증된 `.wbtheme` 한 파일을 만든다. 호스트는 그 파일을 읽어 manifest 를 검증하고, `theme.js` 를 공유 런타임 위에 실어 렌더러로 그린다.

**Architecture:** `packages/themes` 가 manifest 규격 · 검증(`validateManifest`), `.wbtheme` 읽기 · 쓰기(`readWbtheme` · `packWbtheme`), 토큰 CSS(`tokensCss`)를 갖는다 — 빌드 · 업로드(A3) · 호스트(A4 · A5)가 같은 함수를 쓴다. `@wirebound/theme-sdk/runtime` 이 공유 런타임 전역(`__wirebound_runtime__`)을 세우고 `theme.js`(IIFE)가 거기 `register` 한다. 새 `packages/theme-gallery` 가 카탈로그 × variant 표본을 그리는 갤러리 컴포넌트를 갖고, 새 `packages/theme-kit` 이 `wb-theme build`(vite 라이브러리 IIFE + 검증 + zip) · `wb-theme dev`(vite 서버 + 갤러리 + 토큰 패널 + 뷰포트) · 템플릿을 갖는다. `system-admin` 은 kit 프로젝트가 되어 `.wbtheme` 로 빌드된다.

**Tech Stack:** TypeScript · React 19 · zod 4 · fflate 0.8 · vite 6(`build.lib` IIFE · dev 서버) · @vitejs/plugin-react 4 · esbuild(설정 파일 적재) · tsdown · vitest · playwright-core.

**Spec:** `docs/superpowers/specs/2026-09-27-code-themes-design.md` — 「패키지와 번들 계약」 · 「manifest」 · 「작성자 도구」 · 「업로드 · 버전 · 인스턴스 관리자」의 «업로드 검증»(검증 함수만 — 라우트는 A3). 앞 차수 보고: `docs/superpowers/plans/2026-09-27-a1a-report.md` · `-a1a-fix-report.md` · `-a1b-report.md`.

## Global Constraints

- **theme-sdk 는 한 벌이다.** 작성자의 뷰가 쓰는 `Root` 와 렌더러가 여는 `NodeContext` 가 서로 다른 사본이면 `Root` 가 «뷰 안에서만» 으로 던진다. 그래서 kit 이 번들하는 **모든 산출물**(테마 `theme.js` · dev 갤러리 클라이언트)에서 `react` · `react/jsx-runtime` · `react-dom` · `@wirebound/theme-sdk` 는 **밖으로 뺀다**(external). 나머지 `@wirebound/*`(schema · renderer · themes · theme-gallery)는 kit 의 산출물 **안에 묶는다** — 템플릿을 설치하는 기계에는 그 비공개 패키지가 없다.
- `theme.js` 는 **ES 모듈이 아니라 일반 스크립트(IIFE)** 다(spec 「`.wbtheme` 파일」). 외부 import 는 전역 `__wirebound_runtime__` 의 속성으로 바뀐다: `react` → `.react`, `react/jsx-runtime` → `.jsxRuntime`, `@wirebound/theme-sdk` → `.sdk`.
- `.wbtheme` 상한: zip 10 MB · 풀었을 때 50 MB · 항목 500. 항목 허용 목록: `manifest.json` · `theme.js` · `theme.css` · `assets/**`(`png` · `jpg` · `jpeg` · `gif` · `webp` · `svg` · `woff` · `woff2` · `ttf` · `otf`). 절대 경로 · `..` · 심볼릭 링크 거부(spec 「업로드 검증」).
- `packages/themes` 는 브라우저와 Node 양쪽에서 돈다(웹 A4 가 읽는다) — `node:*` 모듈을 쓰지 않는다. 새 런타임 의존은 `fflate` 하나(이미 `packages/cli` 가 쓰는 판 `^0.8.3`).
- semver 는 라이브러리를 들이지 않는다 — manifest 의 `version` 은 `x.y.z`, `sdk` 는 `^x.y.z` · `~x.y.z` · `x.y.z` 셋만 받는다(D2).
- kit 은 저장소 안에서도 저장소 밖(템플릿 설치)에서도 같은 코드로 돈다. 저장소 경로를 코드에 박지 않는다.
- 주석 · 인용 규칙: `docs/guideline/base/03-comments.md` · `04-citation.md`.
- 테스트 보고에는 실행 수 · 건너뛴 수를 적는다. 네트워크가 필요한 판(템플릿 실제 설치)은 환경 변수로만 켜고 기본은 건너뛴다 — 건너뛴 수를 적는다.

## Review Focus

1. **작성자가 흔히 틀리는 manifest** — 참조가 없는 토큰(`{color.brand}`), 타입이 다른 참조, 순환 참조, 카탈로그에 없는 컴포넌트 이름, `variantFrom` 컴포넌트(`Text` · `Field` · `Divider`)에 variants 선언, `defaultVariant` 가 목록 밖. 빌드가 **이유를 항목별로** 말하고 `.wbtheme` 를 만들지 않는다. → Task 1 의 거부 표.
2. **악의 · 실수의 zip** — `../` 경로, 허용 밖 파일(`.exe` · `node_modules/**`), 상한을 넘는 풀린 크기(zip 폭탄), 심볼릭 링크. 읽기가 풀기 **전에** 거절한다. → Task 2.
3. **theme-sdk 두 벌** — kit 산출물이 SDK 를 묶어 버리면 `Root` 가 던져 모든 노드가 기본 뷰로 그려진다(조용한 실패). → Task 6 «빌드한 theme.js 에 theme-sdk 가 묶이지 않는다» · Task 9 «실어 그리면 테마 뷰로 그려진다».
4. **dev 에서 뷰를 고치면 갤러리가 따라온다** — HMR 이 안 되면 작성 루프가 끊긴다. → Task 7 «뷰 파일을 고치면 갤러리의 글자가 바뀐다»(실브라우저).
5. **템플릿이 저장소 밖에서 선다** — tarball 의 의존에 비공개 `@wirebound/*` 가 남으면 설치가 404 로 죽는다. → Task 8 «tarball 의존에 비공개 패키지가 없다».

## 확정한 결정

### D1. manifest 규격은 `packages/themes` 가 zod 로 갖고, 카탈로그와 견주는 검사는 `validateManifest` 가 한다

`ManifestSchema`(모양)와 `validateManifest(raw)`(모양 + 카탈로그 · 토큰 · 패턴 대조)를 둔다. 결과는 `{ manifest: ThemeManifest | null; issues: ManifestIssue[] }` 이고 이슈는 `{ code, path, message }`(한국어). kit 빌드 · 업로드(A3) · 호스트가 같은 함수를 부른다. `ThemeManifest` 타입의 정본은 theme-sdk(`types.ts`)다 — themes 의 zod 규격은 그 타입에 맞는지 `satisfies` 로 잠근다.

### D2. semver 는 좁은 부분집합

`version` 은 `^\d+\.\d+\.\d+$`. `sdk` 는 `^\^?~?\d+\.\d+\.\d+$` 꼴 가운데 `^x.y.z`(같은 major, ≥) · `~x.y.z`(같은 major.minor, ≥) · `x.y.z`(같음) 셋. `satisfiesSdk(range, version)` 과 `compareVersions(a, b)` 를 themes 에 둔다. 0.x 의 `^` 도 «같은 major» 로 읽는다(npm 과 다르다 — manifest 문서에 적는다).

### D3. 공유 런타임 — `@wirebound/theme-sdk/runtime`

```ts
export const WB_RUNTIME_GLOBAL = '__wirebound_runtime__'
export interface WbRuntime { react: typeof React; jsxRuntime: typeof JsxRuntime; sdk: typeof Sdk; sdkVersion: string; register(def: ThemeDefinition): void }
export interface RuntimeHandle { take(): ThemeDefinition | null; uninstall(): void }
export function installRuntime(target?: typeof globalThis): RuntimeHandle
```

호스트는 `installRuntime()` → `theme.js` 를 `<script>` 로 싣기 → `take()`. 두 번 `register` 되면 뒤의 것이 이기고 `console.warn`. `uninstall` 은 전역을 걷는다(테스트 · 갤러리 전환). 이 진입은 theme-sdk 의 **두 번째 export 경로**(`./runtime`)다 — 본 진입(`.`)은 런타임을 모른다.

### D4. `theme.js` 의 진입은 kit 이 짓는다

작성자의 `src/index.tsx` 는 `export default defineTheme({ manifest, views })` 만 한다. kit 은 가상 진입 `import def from '<entry>'; globalThis.__wirebound_runtime__.register(def)` 을 IIFE 로 묶는다. 작성자 코드에 전역 이름이 나오지 않는다.

### D5. 토큰 → CSS 변수는 `tokensCss(manifest, values?)`

`:root { --wb-<키의 . 을 - 로>: <값>; … }` 한 블록. 참조 기본값(`{a.b}`)은 `var(--wb-a-b)`. `values` 는 기본값과 다른 값만(프로젝트의 `theme_tokens` — A3) 받아 덮는다. 값은 그 토큰 타입의 검증을 지난 것만 싣고, CSS 를 깨는 글자(`;` · `{` · `}` · `<`)가 든 값은 버리고 이슈로 돌려준다.

### D6. 갤러리는 `packages/theme-gallery`

`ThemeGallery({ theme, variantsOf? })` — 카탈로그 19 컴포넌트마다 표본 노드(`GALLERY_SAMPLES`)를 manifest 가 선언한 variant 마다 한 번씩 그린다(선언이 없으면 한 번). 표본 노드는 A1a 의 패리티 표본(`git show f842e030:packages/renderer/test/fixtures/sample-nodes.ts`)을 출발점으로 한다. 포커스 · 마커 겹쳐 보기(`showOverlay`)는 렌더러의 `focusElement` · `markerPoint` 로 그린다. kit dev 와 웹 A4 의 토큰 편집 옆 갤러리가 같은 컴포넌트를 쓴다.

### D7. kit 산출물의 묶음 규칙

| 산출물 | 도구 | 밖으로 뺌 | 안에 묶음 |
|---|---|---|---|
| kit 의 Node 쪽(`bin` · `build` · `dev` 서버) | tsdown | `vite` · `@vitejs/plugin-react` · `esbuild` · `fflate` · `zod` · Node 내장 | `@wirebound/schema` · `@wirebound/themes` |
| kit 의 dev 갤러리 클라이언트(`dist/client/*.js`) | vite build(ESM) | `react` · `react-dom` · `react/jsx-runtime` · `@wirebound/theme-sdk` | `@wirebound/renderer` · `@wirebound/schema` · `@wirebound/themes` · `@wirebound/theme-gallery` |
| 작성자의 `theme.js` | vite build(IIFE) | 위 D4 의 셋(전역으로) | 작성자 코드와 그 npm 의존 |

템플릿의 `package.json` 은 `@wirebound/theme-sdk` · `@wirebound/theme-kit` 을 동봉 tarball(`file:vendor/…tgz`)로, 나머지(`react` · `react-dom` · `vite` 등)는 npm 판 범위로 적는다.

### D8. 설정 파일

작성자 프로젝트 뿌리의 `theme.config.ts` 가 `export default defineManifest({ … })` 를 낸다(theme-sdk 의 항등 함수 — 타입만 준다). `src/index.tsx` 는 그 manifest 를 import 해 `defineTheme` 에 넣는다. kit 은 설정을 esbuild 로 임시 ESM 에 묶어 `import()` 한다. 진입 경로 기본값 `src/index.tsx` — `--entry` 로 바꾼다.

### D9. `system-admin` 은 kit 프로젝트가 된다

`theme.config.ts`(`MANIFEST` 를 내보냄) · `src/theme.tsx`(`import './theme.css'` · `export default defineTheme({ manifest, views: DEFAULT_VIEWS })`)를 더하고 `package.json` 에 `"build": "wb-theme build --entry src/theme.tsx"`. 웹이 쓰는 `src/index.ts`(`ADMIN_V0` · `ADMIN_V0_CSS` — `?raw`)는 A4 가 캔버스를 `.wbtheme` 적재로 바꿀 때까지 둔다. 빌드 산출물 `dist/system-admin-0.1.0.wbtheme` 는 A3 의 시딩이 읽는다.

```ts
// packages/themes/test/manifest.test.ts
import { beforeAll, describe, expect, it } from 'vitest'
import { installCatalog } from '@wirebound/schema'
import { validateManifest } from '@wirebound/themes'

beforeAll(() => installCatalog())

const OK = {
  id: 'acme', name: 'ACME', version: '1.2.0', sdk: '^1.0.0',
  tokens: {
    groups: [{ id: 'color', label: '색' }],
    items: {
      'color.primary': { type: 'color', label: '주색', group: 'color', default: '#2563eb' },
      'color.hover': { type: 'color', label: '호버', default: '{color.primary}' },
      density: { type: 'select', label: '밀도', options: ['compact', 'comfortable'], default: 'comfortable' },
      'radius.card': { type: 'length', label: '모서리', default: '12px' },
    },
  },
  components: { List: { variants: [{ id: 'table', label: '표' }, { id: 'cards', label: '카드', hideProps: ['columns'] }], defaultVariant: 'table' } },
}

const codes = (raw: unknown) => validateManifest(raw).issues.map((i) => i.code)
const edit = (f: (m: any) => void) => { const m = structuredClone(OK); f(m); return m }

describe('validateManifest', () => {
  it('맞는 manifest 는 이슈 없이 돌려준다', () => {
    const r = validateManifest(OK)
    expect(r.issues).toEqual([])
    expect(r.manifest?.id).toBe('acme')
  })

  it.each([
    ['모양이 틀리면', edit((m) => { m.tokens = 3 }), 'shape'],
    ['판이 x.y.z 가 아니면', edit((m) => { m.version = '1.2' }), 'bad-version'],
    ['sdk 범위가 셋 밖이면', edit((m) => { m.sdk = '>=1' }), 'bad-sdk-range'],
    ['없는 토큰을 참조하면', edit((m) => { m.tokens.items['color.hover'].default = '{color.brand}' }), 'unknown-token-ref'],
    ['타입이 다른 토큰을 참조하면', edit((m) => { m.tokens.items['color.hover'].default = '{radius.card}' }), 'token-ref-type'],
    ['참조가 돌면', edit((m) => { m.tokens.items['color.primary'].default = '{color.hover}' }), 'token-ref-cycle'],
    ['기본값이 타입에 안 맞으면', edit((m) => { m.tokens.items['radius.card'].default = 'big' }), 'token-default-type'],
    ['select 기본값이 선택지 밖이면', edit((m) => { m.tokens.items.density.default = 'loose' }), 'token-select-default'],
    ['카탈로그에 없는 컴포넌트', edit((m) => { m.components.Carousel = m.components.List }), 'unknown-component'],
    ['variantFrom 컴포넌트에 variants', edit((m) => { m.components.Text = { variants: [{ id: 'a', label: 'a' }], defaultVariant: 'a' } }), 'variant-from-component'],
    ['variant id 가 겹치면', edit((m) => { m.components.List.variants.push({ id: 'table', label: '또' }) }), 'duplicate-variant'],
    ['defaultVariant 가 목록 밖', edit((m) => { m.components.List.defaultVariant = 'grid' }), 'default-variant-missing'],
    ['hideProps 가 그 컴포넌트의 prop 이 아니면', edit((m) => { m.components.List.variants[1].hideProps = ['nope'] }), 'unknown-hide-prop'],
    ['패턴이 스키마를 못 지나면', edit((m) => { m.patterns = { 'hero.split': { name: 'x', schema: { type: 'Nope' } } } }), 'pattern'],
  ])('%s → %s', (_label, raw, code) => {
    const r = validateManifest(raw)
    expect(r.manifest).toBeNull()
    expect(codes(raw)).toContain(code)
  })

  it('첫 이슈에서 멈추지 않는다 — 여럿을 한 번에 말한다', () => {
    const raw = edit((m) => { m.version = 'x'; m.components.List.defaultVariant = 'grid' })
    expect(codes(raw)).toEqual(expect.arrayContaining(['bad-version', 'default-variant-missing']))
  })

  it('이슈는 path 로 자리를 가리킨다', () => {
    const r = validateManifest(edit((m) => { m.components.List.variants[1].hideProps = ['nope'] }))
    expect(r.issues[0]!.path).toBe('components.List.variants.1.hideProps.0')
  })
})
```

```ts
// packages/themes/src/manifest/semver.ts
export const VERSION_PATTERN = /^(\d+)\.(\d+)\.(\d+)$/
export const SDK_RANGE_PATTERN = /^([~^]?)(\d+)\.(\d+)\.(\d+)$/

function parts(v: string): [number, number, number] {
  const m = VERSION_PATTERN.exec(v)
  if (!m) throw new Error(`판이 x.y.z 가 아닙니다: ${v}`)
  return [Number(m[1]), Number(m[2]), Number(m[3])]
}

export function compareVersions(a: string, b: string): number {
  const x = parts(a), y = parts(b)
  for (let i = 0; i < 3; i++) if (x[i] !== y[i]) return x[i]! - y[i]!
  return 0
}

export function satisfiesSdk(range: string, version: string): boolean {
  const m = SDK_RANGE_PATTERN.exec(range)
  if (!m) return false
  const base = `${m[2]}.${m[3]}.${m[4]}`
  const [vMajor, vMinor] = parts(version)
  if (m[1] === '') return compareVersions(version, base) === 0
  if (vMajor !== Number(m[2])) return false
  if (m[1] === '~' && vMinor !== Number(m[3])) return false
  return compareVersions(version, base) >= 0
}
```

```ts
// packages/theme-sdk/src/runtime.ts
import * as React from 'react'
import * as JsxRuntime from 'react/jsx-runtime'
import * as Sdk from './index'
import type { ThemeDefinition } from './types'

/** 호스트가 세우고 `theme.js`(IIFE)가 읽는 전역의 이름. kit 의 빌드가 import 를 이 전역의 속성으로 바꿔 쓴다. */
export const WB_RUNTIME_GLOBAL = '__wirebound_runtime__'

export interface WbRuntime {
  react: typeof React
  jsxRuntime: typeof JsxRuntime
  sdk: typeof Sdk
  sdkVersion: string
  register(def: ThemeDefinition): void
}

export interface RuntimeHandle {
  take(): ThemeDefinition | null
  uninstall(): void
}

export function installRuntime(target: typeof globalThis = globalThis): RuntimeHandle {
  let pending: ThemeDefinition | null = null
  const runtime: WbRuntime = {
    react: React, jsxRuntime: JsxRuntime, sdk: Sdk, sdkVersion: Sdk.SDK_VERSION,
    register(def) {
      if (pending !== null) console.warn('테마가 두 번 등록됐습니다 — 뒤의 것을 씁니다')
      pending = def
    },
  }
  ;(target as Record<string, unknown>)[WB_RUNTIME_GLOBAL] = runtime
  return {
    take() { const d = pending; pending = null; return d },
    uninstall() { delete (target as Record<string, unknown>)[WB_RUNTIME_GLOBAL] },
  }
}
```

`package.json` 의 `exports["./runtime"]` 은 본 진입과 같은 꼴(`development` → `./src/runtime.ts`, `import` → `./dist/runtime.js`). 버전을 1.0.0 으로 올리는 것은 `SDK_VERSION` 과 맞추려는 것이다(Task 8 의 tarball 이름이 이 판을 쓴다).

```ts
// system-themes/admin/build-test/wbtheme.test.ts
// @vitest-environment jsdom
import { readFileSync } from 'node:fs'
import { render } from '@testing-library/react'
import { beforeAll, describe, expect, it } from 'vitest'
import { installCatalog } from '@wirebound/schema'
import { readWbtheme } from '@wirebound/themes'
import { installRuntime } from '@wirebound/theme-sdk/runtime'
import { renderDocument } from '@wirebound/renderer'
import { buildTheme } from '@wirebound/theme-kit'
import { ADMIN_V0_CSS } from '@wirebound/system-theme-admin'

beforeAll(() => installCatalog())
const ROOT = new URL('..', import.meta.url).pathname

describe('system-admin .wbtheme', () => {
  it('kit 으로 빌드되고 읽기 검증을 지난다', async () => {
    const { file } = await buildTheme({ root: ROOT, entry: 'src/theme.tsx' })
    expect(file.endsWith('system-admin-0.1.0.wbtheme')).toBe(true)
    const { files, issues } = readWbtheme(new Uint8Array(readFileSync(file)))
    expect(issues).toEqual([])
    expect(files!.themeCss!.replace(/\s+/g, '')).toContain(ADMIN_V0_CSS.replace(/\/\*[\s\S]*?\*\//g, '').replace(/\s+/g, '').slice(0, 200))
  }, 60_000)

  it('실어 그리면 테마 뷰로 그려진다 — 공유 런타임 한 벌', async () => {
    const { file } = await buildTheme({ root: ROOT, entry: 'src/theme.tsx' })
    const { files } = readWbtheme(new Uint8Array(readFileSync(file)))
    const handle = installRuntime()
    try {
      new Function(files!.themeJs)()          // 호스트가 <script> 로 싣는 것과 같은 일
      const def = handle.take()
      expect(def?.manifest.id).toBe('system-admin')
      const doc = { version: 1, root: { id: 'r', type: 'Page', children: [{ id: 'b', type: 'Button', props: { label: '저장' }, variant: 'primary' }] } }
      const { container } = render(<>{renderDocument(doc as never, { theme: def! })}</>)
      const btn = container.querySelector('[data-wb-id="b"]')!
      expect(btn.tagName).toBe('BUTTON')
      expect(btn.getAttribute('data-wb-variant')).toBe('primary')
      expect(container.querySelector('[data-wb-error]')).toBeNull()
    } finally { handle.uninstall() }
  }, 60_000)
})
```
