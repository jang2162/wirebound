## L-308 — 프리셋 저장

**고침.** `packages/schema` 에 `nestedPagesUnderRoot(nodes)` — 빈 뿌리 `Page` 아래에 놓아 `validateTree` 의 판정을 그대로 쓰고 `nested-page` 만 낸다(경로는 묶음 기준 `/1/children/0`). `POST …/presets` 가 봉투 · NUL 검사 뒤 그것을 불러 있으면 **422** `validation-failed` «프리셋을 저장할 수 없습니다» · 노드마다 이슈 `{ code: 'nested-page', severity: 'error', nodeId, path: '/schema/…', message }`. 문장은 스키마 문장이 아니라 고치는 길을 말하는 프리셋 문장이다: «프리셋에 Page를 담을 수 없습니다 — 적용하면 페이지 안의 Page가 됩니다. 이 페이지 안의 Page를 지우거나 그 안의 노드를 밖으로 옮긴 뒤 저장하세요».

**값.** 재현 = 맨 위 · 깊은 `Page` 프리셋 둘 다 201(본문에 `"type":"Page"` 가 실린 행). 고친 뒤 = 422 · `[['nested-page','n_presetpage1','/schema/1']]` · `[['nested-page','n_presetpage2','/schema/0/children/0']]` · 행 0. **다른 카탈로그 검증은 안 걸었다** — 알 수 없는 타입(`없는타입`)이 든 프리셋은 지금처럼 201(케이스로 잠금 · 변조 N8 이 그 케이스를 죽인다 = 카탈로그 오류 전부를 보면 지금 받던 프리셋이 422 가 된다). 저장된 `Page` 프리셋(`insertPreset` 로 심음) 목록 200 · 삭제 204. 프리셋을 고치는 라우트는 없다(`POST` · `DELETE` 뿐).

**웹 «프리셋으로 저장».** 저장 실패는 `toFailure` → `reason` 이 `issues[].message` 를 이어 붙여 보인다(봉투 문장이 아니라). 옛 문서(페이지 안에 `Page`)에서 저장하는 jsdom 판: 보낸 본문 1 · 화면에 위 프리셋 문장 · 봉투 «프리셋을 저장할 수 없습니다»는 안 보임. 대역의 422 본문은 서버가 내는 꼴을 옮긴 것이고 서버 쪽 문장은 api 케이스가 글자로 잠근다.
