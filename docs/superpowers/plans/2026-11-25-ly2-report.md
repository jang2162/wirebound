### 결정

1. **봉투의 `layout` 필수는 판 7 ~ 지금 판(`CURRENT_DOCUMENT_VERSION`)에만 건다.** 판 6 이하 픽스처(판 1 · 5 로 짓는 케이스 수백 줄)는 그대로 지나고, 지금보다 높은 판도 이 키로 거절하지 않는다 — CLI · MCP 의 «못 올리는 문서 버전을 말한다» 케이스(판 99 픽스처)가 덤프째 거절되는 것을 막는다(`packages/cli/test/page-get.test.ts` · `packages/mcp/test/read-tools.test.ts` · `validate.test.ts` 가 그 판으로 빨강이었다).
2. **`pageKindOf` 는 레이아웃이 없는 문서(판 6 이하 · 검증 전)를 판 6 의 뜻으로 읽는다**(`legacyPageLayout`). 그래서 인구조사의 허용 자리는 계획의 «`validate.ts` 하나» 가 아니라 **둘**이다 — `validate.ts`(짝 검사) · `migrate-page-layout.ts`(판 6 규칙). 판 6 의 뜻을 두 벌로 두지 않으려고 `pageLayoutOf` 가 그 함수를 부른다.
3. `TreePage`(웹) · `PageDocument.layout` 의 TS 타입은 선택이다 — 판 6 이하 문서도 같은 타입으로 든다. 판 7 에서의 «늘 있다» 는 봉투가 지킨다.
4. 인구조사(`packages/schema/test/page-layout-census.test.ts`)는 TypeScript AST 로 센다(`'Popup'` 과 견주는 식의 다른 쪽에 `root` · SQL 의 `->'root'->>'type'` 글자). `@wirebound/test-support` 의 `stripComments` 는 쓰지 않았다 — schema 의 테스트가 test-support(→ themes → schema)에 기대면 빌드 참조가 고리가 된다. `zones-census.test.ts` 와 같은 꼴이다.

### 결정

1. **`0038` 의 `down` 은 레이아웃 행을 다시 짓지 않는다** — 계획(«`down` 은 … 프로젝트마다 기본 레이아웃 행을 다시 짓는다»)과 다르다. 행을 다시 지으면 내린 판의 복원이 payload 의 `layouts: []` 와 견줘 409 로 막히고, 그 아래 `0025` · `0028` · `0029` 의 `down` 이 레이아웃 행 수로 «백업에서 되돌린다» 에 멈춘다(`0025-state-visibility.ts` 의 `down` 이 페이지 · 모듈 · 레이아웃 행 수가 0 이 아니면 던진다 — 코드로 읽은 까닭이다). 행을 짓는 `insert` 는 `seed-user.test.ts` «행 삽입이 없다» 의 마이그레이션 디렉터리 셈에도 걸린다. 빈 표면 걷기 전 판의 코드가 그대로 돈다 — 잃는 것은 걷기 전 레이아웃 행의 id 뿐이다. 설계 문서의 그 문장은 고쳤고, 계획(시점 문서)은 그대로 둔다. 근거는 마이그레이션 머리말에 있다.
2. **저장된 manifest 가 걷힌 `Slot` 을 선언해도 패키지째 읽힌다** — 지침 «카탈로그에서 타입을 걷거나 바꾸는 트랙도 …» 의 위험. `validateManifest(…, { stored: true })` 가 이미 모르는 컴포넌트를 받는 판이라 고칠 곳은 없었고, 그 성질을 `packages/themes/test/manifest.test.ts` «걷힌 Slot 을 선언한 저장된 manifest 도 받는다 — 올리기 판은 거절한다» 로 잠갔다. 얼려 둔 앞 판 기본테마(`apps/web/build-test/fixtures/` 의 0.1.0 · 1.5.0 · 1.6.0 · 1.7.0)는 `Slot` 선언 · `SlotView` · `.slot` 글자가 0 이다(패키지를 풀어 셌다). main 사본으로 시딩한 DB 에서 내보내기 `themeWarning` 을 재는 판은 세우지 않았다 — 남은 것에 적는다.
3. 옛 판 DB 를 세우는 마이그레이션 케이스(`migration-0018` · `compose-field-migration` · `node-zones-migration` · `tree-items-migration` 등)의 레이아웃 문서 픽스처(`Page > Slot`)는 그대로 둔다 — 그 판에는 `layouts` 표가 있다. 끝 판까지 올리는 케이스는 레이아웃 행 단언을 걷었다.
4. `packages/schema/test/zones-census.test.ts` 의 `apps/web/src/api/http-client.ts` 수 1 → 2 — T2 의 `withLayouts`(메뉴 트리 — 노드 아님)가 그 수를 바꿨는데 T2 에서 그 파일을 안 돌렸다. T3 에서 고쳤다.
5. 다른 설계 문서(`2026-09-27-code-themes-design.md` · `2026-10-23-node-slots-design.md` · `2026-11-02-theme-preview-and-project-cards-design.md`)의 `Slot` · `renderComposed` 문장은 그 설계의 시점 기록이라 고치지 않았다. 남은 이름 셈(낱말 단위 · 계획 · 이 설계 문서 빼고): `renderComposed` 1(그 설계 문서) · `SlotView` 0 · `LayoutDocument` 0 · `listLayouts` 0 · `default_layout_id` 는 README 의 걷었다는 문장 둘 · 얼린 `0007-layouts.ts` · 옛 판 케이스 `migration-0018.test.ts` 뿐이다.
