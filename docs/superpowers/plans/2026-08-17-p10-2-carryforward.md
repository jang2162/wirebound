## 2. **화면 이미지 — 이 슬라이스가 세운 것**

### 2.1 계약이 이어진다

```
exportPage({document, title, theme}) → { html, css }
        ↓ setContent + addStyleTag  (파일을 안 쓴다)
   헤드리스 Chromium → PNG
        ↓ readPngSize (바이트의 IHDR)
   PptxScreen { fileName, bytes, width, height }
        ↓ exportPptx (P10-1 이 만든 자리 — **한 줄도 안 고쳤다**)
   ppt/media/imageN.png + 슬라이드의 a:blip
```

| 무엇 | 값 | 어디가 강제하나 |
|---|---|---|
| 그리는 자를 채우는 자리 | **`main.ts` 하나** | `apps/api/test/screen-renderer-census.test.ts` |
| `playwright-core`를 아는 소스 | **하나**(`services/screen-render-chromium.ts`) | 〃 |
| 화소 | 뷰포트 720×552 · 배율 2배 · **화면 전체** → 폭 1440 고정, 높이는 내용이 정한다 | `screen-render-chromium.ts` |
| 못 읽은 화소 | **성공이 아니다.** `readPngSize`가 `null`을 내고 그 장이 실패가 된다 | `test/screen-render.test.ts` · `test/export-pptx-screens.test.ts` |
| 상한 | **200장.** 넘은 장은 이유가 **분모를 함께** 말한다 | `build-test/screen-chromium.test.ts` |
| 동시성·타임아웃 | 동시 4 · 한 장 10초. **브라우저는 `render` 한 번의 수명이다** | 〃 |
| 한글 글꼴 | **두부면 한 장도 안 그린다** | 〃 |
| 바깥 요청 | **끊는다**(`data:`는 산다) | 〃 |

### 2.2 **`screenless`와 `screenFailures`를 접지 마라**

| 값 | 뜻 |
|---|---|
| `screenless` | **아무도 안 그렸다** — 그리는 자가 없었다 |
| `screenFailures` | **그리려다 죽었다** — `{ title, reason }` |

**둘은 겹치지 않는다.** `exportPptx`가 내는 *"이미지 없는 페이지"*의 합집합이 이 둘이고,
이유가 있는 쪽을 덜어 낸 나머지가 `screenless`다. P10-1 이월 §2.3-1이 연 자리가 이것이고
**닫혔다.** 접으면 화면이 *"아직 아무도 안 만들었다"*와 *"만들려다 실패했다"*를 같은 말로 한다.

### 2.3 **PowerPoint가 읽은 값** (이 기계, 16.112)

| 파일 | 결과 | 재현 |
|---|---|---|
| 화면 이미지 셋이 실린 것 | `OPENED` · 슬라이드 1의 도형 셋이 `text box / **picture** / text box` | **2/2** |
| 대조군(열려야 한다 — 같은 코드, 이미지 없음) | `OPENED` | 1/1 |
| 음성 대조군(매체 `png`의 `Default`를 지웠다) | `NOT_OPENED` + 복구 대화상자 | 1/1 |

| 슬라이드 | 이미지 화소 | PowerPoint가 그린 크기 |
|---|---|---|
| 1 | 1440×1104 | **540.0pt × 414.0pt**(자리를 꽉 채운다) |
| 2 | 1440×1760 | **338.7pt × 414.0pt**(세로가 길어 좌우가 남는다) |

**`fitInto`가 진짜 값에서 도는 것을 받는 쪽이 확인해 준 자리다.**

### 2.4 **바로 걸리는 자리 여덟**

| 무엇 | 어디 | 왜 |
|---|---|---|
| **`document.fonts.check`를 쓰지 마라** | `screen-render-chromium.ts`의 `KOREAN_GLYPH_PROBE` | **없는 이름에도 참을 낸다**(쟀다 — 보고서 §2.3). 물어야 할 것은 이름이 아니라 글리프다 |

| **화소를 뷰포트에서 추론하지 마라** | `screen-render.ts`의 `readPngSize` | 화면 전체를 찍으므로 높이는 내용이 정하고 배율이 곱해진다 |
| **`exportPptx`에 그리는 자를 넘기지 마라** | `services/export-pptx.ts` | 넘기는 순간 `packages/exporter`가 브라우저를 알게 된다. census가 그 모양을 센다 |

| **그리는 길의 `try`를 걷어 내지 마라** | `drawScreens` | 이음매의 타입은 *"던지지 않는다"*를 강제하지 못한다. 걷어 내면 **라우트 둘이 500**이 된다(귀속: 리뷰 §2.1) |

## 3. **미결 장부** — P10-1 이월 §4를 갱신한다

**소유하는 문서로 가라.** ✱는 이 슬라이스가 값이나 사정을 더한 것이다.

### 3.1 이 슬라이스가 **닫은 것** — 여섯 (뒤의 셋은 **리뷰 대응**이다)

| 무엇 | 소유 | 상태 |
|---|---|---|
| **`screenless`가 오늘은 늘 전부라 정보가 없다** | P10-1 이월 §2.3-2 · §4.2 | **닫혔다.** 그리는 자가 서서 값이 되었다 |
| **pptx 미리보기가 `errors`에 해당하는 값을 안 낸다** | P10-1 이월 §2.3-1 · §4.2 | **닫혔다.** `screenFailures`가 그 자리다 |
| **화소가 0·NaN이면 비율을 버린다 — 그 갈래를 재는 케이스가 없다** | P10-1 리뷰 §6.1 · 이월 §4.2 | **닫혔다.** 케이스가 셋이다 — `fitInto`가 늘이는 갈래(`packages/exporter/test/pptx.test.ts`) · `readPngSize`가 0을 `null`로 내는 갈래 · 그 값이 계약에 못 들어가는 갈래 |
| ✱ **팝업이 차단 규칙 밖이었다** | P10-2 리뷰 §4 | **닫혔다.** 차단을 페이지에서 **컨텍스트**로 올렸다. `build-test`가 로컬 서버로 **일곱 길 전부**를 재고, `pnpm test`가 `exportPage`의 HTML에 `<script`가 없는 것을 잰다(두 번째 방벽) |
| ✱ **`apps/api/build-test`가 타입검사 밖이었다** | P10-2 리뷰 §9 | **닫혔다.** `tsconfig.json`의 `include`에 넣었다. 리뷰의 T1 변이를 다시 심으니 `pnpm typecheck`가 **종료 코드 2**를 낸다 |
| ✱ **`packages/exporter`의 순수함을 재는 자가 없었다** | P10-2 리뷰 §10.1 | **닫혔다.** 문서 셋이 census를 그 자로 적었는데 census의 분모가 `apps/api/src`뿐이었다. 이제 그 패키지의 `src`(`.tsx` 포함)를 직접 훑는 케이스가 있다 |

### 3.2 **배포** — ✱ **여기가 이 슬라이스가 값을 가장 크게 바꾼 자리다**

P10-1 이월이 *"`Dockerfile`이 없어 「새 배포 조건」이 얼마나 비싼지 아직 아무도 모른다"*로
남겼다. **이제는 안다.**

| 무엇 | 값 |
|---|---|
| 저장소가 더 무거워졌나 | **거의 아니다** — `playwright-core` 13.4MB · **전이 의존 0** · 설치 스크립트 0. `pnpm install`이 1초에 `+1`이었고 **브라우저를 안 내려받았다** |
| 배포가 무거워지나 | **그렇다** — Chromium이 **356MB**(전체) 또는 **196MB**(headless shell). `playwright-core`는 그것을 **안 들고 온다** |
| 그것을 넣는 명령 | **`playwright` 패키지를 안 들여도 된다.** ✱ **다만 이 줄의 경로가 틀렸다** — 설치 매뉴얼 슬라이스(2026-08-18)가 실제로 돌려 봤다: 루트 기준 `node node_modules/playwright-core/cli.js …`는 **`Cannot find module`**이다(pnpm 의 엄격한 배치라 그 패키지가 루트에 없다). 되는 것은 **`node apps/api/node_modules/playwright-core/cli.js install chromium`**이다. `--only-shell`이면 headless shell만(**서버가 실제로 찾는 것이 그것이다** — 오류 문장의 경로가 `chromium_headless_shell-<리비전>`이다), `--with-deps`가 **시스템 라이브러리**를 함께 넣는다 |
| ✱ 내려받기와 디스크는 다른 값이다 | 위 줄의 356MB·196MB는 **디스크**다. `--only-shell`의 **내려받기는 94.7 MiB**(+ FFmpeg 1 MiB)이고 **6.4초** 걸렸다 — 빈 캐시에 실제로 받아 쟀다(설치 매뉴얼 슬라이스). **이미 있으면 출력 없이 종료 코드 0 이다** |
| 없으면 어떻게 되나 | **던지지 않는다.** 전부 실패하고 pptx는 그림 없이 나오며 미리보기가 이유를 말한다(`브라우저를 띄우지 못했습니다: …`). 케이스가 그 갈래를 든다 |
| **한글 글꼴** | **이 기계(macOS)에는 있다. 리눅스 컨테이너에는 보통 없다** — `fonts-noto-cjk` 부류를 넣어야 한다. **없으면 한 장도 안 그린다**(D4). 그 갈래를 **아무도 안 쟀다** — 잴 수 있는 것은 `Dockerfile`이 생긴 뒤다 |

**그러므로 `Dockerfile`을 만드는 사람에게 남기는 것은 세 줄이다:**

1. **브라우저 바이너리를 이미지에 넣어라** — 안 넣으면 pptx의 화면이 통째로 빈다(조용하지는 않다).
2. **한글 글꼴을 넣어라** — 안 넣으면 D4가 발동해 역시 한 장도 안 그린다.
3. **그 둘을 넣었는지 재는 자를 만들어라** — 오늘 `apps/api/build-test/screen-chromium.test.ts`가
   *"이 기계에서"* 재고, 없으면 건너뛴다. **컨테이너 안에서 그것이 초록인지는 아무도 안 본다.**

### 3.3 **흔들리는 api 케이스 둘** — ✱ **세 판째 같은 모양이다**

**소유는 여전히 P9-4 이월 §3.1(ⓐ~ⓓ)이다.**

| 축 | 실행 | 빨강 |
|---|---|---|
| 브랜치 · `pnpm test` | **4** | **1**(ⓐ = `comments-concurrency`의 B5) |

| `main`(f1fead1, 분리된 HEAD 워크트리) · `pnpm test` | **3** | **0** |

**이 표본으로는 브랜치와 `main`을 못 가른다.** **원인을 단정하지 마라.**

**✱ 세 판이 같은 방향을 가리킨다:** 빨강이 `--project api` 축에서 **0**이고 `pnpm test`
축에서만 난다(P9-5 · P10-1 · 이 판). 사건이 셋이라 여전히 못 가르지만 **다음 사람은 두
축을 갈라서 세라** — 이제 그 문장을 세 판이 함께 든다.

**✱ 설치 매뉴얼 슬라이스(2026-08-18)가 더한 표본:** `pnpm test` **1회 · 빨강 0**(273 파일 ·
5060 케이스). **표본 하나이므로 아무것도 뒤집지 않는다** — 이 절의 표에 실행 하나를 더할
뿐이다. 그 판은 api 소스를 안 고쳤고 더한 api 케이스 파일 하나가 이름 순으로
`comments-concurrency.test.ts`(8번째)보다 **앞이다**(`config-screen-chromium.test.ts`) —
`singleFork`라 그 케이스가 **뒤로 밀린다.** P9-5가 더한 둘과 같은 쪽이고 P10-1·P10-2와는
반대쪽이다. **그 축이 무엇을 뜻하는지는 여전히 모른다.**

**✱ 이 브랜치가 그 축에 얹히는 방식:** 더한 api 파일 셋이 **전부 이름 순으로
`comments-concurrency.test.ts`(8번째)보다 뒤다**(14·47·48). `singleFork`라 그 케이스가
**먼저** 돈다 — P10-1과 같은 모양이고, P9-5가 더한 둘만 앞이었다.

**고치는 자리는 그대로다:** 두 요청이 실제로 겹쳤다는 것을 케이스가 확인하는 이음매가
`apps/api`에 필요하다.

| ✱ **PUA 전제가 기계에 달린 것은 그대로다** | 열림. 판정자는 이제 후보 넷이 **서로 같을 때만** 기준선으로 쓰고, 다르면 *"못 물었다"*로 답한다(*"있다"*로 조용히 넘어가지 않는다). **그러나 `U+E000` 부근을 쓰는 글꼴(Nerd Font·Font Awesome 계열)이 깔린 기계에서 무슨 일이 나는지는 아무도 안 쟀다** — 리뷰도 기계의 글꼴을 바꾸는 일이라 안 했다(귀속: 리뷰 §17). **후보가 전부 그 글꼴에 걸리면** 기준선이 다시 서고 판정이 되살아나는데, 그때 기준선은 두부가 아니다 |

### 3.7 **워크트리 격리 슬라이스(2026-08-19)가 닫은 것과 더한 것**

> ✱ **이 절의 판정 하나는 같은 날 뒤집혔다 — §3.10 을 함께 읽어라.** *"컨테이너는 하나를
> 공유하고 DB 이름만 가른다"* 가 *"워크트리마다 자기 컨테이너를 띄운다"* 가 됐다(사용자가
> 다시 정했다). 아래는 **그때의 관측이고 값은 그대로 선다** — 바뀐 것은 결론이다.

> 보고: `2026-08-19-worktree-isolation-report.md` · 계획: `2026-08-19-worktree-isolation.md`
> **새 장부를 만들지 않았다** — 이 절이 그 판의 몫이다.

사용자가 보고한 것은 *"여러 워크트리에서 서버를 올리면 컨테이너명이나 포트번호가 충돌 나는
경우가 있어"* 였다. 재 보니 **갈래가 넷이었고 둘이 조용했다.**

#### 닫은 것 — 넷

| 무엇 | 소유 | 상태 |
|---|---|---|
| **`vite.config.ts`에 3001이 박혀 있다** | §3.6이 안 든 자리(설치 매뉴얼 판은 *"함께 바꿔라"*로 문서화만 했다) | **닫혔다.** `apps/web/config/api-proxy-target.ts`가 `apps/api/.env`의 `PORT`를 따라간다(`node:util`의 `parseEnv` — 새 런타임 의존 없음). **셸 → 파일 → 3001** 순서가 api 의 `--env-file-if-exists`와 같아 **두 실행자가 같은 답을 낸다.** 되짚기에서 워크트리 둘의 로그인이 **각각 자기 DB로** 갔다(전에는 B의 계정이 401, A의 계정이 200이었다) |
| **`.env`를 고쳐도 서버가 안 읽고 아무 말도 안 한다**(§3.6이 열어 둔 것) | §3.6 | **반쯤 닫혔다.** 다시 띄우라는 조치는 그대로지만, 이제 **다시 띄웠는지 확인할 값이 화면에 있다** — api 는 `이 서버가 보는 DB: 127.0.0.1:5433/…`, 에디터는 `➜  API 프록시:  http://127.0.0.1:…`. **vite 도 `apps/api/.env`를 감시하지 않는다는 것을 새로 쟀다**(보고 §5.5) — `tsx watch`와 같은 결이라 README 가 한 자리에서 든다 |
| **워크트리마다 DB를 가르는 길이 없다** | (아무도) | **닫혔다.** `DATABASE_URL`은 원래 열려 있었고 **`TEST_DATABASE_URL`이 안 열려 있던 칸을 이었다** — `pnpm test`는 루트에서 도는 vitest 라 `apps/api`의 `--env-file-if-exists`를 안 지난다. `apps/api/test/test-database-url.ts`가 그 칸이고 **가져가는 키는 `TEST_DATABASE_URL` 하나뿐이다**(운영 `DATABASE_URL`이 테스트 프로세스에 들어가면 안 된다) |
| **`CLAUDE.md`의 *"api 테스트를 동시에 돌리지 않는다"*** | `CLAUDE.md` | **조건부로 풀렸다.** 구현자와 리뷰어가 각각 재서 같은 결론을 냈다 — 같은 테스트 DB 면 **둘 다 종료 1**, 가르면 **둘 다 종료 0**. **값은 `README.md` §3.1의 표가 소유한다**(여기 옮겨 적지 않는다 — 앞 판이 그렇게 해서 수가 낡았을 때 고칠 자리가 다섯이 됐다: 귀속: 리뷰 §7.2). **가르지 않았으면 옛 규칙이 그대로 선다**고 같은 문단에 적었다 |

#### 더한 것 — 열림

| 무엇 | 상태 |
|---|---|
| ✱ **compose 볼륨이 프로젝트 이름을 따라 갈린다 — 그 끝을 못 쟀다** | 열림(**일부 관측 · 일부 추론**). §3.6은 컨테이너 **이름** 충돌까지만 들었는데 **볼륨도 갈린다**: `feat-p1-api_wirebound-pgdata` **LINKS 1 · 수백 MB** vs `wirebound_wirebound-pgdata` **LINKS 0 · 0B** vs `feat-p2b1-editor-shell_…` **0B**(쟀다. **크기는 사는 수라 안 적는다** — 세 번 재서 145.9MB·316.4MB·203.8MB 였다. 읽을 것은 `LINKS` 다). 오늘 그 길을 막는 것은 **`container_name`이 고정이라는 사실 하나뿐**이다. **이름 충돌이 사라지는 날 빈 DB 가 뜨고 사람은 데이터가 사라졌다고 읽는다 — 그 마지막 한 걸음은 안 쟀다**(재현하려면 사용자의 컨테이너를 지워야 한다). README §6.3이 값을, §10이 *"못 쟀다"*를 든다 |
| ✱ **떠 있는 컨테이너가 없어진 워크트리 소유다** | 열림(관측). 라벨이 `project=feat-p1-api`, `working_dir=…/.worktrees/feat-p1-api`인데 **git 은 그 워크트리를 모른다.** 남은 것은 compose 의 바인드 마운트가 되살린 **빈 `docker/postgres-init/`** 뿐이라 `docker-compose.yml`도 없다. 그래서 **최상위에서 `docker compose down`을 쳐도 못 찾고**(`ps`가 빈 표에 종료 0), `-p feat-p1-api`로는 찾는다(둘 다 쟀다). **그 빈 `postgres-init/`은 볼륨이 다시 만들어질 때 `01-test-db.sql`이 안 돈다는 뜻이기도 하다** — §3.6이 *"못 쟀다"*고 남긴 그 함정이 그때 온다. **어떻게 정리할지는 이 판이 정할 자리가 아니다**(사용자의 데이터가 그 볼륨에 있다) |
| ✱ **워크트리에서 `docker compose up -d`의 에러 원문을 이 판이 직접 못 쟀다** | 열림(도구 정책). 이 세션의 분류기가 그 명령을 막았고 **브리프의 금지와 같은 방향이라 우회하지 않았다.** README §6.3의 원문은 **설치 매뉴얼 판이 이 기계에서 잰 값**이다(귀속: `2026-08-18-install-manual-report.md` §3.1). §3.6의 그 줄과 **같은 관측**이라 두 벌이 아니다 |
| **워크트리 셋 이상을 안 재 봤다** | 열림. 이 판의 값은 **전부 워크트리 둘**에서 나왔다. 포트·DB 이름이 셋 이상에서 어떻게 밀리는지는 안 쟀다(에디터 포트가 5173→5174→5175로 밀리는 것까지만 봤다) |
| **`apps/web`에 `@types/node`가 들어왔다** | 열림(판정). `vite.config.ts`가 `node:fs`·`node:util`을 쓰기 때문이다. **타입 전용 devDependency**이고 저장소의 나머지와 같은 `^26.1.2`다. **브라우저 프로그램에 Node 타입이 새지 않도록 `apps/web/tsconfig.node.json`으로 갈랐고**, 루트 `typecheck` 글롭을 `apps/*/tsconfig*.json`으로 넓혔다. 그 새 tsconfig 가 **실제로 검사받는 것**을 오류를 심어 확인했다(종료 2 → 복구 후 0) |
| **`resetRealData`를 거는 파일이 하나가 아니라는 것** | 닫힌 문서 오류이자 **열린 설계 사실**. `apps/api/README.md`는 *"`revisions-concurrency.test.ts`가 `DELETE FROM` 으로 지운다"*고 적었는데 **`DELETE FROM` grep 은 0 건**(Kysely 로 적혀 있다)이고 **파일도 하나가 아니다.** 문서는 고쳤고, **수를 다시 적는 대신 `real-api-harness.test.ts`가 불변식을 센다**(*"`withRealApi`를 쓰는 파일은 전부 청소를 건다"* — 파일이 늘어도 안 낡는다). **남는 사실은 격리 전략의 범위가 `singleFork` — 즉 프로세스 하나 — 라는 것**이고, 그래서 프로세스가 둘이면 안 닿는다 |


### 3.8 **워크트리 격리 리뷰 대응(2026-08-19)** — 리뷰가 이월로 넘긴 다섯

> 리뷰: `2026-08-19-worktree-isolation-review.md` §12.2 · 판정은 **병합 가능**이었고
> **막는 것은 없었다.** 아래는 그 리뷰가 값과 함께 넘긴 다섯이다.
> **새 장부를 만들지 않았다.**

**리뷰가 변이 아홉을 심어 넷이 살았다**(귀속: 리뷰 §9). 살아남은 자리가 전부 한 꼴이었다 —
***"순수한 규칙에는 자가 촘촘한데 그 규칙을 꽂는 배선 한 줄에는 자가 없다."*** 구현자의 변이
여덟은 전부 **덮인 쪽**에 심겨 여덟이 다 죽었고, 안 덮인 배선에 심으면 **게이트 넷이 전부
초록인 채로** 회귀가 지나갔다.

#### 이 판이 닫은 것 — 둘

| 무엇 | 리뷰의 값 | 상태 |
|---|---|---|
| **`vite.config.ts`의 배선 한 줄**(리뷰 §12.2-1 · R3) | `shellEnv`·`fileEnv`를 뒤집자 `.env`의 `PORT=3063`이 셸의 `PORT=3099`를 이겼다 — **D1이 없애려던 어긋남 그대로**인데 게이트 넷이 초록이었다 | **닫혔다.** `api-proxy-target.test.ts`가 `?raw`로 원문을 읽어 인자 객체를 키→값으로 대조한다(`shell-css`·`store-access`와 같은 관용구, 빈 문자열 함정을 잡는 카나리아를 먼저 둔다). **재심기: 죽는다(종료 1)** |
| **`helpers.ts`의 배선 한 줄**(리뷰 §12.2-1 · R4) | `fileEnv` 인자를 빼자 스위트가 조용히 `wirebound_test`를 먹고 **전부 통과**했다. 이 슬라이스가 산 *"워크트리마다 테스트 DB가 갈린다"*가 통째로 사라지는데 아무도 안 죽었다 | **닫혔다.** 읽기+순서를 `resolveTestDatabaseUrlFrom`으로 내리고 **경로를 인자로 받게** 해서 임시 파일로 합쳐진 동작을 잰다. `helpers.ts`에 남은 한 줄은 인구조사가 못박는다. **재심기: 죽는다(종료 1)** |
| **`global-setup` 힌트 경로 — 자격 문자열 유출 포함**(리뷰 §12.2-2 · R5·R6) | 관문을 `3D000`→`42P01`로 바꾸면 힌트가 **안 뜨고**, 이름 대신 원문을 쓰게 하면 `테스트 DB "postgres://wirebound:wirebound@…" 가 없습니다`로 **자격 문자열이 통째로 실린다.** 둘 다 살았다 | **닫혔다.** `missing-database-hint.ts`로 꺼냈다 — 그 `catch`는 마이그레이션이 실패해야만 지나는 길이라 케이스가 못 닿았다. **D4의 *"자격 문자열을 통째로 찍지 마라"*를 케이스 넷이 문다**(R6 재심기가 그 넷을 죽인다). **재심기: 둘 다 죽는다** |
| **`.env.example`을 읽는 자가 없다**(리뷰 §12.2 · R7) | `#TEST_DATABASE_URL=` 줄을 지워도 저장소 어디도 안 운다. README §3.1의 4번은 *"주석을 푼다"*로 **그 줄의 존재를 전제한다** | **닫혔다.** `env-example-census.test.ts`가 `src/config.ts`의 `EnvSchema`를 소스에서 세어 대조한다 — 목록을 손으로 안 적으므로 **새 env 를 열고 안 적는 것**도 함께 잡힌다. **재심기: 죽는다(종료 1)** |

> `apps/api`를 import 할 수 없다). 그래서 **행동을 잴 수 있는 쪽은 행동으로**(api — 임시
> 파일을 주고 실제로 읽게 한다), **못 재는 쪽은 인구조사로**(web — 브라우저 프로그램에
> `node:fs`가 없어 `?raw`로 원문을 읽는다) 나눴다. 인구조사는 글자를 보는 자라 **뒤집기·삭제는
> 잡고 같은 뜻의 다른 표기는 못 잡는다** — 그 한계를 안고 쓴다.

#### 아직 열린 것 — 셋

| 무엇 | 값 | 상태 |

### 3.10 **워크트리마다 컨테이너(2026-08-19)** — 앞 판의 판정을 뒤집었다

> 보고: `2026-08-19-per-worktree-container-report.md` · 계획: `2026-08-19-per-worktree-container.md`
> **새 장부를 만들지 않았다.** 사용자가 다시 정했다 — *"컨테이너 고정 해제 하고 개방 포트
> `.env` 에서 설정 가능하도록"* · ***"워크트리마다 완전 별개(컨테이너·포트·데이터 전부)"***.

**§3.7 의 *"컨테이너는 하나를 공유하고 DB 이름만 가른다"* 가 뒤집혔다.** `container_name`
고정을 걷고 호스트 포트를 `apps/api/.env` 의 `POSTGRES_PORT` 로 받는다 — compose 가 디렉터리
이름을 프로젝트 이름으로 쓰는 것이 **이제 격리 기전**이다(컨테이너·볼륨이 그 이름을 따라간다).

#### 닫은 것 — 넷

| 무엇 | 소유 | 상태 |
|---|---|---|
| **§3.7 이 열어 둔 *"이름 충돌이 사라지면 빈 DB 가 뜬다 — 그 마지막 한 걸음을 안 쟀다"*** | §3.7 | **닫혔다 — 끝까지 쟀다.** 임시 프로젝트 둘로 재현했다(사용자 컨테이너는 안 건드렸다): 이름을 안 고정하면 둘째가 `<프로젝트>-postgres-1` 로 뜨고 **자기 볼륨을 새로 만들며 그 DB 는 비어 있다.** **그리고 그것이 이제 정상 경로**라 조용하면 안 된다 → 아래 |
| **빈 DB 가 조용하다**(D3) | (새로) | **닫혔다 — 계획서의 자리와 다른 자리에서.** 계획서는 *"뜰 때 0 건이라고 말하라"* 였는데 **빈 DB 에서는 서버가 뜨지 못한다**(`buildApp` 이 `themes` 에 쓴다 — `relation "themes" does not exist`, 종료 1). 그래서 **뜬 뒤**에는 `이 서버가 보는 DB: … · 마이그레이션 N건`, **못 떴을 때**는 원문 대신 *"이 DB 는 비어 있습니다 … 지우지 말고 다른 이름의 볼륨을 찾으십시오"* 를 낸다(`src/db/describe-schema-state.ts`) |
| **포트가 두 자리에 있어 어긋나면 남의 컨테이너에 붙는다**(D2) | (새로) | **닫혔다 — 자로.** **한 자리로 못 모은다는 것을 쟀다**: Node 의 `--env-file` 도 `util.parseEnv` 도 `${...}` 를 안 펴고 compose 는 URL 에서 포트를 못 뽑는다. 그래서 `src/db/port-agreement.ts` 가 규칙을 들고 **`loadConfig`(서버·`migrate`)와 테스트 DB 해석이 각각 그것을 지난다** — 어긋나면 **둘 다 안 돈다**(각각 종료 1). **`POSTGRES_PORT` 가 없으면 아무것도 안 잰다**(자기 Postgres 를 쓰는 사람) |
| **`missing-database-hint` 가 없어진 컨테이너 이름을 권한다** | §3.8 | **닫혔다.** `docker exec wirebound-postgres …` → `docker compose exec postgres …`. 이름을 몰라도 되고 **자기 디렉터리의 컨테이너**를 고른다 |

#### 더한 것 — 열림

| 무엇 | 상태 |
|---|---|
| ✱ **compose 가 조용해지는 길이 있다 — 포트 충돌 뒤 한 번 더 치면 컨테이너가 *포트 없이* 뜬다** | 열림(**쟀다**). 첫 `up -d` 는 `Bind for 0.0.0.0:<포트> failed: port is already allocated` 로 시끄러운데, **그대로 다시 치면 종료 0 으로 `Started` 를 찍고 `Up (healthy)` 가 되며 `PORTS` 칸이 빈 칸이다.** 그 포트에 붙는 것은 전부 **먼저 잡은 워크트리의 컨테이너**다. **포트 검사가 이것을 못 잡는다**(두 값이 서로는 맞다) — 시끄럽게 만드는 것은 **DB 이름을 워크트리마다 가르는 것**이고 그래서 §3.7 의 그 메커니즘을 **절차에서 안 걷었다**(D4 판정). 오늘의 조치는 **문서**다: README §3.1·§6.3 이 *"`up -d` 뒤에 `PORTS` 칸을 보라"* 를 든다. **코드로 닫는 길은 안 정했다** |
| ✱ **옛 볼륨(`feat-p1-api_wirebound-pgdata`)을 새 이름으로 옮기는 일** | 열림. **메인 세션이 병합 때 한다.** 절차와 검증 방법을 보고 §10 이 든다 — **복사이지 이동이 아니고 옛 볼륨을 안 지운다.** **이 판이 안 돌려 봤다**(사용자 데이터라 손대지 않았다). 그 볼륨을 마운트한 컨테이너가 여전히 `feat-p1-api` 프로젝트 소유라는 §3.7 의 사실은 **그대로 선다** |

| ✱ **`.env` 값에 `$` 가 있으면 compose 가 경고를 낸다** | 열림(쟀다, 무해). compose 가 `apps/api/.env` 를 읽으므로 그 안의 `$` 를 펴려 하고 `The "…" variable is not set. Defaulting to a blank string.` 를 낸다. **compose 가 그 파일에서 쓰는 값은 `POSTGRES_PORT` 뿐**이라 결과는 안 바뀐다(종료 0). 비밀번호에 `$` 를 쓰는 사람이 나오면 그때 다시 본다 |

### 3.14 **잠금이 판정을 끄고, 계약에 사람이 읽을 축이 생겼다(2026-09-03)** — UI 점검 4차

> 브랜치 `fix/lock-abilities`(넷) · `feat/component-labels`(하나). **계획서를 안 만들었다** —
> UI 점검에서 나온 두 덩어리다.

#### 잠금 — 스테일 선택이 1차 방어의 유일한 구멍이었다

`structureAbilities(document, nodeId)` 가 **잠금을 아예 안 봤다.** `selectNode` 는 잠긴 노드를
거부하지만 **이미 골라 둔 선택은 `setLocks` 가 안 건드리므로**, 페이지를 열 때 자동 선택된
루트가 그대로 남아 **잠금 전에 눌러 둔 사람만 편집할 수 있는** 상태가 됐다.

**먼저 재고 갈래를 갈랐다**(스파이크). 진짜 `findLockConflict` 를 서버 대역으로 놓고 켜진
도구를 전부 눌러:

| 무엇을 건드리나 | 서버 | 화면에 보이는 것 |
|---|---|---|
| **형제 자리**(루트의 `안에 추가` · 비루트의 `안에/아래 추가`) | **200 으로 통과** | 아무 저항 없이 나간다 |
| **잠긴 서브트리**(삭제·위로·아래로 등) | **423** | 붙었다 사라지고 *"편집 1개가 취소됐습니다"* |

**판정: 전부 끈다.** `packages/schema/test/lock.test.ts` 가 *"구멍이 아니라 대가다"* 로
**«못 고르는 노드 = 툴바로 못 고치는 노드»를 등식으로** 못박았고 이 자리가 그 유일한
예외였다. 리뷰어가 **형제 갈래만 살린 판을 실제로 세워** 반증을 시도했고, 잠긴 루트에
*"고를 수 없는 줄 위에 켜진 버튼 하나"* 가 남는 것을 보였다.

고침은 `structureAbilities` 의 셋째 인자로 **스토어의 `lockedBy` 결과**를 받는 것이다 —
**판정을 새로 짓지 않는다**(`apps/web/src` 의 `findLockConflict` 호출은 스토어 한 자리
그대로). 툴바가 아니라 `useStructureCommands` 에서 끄므로 **단축키까지 막힌다**.

**고르개 넷을 한 자리로.** 패턴은 «꽂힐 자리»의 잠금, 프리셋은 «페이지에 남의 잠금이 하나라도
있으면»(op 이 `replace /root/children` 하나라 언제나 부딪친다 — **과차단이 아니라 서버와 같은
값**)이다. **둘을 한 값으로 묶으면 남이 아무 노드나 잡는 동안 패턴 삽입이 페이지 통째로 언다.**
타입 고르개까지 순수 함수 `visiblePicker(commands)` 하나가 답한다.

**막다른 길이 아니다**(재서 확인했다) — 페이지의 모든 자리가 잠기면 도구 아홉과 트리 줄
여섯이 다 꺼지지만 **모드 전환 둘과 다른 페이지 링크가 살아 있다.** 남겨 두었던 탈출구는
**누르면 423 을 받는 거짓 탈출구**였다.

#### 계약 — 사람이 읽을 축은 테마의 어휘와 다른 축이다

`ComponentDef` 에 `label`·`description`·`group` 을 **필수로** 더했다. **§6.11 의 «여섯»은
`ComponentDef` 의 필드 수가 아니라 렌더러가 내보내는 DOM 속성**이고(원문이 스스로 그렇게
적고 있다) 새 필드는 `data-wb-*` 를 하나도 만들지 않는다. `define.ts` 에 두 축의 표를 세웠다 —
**`variantFrom` 주석이 «속성»을 안 가른 탓에 이 질문을 처음부터 다시 하게 됐다.**

**이름 표는 이미 있었다.** `interaction/describe.ts` 의 `COMPONENT_NOUNS` 가 19종의 한국어
이름을 갖고 있었고 그 파일이 *"한국어 이름을 `ComponentDef` 에 두지 않았다"* 는 근거까지
적어 두었다. **두 벌로 두지 않고** `name` 을 `def.label` 에서 유도했다(`labelProp` 은 다른
축이라 리터럴). **정적 배열을 훑으므로 `installCatalog()` 와 무관한 것이 유지된다** —
`packages/exporter` 가 그것에 기대고, 리뷰어가 **빈 레지스트리에서 `describeNode` 가 실제로
«① 검색 버튼» 을 내는 것**과 **옛 표와 키·순서·이름·`labelProp` 이 19/19 동일**함을 기계
diff 로 확인했다. 옛 머리말의 설계 출처(§9·§8.2 셋과 `Placeholder` 의 *"미정 영역 영역"*
근거)도 카탈로그로 함께 옮겼다.

**갈래는 선언하고 어긋남은 케이스가 막는다** — 실행 시점에는 파일 경로를 모르지만 테스트는
안다(`catalog/*` 를 모듈째 import 해 대조).

**이 라운드가 다시 확인한 부류.** *"동작이 바뀌었는데 재는 것이 없다"* 가 또 두 번 나왔다 —
패턴·프리셋을 막았는데 **앞 판은 패턴 하나만 케이스가 있어 나머지 셋이 조용히 열려 있어도
안 죽었고**, 타입 고르개 가드가 **의도치 않게 다른 동작까지 바꿨는데** 그 자리를 잰 케이스가

### 3.15 **업그레이드도 프록시를 태운다(2026-09-03)** — UI 점검 5차

> 브랜치 `fix/vite-ws-proxy`. §3.14 이월 **F** 를 닫는다. **프로덕션 변경은 한 줄**이고
> 나머지 327줄은 전부 **그 한 줄을 잠그는 자**다 — 그 자가 세 번 뒤집혔기 때문이다.

#### 실시간이 개발 환경에서 통째로 죽어 있었다

`vite.config.ts` 의 `'/api'` 프록시에 `ws: true` 가 없었다. 서버의 실시간 라우트는
`/api/projects/:projectId/ws` 라 **컨텍스트 매칭은 통과한다** — 걸리는 곳은 그 다음
게이트다. vite 는 업그레이드를 **따로** 다루며 `opts.ws || 대상이 ws:/wss:` 를 한 번 더
묻고, 셋 다 거짓이면 **소켓을 닫지도 상태 코드를 쓰지도 않고 빠져나온다**(원문에
`break`·`continue`·`return` 이 아예 없다 — `if` 에 `else` 가 없는 `for…in` 이 그냥 다음
키로 간다. 리뷰어가 정규식 컨텍스트를 앞에 끼워 뒤의 `/api` 가 `101` 을 내는 것으로
**라이브 실증**했다).

| 잰 것 | 전 | 후 |
|---|---|---|
| 원시 업그레이드(5173) | **응답 바이트 0** · 타임아웃 · 소켓은 열린 채 | `101` + `joined`·`presence`·`locks` |
| 브라우저 `new WebSocket` | 8092ms `readyState=0` · **이벤트 0건** | `open @15ms` |
| api 로그의 그 요청 | **없다** | `host: localhost:5173` |
| 같은 시각 REST | `200` | `200` |

**이 실패 모양이 가장 나쁘다.** `onclose` 가 안 오므로 `connection.ts` 의 재연결 사다리도
안 탄다 — 화면은 *"붙는 중"* 에서 영원히 멈추고 **아무도 그렇다고 말하지 않는다.**
§3.14 가 고친 잠금 동작을 `pnpm dev` 로는 볼 수 없는 상태였다.

**`changeOrigin: false` 는 그대로 둔다.** http-proxy 가 업그레이드 헤더를 통째로 베끼고
(`setupOutgoing` 의 `Object.assign({}, req.headers)`) `changeOrigin` 이 손대는 것은
**`Host` 하나뿐**이라 세션 쿠키가 same-origin 으로 실린다 — D4 의 근거가 WS 에도 그대로
선다. **논증이 아니라 값으로 확인했다**: api 가 `host: localhost:5173` 을 **본 채**
`projectGuard('viewer')` 를 통과했다. 리뷰어가 음성 대조(쿠키 없음 401 · 비멤버 404)까지 세웠다.

**`ws: true` 하나로 끝난다.** 대상 규칙도 한 벌 그대로다 — vite 의 업그레이드 핸들러가 같은
`proxies[context]` 엔트리를 다시 꺼내 쓴다. 재연결도 그대로 산다: 서버를 죽였다 살리니
`+13905ms` 닫힘 → 500·1000·2000ms 백오프(끝 값 반복 — 계약대로) → **`+31594ms` 에 스스로
붙었다.** 기전은 `ws-incoming.stream` 의 `onOutgoingError` 가 `socket.end()` 를 부르는 것이다
— **`ws:true` 가 없을 때와 정반대다**(그때는 안 닫혀서 재연결이 안 탔다).

#### 자가 세 번 뒤집혔다 — 이 라운드의 본론

| 판 | 방법 | 뚫린 것 |
|---|---|---|
| 1 | 원문 정규식 `/'\/api':\s*\{([^}]*)\}/` | **거짓 빨강** — `ws: true` 앞에 객체가 오면 런타임은 `101` 인데 「ws 가 없다」고 죽고, **카나리아는 통과해서** 원인을 안 짚는다 |
| 2 | 손으로 쓴 중괄호 세기 | **거짓 초록 9.** 최악은 `'/api': { …, ws: false, todo: 'ws: true' }` 가 **20/20 초록**이다 — 설정이 실시간을 끄고 있는데 「켜져 있다」고 한다 |
| 3 | `resolveConfig` 로 **값**을 읽고 vite 의 매칭 규칙을 **옮겨** 적용 | **거짓 초록 4** — `bypass`·`configure`·`rewrite`·`configureServer`. 앞의 셋은 **임의의 함수**라 값으로도 못 읽는다 |
| **4** | **vite 를 실제로 띄워 업그레이드 바이트를 잰다** | 열셋이 다 죽는다 |

2판의 아홉은 중괄호 균형 문제가 **아니었다.** 주된 경로는 ⓐ 머리 정규식이 **첫 매치만 본다**
(같은 객체의 중복 키 — 뒤엣것이 런타임에서 이기는데 자는 앞엣것을 읽는다 · `preview.proxy` 를
`server` 앞에 둔 미끼 · 로그 문자열 안의 글자), ⓑ **`ws: true` 가 실행되는 자리인지 안 본다**
(`agent: { ws: true }` · `...(false ? { ws: true } : {})`), ⓒ `rewrite: /^https?:\/\//` —
**프록시 설정에서 가장 흔한 정규식 자리**인데 `stripComments` 가 `//` 뒤를 지워 `}` 를 없앤다.

3판의 옮긴 규칙 자체는 **충실했다**(리뷰어가 vite 6.4.3 원문과 대조). 그런데도 뚫린 것은
**자가 안 보는 옵션**이 남았기 때문이고, 그것은 파싱을 더 잘해서 닫히는 종류가 아니다.

**4판은 판정이 한 벌이다** — 스텁 상류(`node:http`) + 진짜 dev 서버(`createServer`,
`vite.config.ts` 그대로 · **대상 한 값만** 스텁으로) + 원시 업그레이드 바이트. 옮겨 온
`matchesContext`·`restEntry`·`upgradeEntry` 는 **지웠다**(§7.2 의 *"판정이 두 벌이면
갈린다"*). **값 읽기는 카나리아로 남겼다** — 라이브가 **왜** 죽었는지 가르는 것이 그것이고,
세 갈래가 각각 다른 문장으로 죽는 것이 그 값이다.

열셋이 죽고 **무관한 `'/uploads'` 엔트리에는 안 죽는다**(과민하지 않다). 파일 단독 **약 1.0초**,
5회 연속·5173 점유 중·동시 2회 모두 22/22. 막은 것 하나: http-proxy 가 첫 요청에서
`opts.target` 을 `url.parse()` 결과로 **제자리 바꾸고** 그 객체가 `config.server.proxy['/api']`
와 같아서, 값 스냅샷을 요청 **전에** 찍도록 옮겼다.

#### 이 라운드가 새로 세운 것

**«재는 척하는 케이스»가 이 저장소의 반복 부류의 뒤집힌 판이다.** 여태 넷은 *"규칙은 적혀
있는데 재는 것이 없다"* 였는데, 여기서는 **케이스가 있는데 아무것도 안 잠갔다** — 새 케이스
다섯 중 하나(`vite 가 묻는 조건을 만족한다`)는 단언 둘이 다른 케이스의 **글자 그대로 사본**
이고 셋째는 혼자 죽을 수 없어, 변조 열한 건 전부에서 **혼자 죽은 적이 없었다.** 지웠다.

**«거짓 빨강이면 안전하다»는 절반만 맞다.** 1판의 실패 방향은 거짓 빨강뿐이라 안전했고,
그것을 고치려고 손으로 파서를 쓴 순간 **거짓 초록이 가능한 설계로 바뀌었다.** 2판 워커는
자기 첫 판의 거짓 초록을 **스스로 잡아** 고치고 *"빗나가는 방향은 짧게 끊기는 쪽"* 이라
적어 뒀던 주석까지 실측대로 뒤집었지만, **한 갈래를 막은 것이 나머지 여덟을 막지 못했다.**

**같은 계정 두 탭으로는 잠금을 못 잰다.** `packages/schema/src/lock.ts` 가 *"연결이 아니라
사람이다(P3-3 D3)"* 라 같은 사람의 다른 탭은 서로를 안 막는다. `localhost` / `[::1]` 로
오리진을 갈라 쿠키 항아리를 둘로 만들고 계정도 둘 써야 한다 — **워커가 스스로 찾았다.**

#### B — 되돌리기의 판정 단위는 «고른 노드» 가 아니라 ops 다

`findLockConflict` 에 `lockPointers(ref.inverse)` 를 넣는다 — **판정은 여전히 한 자리다.**

프로덕션 15줄. `#startFrom` 이 후보를 정한 직후·**낙관 적용 전에** 묻고, 막힌 항목은

#### C·D·E — 세 자리 다 «앞 판의 말이 지금 사실이 아니었다»

**C.** 고른 것이 없어도 쓸 수 있는 조작 둘이 페이지 잠금에 함께 꺼지는데, 그때 상태줄은

고르라고 한다.** 새 칸을 위에 두되 **«고르면 된다»를 되풀이하지 않는다**(둘을 가르려면
새 판정이 필요하고 그것은 그 파일이 금지한다).

**D. «도달 불가»가 절반만 맞았다.** `-notice` 가 싣는 것 하나는 **사용자가 지은 프리셋
이름**이고 서버 상한이 1~60자·글자 종류 제약 없음이라 **공백 없는 라틴 60자가 오늘 들어온다.**
그리고 리뷰가 구현자의 근거를 **반증했다** — `word-break: break-word` 도 240px/0/0 으로
고친다(`overflow-wrap: break-word` 와 혼동했다). **값은 옳고 근거만 틀렸었다.**
`anywhere` 의 진짜 근거 셋: 선례 · **computed 가 `normal` 이라 값으로 안 읽힌다** ·
후손이 `word-break: normal` 로 되돌리면 min-content 가 **7.1px 대 426.1px** 로 갈린다.

**E. 근거 ②가 전제부터 거짓이었다.** *"잠금이 풀렸다 = 남이 편집을 끝냈다"* 가 아니다 —
**잠금은 «선택»으로 잡히지 «편집»으로가 아니다**(`use-node-lock.ts`). **반례를 그 함수의
케이스가 이미 들고 있었다.** 편집 0건으로 오갔다 오는 판이 흔하고 그때는 아무것도 안 낡는다.
**친 글자는 문서와 무관해 어느 판에서도 안 낡는다** — 그래서 이름칸은 살리고(리뷰가 아홉 줄
길을 실증했다) 타입은 «지금 꽂을 수 있는 것»에서 나오는 값이라 되돌아가는 성질을 유지한다.

#### G — **자를 네 판 지었고 셋이 뚫렸다. 다섯 판째는 짓지 않는다**

| 판 | 방법 | 결과 |
|---|---|---|
| `main` | 원문 읽기 | 거짓 빨강 1 · 거짓 초록 1 |
| 1판 | 라이브(값)만 | **거짓 초록 1** — 손으로 만든 대상 |
| 2판 | 원문 + 라이브 **둘** | **거짓 초록 7**(다섯은 `tsc` 도 통과) **· 거짓 빨강 2** |
| **3판** | **원문 파서를 버리고 «규칙의 답 대 런타임 대상»** | 일곱이 다 죽고 거짓 빨강 둘도 사라졌다 |

**2판이 뚫린 원인 한 줄이 이 라운드의 소득이다:** 자는 «이름»을 보고 라이브는 «값»을 보는데
**라이브가 심는 값이 `process.env.PORT` 라** 손으로 만든 `${process.env.PORT ?? '3001'}` 이
**둘 다 통과한다** — **두 자의 사각이 서로를 덮는 것이 아니라 겹친다.** 겹치면 자를 하나 더
얹어도 안 는다. 그리고 깊이 속이기는 **§3.15 와 같은 구멍**이었다(그때는 `stripComments` 가
`//` 를 먹었고 이번엔 `matchingBrace` 가 정규식 리터럴의 `}` 를 먹었다) — 3판이 세는 자를
없애 **부류째** 닫혔다.

**마지막 반증이 거짓 초록 다섯을 더 찾았지만 막지 않고 사각으로 적었다** — 전부 «런타임에
대상을 바꾸는 임의의 함수·미들웨어» 부류다(비-GET `bypass` · `middlewares.use` · `HOST`
덧씌우기 · 규칙이 모르는 env · import 별칭). **적어 둔 사각도 틀린 것을 고쳤다** — 2번은
거짓이었고(두 절 다 `PORT` 를 심어 **`pnpm dev` 조건을 아무도 안 잰다**), 1번의 «해롭지
않다»의 근거는 «그 기계»가 아니라 **«PORT 계약을 정확히 베꼈다»** 이며(베낀 복제도 `HOST` 를
하나 더 보면 해롭다), 3번의 원인은 컨텍스트 순서가 아니라 **표본이 URL 둘·GET 하나**다.

거짓 빨강 둘(NodeNext 확장자·네임스페이스 import — **행동 동일한 옳은 설정**)은 없앴다.
**«지워도 되는가»부터 쟀고 답이 «아니다»였다** — 계약을 정확히 베낀 복제는 값 대 값이 정의상
못 본다. 그래서 케이스는 남기고 **재는 방법만** 바꿨다: `resolveConfig` 의
**`configFileDependencies`**(esbuild 가 설정을 번들할 때 실제로 먹은 입력 파일 목록).
«import 만 하고 안 부르면 못 본다»는 **앞 판의 정규식을 변조본에 직접 걸어 재서** 새로 난
구멍이 아님을 확인했다.

#### 이 라운드가 세운 것

**«두 자를 겹쳐 두면 사각도 겹친다.»** 자를 더할 때 묻는 것은 «무엇을 더 잡나» 가 아니라
**«이 자의 사각이 저 자의 사각과 겹치나»** 다. 겹치면 하나 더 얹어도 안 는다.

**«자를 몇 판 지었나»가 멈출 때를 말한다.** 이 축은 네 판이고 셋이 뚫렸다. 다섯 판째 대신
**못 재는 것을 적었다** — 원래 G 는 *"거짓 빨강 하나"* 의 낮은 무게였고,
**거짓 빨강 하나를 지우려다 거짓 초록 일곱을 얻는 거래는 하지 않는다.**

**§3.15 의 «재는 척하는 케이스»가 두 번 더 나왔고 둘 다 처리가 갈렸다.** B 의 막다른 길
단언은 **혼자 죽지 않지만** 같은 변조가 46건을 더 죽이고 그중 §3.14 전용 케이스가 같은 것을
잰다 — **중복이지 헛돌지는 않아** 지우지 않고 **축의 주인을 이름으로 가리키게** 했다.
그리고 **검증할 수 없는 수(«변조 열일곱 건»)는 docstring 에서 뺐다** — 수를 두 자리가 각각
적으면 그것도 두 벌이다.

### 3.18 **우측 패널의 초안이 탭·페이지를 오가도 남고, 남의 자리에 안 쓰인다(2026-09-21)** — UI 점검 8차

#### 출발 — jsdom 값이 결함으로 올라왔다

§3.17 통합이 낸 결함(«페이지 설명» 초안이 탭·모드 전환에 사라진다)을 고친 워커가 곁가지로
*"속성 패널도 탭을 누르면 친 글을 잃는다"* 를 쟀다. **jsdom 값이었다.** jsdom 의 `fireEvent.click`
은 **포커스를 옮기지 않아 blur 가 안 난다.** 실제 Chrome 에서는 위젯 다섯 × 클릭 갈래 다섯,
