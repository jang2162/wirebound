## 계획과 달라진 것

- 페이지 JSON 의 `comments` 대신 `markers`(`{ nodeId, marker }`) — 런타임이 쓰는 것은 번호와 노드뿐이고 본문은 셸이 이미 그린다.
- 내보내기 런타임의 공개 서브패스 `@wirebound/exporter/browser`(web 의 견주기 케이스가 `mountExportDocument` 를 쓴다)를 더했다.
- api 는 런타임을 모듈 캐시(`readExportRuntime`)로 쥐고, 케이스 이음매로 `BuildAppOptions.exportRuntimePath` 를 둔다.
- 계획은 내보내기 행 읽기가 한 트랜잭션이라고 적었으나 그런 트랜잭션이 없다 — 테마는 `findProjectTheme` · `findThemePackage`(manifest 열) · `readThemePackageFiles` 로 따로 읽는다.
- 화면 모드는 `data-wb-screen` 속성이 아니라 클래스(`wb-export-screen`).
- 미리보기에 `themeWarning` 을 더하고 web 내보내기 패널에 «프로젝트 테마를 싣지 못했습니다» 한 줄.
- 워커로 넘기는 테마는 전송하지 않고 복제한다(메시지 `{ t: 'rows', part: 'theme' }`).
- PPTX 는 번들을 `job()` 안에서 늦게 짓는다(그리는 자가 없으면 안 짓는다).
- PPTX 화면에 코멘트 번호 마커가 함께 찍힌다 — 번들 페이지 그대로이기 때문이다(슬라이드의 오른쪽 칸이 같은 번호를 든다).
- **change 트리거:** 새 런타임은 renderer 와 같아 React `onChange` 가 서는 입력에서만 change 규칙이 돈다(캔버스와 같다). 옛 번들은 아무 요소의 네이티브 `change` 에도 돌았다.

## 이월

1. **pptx 미리보기는 `themeWarning` 을 싣지 않는다** — 패키지를 못 읽은 판(패키지가 불변 · 업로드 때 검증되어 실제로는 설 길이 거의 없다)에서 PPTX 화면이 말없이 기본 뷰다. html 미리보기만 말한다.
2. **`pnpm test:browser` 두 판을 한꺼번에 돌리면** 둘 다 `beforeAll` 에서 `dist/runtime.js` 를 덮는다 — 한쪽 api 가 쓰이는 중인 파일을 읽을 창을 재지 않았다.
3. **런타임 소스를 고친 뒤 개발 서버** — api 는 `runtime.js` 를 기동 때 한 번 읽어 쥔다. `apps/api/README.md` 내보내기 절에 «`build:runtime` 뒤 api 를 다시 띄운다» 를 적었다. 워크트리 부트스트랩(`CLAUDE.md` 「생성 직후 세팅」)의 `pnpm build` 가 이것을 이미 짓는다.
4. **실브라우저 판의 글꼴 원천이 기계에 기댄다** — 저장소에 글꼴 파일을 두지 않았다. 후보 셋이 없으면 케이스가 던진다.
