## H1 — 복원이 만든 겹친 잠금을 하트비트가 안 푼다(높음 · 새 길)

**판**(api · `restore-overlap.probe.ts`). 보라(owner) · 다혜(editor). 문서 S1 `[n_a[n_a1, n_x], n_c]` 를 스냅샷으로 얼리고 `PUT …/schema` 로
`[n_a[n_a1], n_x, n_c]` 로 바꾼다. 보라가 `n_a`, 다혜가 `n_x` 를 쥔다(겹침 없음). 보라가 S1 을 복원한다 — 이제 `n_x` 가 `n_a` 안이다. 둘이 같은 자리를
다시 보낸다(하트비트 — 웹은 편집마다 `refresh` 로 보낸다). 0.8s 뒤 다혜가 `n_x` 의 `props` 를 바꾸고 보라가 `n_a` 를 지운다(REST).

| | 복원 직후 서버 잠금 | 하트비트 뒤 | 거절 | 다혜 편집 | 보라 편집 |
|---|---|---|---|---|---|
| **E2**(3/3 같은 값) | `bora:n_a` · `dahye:n_x` | **`bora:n_a` · `dahye:n_x`(겹친 채)** | 없음 | **423** «사용자1님이 편집 중인 영역입니다» | **423** «사용자2님이 편집 중인 영역입니다» |
| main(3판) | 같음 | 한쪽만 남음(`dahye:n_x` 2판 · `bora:n_a` 1판 — 먼저 판정된 쪽이 거절됨) | 진 쪽 `[n_a]` 또는 `[n_x]` | 이긴 쪽 200 · 진 쪽 423 | 같음 |

**원인.** `ws/lock.ts` 의 `settle` — «남는다(지금 쥐었고 집합에 있다)»는 판정하지 않는다(머리말 「집합을 갈아 끼운다 — 새로 드는 것만 판정한다」).
그 표의 까닭 «쥔 동안 남의 겹치는 잠금은 서지 못했다»는 **문서가 그대로일 때만** 참이다 — 복원(`services/restore.ts`)은 잠금을 안 보고 문서를 통째로
갈아 끼워 이미 선 두 잠금을 조상/자손으로 만든다. main 은 같은 자리를 다시 보내면 판정을 다시 돌려(옛 표 «판정은 그대로 돌고 막히면 위 첫 줄이다»)
첫 하트비트에서 한쪽이 거절되고 겹침이 풀렸다. E2 에서는 둘 다 안 놓을 때까지 겹친 채 서고, 서로의 편집을 2차 방어(`lockConflictOfOps`)가 423 으로
막는다 — 다혜는 제가 고른 노드를 못 고치고 보라는 제 노드를 못 지운다.

**닿는 길.** 남의 편집은 2차 방어가 막으므로(아래 1(d)) 잠금 둘의 조상 관계를 바꾸는 것은 잠금을 안 보는 쓰기 — 지금은 스냅샷 복원이다. 복원은
owner 의 일이고 함께 고르는 사람이 있을 때 난다.

**고칠 방향.** 남는 노드의 판정을 «쥔 뒤 문서가 바뀌었을 때»로 되살린다 — 쥘 때 페이지 행에서 읽은 `head_seq` 를 집합에 적고, 다음 프레임의
`head_seq` 가 다르면 남는 것도 판정한다(같은 페이지에 남의 잠금이 없으면 문서를 안 읽는 비용은 그대로 · 200 개 하트비트는 편집마다 문서를 읽게 되니
«복원이 바꾼 페이지»로 좁히는 길이 더 싸다 — 복원이 그 페이지들의 잠금을 놓고 `locks` 를 알리면 화면은 «잡지 않은 선택»으로 간다). 이 판을
`ws-lock-set.test.ts` 에 케이스로 잠근다(복원 뒤 하트비트 → 겹친 잠금 0 · 한쪽 거절).

## H2 — 일괄 속성 칸에 친 글이 목록이 바뀌는 순간 사라진다(높음 · 새 길)

**판 A — 일부 거절**(실브라우저 · `b-lists-bulk.bprobe.ts` «4e»). 글 다섯. bob 이 `n_t02` 를 쥔다. alice 는 WS 내림 2.5s 지연(늦춘 덩어리 > 0)이라
그 소식을 모른 채 `n_t01 … n_t03` 을 사각형으로 고른다 → 속성 패널이 «Text 3개». 곧바로 «내용» 칸을 눌러 «새 글»을 친다(blur 전 칸 값 `새 글`).

| 거절이 닿은 뒤 | 값 |
|---|---|
| 고른 것 | `n_t01` · `n_t03`(기준 `n_t03`) — 거절된 `n_t02` 만 빠짐 |
| «내용» 칸 | **값 `''` · 자리표 «여러 값»** — 친 글이 없다 |
| 포커스 | **`BODY`** — 칸이 다시 서며 포커스를 잃었다 |
| 그 뒤 Tab | 나간 `patch` **0** |
| 서버(3.5s 뒤) | `n_t01:줄 1` · `n_t03:줄 3` — 아직 쥔 두 노드에도 안 갔다 |
| 하단 바 | «밥님이 편집 중이라 고를 수 없습니다»(거절의 통지뿐 — 친 글을 버렸다는 말은 없다) |

**판 B — 같은 사람의 다른 탭이 고른 것 하나를 지움**(«2» 의 `typingBulk`). alice 가 `n_b0` · `n_a0`(글 둘)를 고르고 «내용» 칸에 «일괄 글»을 친 채
alice 의 REST `PATCH` 가 `n_a0` 를 지운다(200). 0.9s 뒤 고른 것 `[n_b0]` · 패널은 하나 고른 판으로 바뀌어 칸 값 `n_b0`(원래 글) · Tab 뒤 나간 `patch` 0 ·
서버 `n_b0:n_b0` · 통지 없음.

**원인.** `panels/property-panel.tsx` 의 `BulkProperties` 가 위젯에 `key={widgetKey}`(`props.nodeIds.join(',')`)를 걸어 목록이 바뀌면 위젯을 새로
세운다(머리말 «앞 목록에 친 초안을 다른 목록에 커밋하지 않는다»). 초안은 `TextControl` 의 상태라 다시 서면 사라지고, 지워지는 입력에는 blur 커밋이
없다(포커스가 `BODY` 로 갔다). 목록이 바뀌는 길에 사용자가 안 한 것이 있다 — 일부 거절(`use-realtime.ts` → `dropFromSelection`)과 문서가 바뀔 때의
정리(`EditorStore` 의 `#withSelection`). 판 B 의 목록 줄임 → 하나 고른 패널은 다른 컴포넌트라 결과가 같다.

**main 대조.** main 에는 일괄 칸이 없다. 하나 고른 판에서 같은 사람의 다른 탭이 고른 노드를 지우면 친 글이 사라지는 것은 main 도 같다(I2) — 노드가
없어졌으니 갈 곳이 없다. H2 는 **아직 쥔 노드**에 갈 글이 사라지는 것이라 이 트랙이 연 길이다.

**닿는 길.** 판 A 의 창은 «고른 뒤 거절이 닿기까지» — 보통 한 왕복이지만 남의 `locks` 가 늦은 판(그 노드를 막 잡은 남 · 느린 망)에서 연다. 판 B 는
같은 사람의 두 탭 · 복원.

**고칠 방향.** 목록이 **줄기만** 했으면(빠진 것만 있고 새로 든 것이 없다) 위젯을 다시 세우지 않고 초안을 지켜 커밋 때 지금 목록에 쓴다(`commitEach`
는 이미 커밋 순간의 `nodes` 로 짓는다 — 다시 서지만 않으면 된다). 새로 든 노드가 있으면 다시 세우되 버리는 초안이 있으면 하단 바에 한 줄. 이 판을
`apps/web/build-test/multiselect.test.ts` 의 «늦은 목록 · 부분 거절» 꼴로 잠근다(거절 뒤 칸 값 · Tab 뒤 서버 두 노드).

## I1 — 지운 페이지의 잠금이 남는다(정보 · 원래 길)

`credential-release.probe.ts` «page-delete». 다혜가 `[n_a, n_b, n_c]` 를 쥔 채 owner 가 페이지를 지운다(204). 서버 잠금 · 남(viewer)의 마지막 목록
`[n_a, n_b, n_c]` 가 그대로다. main 도 하나짜리 `[n_a]` 가 남는다. 화면은 그 페이지를 떠나며 놓고, 아니면 TTL 이 걷는다. 집합이 남는 줄 수를 늘릴
뿐 길은 같다.
