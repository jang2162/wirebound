## 남은 것 · 사람이 할 일

1. **저장소 About 을 영어 한 줄로** — 위 점검 표 첫 줄의 명령.
2. **Docker 빠른 시작을 한 번 지어 본다** — 디스크를 비운 기계에서 README 「Installation」 을 그대로(`docker compose up -d --build` · `/health` · 로그인 · `SEED_USER_ADMIN=1` 이 관리자를 만드는지).
3. **`SEED_USER_ADMIN` 이 배포 템플릿에 없다** — 뿌리 `.env.example` · `docs/guides/deploy-docker.md` 「환경 변수」 표에 그 키가 없어, 문서대로만 한 사람은 첫 계정이 관리자가 아니고 초대 링크를 못 만든다(소스 길에서는 개발 안내가 `SEED_USER_ADMIN=1` 을 든다). 사용자 문서는 «그 줄을 직접 더한다» 로 적었다. 템플릿에 더하려면 `.env.example` 과 그 표를 함께 고치고 compose 인구조사 케이스(`apps/api/build-test/deploy-compose.test.ts`)를 돈다 — 이 트랙은 설정 파일을 안 건드렸다.
4. **npm 에 낸 패키지 README 는 다음 판까지 옛 앵커를 든다** — 저장소의 `packages/cli` · `packages/mcp` README 는 고쳤지만 0.1.0 의 tarball 에는 옛 링크가 실려 있다(그 앵커가 이제 없어 뿌리 README 의 맨 위로 간다).
5. `CHANGELOG.md` 를 둘지 — 릴리스 절차와 함께.
6. 띄운 서버 · vitest 는 내렸다(포트 3153 · 5174 리스너 0). 이 워크트리 개발 DB 에 예제 프로젝트 하나(`First design` · 계정 `pd@example.com`)를 남겼다 — 워크트리 폐기 때 볼륨과 함께 간다.
