# P10-1 보고 — **PPTX가 나온다.** 받는 쪽이 열었는데, 그 받는 쪽이 PowerPoint는 아니다

> 계획: `2026-08-17-p10-1-pptx-assembly.md` · 이월: `2026-08-17-p10-1-carryforward.md`

`wireb export --format pptx -o dir`이 **진짜 pptx 파일**을 떨어뜨린다. 페이지마다 슬라이드
한 장이고 코멘트와 상호작용 문장이 실린다. **화면 이미지만 아직 없고, 그 상태를 파일과 값이
둘 다 말한다.**

**짐작이 아니라 잰 것만 적는다.** 남이 잰 값에는 귀속을 붙였다.

---

## 1. T1 — 재라 여덟을 쟀다

계획서의 *"내가 안 재고 쓴 문장들"* 표다. **넷은 계획서의 예측과 어긋난다** — 아래 각 줄에
값과 근거를 적었다.

| # | 계획서의 문장 | 잰 값 |
|---|---|---|
| **1** | `BundleFile.content`를 바이너리까지 넓힐 수 있다 | **넓힐 수 있는데 안 넓혔다.** 넓히니 `pnpm typecheck`가 **34자리**에서 죽었고(7파일) **프로덕션은 하나뿐**이다(`apps/api/src/routes/export.ts`의 `zipBundle(bundle.files, …)`). 나머지 33은 전부 **케이스**이고, 고치는 일이 곧 *"케이스를 고쳐 넘기는 것"*이 된다. §2가 판정과 근거다 |
| **2** | PPTX가 그냥 zip이면 된다 | **그렇다.** ODF 같은 *"첫 항목이 `mimetype`이고 stored여야 한다"*가 **없다.** 참조 pptx(이 기계의 PowerPoint 16.112가 만든 것, 항목 634개)를 `zipinfo`로 재니 **`[Content_Types].xml`을 포함해 전 항목이 deflate**(`defS`)였다. 우리 것도 전부 deflate이고 받는 쪽이 연다 |

| **4** | 이 기계에서 pptx가 열리는지 잴 수단이 있다 | **반만 그렇다. §3 전체가 이 줄이다.** PowerPoint 16.112가 **설치돼 있는데 터미널에서 못 쓴다.** 대신 **macOS의 OOXML 구현 둘**(Spotlight·QuickLook)에게 먹였다 |
| **5** | CLI가 바이너리를 파일로 쓸 수 있게 넓힐 수 있다 | **그렇다.** `Io.files.write`를 넓히면 `typecheck` **2자리**만 죽고 **둘 다 `packages/cli/test/fake-io.ts`**다. **`packages/mcp`는 0 사망** — 가짜를 `@wirebound/cli/test-support`로 보긴 하지만 **파일을 안 쓴다.** 계획서 D7의 *"그것을 이제 `packages/mcp`도 본다"*는 구조로는 맞고 **값으로는 0**이다. 이어서 `FakeIo.fs`까지 넓히면 **17자리**(5파일)이고 그 판정이 §5.2다 |
| **6** | `describeInteraction`을 pptx가 그대로 부를 수 있다 | **부를 수 있는데 카탈로그가 필요하다 — 그리고 pptx는 그 자리를 물려받지 못한다.** 안 부르면 던지지도 않고 문장 개수도 그대로인데 *"② 목록이 **loading**로 바뀝니다"*가 된다(부르면 *"**로딩 상태**로 바뀝니다"*). **스모크에서 실제로 났다**(§4.2) |
| **7** | 슬라이드 노트가 잘리지 않는다 | **못 쟀다.** 노트 창을 여는 것이 PowerPoint이고 그것을 못 썼다(§3). Spotlight가 노트 글자를 **뽑는 것**은 확인했지만 그것은 *"파일에 들어 있다"*이지 *"사람이 다 본다"*가 아니다. 이월이 든다 |
| **8** | 미리보기가 pptx에 대해 말할 것이 있다 | **하나 있다 — `screenless`.** 나머지 넷(`duplicateTargets`·`brokenLinks`·`errors`·`themeId`)은 **HTML 번들의 성질이라 pptx 응답에서 뺐다.** 판정과 근거는 §5.1 |

## 2. D1 판정 — `BundleFile`을 넓히지 않고 `PptxPart`를 따로 뒀다

계획서 D1은 `BundleFile.content`를 바이너리까지 넓히는 것을 *"이 슬라이스의 첫 파장"*으로
봤다. **넓혀 보고 쟀다.**

| 무엇 | 값 |
|---|---|
| `BundleFile.content: string` → `string \| Uint8Array` | `pnpm typecheck` **34 사망**, 7파일 |
| 그중 **프로덕션** | **1** — `apps/api/src/routes/export.ts`(`zipBundle`이 `ZipEntry.content: string`을 받는다) |
| 그중 **케이스·헬퍼** | **33** — `apps/api/test/export-bundle.test.ts` 17 · `packages/exporter/test/runtime-bundle.test.ts` 7 · `bundle-size` 3 · `runtime-sentences` 2 · `bundle.test.tsx` 2 · `bundle-parity.test.tsx` 2 |

**판정: 안 넓힌다.**

- **값보다 뜻이 먼저다.** `BundleFile`은 §11.3 번들의 **뿌리 기준 산출물 파일**이고
  (`wirebound-export-<슬러그>/` 아래로 들어간다) `PptxPart`는 **파일 하나의 안쪽**이다.
  한 타입으로 두면 *"경로는 번들 뿌리 기준의 상대 경로다"*라는 그 타입의 계약 문장이
  한쪽에 대해 거짓이 되고, `ProjectBundle.files`에 pptx 파트를 실을 길이 **타입으로** 열린다.
- **모양은 D1이 요구한 그대로다** — 순수 함수가 `경로 → 바이트`를 내고 압축은 부르는 쪽이
  한다. `packages/exporter`는 zip을 모르는 채로 남았고, **그 성질을 지키는 자를 만들었다**
  (`test/public-api.test.ts`의 *"src가 압축 라이브러리를 부르지 않는다"* — 분모가 `src/**`다).

**넓힌 것은 하나다: `ZipEntry.content`**(`apps/api/src/services/export-zip.ts`). 거기는
*"압축에 들어가는 것"*이라는 더 넓은 물음에 답하는 자리라 글자와 바이트를 함께 받는 것이
맞다. 압축하는 코드는 여전히 **하나**다(`zipEntries` — `zipBundle`과 `zipParts`가 이름 짓는
규칙만 다르게 준다).

## 3. **PowerPoint를 자로 못 썼다** — D6의 어려운 자리

계획서 D6이 *"PPTX의 소비자는 PowerPoint이고 그것이 이 기계에 없다"*고 적었다. **그 문장이
틀렸다 — 있다.** 그런데 **자로 쓸 수 없다.**

### 3.1 관측

| 무엇 | 값 |
|---|---|
| 설치 | `/Applications/Microsoft PowerPoint.app` · `CFBundleShortVersionString` **16.112** |
| AppleScript `open POSIX file` | `-609 연결이 유효하지 않습니다` — 스크립트 도중 앱이 사라진다 |
| `open -a "Microsoft PowerPoint" <파일>` (LaunchServices) | 앱은 뜨는데 `count of presentations` = **0**, 창 **0개** |
| 화면에 뜬 것 | 창 이름 **`파일 액세스 부여`** · 버튼 `선택...` · `취소` — **샌드박스가 파일마다 사람의 선택을 요구한다** |
| `orca computer list-windows --app com.microsoft.Powerpoint` | `windows: []` · `isRunning: true` |

### 3.2 **대조군을 돌렸다 — 막는 것은 우리 파일이 아니다**

같은 절차를 **PowerPoint 자신이 만든 pptx**(이 기계에 있던 44KB짜리)로 돌렸다. **같았다** —
같은 대화상자, 같은 `presentations = 0`. 곧 **자동화가 막히는 것이지 우리 파일이 거절당하는
것이 아니다.** 이 대조가 없으면 위 관측은 *"우리 pptx가 PowerPoint에서 안 열린다"*로도
읽히는데, 그것은 거짓이다.

**지어내지 않았다.** 여기서 말할 수 있는 것은 *"PowerPoint로 재지 못했다"*뿐이고,
*"PowerPoint가 연다"*는 **이 슬라이스가 확인하지 못한 문장**이다. 이월이 그것을 든다.

### 3.3 대신 쓴 자 둘 — **둘 다 Apple이 만든 OOXML 구현이다**

| 자 | 무엇을 하나 | 어떻게 부르나 |
|---|---|---|
| **Spotlight** `/System/Library/Spotlight/Office.mdimporter` | 파일 종류를 알아보고 **슬라이드 안 글자를 뽑는다** | `mdimport -t -d3 <파일>` |
| **QuickLook** `/System/Library/QuickLook/Office.qlgenerator` | **첫 슬라이드를 그린다** | `qlmanage -t -s <크기> -o <디렉터리> <파일>` |

**우리 코드가 아니다.** 그래서 이 자는 *"우리가 만든 규칙에 우리가 맞춘 것"*이 아니다.
**그래도 PowerPoint가 열었다는 뜻은 아니다** — 그 한계가 이월의 첫 줄이다.

**이 기계에 없는 것:** LibreOffice(`soffice`) · `unoconv` · `python-pptx` · Keynote.

## 4. 무엇이 섰나

### 4.1 T2 — 최소 OOXML이 먼저 섰다 (D5)

**얹기 전에 열리는 것부터 세웠다.** 파트 목록·`[Content_Types].xml`·관계 파일을 **한 자리에서
함께 늘리는** `pptxPackage` 하나와, **닫힘을 재는 케이스 열다섯**(`test/pptx-package.test.ts`):
모든 관계의 타겟이 파트로 있는가 · 모든 파트가 콘텐츠 타입을 갖는가 · 모든 XML이 형태를
갖췄는가 · 슬라이드 수와 `sldIdLst` 항목 수가 같은가.

**그 순서가 실제로 값을 아꼈다.** T2에서 슬라이드 셋짜리가 열리는 것을 확인한 뒤에 코멘트·
문장·노트·이미지를 얹었고, 그 뒤로 *"안 열린다"*가 한 번도 안 났다.

**받는 쪽이 T2에서 이미 열었다:**

```
mdimport → org.openxmlformats.presentationml.presentation
           kMDItemTextContent 에 슬라이드 셋의 제목과 노트 전문
qlmanage → produced one thumbnail
```

**`unit` 프로젝트에 DOM이 없어서**(루트 `vitest.config.ts` — jsdom은 `web`에만 걸린다)
케이스가 XML을 읽을 자가 없었다. `test-support/xml.ts`에 형태 검사기를 뒀다 — **프로덕션은
그것을 안 부른다.**

### 4.2 **카탈로그를 설치한다 — 스모크가 찾아냈다**

`exportPage`는 `renderPageTree`를 지나며 `installRegistries()`가 불린다. **PPTX는 그리지
않으므로 그 자리를 물려받지 못한다.**

**실측**(`packages/exporter/dist`를 직접 부르는 스크립트에서 났다):

| 카탈로그 | 문장 |
|---|---|
| 없음 | `① 검색 버튼 클릭 시 ② 목록이 **loading**로 바뀝니다` |
| 있음 | `① 검색 버튼 클릭 시 ② 목록이 **로딩 상태**로 바뀝니다` |

**던지지도 않고 문장 개수도 그대로다** — 조용히 나빠진다. `packages/cli`의 `read/catalog.ts`가
`pageView`에 대해 **같은 값을 재서 같은 말**을 적어 두었고, 그 자리가 PPTX에서 한 번 더
났다. `exportPptx`가 `installRegistries()`를 부르고 `test/pptx-catalog.test.ts`가
`resetRegistry()`로 그 차이를 잰다(그 파일이 따로 있는 이유는 그 함수가 **프로세스 전역**을
비우기 때문이다).

**`apps/api`는 부팅에서 이미 설치한다**(`schema-setup.ts`) — 이 결함은 **라우트 밖에서만**
드러났고, 그것을 드러낸 것이 *"빌드된 것을 진짜 소비자에게 먹인다"*였다.

### 4.3 D4 — 두 벌이 되는 것을 지키는 자가 **둘**이다

`commentEntries`와 문장화를 **번들과 PPTX가 같은 함수로** 부른다. 그런데 문장화의 견딤 규칙
(*"깨진 자식만 걷어 내고 나머지 문장은 살린다"*)이 `bundle/shell.tsx` 안의 **사설 함수**여서
PPTX가 부를 수 없었다 — **다시 짜는 것이 가장 쉬운 길**이었다. `src/sentences.ts`로 올렸고,
빈 상태의 말과 §9 탭 이름은 `src/labels.ts`가 소유한다.

| 지키는 자 | 무엇을 | 왜 둘 다 필요한가 |
|---|---|---|
| `test/pptx-parity.test.ts` | **값** — 같은 페이지에서 번들 HTML(DOM으로 판)과 슬라이드 XML의 글자를 견준다 | 소스만 세면 **같은 함수를 부르면서 다르게 엮는 것**이 안 보인다 |
| `test/duplicate-census.test.ts` | **소스** — 부르는 **자리**의 수를 센다 | 값만 재면 복제가 **아직 값을 안 바꿨을 때** 안 보인다 |

**센서스의 첫 판은 반증됐다.** 앞 판은 *"부르는 **파일**"*을 셌고, 변이로 `sentences.ts`
**안에** 두 번째 문장화 함수를 심었더니 **13건 중 0건이 죽었다**(목록이 여전히
`['sentences.ts']`였다). **두 벌은 다른 파일에서만 생기는 것이 아니다.** 지금은 부름의
**개수**를 세고, 그 변이가 죽는다(§6의 `duplicate`·`duplicate-other-file`).

### 4.4 D2 — 이미지가 없다는 것을 **두 자리**가 말한다

| 어디 | 무엇 | 누구에게 |
|---|---|---|
| 슬라이드 안 | 화면 자리에 점선 상자와 *"화면 이미지가 실리지 않았습니다"* | **파일을 연 사람** |
| 값 | `ExportedPptx.screenless[]` → 라우트의 `GET .../export/preview?format=pptx` | **내려받기 전의 사람** |

한 자리만 두면 안 된다. 값만 내면 파일을 받아 연 사람이 **빈 자리를 형식의 성질로 읽고**,
슬라이드만 말하면 내려받기 전에 아무도 모른다.

**자리만 만들고 안 재지 않았다.** 진짜 PNG 바이트(1×1)를 넣어 `ppt/media/image1.png`로
실리는 것 · 슬라이드가 그것을 관계로 가리키는 것 · **바이트가 그대로인 것** · 비율을 지켜
자리 안에 드는 것을 케이스가 든다.

### 4.5 D3 — 배치가 §9와 같다

QuickLook이 그린 첫 슬라이드에서 눈으로 확인했다: 제목이 위, **화면 자리가 왼쪽**(점선
상자와 그 말), **코멘트와 상호작용이 오른쪽**. 바탕은 흰색이다 — **마스터에 `p:bg`를 안
적었더니 QuickLook이 회색으로 그렸다**(T2 실측). 받는 쪽마다 다른 색이 나오는 것 자체가 이
산출물이 피하려는 상태라 흰색을 못 박았다.

**노트가 전문을 받는다.** 슬라이드에 실린 것 전부 + 페이지 설명이다. 슬라이드는 넘치면
잘리므로 그 자리가 필요하고, 케이스가 **이중 적재**를 값으로 든다(슬라이드의 모든 글자가
노트에도 있는가).

**페이지 설명은 노트에만 싣는다** — D3이 슬라이드를 *"화면 · 코멘트 · 상호작용"* 셋으로 못
박았고, 설명은 문단이라 오른쪽 칸에 넣으면 코멘트를 밀어낸다. **버리지는 않는다.**

## 5. T5 — 배선의 판정 둘

### 5.1 **새 라우트가 아니라 `?format=`이다** (D7)

자원이 같다 — *"이 프로젝트의 내보내기"*이고 표현만 다르다.

| 근거 | 값 |
|---|---|
| 라우트를 늘리면 | `permission-matrix`·`actor-census`의 **라우트 표**가 형식마다 자란다. 형식은 앞으로도 는다 |
| 파일 이름 | **이미 URL에 없다**(P8-4 D7) — 그러므로 경로로 형식을 가르는 이득이 없다 |
| `wireb export --format` | **이미 있는 인자**(P9-3 D9)이고 한 줄로 이어진다 |

**기본은 `html`이다** — P8-4가 만든 URL이 인자 없이 계속 zip을 받는다. **모르는 값은 400**:
조용히 html로 떨어뜨리면 pptx를 부른 사람이 zip을 받고 그 상태는 파일을 열어 봐야 보인다.

**미리보기는 형식마다 다른 것을 말한다.** pptx는 `{ format, pages, screenless, fileName }`
이고 **`duplicateTargets`·`brokenLinks`·`errors`·`themeId`를 안 싣는다** — 그 넷은 HTML
번들의 성질이다(PPTX는 페이지 사이 링크를 안 만들고 §6의 테마도 안 쓴다). 그대로 실으면
**값이 있는데 그 값이 아무것도 안 가리킨다.** `format`을 되싣는다 — 화면이 어느 갈래를
받았는지 **키의 유무로 짐작하지 않는다.**

**수집을 `services/export-source.ts`로 올려 둘이 공유한다.** 같은 프로젝트를 같은 순서로
같은 이름으로 실어야 하고, 수집이 두 벌이면 그 갈림은 **두 파일을 나란히 열어 본 사람에게만**
보인다.

### 5.2 CLI — **이름을 지어내지 않는다**

pptx는 파일 하나이므로 이름이 필요한데, **CLI가 만들지 않고 서버의 `Content-Disposition`에서
읽는다**(P8-4 D7 — *"사람이 읽는 이름은 `Content-Disposition`과 미리보기의 `fileName`에만
있다"*). 지어내면 웹에서 내려받은 파일과 `wireb`가 쓴 파일의 이름이 갈리고, 사람은 그 둘이
같은 산출물인지 알 수 없다. **서버가 이름을 안 주면 코드 3으로 끊는다.**

**서버가 준 이름도 믿지 않는다** — 그 값이 곧 사용자의 파일 시스템 경로가 되므로 경로 마디가
있으면 끊는다(`readArchive`가 압축 안의 경로를 안 믿는 것과 같은 이유다).

**pptx를 풀지 않는다.** pptx도 zip이지만 그것은 **파일 하나의 안쪽**이다 — 풀어 놓으면 사람이
받아야 할 `.pptx`가 사라지고 `[Content_Types].xml` 같은 것이 디렉터리에 흩뿌려진다.

**형식 목록이 둘인데 같은 물음에 답하지 않는다.** `packages/cli`의 `EXPORT_FORMATS`는
*"이 `wireb`가 파일로 쓸 줄 아는 형식"*이고 `apps/api`의 것은 *"이 서버가 만들 줄 아는 형식"*
이다 — 형식마다 CLI가 하는 일이 다르므로(풀기 vs 파일 하나) 서버가 형식을 더해도 옛 `wireb`가
못 쓰는 것이 맞다. **둘이 같은 글자를 써야 하는 자리는 `?format=`에 실리는 값 하나**이고 그
자리를 재는 자가 양쪽에 있다. 이월이 이 손 맞춤을 든다.

### 6.1 **받는 쪽에게도 변이를 먹였다** — 그 자에 이빨이 있는가

위 표는 우리 케이스가 죽는지를 잰 것이다. **받는 쪽(macOS의 OOXML 구현 둘)이 무엇을 잡고
무엇을 놓치는지도 쟀다** — 변이를 심고 **`dist`를 다시 빌드한 뒤** `pnpm test:build`의
스모크를 돌렸다.

| 되돌린 것 | 스모크 사망 | 관측 |
|---|---|---|
| `presentation.xml.rels`의 슬라이드 관계 | **4** | Spotlight가 **글자를 하나도 못 뽑고** QuickLook도 못 그렸다(25.8초 만에 실패) |
| 마스터의 테마 관계 | **1** | QuickLook만 죽었다. **Spotlight는 글자를 그대로 뽑았다** |
| `[Content_Types].xml`의 슬라이드 `Override` | **0** | **둘 다 그냥 읽었다** |
| `&`·`<`·`>` 이스케이프 | **2** | Spotlight가 코멘트 본문을 못 뽑고 QuickLook은 **60초 상한에 걸렸다**(§6.2) |

**마지막 줄이 이 자의 한계다.** 규격은 그 `Override`를 요구하고 **우리 케이스는 그것을
잡는다**(`test/pptx-package.test.ts` — 1 사망). 받는 쪽 하나가 관대하다고 규격이 느슨해지는
것이 아니므로 **두 자가 서로를 대신하지 않는다.**

### 6.2 **깨진 pptx에서 QuickLook이 멈춘다 — 스모크에 상한이 없었다**

테마 관계를 지운 변이에서 `qlmanage`가 **실패하지 않고 매달렸다.** 사람이 죽일 때까지
**9분 27초**였고 그동안 케이스는 아무것도 말하지 않았다. **상한이 없으면 빨강이 아니라
정지다.**

`execFileSync`에 `timeout: 60_000`을 걸었다 — 정상 파일에서 이 둘은 1초 안쪽이다(쟀다).
**이 저장소가 15분 타임아웃으로 겪어 온 부류와 같다**(P9-5 이월의 *"워커 브리프"* 절).

### 6.3 **0 사망이 두 번 났고 둘 다 고쳤다**

1. **`duplicate` — 센서스의 자가 틀렸다.** 부르는 **파일**을 세면 같은 파일 안의 두 벌을
   못 본다. 부름의 **개수**를 세도록 고쳤고, 그 근거를 그 함수의 머리말에 값과 함께 적었다.
2. **`zip-bytes` — 오늘 라우트가 이미지를 안 싣는다.** 그래서 `export-pptx-route.test.ts`
   15건 중 **0건**이 죽었다. 바이너리 갈래를 누르는 자가 없었던 것이고,
   `export-zip.test.ts`에 `zipParts`를 **바이트로 직접** 누르는 케이스를 더했다(그 뒤 2 사망).
   **P10-2가 이미지를 실으면 라우트 쪽에서도 눌린다** — 그때까지 그 자리를 지키는 것은 이
   케이스다.

### 6.4 **끝에서 끝까지 한 번 — 진짜 서버와 진짜 `wireb`로**

케이스는 Fastify `inject`와 가짜 `io`로 양쪽을 따로 눌렀다. **사람이 실제로 쓰는 사슬은
그것이 아니므로** 한 번 통째로 돌렸다.

```
tsx 로 api 기동(3099) → signup · 프로젝트 · 메뉴 둘 · 페이지 둘 · 스키마 · 코멘트 · 토큰
→ .wirebound.json 과 자격 파일을 임시 HOME 에 → **빌드된 `wireb`**(packages/cli 의 bin)
→ wireb export --format pptx -o dist
```

| 무엇 | 값 |
|---|---|
| `wireb` 종료 코드 | **0** · *"…/dist 에 1개 파일을 썼습니다"* |
| 떨어진 파일 | `wirebound-export-p10-smoke-<…>.pptx` — **서버가 준 이름 그대로** |
| Spotlight | `org.openxmlformats.presentationml.presentation` · 코멘트 본문 · 상호작용 문장 · **조상 붙은 번들 이름** · **카탈로그가 붙인 한국어 prop 라벨**(*"로딩 상태"*) 전부 있다 |
| QuickLook | 첫 슬라이드를 그렸다 — **§9의 3분할 그대로**(제목 위 · 화면 자리 왼쪽 · 코멘트와 상호작용 오른쪽), 바탕 흰색, 자리에 *"화면 이미지가 실리지 않았습니다"* |

**이 사슬에서만 눌리는 것 셋:** 빌드된 `bin`이 실제로 뜬다 · `Content-Disposition`을 실제
헤더에서 읽는다 · **`apps/api`의 카탈로그 설치가 pptx 경로에도 실제로 걸린다.**

### 7.1 두 축으로 세었다 — **`main`을 별도 워크트리에서 함께 돌렸다**

계획서의 전역 제약이 지시한 그대로다. `main`은 최상위가 체크아웃하고 있으므로 **분리된
HEAD**로 새 워크트리를 만들었다(`git worktree add --detach … 0a55515`) — **최상위를 안
건드렸다.** api 테스트는 Postgres 하나를 공유하므로 **전부 순차로** 돌렸다.

| 축 | 실행 | 빨강 |
|---|---|---|
| **브랜치 · `pnpm test`** | **6** | **1** — 위 B5(첫 실행) |
| **브랜치 · `--project api`** | **5** | **0** |
| **`main`(0a55515) · `pnpm test`** | **3** | **0** |
| **`main` · `--project api`** | **3** | **0** |

**이 표본으로는 브랜치와 `main`을 못 가른다.** 브랜치의 1/6과 `main`의 0/3은 같은 비율에서도
나올 수 있는 값이다 — **원인을 단정하지 않는다.**

**갈림 하나가 이어진다.** P9-5 이월 §3.4가 *"빨강이 `--project api` 축에서 0회이고 비-api가
함께 도는 `pnpm test` 축에서만 났다"*를 남겼는데(ⓒ-1과 어긋나는 관측), **이 브랜치도 같은
모양**이다: `--project api` 축 **브랜치 5회·`main` 3회 모두 0**, 빨강은 `pnpm test` 축에서만.
**두 판이 같은 방향을 가리킨다** — 다만 사건이 둘이라 여전히 못 가른다.
