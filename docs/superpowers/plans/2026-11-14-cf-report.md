# CF 보고 — 코멘트 포커스 구현

설계 `docs/superpowers/specs/2026-11-13-comment-focus-design.md` · 계획 `docs/superpowers/plans/2026-11-13-comment-focus.md` 를 브랜치 `feat/comment-focus`(기준 main `e943cd14`)에 구현했다.

## 바꾼 것

- **Task 1** — `apps/web/src/shell/use-view-state.ts` 의 `stateShowingNode` · `apps/web/src/comments/comment-pointing.tsx`(`CommentPointingProvider` · `useCommentPointing`) ·
  `apps/web/src/routes/editor.tsx`(`EditorShell` 이 provider 를 깔고, `RightPanel` 이 «코멘트» 탭이 안 보이면 — 다른 탭 · 우측 접힘 — 가리킴을 걷는다).

## 결정

1. **`stateShowingNode` 에 노드 유무 검사를 두지 않는다.** 없는 노드는 어느 상태의 숨은 집합(`hiddenNodeIds`)에도 없어 첫 줄(«지금 보이면 안 바꾼다»)에서 이미 `{ change: false }` 로 끝난다. 계획의 «없는 노드 → 안 바꿈» 은 그 줄이 낸다.
2. **우측 접힘은 `RightPanel` 이 받는다**(계획은 «`EditorShell` 이 `layout.panelFolded` 면 `point(null)`»). 셸은 provider 를 까는 자리라 제 provider 의 훅을 못 부른다 — 접힘을 `RightPanel` 의 `folded` 로 내리고 «탭이 `comments` 이고 안 접힘» 이 아니면 걷는 이펙트 하나로 둘을 합쳤다.

### 혼자 죽는 변조 — Task 1(jsdom)

| 변조 | 무엇을 바꿨나 | 죽은 케이스(실행 수) |
|---|---|---|
| T1a | 첫 줄의 «지금 보이면 안 바꿈» 을 뗌 | «지금 상태에서 보이면 안 바꾼다» · «없는 노드 · 문서가 없으면» (6 중 2) |
| T1b | 기본(`current === null`)이면 안 바꿈 | «숨었으면 … 기본에서 숨은 `only` 노드» (6 중 1) |
| T1c | `hiddenNodeIds` 의 물려받음(`hidden ||`)을 뗌 | «부모가 숨으면 자식도 숨는다» (6 중 1) |
| T1d | 후보에서 기본(`null`)을 뺌 | «기본이 첫 후보다» (6 중 1) |
| T1e | 보이는 상태가 없으면 기본으로 | «어느 상태에서도 안 보이면 안 바꾼다» (6 중 1) |
| T1f | `document === null` 가드를 뗌 | **산다** (6 중 0) — `hiddenNodeIds(null)` 이 빈 집합이라 같은 답이다. 가드는 타입 좁히기로만 남는다 |
| P1a | `point` 가 안 세움 | «point 로 세운 노드를 읽는다» · «페이지를 옮긴 첫 렌더에서 걷힌다» (3 중 2) |
| P1b | 페이지가 바뀐 렌더에서 안 걷음 | «페이지를 옮긴 첫 렌더에서 걷힌다» (3 중 1) |
| P1c | provider 없을 때 값을 들고 있음 | «provider 가 없으면 늘 null» (3 중 1) |
| P1d | `point(null)` 이 안 걷음 | «point 로 세운 노드를 읽는다 · null 로 걷는다» (3 중 1) |
