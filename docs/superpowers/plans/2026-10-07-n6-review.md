# N6 좁은 반증 — 서버 장치 다섯(rv-n6)

브랜치 `feat/n6-server`(코드 커밋 `911ca101` 위 · 끝 `d69cf316`). 겨눈 것은 N6 이 세운 장치 다섯이다 — 하트비트 판정 도장 · 잃은 트리 쓰기를 성공으로 답함 · 늦은 커밋 지켜보기 · 외짝 서로게이트 400 · 지운 페이지 잠금 놓기. 고치지 않았다 — 변조는 백업(경로 전체 이름) → 맞은 수 1 → 돌림 → `cmp` 복원, 끝의 `git status` 깨끗 · `git diff --stat` 빔. 탐침은 `.coord/rv-n6/*.probe.ts`(테스트 글롭 밖 · 스크래치 vitest 설정 `vitest.probe.config.ts` 가 api 프로젝트의 `globalSetup` · `setupFiles` 를 싣는다 — 다시 재는 법: 워크트리에서 `pnpm vitest run --config ../.coord/rv-n6/vitest.probe.config.ts <파일 이름>`). 값은 탐침이 찍는 `R…` 줄이다. 덮개 잠듦: `pmset -g log` 의 마지막 Sleep 09:36 — 탐침 실행(15:37–15:54)과 안 겹친다.

## 한 줄

**높음 하나 · 낮음 넷 · 정보 몇.** 높음은 **늦은 커밋 지켜보기(새 장치)가 연 길**이다 — 지켜보기의 한 번 묻기가 연결을 **마감까지 남은 몫(최대 30s)** 쥐어, 확인 질의가 답을 못 받는 판에서 잃은 트리 쓰기 10 개가 **풀 10 칸을 전부 쥐고 다른 프로젝트의 요청까지 503** 이 되고(조건이 풀린 뒤에도 15s 넘게), 잃은 쓰기 하나가 **종료를 29.8s 붙잡는다**(3-a · 3-b). 지켜보기를 뗀 변조에서는 같은 판이 풀 0 · 200 · 0ms 다.

도장(1)은 **안전 축에 결함이 없다** — 판정을 바꾸는 바뀜은 전부 세대나 머리 번호를 올린다. 대신 **웹이 실제로 내는 하트비트(편집 직전 잠금 프레임)에는 거의 안 맞아**(1/10) L-101 의 비용이 웹 흐름에서는 그대로다(1-a · 낮음 · 원래 길). 잃은 트리 쓰기의 성공 답(2)은 거짓 성공 0. 외짝 서로게이트(4)는 경계값 16 × 입구 5 에서 거짓 거절 0 · 놓침 0. 지운 페이지 놓기(5)는 커밋 뒤에만 돌고 viewer 도 받는다.
