# GR 1부 보고 — 그리드 · 페이지네이션 바 설계

브리프: `.worktrees/.coord/brief-gr.md`(1부 — 설계만). 설계 문서: `docs/superpowers/specs/2026-10-25-grid-design.md`. 기준 main `665ddd27` · 브랜치 `feat/grid`. 코드는 고치지 않았다.

## 설계 요약 — 결정과 이유

| 물음 | 결정 | 이유 |
| --- | --- | --- |
| 노드 모델 | (다) 섞음 — 열 노드(머리 칸 + 셀 틀) × 행 노드(`repeat` · `kind` · `tone`, 필요할 때만 제 칸 `GridCell`) | 설계서는 «대표 몇 행 + 같은 꼴» 이다. 행 50 × 열 10 이 노드 22(1.7KB) — 행 × 칸 모델은 1061(82KB) · 트리 줄 1061 · 열 하나를 고치면 모든 행을 쥔다 |
| 되풀이 행 | 렌더러가 «사본» 으로 그린다 — 속성 · 표지 · 상호작용은 같고 `data-wb-id` 대신 `data-wb-copy-of` · 뷰 `nodeId` 에 꼬리 | 같은 노드가 DOM 에 여럿이면 `[data-wb-id]` 훑기(끌기 · 범위 선택 · 안내선)와 HTML `id` 가 겹친다. 원본은 «칸 없는 첫 데이터 행» — OD 의 «첫 행 셀» 표지 자리와 맞는다 |
| `List` | 걷고 새 `DataGrid` · `0032-list-data-grid` 가 다섯 자리를 옮긴다(노드 id 를 지킨다) · 문서 판 4 → 5(런타임 사슬 없음 — `0029` 의 길) | props · 구역 · 뷰가 다 바뀌어 남는 것이 이름뿐이고, 그 이름이 구조 트리 줄에 «List» 로 선다 |
| 새 타입 | `DataGrid` · `GridColumnGroup` · `GridColumn` · `GridRow` · `GridCell` · `Pagination`(여섯) | 열 묶음 깊이가 머리 단 — `colspan` · `rowspan` 을 사람이 안 적는다 |
| 셀 종류 | 지금 조각 그대로 · «No» 만 열의 `numbering` | 정한 것 A · 배지 · 색 글자는 `Chip` · `Affix` · `Placeholder` 로 대신 서고 9 를 막지 않는다 |
| 계약 | SDK 1.7.0 — `zoneItems` · `ViewItem.props` · `ViewItem.items` · `ViewItem.copy` · `gridLayout` · `GridProvider` · `useGridHead` · `useGridRow` · `placement` 자리 여럿 | 행의 `tr` 은 행 노드의 뿌리라 그리드 뷰가 칸을 끼울 수 없다 — 행 · 열 뷰가 그리드 뷰가 내린 배치를 읽는다 |
| 페이지네이션 | 새 `Pagination` 노드 — 그리드 «바닥» 구역 기본 내용 · 세 구역은 조각 | 그리드와 함께 움직이고 표지 · 상태 보임 · 모듈 단위가 된다. 조각 표지(«행 수 셀렉트 옆»)는 7단계가 4단계와 같은 자리에서 정한다 |
| 좁은 창 | 접지 않는다 — 표 칸만 가로 스크롤(테마의 몫 · 기본테마 640px 아래 고정 풀기) | 열 머리 · 병합 · 고정 열의 뜻이 남는다 |
| 에디터 | 받는 규칙(`accepts`)이 생기지만 부모를 바꾸는 입구 여섯은 이미 `fitRefusal` 을 지난다. 새로 짓는 것: 사본 → 원본 고르기 · 팔레트 «안» 거절 시 «뒤» · 행 줄 «한 행 떼어 내기» · «열 틀로 칸 짓기» | `git grep` 으로 센 지금 입구(설계 «8») |
| 나누기 | GR-A(모델 · 렌더 · 테마 · `0032` · 픽스처 86 파일 — L) → GR-B(에디터 입구 — M), 차례로 | A 만으로 4단계보다 크고 B 는 A 의 타입 · 사본 표지에 기댄다. A 만 병합해도 쓸 수 있다(복제 · 그리드를 골라 팔레트) |

## 구현 나누기

설계 문서 «11. 구현을 나누는 법» 이 차례 · 겹치는 파일 · 크기를 갖는다. 요지: GR-A 의 차례는 카탈로그 → 렌더러 사본 · 구역 자식 → SDK `gridLayout` · 뷰 · 판 → 기본테마 → 갤러리 · 템플릿 · `check` · `shots` · 개수 하한 → 찍는 판 표지 → `/llms.txt` · MCP 스킬 → `0032` → `List` 픽스처 → 실브라우저 판(사본 · 병합 머리 · 고정 열 · 넓은 표 390 · 720 · 1280 · 빈 구역 칸이 `tbody` 안 · 비용 판) → 정본. 6단계와 나란히 돌리지 않는다(카탈로그 · SDK · 기본테마 판 · 마이그레이션 번호 · 개수 하한이 겹친다).

## 게이트

코드 변경 없음 — 게이트 생략. 문서 두 파일만 커밋한다(`pnpm fmt` 는 md 를 안 본다 — `.oxfmtrc.json`).

## 남은 것

- 설계 승인(사용자 — Q1 ~ Q5). 승인되면 2부(GR-A · GR-B)를 코디네이터가 맡긴다.
- 설계가 «실브라우저로 잰다» 로 남긴 위험 셋: 빈 구역 칸(`div`)이 `thead` · `tbody` 안에 서는 판 · 고정 열 `left` 를 재는 레이아웃 이펙트가 내보낸 번들에서도 도는가 · 행 50 × 열 10 사본 그리기의 편집 지연. GR-A 가 먼저 잰다.

## 지침

| 무엇이 틀렸나 · 비었나 | 어느 문서 어느 절 | 넣을 문장 |
| --- | --- | --- |
| `git grep` 의 옵션을 패턴 **뒤**에 두면(`git grep -n -E '<식>' -A4 -- <경로>`) `-A4` 를 리비전으로 읽어 `fatal: unable to resolve revision: -A4` 로 죽는다 — 설계 문서의 «다시 재는 법» 명령을 그 꼴로 썼다가 돌려 보고 고쳤다. 오류를 내므로 조용히 틀리지는 않지만, 문서에 실린 명령을 안 돌려 보면 다음 사람이 그 자리에서 멈춘다 | `.ruler/` 의 wirebound 검증 소스 「수를 셀 때는 두 번 세고 표본을 열어 본다 — 덧붙임」(생성물 `AGENTS.md` 의 같은 절) | «**문서 · 보고에 싣는 셈 명령은 실은 그대로 한 번 돌린다** — `git grep` 의 옵션(`-A` · `-B` · `-c`)은 패턴 앞에 둔다. 패턴 뒤의 옵션은 리비전으로 읽혀 `fatal: unable to resolve revision` 으로 죽는다. 블록을 파일로 뽑아 `zsh <파일>` 로 돌리면 실은 글자 그대로 잰다.» |
