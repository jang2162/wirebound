## Task 7 — 비밀번호 api

### 먼저 센 것

- **다른 세션의 WS 를 끊는 길:** 로그아웃이 쓰는 `ws/notify.ts` 의 `closeSessionConnections`(그 세션의 연결을 룸에서 빼고 4403 으로 닫고 잠금을 놓는다)가 명시적인 길이다. 수동 길은 그 연결의 다음 프레임 · 방송의 `stillAllowed`(`sessionIsLive`)뿐이다. 비밀번호 바꾸기는 지운 세션 id 들(`DELETE … RETURNING id`)에 커밋 뒤 `closeSessionConnections` 를 부른다 — 로그아웃과 같은 길. 그 호출을 뗀 변조(M5)에서 다른 세션의 WS 는 1000ms 안에 안 닫혔다.
- **토큰으로 부르면:** 이 라우트는 `:projectId` 가 없어 토큰이 사람을 안 채운다(`auth/plugin.ts` 머리말 «토큰은 프로젝트 라우트에서만 사람을 채운다») — `requireAuth` 가 **401** 을 낸다(`/api/auth/tokens` 와 같은 답). 계획의 403 은 닿지 않는다(아래 «계획과 달라진 것»). `requireSessionUser`(403)는 그 규칙이 바뀐 날의 두 번째 겹으로 둔다.

## 계획과 달라진 것

1. **토큰으로 부르면 401 이다(계획 403).** 프로젝트 밖 라우트에는 토큰이 사람을 안 채운다 — `/api/auth/tokens` 가 같은 401 이고 README 가 그렇게 적는다. `requireSessionUser`(403)는 두 번째 겹으로 남겼다(`auth/session-only.ts` 머리말). README 줄 · 이 보고의 케이스가 401 이다. **C4 가 정본 「권한 모델」 을 고칠 때 «토큰으로 부르면 거절(401)»로 적는다.**
2. **트랜잭션 차례는 사용자 행 → 재확인 → 다른 세션 삭제다(계획: 재확인 → 갱신 → 삭제).** 계획의 차례는 같은 사람의 두 세션이 함께 바꿀 때 고리를 만든다(M6). 새 차례에서는 둘이 사용자 행에서 줄을 서고 뒤는 앞이 지운 제 세션을 재확인에서 보고 401 이다.
3. **틀린 지금 비밀번호의 봉투는 로그인 실패 상수 그대로**(«이메일 또는 비밀번호가 올바르지 않습니다»)이고, 이슈(`path: currentPassword` · `code: wrong-password` · «지금 비밀번호가 맞지 않습니다»)를 싣는다 — 웹은 이슈 코드로 가르고 제 문장을 그린다.
4. **비밀번호 절은 `account/password-section.tsx`**(계획 `settings/password-section.tsx`) — `settings/` 는 프로젝트 설정의 절들이다. `routes/tokens.tsx` 는 지웠다(`/tokens` 의 `Navigate` 는 `app.tsx` 한 줄).
5. **`/account` 의 화면 루트는 `.wb-shell-settings`** — 새 팔레트 루트를 세우지 않았다(`SCREEN_ROOTS` 그대로).
6. **설정 · 계정 머리는 `SessionMenu` · «프로젝트 목록» 글자 링크 그대로**(물음 Q1 의 답 — 로고는 C1 의 `BrandLink`). 멤버 api 메서드는 `projectId` 를 첫 인자로 받는다(계획의 꼴에는 없었다).
7. **멤버 절의 «나를 바꾸면»은 통지 길이 아니라 다시 읽기다** — 설정 페이지는 룸에 없다.
8. `projects/delete-confirm.tsx` 는 `settings/delete-confirm.tsx` 로 옮겼다 — 쓰는 자리가 위험 구역 하나다. 머리말의 «앱에 모달 선례가 없다(0)»는 C1 의 대화 상자가 들어오면 거짓이 되는 문장이라 «절 안의 인라인 입력»으로 고쳤다.
