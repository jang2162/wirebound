## 고친 모양 — 한 판정 함수 · 두 겹

- **`sameDrop`**(`src/edit/structure-drop.ts`) — 보인 자리와 다시 물은 자리가 같은가. 앞 · 뒤는 부모 · 차례 · 띠, «안» 은 부모 · 띠. 경로 층의 `holds`(보인 자리 다시 판정)와 끌기 장치의 놓는 순간 견줌이 같은 이 함수다. 트리 줄 끌기 · 캔버스 손잡이가 함께 쓴다(R2 «같은 판정 함수»).
- **놓는 순간 견줌(F1)**(`src/drag/use-pointer-drag.ts` 머리말 «놓는 답은 보인 답이다») — 부르는 쪽이 `sameDrop` 을 주면, 뗀 좌표가 마지막으로 물은 좌표에서 문턱(4px) 안일 때 다시 물은 답이 **지금 그린 표시**와 같은 자리일 때만 `onDrop` 한다. 다르면(표시가 없던 판 포함) 편집 0. 문턱 밖이면 다시 물은 답으로 놓는다.
- **다시 잴 때 다시 물음**(`refresh`) — 캔버스가 측정 이펙트와 같은 의존(문서 · 줌 · 폭 · 겹layer · iframe 크기 변화 `measureTick` · 창)으로 지은 `layoutKey` 를 손잡이에 내리고(`canvas.tsx` · `canvas-drag-handle.tsx`), 바뀌면 끌기 장치가 마지막 좌표로 다시 묻는다. 같은 자리면 새 상자로 다시 그리고 **다르면 표시를 걷는다** — 새 자리를 곧바로 그리지 않는다(멈춘 포인터 밑에서 표시가 뛰어 바로 뗀 판이 안 본 자리로 가지 않게). 걷힌 뒤 움직이면 새 자리가 선다. 끝 스크롤의 다시 물음은 사람이 미는 몸짓이라 새 답을 그대로 그린다(그대로 둠).
- **F2(«문서가 바뀌면 버림»)는 고르지 않았다** — 리뷰의 대조군 둘(«bob 이 아래 다른 노드의 글을 고쳐도 …» · «끄는 중 내 앞 편집이 리베이스돼도 …»)이 아래 게이트에서 초록이다.

## 브리프와 달라진 것

1. **F1 은 끌기 장치(`use-pointer-drag.ts`)에 들어갔다** — 경로 층의 `onOver` 는 «뗌의 다시 물음» 과 «움직임» 을 가르지 못한다(장치가 같은 `onOver` 를 부른다). 움직임 쪽에 같은 견줌을 걸면 띠 경계를 넘을 때마다 문턱만큼 표시가 꺼진다. 그래서 장치에 선택 옵션 `sameDrop` 과 `refresh` 를 더했다 — D1 보고가 «손대지 않는다» 고 적은 장치다. `sameDrop` 을 안 주면 장치는 그대로다 — **메뉴 트리(`panels/menu-tree.tsx`)는 주지 않았다**(아래 이월 3).
2. **R2 의 «안» 카드 판** — 첫 실행은 «안» 도 차례까지 견주는 `sameDrop` 이었고, 트리 «안» 카드 판이 빨강이었다(놓기가 버려져 편집 0 — `n_t3` 가 제자리인 뿌리의 n_t2 뒤). 리뷰 «3» 표의 «F1 이 부모 · 띠로 견주면 그대로 놓인다» 대로 «안» 을 부모 · 띠로 견주게 고쳤고, 이 고침이 R3 의 «고칠 방향» 과 같은 자리라 R2 커밋에 함께 들어갔다. R3 커밋은 케이스만 더한다.
3. **R1 표시 겹은 «다르면 걷음»** — 브리프의 «표시를 옛 좌표에 남기지 않는다» 는 «새 답을 곧바로 그림» 으로도 읽힌다. 걷는 쪽을 골랐다(머리말 «다시 잴 때 다시 물음» 의 까닭). MU3 이 그 차이를 잰다.
4. R4 · R5 는 같은 파일(`canvas-drop.test.ts`)이라 한 커밋이다(`git add -p` 를 못 쓴다).
5. 리뷰가 «[빨강]» 으로 세운 케이스 셋의 이름 · 머리말에서 «[빨강]» 을 걷고, 머리말의 «옛 판은 …» 을 고장 방식 문장으로 바꿨다(`docs/guideline/base/03-comments.md`).
