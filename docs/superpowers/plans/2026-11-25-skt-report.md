## 항목

### 03. 영역 사이 여백 (뿌리)

- 바꾼 것: `theme.css` 「골격」 의 «세로로 쌓인 노드» 묶음에 `[data-wb-component="Page"] > :not([data-wb-component="Section"], [data-wb-component="Text"])` 를 더했다 — 자기 아래 8px · 위 0.
- 결정: 페이지 뿌리의 구역(`Section`) · 글(`Text`)은 뺐다 — 구역은 바탕을 칠하는 띠(히어로 · 옅게)라 띠 사이에 8px 흰 틈이 서면 안 되고, 글은 `<p>` · 제목이라 제 문단 여백(1em)으로 쌓이는 문서다. 글까지 넣은 첫 판(`7a78e439`)은 뿌리에 글만 40 줄 쌓은 실브라우저 판 다섯 파일(`canvas-drop-below` · `comment-focus` · `editor-shortcuts-review` · `multiselect` · `n1-layout`)의 7 케이스를 죽였다 — 위 여백 0 이 긴 문서를 짧게 해 굴림이 안 서고 노드 사이 틈이 8px 아래로 접혔다(같은 파일을 2.0.0 테마로 돌린 판은 81/81 초록 · 글을 뺀 판도 81/81 초록). 끝 노드의 8px 은 남긴다(lms 는 `:last-child` 로 걷지만 이 테마는 «형제 구조로 가르지 않는다»). 팝업 몸통은 이미 그 묶음에 들어 있어 그대로다.
- 잰 값: 뿌리 사이 0 · 0 → 8 · 8.

### 02 · 08 · 10. 결과 머리 · 쪽 넘김 · 폼 제목

- 바꾼 것:
  - 그리드(`DataGrid`)를 결과 카드 꼴로 — 뿌리에 테두리 1px · 모서리 `radius.lg` · 흰 바탕, 머리줄(`head`) 최소 42px · 여백 6/12 · 밑선, 바닥(`footer`) 여백 8/12 · 윗선. 표(`table`)는 제 바깥 선을 안 긋고 끝 줄 아래 선을 걷는다(카드에 붙은 그리드에만 있던 두 규칙을 일반으로 옮겼다). 스크롤 조각이 첫 · 끝 조각이면(머리줄 · 바닥 없음) 그쪽 모서리를 뿌리 안쪽에 맞춘다(그림만 — 형제 셀렉터 허용 범위).
  - 카드에 붙은 그리드는 뿌리 테두리 · 모서리 · 스크롤 조각 모서리를 걷는다 — 바깥 선은 카드가 긋는다. 머리줄 · 바닥 꼴은 카드 밖과 같아 카드 전용 규칙(머리줄 · 바닥 · 표 선)은 걷었다.
  - `featured` 그리드의 주색 윗선은 표에서 뿌리로 옮겼다(표는 이제 선이 없다).
  - 머리 왼쪽(`headStart`)에 곧바로 든 본문 역할 `Text` 는 결과 제목 — h5(14px) · 굵게 · 짙은 글. 캡션 역할 글은 제 규칙(12px · 흐림) 그대로.
  - 등록 폼(`EntryForm`)을 카드 꼴로 — 상자 여백 0 · 조각 틈 0, 제목(`label`) 최소 42px · 여백 6/12 · 밑선 · 14px 굵게, 몸통(`row`) 여백 12px, 단추줄 여백 0 12 12.
- 결정:
  - **그리드를 늘 카드로 감싼다.** lms 의 목록은 늘 `.adp-card` 안이고, 감싸지 않으면 머리 · 쪽 넘김의 좌우 여백 · 선을 둘 기준 상자가 없다(쪽 넘김 오른끝 글이 표 오른끝에 붙는다). 카드에 붙은 판은 이미 이 꼴이었다 — 이제 카드 밖도 같은 꼴이다. 대가: 구역 · 탭 패널 · 팝업 몸통 · 폼 표 값 칸에 든 그리드도 둥근 테두리 상자가 되고, 머리줄이 있는 그리드는 높이가 조금 는다(머리줄 38 → 43px · 바닥 위 선 · 좌우 12px).
  - **«총 N건» 보조 글은 따로 꾸미지 않았다.** 그리드 머리에는 부제 조각이 없다(`headStart` · `headEnd` 구역뿐 — `packages/theme-sdk/src/default-views/data.tsx` 의 `DataGridView`). 글 노드 하나에 «검색결과 총 3건» 을 다 쓴 설계는 통째로 14px 굵게 선다. 보조 글을 12px 흐리게 하려면 설계에서 «총 N건» 을 캡션 역할 `Text` 로 나눈다(제 규칙이 12px · `textMuted` 다 — 팝업 판의 «총 3건 · 오류 1건» 이 그 꼴로 섰다).
  - 조회 폼 단추줄은 이미 lms `.adp-search__foot` 꼴(오른쪽 · 8/12 · 윗선 — 열을 정한 조회 폼)이라 고치지 않았다. 열을 안 정한 한 줄 조회 폼의 단추는 줄 끝 그대로다(윗선을 두면 필드 옆 단추 위에 선이 선다).
  - 조회 폼에는 제목 조각이 없다 — 접힌 판의 머리줄(`toggle`)은 이미 42px · h5 꼴이다.
- 잰 값(전 → 후): 그리드 테두리 0 → 1px · 모서리 0 → 4px · 머리줄 38 → 43px(단추 30 + 여백 12 + 밑선 1 — lms 와 같다) · 머리 여백 0 0 → 6 12 · 머리 밑선 0 → 1px · 표 위 선 1 → 0 · 머리 아래끝 − 표 위끝 0 → 0 · 표 아래끝 − 쪽 넘김 위끝 0 → 0 · 쪽 넘김 윗선 0 → 1px · 쪽 넘김 여백 8 0 → 8 12 · 범위 글 오른끝 안쪽 0 → 13px(테두리 1 + 여백 12) · 머리 제목 13px 400 → 14px 700 · 머리 제목 왼끝 안쪽 0 → 13px. 등록 폼 제목 높이 30 → 42 · 몸통 여백 0 → 12.

### 01. Select 모양

- 바꾼 것: 셀렉트의 값 · 안내 글 조각(`text`)을 한 줄로 — `flex: 1 1 auto` · `min-width: 0` · `overflow: hidden` · `nowrap` · 말줄임. 화살표(`::after`)는 글자 «▾» 대신 7×7 상자의 오른쪽 · 아래 변(1.5px · `textMuted`)을 45° 돌린 쉐브론.
- 결정: **`short` 셀렉트 폭(6em = 78px)은 그대로 둔다.** 안내 «- 전체 -» 는 말줄임 없이 다 든다(잰 값 `clipped: false`). «제목+내용» 은 짧은 칸에서 «제목+…» 로 잘린다 — 한 줄 · 30px 은 지키고, 그 칸을 `medium` 으로 바꾸는 것은 설계(프로젝트) 몫이다(시안 01 의 «프로젝트» 갈래와 같다). Input 의 `short` 와 폭이 같아야 조회 폼의 짧은 칸 둘이 한 꼴로 선다.
- 잰 값(전 → 후): 짧은 셀렉트 «제목+내용» 49px 2줄 → 30px 1줄(말줄임) · 안내 «- 전체 -» 49px 2줄 → 30px 1줄(안 잘림) · 긴 값 88px 4줄 → 30px 1줄(말줄임) · 보통 칸 30px 1줄 → 그대로 · 화살표 글자 «▾» → 빈 글 + 7×7 테두리 · 입력칸 30px(카나리아).

### 09. 팝업 틀

- 바꾼 것: 닫기(`close` 조각)를 26×26(`space.unit` × 6.5) 가운데 정렬 칸 · 표지 16px(h3 크기 — 본문 + 3px)로.
- 이미 lms `_popup.scss` 와 같던 것(안 고침): 제목줄 여백 12/16 · 제목 15px 굵게(h4) · 몸통 여백 12(몸통 `12 12 4` + 자식의 아래 8px) · 바닥 여백 10/16 · 옅은 바탕 #F3F4F6 · 윗선 · 오른쪽 · 틈 6 · 덮개 위 그림자 `0 12px 40px rgba(20,30,50,.24)`.
- 결정: **`semantic.header` 기본값은 `{semantic.canvas}`(#F3F4F6) 그대로 둔다.** lms 의 #F2F4F7 과 R 값 1 차이라 눈으로 안 갈린다. 리터럴로 바꾸면 «2.0.0 이 더한 토큰 가운데 글 · 바탕에 쓰이는 것은 옛 키의 참조다»(`system-themes/admin/test/admin.test.ts`)를 깬다 — 옛 판에서 `semantic.canvas` 를 어둡게 덮은 프로젝트가 판을 올리면 표 머리 · 팝업 제목줄만 밝은 #F2F4F7 로 남는다(`src/manifest.ts` 머리말).
- 닫기 표지 글자는 기본 뷰의 «✖»(U+2716) 그대로다 — 글자를 «✕» 로 바꾸는 것은 SDK 몫이라 이 트랙 밖.
- 팝업이 캔버스에서 페이지 틀 위에 겹쳐 그려지는 것은 시스템(레이아웃) 몫이라 고치지 않았다.
- 잰 값(전 → 후): 닫기 19.25×13 · 13px → 26×26 · 16px. 제목줄 · 제목 · 몸통 · 바닥 값은 그대로(위 목록).

### 11. 숫자칸 안내 글

- 바꾼 것: 숫자칸(`Input` `kind: number`)의 안내 글 조각(`[data-wb-placeholder]` — 기본 뷰 `TextPart` 가 값이 없을 때만 단다)에 `margin-right: auto` — 안내 글은 왼쪽, 값은 그대로 오른쪽(`justify-content: flex-end`).
- 잰 값(전 → 후): 안내 «예) 2026» 의 왼끝 안쪽 97.09 → 9px(테두리 1 + 여백 8) · 값 «120000» 의 오른끝 안쪽 9 → 9.

### 06. 가로 배치의 글 · 링크 기준선 — 안 고침

- 원인(잰 값 — «팝업» 의 `Flex` 행): `Text` 는 `<p>` 라 브라우저 기본 여백(1em = 13px)을 위아래에 갖고, `Link`(`<a>`)는 여백이 없다. `Flex` 의 `align-items` 는 기본 `stretch` 라 두 항목 모두 줄 위끝에서 시작하는데, 글은 여백 13px 아래에서 글자가 서고 링크는 0 에서 선다 — 링크 기준선이 글보다 13px 위(`baselineGap −13` · 글 위끝 13 · 링크 위끝 0 · 링크 상자 높이 45.5 = 줄 높이로 늘어남).
- 결정: **고치지 않는다.** 링크 쪽 상자만으로 닫는 길이 없다 — `align-self: center` 는 사람이 `Flex` 에 정한 정렬(시작 · 끝)을 링크만 어기고, 링크에 글과 같은 위아래 여백을 주면 글 없는 가로 행(링크만 늘어선 줄)이 26px 높아진다. 닫는 길은 둘이다: ① 가로 `Flex` 에 곧바로 든 `Text` 의 문단 여백을 걷는다(테마 — 이 트랙 밖의 판단: 지금 가로 행의 높이가 모두 26px 준다) ② 문장 속 링크(`Text` 안 인라인 링크 — 시스템, 시안 06 의 근본). 그 전까지 설계는 링크를 문장 끝 따로 줄로 둔다(시안 ② 의 안내와 같다).

## 남은 것

- **06 글 · 링크 기준선** — 고치지 않았다(위 «06»). 가로 `Flex` 에 곧바로 든 `Text` 의 문단 여백을 걷을지(테마 · 가로 행 높이가 모두 26px 준다), 문장 속 링크를 들일지(시스템)는 판단이 필요하다.
- **«총 N건» 보조 글** — 그리드 머리에 부제 조각이 없어 한 글 노드면 통째로 제목 꼴이다. 설계에서 캡션 역할 `Text` 로 나누거나, SDK 가 머리 부제 조각을 들이면 테마가 카드 부제와 같은 꼴로 건다.
- **`short` 셀렉트의 «제목+내용»** — 한 줄 말줄임(«제목+…»)으로 선다. 그 칸을 `medium` 으로 바꾸는 것은 프로젝트 몫.
- **팝업 닫기 글자 «✖»** — SDK 기본 뷰의 글자다(시안은 «✕»). SDK 몫.
- **`layout-guides` «남이 Flex 를 세로로 바꾸면 …»** — 부하에서 2.0.0 테마로도 4/16 빨강인 흔들림(위 «게이트»). 이 트랙 밖.
- 사용자 개발 DB 에 2.1.0 이 시딩되지 않았다 — 이 워크트리의 dev api 를 띄우지 않았다.
