## 바꾼 것

### 태스크 1 — 파서

- `packages/schema/src/comment-tokens.ts` — `parseCommentBody` · `formatCommentToken` · 타입 둘. 왼쪽부터 훑는 스캐너.
- 라벨의 맨 `[` · 줄바꿈은 토큰을 깨뜨린다(`[[x [A](wb:…)` 의 뒤 토큰이 산다). `formatCommentToken` 은 `\` · `[` · `]` 를 이스케이프하고 라벨의 줄바꿈을 공백으로 적는다.
- 코드값은 `encodeURIComponent` 에 `(` · `)` 를 더 감싼다(`encodeURIComponent` 는 괄호를 그대로 둔다).

### 태스크 2 — 풀기 · lint

- `resolveCommentTokens` · `commentTokenText` · `buildMarkerIndex` · `markerKey` · `commentTokenTargetText` · `COMMENT_TOKEN_BROKEN_TEXT`(«찾을 수 없음»).
- `buildMarkerIndex` 는 문서의 **모든 노드**를 담는다(번호 없으면 `marker: null`) — 번호 걷힌 노드가 «페이지 › 노드 이름» 으로 이어지려면 그 노드가 색인에 있어야 한다.

### 태스크 3 — api 번호 색인

- `GET /api/projects/:projectId/comments/index`(viewer) — `services/comment-index.ts` 의 `readCommentIndex`. 응답 `{ pages: [{ id, title, menuPath }], markers: [{ pageId, nodeId, marker, nodeName, firstComment }] }`.
- `markers` 는 코멘트 달린 노드 **+ 이 프로젝트 코멘트의 토큰이 가리키는 노드** — 번호 걷힌 노드(Review Focus 5)는 코멘트가 없어 앞 조건만으로는 빠진다.
- 못 올리는 문서(`migrateDocument` 실패)는 그 페이지의 노드만 빠진다 — 색인 전체를 400 으로 만들지 않는다.
- `commentTokenPages`(schema) — `targetedPages` 결과에서 `CommentTokenContext.pages` 를 짓는 한 벌.
- README 엔드포인트 표 한 줄 · `permission-matrix` 표에 «코멘트 번호 색인».

### 태스크 4 — 웹 패널 · 이동

- `comments/comment-index.tsx` — `ProjectCommentIndexProvider`(셸이 든 색인 · 공통코드 표와 같은 꼴) · `useCommentTokenContext(pageId)`. 다시 읽는 때: 코멘트 신호(`comments-changed` · `page-stale` · 다시 붙음) · `menu-changed` · `codes-changed` · 연 페이지가 바뀜.
- **열린 페이지는 스토어의 문서로 푼다**(서버 색인의 그 페이지 몫을 덮는다) — 내 재번호가 답 · 다시 읽기 없이 «#3» → «#1».
- `panels/comment-body.tsx` — `CommentBody` · `commentTokenHref`. 링크는 `<a href>` + 보통 누름만 `navigate`(새 탭 누름은 브라우저에). 끊김은 `<span>` + «찾을 수 없음». 색인을 못 읽은 동안은 대체 글만(끊겼다고 단언하지 않는다).

### 태스크 5 — `#` 자동완성

- `panels/comment-token-picker.tsx` — `useTokenPicker`(글 상자에 펴 넣는 속성 + 목록) · `hashQuery` · `tokenCandidates`(무리 다섯: 이 페이지 번호 · 페이지 · 다른 페이지 번호 · 공통코드 그룹 · 항목) · `filterCandidates`(이름 + 덧말 — 노드 이름 · 첫 코멘트 · 그룹 키 · 코드값). 목록은 `role="listbox"` · 상자는 `aria-expanded` · `aria-activedescendant`.
- 새 코멘트 상자 · 고치는 상자 둘에 붙였다. 조합 중에는 열지도(`compositionstart` ~ `end`) 고르지도(`isComposing` · 같은 구간) 않는다. Escape 는 그 `#` 를 «닫음» 으로 적어 다시 안 연다.
- `refreshCommentTokenLabels`(schema) — 달기 · 고치기 저장 직전에 산 토큰의 라벨을 지금 이름으로. 다시 적어 길이 한도를 넘으면 친 그대로 보낸다.
- 길이 한도 셈은 서버 검증과 같은 `string.length`(UTF-16)다.

- `BundlePage` · `PptxPage` 에 `id` · `menuPath` · `pageTitle` — 내보내는 페이지들이 곧 풀 자료다(`exportTokenBase`). api 의 `projectBundle` · `buildProjectPptx` 가 `TargetedPage` 에서 넘긴다.
- `CommentEntry`(comment) 에 `segments`(풀린 조각) · `text`(한 줄 — 끊김은 `대체 글 (찾을 수 없음)`). 번들 셸은 조각을 `<a class="wb-export-token">` · 끊김 `<span>` 으로, PPTX 는 `text` 를 싣는다.
- 닻: 페이지 장 코멘트 칸의 그 노드 첫 줄 `id="wb-marker-<노드 id>"`(`markerAnchor`) · «공통코드» 장의 그룹 `section` · 항목 `tr` 에 `codeAnchor`(`wb-code-<KEY>` · `wb-code-<KEY>--<값의 UTF-8 16진>`).
- 셸 CSS 의 토큰 규칙 셋은 `SHELL_CSS` 끝에 덧붙였다(`bundle-stateless-bytes` 의 «옛 글자가 앞에 그대로» 를 지킨다 — 허용 선택자에 `.wb-export-token…` 을 더함). «글» 페이지의 해시만 다시 지었다(그 페이지의 코멘트 줄에 번호 닻 `id` 가 붙음 · 머리말에 까닭).
- **`ExportRows` 에 칸을 더하지 않았다** — 페이지 id · 메뉴 경로 · 제목은 이미 행(`pages` · `menu`)에 있고 `assembleExportSource` 의 `ordered` 가 짓는다. 그래도 워커를 지나는 길을 라우트로 내려받은 zip · pptx 에서 쟀다.

## 결정

- **가져오기의 토큰 다시 잇기를 짓지 않았다.** 페이지 JSON 봉투(`PageJsonPage`)에 페이지 id 가 없어 계획의 «파일에 옛 페이지 id 가 있을 때만» 이 서는 판이 없다. 그리고 가져오기는 노드 id 를 다시 짓는다(`planPageImport` 의 `remapNodeIds`) — 설계 «들이는 입구» 대로 «끊김» 으로 남긴다. 같은 프로젝트의 산 페이지를 가리키던 토큰은 그대로 이어진다(`apps/api/test/page-import-tokens.test.ts` — 고치기 전에도 초록인 성질 잠금). 다시 이으려면 봉투에 페이지 id 를 싣는 판 변경이 먼저다(남은 것).
- MCP · `--json` 의 코멘트에 `text` 도 싣는다(계획은 `resolved` 꼴 하나) — 사람 출력과 같은 글을 `--json` 이 함께 내야 «사람이 읽는 판과 `--json` 이 같은 값» 이 선다.
- 번들 · PPTX 의 페이지 토큰은 **페이지 제목**(`pageTitle`)이다 — 번들의 `title` 은 조상이 붙은 번들 이름(`관리자 회원 상세`)이라 그대로 쓰면 설계 «풀린 모양» 과 갈렸다(라우트 케이스가 처음 잡았다).
- `#` 는 줄 머리 · 공백 · 여는 괄호 뒤에서만 연다(`a#b` 의 `#` 로는 안 연다). 친 글은 40 자 · 줄바꿈 없음까지 — 제목 · 이름의 공백은 받는다. 목록은 40 개까지.
- 렌더 꼴: 계획의 `<CommentBody body context onNavigate />` 대신 `projectId` 를 받아 `href` 를 스스로 짓는다 — 링크가 `<a href>` 여야 새 탭 열기 · 접근 이름이 선다.
- 남이 **다른 페이지**에서 한 재번호는 신호가 없어(`renumber` 는 `comments-changed` 를 안 낸다) 다음 다시 읽기(페이지 옮김 · 코멘트 신호 · 메뉴 · 코드)까지 옛 번호로 보인다 — 이동은 id 라 맞다. 서버에 신호를 더하지 않았다.
- 대상이 없는 끊김은 `commentTokenText` 에서 대상 없이 `대체 글 (찾을 수 없음)` — MCP 에도 끊긴 토큰의 id 를 싣지 않는다(쓸 데가 없다).
- 대상 글 꼴은 `page:<id>` · `comment:<pageId>/<nodeId>` · `code:<KEY>[/<인코딩한 값>]` — 토큰 원문의 `wb:` 를 떼고 첫 `/` 를 `:` 로.
- 같은 제목 판의 앞머리는 조상 메뉴 경로 전체(`관리자 › 상품 › 목록`).
- 번호 걷힌 노드는 같은 페이지여도 «페이지 › 노드 이름» 이다(설계 표 그대로).
- 정본 「lint 규칙」 줄을 태스크 2 에서 넣었다(계획은 태스크 8) — 위 까닭.
- 라벨 이스케이프에 `\[` 를 더했다(계획은 `]` · `\` 만) — 맨 `[` 를 라벨에서 받으면 앞선 `[` 가 뒤 토큰을 삼킨다.

## 남은 것

- **가져오기의 토큰 다시 잇기** — 페이지 JSON 봉투에 페이지 id 가 없어 짓지 않았다(«결정»). 잇려면 봉투에 `page.id` 를 싣는 판 변경(정본 「페이지 JSON」)이 먼저다.
- **남의 다른 페이지 재번호** — `renumber` 가 `comments-changed` 를 안 내 열린 탭은 다음 다시 읽기까지 옛 번호로 본다. 서버가 재번호 뒤 그 신호를 내면 닫힌다(코멘트 목록도 다시 읽게 된다 — 비용은 작다).
- 혼자 죽는 변조가 없는 케이스: jsdom «뷰 모드에서도 간다»(T4f 와 함께) · «토큰을 … 링크로»(T4h 와 함께) · exporter «표가 없는 번들의 코드 토큰은 끊김»(끊김 표지 변조와 함께) · cli/mcp 의 `resolved` 둘(T7b 둘 다) · `page-import-tokens`(성질 잠금 — 고치기 전에도 초록).
- 실브라우저 판은 dev 번들로만 쟀다(`EDITOR_STACK_BUNDLE=build` 판은 안 돌렸다 — 이펙트 순서를 바꾼 트랙이 아니다).
- «뷰 모드에서도 간다» · «토큰을 … 링크로(날 id 없음)» 는 혼자 죽는 변조가 없다 — 앞은 T4f, 뒤는 T4h 와 함께 죽는다(각각 이동 · 번호 걷힌 노드 축은 «다른 페이지 번호 토큰 →» · «끊긴 토큰은 …» 가 소유).

## 지침

- **무엇이 틀렸나:** 계획(`2026-11-11-comment-tokens.md`) 태스크 2 는 lint 규칙을 더하고 정본 「lint 규칙」 은 태스크 8 에서 고치라 적었는데, `packages/schema/test/lint-rules.test.ts` 가 표와 정본의 줄을 대조해 그 사이 빨강이다. **어느 문서 어느 절:** `docs/guideline/…` 가 아니라 이 저장소 `.ruler/wirebound/` 의 검증 덧붙임(«정본 설계서를 고친 트랙의 게이트는 …» 줄 근처). **넣을 문장:** «lint 규칙을 더하는 태스크는 그 커밋에서 정본 「lint 규칙」 의 줄을 함께 고친다 — `lint-rules.test.ts` 가 표와 정본을 글자로 대조한다. 계획이 정본 갱신을 뒤 태스크로 미뤘어도 그 줄만은 앞당긴다.»
