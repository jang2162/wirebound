# 워크트리 격리 구현 계획 — 포트 한 자리, DB는 워크트리마다

> **에이전트에게:** 태스크 단위로 실행한다. 각 태스크는 실패하는 케이스 → 최소 구현 →
> 통과 → 커밋의 순서를 지킨다.

**목표.** 워크트리를 여럿 띄워도 부딪히지 않고, **부딪히면 조용하지 않다.**

**사용자가 보고한 것:** *"여러 워크트리에서 서버를 올리면 컨테이너명이나 포트번호가 충돌
나는 경우가 있어."*

**코디네이터가 재서 갈래 넷을 찾았고 사용자가 둘을 판정했다.**

| 갈래 | 오늘 | 드러나는 방식 | 판정 |
|---|---|---|---|
| API 포트 3001 | `.env`로 바꾼다 | `EADDRINUSE` — **시끄럽다** | **`.env` 한 자리로 정하고 나머지가 따라간다**(사용자) |
| web → api 프록시 | `vite.config.ts`에 **3001이 박혀 있다** | B의 화면이 **A의 API에 붙는다** — **조용하다** | 〃 |
| Postgres 컨테이너 | 이름·포트 5433 고정 | 이름 충돌 — **시끄럽다** | 컨테이너는 **하나를 공유한다**(사용자) |
| DB 내용 | `DATABASE_URL`이 같으면 같은 DB | 한 워크트리의 마이그레이션이 **모두의 스키마를 바꾼다** — **조용하다** | **워크트리마다 DB를 가른다**(사용자) |

**스택.** `apps/web`(프록시) · `apps/api`(.env·문서) · 루트 설정 · `README.md` · `CLAUDE.md`.

---

## 전역 제약

- **워크트리 안에서만 작업한다.**
- **게이트는 넷이다.** `pnpm test` · `pnpm typecheck` · `pnpm build` · `pnpm test:build`.
  전부 0이어야 하고 **종료 코드를 파이프 없이 따로 찍어라.**
- **공유 자원 — 어기면 사용자의 데이터가 날아간다.**
  - **`docker compose down -v` 절대 금지.** 볼륨에 사용자의 프로젝트가 들어 있다.
  - **컨테이너를 새로 띄우지 마라.** 최상위의 것 하나를 쓴다(사용자가 그렇게 판정했다).
  - **포트 3001을 쓰지 마라** — 사용자의 dev 서버가 거기 떠 있을 수 있다.
  - **`wirebound`·`wirebound_test` DB의 내용을 지우지 마라.** 검증용 DB는 **새 이름**으로
    만들고 끝나면 지워라.
- **`git checkout --`을 쓰지 마라.** python 치환으로 심고 `finally`에서 원본 전문을 되쓴다.
- **0 사망이 나오면 그렇다고 보고해도 된다. 원인을 단정하지 마라.**
- **자를 구현 파일에 두지 마라.** **수를 산문에 적지 마라.**
- **설계 문서(`docs/superpowers/specs/*`)는 고치지 않는다.**
- **남이 잰 값은 귀속을 붙여 옮긴다.**

## 이 계획이 딛고 선 사실

| # | 사실 | 어디 |
|---|---|---|
| 1 | **`vite.config.ts`가 3001을 박아 두고 주석이 그것을 인정한다** — *"`PORT`를 바꾸면 이 대상도 함께 바꿔야 한다 — 자동으로 따라가지 않는다"* | `apps/web/vite.config.ts` |
| 2 | **vite는 포트를 자동으로 올려 뜬다**(`strictPort` 미설정). 그래서 **web끼리는 안 부딪히고**, 사실 1의 조용한 교차가 **더 잘 만들어진다** | 〃 |
| 3 | **`PORT`·`HOST`·`DATABASE_URL`이 전부 `.env`로 열려 있다** | `apps/api/src/config.ts` |
| 4 | **`TEST_DATABASE_URL`이 이미 환경변수로 열려 있다** — `process.env.TEST_DATABASE_URL ?? '…/wirebound_test'` | `apps/api/test/helpers.ts` |
| 5 | **`docker/postgres-init/01-test-db.sql`은 볼륨을 처음 만들 때만 돈다** — 새 DB는 그 길로 못 만든다 | `apps/api/README.md` |
| 6 | **`CLAUDE.md`가 오늘의 규칙을 적고 있다** — *"컨테이너를 워크트리마다 띄우지 않는다"*와 ***"api 테스트를 도는 작업끼리도 Postgres 하나를 공유하므로 동시에 돌리지 않는다"*.** 뒤엣것이 이 슬라이스로 바뀔 수 있다 | `CLAUDE.md` |
| 7 | **`README.md`가 방금 생겼고 §6이 *"막히는 자리"*다** — 이 슬라이스의 산출물이 거기 앉는다 | `README.md` |

## 확정한 결정

### D1. **포트는 한 자리에서 온다 — `apps/web`이 `apps/api`의 값을 읽는다**

사실 1·2다. 사람이 두 자리를 맞추는 구조라 **어긋나는 것이 정상이고, 어긋나면 조용하다.**

- **판정: `apps/api/.env`의 `PORT`를 `vite.config.ts`가 읽어 프록시 대상을 만든다.**
- **셸 환경변수가 이기게 하라** — `apps/api`의 `--env-file-if-exists`가 이미 그 결이다
  (파일이 있어도 셸에 있는 값을 안 덮는다). **두 실행자가 다른 답을 내면 안 된다.**
- **새 런타임 의존을 들이지 마라.** Node 22.9의 수단으로 되는지 재라(**재라 #1**).
  `dotenv` 같은 것을 들이려면 근거를 적어라.
- **값이 없으면 오늘과 같다**(3001). 케이스가 그것을 든다.
- **`vite.config.ts`의 그 주석이 이제 거짓이 된다 — 함께 고쳐라.**

### D2. **DB는 워크트리마다, 컨테이너는 하나**

사용자가 그렇게 판정했다.

- **`DATABASE_URL`의 DB 이름만 워크트리마다 다르게 한다.** 컨테이너·포트 5433은 그대로다.
- **그 DB를 만드는 절차가 필요하다**(사실 5 — init 스크립트로는 안 된다). **한 줄로 되게
  하고 문서가 그것을 든다.**
- **마이그레이션이 워크트리마다 따로 돈다는 것**과 **데이터도 따로라는 것**을 문서가 말해야
  한다 — 사용자가 그 대가를 알고 골랐다.

### D3. **테스트 DB도 가른다 — 사실 4가 그것을 거의 공짜로 만든다**

**`CLAUDE.md`의 *"api 테스트를 동시에 돌리지 않는다"*가 이 슬라이스로 풀릴 수 있다.**

- **먼저 재라(재라 #3):** 오늘 두 워크트리가 `pnpm test`를 동시에 돌리면 **무엇이 깨지는가.**
  `apps/api/README.md`가 *"`revisions-concurrency.test.ts`가 `projects`·`users`를 범위 없이
  지운다"*고 적었는데 **코디네이터의 grep은 `DELETE FROM`을 못 찾았다** — 다른 꼴로 적혀
  있을 수 있다. **재고 값을 적어라.**
- **가르기로 하면**: 워크트리마다 `TEST_DATABASE_URL`이 다르고, `global-setup`이 그 DB에
  마이그레이션을 올린다. **그 DB가 없으면 무엇이 보이는가**를 재고, 안 보이면 **보이게 하라**
  (사실 5의 함정과 같은 부류다 — 이유를 알기 어려운 접속 에러).
- **비용이 크면 안 해도 된다.** 다만 **판정과 근거를 적고 `CLAUDE.md`의 그 줄을 그대로 두어라.**

### D4. **조용한 것을 시끄럽게 만든다**

D1·D2가 구조로 막지만 **사람이 값을 잘못 적는 길은 남는다.**

- **서버가 뜰 때 자기가 어느 포트에서 어느 DB를 보는지 말하게 하라.**
- **vite가 뜰 때 프록시 대상을 말하게 하라.**
- **두 터미널을 나란히 놓은 사람이 눈으로 가를 수 있어야 한다.** 그것이 이 결정의 전부다 —
  **DB 이름을 로그에 찍을 때 자격 문자열을 통째로 찍지 마라.**

### D5. **규칙이 바뀌면 `CLAUDE.md`를 고친다 — 두 벌을 만들지 마라**

사실 6이다. 이 슬라이스가 워크트리 규칙을 바꾼다.

- **`CLAUDE.md`의 *"생성 직후 세팅"* 절과 병렬화 절을 새 사실에 맞춰라.**
- **`README.md`는 설치·운영의 길이고 `CLAUDE.md`는 에이전트의 규칙이다.** 같은 문단을 두 곳에
  적지 말고 **한쪽이 소유하고 다른 쪽이 가리켜라**(README §6이 *"막히는 자리"*를 소유한다).

### D6. **되돌릴 수 있어야 한다**

- **오늘의 사용자가 아무것도 안 바꿔도 지금처럼 돌아야 한다.** `.env`를 안 고친 사람이
  깨지면 그것은 실패다. **케이스가 그 기본값을 든다.**

## 재라 — 내가 안 재고 쓴 문장들

| # | 문장 | 어디서 왔나 |
|---|---|---|
| 1 | **새 의존 없이 `vite.config.ts`가 `apps/api/.env`를 읽을 수 있다** | Node 22.9에 그런 수단이 있다고 **기억**한다. **D1이 걸린다** |
| 2 | **셸 환경변수를 이기게 하는 것이 `--env-file-if-exists`와 같은 결이다** | README가 그렇게 적었다. **vite 쪽에서도 같은 순서가 되는지 안 쟀다** |
| 3 | **두 워크트리가 `pnpm test`를 동시에 돌리면 깨진다** | `apps/api/README.md`가 그렇게 적었는데 **내 grep은 `DELETE FROM`을 못 찾았다.** D3 전체가 걸린다 |
| 4 | **`docker exec`로 DB를 한 줄에 만들 수 있다** | 추론이다. **권한·인코딩·소유자를 안 쟀다** |
| 5 | **vite가 포트를 자동으로 올린다** | 설정에 `strictPort`가 없는 것만 봤다. **실제로 올려 뜨는지 안 쟀다** |
| 6 | **`.env`를 안 고친 사람이 안 깨진다** | D6이 그렇게 되도록 정했지만 **안 쟀다** |

## 계획이 재지 않은 것

- **컨테이너를 워크트리마다 띄우는 길** — 사용자가 안 고른 선택지다.
- **포트 자동 배정** — 사용자가 안 고른 선택지다.
- **`Dockerfile`·배포** — 미결 장부가 소유한다.
- **미결 장부의 나머지** — T7이 갱신하되 닫지 마라.
