## 코디네이터 판단

### ① 더블클릭 넣기 (ub)

- 컴포넌트 탭 · 모듈 탭 카드 몸통의 **더블클릭이 «넣기» 와 같은 넣기를 한 번** 한다. 홑클릭은 지금처럼 넣지 않는다. 키보드는 그대로.
- 자리는 «넣기» 단추와 같은 판정이다(`palette/palette-add.ts` — 방금 넣은 것 뒤 규칙 포함).
- 넣기 단추의 더블클릭 삼킴(`DOUBLE_CLICK_MS`)은 그대로 둔다 — 단추를 두 번 눌러 둘이 들어가는 일이 다시 생기지 않는다.

### ② 페이지 정보 입력 스타일 (ub)

- 편집 · 뷰 모드의 «페이지 정보» 탭에서 셸 입력 스타일이 안 먹은 요소를 실브라우저로 찾아(스크린숏 · 계산된 스타일), «속성» 탭 입력과 같은 꼴로 맞춘다.
  찾은 요소 목록과 고치기 전 · 뒤 스크린숏 경로를 보고에 적는다.

### ⑥ 페이지 JSON 내보내기 모달 (ub)

- 페이지 줄 `…` 의 «JSON 내보내기» 가 곧바로 파일을 받는 대신 **모달**을 연다: 읽기 전용 글 상자(지금 파일과 같은 JSON) · «클립보드에 복사» · «파일로 받기» · «닫기».
- 읽는 동안은 상자에 «불러오는 중», 실패는 모달 안 문장. 파일 이름 · 내용은 지금 판과 같다. 복사 성공 · 실패를 모달 안에 짧게 말한다.
- 모달은 셸의 기존 대화 상자 꼴(`apps/web/src/shell/shell-dialog.tsx`)을 따른다.

### ③ 컴포넌트 탭 (ct)

- 편집 모드 우측 탭 «속성» 의 이름을 **«컴포넌트»** 로. 탭 안은 묶음 둘 — **«속성»**(지금 속성 패널의 내용 전부) · **«코멘트»**(고른 노드의 코멘트).
- «코멘트» 묶음: 고른 노드에 달린 코멘트 목록(«코멘트» 탭과 같은 데이터 · 같은 줄 꼴 — 한쪽에서 달거나 고치면 다른 쪽도 같다). 없으면 빈 문장과 새 코멘트
  상자. 있어도 새로 달 수 있다. 고치기 · 지우기 권한은 «코멘트» 탭과 같다. 초안은 탭을 오가도 남는다(`PanelDraftsProvider`).
- **«코멘트» 탭은 그대로 둔다**(사용자 결정).
- **캔버스에서 노드를 누르면(고르면) 우측 탭이 «컴포넌트» 로 바뀐다.** 구조 트리 줄 누름 · 키보드 고르기는 탭을 안 바꾼다(요청이 «화면에서 클릭» 이다).
- 뷰 모드는 그대로(«컴포넌트» 탭 없음 — 지금 «속성» 탭도 없다).

### ④ 그리드 행 «기본 / 커스텀» (gr)

지금 꼴: 행(`GridRow`)이 칸(`GridCell`)을 안 가지면 열의 셀 틀을 되풀이하고, 칸을 가지면 제 칸을 그린다. 요청은 이것을 행 옵션으로 드러내는 일이다.

- 행 속성에 **«행 내용: 기본 / 커스텀»** 을 둔다. 기본 = 셀 틀을 되풀이(첫 행과 같은 꼴). 커스텀 = 제 칸.
- **첫 행(행 구역의 첫 `GridRow`)은 옵션을 안 보이거나 꺼서 보인다**(까닭 문장). 첫 행은 늘 기본이다.
- 기본 → 커스텀: 열의 셀 틀을 그 행의 칸으로 **베껴 넣어** 같은 모양에서 고쳐 나가게 한다. 커스텀 → 기본: 제 칸을 걷는다 — 칸에 내용이 있으면 확인을 받는다.
- 반복 행 표(`DataGrid:repeatRows`)에서 행을 하나 더 두기 쉬운지(행 추가 입구)를 본다. 없으면 보고에 적는다.
- 판(옵션을 prop 으로 둘지 · 칸 유무로 셈할지)은 워커가 grid 설계(`docs/superpowers/specs/2026-10-25-grid-design.md`)와 견줘 정한다. 지금 문서에 첫 행이 제 칸을 가진
  판(합계 행 등)이 있으면 그 판을 깨지 않는 쪽으로 — 갈림이 크면 묻는다.

### ⑤ 트리 (tr — gr 뒤)

- `Tree` 의 `items: string[]` + `depth` 를 **항목마다 자식을 갖는 중첩 목록**으로 바꾸고, 속성 편집은 구조 트리 · 메뉴 트리처럼(항목 더하기 · 하위로 · 들여쓰기 ·
  내어쓰기 · 순서 · 이름) 짠다. 기존 문서는 마이그레이션으로 옮긴다. 세부는 ④ 병합 뒤 브리프에서 정한다.
