## 결정과 이유

- **상태 설명 한도 2000 · UTF-16 단위** — 페이지 설명 · 코멘트와 같은 수 · 같은 단위(입력 칸의 `maxLength` 가 세는 단위)라 한 규칙이다. 빈 글 ·
  보이는 글자 없는 글은 봉투가 거절한다 — «설명 없음»은 칸이 없는 판 하나다(화면은 비우면 `remove`). 짝 없는 서로게이트는 거절(`jsonb` 가 500 으로 죽는다).
  줄바꿈 · 방향 제어는 페이지 설명처럼 받는다.
- **상태 보임 깊이 표시 — 이름 앞 `›` 를 깊이만큼**(`aria-hidden` — 접근 이름은 이름 그대로). 상태 단추가 줄을 바꿔 흐르므로 들여 쓰기로는 깊이가 안 보인다.
  라디오는 `role="radio"` 단추 셋(← → · Home · End 로 옮겨 고른다 — 셸의 탭 줄과 같은 `rovingStep`).
- **페이지 이름 — 설명과 같은 저장 장치를 일반화했다**(`page-description.tsx` 의 `useMetaWrite(field)` — 칸 셋 `SLOTS` · 말 `WORDS`만 갈린다). 요청은 메뉴
  트리의 이름 변경과 같은 `PATCH …/pages/:id {title, base: {title}}`, 충돌 화면은 같은 `MetaConflict`(낱말 «제목»). 트리의 `useTreeCommands` 를 셸로 끌어올려
  나눠 쓰는 갈래는 고르지 않았다 — 그 훅은 «부르는 자리가 하나»를 전제로 잠금(`inFlight`)을 ref 로 든다.
- **남이 바꾼 이름은 `menu-changed` 로 다시 읽는다** — 셸의 `menuRev` 를 탭 본문에 내리고, 마운트 뒤 오른 번호에만 `getPage` 를 한 번 낸다(불러오는 중으로
  안 돌아간다 · 늦게 낸 답만 받는다 — `answered`). 탭에서 바꾼 이름도 서버가 `menu-changed` 를 방송해 메뉴 트리가 다시 받는다(실브라우저 판이 잰다).
- **뷰 모드의 «페이지 정보»는 읽기만**(브리프). 그래서 설명 편집은 편집 모드의 그 탭으로 옮겼다 — 처음 고른 탭은 그대로 «속성»이라 페이지를 열 때 `getPage`
  가 늘지 않는다.
- **HTML 번들의 첫 탭 이름은 «페이지 설명»으로 둔다** — 바꾸면 상태 없는 페이지의 번들 바이트가 바뀐다(`bundle-stateless-bytes.test.ts` 가 잡았다). 상태 목록은
  상태가 있는 페이지에만 선다. **PPTX 는 상태를 싣는 자리가 없어 이번에 안 만들었다.**
- **복사(클립보드 봉투)는 출처 페이지의 `viewStates` 를 통째로 싣는다** — 설명도 따라간다(붙이는 쪽은 이름으로만 맞추고 상태를 만들지 않는다). **모듈 저장은
  보임째 걷어 상태를 안 싣는다** — 설명도 해당 없음. 페이지 JSON · 스냅샷 · 가져오기는 문서째라 설명이 함께 간다.
- **몫 · 상태 보임 칸의 같은 `key` 를 갈랐다**(`${node.id}:weight` · `${node.id}:visibility`) — main 부터 있던 결함이다. 변조 D1 이 몫 칸 케이스를 함께 죽여 찾았고, 되돌린 변조(D3)에서 «Flex 자식 둘을 차례로 고르면 둘째의 몫 칸이 빠진다»가 값으로 섰다. 칸 차례를 바꾸는 이 트랙이 그 짝 짓기를 흔드는 자리라 함께 고쳤다.
- 상태 설명 저장 단추는 «상태 설명 저장» — 같은 탭의 «설명 저장»(페이지 설명)과 이름이 겹치면 접근 이름으로 못 가른다.

## 혼자 죽는 변조 표

jsdom · 스키마 · exporter 케이스의 변조 50개(첫 묶음 46 + E2b · D1 · D2 · D3). 변조마다 그 케이스 파일만 돌렸다(`scratchpad/mut/run.py` — 경로 전체 이름 백업 · 바이트 비교 복원 · 맞은 수 1 확인). 실행 수는 통과 + 실패. 50개 모두 죽었고 E2 만 혼자가 아니어서 E2b 를 더했다. 실패 값은 재려던 값이다(예: E2b `expected [ [ '로그인', '0px' ], …(2) ] to deep equally contain [ '새 상태', '12px' ]` · D3 `expected null not to be null` — 몫 칸이 빠졌다).

D1 의 첫 판은 몫 칸 케이스 둘(«까닭은 바른 값을 보내면 걷힌다» · «남이 잡은 노드면 꺼진다»)까지 함께 죽였다 — 그 원인이 아래 «결정과 이유»의 같은 키 결함이다. 키를 가른 뒤 다시 돌린 판이 표의 값이다.

## 지침

1. **무엇이 비었나:** 변조가 엉뚱한 케이스를 함께 죽였을 때 그 원인이 변조가 아니라 소스의 React 같은 키(형제 칸 둘이 `key={node.id}` 를 나눠 씀)였다 — 차례를 바꾸는 변조가 키 짝 짓기를 흔들어 몫 칸의 초안 · 까닭 케이스가 죽었다. 같은 결함은 main 에서 «몫이 서는 노드를 차례로 고르면 둘째의 몫 칸이 빠진다»로 섰다.
   **어느 문서 어느 절:** `.ruler/wirebound/` 의 「워커에게 맡길 때 — wirebound」 «전체가 죽는다»는 «이 케이스가 죽는다»가 아니다» 문단 끝.
   **넣을 문장:** «**변조가 겨누지 않은 케이스를 함께 죽이면 변조를 고치기 전에 그 파일 실행의 콘솔 경고(React `same key` 등)를 센다** — 형제 칸 둘이 같은 `key` 를 나눠 쓰면 차례를 바꾸는 변조가 짝 짓기를 흔들어 다른 칸의 케이스가 죽는다. 그것은 변조의 몫이 아니라 소스의 결함이다(`apps/web/src/panels/property-panel.tsx` 의 몫 · 상태 보임 키).»
2. **무엇이 비었나:** 공용 경로(열린 문서 · 스토어)를 «얼리는» 변조는 그 경로를 지나는 모든 케이스를 죽여 «남의 편집이 선다» 케이스가 혼자 안 죽는다.
   **어느 문서 어느 절:** 같은 파일 「변조를 `git checkout` 으로 되돌리지 않게 한다」 문단의 «떼려는 장치가 판 만들기와 같은 길이면 …» 문장 뒤.
   **넣을 문장:** «**남의 편집을 재는 케이스의 변조는 «남의 것만» 막는다** — 열린 문서를 첫 판에 얼리면 내 편집 뒤 목록을 읽는 케이스까지 죽는다. 내 커밋을 부를 때 녹는 얼림으로 짓는다(`docs/superpowers/plans/2026-10-22-pi-report.md` 의 E2b).»

3. **무엇이 비었나:** 탭을 하나 더한 트랙의 인구조사(브리프 «`getByRole('tab')` · «페이지 설명»»)가 `.wb-shell-tab` 클래스 + `.first()` 로 «첫 탭 = 고른 탭»에 기댄 실브라우저 판을 못 셌다 — 게이트의 실브라우저 전량이 잡았다.
   **어느 문서 어느 절:** `.ruler/wirebound/` 「워커에게 맡길 때 — wirebound」 «입구 · 단추를 걷거나 더하는 트랙은 …» 문장의 예 목록.
   **넣을 문장:** 그 목록의 괄호 끝에 «· 우측 탭 클래스의 `.first()` 를 고른 탭으로 읽는 판(`keyboard-holes` «우측 패널 탭» — 탭을 앞에 더하자 정지점이 둘째로 갔다)» 를 더한다.
