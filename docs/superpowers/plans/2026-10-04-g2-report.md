# G2 보고 — 열린 메뉴의 Delete 막기 · 배치 선에 행 · 열 구분

브랜치 `feat/g2-menu-delete-guides`(main `23d7d2d3` 위). 브리프 `.worktrees/.coord/brief-g2.md`. 정본 `docs/superpowers/specs/2026-08-03-wirebound-design.md` 「설계서 화면 구조」의 «`…` 메뉴» · «배치 선» · «단축키»(표의 Delete 줄 · «키를 쓰는 위젯» 문단)를 지금 모양으로 고쳤다.

커밋(차례): `566a04ac` 열린 행동 메뉴의 Delete · Backspace · `910f7744` 배치 선의 안쪽 선 · 이 보고.

## 요약

- **열린 행동 메뉴는 Delete · Backspace 를 쥔다.** 메뉴의 단추 상자와 portal 된 목록에 `data-wb-holds-keys="menu"` 를 달고, `keyHeldByWidget` 이 그 표지에 목록 키 여덟에 더해 Delete · Backspace 를 준다. 메뉴는 그 둘을 받아 아무것도 안 하고 열린 채다. 메뉴가 닫히면(Escape · 바깥 누름 · 항목 고르기) Delete 는 지금처럼 고른 노드를 지운다.
- **메뉴 트리의 `…` 에는 길이 하나 더 있었다** — 목록의 키가 React 트리를 따라 메뉴 트리 상자의 `handleKeyDown` 에 닿아 삭제 확인(«정말 삭제합니까?»)을 걸었다. 그 핸들러도 `keyHeldByWidget` 을 지나게 했다(덤으로 열린 메뉴 안의 Alt+화살표가 고른 메뉴의 자리를 안 바꾼다).
- **표지는 역할(`menu` · `menuitem`)이 아니라 셸의 표지로 가른다** — 역할로 가르면 캔버스에서 테마가 그린 ARIA 메뉴의 단추를 누른 뒤의 Delete 도 먹는다. 구조 트리의 고르개(`StructurePicker` — 표지 값 `""`)는 지금처럼 Delete 를 안 쥔다.
- **배치 선에 안쪽 선을 더했다** — Grid 는 열 · 행 사이, Flex 는 자식 사이(주축에 직각)와 줄바꿈의 줄 사이. 자리는 그려진 자식 상자로 정한다: 축마다 **겹치는 자식끼리 묶고**, 이웃 묶음 사이 간격의 가운데(간격 0 이면 경계)에 긋는다. 바깥 점선과 같은 색의 반투명 점선(굵기는 줌을 걷어 화면 1px), 셸 겹, 바깥 점선과 같은 다시 잼.
- **브리프와 다르게 한 것 하나** — Grid 의 열 · 행을 «서로 다른 왼끝 · 윗끝»이 아니라 «겹침»으로 묶었다. 칸 안에서 가운데 · 끝으로 붙은 자식(`align-items: center`)은 윗끝이 칸마다 달라 윗끝으로 묶으면 행이 갈라진다. 허용 오차는 «맞닿은 두 상자를 다른 묶음으로 보는 겹침 하한» `TOUCH = 1`(캔버스 문서 px)이고, 간격 0 판(간격 단위 토큰 0 의 관리 테마)으로 잰다 — 그 판에서 맞닿은 칸을 잇게 바꾸면 세로선이 다 빠진다(변조 G6).

## 1. 열린 행동 메뉴의 Delete · Backspace

### 재현 — 고치기 전 소스(Chrome · `apps/web/build-test/action-menu-delete.test.ts`)

판: `[카드[글 1, 글 2, 글 3], 글 4, 글 5]` · 고른 노드 «글 2» · 시작 `headSeq` 1. 값은 서버 문서(`GET …/pages/:id`) · 열린 `role="menu"` 수 · 고른 노드. 로그 `[메뉴 Delete]`.

머리 · 셸 메뉴는 고른 노드에 매이지 않아(`openWhile` 없음) 지운 뒤에도 열린 채였다. 마지막 판은 메뉴가 열려 있어도 포커스가 메뉴 밖이면 단축키가 선다는 지금 규칙(«표지는 포커스가 그 안일 때만 쥔다» — `keyHeldByWidget` 머리말 «R2»)대로다. 마우스로 캔버스를 누르면 메뉴가 먼저 닫혀, 이 판은 프로그램으로만 선다(이월 후보 1).

### 고침

- `apps/web/src/edit/editor-shortcuts.ts` — `MENU_KEYS`(목록 키 여덟 + Delete · Backspace) · `keyHeldByWidget` 의 첫 판 `[data-wb-holds-keys="menu"]`. 머리말 표에 그 줄과 까닭.
- `apps/web/src/shell/action-menu.tsx` — 열린 동안 단추 상자에 `data-wb-holds-keys="menu"`, portal 된 목록에도 같은 표지.
- `apps/web/src/panels/menu-tree.tsx` — `handleKeyDown` 이 입력 표면 거름 뒤 `keyHeldByWidget` 을 지난다.
- 정본 «단축키» — 표의 Delete 줄 · «키를 쓰는 위젯» 문단에 «행동 메뉴가 열려 있으면 Delete · Backspace 는 메뉴가 받는다», «`…` 메뉴» 문단에 «메뉴가 쥔 키는 그 트리의 단축키도 안 받는다».
- 옛 동작을 단언하던 케이스 셋을 새 동작으로: `build-test/action-menu-portal.test.ts` «키 — 구조 트리 줄 `…`»(Delete 는 메뉴가 받는다) · «키 — 메뉴 트리 페이지 줄 `…`»(삭제 확인 0), `test/edit/use-editor-shortcuts.test.tsx`(메뉴 표지 케이스를 더하고 고르개 케이스 이름을 «열린 고르개»로), `test/shell/action-menu.test.tsx`(단추 · 목록이 Delete · Backspace 도 쥔다).

같은 판정을 지나는 다른 키(E1 — Cmd+D · Cmd+X · Cmd+V · 화살표 · Escape)는 `editor-shortcuts-review` · `-review-2` · `editor-shortcuts` · `action-menu-portal` · `action-menu-place` 26 케이스가 새 소스에서 초록.

## 2. 배치 선의 안쪽 선

### 고침

- `apps/web/src/canvas/layout-guides.tsx` — `Guide.lines`(캔버스 문서 좌표의 `GuideLine` — 축 · 자리 · 길이), `childRects`(노드 요소 안에서 자식 id 로 · 미리보기 · 크기 0 뺌 · 상자가 없는 요소는 `data-wb-focus` 상자), `groups`(한 축으로 `TOUCH` 넘게 겹치는 상자끼리), `between`(이웃 묶음 사이 간격의 가운데), `gridLines` · `flexLines`(Flex 의 축은 모서리 글과 같은 `axisOf`). 머리말 «안쪽 선».

- `apps/web/src/shell.css` — `.wb-shell-guide-line` · `.wb-shell-guide-line-grid`(바깥 점선 색의 45% · 굵기는 인라인 `1 / zoom`).

1. **메뉴를 연 채 포커스만 캔버스로 옮긴 판의 Delete 는 고른 노드를 지운다** — «표지는 포커스가 그 안일 때만 쥔다»(R2)를 지켰다. 마우스 누름은 메뉴를 먼저 닫으므로 사람의 손으로는 거의 안 서는 판이다. «메뉴가 열려 있으면 어디서든»으로 넓히려면 R2 의 «고르개가 선 동안 캔버스의 Delete 를 먹었다»와 같은 고장을 다시 재야 한다.
2. **구조 트리의 고르개(타입 · 패턴 · 프리셋) 안의 Delete 는 지금처럼 고른 노드를 지운다** — 브리프의 «행동 메뉴»에 안 들어 바꾸지 않았다. 고르개도 쥐게 하려면 표지 값 `""` 판에 Delete · Backspace 를 더한다.
