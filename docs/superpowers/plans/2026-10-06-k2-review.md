## H1 — 흐린 가지 판정이 «뺀 뒤» 좌표를 못 읽는다(높음 · 새 길)

**판(실브라우저):** 손님 상태(손님 가지 없음 — 영역은 흐린 기본 가지). 서버의 기본 가지 `n_cd` 를 편집 앞뒤로 견준다.

| 판 | 나간 프레임 | 기본 가지 |
|---|---|---|
| P1 `n_pre` 줄을 끌어 `n_dt` 아래에 놓음 | `move /root/children/0 → /root/children/0/children/0/children/1` | `[n_dt, n_pre, n_dt2]` — **바뀜** |
| P2 `n_pre` → Cmd+클릭 `n_dt` → Delete | `remove /root/children/0` · `remove /root/children/0/children/0/children/0` | `[n_dt2]` — **바뀜** |
| P4 같은 판, 고른 차례만 `n_dt` → `n_pre` | 같은 두 연산 | `[n_dt2]` — **바뀜** |
| Q7 캔버스 사각형으로 `n_pre` ~ `n_dt` → Delete | 같은 두 연산 | `[n_dt2]` — **바뀜** |
| P3 `n_pre` → Cmd+클릭 `n_dt` → Cmd+D | `add /root/children/1` · `add /root/children/2/children/0/children/1` | `[n_dt, (n_dt 사본), n_dt2]` — **바뀜** |

넷 다 하단 바 알림 0 · 프레임 1 · 서버 200. 판정 함수 값(`unit/plan.probe.ts`)도 같다 — 같은 묶음을 «영역 안이 먼저»인 차례로 지으면(`move n_out → 기본 가지` · `removeMany [n_dt, n_out]` · `duplicate [n_dt, n_pre]`) 거절(`refused`)이 선다.

**원인:** `apps/web/src/edit/view-state-fork.ts` 의 `planViewStateEdit` 는 `dimmedRegions` 가 **편집 전 문서**에서 지은 기본 가지 경로와 연산의 포인터를 글자째 견준다(`under` · `onCase`). 그런데 묶음의 포인터는 앞 연산을 적용한 **뒤** 좌표다 — `apps/web/src/edit/ops.ts` 의 `moveNodeOps` 는 `path` 를 «뺀 뒤 문서»에서 짓고, `apps/web/src/edit/paste-ops.ts` 의 `removeManyOps` · `duplicateOps` 는 `running` 문서로 차례로 짓는다. 영역 · 그 조상의 **앞 형제**를 빼거나 넣으면 영역의 번호가 밀려 뒤 연산의 포인터가 어느 흐린 가지에도 안 맞고(`touched` 0), 판정이 `plain` 을 낸다. `CLAUDE.md` 「메인 세션은 디스패치·판정·병합만 한다」의 «편집의 포인터를 판정에 넣을 때 그 좌표가 어느 문서의 것인지 센다»와 같은 꼴이다.

**닿는 조건:** 영역(또는 그 조상)보다 앞 자리의 형제를 옮기거나 지우거나 그 뒤에 넣는 연산이 같은 묶음에서 흐린 가지 안 연산보다 **앞**에 선다. 지금 화면에서 그 꼴을 내는 입구는 위 넷이다.

**고칠 방향:** 판정을 연산마다 «그 연산 앞까지 적용한 문서»에서 한다 — 연산을 차례로 적용하며 매번 `dimmedRegions` 를 다시 짓거나, 포인터 대신 영역 id · 노드 정체성으로 «흐린 가지 안인가»를 센다(`packages/schema/test/lock-ops-identity.test.ts` 의 오라클 꼴). 케이스는 «앞 형제를 미는 연산 + 흐린 가지 안 연산» 묶음(위 넷)을 싣는다.

## H2 — 남이 가지를 먼저 만들면 고른 노드 · 친 글이 숨은 기본 가지에 쓴다(높음 · 새 길)

**판(실브라우저 `others.probe.ts`):** alice · bob 둘 다 손님 상태. alice 가 흐린 `n_dt` 를 고른다(bob 화면에 잠금 배지). bob 이 흐린 `n_dt2` 의 글을 고쳐 손님 가지를 만든다(복사 + 편집 — 서버 200, alice 의 잠금에 안 막힘: 복사는 `n_dt` 를 안 건드린다).

| 무엇 | R1(bob 뒤에 alice 가 고침) | R2(alice 가 친 채 bob 이 만듦 → alice 가 칸을 떠남) |
|---|---|---|
| alice 의 트리 · 캔버스 선택 | `[]` · 없음 — `n_dt` 는 이제 숨은 기본 가지 | `[]` |
| alice 의 속성 패널 | 여전히 `n_dt`(값 «기본 글») | 친 글 «앨리스 초안»이 남음 |
| alice 가 낸 프레임 | `replace /root/children/1/children/0/children/0/props/content` «앨리스 고침» — 평범한 편집 | 같은 꼴 «앨리스 초안» |
| 서버 기본 가지 | `n_dt:앨리스 고침` — **바뀜** | `n_dt:앨리스 초안` — **바뀜** |
| alice 화면 | 손님 가지(bob 의 복사)가 보여, 친 글이 화면 어디에도 안 선다 · 알림 0 | 같음 |
| bob 화면의 `n_dt` 배지 | 0 — alice 의 잠금이 숨은 노드에 남는다 | — |

**원인:** `planViewStateEdit` 는 «지금 상태의 가지가 **없는**» 영역만 센다. bob 의 복사 뒤 영역에는 손님 가지가 있어 흐린 영역이 아니게 되고, 숨은 기본 가지를 건드리는 편집은 `plain` 이다. 고른 노드를 복사로 옮기는 것(`use-edit-commit.tsx` 의 `commitOps` · `rememberFork`)은 **내가 낸** 복사에만 선다 — 남의 복사 뒤에는 고른 것이 숨은 노드에 남고, 속성 패널은 화면에 안 보이는 노드를 계속 그린다.

**고칠 방향:** 판정이 «지금 상태에서 안 보이는 가지»를 건드리는 편집도 센다 — 안 보이는 가지 안만 건드리면 보내지 않고 까닭을 말한다(«모든 가지 보기»를 켜고 고른 판을 예외로 둘지 정한다). 남의 편집으로 고른 노드가 숨으면 선택에서 빼고, 그 노드의 남은 초안을 쓰지 않고 떠남 통지로 말한다.

## H3 — 풀기 확인 상자가 연 순간의 목록을 보이고 지금 문서로 지운다(높음 · 새 길)

**판(실브라우저 `unsplit.probe.ts` U1):** alice(기본 상태)가 `n_sw` 의 «상태 나누기 풀기»를 연다. 그다음 bob 이 손님 상태에서 흐린 `n_dt2` 를 고쳐 손님 가지를 만들고 선택을 푼다. alice 가 «풀기»를 누른다.

| 무엇 | 값 |
|---|---|
| 연 순간 상자 | «기본 가지만 남기고 가지 1개(관리자)의 내용이 함께 삭제됩니다.» · 목록 `[n_at]` |
| bob 뒤 상자(1.0s 뒤) | 그대로 — 알림 0 · 단추 «풀기» · 꺼짐 없음 |
| 누름 뒤 서버에서 사라진 id | `n_sw` · `n_cd` · `n_ca` · `n_at` · **bob 의 손님 가지와 그 안 노드 둘** |

상태 삭제 상자(`shell/view-states-dialog.tsx`)는 같은 판(D1 · D2)에서 다시 선다 — 풀기 상자만 견줌이 없다.

**원인:** `apps/web/src/panels/structure-toolbar.tsx` 의 `askUnsplit` 은 연 순간의 `unsplit.shown` 을 `unsplitting` 에 쥐고, `runUnsplit` 은 누를 때 `unsplitPlan` 을 지금 문서로 다시 지어 견주지 않고 보낸다. `panels/unsplit-dialog.tsx` 는 쥔 값만 그린다.

**고칠 방향:** 상태 삭제 상자의 꼴(`removal` 의 정렬 id 열쇠 · 렌더 중 견줌 · «목록이 바뀌었습니다» · «새 목록 확인» · 누를 때 한 번 더 견줌)을 풀기 상자에 그대로 단다. 열쇠는 지우는 가지 id 와 그 안 노드 id 전부.

## L1 — 가지 줄의 Cmd+D 는 서버가 거절한다(낮음 · 새 길)

**판(`rules.probe.ts` V2 · V3):** «모든 가지 보기»로 `n_ca`(관리자 가지) 줄을 고르고 Cmd+D → 프레임 `add /root/children/1/children/2` 값은 **Text «관리자 글»**(가지가 아니라 가지 내용의 사본 — `prepareNodesForPaste` 가 홀로 선 가지를 풀어 붙인다) → `patch-error` · 하단 바 «상태 영역에는 상태 가지만 둘 수 있습니다 (현재: Text) — 페이지를 서버 상태로 다시 불러왔고, 편집 1개가 취소됐습니다.». 기본 가지 `n_cd` 도 같은 값(V3). 데이터는 안 바뀐다.

**원인:** `apps/web/src/edit/paste-ops.ts` 의 `duplicateOps` 는 붙이기(`insertMany` 의 «검증 오류가 늘면 거절»)와 달리 결과 문서를 검증하지 않고, 가지 줄의 «아래 추가» 규칙(`edit/structure-actions.ts` 의 `regionRules`)도 안 본다.

**고칠 방향:** 복제가 `insertMany` 와 같은 검증을 거치거나, 가지 줄이 든 선택에서 Cmd+D 를 `regionRules` 의 «아래 추가» 까닭으로 막는다.

## L2 — 흐린 영역의 «풀기»가 켜져 있다가 엉뚱한 까닭으로 거절된다(낮음 · 새 길)

**판(`rules.probe.ts` U3):** 손님 상태(손님 가지 없음)에서 `n_sw` 줄 `…` 의 «상태 나누기 풀기» — `aria-disabled` 없음 · 까닭 없음 → 확인 상자 → «풀기» → 프레임 0 · 하단 바 «이 상태의 가지가 없는 영역 안과 밖을 한 번에 고칠 수 없습니다 — 영역 안을 먼저 고쳐 이 상태의 가지를 만드세요» · 상자는 열린 채.

**원인:** 풀기 묶음(기본 가지 자식을 영역 밖으로 `move` · 영역 `remove`)은 `from` 이 흐린 기본 가지 안이고 `path` 가 밖이라 `planViewStateEdit` 가 거절한다. `structure-toolbar.tsx` 의 `unsplitWhy` 는 잠금만 보고 그 판정을 안 부른다.

**고칠 방향:** 영역째 다루는 묶음(풀기 — 영역 노드 자신을 지우는 연산이 든 묶음)은 판정에서 `plain` 으로 보거나, `unsplitWhy` 가 판정을 불러 꺼진 까닭을 단다.

## L3 — 가지 줄의 붙여넣기는 막히지만 문장이 일반 검증 문장이다(낮음 · 새 길)
