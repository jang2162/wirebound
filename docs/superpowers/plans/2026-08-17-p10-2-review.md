## 2. 발견 1 — **이음매의 계약이 문서뿐이다.** 그리는 자가 던지면 내보내기 하나가 통째로 500 (중)

### 2.1 관측 — **값으로 봤다**

`ScreenRenderer.render`의 계약은 *"던지지 않는다"*이고(`screen-render.ts` 머리말 · D5),
`chromiumScreenRenderer`가 그 규율을 지킨다. **그런데 부르는 쪽에 아무 방어가 없다.**

`services/export-pptx.ts`의 `drawScreens`:

```
const batch = await renderer.render(requests)   // ← try 도 catch 도 없다
```

던지는 `ScreenRenderer`를 `withApi`에 넣어 라우트 둘을 쟀다(임시 케이스 · 지웠다):

| 라우트 | 상태 | 본문 |
|---|---|---|
| `GET …/export/preview?format=pptx` | **500** | `{"error":{"code":"internal","message":"서버 오류가 발생했습니다"}}` |
| `GET …/export?format=pptx` | **500** | 〃 |

### 2.2 왜 이것이 그 부류인가

**보고서 §5.2가 자랑스럽게 적은 스모크의 발견이 정확히 이 모양이었다** — 글꼴 물음의 예외가
`render` 밖으로 새어 *"내보내기 하나가 통째로 500"*이 되었다. 고침은 **`screen-render-chromium.ts`
안쪽**에서 이뤄졌다(답을 셋으로 넓혔다). **그 고침은 그 한 갈래만 닫는다.**

오늘 남아 있는 탈출구를 소스에서 셌다:

| 자리 | 오늘 던지나 |
|---|---|
| `chromium.launch()` | 잡는다(`catch` → 전부 실패) |
| `probeKoreanGlyphs` | 잡는다(`{ reason }`) |
| `renderOne` | 잡는다(`catch` → `failure`) |
| **`finally { await browser.close() }`** | **안 잡는다.** 여기서 던지면 `render` 밖으로 그대로 나간다 |
| **`renderer` 자체가 다른 구현일 때** | **아무도 안 잡는다** — 이음매의 타입은 *"던지지 않는다"*를 강제하지 못한다 |

### 2.3 고치는 법 — **한 줄이다**

`drawScreens`가 `renderer.render`를 `try`로 감싸고, 던지면 **모든 페이지를 그 이유로 실패**
시키면 된다. 그러면 D5(*"하나 때문에 전부를 잃지 않는다"*)가 이음매의 **규율**이 아니라
**구조**가 된다. 케이스 하나(*"그리는 자가 던져도 pptx가 나온다"*)가 그것을 센다 —
오늘 `export-pptx-screens.test.ts`의 `FakeRenderer`는 **한 번도 던지지 않는다.**

**등급: 중 · 고치고 병합하기를 권한다**(값이 싸고, 이 슬라이스가 이미 한 번 물린 부류다).

## 3. 발견 2 — **두부 판정자에 구분력이 없다.** 그리고 그 전제가 기계에 달렸다 (중)

### 3.1 **0 사망** — `KOREAN_GLYPH_PROBE`를 `return true`로 갈아도 아무도 안 죽는다

```
- return ink('한글') !== ink('')
+ return true
```

| 게이트 | 결과 |
|---|---|
| `pnpm test` | **0 · 272 파일 · 5047 케이스 전부 초록** |
| `pnpm test:build` | **0 · 6 파일 · 64 케이스 전부 초록** |

**곧 D4의 판정자 전체를 상수로 바꿔도 게이트가 아무 말도 안 한다.** 오늘 죽는 것은
*"두부라고 답했을 때 안 그리는가"*(구현자의 M12)뿐이고, ***"두부를 두부라고 답하는가"***는
**아무도 안 잰다.** 구현자가 T1에서 손으로 쟀지만 그 측정이 케이스가 되지 않았다.

### 3.2 전제 하나가 **이 기계에서 이미 깨진다**

보고서 §2.3이 *"PUA 두 벌이 같은 해시다 → 그러므로 「같으면 두부」가 성립한다"*를 **표본
둘**로 세웠다. 다섯으로 늘려 다시 쟀다(같은 기계 · 같은 캔버스 · `32px sans-serif`):

| PUA 두 글자 | 해시 |
|---|---|
| `U+E000 U+E001` | `-4617802` |
| `U+E010 U+E011` | `-4617802` |
| `U+E100 U+E101` | `-4617802` |
| **`U+F8FF U+F8FE`** | **`2042580645`** ← 다르다 |
| `U+E500 U+E501` | `-4617802` |

`U+F8FF`는 macOS에서 **실제 글리프가 있는 사용자 영역 코드포인트**다(Apple 로고).
곧 ***"사용자 영역은 반드시 두부"*는 참이 아니고, 참인지 아닌지가 기계에 달렸다.**

오늘 고른 `U+E000·U+E001`이 이 기계에서 두부인 것은 맞다. 그러나 **Nerd Font·Font
Awesome·Material Icons·Powerline 계열은 정확히 `U+E000` 부근을 쓴다** — 그런 글꼴이 깔린
기계(개발 기계·일부 컨테이너)에서는 기준선이 두부가 아니게 되고, 그때 판정자는
**한글이 두부여도 *"있다"*로 답한다.** 그것이 D4가 막으려던 바로 그 사고다.

### 3.3 거짓 양성은 못 봤다

같은 물음을 스무 번 반복해 **20/20 동일**(`true`), 곧 이 기계에서 조용한 거짓 경고는 없다.
`document.fonts.check`가 없는 이름에도 `true`를 내는 것도 **독립적으로 재현했다**
(`"Malgun Gothic"`·`"Zzzz No Such Font 12345"` 둘 다 `true`) — 재라 #4에 대한 구현자의
판정은 **옳다.**

### 3.4 무엇을 만들면 자가 서나

브라우저 안에서 **판정 방법 자체**를 재는 케이스 하나면 된다:
`ink(PUA_a) === ink(PUA_b)`(기준선이 두부다) **그리고** `ink(한글) !== ink(PUA)`(한글은 다르다).
앞 절이 없으면 `return true`와 구분되지 않는다. **기준선 후보를 여러 개 두고 서로 같은 것만
쓰는 것**도 §3.2를 값으로 막는다.

**등급: 중 · 이월에 값으로 남기면 병합은 가능하다.**

## 4. 발견 3 — **차단이 페이지 단위다.** 팝업이 규칙 밖으로 나간다 (하 · 잠재 SSRF)

### 4.1 관측 — 로컬 서버로 셌다

127.0.0.1의 임시 HTTP 서버를 띄우고, 그 주소를 **일곱 가지 방법**으로 건 페이지를
프로덕션 렌더러(`chromiumScreenRenderer`)로 그렸다.

| 나가는 길 | 서버가 받았나 |
|---|---|
| `<link rel=stylesheet href=http://…>` | **아니다** |
| `<script src=http://…>` | **아니다** |
| `<img src=http://…>` | **아니다** |
| `<iframe src=http://…>` | **아니다** |
| `fetch('http://…')` | **아니다** |
| CSS `@font-face { src: url(http://…) }` · `background-image: url(http://…)` | **아니다** |
| **`window.open('http://…')`** | **그렇다 — 요청이 나갔다** |

두 번째 프로브로 재확인: `window.open` 뒤 **같은 컨텍스트의 페이지가 1 → 2**가 되고
로컬 서버 적중 1건(`/from-eval.html`).

**원인:** `newRenderPage`가 `page.route('**/*')`를 건다 — **페이지 단위**다.
`browser.newPage()`가 만드는 **컨텍스트**에 새 페이지(팝업)가 생기면 그 페이지에는 규칙이
없다. `browser.newContext()` + `context.route(...)`로 올리면 닫힌다.

### 4.2 **오늘은 못 닿는다** — 그것도 쟀다

`exportPage`가 내는 HTML에 `<script>`가 **하나도 없고**, 사용자 글자는 React가 이스케이프한다.
직접 쟀다: 노드 `content`와 `title`에 `<script>alert(1)</script>`를 넣었더니
`HTML_HAS_SCRIPT_TAG=false`이고 제목이 `&lt;script&gt;alert(1)&lt;/script&gt;`로 나갔다.

**그러므로 오늘 이 구멍으로 갈 길이 없다.** 다만 P8-3이 **번들 셸에는 이미 `<script>`를
얹었으므로**, `exportPage`가 언젠가 하나를 갖거나 컴포넌트가 원시 HTML을 그리게 되는 날
**차단 규칙이 조용히 안 덮는다.**

### 4.3 `data:`는 산다 — 이월의 그 줄이 맞다

같은 차단 아래에서 `data:image/png` `<img>`가 `naturalWidth > 0`으로 **로드되고**, 원격
`<img>`는 안 된다. **이월 §2.1의 *"`data:`는 산다"*를 독립적으로 확인했다.**

**등급: 하 · 이월에 한 줄.** (오늘 도달 불가이므로 병합을 막지 않는다.)

| `timeoutMs: 1`(글꼴 물음이 죽는다) | — | **0** |

| | R2 변이 아래 | 원본 |

## 6. 발견 5 — **래스터가 실제로 그 페이지처럼 보이는지 아무도 안 잰다** (중)

### 6.1 **0 사망** — 테마 시트를 안 얹어도 아무도 안 죽는다

```
- await page.addStyleTag({ content: request.css })
+ void request.css
```

`pnpm test:build` **6파일 64케이스 전부 초록.** `pnpm test`는 가짜를 쓰므로 애초에 못 본다
(그쪽은 *"시트를 넘겼는가"*만 재고 *"시트가 그림에 반영됐는가"*는 안 잰다).

**곧 「슬라이드의 화면이 곧 그 테마다」(`export-pptx.ts` 머리말 · 이월 §1.2의
「렌더러가 하나다」)를 지키는 자가 없다.**

### 6.2 스모크 픽스처가 **오류 상자를 그린다**

PowerPoint 화면을 눈으로 보다가 찾았다. `build-test/screen-chromium.test.ts`의 `doc()`이
만드는 노드가 **카탈로그에 없거나 prop 이름이 틀렸다.**

| 픽스처가 쓰는 것 | 카탈로그의 진실 | 그려지는 것 |
|---|---|---|
| `type: 'Heading'` | **그런 타입이 없다** (`Text` + `role: 'h1'`이다) | *"알 수 없는 컴포넌트 타입: Heading"* 상자 |
| `type: 'Text', props: { text }` | `Text`의 prop은 **`content`**다 | *"Text의 props가 올바르지 않습니다: 인식할 수 없는 키: "text""* 상자 |
| `type: 'Button', props: { label }` | 맞다 | 진짜 버튼 |

카탈로그의 실제 타입: `Button Card Divider EntryForm Field Flex Grid KeyValue Link List
Media Page Placeholder SearchForm Section Slot Tabs Text Tree` — `Heading`이 없다.

**그래서 「진짜 브라우저가 그린 PNG」는 오늘 대부분 오류 상자의 사진이다.** §6.1과 합치면:
**래스터 경로가 진짜 컴포넌트·진짜 스킨을 지나는지 재는 자가 하나도 없다.**

계약 쪽 측정(PNG 서명 · 폭 1440 · 높이가 는다 · 타임아웃 · 상한 · 차단)은 **내용과 무관하므로
그대로 유효하다.** 무너지는 것은 *"화면이 화면처럼 보인다"* 쪽뿐이다.

**등급: 중 · 픽스처를 `Text{content, role}`로 고치는 값이 매우 싸다.** 시트가 실제로
반영되는지는 픽셀 하나(예: 테마 배경색)를 재면 닫힌다.

동시 요청 수를 바꿔 가며 최고 프로세스·최고 RSS를 쟀다(요청마다 8장 · 40행):

## 12. PowerPoint — **내가 다시 쟀다.** 자가 양방향으로 서고 **그림이 실제로 보인다**

## 15. 이월의 완전성 — **§1은 완전하고 §4는 빠진 것이 있다**

### 15.1 §1(로드맵이 무엇으로 서 있나) — **완전하다**

설계서 §15의 표는 **열네 행**(P0·P1·P2a·P2b·P3·P4a·P4b·P4c·P5·P6·P7·P8·P9·P10 — 곧
*"열한 단계"* P0~P10을 넷으로 쪼갠 것)이고, 이월 §1.1이 **같은 열네 행을 그대로 든다.**
**빠진 단계가 없고 이름과 자리가 맞는다.** §1.2(의존 방향)·§1.3(자 넷)도 값과 맞는다 —
다만 §1.2 한 칸이 틀렸다(§10.1).

### 15.2 §4.1(§16이 스스로 든 다섯) — **완전하다**

설계서 §16의 다섯(구조 목록 범위 · 테마 마켓 · 패턴 슬롯 타입 · 스냅샷 보관 · revision 압축)이
**그대로 다섯 다 있다.** 각각의 *"오늘"* 칸도 맞는다.

### 15.3 §4.2(구현이 판정했고 설계서에 줄이 없는 것) — **빠진 것이 있다**

§4.2는 **"설계서가 침묵한 것"**만 든다. **"설계서가 틀린 채로 남은 것"**을 안 든다 —
그런데 P10-1 §3.3(§12.3의 `--format html`)은 정확히 그 부류이고 **§4.2에 들어 있다.**
곧 분류가 이미 그것을 포함하는데 **앞선 슬라이스들이 남긴 같은 부류가 누락됐다.**

|---|---|---|
