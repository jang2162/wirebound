## Task 2 — 옛 문서 옮기기 · `StateSwitch` 걷기

### 바꾼 것

- **판 1 → 2 는 이미 있던 사슬(`migrate.ts` 의 `MIGRATIONS`)의 첫 단계다** — `CURRENT_DOCUMENT_VERSION = 2`. 그래서 지금 `migrateDocument` 를 부르던
  경계(편집 파이프라인 2단계 · `GET` · `PUT …/schema` · 페이지 JSON 가져오기 · 클립보드 봉투 · 스냅샷 lint 입력 · CLI · MCP 읽기)가 모두 같은 함수를 탄다.
  이름 `migratePageDocument(doc, { pageId })` 는 그 사슬 그대로이고 `MigrationError` 에 페이지 id 를 싣는다.
- 새 `migrate-document.ts` 의 `liftStateRegions` — 설계서 C4 규칙(기본 가지 → `except [영역의 상태들]` · 상태 가지 → `only [S]` · 바깥 가지 안이면 합친
  집합을 `only` · 목록 밖 · 둘째 가지 · 가지 아닌 자식 · 빈 집합은 버리고 `dropped` 로 셈 · 영역 밖 `StateCase` 는 자식만). 상태 영역이 없는 문서는
  손대지 않는다(겹친 id 는 검증의 `duplicate-id` 몫 — 아래 «고친 결함»).
- **스냅샷 복원**은 대상 payload 의 옛 판 페이지를 계획 전에 옮긴다(`services/restore.ts` 의 `currentVersionPages`) — 안 옮기면 갈아 끼운 문서의 판이
  달라 파이프라인 7단계 `invalid` 였다(변조 M9 의 값).
- **클립보드:** 판 1 봉투는 출처의 상태 목록을 실은 채 옮긴다(목록 없이 옮기면 상태 가지가 «목록 밖»으로 버려진다). `prepareNodesForPaste` 의 가지
  거름을 보임 거름으로 — 붙일 페이지에 없는 상태를 빼고 셈(`droppedStates`) · `only` 가 비면 보임째 걷고 셈(`clearedOnly`).
- 걷음: 카탈로그 `StateSwitch` · `StateCase`(19종) · `THEMELESS_TYPES` · 테마 manifest `themeless-component`(이제 `unknown-component`) · 렌더러 투명 노드 ·
  `view-state.ts` · `view-state-touch.ts` · 나누기 · 풀기 · 가지 복사 · 복사 + 편집 · 검증 코드 넷(`state-case-default` · `-duplicate` · `-outside` ·
  `state-switch-child`) · lint `view-state-nested` · 줄 요약의 «가지 N» · `caseStateName`. `DEFAULT_CASE` → `DEFAULT_VIEW_STATE`.
- 렌더러: `RenderOptions.viewStates` · 숨은 노드는 자손째 안 그림(`isVisibleIn` — 겹layer 숨김과 같은 자리 · 폴백도 안 알림) · 노드 캐시 열쇠는 고른 상태의
  조상 줄(`stateLineage`).
- lint: `view-state-unknown`(보임이 목록 밖 상태를 가리킴 · 자리 `…/visibility`) · `view-state-unused`(그 상태도 하위 상태도 아무 보임이 안 가리킴).
  정본 「lint 규칙」 줄 둘을 고쳤다(`lint-rules.test.ts` 가 정본을 읽는다).
- 읽기: `pageView` 의 `nodes[].viewState` → `nodes[].visibility`(노드 자신의 것 그대로). 이름 맥락(`namingContexts`)은 가장 가까운 `only` 보임의 상태들을
  ` · ` 로 잇는다(Task 5 의 이름 규칙을 여기서 함께 — `view-state.ts` 를 걷으며 옮겼다).
- exporter: 번들 고르개가 트리 차례 · 하위 상태는 줄바꿈 없는 빈칸 둘씩 들여 씀(Task 5 몫을 함께 — `DEFAULT_CASE` 를 걷으며).
- MCP 스킬 «화면 상태를 다룰 때»를 새 꼴로(예 넷: `add-state` · `add-child-state` · `show-only` · `remove-state` — api `view-states-skill` 이 글자
  그대로 저장 경계에 보낸다).

- `seed-user` 의 마이그레이션 글자 셈에 «`update users` 도 없다»를 더했다(0025 는 `update` 만 한다 — 브리프 교훈).

### 고친 결함 하나 — 재현 먼저

**상태 영역이 없는 판 1 문서의 겹친 id 가 400 이 됐다**(처음 판의 `liftStateRegions` 가 모든 문서에서 겹침을 봤다). api 전량 1판에서
`page-import` «duplicate-id도 422다» · `pages` «id가 중복되면 422» 둘이 `400 «문서를 판 2 로 옮기지 못했습니다»` 로 재현됐다. 겹침 검사를 «상태
영역을 푼 문서»에만 걸었다 — 영역이 없으면 옮길 것이 없고 겹침은 검증의 `duplicate-id`(422) 몫이다. 케이스 «상태 영역이 없는 문서는 겹친 id 를
보지 않는다»(변조 M4 혼자 죽음).
