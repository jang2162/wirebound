# DK 보고 — 배포 구성을 «앱만 · 프록시는 override» 로, 개발 compose 를 `docker/dev/` 로, 배포 문서를 Docker 기준으로

브랜치 `feat/deploy-docker`(main `a1cb6fd1` 위). 잰 기계: macOS · Colima(linux/arm64) · Docker Compose 5.6.0 · Node v24.21.0.

## 바꾼 배치

| 앞 자리 | 지금 자리 | 무엇 |
| --- | --- | --- |
| `deploy/docker-compose.yml` | `compose.yaml` | 배포 compose — 앱만(TLS · `SITE_ADDRESS` · 443 · `caddy-*` 볼륨 걷음) · web 은 `${APP_PORT:-8080}:80` 하나 · `TRUSTED_PROXIES` |
| `deploy/.env.example` | `.env.example`(뿌리) | 배포 템플릿 — `SITE_ADDRESS` · `HTTP(S)_PORT` 걷음 · `APP_PORT` · `TRUSTED_PROXIES` 더함 |
| `deploy/Caddyfile` | `docker/web/Caddyfile` | 입구 — `:80` 하나 · `trusted_proxies static {$TRUSTED_PROXIES}` + `trusted_proxies_strict` · `header_up X-Forwarded-For {client_ip}` · `/health` 도 api 로 |
| `docker-compose.yml` | `docker/dev/compose.yaml` | 개발 Postgres — `x-run-via` 가드 · init 바인드 `./docker/dev/postgres-init` |
| `docker/postgres-init/` | `docker/dev/postgres-init/` | |
| `docs/guides/deploy-komodo.md` | `docs/guides/deploy-docker.md` | 배포 정본(Komodo 는 부록) |
| `/deploy/compose.server.yaml`(`.gitignore`) | `/compose.override.yaml`(`.gitignore`) | `git ls-files compose.override.yaml` 빈 출력 |
| — | 루트 `package.json` 의 `db` | `WIREBOUND_DEV_DB=1 docker compose --project-directory . -f docker/dev/compose.yaml --env-file apps/api/.env` |
| — | `apps/api/build-test/dev-compose.test.ts` | 개발 compose 의 프로젝트 · 볼륨 이름 · init 바인드 · 가드 |

`deploy/` 는 없다. 뿌리의 `docker-compose*.yml` · `compose*.yaml` 은 `compose.yaml` 하나(`git ls-files | grep -E '^(docker-)?compose'`).

## 결정과 이유

- **개발 compose 자리 `docker/dev/compose.yaml` · 부르는 길 `pnpm db …`.** 브리프의 기본값 그대로. 이름을 `compose.yaml` 로 둔 것은 그 디렉터리에서
  누가 맨 `docker compose` 를 쳐도 그 파일이 잡혀 가드(`x-run-via`)에 걸리게 하려는 것이다.
- **격리 기전 — `--project-directory .`.** compose 가 체크아웃 디렉터리의 basename 을 스스로 정규화해 프로젝트 이름으로 쓴다(뿌리에 파일이 있던
  판과 같은 규칙 — M0). 스크립트가 이름을 손으로 지으면(`-p $(basename …)`) compose 의 정규화와 갈려 기존 볼륨을 놓칠 수 있어 고르지 않았다.
  **워크트리마다 바꾸는 `.env` 값은 늘지 않았다**(다섯 그대로) — `worktreeEnvError` 류 가드는 고칠 것이 없다. `--project-directory` 를 빼먹는
  판은 이름이 `dev` 하나로 모이므로 개발 compose 가 `${WIREBOUND_DEV_DB:?…}` 로 스크립트 밖 호출을 멈춘다.
- **환경 파일 — 뿌리 `.env` · 템플릿 뿌리 `.env.example`.** compose 기본 자리 · Komodo Env File Path 기본값과 같다. `.gitignore` 의 `!.env.example` 이
  추적한다(`git ls-files .env.example` → `.env.example`). 개발 명령에 안 샌다(M6). api 가 읽는 값의 목록은 `apps/api/.env.example` 이 그대로 갖는다
  (`env-example-census.test.ts` 는 그 파일만 잰다 — 배포 템플릿은 사람이 적는 키만 든다).
- **앱 포트 `${APP_PORT:-8080}`.** 80 은 서버의 프록시가 쥐는 일이 흔해 비켰다. 기본 바인드는 모든 주소다(브리프 «그대로 올리면 그 포트로 답한다»).
- **믿는 앞단 — `TRUSTED_PROXIES`(기본 빈 값 = 아무도).** Caddy `servers { trusted_proxies static … ; trusted_proxies_strict }` + `header_up
  X-Forwarded-For {client_ip}`. 덧붙이는 기본값을 그대로 두면 api(입구 하나만 믿음)가 오른쪽 끝의 **프록시 주소**를 클라이언트로 센다 — 고른 주소
  하나로 새로 적는 것이 api 의 `TRUST_PROXY` 를 안 바꾸는 길이다. 왼쪽부터 읽는 Caddy 기본은 클라이언트가 지은 값을 고르므로 strict 를 건다(M8).
- **입구가 `/health` 도 넘긴다.** 프록시 · 감시가 입구 너머 api 의 생사를 물을 자리가 없었다(처음 판의 `/health` 는 SPA 의 200 html — M7).
- **Q1(맨 HTTP 로그인)** — `q-dk.md` 답대로 api 코드 · `NODE_ENV` 를 안 바꿨다. 가이드 「확인」이 «로그인은 TLS 너머 · 아니면 localhost» 를 사실로 적는다.
- **README 에 남긴 것 · 옮긴 것.** 이미지와 무관한 조건(「api 가 필요로 하는 것」 · 「pptx 의 화면 이미지」 · 「에디터 — 정적 파일」 · 「앞단(리버스 프록시)이
  지킬 조건」 · 「화면 그리기 상한」)은 README 「배포하려면」 아래에 제목째 남겼다 — 코드 주석 · `apps/api/README.md` · `.env.example` 이 그 제목으로
  가리킨다(아래 「가리킴」). 절차(올리기 · 운영 명령 · 다시 재는 법 · 안 잰 것 · 잰 값)는 가이드로 옮겼다. 「앞단 조건」 표는 «걸리는 곳» 칸(입구 /
  각자의 프록시)으로 다시 썼고, TLS · Caddy 앞단을 전제로 잰 수(WS 150s 유휴 · 끊음 4.00s · nginx 설정 블록 등)는 다시 안 쟀으므로 걷었다.
- **`deploy-compose.test.ts` 의 건너뜀 조건을 바꿨다.** 처음 판은 `docker compose config` 가 실패하면 건너뛰었다 — 깨진 compose 가 «건너뜀 · 성공»
  으로 지나간다(M12 의 D4c). 지금은 `docker compose version` 이 안 돌 때만 건너뛰고, `config` · `caddy adapt` 실패는 죽는다.

### M1 — 사용자 데이터 보존: 최상위 체크아웃의 프로젝트 · 볼륨 이름 (`config` 만 · `up` 없음)

볼륨에는 닿지 않았다(읽기 전용 `config` 만 · 그 디렉터리의 파일은 `git archive HEAD` 와 이 브랜치의 사본).

| --- | --- | --- | --- | --- |
| 옛 (HEAD `docker-compose.yml`) | `docker compose --env-file apps/api/.env config` | `wirebound` | `wirebound_wirebound-pgdata` | 5433 |

### M0 — compose 동작 탐침 (스크래치 · `config`)

- `--project-directory .` 이면 프로젝트 이름 = 체크아웃 디렉터리 basename 을 compose 가 정규화한 값(`Wb-Dk.Probe` → `wb-dkprobe`) —
  뿌리에 compose 가 있던 판과 같은 규칙이다. 상대 경로도 그 디렉터리 기준이다.
- 빼면 `name: dev` — 모든 체크아웃이 한 이름. `x-run-via: ${WIREBOUND_DEV_DB:?…}` 가 스크립트 밖 호출을 `required variable … is missing` 로 멈춘다.
- `--env-file apps/api/.env` 를 주면 프로젝트 디렉터리의 `.env` 는 안 읽는다 — 뿌리 `.env` 에 `WB_GUARD=…` 를 두고 `--env-file` 을 준 판이 그 값을 못 봤다.
- `pnpm db exec postgres psql -U … -d … -c '…;'` 의 인자는 그대로 넘어간다(`-U` · `-d` · `-c` 포함). 출력을 읽을 때는 `pnpm -s` — 안 주면 pnpm 머리 두 줄이 붙는다.
- Caddy 2.11.4 `caddy adapt`: `trusted_proxies static {$TRUSTED_PROXIES}` 에 빈 값이면 `{"source":"static"}`(범위 없음) · 값이면 `ranges` 로 읽힌다.

### M4 — 옛 습관 명령을 새 배치에서 치면

| 친 것(체크아웃 뿌리) | 결과 |

| `docker compose -f docker/dev/compose.yaml --env-file apps/api/.env up -d` | 종료 1 · `required variable WIREBOUND_DEV_DB is missing a value: docker/dev/compose.yaml 은 저장소 뿌리에서 pnpm db 로 부른다 …` |

### M5 — 배포 `compose.yaml` 과 override 예의 `config` (스크래치 사본 · `.env` 는 `POSTGRES_PASSWORD=probe` 하나)

| 판 | web `ports` | web `networks` | 그 밖 |
| --- | --- | --- | --- |
| `compose.yaml` 만 | `8080:80`(모든 주소) | `backend` · `ipv4_address 10.231.47.2` | `name wirebound-prod` · 볼륨 `wirebound-prod_pgdata` · api `TRUST_PROXY 10.231.47.2` · web `TRUSTED_PROXIES ''` · 바깥 포트를 여는 것은 web 하나 |
| + ⓐ(`ports: !reset []` · `proxy` 더함 · `external: true`) | 없음 | `backend`(고정 주소 그대로) + `proxy`(`aliases: [wirebound-web]`) | 최상위 `proxy: {name: proxy, external: true}` |
| + ⓑ(`ports: !override` `127.0.0.1:${APP_PORT:-8080}:80`) | `127.0.0.1:8080:80` 하나 | `backend` 그대로 | `APP_PORT=9090` 이면 `127.0.0.1:9090:80` |
| ⓐ 를 `compose.override.yaml` 이름으로 두고 `-f` 없이 | ⓐ 와 같다 | ⓐ 와 같다 | compose 가 그 이름을 스스로 읽는다 |
| ⓐ 에서 `!reset` 을 빼고 `ports: []` | **`8080:80` 이 남는다** | | 빈 목록은 합쳐질 뿐이다 — 닫으려면 `!reset` |

`env_file: .env` 는 필수다 — 뿌리에 `.env` 가 없으면 `config` 부터 `env file …/.env not found` 로 멈춘다(보간이 먼저 걸리면 그 문장이 먼저 나온다 — M4).

### M6 — 뿌리 `.env`(배포 값)가 개발 명령에 새지 않는다

이 워크트리 뿌리에 미끼 `.env`(`POSTGRES_PORT=1` · `DATABASE_URL`/`TEST_DATABASE_URL=…127.0.0.1:1/leak` · `PORT=1` · `SESSION_COOKIE_NAME=leak`)를 두고:
`pnpm -s db config` 의 `published` = `5441` · `pnpm --filter @wirebound/api migrate` 의 `대상 DB: 127.0.0.1:5441/wb_deploydo` ·
`pnpm vitest run apps/api/test/health.test.ts` 18 통과(1 파일). 어느 출력에도 `1` 포트 · `leak` 이 없다. 미끼는 지웠다.

### M7 — 배포 스택을 지어 올렸다 (`-p wb-dk-base` · `WIREBOUND_TAG=dk` · `APP_PORT=18080`)

- `docker compose -p wb-dk-base build`(캐시 없음 — 이 기계에 wirebound 이미지가 없었다) **3:01** · api `1.98GB` · web `86.1MB`.
- `up -d` 51s — postgres healthy → migrate → api healthy → web. web 은 `0.0.0.0:18080->80/tcp` 하나를 연다(443 · 2019 는 caddy 이미지의 `EXPOSE` 라 열린 포트가 아니다).
- 맨 HTTP 로 입구: `/health` **200 json `{"status":"ok"}`**(입구가 `/health` 도 api 로 넘긴다 — 처음 판은 SPA 의 200 html 이라 고쳤다) · `/api/auth/me` 401 json ·
  `/` 200 html · `/projects/x/deep` 200 html(`try_files`).

### M8 — 클라이언트 주소(XFF) 두 판 — backend 네트워크에 고정 주소 컨테이너 둘(A `10.231.47.10` · B `10.231.47.11`)

## 최상위 체크아웃 전환 절차 (병합 뒤 코디네이터가 친다)

최상위의 컨테이너 `wirebound-postgres-1`(5433 · 볼륨 `wirebound_wirebound-pgdata`)은 병합만으로는 안 바뀐다 — 옛 바인드(`…/wirebound/docker/postgres-init`)
를 든 채 계속 돈다. 다음 `pnpm db up -d` 가 바인드가 바뀐 것을 보고 컨테이너를 다시 만든다(볼륨은 그대로 — M3 이 워크트리에서 같은 판을 쟀다).
다시 만드는 몇 초 동안 사용자의 api 가 DB 연결을 잃는다 — 사용자가 안 쓰는 때에 친다.

```bash
T=/Users/jang2162/IdeaProjects/wirebound
# 0. 전 — 볼륨 이름 · 수를 적어 둔다
docker inspect wirebound-postgres-1 --format '{{range .Mounts}}{{.Type}} {{.Name}}{{.Source}}{{println}}{{end}}'
docker exec wirebound-postgres-1 psql -U wirebound -d wirebound -tAc 'SELECT (SELECT count(*) FROM users),(SELECT count(*) FROM projects),(SELECT count(*) FROM pages)'
# 1. 새 명령이 같은 이름을 보는지 — 읽기만
pnpm -s -C "$T" db config | grep -E '^name:|    name: .*pgdata|published'
#    → name: wirebound · name: wirebound_wirebound-pgdata · published: "5433"   (셋 중 하나라도 다르면 멈춘다)
# 2. 다시 만든다
pnpm -C "$T" db up -d                     # → Container wirebound-postgres-1 Recreated · Started
pnpm -C "$T" db port postgres 5432        # → 0.0.0.0:5433
# 3. 후 — 0 과 같아야 한다
docker inspect wirebound-postgres-1 --format '{{range .Mounts}}{{.Type}} {{.Name}}{{.Source}}{{println}}{{end}}'   # volume wirebound_wirebound-pgdata · bind …/docker/dev/postgres-init
docker exec wirebound-postgres-1 psql -U wirebound -d wirebound -tAc 'SELECT (SELECT count(*) FROM users),(SELECT count(*) FROM projects),(SELECT count(*) FROM pages)'
```

- 컨테이너를 다시 만들기 전에 그것이 재시작되면(도커 재기동 · 기계 재부팅) 옛 바인드 자리 `docker/postgres-init/` 가 빈 디렉터리로 되살아난다(README
  「컨테이너를 못 찾는다」 절의 그 현상) — 2번을 치면 새 바인드로 바뀌고, 남은 빈 디렉터리는 지워도 된다(git 은 빈 디렉터리를 안 본다).
- 사용자의 api dev 서버는 1 · 2 와 상관없이 같은 `apps/api/.env`(5433)를 본다 — 고칠 값이 없다.
- 최상위에서 옛 습관(`docker compose --env-file apps/api/.env up -d`)을 치면 배포 compose 를 읽고 `required variable POSTGRES_PASSWORD …` 로 멈춘다(M4) —
  최상위에 배포 `.env` 를 두지 않는 한 아무것도 안 만든다.

## 이미 올린 서버가 겪을 것

- 같은 프로젝트(`wirebound-prod`) · 같은 볼륨(`wirebound-prod_pgdata`)이라 DB 는 잇는다. 단 **compose 파일 자리가 뿌리로 바뀌어** 명령에 `-f deploy/docker-compose.yml`
  을 붙이던 자리는 맨 `docker compose` 가 된다. 배포 값 파일도 `deploy/.env` 에서 뿌리 `.env` 로 옮겨야 한다(안 옮기면 `env file …/.env not found` 로 멈춘다).
- **80 · 443 을 더는 안 연다** — web 은 `${APP_PORT:-8080}` 하나다. 그 서버에서 사람들이 쓰던 `https://<도메인>` 은 이제 그 서버의 프록시가 받아 넘겨야 한다
  (ⓐ 또는 ⓑ). 프록시 없이 올리면 그 도메인은 응답이 없다.
- `SITE_ADDRESS` · `HTTP_PORT` · `HTTPS_PORT` 는 더는 안 읽는다(`.env` 에 남아도 무해 — api 컨테이너 환경에 실릴 뿐이다).
- 인증서 볼륨 `wirebound-prod_caddy-data` · `wirebound-prod_caddy-config` 는 이 compose 가 안 쓴다 — 남는다(지워도 되고, 프록시를 Caddy 로 세우면 그 인증서를 옮겨 쓸 수 있다).
- Komodo Stack 이면 Run Directory 를 `deploy` → 비움(뿌리), File Paths 를 `docker-compose.yml` → `compose.yaml`(+ override) 로 바꾼다 — 안 바꾸면 Deploy 가 파일을 못 찾는다.
- `api` 의 `TRUST_PROXY` · 입구 고정 주소(`EDGE_IP`) · 대역은 그대로다.

   **넣을 문장:** «`git mv` · `git rm` 은 친 자리에서 stage 한다 — 묶음마다 커밋하면 커밋 직전에 `git diff --cached --stat` 으로 stage 목록이 그 묶음뿐인지 본다.»
