## 1. 폭 맞춤(`useAutoFitZoom` · `zoomFit`)

묶음의 단추 셋과 접힌 머리 `…` 의 항목 셋(`zoom-out` · `zoom-in` · `zoom-fit` — 같은 파일 `menuItems`)이다. 배율 칸(입력)은 없다. 키보드 단축키는 없다 —
`edit/editor-shortcuts.ts` 의 명령 표에 배율 명령이 없다(`git grep -n -iE "zoom|배율" -- apps/web/src/edit/editor-shortcuts.ts apps/web/src/shell/editor-keys.tsx` 0 줄).
트랙패드 핀치 · Ctrl+휠은 캔버스가 받지 않는다(`git grep -n "wheel" -- apps/web/src` 에 줌 처리 0) — 브라우저 확대라 칸의 CSS 폭이 바뀌어 켜진 동안은 다시 맞춘다.

## 게이트 확인 — `change-kind-code` 경주

**읽은 것.** `apps/web/build-test/change-kind-code.test.ts` «못 받는 종류로 바꾸면 …» 의 끝 단언은 두 편집 각각을 **REST 로 서버 문서가 바뀌기를 기다린**(`poll` ·
`piece`) 곧 뒤에 WS 프레임 목록의 `patch-ack` 수를 센다. 둘째 편집의 서버 값이 REST 로 보인 순간에 그 편집의 ack 프레임은 아직 브라우저에 안 닿았을 수 있다
— 지침 «REST 로 서버 값을 기다린 뒤 키를 누르는 케이스는 ack(WS)가 아직 안 닿은 판을 낸다» 의 꼴 그대로다(«서로 다른 연결로 가는 두 메시지의 도착 순서»).
실패 값 `{ ack: 1, error: 0 }` 이 그 판과 맞다.

**이 트랙과 무관한가.** 그 파일은 기준 `git merge-base main HEAD` = `2c4b1d25` 이후 안 바뀌었다(`git diff --stat 2c4b1d25 HEAD -- <파일>` 빈 줄 · 마지막 커밋
`990f7491`). 그 케이스는 트리 줄의 행동 메뉴로 종류를 바꾸고 서버 문서 · 프레임만 본다 — 이 트랙이 바꾼 것(폭 맞춤 배율 · 트리의 칩 · 타입 글 조각)은 판
만들기(`hasText: 'Select 새 가'` — 별칭 · 요약이 든 줄이라 타입 조각이 흐려질 뿐 글은 같다)에만 닿고 경주의 두 연결에는 안 닿는다. **판정: 이 트랙과 무관한
케이스 쪽 경주.** main 에서 동시 넷 · 두 판으로 돌려 보지는 않았다(브리프의 «또는 읽고 적는다» 갈래). 고칠 방향은 구현 보고 «남은 것» 6 그대로(끝 단언 앞에
`patch-ack + patch-error` 수가 2 에 닿기를 기다리는 폴).
