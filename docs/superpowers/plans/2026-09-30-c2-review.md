## 항목 1 — 서버 잠금 검사의 좌표

### 입구

편집이 `lockConflictError`(`apps/api/src/lock/check.ts`)에 닿는 입구는 셋이다 — REST `PATCH …/ops`(`routes/pages.ts`) · WS `patch`(`ws/patch.ts`) · MCP `patch_page`(`packages/mcp/src/handlers.ts` 의 `patchPage` — 같은 REST `…/ops` 를 토큰으로 부른다). `PUT …/schema`(`routes/pages.ts`)는 `replace /root` 하나라 좌표가 밀리지 않는다(잠금이 하나라도 있으면 늘 부딪친다).

### 원인

`lockPointers(ops)`(`packages/schema/src/lock.ts`)는 연산마다 적힌 포인터를 그대로 모으고, `findLockConflict` 는 그것을 **편집 전 문서**에서 찾은 잠금 경로와 견준다. RFC 6902 의 포인터는 **앞 연산을 적용한 뒤 문서**의 좌표이고 `move` 의 `path` 는 `from` 을 **뺀 뒤** 문서의 좌표다(`patch/apply.ts` 의 `move`). 앞쪽 형제를 빼거나 넣으면 뒤쪽 좌표가 한 칸 밀린다. 구현 보고 이월 1 은 `move` 만 짚었는데 **같은 뿌리가 `add` · `remove` · `replace` 묶음에도 있다** — 그쪽이 더 넓다(아무 편집자가 «맨 앞에 넣기 + 밀린 좌표로 고치기» 두 줄로 남의 잠금을 지난다).

### 값(api · 보라가 `n_b` 를 잡음 · 다혜가 편집)

문서 `root > [n_a > [n_a1], n_b > [n_b1, n_b2], n_c]`.

| 입구 | 편집 | 기대 | 받은 값 | 서버 문서의 `n_b` 자식 |
|---|---|---|---|---|
| REST(세션) | `move /root/children/0 → /root/children/0/children/-` | 423 | **200** | `[n_b1, n_b2, n_a]` — 남의 잠긴 서브트리 안으로 커밋 |
| WS `patch` | 같은 편집 | 423 | **200**(`patch-ack`) | `[n_b1, n_b2, n_a]` |
| MCP(토큰 · `x-wb-client: mcp`) | `remove /root/children/0` · `remove /root/children/0` | 423 | **200** | **`n_b` 가 없다** — 남이 잡은 노드를 통째로 지움 |
| REST(세션) | `move /root/children/0 → /root/children/1`(`n_b` 뒤로 — 안 건드림) | 200 | **423** | 그대로(거짓 거절) |

main 사본(`0181fd04`)에서 같은 두 파일을 돌려 **같은 9 빨강 · 같은 값**(`{ status: 200, b: null }` 포함)을 봤다 — 원래 있던 길이다.

**(결함 · 원래 있던 길) 두 사람이 번갈아** — alice 가 `나3` 을 `나1` 위로(서버 `[나3, 나1, 나2]`) → bob 의 트리는 800ms 뒤에도 `[나1, 나2, 나3]` → bob 이 `나1` 을 `나2` 아래로 놓음 → 서버 **`[나3, 나1, 나2]`**(변화 없음 — bob 의 뜻 `[나3, 나2, 나1]` 이 사라짐), bob 의 트리는 다시 받아 서버 차례를 그린다. 원인: 메뉴 트리가 남의 변경을 받지 않고(`use-tree-commands.tsx` — 제 조작 뒤에만 `load`), 보내는 값이 옛 차례로 셈한 «옮긴 뒤 번호»다. main 사본에서 옛 툴바로 같은 판(alice «위로» ×2 · bob «아래로»)을 돌려 **같은 값**(`second: [나3, 나1, 나2]`)을 봤다. 고칠 방향: 트리 변경을 룸에 방송해 다른 화면이 다시 받게 하거나, 번호 대신 «이 형제 앞/뒤»(형제 id)를 보내 서버가 지금 차례에서 자리를 셈. 무게 낮음(차례만 · 조용하지만 화면이 결과를 그린다).
