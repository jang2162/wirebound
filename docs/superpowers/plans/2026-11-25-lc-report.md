## 결정

1. **트리는 트리 칸의 것을 쓴다(캔버스가 `getTree` 를 따로 안 부른다)** — 트리를 쥔 곳은 `tree/use-tree-commands.tsx` 하나다(판 번호 · `menu-changed` · 복원 뒤 다시 받기). 따로 읽으면 두 조회가 다른 판을 받아 트리 칸과 틀의 메뉴가 갈린다. 트리 칸은 좌측을 접어도 안 내려가(클래스로 접는다) 값이 산다. 트리가 아직 없거나 실패면 «지금 페이지가 트리에 없는» 내비(`gnb` 빈 목록 · `trail` 은 지금 페이지 하나).
2. **트리 응답은 차례대로 오지 않는다** — 트리 칸이 그릴 때 `sortOrder` 로 정렬한다(`menu-tree.tsx` 의 `byOrder`). `buildLayoutNav` 는 받은 차례를 쓰므로 캔버스가 넘기기 전에 메뉴 · 페이지 · 하위 메뉴를 정렬한다.
3. **페이지 이름(틀의 `title`)은 트리의 페이지 줄에서 읽는다** — 스토어는 문서만 들고 `pages.title` 을 안 든다(`getPage` 의 `title` 은 싣지 않는다). 이름 바꾸기가 트리를 다시 받아 따라온다. 트리에 없으면 빈 글.
4. **틀 누름은 링도 안 걷는다** — 설계 «아무 일도 없다» 를 글자대로. 표면 누름의 맨 앞에서 끝낸다(뷰 모드의 `beginGesture` 캡처는 그대로 돈다).
5. **`use-view-prefs` 는 공급자다(훅 하나가 아니다)** — 읽는 쪽(캔버스)과 바꾸는 쪽(T7 의 «보기»)이 셸의 다른 칸이라 값 하나를 함께 봐야 한다. 공급자 밖은 다 켬 · `set` 은 아무것도 안 함.
6. **`canvas-iframe.tsx` · `use-canvas-marquee.ts` 는 안 바꿨다** — iframe 의 높이 관찰은 `body` 와 그 자식(틀의 겉 상자)을 보아 틀이 든 높이를 따라간다. 사각형은 틀에서 시작해도 바탕과 같다(케이스로 잠갔다).
7. **«보기 메뉴 영역 이름 격리»(lt «남은 것»)는 이 트랙에 자리가 안 생겼다** — 캔버스는 영역 이름(manifest `label`)을 그리지 않는다. 틀의 페이지 이름 · 메뉴 이름은 `LayoutFrame` · `buildLayoutNav` 가 이미 `isolateBidi` 로 가둬 내린다. 영역 이름을 그리는 자리는 T7 의 «보기» 메뉴다.

- **재현**: 새 `apps/web/test/store/view-prefs-early.test.tsx`(리뷰 탐침 F1 꼴). 고치기 전: «GET 의 답이 온 뒤 PUT 이 실패» → 화면 `''` ≠ 서버 `subpage.gnb` · «PUT 이 GET 의 답보다 먼저 실패» → 화면 `''` ≠ `subpage.gnb`(둘 다 빨강). 셋째 «GET 보다 늦게 커밋된 PUT» 은 고치기 전에도 초록 — 고침이 새로 세운 갈래를 잠그는 케이스다.
- **바꾼 것**(`apps/web/src/store/use-view-prefs.ts`): 바꾼 뒤 온 GET 의 답도 되돌릴 값(`saved`)에는 적는다(화면에는 안 싣는다). 받아 준 PUT 이 이미 있으면(`confirmed`) 그 PUT 의 값이 더 늦은 판이라 GET 의 답을 안 적는다. 서버 값을 아직 모르는 채(`known` 거짓) 실패하면 되돌리지 않고 GET 의 답을 기다려 그 값으로 맞춘다(`revertOnRead` — GET 마저 실패하면 다 켬). 그 사이 또 바꾸면 기다림을 걷는다. 머리말 표 두 줄을 그 뜻으로 고쳤다.
- **결정 — 실브라우저 케이스는 안 세웠다**: 브리프는 «화면 = 서버» 를 실브라우저(`page.route` 로 GET 늦춤 · PUT 전부 500)로 잠그라 했지만 이 브랜치에는 `set` 을 부르는 화면 입구가 0 이다(`git grep useViewPrefs apps/web/src` — 읽는 자리 `canvas.tsx` 하나). 물음 `q-fx-lc.md` 1 에 적고 기본값(jsdom 케이스로 잠그고 실브라우저 판은 T7 로 넘김)으로 갔다.

### L2 — 뷰 모드 틀 링크의 같은 페이지 이동(`52173d4e`)

- **메뉴 트리의 동작**: 트리 칸의 `<Link>` 는 react-router 기본값으로 «갈 주소(경로 · 질의 · 조각)가 지금 주소와 같으면 replace» 다.
- **바꾼 것**(`apps/web/src/canvas/canvas.tsx` 의 `frameNavigate`): 같은 규칙 — `navigateTo(path, { replace: path === 지금 주소 })`. 지금 주소는 `useLocation` 을 ref 에 실어 읽는다(이동 처리기를 주소마다 새로 짓지 않게).
- **재현 · 케이스**: 새 `apps/web/build-test/page-layout-canvas-review.test.ts` «뷰 모드에서 틀 링크로 지금 페이지를 누르면 …». 고치기 전 `{ 틀: 1, 트리: 0, 다른페이지: 1 }` → 고친 뒤 `{ 틀: 0, 트리: 0, 다른페이지: 1 }`(다른 페이지 링크의 +1 · 주소 «둘째» 가 카나리아).
- `?state=` 가 걸린 주소의 판은 못 쟀다(리뷰와 같은 까닭 — 픽스처에 화면 상태가 없다). 규칙이 `<Link>` 와 글자째 같아(질의까지 견줌) 그 판도 트리 링크와 같은 이력이다(코드).

### L3 — 팝업 레이아웃의 막 아래 바탕(`e0055fa2`)

- **재현**: 같은 새 파일의 «짧은 팝업 — …». 고치기 전: 막 아래 바탕 점 `bare` 3210 · 막 바닥 − iframe 바닥 89px · 문서 끝 띠의 점이 `HTML` · 누르면 고름 `null` · 거기 놓으면 미리보기 1(Popup 몸통 끝) · 편집 1 — 리뷰 값 그대로.
- **바꾼 것**: 캔버스 기본 시트(`canvas.tsx` 의 `BASE_SHEET`)에 `[data-wb-layout="popup"] { min-height: 320px }` — 320 은 iframe 최소 높이(`canvas-iframe.tsx` 의 `MIN_HEIGHT` 를 내보내 그 값에서 짓는다). iframe 높이는 «최소 높이 · 문서 높이» 의 큰 쪽이라 막이 늘 iframe 을 다 덮고, 막 위 누름 · 놓기는 이미 막 안과 같은 «틀» 갈래를 탄다(고름 그대로 · 놓을 자리 없음). 캔버스에만 얹었다 — SDK 기본 CSS(번들 · PPTX 가 함께 쓴다)는 안 건드렸다.
- **결정 — `100vh` 로 세우지 않는다**: 처음 판 `min-height: 100vh` 는 짧은 판을 고쳤지만 창보다 긴 팝업에서 끌기 뒤 iframe 이 1631 → 1641px 로 자란 채 남았다(탐침 — 끄는 동안 빈 구역 칸이 키운 문서가 줄어도 막이 iframe 높이에 묶여 `body` 상자가 안 바뀌어 높이 관찰이 안 깬다). 그 판을 변조 L3-M2 로 남겼다.
- **긴 판**: «창보다 긴 팝업 — …»(글 마흔 줄 · iframe 1631px > 창 1000)은 고치기 전에도 초록(막이 내용 높이 = 문서 높이) — 고침이 긴 판을 안 깨는지 잠근다. 두 판 모두 막 위 − 문서 위 0 · 바닥 차 0 · 바탕 점 0 · 끌기 전후 iframe 높이 같음.
- 정본은 안 고쳤다 — 설계 「캔버스」 의 «뷰포트 폭 전체를 흐린 막 … 막은 틀이다» 는 그대로 참이다(높이는 캔버스 구현의 몫).
