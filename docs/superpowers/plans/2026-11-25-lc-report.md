## 결정

1. **트리는 트리 칸의 것을 쓴다(캔버스가 `getTree` 를 따로 안 부른다)** — 트리를 쥔 곳은 `tree/use-tree-commands.tsx` 하나다(판 번호 · `menu-changed` · 복원 뒤 다시 받기). 따로 읽으면 두 조회가 다른 판을 받아 트리 칸과 틀의 메뉴가 갈린다. 트리 칸은 좌측을 접어도 안 내려가(클래스로 접는다) 값이 산다. 트리가 아직 없거나 실패면 «지금 페이지가 트리에 없는» 내비(`gnb` 빈 목록 · `trail` 은 지금 페이지 하나).
2. **트리 응답은 차례대로 오지 않는다** — 트리 칸이 그릴 때 `sortOrder` 로 정렬한다(`menu-tree.tsx` 의 `byOrder`). `buildLayoutNav` 는 받은 차례를 쓰므로 캔버스가 넘기기 전에 메뉴 · 페이지 · 하위 메뉴를 정렬한다.
3. **페이지 이름(틀의 `title`)은 트리의 페이지 줄에서 읽는다** — 스토어는 문서만 들고 `pages.title` 을 안 든다(`getPage` 의 `title` 은 싣지 않는다). 이름 바꾸기가 트리를 다시 받아 따라온다. 트리에 없으면 빈 글.
4. **틀 누름은 링도 안 걷는다** — 설계 «아무 일도 없다» 를 글자대로. 표면 누름의 맨 앞에서 끝낸다(뷰 모드의 `beginGesture` 캡처는 그대로 돈다).
5. **`use-view-prefs` 는 공급자다(훅 하나가 아니다)** — 읽는 쪽(캔버스)과 바꾸는 쪽(T7 의 «보기»)이 셸의 다른 칸이라 값 하나를 함께 봐야 한다. 공급자 밖은 다 켬 · `set` 은 아무것도 안 함.
6. **`canvas-iframe.tsx` · `use-canvas-marquee.ts` 는 안 바꿨다** — iframe 의 높이 관찰은 `body` 와 그 자식(틀의 겉 상자)을 보아 틀이 든 높이를 따라간다. 사각형은 틀에서 시작해도 바탕과 같다(케이스로 잠갔다).
7. **«보기 메뉴 영역 이름 격리»(lt «남은 것»)는 이 트랙에 자리가 안 생겼다** — 캔버스는 영역 이름(manifest `label`)을 그리지 않는다. 틀의 페이지 이름 · 메뉴 이름은 `LayoutFrame` · `buildLayoutNav` 가 이미 `isolateBidi` 로 가둬 내린다. 영역 이름을 그리는 자리는 T7 의 «보기» 메뉴다.
8. **«앞 판 테마 … «보기» 항목 0» 은 안 쟀다** — «보기» 메뉴가 T7 이라 없다. 같은 판의 «캔버스 문서가 빈 판과 같은 상자 · 영역 0» 만 잰다.
