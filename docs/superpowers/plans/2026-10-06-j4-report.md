### 1 · 메뉴 트리에 ↑ ↓ 줄 이동이 없다(F1 이월)

**재현(Chrome).** `가1` 링크에 포커스를 두고 ↓ ×3 · ↑ — 포커스 `가1` · 고른 줄 `가1` 그대로(4번 다). 1s 누름(keydown 19) 뒤에도 그대로. 남의 바꿈 판은 ↓ 로 대상 줄에 못 가 재지 못했다(`reached: 가1`).

**고침.** `apps/web/src/panels/menu-tree.tsx` 의 `rowStep` — 줄 단추 · 페이지 링크에서 친 맨 ↑ ↓ 가 보이는 줄(DOM 의 `[data-tree-row]` 차례 — 접힌 메뉴 안은 DOM 에 없다)을 옮겨 다니며 `commands.select` 로 고르고 그 줄 단추 · 링크에 포커스를 옮긴다. 끝에서 멈춘다. `+` · `…` 의 ↑ ↓ 는 안 받는다(메뉴를 연다).

남의 바꿈 뒤:
- 고른 줄이 다시 받은 트리에서 사라지면 `use-tree-commands.tsx` 의 `reconcile` 이 `pickAfterGone`(메뉴 트리가 준 `neighborOf` — 앞 렌더의 보이는 차례에서 다음으로 남은 줄, 없으면 앞으로 남은 줄)을 고른다. 고치기 전에는 고름을 풀어 주소의 페이지로 돌아갔다.
- 포커스가 선 줄 단추 · 링크가 DOM 에서 빠진 렌더(지움 · 옮김으로 다시 그려짐)에 포커스가 `body` 면 그 줄(옮겨졌으면 새 자리) · 훅이 고른 이웃 · 보이는 이웃으로 포커스를 돌려준다(`MenuTree` 의 `focusedRow` 와 렌더마다 도는 레이아웃 이펙트). 사람이 다른 데 둔 포커스는 안 뺏는다.

**판 — 메뉴 트리의 Enter · 클릭과 ↑ ↓ 의 관계(Chrome 값).**

| 줄 | 클릭 | Enter(포커스가 그 줄) | ↑ ↓ 로 그 줄에 옴 |
|---|---|---|---|
| 메뉴 | 고른다(`aria-pressed`) | 고른다(단추의 Enter = 클릭) | 고르고 포커스 · 열지 않음(메뉴는 열 것이 없다) |
| 페이지 | 연다(주소) + 고름을 풀어 주소의 페이지가 고른 줄 | 연다(링크의 Enter = 클릭 — `가2` 에서 Enter → 열린 페이지 `가2` · 고른 줄 `가2`) | **고르기만** — 열린 페이지는 그대로(`가1`) |

**케이스.** 실브라우저 «1 · 메뉴 트리 ↑ ↓» 넷 — 보이는 줄 · 접힌 메뉴 건너뜀 · 끝에서 멈춤 · Enter 가 엶 / 1s 누름(keydown ≥ 10) · 두 번 치기 / 뷰 모드 / 남의 이름 바꿈 · 옮김 · 지움 · 하위째 지움. 서버 트리(`GET …/tree`)가 그대로인지 단언한다. jsdom `test/panels/menu-keyboard.test.tsx` «줄 옮기기 · 접고 펴기 — 읽는 키» 여섯(편집 · 뷰 × 둘 · Alt+↓ · 토글 ↓).

### 2 · 펼침 단추가 키보드 정지점이 아니다(F1 이월)

**재현(Chrome).** 편집 모드는 이미 표준 트리 꼴이었다 — 접근성 트리(CDP `Accessibility.getFullAXTree`, 무시 안 된 마디)에서 메뉴 줄 단추는 `role button · expanded true · pressed false`, 페이지 줄은 `link`(expanded 없음), «접기» · «펴기» 이름의 마디 0. `다` 줄 단추에서 Tab ×3 → `다 추가` · `다 더 보기` · `다1`(펼침 단추에 안 선다). ← → 뒤 `expanded` false → true. **결함은 뷰 모드였다** — ↑ ↓ 에 더해 ← 를 쳐도 `aria-expanded` 가 `true` 그대로(`handleKeyDown` 이 `editable` 이 거짓이면 접기 키 전에 돌아갔다). 정본은 접기를 «고르기와 같은 읽기라 뷰 모드 · viewer 에게도 선다»로 적는다.

**고침.** 읽는 키(`foldKey` · `rowStep`)를 `editable` 판정 앞으로 옮겼다. 편집 단축키(Delete · Alt+화살표)는 그대로 뒤다. 접근성 표지는 손댈 것이 없었다.

**케이스.** 실브라우저 «2 · 펼침 단추와 줄의 접근성»(고치기 전에도 초록 — 잠금) · «1» 의 뷰 모드 판 · jsdom 뷰 모드 ← →.

### 3 · 메뉴를 연 채 포커스만 캔버스로 옮기면 Delete 가 노드를 지운다(G2 이월 1)

**재현(Chrome).** 구조 줄 `글 2` 의 `…` 를 연 채 — 캔버스 iframe `contentWindow.focus()` 뒤 메뉴 1(열린 채) · 포커스 iframe, Delete 가 `글 2` 를 지움. 단추에 포커스를 둔 채 Tab 해도 메뉴 1 · 포커스 다음 줄 단추. 목록 안에서 Tab 은 이미 닫았다(메뉴 0).

**고른 길과 까닭.** 기본값 «메뉴 밖으로 포커스가 가면 닫는다». 메뉴가 밖의 Delete 까지 쥐는 길은 고르개 표지가 포커스 밖까지 쥐던 판(R2 — 캔버스 · 줌 단추의 키를 말없이 먹었다)과 같은 고장을 다시 연다. 닫으면 «열린 메뉴 = 포커스가 그 안»이 늘 참이라 표지 규칙(«포커스가 그 안일 때만 쥔다»)이 그대로 맞는다.

**고침.** `apps/web/src/shell/action-menu.tsx` 의 `closeWhenFocusLeaves` — 단추 상자의 `onBlur`(portal 된 목록의 것도 React 트리를 따라 닿는다)가 한 틱 뒤 `activeElement` 를 보고 단추 상자 · 목록 밖의 요소면 닫는다. `body`(목록의 빈 자리 · 머리 누름, 창을 떠남)는 닫지 않는다.

**케이스.** 실브라우저 «3» 둘 — 캔버스 포커스 · 단추에서 Tab · 메뉴 안에서 Tab(닫힌 뒤 Delete 는 닫힌 메뉴처럼 지운다 — 정본대로) / 머리 누름은 열린 채(포커스 `body` · 메뉴 1). `action-menu-delete.test.ts` «캔버스 포커스»의 `menusBefore` 를 1 → 0 으로 고쳤다(고침이 바꾼 값). jsdom `test/shell/action-menu.test.tsx` «포커스가 밖으로 가면» 둘.

### 4 · 구조 트리 고르개 안의 Delete 가 노드를 지운다(G2 이월 2)

**재현(Chrome).** «아래 추가» 타입 고르개의 첫 단추에서 Delete · Backspace · 1s 누름 — `글 2` 가 지워지고 고르개가 닫힘(고른 것 없음). «패턴 넣기» · «프리셋» 고르개의 Delete — `글 2` 가 지워지고 고르개는 **열린 채**(넣을 자리를 잃은 채).

**고침.** `apps/web/src/edit/editor-shortcuts.ts` 의 `keyHeldByWidget` — 셸의 표지 `[data-wb-holds-keys]` 는 값과 무관하게(열린 행동 메뉴 · 고르개) 같은 `HELD_KEYS`(화살표 넷 · Home · End · Escape · Enter · Delete · Backspace)를 쥔다. ARIA 역할 위젯은 그대로 `LIST_KEYS`(Delete · Backspace 빼고)다 — 테마가 그린 ARIA 메뉴의 Delete 를 안 먹게.

**케이스.** 실브라우저 «4» — 타입 Delete · Backspace · 누름 · 패턴 · 프리셋(서버 문서 그대로 · 고르개 1 · 고른 것 `글 2`). 메뉴 트리 «옮기기» 목록의 Delete · Backspace 는 **고치기 전에도 막혀 있었다**(`handleKeyDown` 의 `reparenting` 가드 — 확인 0 · 목록 1) — 잠금 케이스로 둔다. jsdom `test/edit/use-editor-shortcuts.test.tsx` 고르개 케이스의 «안의 Delete 는 단축키가 받는다»를 «안의 Delete · Backspace 는 쥔다 · 안의 Cmd+D 는 받는다»로 고쳤다.

### 5 · 고르개를 Escape · «취소»로 닫으면 포커스가 `body` 로 떨어진다(E-N13)

**재현(Chrome).** 줄 `+` «아래 추가» Escape · «취소» Enter · 줄 `+` «패턴 넣기» Escape · 머리 `+` «프리셋» Escape · 줄에서 Alt+Shift+I 뒤 Escape — 다섯 다 포커스 `body`(고른 것은 `글 2` 그대로). 메뉴 트리 «옮기기» 목록의 «취소» Enter 도 `body`(브리프 밖 — 같은 꼴이라 함께 고쳤다).

**고침.** `apps/web/src/panels/structure-toolbar.tsx` — `StructurePicker` 가 고르개가 설 때 마운트되는 `PickerBox` 를 그리고, 그 상자가 처음 그려질 때의 포커스(연 자리 — 줄 · 머리 `+` 는 행동 메뉴가 포커스를 `+` 로 돌려준 뒤 고르개를 연다, Alt+Shift+I · P 는 줄 단추)를 쥔다. Escape · «취소»가 포커스가 고르개 안일 때만 그 자리로 돌려준다. `apps/web/src/panels/menu-picker.tsx` 도 같은 꼴(«취소» → 줄 `…`).

**케이스.** 실브라우저 «5» 둘 — 여섯 판(연 자리 = 돌아온 자리) / 포커스를 머리 `…` 에 둔 채 «취소»에 클릭만 보냄(포커스를 안 옮기는 누름 — macOS Safari 의 단추를 흉내 냄)은 머리 `…` 에 남는다. jsdom `test/panels/menu-picker.test.tsx` 둘.

### 6 · 닫힌 `…` 토글의 ← · 카드 «넣기»의 ↑ ↓(E-N11) · 토글의 ↓ 가 메뉴를 연다(E-O4)

**정본과 견줌.** 정본 「설계서 화면 구조」의 `…` 메뉴 «단추로 열고(클릭 · Enter · Space · ↓)», 단축키 «그 밖의 위젯 안에서 그 위젯이 안 쓰는 축의 화살표 …는 선다». 닫힌 단추 · «넣기»는 키를 쓰는 위젯이 아니다. Chrome 값:

| 판 | 값 | 판정 |
|---|---|---|
| `글 2` 를 고르고 닫힌 `…` 에서 ← | 고른 것 `카드`(부모) · 메뉴 0 · 포커스 `Text 글 2 더 보기` 그대로 → Enter 하면 메뉴 1 · 고른 것 `글 2`(여는 누름이 그 줄을 다시 고른다) · 서버 그대로 | 의도(정본대로) — 대상을 쥐지 않아 해가 없다 |
| `글 2` 를 고르고 «구분선 넣기»에서 ↓ | 고른 것 `글 3` · 서버 그대로 | 의도 — «넣기»는 누를 때의 선택에 넣는다 |
| `…` 를 Escape 로 닫은 뒤(포커스 `…`) ↓ | 메뉴 1 · 포커스 첫 항목 · 고른 것 그대로 | 의도(«단추로 연다 ↓») |
| **메뉴 트리 닫힌 `가 더 보기` 에서 Alt+↓** | 메뉴 1 **이고 서버 트리 `나 · 가` — `가` 가 아래로 옮겨졌다** | **결함** — 한 키가 두 일을 했다 |

**고침(마지막 줄만).** `menu-tree.tsx` 의 `handleKeyDown` 이 맨 앞에서 `defaultPrevented` 를 거른다 — 토글이 받은(메뉴를 연) 키를 트리의 순서 이동이 다시 받지 않는다. 구조 트리는 에디터 단축키가 이미 `shortcutsBlocked` 로 거르고 있었다. 정본에 «닫힌 단추 · «넣기»는 키를 쓰는 위젯이 아니다»를 적었다.

**케이스.** 실브라우저 «6»(네 판 — 앞 셋은 고치기 전에도 초록인 잠금, 넷째가 고침) · jsdom 메뉴 트리 Alt+↓.

## 위젯 키 표 — 지금 `keyHeldByWidget` 와 트리 상자

«쥔다» = 에디터 단축키가 안 받고 `preventDefault` 도 안 건다(위젯 · 브라우저가 갖는다). «안 쥔다» = 입력 표면이 아니면 단축키로 간다. 키는 `event.key` 로만 본다(수식 키와 무관 — Alt+↑ 도 ↑ 다).

| 포커스 자리 | 쥐는 키 | 안 쥐는 키(단축키로) |
|---|---|---|
| 열린 행동 메뉴 — 단추 상자 · 목록(`[data-wb-holds-keys="menu"]`) | ↑ ↓ ← → · Home · End · Escape · Enter · Delete · Backspace | Cmd/Ctrl 조합 · `?` · F2 · Tab(메뉴가 받아 닫는다) |
| 열린 고르개(`[data-wb-holds-keys=""]` — 타입 · 패턴 · 프리셋) | 위와 같다(**Delete · Backspace 가 새로 든다**) | 위와 같다 |
| ARIA menu · menuitem · listbox · option · radiogroup · combobox(테마가 그린 것 포함) | ↑ ↓ ← → · Home · End · Escape · Enter | Delete · Backspace · Cmd/Ctrl 조합 · `?` · F2 |
| tab · tablist | 탭 줄 축의 화살표(가로 ← → · 세로 ↑ ↓) · Home · End | 직각 화살표 · Escape · Enter · Delete · Backspace · 조합 · `?` |
| separator · slider | 제 축의 화살표 · Home · End | 직각 화살표 · 그 밖 |
| 닫힌 행동 메뉴 단추(`…` · `+`) | 없음 — ↓ ↑ 는 단추가 받아 메뉴를 연다(`preventDefault` 라 단축키 · 메뉴 트리가 거른다) | ← → · Delete · Escape · 조합 · `?` |
| 컴포넌트 카드 «넣기»(`role="group"`) | 없음 | 전부 |
| 메뉴 트리 상자(`[data-wb-own-shortcuts]`) | 에디터 단축키 전부 안 선다 — 상자의 키: 줄 단추 · 링크의 ↑ ↓(줄 옮기기) · 메뉴 줄 ← →(접고 펴기) — 모든 모드 · Delete · Backspace(삭제 확인) · Alt+↑ ↓ · Alt+Shift+← →(편집 모드) | — |

## 이월 후보

1. **메뉴 트리에 Home · End 가 없다** — 표준 트리는 첫 · 끝 줄로 간다. ↑ ↓ 만 브리프 범위였다.
2. **Tab 으로 줄에 선 포커스와 고른 줄이 갈린다**(E-N15 의 메뉴 트리 꼴) — Tab 은 고르지 않아, 열린 페이지가 고른 줄인 채 다른 줄에 포커스를 두고 Delete 를 치면 열린 페이지의 삭제 확인이 선다. ↑ ↓ 는 둘을 함께 옮긴다.
3. **고르개에서 항목을 고른 뒤(넣기) 포커스는 `body` 다** — 브리프는 Escape · «취소»만 짚었다. 재지 않았다.
4. **옮기기 목록 안의 Escape 는 목록을 닫지 않는다**(`<select>` 의 Escape 는 브라우저의 것 · 단추에는 처리 없음) — 정본의 «고르개 안의 Escape 는 고르개를 닫는다»가 옮기기 목록까지 덮는지 문장이 갈린다. 재지 못했다(탐침의 두 번째 열기가 시간 초과).
5. **창을 떠났다 돌아온 판의 열린 메뉴** — 헤드리스 Chrome 은 창을 잃는 판을 못 낸다(`document.hasFocus()` 가 참). 설계상 `body` 판처럼 열린 채이지만 재지 않았다.
6. **포커스 되돌림은 트리 전체 다시 싣기(스냅샷 복원 — `reloadToken`) 뒤에도 돈다** — 줄이 내려갔다 다시 서는 사이 포커스가 `body` 면 그 줄로 돌아간다. 재지 않았다.
7. **열린 페이지(고른 줄이 아니던) 가 남의 지움으로 사라지면 고른 줄이 이웃으로 옮는다** — 캔버스는 «대상을 찾을 수 없습니다»다. `menu-realtime` 의 실브라우저 판이 게이트에서 초록인 것까지 쟀고, 그 판의 고른 줄 값은 단언하지 않는다.
8. **macOS Safari 등 누름이 포커스를 안 옮기는 브라우저**는 이 기계에서 안 잰다 — «취소» 의 «안» 판정은 Chrome 에서 `dispatchEvent('click')` 흉내로만 잰다(M16).
