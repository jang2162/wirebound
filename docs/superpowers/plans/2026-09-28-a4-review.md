## 2. 번들 적재 realm(`theme/bundle-loader.ts`)

### 2a. 번들 모양(설계대로)

| 번들 | 캔버스 · 알림 | 콘솔 |
| --- | --- | --- |
| `register` 두 번(앞은 뷰 없음) | 뒤의 것 — `샘플 카드` · 알림 없음 | `테마가 두 번 등록됐습니다 — 뒤의 것을 씁니다` |
| 최상위에서 던짐(등록 앞) | 기본 뷰 · «테마 번들이 등록하지 않았습니다(throwtop@1.0.0)» | `pageerror: top` |
| 최상위에서 던짐(등록 뒤) | `샘플 카드` · 알림 없음 | `pageerror: after` |
| 뷰가 렌더 중 던짐 | 그 노드만 `data-wb-error="테마 뷰가 던졌습니다: Error: view boom"` · 옆 노드(`원문`)는 그려짐 · 셸 알림 없음 | React 오류 3 쌍 |

- 알림 문장이 «던졌다» 와 «등록 안 했다» 를 가르지 않는다(둘 다 `take()` 가 `null`) — 무게 없음, 적어만 둔다.

### 2b. 늦은 등록이 다음 번들의 정의가 된다 — 결함(낮음)

- **판**: `late@1.0.0` 은 `setTimeout(() => register(s), 0)` · `silent@1.0.0` 은 등록하지 않는다. late 로 묶고(실패 알림) → silent 로.
- **값**: late → «테마 번들이 등록하지 않았습니다(late@1.0.0)». silent → **알림 없음 · 카드 `늦은 카드`**(late 의 뷰). silent 는 `ok` 로
  캐시돼 다시 불러와도 late 의 뷰다.
- **빨강**: `theme-review.test.ts` «늦게 등록한 번들의 정의를 다음 번들이 제 것으로 받지 않는다» → `{ alert: null, note: "늦은 카드" }`
  (기대 `{ alert: …(silent@1.0.0), note: null }`).
- **원인**: 런타임의 등록 칸 하나(`installRuntime` 의 `pending`)를 `load` 이벤트의 `take()` 가 비운다 — 어느 스크립트가 넣었는지 모른다.
  제때 등록한 번들 뒤에 오면 덮여(«두 번 등록» 경고) 드러나지 않고, **등록 안 하는 번들 뒤에서만** 선다. 같은 번들의 «다시 불러오기» 는
  앞 스크립트의 늦은 등록을 받아 «성공» 한다(같은 테마라 해는 없다).
- **고칠 방향**: `register` 가 `document.currentScript` 를 함께 적고 `take(script)` 는 그 스크립트가 돌 때 들어온 등록만 받는다 — 스크립트
  밖의 등록은 버리고 경고한다.
- **한계**: 두 번들이 다 망가져야 선다 — 관리자가 올린 신뢰 코드다(spec 「인스턴스 관리자」). 그래서 낮음.

### 2c. 번들 manifest 와 서버 manifest 가 다르다 — 결함(낮음)

- **판**: `drift@1.0.0` 의 `manifest.json`(서버)은 Card variant 에 `huge` 를 더하고 `theme.js` 의 manifest 는 plain · loud 그대로. 카드 노드의
  `variant` 를 ops 로 `huge`(200).
- **값**: 속성 패널 «변형» 선택지 `(기본) · plain · loud · huge`, 값 `huge`. 캔버스 노드 `data-wb-variant="plain"` · 알림 없음.
- **빨강**: «번들 안 manifest 가 서버 manifest 와 달라도 패널이 보이는 variant 와 캔버스가 그리는 variant 가 같다» →
  `{ panel: 'huge', drawn: 'plain' }`.
- **원인**: 캔버스의 렌더러는 `definition.manifest`(번들)로 `resolveVariant` 하고, 패널 · 패턴 고르개는 `useProjectTheme().manifest`(서버)를
  읽는다. 업로드는 `theme.js` 를 실행하지 않으므로 둘이 같은지 못 본다 — kit 은 둘을 한 `theme.config` 에서 내지만 번들이 다른 manifest 를
  import 하면 갈린다.
- **고칠 방향**: 공급자가 번들 정의의 manifest 를 서버 manifest 로 바꿔 끼운다(`{ ...definition, manifest }`) — 뷰는 번들, 선언은 서버 한 벌.
  갈리면(id · version · components) 알림 한 줄을 더할지는 함께 정한다.
- **한계**: 손으로 만든(또는 manifest 를 두 벌 둔) 패키지에서만 선다.

### 2d. 한도 뒤 늦은 등록 · 두 프로젝트

- **한도**: `slow@1.0.0` 의 `theme.js` 를 붙잡아 10s → «테마 번들이 10초 안에 오지 않았습니다(slow@1.0.0)» · 기본 뷰. 그 뒤 놓아 늦게 돌게
  하고 → 등록 안 하는 `noreg2` 로: «등록하지 않았습니다(noreg2@1.0.0)» · 카드 없음(오염 없음) → C: `샘플 카드 C`. `load` 안의 `take()` 가
  늦게 돈 스크립트의 등록을 비운다(2b 는 `load` 뒤에 등록하는 판이라 다르다).
- **두 프로젝트**: 한 문서 안에서 주소만 바꿔 P(`sample@1.0.0` · `#010101`) → Q(`1.0.1` · `#020202`) → P → Q. 네 번 다 제 카드 · 제 href ·
  제 토큰, js 요청 `1.0.0` · `1.0.1` 각 1, realm iframe 1.
- **판정**: 재현 안 됨.

## 3. 전이 멈춤(`@layer wb-hold`, `843af9cf`)

측정값은 캔버스 문서의 `style[data-wb-hold]` 유무 · 카드의 `transitionDuration` · `paddingTop`. 픽스처 `trans@1.0.0/1.0.1` 의 CSS 는
`.sample-card{padding:10px;transition:padding .3s}`.

| 판 | 값 |
| --- | --- |
| `theme.css` 응답이 영영 안 옴 | 2s 뒤 멈춤 있음 · `0s` · `0px`(시트가 안 실렸다) → 토큰 프레임 뒤에도 그대로 → 판을 1.0.1 로 바꾸면 멈춤 없음 · `0.3s` · `10px` → 페이지를 오가도 그대로 |
| `theme.css` 가 `@import` 한 시트가 안 끝남 | 3s 뒤 멈춤 있음 · `0s` · **`0px`**(Chrome 은 import 가 끝날 때까지 시트를 안 얹는다) → import 를 놓으면 멈춤 없음 · `0.3s` · `30px` |
| 시트를 기다리는 동안 페이지를 오감(iframe 이 새로 섬) | 시트를 놓은 뒤 멈춤 없음 · `0.3s` |
| 같은 link 를 1.0.0 → 1.0.1(시트 붙잡음) → 1.0.0 | 1.0.1 에서 멈춤 있음 → 1.0.0 으로 돌아오면 멈춤 없음 · `0.3s` → 붙잡은 1.0.1 을 놓아도 그대로 |

- **3a 판정**: 재현 안 됨 — 멈춤이 남는 판은 시트가 안 실린 판뿐이라 그 문서에서 살아 있어야 할 테마 전이가 없다(기본 뷰 CSS 에는
  `transition` 이 없다). 다음 판 바꿈 · 페이지 옮김이 푼다.
- **3b — `!important`**: `.sample-card{padding:60px !important;transition:padding 1s !important}`(층 밖) · 같은 것을 `@layer t {…}` 안 ·
  대조군(`!important` 없음)을 800ms 늦게 실어 rAF 마다 카드 높이. 세 판 모두 **자리 둘**(`60.7 → 215.4`) · 뒤에 `transitionDuration: 1s`.
  - 변조: `HOLD_CSS` 에서 층을 뗌(`* {transition:none !important}`) → 대조군은 둘 그대로, 층 밖 · 층 안 `!important` 판은 **자리 30 여 개**
    (`60.7, 96.4, 97.7, 99.4, … 189.7`)로 미끄러짐. 규칙을 비움 → 세 판 다 미끄러짐.
  - **층을 뗀 변조에 기존 케이스가 다 산다**: `build-test/canvas-iframe.test.ts` + `theme-canvas.test.ts` 14/14 통과 · jsdom
    `test/canvas/canvas-iframe.test.tsx` 18/18 통과(`HOLD_CSS` 머리말이 «케이스는 `!important` 없는 system-admin 으로만 잰다» 고 적은 그대로).
  - **잠금**: `theme-review.test.ts` «층 밖 !important 전이를 실은 테마 CSS 가 늦게 실려도 노드가 미끄러지지 않는다» — HEAD 초록,
    층을 뗀 변조에서 `자리 60.7, 96.4, … 215.4: expected 59 to be less than or equal to 2` 로 죽음(복원 identical). 카나리아: 시트가 실림
    (`padding 60px`) · 멈춤이 걷힘(`hold false`) · 전이가 되살아남(`1s`).
  - 남는 틈(재지 않음): 뷰가 `style` 속성에 `setProperty('transition', …, 'important')` 로 실은 전이는 층보다 앞선다(요소에 붙은 선언).
    React 의 `style` prop 은 `!important` 를 못 싣는다 — 무게 없음.

- **빨강**: «토큰 초안을 둔 채 같은 테마의 새 판으로 바꿔도 친 값이 말없이 사라지지 않는다» → `expected '#e11d48' to be '#ff5500'`.
  «토큰 초안을 둔 채 고르개가 409 로 다시 읽어도 …» → `expected '#000000' to be '#ff5500'`.
- **원인**: `settings/token-editor.tsx` 의 `useEffect(() => setDraft(draftOf(view.manifest, view.tokens)), [view])` — 절이 넘긴 바인딩 객체가
  바뀌면 무엇이 바꿨든 초안을 서버 값으로 다시 세운다. 토큰 편집기 제 저장 · «서버 값으로» 에는 맞고, 옆 고르개의 저장 · 409 다시 읽기에는
  초안을 말없이 버린다.
- **고칠 방향**: 초안이 바탕(`baseline`)과 다르면 바인딩이 바뀌어도 초안을 지우지 않고 새 manifest 로 옮긴다(`migrateTokens(옛 manifest,
  새 manifest, 초안)` — 이어진 키는 남고 버려진 키는 확인 상자가 센다). 또는 고르개의 «바꾸기» 가 저장 안 한 초안이 있으면 확인 상자에
  그 수를 싣는다. 케이스는 앞쪽(초안이 남는다)으로 적었다 — 뒤쪽을 고르면 케이스의 단언을 «말한다» 로 바꾼다.
- **한계**: 저장 안 한 화면 상태를 잃는 것이다(서버 데이터는 안 잃는다). 페이지를 떠날 때의 경고가 없는 것은 보고서가 이미 이월로 적었다.

### 4b. «내 값으로 덮기» 가 남이 바꾼 판을 되돌리나

- **판**: 초안 `#ff5500` → API `#111111`(rev 2) → «토큰 저장» → 409(같은 판 — «다른 사람이 먼저 저장했습니다 — 다른 칸만 나란히 봅니다») →
  API 로 판을 `1.0.1`(rev 3) → «내 값으로 덮기».
- **값**: 둘째 409 → 문장 «다른 사람이 테마를 sample@1.0.1 으로 바꿨습니다 — 서버 값으로 다시 섭니다» · «내 값으로 덮기» 단추 0 · 서버
  `{ version: '1.0.1', rev: 3 }` 그대로 · 초안 칸 `#ff5500` 남음.
- **판정**: 재현 안 됨 — 덮기는 409 의 `current.rev` 를 싣고, 그 뒤 판을 바꾼 저장은 `rev` 를 올려 둘째 409 가 된다.
