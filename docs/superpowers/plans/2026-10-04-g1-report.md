## 요약

- **행동 메뉴의 펼친 목록**(트리 줄 `+` · `…` · 트리 머리 `+` · 셸 `…` · 셸 밖 화면 머리 `…`)을 `document.body` 로 portal 하고 단추 상자로 지은 `position: fixed` 좌표에 놓는다 — 아래가 모자라면 넓은 쪽(맨 아래 줄은 위), 창 밖이면 창 안으로. 열린 동안 칸 스크롤 · 창 크기 · 단추 이동을 프레임마다 따라가고, 단추가 칸의 보이는 자리 밖으로 굴러가면 닫는다.
- **캔버스 도구**(뷰포트 폭 · 줌)를 하단 바에서 머리의 «편집 / 뷰» 뒤 · `…` 앞(구분선 뒤)으로 옮겼다. 두 모드 모두에 선다. 창 930 아래는 «뷰포트 폭» 글을 눈에서만 감추고, 875 아래는 줌 묶음을 `…` 의 첫 항목 셋으로 접는다. 하단 바는 통지 + «컴포넌트»이고 높이 40 을 지킨다.
- **portal 은 지금 셸에서 짐을 안 진다**(변조 M1) — 잘림을 고친 것은 고정 좌표다. portal 은 조상이 포함 블록 · 쌓임 맥락이 되는 판의 보험이고 브리프의 설계라 남겼다(아래 «이월 후보» 1).

## 이월 후보

1. **portal 을 걷을지**(변조 M1) — 지금 셸에서 portal 을 떼고 고정 좌표만 둬도 15 자리 · 성질 케이스가 다 초록이다. portal 이 부른 보정 넷(바깥 누름 `inside` · `data-wb-own-shortcuts` 옮겨 싣기 · Tab 처리 · 팔레트 루트)과 jsdom 케이스 13건(머리 안에서 메뉴를 찾던 것)의 이사가 그 값이다. 남기는 근거는 앞으로 트리 · 머리의 조상에 `transform` · `filter` · `contain` 이 걸리거나 쌓임 맥락이 생기는 판(놓을 자리 표시 `drop-indicator.tsx` 가 같은 위험을 머리말에 적고 있다). 걷으면 단추 상자 안에 그리는 판으로 돌아가고 보정 넷이 사라진다.
2. **접힌 머리(창 875 아래)에서 지금 배율이 안 보인다** — 줌 값이 묶음째 `…` 로 갔다. 또 `…` 의 «확대»를 누르면 메뉴가 닫혀, 여러 칸 밀려면 다시 연다.
3. **열린 행동 메뉴 안의 Delete 가 고른 노드를 지운다**(정본 «단축키» 그대로 · 고치기 전과 같음) — 브리프 문장(«메뉴 안의 Delete 가 뒤 트리의 명령이 되지 않는지»)과 갈린다. 메뉴가 Delete 도 쥐게 하려면 `keyHeldByWidget` 의 메뉴 판에 Delete · Backspace 를 더하는 정본 결정이 먼저다.
4. **문턱은 창 폭이다** — 이름이 긴 프로젝트는 문턱 위에서도 머리가 두 줄로 줄을 바꾼다(넘치지 않음). 창 700 의 여유는 17px 이고 다른 OS 글꼴로는 안 쟀다.
5. **뷰 모드 · viewer 의 하단 바는 통지가 없으면 빈 40px 줄이다** — 기본값(높이 유지)대로 뒀다. 줄일지는 스크린숏을 보고 정한다(줄이면 모드를 바꿀 때 캔버스 칸이 28px 튄다).
6. **자리 판(잘림 행렬)에 안 든 자리** — 메뉴 트리 줄 `…` · 메뉴 트리 머리 `+` · 셸 밖 화면 머리 `…`. 같은 부품 · 같은 판정이고 고르기는 잰다.
7. **창 700 의 아이콘 단추 넘침 판**(`icon-buttons` «좁은 칸»)은 줌 묶음이 접혀 줌 단추 셋을 안 잰다 — 1440 판이 잰다.
