**원인(값으로 가름):**

1. **변환 전 폭이 넘침으로 잡힌다** — `scrollWidth` = 프리셋 + 안쪽 여백 48(1920 → 1968). 보이는 오른끝은 칸 안(843 < 867)인데 가로 막대가 선다. 프레임이 칸의 흐름 속 자식이라 그 레이아웃 폭(`transform` 전)이 넘침이 됐다.
2. **좁은 프리셋의 가운데 정렬 여백을 못 읽는다** — `getComputedStyle(frame).marginLeft` 가 `'0px'`(쓰인 값 222 · 25.5) → `fitZoom` 이 여백을 안 빼 넘게 키운다(375: 오른끝 996 > 867, 768: 868.5 > 867). `fitZoom` 머리말에 있던 «Chrome 은 쓰인 값 55.5px 를 준다»는 이 판에서 재현되지 않았다.
3. 세로 스크롤바 폭 — 0(헤드리스 오버레이 스크롤바, `offsetWidth − clientWidth` = 0). 원인 아님. 반올림 — 원인 아님.

## 계획과 달라진 것

1. **`SessionMenu` 컴포넌트는 남겼다**(D3 은 «걷음»). 설정 · 토큰 · 테마 관리 머리가 쓴다 — 앞 둘은 C3 의 파일이라 걷으면 병합 충돌이다. 흐름은 `useLogout(settle)` + `SessionNotices` 로 뺐고 `SessionMenu` 는 그 위에 선다. C3 · C4 가 그 머리를 바꾼 뒤 걷을 수 있다.
2. **`<footer>` 는 `contentinfo` 랜드마크다**(계획은 «아니다»). 셸 그리드의 `div` 바로 아래라 구역 요소 안이 아니다 — 케이스가 `getByRole('contentinfo', { name: '하단 바' })` 로 찾는다.
3. **바깥 누름은 `mousedown`** 이다(D1 케이스 문장은 `pointerdown`) — `usePopoverDismiss` 의 계약. 포커스는 «메뉴 안에 있었을 때만» 단추로 돌려준다(바깥 누름은 누른 자리가 포커스를 가져간다).
4. **대화 상자의 Escape 에 한글 조합 가드를 더했다**(`compositionstart/end` 로 조합 구간을 든다 — 모달의 `cancel` 에는 `isComposing` 이 없다). jsdom 스텁으로만 잰 것 — 실브라우저에서 조합 중 Escape 가 `cancel` 을 내는지는 안 쟀다(이월).
5. **모달이라 열린 동안 하단 바가 `inert`다.** 복원 답을 잃은 문장을 «화면 위 «다시 불러오기»» → «이 상자를 닫고 하단 바의 «다시 불러오기»»로 바꿨다(조각 «복원됐는지 알 수 없습니다»를 단언하는 2 자리는 그대로 참). `editor-restore-unanswered` 에 «Escape 로 닫고 누른다» 걸음을 더했다.
6. **`…` 의 접근 이름은 «더 보기»**(에디터 · 목록 같음), 대화 상자 제목은 «스냅샷» · «프로젝트 내보내기». 몸체의 `role=group` 이름(«스냅샷» · «내보내기»)은 기존 케이스를 위해 남겼다.
