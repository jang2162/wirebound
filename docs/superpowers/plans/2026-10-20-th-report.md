브랜치 `feat/default-theme` · 기준 main `084d7027` · 브리프 `.worktrees/.coord/brief-th.md`.

## 바꾼 것

- `system-themes/{commerce,docs,portal,saas-marketing}` 를 걷었다 — 소스 · 케이스 · build-test · `checksums.json` · 루트 `tsconfig.json` 참조 · `vitest.config.ts` 별칭 · lockfile. 워크스페이스(`system-themes/*`) · `pnpm build`(`--filter './system-themes/*'`) · Dockerfile(`COPY . .` · 테마별 줄 없음)은 글롭이라 고칠 줄이 없었다.
- `system-admin` 의 보이는 이름 `'관리자'` → `'기본테마'`. 바이트가 바뀌므로 판을 `1.2.0` → `1.2.1` 로 올렸다(같은 판이면 그 판을 넣은 DB 의 기동이 «이미 올린 버전의 내용이 바뀌었습니다» 로 멈춘다). `checksums.json` 에 `system-admin@1.2.1` 줄을 빌드 산출물의 sha256 으로 더했다(배포한 판의 줄은 그대로). id · 패키지 이름 · 폴더는 그대로.
- 마이그레이션 `0027-retire-system-themes` — 넷에 고정한 프로젝트를 `system-admin` 최신으로 옮기고 넷의 패키지를 숨긴다.
  - 처음 `0026` 으로 지었다 — main 에 `pm` 의 `0026-personal-modules` 가 병합돼 `0027` 로 옮겼다(몸체는 같다 · 아래 M1–M5 는 `0026` 이름일 때 잰 값이다).
- 기동 시딩(`apps/api/src/services/system-themes.ts` 의 `findArtifacts`)이 `package.json` 이 있는 테마 디렉터리만 읽는다.
- 걷은 넷을 쓰던 케이스를 옮겼다(아래 「케이스」).

## 결정과 이유

### 넷의 `theme_packages` 행은 지우지 않고 숨긴다

| 무엇이 테마 id 를 가리키나 | 행을 지우면 | 행을 남기고 숨기면 |
| --- | --- | --- |
| `projects.theme_id/version`(FK `projects_theme_fk` RESTRICT) | 옮긴 뒤라 FK 는 선다 | 옮긴 뒤라 아무도 안 가리킨다 |
| 판 3 스냅샷 payload 의 `theme`(FK 없음 · JSON) | 복원이 6′단계에서 `missing-theme` 409 로 **복원 전체가 멈춘다**(`apps/api/src/services/restore.ts`) | 복원이 선다 — 숨긴 판도 받는다(spec 「스냅샷」 «숨긴 버전이어도 된다») |
| 내보낸 번들 | 영향 없음 — 번들이 `theme.js` · `theme.css` · 자산을 제 안에 싣는다(`packages/exporter/src/bundle/index.ts:193`) | 같음 |
| 테마 고르개 · 목록(`GET /api/theme-packages`) | 안 보인다 | 숨긴 판은 관리자에게만 보인다 · 새로 못 고른다 |
| 시딩 | 산출물이 없어 다시 안 넣는다 | 같음 · 있는 행은 안 건드린다(숨김 유지) |
| CLI · MCP | 프로젝트가 고정한 manifest 를 `GET …/theme` 로 읽는다 — 옮긴 뒤엔 admin | 같음 |
| 웹 단위 케이스의 이름 목 · test-support | 테마 id 를 실물로 안 쓴다(목) · `systemThemeVersion` 은 산출물에서 읽는다 | 같음 |

설계서가 «패키지는 불변이고 지우는 길이 없다» 를 못박고(정본 §6 · `0019` 머리말) 스냅샷이 그것에 기대므로 지우면 옛 스냅샷 복원이 깨진다. 숨기면 깨지는 판이 없다 — **옛 스냅샷을 복원하면 프로젝트가 숨긴 그 판(예: `system-saas-marketing@1.0.0`)으로 돌아간다**(«그때 그 화면»). 그 뒤 owner 가 설정에서 기본테마로 바꿀 수 있다. 복원이 넷을 `system-admin` 으로 읽게 하는 길은 고르지 않았다 — spec 의 «판 3 복원은 바인딩도 되돌린다» 를 뒤집고, 행이 있는데 다른 테마로 읽는 갈래를 새로 세운다. 코디네이터가 «복원도 기본테마로» 를 원하면 restore 6′단계에 한 갈래를 더하는 일이다.

관리자는 테마 관리 화면에서 넷의 판을 되살릴 수 있다(숨김의 정의 그대로) — 되살리면 다시 고를 수 있다.

### 토큰은 화면의 테마 바꾸기와 같은 값으로 잇는다

키가 겹친다(넷 모두 `semantic.primary` · `semantic.primarySoft` 등). `migrateTokens`(설정 화면 · `GET …/theme/impact` 가 부르는 한 함수)로 키 · 타입이 같은 값을 잇고, `PUT …/theme` 처럼 새 기본값과 같은 값을 뺀다. 옛 토큰은 이미 길이 · 전체 한도를 지난 값이라 그 부분집합도 지난다 — 그래서 `services/theme-tokens.ts` 를 마이그레이션에 끌어오지 않았다. `theme_rev` 는 1 올린다(열린 화면의 낡은 저장이 409 를 받는다).

### `down` 은 되돌리지 않는다

옮기기 전의 바인딩 · 토큰과 «마이그레이션 전에 이미 숨겼던 판» 을 적어 두지 않았다. 숨김을 다 풀면 관리자가 숨긴 판까지 고를 수 있게 되므로 좁은 쪽(아무것도 안 함)을 골랐다. 머리말에 적었다.

### 시딩은 `package.json` 이 있는 테마 디렉터리만 읽는다

걷은 테마는 체크아웃에 무시된 `dist/*.wbtheme` 를 남긴다(`git pull` 은 추적 파일만 지운다 — 이 워크트리에서 `git status --ignored system-themes` 로 넷의 `dist/` · `node_modules/` · `.tsbuild/` 가 무시된 채 있음을 봤다). 시딩은 `<dir>/*/dist/*.wbtheme` 를 다 읽었으므로 옛 체크아웃의 **새 DB**(개발 · 테스트)에 넷이 숨김 없이 다시 들어왔을 것이다. 운영 이미지는 `.dockerignore` 의 `**/dist` 로 안 실린다. 체크섬 자(`apps/api/test/system-theme-checksums.test.ts` 의 `themeDirs`)와 global-setup(`theme.config.ts`)이 이미 같은 규칙으로 테마를 고르므로 맞췄다. `SYSTEM_THEMES_DIR` 의 계약이 «`package.json` 이 있는 테마 디렉터리» 로 좁아진다 — `config.ts` · `.env.example` · `apps/api/README.md` 에 적었다.
