# FX2-CF 보고 — 묶음 포커스가 곧 고름

브랜치 `feat/comment-focus`(시작 머리 `53b5bdb9`)에서 좁은 반증 `docs/superpowers/plans/2026-11-14-rv2-cf-report.md` 의 M-1 · M-2 를 사용자의 결정(«코멘트» 탭 묶음에
포커스가 가면 그것이 곧 고름)으로 닫았다. 값은 따로 적지 않으면 실브라우저(Chrome · dev 번들 · `editor-stack` · 창 1600×900 · 줌 1 · 기본테마)다. jsdom 값은
«jsdom» 이라 적는다.

## 바꾼 것

- `apps/web/src/panels/comment-panel.tsx` — 묶음 `li` 의 `onFocus`(React 의 `focusin` — 묶음 자신 · 그 안의 단추 · 글 상자)가 링과 함께 곧바로 고른다(`showNode` —
  화면 상태 · 펼침 · 칸 굴림). `onClick` 은 묶음 자신을 누른 판(`pickTarget`)에서 다시 고른다 — 이미 포커스가 선 묶음을 다시 누르면 새 `focus` 가 없다.
  Enter/Space 는 그대로. 토큰 링크에 든 포커스는 링만 세운다(`tokenLink` — 아래 «결정» 2). 머리말의 몸짓 표 · 문단을 지금 규칙으로 썼다.
- `apps/web/src/comments/comment-pointing.tsx` — 머리말 «펼침» 의 «포커스로는 안 펼친다» 를 «고를 때 곧바로 펼친다» 로.
- 정본 `docs/superpowers/specs/2026-08-03-wirebound-design.md` «코멘트» 탭 — 셋(포커스 — 링 · 고름 — 보이게 · 머리 단추)을 둘(포커스가 곧 고름 · 머리 단추)로.
  고름은 곧바로이고 곧이어 한 다른 몸짓을 덮지 않는다 · Tab 훑기 · 글 고르기도 화면을 바꾼다 · 같은 노드를 거듭 고르면 같은 답 · 토큰 링크는 링만 ·
  걷히는 때(링 · 펼침 · 포커스가 묶음 밖으로 나가기만 해서는 안 걷힘 · 탭으로 돌아와도 다시 안 고름). «링 · 고른 노드를 캔버스 칸 안으로 굴린다» 의
  «링이 설 때» 에서 «묶음에 포커스가 듦» 을 뺐다(이제 그것은 고름이다 — 같은 문장의 «묶음을 고를 때» 가 덮는다). 연대기 낱말(더한 줄의 «이제 · 바뀌었 ·
  앞 판 · 더는 · 지금은 · 원래 · 고쳤 · 뒤집») 0 · «전에는» 3 은 모두 조건(«… 들기 전에는») · 숨은 글자 0.

### 걷은 것

`PICK_WAIT_MS`(과 그 `DOUBLE_CLICK_MS` import) · `textSelectedIn` · `pendingPick` · `latestShowNode` · `cancelPick`(과 그 언마운트 정리 이펙트) · `detail === 0` /
`detail > 1` 갈래 · 머리말 «글을 고르는 몸짓도 고름이 아니다» 문단. 케이스 쪽 — `pickSettled` · `PICK_WAIT_MS` import · jsdom `pastWait`. 실브라우저의 `pickedInto`
는 간격을 안 기다리는 `stateIs`(두 프레임 뒤 한 번 읽기)로 이름째 바꿨다.

낱말 셈(`git grep -n -w -E '<이름>' -- ':!docs/superpowers/plans'` · 파이썬 `re` 유니코드 경계로 한 번 더 — 같은 수): `PICK_WAIT_MS` 0 · `textSelectedIn` 0 ·
`pendingPick` 0 · `latestShowNode` 0 · `cancelPick` 0 · `pickSettled` 0 · `pickedInto` 0 · `pastWait` 0. 맨 낱말 «미룬 고름» 은 `apps/web` 소스 · 케이스에 0, 정본에 0.
«더블클릭 간격» 이 남은 자리는 이 트랙과 무관한 셋(행동 메뉴 · 팔레트 · 그 케이스들)과 새 실브라우저 케이스의 `chooseState`(전환기 메뉴의 둘째 누름 삼킴을
비켜 가는 기다림 — `DOUBLE_CLICK_MS` 를 가리킨다) · 새 판의 «늦게 서는 고름이 있으면 섰을 때까지» 기다림(700ms — 더블클릭 간격보다 넉넉히)이다.
`docs/superpowers/specs/2026-11-13-comment-focus-design.md`(이 기능의 날짜 붙은 설계안 — 이력)는 옛 규칙(«Tab 으로 들기만 해서는 상태를 안 바꾼다»)을 그대로 둔다.

## 결정

1. **«같은 답» 은 거듭 불러서 지킨다 — 거르지 않는다.** `focusin` 은 묶음 안에서 자식 사이로 옮길 때마다 다시 서고, 포인터 누름은 `focus` 뒤에 `click` 이
   따라 한 몸짓에 고름이 두 번 선다. 둘째 고름은 그 사이 렌더가 끝나 있어 상태는 이미 보이고(`stateShowingNode` 의 `change` 가 거짓), 펼침은 새 값이지만 그
   노드가 칸 안이라 굴리지 않는다(V1 의 1px 거름 — 실브라우저 V1 판 «포커스가 선 묶음의 작성자 줄 누름» 이 쓰기 수가 그대로임을 잰다). 그래서 «묶음 밖에서 들어온
   포커스만» 같은 거름을 두지 않았다 — 두면 «이미 포커스가 선 묶음 안의 단추를 다시 누른» 판이 고름을 잃는다.
2. **토큰 링크에 든 포커스는 고르지 않는다(브리프 «토큰 링크 누름도 그 묶음의 고름이다» 를 고쳐 짬).** 문장 그대로(링크 포커스도 고름) 짠 판을 실브라우저로
   재니 데려간 노드가 가려졌다: 픽스처 `n_x`(`except s_admin`) · `n_b`(`only s_admin`) 의 코멘트에 `n_x` 번호 토큰 → 링크 누름 → 700ms 뒤
   편집 `{ state: '관리자', drawn: 0, selected: [] }`(진짜 선택은 `n_x` 이나 숨어 외곽선이 없다) · 뷰 `{ state: '관리자', drawn: 0 }`. 링크를 누르면 포커스가 먼저
   들어(`mousedown`) 고름(관리자)이 서고 그 뒤 `click` 이 `?node=n_x` 로 고르기 때문이다. 링크에 든 포커스는 링만 세우게 했다(`tokenLink`) — 키보드로 링크에
   들어도 같다(묶음 밖에서 Shift+Tab 으로 링크에 바로 든 판은 고름이 없다 · 묶음 앞 순서로 Tab 하면 묶음 `li` 가 먼저 골라진다). 고친 뒤
   `{ state: '기본', drawn: 1, selected: ['n_x'] }`. 다른 페이지 토큰(`wb:page/…`)은 데려간 페이지 · «뒤로» 돌아온 첫째 다 `기본`(화면 상태는 페이지를 옮기면
   기본으로 돌아간다 — 이 장치와 무관하게 참이다).
3. **묶음 안 단추 · 글 상자의 `click` 은 다시 고르지 않는다(`pickTarget` 을 남김).** 포커스가 들 때 이미 골랐고, 남기지 않으면 토큰 링크의 `click` 이 데려간
   뒤에 묶음 `li` 의 `onClick` 이 그 묶음을 다시 골라 «결정» 2 를 되연다(변조 X4). 대가 — 포커스가 «수정» 단추에 선 채 사람이 전환기로 상태를 바꿨다가 그
   단추를 다시 누르는 판은 다시 고르지 않는다(전환기를 누르면 포커스가 나가므로 실브라우저에서는 그 판이 «다시 든 포커스» 로 고른다 — jsdom 만 그 판을 세운다).
4. **펼침은 하나라 다른 묶음에 든 포커스가 앞 펼침을 걷는다.** M2 의 걷힘 규칙(«다른 묶음을 고름 — 그 노드로 바뀜»)을 그대로 두었다. 옛 규칙에서 «다른 묶음으로
   옮겨도 되돌리지 않는다» 가 참이었던 것은 포커스가 고름이 아니어서였다 — 이제 다른 묶음에 들면 그 묶음의 고름이 이긴다. 묶음 밖(우측 탭 단추 · 폼)으로
   나가기만 하면 남는다. 화면 상태는 다르다 — 다른 노드가 이미 보이면 안 바꿔 앞 고름의 상태가 남는다(정본에 둘을 따로 적었다).
5. **우측 탭이 «코멘트» 로 돌아올 때** — 패널이 다시 서도 묶음에 포커스를 돌려주는 장치가 없어(`apps/web/src` 의 코멘트 쪽 `.focus(` 0) 다시 고르지 않는다.
   케이스로 잠갔다(«우측 탭을 옮겼다 «코멘트» 로 돌아와도 …»).
6. **머리 단추와 묶음 고름이 겹친다** — 머리 단추를 누르면 포커스가 묶음에 들어 고름이 먼저 서고, `click` 이 고름 + 진짜 선택 + «컴포넌트» 탭을 한다. 고름이
   적은 «고를 때의 선택» 이 진짜 선택이 바뀌며 달라져 그 펼침은 걷히고 진짜 선택의 펼침이 선다(앞 차수와 같은 길) — 기존 케이스 둘(jsdom · 실브라우저)이 그대로
   초록이다.

## 남은 것

1. **좁은 반증 «낮음» 의 판** — L-1(간격 안 탭 옮김 · 캔버스 누름으로 고름이 사라짐)은 간격이 없어져 성립하지 않는다(고름이 누른 그 렌더에 선다). L-2(첫 링 굴림이
   칸을 가로로 20px 민다)는 이 트랙이 안 건드렸다 — 그대로다. L-3(뷰 모드에서 상호작용이 연 탭 안 노드의 묶음을 고르면 펼침이 겹layer 의 `active` 를 안 봄 —
   원래 있던 길)도 그대로다.
2. **창이 포커스를 잃었다 돌아오면** 묶음에 선 포커스가 `focus` 를 다시 받아 다시 고른다 — 그 사이 휠로 밀어낸 링이 끌려온다(상태는 같은 답이라 안 바뀐다).
   헤드리스 Chrome 은 창을 잃는 판을 못 내 재지 않았다(`.ruler` 「워커에게 맡길 때」 의 «헤드리스 Chrome 은 창을 잃는 판을 못 낸다»). 거르려면 `blur` 때
   `document.activeElement` 가 그 묶음에 남는지(창이 포커스를 잃음)를 적어 두고 다음 `focus` 를 넘기는 장치가 필요하다 — 사람의 판단거리.
3. **묶음 밖에서 Shift+Tab 으로 묶음의 마지막 토큰 링크에 바로 든 판**은 고름이 없다(«결정» 2) — 링만 선다.
4. **사용자가 바꿀 수 있는 판단** — «결정» 2(토큰 링크는 링만) · «결정» 3(포커스가 든 뒤 묶음 안 단추 · 글 상자의 `click` 은 다시 고르지 않음) · «결정» 4(다른 묶음에
   든 포커스가 앞 펼침을 걷음).
5. **못 잰 것** — Firefox · Safari(Safari 는 단추 · 링크를 눌러도 포커스를 안 준다 — 그 판의 «묶음 안 단추 누름» 은 `click` 이 `pickTarget` 에 걸려 고르지 않는다) ·
   운영 번들(`EDITOR_STACK_BUNDLE=build`) · 터치 · 펜.

## 지침

- **무엇이 빠졌나:** 고름 · 상태 전환을 `focusin` 에 거는 장치는 그 묶음 안의 **링크**가 받는 누름과 겹친다 — 누르면 `mousedown` 의 포커스가 먼저 들어 고름이
  화면 상태를 바꾸고, 그 뒤 `click` 의 링크가 다른 노드를 고르는데 그 노드가 바뀐 상태에서 숨는다. 브리프 문장(«토큰 링크 누름도 그 묶음의 고름이다»)을 그대로
  짠 판이 실브라우저에서 그랬다(«결정» 2). jsdom 은 `fireEvent.click` 이 포커스를 안 줘 이 차례가 안 선다.
- **어느 문서 어느 절:** `.ruler/30-delegation.md`(생성물 `AGENTS.md`) 「워커에게 맡길 때 — wirebound」 의 «**«포커스가 서면 …한다» 장치를 새로 걸면 포인터가 준
  포커스를 먼저 센다**» 문장 뒤.
- **넣을 문장:** «**포커스가 들면 화면을 바꾸는 장치는 그 안의 링크 · 이동 단추를 누른 판을 센다** — 누름의 포커스(`mousedown`)가 먼저 화면을 바꾸고 그 뒤
  `click` 이 데려간 대상이 바뀐 화면에서 가려진다(코멘트 묶음의 토큰 링크 — `apps/web/src/panels/comment-panel.tsx` 의 `tokenLink`). 데려간 대상이 그 화면에서
  숨는 픽스처로 실브라우저에서 잰다 — jsdom 의 `fireEvent.click` 은 포커스를 안 줘 그 차례가 안 선다.»
