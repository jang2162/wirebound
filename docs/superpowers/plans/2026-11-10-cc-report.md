## 결정

- **대표 글 타입은 계획의 여덟 그대로**(`Button.label` · `Link.label` · `Text.content` · `Chip.label` · `Affix.text` · `Placeholder.label` · `TabPanel.label` · `Input.value`). 카탈로그를 훑어 뺀 것: `Field.label` · `GridColumn.label` · `GridColumnGroup.label`(칸 · 열 머리 — 코드 이름이 아니라 칸 이름이다), `TextArea.value`(여러 줄 글), `Section` · `Card` 의 제목(구획 이름), `KeyValue` · `FileAttach` · `Tree` 의 줄(노드가 아니다).
- **`broken-code-ref` 를 둘로 갈랐다 — `broken-code-ref`(error · 없는 그룹 · 항목) · `broken-code-selected`(warning · 묶인 선택 위젯의 고른 값이 없거나 사용 안 함).** 계획은 한 규칙이 경우에 따라 severity 를 바꾸게 적었지만, lint 표(`lint/rules.ts`)는 «severity 는 규칙이 든다 · 만드는 자리가 고르지 않는다»를 타입으로 지킨다(`lintIssue`). 한 규칙에 두 등급을 두려면 그 장치를 풀어야 해서 규칙을 나눴다. Review Focus 3 의 «`broken-code-ref` 경고»는 이 판에서 `broken-code-selected` 경고다.
- **`broken-code-ref` 만 lint 의 자기 규칙 가운데 `error` 다** — `rules.ts` 머리말 «severity 축»이 «자기 규칙은 warning · info» 라 적었던 자리에 예외 하나와 까닭을 적었다(설계 「lint」 가 오류로 정했다).
- **공통코드 규칙은 페이지만 본다** — `LintProject` 에 레이아웃 · 모듈이 없다(입력 모양 그대로). 레이아웃 · 모듈의 참조는 사용처(`codeUsage`)가 센다.
- **`nodeDisplayName` 의 표 인자는 셋째 자리다** — 둘째(`NamingContext`)는 노드마다 짓는 맥락이라 거기 표를 실으면 맥락을 짓는 자리(`namingContexts`)마다 표를 들고 다녀야 한다.
- **코드 쓰기의 첫 잠금은 `lockProjectTree`(프로젝트 행 `FOR NO KEY UPDATE`)** — 같은 프로젝트의 코드 쓰기를 한 줄로 세워 «키 겹침 · 상한을 읽고 판정»하는 사이에 남이 못 끼게 하고(유일 제약 위반을 트랜잭션 안에서 맞지 않는다), 복원 · 프로젝트 삭제의 `FOR UPDATE` 뒤에 서게 한다. 순서는 «프로젝트 행 → 코드 행 → 재확인» — `lockProjectShared` 머리말이 잰 교착 판과 같은 방향이라 프로젝트 삭제가 코드 행을 CASCADE 전에 따로 잡지 않아도 된다. 대가는 코드 쓰기가 같은 프로젝트의 트리 쓰기(메뉴 · 페이지 생성 · 이동 · 가져오기)와 한 줄에 서는 것이다.
- **응답 꼴** — 쓰기는 고친 그룹(`{ group }`) · 항목(`{ item }`)만 낸다(표 전체를 내지 않는다 — 많으면 그룹 500 × 항목 200). 사용처는 `{ usage }`, 사용 수는 `{ counts }` 로 감쌌다(다른 목록 응답 `{ modules }` 와 같은 꼴). 겹친 키 · 값의 409 는 `issues[0].code = 'code-key-taken'` 이다.
- **사용처의 페이지 차례는 `sort_order` · id** — `withApi` 는 한 트랜잭션이라 `created_at` 이 같아(AGENTS.md «목록의 차례를 단언하는 케이스»), 만든 차례로 정렬하면 차례가 무작위였다.
- **복원은 코드 행을 따로 잠그지 않는다** — `lockProjectForRestore` 에 코드 표를 더하지 않았다. 코드 쓰기는 모두 프로젝트 행을 `FOR NO KEY UPDATE` 로 먼저 잡아 복원의 `FOR UPDATE` 뒤에 서므로(`restore-lock-census` 의 여섯 줄이 «막힌다»를 잰다) 행 잠금 없이도 복원 중에 표가 안 바뀐다. 코드 행을 쓰는 다른 길이 생기면 그 길도 프로젝트 행을 먼저 잡아야 한다(`routes/codes.ts` 머리말).
- **판 4 복원은 표가 같아도 덮고 신호를 낸다** — `set-theme` 와 같은 판정(계획이 «같은가»를 견주지 않는다). 판으로 가른다 — 판 3 인데 `codes` 가 든 손댄 payload 는 표를 안 건드린다.
- **복원 응답(`summary`)에 공통코드 수를 싣지 않았다** — 화면의 복원 확인 상자는 «공통코드 표도 그 시점으로 돌아갑니다» 한 줄만 말한다(태스크 7 이후 웹).
- **«하나만 고르는 타입»의 정본은 선택지 칸의 `select: 'one'`**(`picksOneChoice`) — 타입 이름 목록을 두 벌 두지 않는다.
