## H1 — Delete 를 누르고 있거나 두 번 치면 부모 컨테이너까지 지운다(높음 · 새 길)

**판.** 페이지 `[카드[글 1, 글 2, 글 3], 글 4, 글 5, 단추]`. 캔버스에서 «글 2»를 눌러 고름(포커스 `IFRAME>BODY`).

| 조작 | e1 서버(뿌리 자식 전위) · `headSeq` | main |
|---|---|---|
| Delete 를 1s 누름(CDP `autoRepeat` — 첫 반복 400ms · 33ms 간격 · keydown 18) | `[글 4, 글 5, 단추]` · 1→**3**(편집 2) — «글 2» 다음 **카드(글 1 · 글 3 포함)** 가 지워졌다. 끝 선택 = 뿌리 | (재지 않음 — 아래 «두 번» 판처럼 main 에는 캔버스 문서 리스너가 없다) |
| Delete · 150ms · Delete(따로 두 번) | 같음 — `[글 4, 글 5, 단추]` · 3 | 변화 없음 · 1 |
| 구조 트리 줄 «글 2»에 포커스 · Delete 1s 누름 | 같음 — `[글 4, 글 5, 단추]` · 3 | `[카드[글 1, 글 3], 글 4, 글 5, 단추]` · **2**(한 번만) · 끝 선택 = 카드 |

화면 = 서버(트리 줄 차례가 서버 전위와 같다) · 통지 0. 되돌리기로 돌아오는지는 이 판에서 재지 않았다(편집 둘 — 되돌리기 둘이 필요하다).

**원인.** 키보드 삭제는 `useStructureCommands` 의 `removeSelected` 를 부르고 그것이 지운 뒤 **부모를 고른다**(`apps/web/src/panels/structure-toolbar.tsx` 의
`removeSelected` — `store.selectNode(spot.parentId)`). main 에서는 같은 함수였지만 키를 받는 자리가 트리 상자의 React `onKeyDown` 이었다 — 지운 줄의 단추가 사라지며
포커스가 `BODY` 로 빠져 다음 키가 상자에 안 닿아 한 번에서 멈췄다(위 표 main «2»). E1 은 리스너가 문서 전역(`apps/web/src/edit/use-editor-shortcuts.ts` 의 `onKeyDown`)
이고 `event.repeat` 를 안 보므로, 다음 Delete 가 막 골라진 부모를 지운다. 뿌리에서 멈추는 것은 `abilities.remove` 가 뿌리에 거짓이라서다.

**같은 화면의 선례.** 컴포넌트 판 «넣기»는 «누른 채의 키 반복은 넣지 않는다»(`apps/web/src/palette/component-palette.tsx` 의 `moveCard` · 정본 «넣기» 문단).

**고칠 방향.** 편집 명령(`Shortcut.edits`)에는 `event.repeat` 를 거른다 — 그리고 키보드 삭제 뒤의 선택을 부모가 아닌 쪽(다음 형제 → 앞 형제 → 없으면 부모,
또는 선택 없음)으로. 반복만 거르면 «두 번 친» 판(150ms)이 남는다.

## H2 — 열린 줄 메뉴 안의 ← · → 가 선택을 옮겨 «삭제»가 다른 노드를 지운다(높음 · 새 길)

**판.** 페이지 `[글 0, 카드[글 1, 글 2, 글 3], 글 4]`. 구조 트리 줄을 누르고 그 줄의 `…`(«… 더 보기»)를 클릭으로 엶 — 포커스는 메뉴의 첫 항목.

| 판 | e1: 키 뒤 선택 · 메뉴 · «삭제» 뒤 서버 | main |
|---|---|---|
| «글 2» 의 `…` · `←` · «삭제» | 선택 글 2 → **카드** · 메뉴 그대로 열림(포커스 그 메뉴 항목) · 서버 `[글 0, 글 4]` — **카드와 글 1 · 2 · 3 이 지워졌다** | 선택 그대로 · 서버 `[글 0, 카드[글 1, 글 3], 글 4]`(글 2 만) |
| «카드» 의 `…` · `→` · «삭제» | 선택 카드 → **글 1** · 메뉴 열림 · 서버 `[글 0, 카드[글 2, 글 3], 글 4]` — 카드가 아니라 글 1 이 지워졌다 | 서버 `[글 0, 글 4]`(카드) |

**원인.** `ActionMenu` 의 `onListKeyDown`(`apps/web/src/shell/action-menu.tsx`)은 ↑ · ↓ · Home · End · Enter · Space · Escape · Tab 만 받고
`preventDefault` 한다 — ← · → 는 그대로 문서로 올라가 단축키 `selectParent` · `selectFirstChild` 가 된다(`shortcutsBlocked` 는 `role="menu"` 를 모른다).
줄 메뉴의 항목은 그 줄이 아니라 **지금 고른 노드**에 대한 명령이다(`apps/web/src/panels/tree-row-actions.tsx` 의 `structureRowItems(row.commands, …)` — 열 때
그 줄을 고르는 것으로 맞춰 둔다). 메뉴가 열린 채 선택이 옮겨 가면 메뉴의 이름(«Text 더 보기»)과 실제 대상이 갈린다. `+`(«… 추가»)의 «아래 추가» ·
«패턴 넣기»도 같은 뿌리다(재지 않았다).

**같은 판의 다른 위젯**(아래 «화살표 표»): ← · → 를 쓰지 않는 위젯은 거기서 선택이 옮겨 가도 그 위젯이 대상을 안 쥐어 해가 없다 — 메뉴만 «연 때의 대상»을 쥔다.

**고칠 방향.** 열린 메뉴 안에서 난 키는 단축키가 안 받게 한다(`shortcutsBlocked` 가 `closest('[role="menu"]')` 를 보거나, `onListKeyDown` 이 안 쓰는 키도
막음). 근본은 줄 메뉴 항목을 연 줄의 id 에 묶는 것이다.

**L2 원인 · 방향.** `shell/use-popover-dismiss.ts` 의 `onKeyDown`(Escape) 는 `preventDefault` 를 안 걸고, 단축키 리스너가 먼저(마운트 때 걸림) 선택을 푼다 — 항목에 포커스가 없는 메뉴는
`onListKeyDown` 을 안 지나므로 막을 자가 없다. 팝오버 Escape 가 `preventDefault` 를 걸어도 단축키가 먼저 돌므로 소용이 없다 — 단축키 쪽이 «열린 팝오버»를
알아야 한다(또는 단축키 리스너를 capture 로 옮기고 팝오버가 먼저 받음).

**L3 원인 · 방향.** «취소» 단추는 입력 표면이 아니라 Escape 가 «선택 해제»가 된다. 고르개는 `visiblePicker`(`panels/structure-toolbar.tsx` — `case 'after'` 가 `abilities.addAfter`
가 선택에 매임)로 감춰질 뿐 `adding` 은 `'after'` 로 남아 다음 선택에 다시 선다. 고르개 상자의 Escape 를 `cancelAdd`(같은 파일 `useStructureCommands` 의 반환)에
잇거나, 선택이 비면 `adding` 을 걷는다.

## 항목 5 — `isTypingSurface` 변경

**기존 판은 그대로다**(e1 = main): 메뉴 트리 이름 입력에서 `xy` · Backspace · `?` · Cmd+Z · Delete → 값 «첫째x»(칸의 되돌리기) · 대화 상자 0 · 구조 서버
그대로 · Escape 가 이름 입력만 취소. 메뉴 트리 페이지 링크에서 Alt+↓ → 메뉴 트리 «첫째 · 둘째» → «둘째 · 첫째» · 구조 서버 그대로. 구조 트리 줄 Delete 는
지운다(H1 표).

**캔버스 문서에 심은 표면**(시스템 테마는 진짜 입력을 안 그린다 — 구현 보고와 같은 까닭으로 심었다). 각 판: 포커스 → `xy` · Backspace(여기서 값 · `headSeq` 를
한 번 읽음) → Delete · `?` · Cmd+Z · ↑(끝 값). Backspace 뒤 값이 칸의 동작을, `headSeq` 가 노드 편집을 잰다 — 끝 값은 칸의 Cmd+Z 가 섞여 판정에 안 쓴다.

| 표면 | e1: Backspace 뒤 값 · `headSeq` | e1: 끝 | main: Backspace 뒤 값 · `headSeq` |
|---|---|---|---|
| `contenteditable` div(`ce`) | `cex` · 1 | 서버 그대로 · 대화 상자 0 · 선택 그대로 | `cex` · 1 |
| `<div role="textbox" tabindex=0>` | (글 없음) · 1 | 서버 그대로 · 선택 그대로 | 1 |
| 열린 shadow root 안 `<input>` | `x` · 1 | 서버 그대로 | `x` · 1 |
| **L1 닫힌 shadow root 안 `<input>`** | **`xy`**(글자가 안 지워짐) · **2**(고른 노드 «글 2»가 지워짐) | 이어 `?` 가 도움말을 엶 | `x` · 1 |
| `inert` 상자 안 `<input>` 을 누름 | (포커스가 안 감 — `IFRAME>BODY`) · 2(고른 노드가 지워짐) | 도움말 열림 | 1 |
| `<input type="checkbox">` | — · 1 | 서버 그대로 · 선택 그대로(화살표도 막힘) | 1 |

**L1 원인.** 닫힌 shadow root 의 이벤트 대상은 호스트로 리타게팅되고 호스트의 `shadowRoot` 가 `null` 이라 ㉣ 가 못 본다(`apps/web/src/panels/typing-surface.ts` 의 `isTypingSurface` 마지막 줄 `element.shadowRoot !== null` —
그 머리말 «이 판정이 못 보는 것»이 적은 구멍). main 에는 캔버스 문서 리스너가 없어 닿지 않았고, E1 의 캔버스 리스너가 그 구멍을 테마 뷰(임의의 React —
웹 컴포넌트가 닫힌 shadow 를 쓸 수 있다)에 연다. 무게는 «친 글 대신 노드가 지워짐»의 꼴이지만 사용자 테마가 닫힌 shadow 입력을 그릴 때만 닿아 **낮음**으로
적는다. 방향: `composedPath()` 도 닫힌 root 안을 바깥에 안 보여 쓸 수 없다 — 캔버스 문서에서는 대상이 `body` · `documentElement` · 글을 안 받는 기본 컨트롤
(`button` · `a[href]`)일 때만 단축키를 세우고, 그 밖의 포커스 받은 요소(닫힌 shadow 호스트 `div` 포함)는 표면으로 본다. **`body` 하나로 좁히면 안 된다** —
캔버스의 Text · Field 노드를 누르면 포커스가 `IFRAME>BODY` 지만 Button 노드를 누르면 `IFRAME>BUTTON` 이다(시스템 admin 테마 — 탐침 `probe-btnfocus.ts`).

**`inert` 판은 결함으로 적지 않는다** — 포커스가 입력에 못 가므로 키는 캔버스(고른 노드)의 것이다. 다만 «캔버스의 입력은 `inert`»(계획 Review Focus 1)는 코드에
없다(`git grep inert apps/web/src packages/renderer/src packages/theme-sdk/src` — 축소판 `palette-thumbs.tsx` 하나) — 캔버스 테마의 입력은 포커스를 받고,
그때는 위 표대로 막힌다.

(`shell/editor-keys.tsx` 의 `run` 의 `case 'selectSiblings'`). 사람이 «글 전부 고르기 → 복사»를 기대하는 자리(상호작용 문장 · 통지 · 캔버스의 글)에서 고르기가 안 서고, 이어 친 Cmd+C 는 «긁어 고른
글자»가 없으니 노드 봉투를 싣는다. 방향: 여럿 고르기가 서기 전(E1)에는 표에서 빼 브라우저에 두거나, 적어도 `preventDefault` 를 안 건다.
