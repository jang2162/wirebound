# A4 — 프로젝트 설정 페이지 · 테마 고르기 · 토큰 편집 · 관리자 화면 · 캔버스가 프로젝트 테마를 싣는다 (web) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 이 저장소에서는 `CLAUDE.md` 「메인 세션은 디스패치·판정·병합만 한다」를 따른다 — 태스크는 워크트리의 Orca 워커가 한다.

**Goal:** 사이트에서 프로젝트의 테마를 고르고 토큰을 고치며(설정 페이지), 인스턴스 관리자가 테마를 올리고 숨기고(관리자 화면), 에디터 캔버스가 저장소 상수 대신 프로젝트가 고정한 `id@버전` 의 번들과 토큰으로 그리고 다른 사람의 저장을 곧바로 따라간다.

**Architecture:** 번들(`theme.js`)은 에디터가 세션마다 하나 두는 **숨은 적재 iframe**(스크립트 realm)에 `<script>` 로 싣고 `installRuntime` 으로 받은 `ThemeDefinition` 을 `id@버전` 으로 캐시한다. 캔버스 · 갤러리 iframe 은 그 정의로 그리고, `theme.css` 는 각 iframe 에 `<link>` 로, 토큰은 그 뒤 `<style>` 로 싣는다. 에디터 셸이 `GET …/theme` 으로 바인딩을 쥐고 `theme-changed` 프레임 · 다시 읽기의 `themeRev` 로 따라잡는다. 설정 페이지(`/projects/:projectId/settings`)는 셸 밖 라우트로 «일반»(이름 · 슬러그 · 설명)과 «테마»(고르기 · 확인 · 토큰 편집 + 갤러리 미리보기) 절을 갖는다. 관리자 화면(`/admin/themes`)은 «내 API 토큰» 화면의 꼴을 따른다.

**Tech Stack:** React 19 · react-router 7 · vite 6 · vitest(jsdom) · playwright-core(`apps/web/build-test`).

**Spec:** `docs/superpowers/specs/2026-09-27-code-themes-design.md` — 「캔버스 iframe」 · 「관리자 화면」 · 「테마 바꾸기와 버전 올리기」 · 「토큰 편집」 · 「실시간」 · 「진행 단계」의 A4 줄과 «A4 의 설정 페이지는 별도 과제 … 가 뼈대를 먼저 세운다»(사용자 결정: **그 과제(B — 프로젝트 설정 페이지)를 이 차수에 합친다**). 앞 차수: `docs/superpowers/plans/2026-09-28-a3-report.md` · `-a3-review.md` · `-a3-fix-report.md`(api 계약 — `apps/api/README.md` 「테마 패키지와 프로젝트 테마」).

## Review Focus

1. **번들이 안 오거나 깨진 채 캔버스를 연다** — 404 · 스크립트 오류 · `register` 를 안 부르는 번들 · 응답이 끝없이 늦음(10 s 한도) 모두에서 캔버스가 **SDK 기본 뷰로 그리고** 셸 머리에 한 줄 알림과 «다시 불러오기» 가 선다. 빈 캔버스로 멈추지 않는다. → Task 3 · Task 8.
2. **다른 사람이 테마 · 토큰을 저장한다** — 열린 캔버스가 새로고침 없이 따라간다: 토큰만이면 CSS 변수 · `useToken` 만, 판이 바뀌면 번들을 다시 싣는다. 프레임을 놓친 탭(끊겼다 다시 붙음)은 다시 읽기의 `themeRev` 로 따라잡는다. 옛 `rev` 의 프레임은 버린다. 판 3 복원도 같은 길이다. → Task 3 · Task 8.
3. **페이지를 옮겨 캔버스 iframe 이 새로 선다** — 새 iframe 에도 테마 `<link>` · 토큰 `<style>` 이 순서대로 선다(토큰이 테마 시트보다 뒤 — system-admin `theme.css` 가 `:root` 에 기본값을 적는다). → Task 3.
4. **토큰 폼에 반쯤 친 값**(`#12` · `12p`) — 미리보기가 깨지지 않고(그 키만 기본값), 저장 단추는 그 키의 사유를 보이며 요청을 안 보낸다. 서버 422 는 키마다 사유로 선다. 409 는 내 값과 서버 값을 나란히 보이고 고르게 한다. → Task 6.
5. **권한이 바뀐다** — owner 가 아닌 멤버는 설정 페이지를 읽기로만 본다. 인스턴스 관리자가 아닌 사람에게 관리자 링크가 없고, 주소로 들어오면 서버 403 을 문장으로 보인다. 로그인 직후에도 관리자 링크가 옳게 선다(D8). → Task 4 · Task 7.

### D2. 번들 적재 — 숨은 적재 iframe · 캐시 · 한도

```ts
// apps/web/src/theme/bundle-loader.ts
export interface ThemeRef { themeId: string; version: string }
export type BundleResult = { status: 'ok'; definition: ThemeDefinition } | { status: 'failed'; reason: string }
export interface ThemeBundleLoader { load(ref: ThemeRef): Promise<BundleResult>; forget(ref: ThemeRef): void }
export function createScriptBundleLoader(host?: Document, deadlineMs?: number): ThemeBundleLoader
export const BUNDLE_DEADLINE_MS = 10_000
export function themeFileUrl(ref: ThemeRef, file: string): string   // `/api/theme-packages/${enc(id)}/${enc(v)}/files/${file}`
// apps/web/src/theme/bundle-context.tsx
export function ThemeBundleProvider(props: { loader?: ThemeBundleLoader; children: ReactNode }): JSX.Element
export function useThemeBundleLoader(): ThemeBundleLoader
```

- `createScriptBundleLoader` 는 호스트 문서에 **숨은 `about:blank` iframe 하나**(`wb-shell-bundle-realm` — 크기 0 · `aria-hidden`)를 두고, 그 창에 `installRuntime(realm.contentWindow)` 한 뒤 `<script src=themeFileUrl(ref,'theme.js')>` 를 붙여 `load` · `error` 를 기다리고 `handle.take()` 로 정의를 받는다. `take()` 가 `null`(register 를 안 부른 번들) · `error` 이벤트 · `BUNDLE_DEADLINE_MS` 지남 → `failed`(까닭 문장). 같은 `ref` 는 한 번만 싣는다(진행 중 약속을 나눠 쓴다) · `ok` 는 캐시, `failed` 는 캐시하지 않는다(«다시 불러오기» 가 다시 싣는다 — `forget`).
- **왜 캔버스 iframe 이 아니라 따로 두는가**: 캔버스 iframe 은 페이지를 옮길 때마다 새로 서므로 번들을 매번 다시 실행하게 된다. 정의(뷰 함수)는 런타임이 준 **호스트의 React · SDK** 로 지어져 어느 iframe 에 포털로 그려도 같다(A1a 의 포털 설계). 번들의 최상위 코드는 적재 realm 에서만 돌아 에디터 문서를 안 건드린다. 뷰는 `window` 대신 `useWindow()` 를 써야 한다(SDK 계약 — 적재 realm 의 `window` 는 캔버스가 아니다). 이 판단을 `bundle-loader.ts` 머리말에 적는다.
- 판 하나에 적재는 세션당 한 번이다(파일 응답이 `immutable` 이라 두 번째부터는 캐시에서 온다).
- jsdom 테스트는 `<script src>` 를 실행하지 않는다 — `ThemeBundleProvider` 의 `loader` 를 바꿔 끼운다. `apps/web/test/theme-loader.ts` 에 `staticBundleLoader(map: Record<string, ThemeDefinition | 'fail' | 'hang'>)` 를 두고, 기본 하네스(`renderEditor` · `routes.test.tsx` 의 `renderAt`)는 `system-admin@0.1.0 → ADMIN_V0`(devDependency 로 남는 `@wirebound/system-theme-admin`) 을 준다.

### D3. 캔버스에 싣는 시트 — `<link>` 와 토큰 `<style>`

- `CanvasIframe` 의 `styles` 를 `readonly CanvasSheet[]` 로 넓힌다: `{ id; css: string } | { id; href: string }`. 배열 차례대로 머리에 선다(`<style data-wb-style=id>` · `<link rel=stylesheet data-wb-style=id>`). 같은 `id` 의 종류 · 값이 바뀌면 그 자리에서 바꾼다.
- 캔버스 시트: `base`(`defaultViewsCss()`) → `theme`(`{ href: themeFileUrl(ref,'theme.css') }`) → `tokens`(`tokensCss(manifest, tokens).css`). `theme.css` 는 `<link>` 여야 한다 — 번들 CSS 의 자산 경로가 `./assets/…` 라 파일 URL 기준으로 풀려야 한다(spec 「.wbtheme 파일」).
- `useToken` 값은 `tokenValues(manifest, tokens)`(참조 기본값을 푼 값). 번들이 실패하면 `theme` 시트를 빼고 정의 대신 `{ manifest, views: {} }` 로 그린다(렌더러가 노드마다 기본 뷰로 떨어진다) — manifest 는 `GET …/theme` 에서 받으므로 variant · 패턴 칸은 그대로 선다.

### D4. 에디터의 프로젝트 테마 상태

```ts
// apps/web/src/theme/project-theme.tsx
export interface ProjectThemeState {
  status: 'loading' | 'ready' | 'bundle-failed' | 'failed'
  ref: ThemeRef | null; manifest: ThemeManifest | null; tokens: Record<string, string | number>; rev: number
  definition: ThemeDefinition | null   // bundle-failed 이면 { manifest, views: {} }
  failure: string | null
}
export function ProjectThemeProvider(props: { projectId: string; children: ReactNode }): JSX.Element
export function useProjectTheme(): ProjectThemeState & { retry(): void; catchUp(rev: number): void; applyFrame(frame: ThemeChangedFrame): void }
```

- 셸(`EditorShell`)이 감싼다. 첫 적재는 `api.getProjectTheme(projectId)` → `loader.load(ref)`.
- `theme-changed` 프레임(`use-realtime.ts` 의 `default` 를 걷고 `onThemeChanged` 로 넘긴다): `frame.rev <= rev` 면 버린다. `ref` 가 같으면 `tokens · rev` 만 바꾼다. 다르면 `getProjectTheme` 을 다시 읽어(manifest 가 필요하다) 번들을 싣는다 — 싣는 동안 옛 정의로 그리고, 새 정의가 서면 바꾼다(빈 캔버스 없음).
- 다시 읽기의 따라잡기: `EditorShellRoute.reread` 가 받은 `project.themeRev`(GET 프로젝트의 칸)를 `catchUp(themeRev)` 로 넘기고, `themeRev > rev` 면 `getProjectTheme` 을 다시 읽는다. 판 3 복원은 `theme-changed` 를 함께 보내므로 따로 행을 더하지 않는다 — `editor.tsx` 의 «복원이 바꾸는 것» 표에 «테마 바인딩 | `theme-changed` 프레임(복원도 보낸다) · 놓치면 `themeRev`» 한 줄을 더한다.
- 소비자: `canvas/canvas.tsx`(정의 · 시트 · 토큰), `panels/property-panel.tsx` · `panels/pattern-picker.tsx`(`manifest`). **`canvas/canvas-theme.ts` 를 걷는다** — `CANVAS_THEME` 을 `vi.mock` 하던 테스트(`test/panels/structure-pattern.test.tsx` · `pattern-picker.test.tsx` · `property-panel.test.tsx` · `test/lock/toolbar-abilities.test.tsx` · `test/canvas/canvas.test.tsx` · `bundle-parity.test.tsx`)는 `ProjectThemeProvider` 대신 쓰는 시험용 공급자(`test/theme-loader.ts` 의 `withProjectTheme(definition, tokens?)`)로 옮긴다.
- 셸 머리 알림: `status === 'bundle-failed' | 'failed'` 면 `p.wb-shell-theme-alert` «테마를 불러오지 못해 기본 모양으로 그립니다 — <까닭>» + 단추 «다시 불러오기»(`retry` — `loader.forget` 뒤 다시). `loading` 동안 캔버스는 기존 «여는 중» 알림 꼴을 쓴다.

### D5. «테마» 절 — 고르기 · 확인

- 지금 값: `이름 id@버전`, 같은 테마에 더 높은 숨기지 않은 판이 있으면(`latest`) «새 버전 x.y.z» 표시.
- 고르기: `listThemePackages()` 의 테마 · 판을 두 칸(테마 · 버전)으로. 숨긴 판은 목록에 없다(관리자에게는 «숨김» 표시로 보이되 고를 수 없다 — 지금 고정한 판이면 그대로 표시).
- 다른 `id@버전` 을 고르면 그 자리에 **인라인 확인**이 열린다: `getThemeImpact` 의 토큰 이어짐 · 버려짐 · 기본값 수와 페이지별 «없는 variant» 수(페이지 제목). «바꾸기» → `putProjectTheme({ themeId, version, tokens: migrateTokens(현재 manifest, 새 manifest, 현재 tokens), rev })`.
- `migrateTokens(from, to, tokens)` 를 `packages/themes` 에 두고(«키와 타입이 같으면 잇는다 · 새 manifest 로 검사해 이슈 난 키는 버린다»), **api 의 impact 계산도 그 함수로 센다**(`apps/api/src/services/theme-impact.ts` — 두 벌 금지). 새 manifest 는 `getThemeManifest(ref)` 로 받는다.
- 결과: 200 → 절이 새 값으로 선다(토큰 편집기도). 409 → «다른 사람이 먼저 바꿨습니다» + 서버 값으로 다시 읽기. 422 `hidden-version` → «이 판은 숨겨져 고를 수 없습니다».

### D6. 토큰 편집기 · 미리보기

- manifest `tokens.groups` 차례로 무리 짓고, 무리 없는 키는 «기타». 타입마다 컨트롤: `color` — `<input type=color>`(`#rrggbb` 일 때) + 글 칸 · `length` — 수 + 단위 `<select>`(`px rem em % vh vw`) · `number` — `<input type=number>` · `font` — 글 칸 + 기본 글꼴 목록 `<datalist>` · `select` — `<select>` · `shadow` — 글 칸. 칸마다 «기본값으로», 절 끝에 «전부 기본값으로».
- 초안은 화면 상태다(저장 전에는 서버 · 다른 사람에게 가지 않는다). 칸마다 `tokensCss(manifest, { [key]: value }).issues` 로 사유를 곧바로 보인다(서버와 같은 함수). 사유가 있는 키는 미리보기에서 기본값으로 선다(`tokensCss` 가 그렇게 한다).
- 미리보기: 오른쪽 `CanvasIframe`(시트 `base` · `theme` link · `tokens`) 안에 `ThemeGallery`(`@wirebound/theme-gallery` — `apps/web` 의존 · tsconfig 참조를 더한다, `catalog-setup` 을 먼저 들인다). 좁은 폭(< 960px)에서는 폼 아래로.
- 저장: 바뀐 것이 있고 사유가 0 일 때만 켜진다 → `putProjectTheme({ 같은 id@버전, tokens: 초안에서 기본값과 같은 것을 뺀 값, rev })`. 409 → `current` 와 내 초안을 **칸마다 나란히**(다른 칸만) 보이고 «서버 값으로» · «내 값으로 덮기»(서버 `rev` 로 다시 보냄). 422 → `issues[].path`(`tokens.<키>`)를 칸에 붙인다.
- owner 가 아니면 폼은 읽기 전용이고 미리보기는 지금 값으로 선다.
- 저장하지 않은 초안을 두고 떠나는 것은 막지 않는다(이 차수 밖 — 보고의 이월에 적는다).
