## 1. `packages/schema/test/lock-selection-oracle.test.ts` — 5s 시간 초과

**원인: 테스트 자신의 오라클(옛 판정 사본)이 시간을 거의 다 쓴다 — 새 판정은 0.01s.** 한 판에서 옛 판정은 묻는 노드마다 `findNodePath`(문서 훑기)를 부르고, 그 안에서 남의 잠금마다 다시 `findNodePath` 를 불러 노드 수 × 잠금 수 × 문서 훑기가 된다. 카나리아의 `firstOfMany` 는 막힌 노드마다 잠금 하나씩 옛 판정을 다시 돌려 같은 값을 또 냈다.

혼자 돌린 판의 구간 시간(`performance.now()` 로 구간을 감싼 사본을 `pnpm vitest run` 으로 — 사본은 지웠다):

| 구간 | ms |
|---|---|
| 무작위 트리 생성(`board`) | 12 |
| 옛 판정(`oldVerdict`) | 1115 |
| 새 판정(`selectionConflicts`) | 10 |
| 노드마다 `expect` | 291 |
| 카나리아 집계(`firstOfMany` 의 옛 판정 재실행 · `kindOf`) | 2015 |
| 합(파일 3447ms) | 3443 |

**고침: 판 수(4000)와 규칙은 그대로 두고 문서 훑기만 줄였다.** 판마다 `findNodePath` 를 노드당 한 번 부르는 사본(`memoPaths`)을 옛 판정 · 카나리아가 함께 쓴다 — 같은 함수라 포인터 규칙(첫 전위 자리 · 세그먼트 접두)이 그대로다. `firstOfMany` 는 잠금 하나의 겹침을 노드마다 한 번에 낸다(`overlapsPerNode` — 옛 판정과 같은 규칙). 판 수를 줄이는 길과 한도만 늘리는 길은 고르지 않았다 — 느린 것이 «정말 느린 일»이 아니라 같은 훑기의 되풀이였다.

**카나리아는 고치기 전과 값이 같다**(판 4000 · 노드 87403 · 막힘 44221 · 자유 43182 · self 4762 · inside 24967 · contains 14492 · 같은 id 둘 1710 · 없는 노드 잠금 1019 · firstOfMany 22343).

**오라클 구분력 재확인** — 새 판정(`packages/schema/src/lock.ts` 의 `selectionConflicts`)에 변조 다섯을 심고 옛 파일(HEAD 사본)과 새 파일을 함께 돌렸다. 둘 다 같은 변조에 죽는다:

| 잠금 차례 무시(뒤 잠금이 이김) | 죽음 | 죽음 |
| 서브트리 모음을 `max` 로 | 죽음 | 죽음 |
| 조상 사슬 물려받기 뗌 | 죽음 | 죽음 |

## 2. `apps/web/build-test/editor-shortcuts.test.ts` «캔버스 iframe 에 포커스가 있어도 …» — 제품 결함

**원인: ack 전에 누른 Cmd+Z 가 그 편집이 아니라 앞 항목을 되돌렸다 — 페이지가 통째로 비었다.** 되돌리기 스택은 편집의 ack 가 서버의 `inverse` 로 쌓는다(`EditorStore.ackEdit`). 케이스는 Alt+↑ 뒤 서버 번호(REST `GET`)가 2 가 되면 Cmd+Z 를 누르는데, ack 는 다른 연결(WS)로 온다 — 서버가 커밋한 뒤 ack 가 닿기 전의 틈에 누르면 스택 맨 위는 새로고침으로 채운 «픽스처 4노드 넣기» 항목이고, 그 `inverse`(제거 넷)가 나간다.

잰 값(프레임 로그 탐침 · 실패 판):

- 통과 판: `patch-ack`(옮김) → `KEY Cmd+Z` → `patch`(`move` 되돌림).
- 실패 판: `patch`(옮김) → `KEY Cmd+Z`(ack 보다 16ms 앞) → `unlock` → `patch-ack`(옮김) → `patch`(`remove /root/children/3 · 2 · 0 · 0`, `baseSeq` 2). 서버 끝 문서 `ids: []` · `headSeq` 3. 속성 패널은 Cmd+Z 뒤 17–26ms 에 «노드를 고르면 속성이 보입니다»로 바뀌어 그대로다 → ↓ 가 루트를 고르고 글 칸이 없어 `inputValue` 30s 시간 초과.

케이스의 기다림 탓이 아니다 — 사람이 같은 틈(망에서는 왕복 시간만큼)에 누르면 페이지를 잃는다.

**고침(`apps/web/src/edit/use-edit-commit.tsx` 의 `afterAck` · `EditorStore.awaitsStackAck` · `boardEpoch`)**: 그 스택을 먹일 편집(undo 스택은 `edit` · `redo`, redo 스택은 `undo`)이 큐에 있으면 누름을 ack 까지 미뤘다가 한 번 한다. 설계서 「개인 undo/redo」의 «ack 전의 누름»에 적었다. 코디네이터 답(`.coord/q-l1.md`)대로 기본값으로 갔다.

**미룸 장치의 입구 · 끝**

| 입구 | 끝 | 재는 케이스 |
|---|---|---|
| ack 전 누름 | ack 뒤 맨 위가 바뀌었으면 마이크로태스크에서 한 번 한다 | `test/edit/undo-before-ack.test.tsx` «ack 전에 누르면 …» · `build-test/editor-undo-before-ack.test.ts` |
| 미루는 동안 같은 키를 또 누름 | 버린다 — **한 단계만**(정함) | «미루는 동안 또 누른 것은 버린다» |
| 답이 거절(409 `patch-error`) | 미룬 것은 나가지 않는다 · 앞 항목을 안 건드린다(수습이 판을 다시 실어 스택이 빈다) | «답이 거절이면 …» |
| 한도 3s(`UNDO_ACK_WAIT_MS`) 지남 | «편집이 아직 서버에 닿지 않아 되돌리지 못했습니다 …»를 말하고 안 한다 · ack 가 뒤에 오면 그 문장을 거둔다(다른 통지가 갈아 끼웠으면 안 건드린다) | «한도가 지나면 …» |
| 미루는 동안 페이지를 옮김 | 판(`boardEpoch`)이 갈려 버린다 | «미루는 동안 페이지를 옮기면 …» |
| 미루는 동안 언마운트 | 구독 · 시계를 거둔다 | 없음(아래 변조 표) |
| 로그아웃 · 복원 배너 · 남의 편집 리베이스 | 로그아웃 · 복원 · 재연결 수습은 판을 다시 싣거나 비워 `boardEpoch` 가 갈린다. 남의 편집 리베이스는 판을 안 바꾼다 — 그때 맨 위가 바뀌는 것은 내 편집의 ack 뿐이라 그 편집을 되돌린다 | 따로 케이스 없음 — 판 대조 가드는 아래 표처럼 못 잰다 |

**변조 표**(`use-edit-commit.tsx` 에 한 곳씩 · 백업 → 치환(맞은 수 1) → jsdom 5 케이스 → `cmp` 복원):

| 변조 | 죽은 케이스 |
|---|---|
| 미루지 않음(`awaitsStackAck` 무시) | «ack 전에 누르면 …» · «한도가 지나면 …» |
| 또 누름을 안 버림 | «미루는 동안 또 누른 것은 버린다» |
| 한도 뒤 문장 거둠 뗌 | «한도가 지나면 …» |
| 맨 위 변화 안 봄(`top() !== pressedTop` → 참) | **산다** — 맨 위가 안 바뀐 채 큐가 비는 입구(거절)는 수습이 판을 다시 실어 스택을 비우고 판도 갈린다. 지금 표면으로는 그 판을 못 세운다 — 방어로 남긴다 |
| 판 대조 둘(구독 · 마이크로태스크) 함께 뗌 | **산다** — 판이 갈리는 순간 새 판의 스택이 비어 `startUndo` 가 아무것도 안 낸다 |
| 언마운트 정리 뗌 | **산다** — 재는 케이스 없음 |

실브라우저 케이스(`editor-undo-before-ack.test.ts`)는 서버 → 브라우저 WS 를 600ms 늦춰(`startDownDelay`) ack 가 늦는 판을 결정론으로 세운다. 카나리아: Cmd+Z 를 누른 때까지 `patch-ack` 0. 고치기 전 소스(HEAD 의 두 파일)에서 빨강: `ids: []` · `selected: (없음)`.

**기존 케이스 하나를 고쳤다** — `test/edit/undo-restore-history.test.tsx` «누르기 전에 서 있던 통지는 받은 뒤의 되돌리기가 치운다». 나간 편집의 답이 없는 채 누르던 판이라 미룸에 걸렸다. 그 편집의 ack 를 먼저 보내고 누르게 했다 — 그래서 이 케이스는 이제 이력을 받지 않고 그 세션 항목을 되돌리며, 재는 것은 «누르기 전의 통지를 누른 되돌리기가 치운다»뿐이다(이력 조회와 겹친 판은 안 잰다).

## 지침 제안

- `CLAUDE.md` «서로 다른 연결로 가는 두 메시지의 도착 순서에 기대는 판정은 앞섬(ms)을 재서 적는다» 절 끝에 넣을 문장: «**REST 로 서버 값을 기다린 뒤 키를 누르는 케이스는 그 동작의 ack(WS)가 아직 안 닿은 판을 낸다** — 서버 커밋은 ack 보다 먼저 보인다. 되돌리기 · 선택처럼 ack 가 쌓는 상태를 다음 걸음이 쓰면, 서버 값이 아니라 그 상태(되돌리기 단추 · 화면)를 기다리거나 `startDownDelay` 로 ack 를 늦춘 판을 따로 세운다.»
- `pnpm test` 에 `--project '!api'` 를 덧붙이면 부정 패턴이 둘이 되어 아무것도 안 빠진다(`CLAUDE.md` 가 이미 적었다) — 브리프의 부하판 «`pnpm test --maxWorkers=50%` 셋 겹침»은 한 워크트리의 테스트 DB 를 셋이 함께 내렸다 올려 api 가 깨진다. 이번 부하판은 `pnpm vitest run --project unit --project web --maxWorkers=50%` 셋으로 세웠다. 브리프 쓰는 자리(`CLAUDE.md` «변이마다 전량을 돌리게 하지 않는다» 절)에 «부하판은 api 를 뺀 프로젝트로 겹친다»를 넣자.
