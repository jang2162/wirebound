## 결정과 이유(빌더에게 맡긴 것)

| 결정 | 이유 |
|---|---|
| 표를 따로 둔다(`personal_modules`) | `modules` 에 소유자 칸 + CHECK 면 «프로젝트 삭제 · `lockProjectModules` 가 개인 행을 안 건드린다» 가 질의의 `where` 하나에 걸린다. 표를 가르면 구조다 — 프로젝트를 가리키는 FK 가 없어 CASCADE 가 닿을 길이 없다 |
| 경로 `/api/me/modules` | 프로젝트 밖 · 사람 단위. `:projectId` 가 없어 토큰이 사람을 안 채워 401(`auth/plugin.ts`) — «토큰은 개인 모듈에 안 닿는다» 가 기존 장치로 선다. `requireSessionUser` 가 두 번째 겹 |
| 복사는 서버 엔드포인트 없이 화면이 «다시 읽고 → 대상 쪽 저장» | 복사가 저장과 같은 가드(«프로젝트 모듈로 복사» 는 `POST …/modules` 의 editor 가드) · 거름 · 한도 · 재확인을 그대로 지난다. 새 쓰기 경로 · 새 잠금 셈이 없다. 개인 id 가 프로젝트 라우트에 실리는 길도 없다 |
| 저장 상자 고르기는 라디오, **기본값 «개인 모듈»** | 남에게 안 보이는 쪽이 기본이면 고르지 않고 저장해도 아무에게도 새지 않는다(좁은 쪽) |
| 프로젝트 쪽 고르기는 «아예 안 선다» | 설계가 허락한 두 꼴 중 짧은 쪽. viewer 의 상자에 개인 하나 |
| 카드 행동은 아이콘 단추 줄(많아야 넷), 카드 폭 220 → 240px · 오른쪽 여백 84 → 112px | `…` 메뉴로 접으면 끌기 몸통 · 단추 줄 판정과 행동 메뉴의 겹침 판(`DOUBLE_CLICK_*`)이 새로 생긴다. 넷이면 한 줄에 들어간다 |
| 넣을 수 없는 판의 토글 · 판 이름을 «모듈» · «모듈 목록» 으로 | «컴포넌트» 단추가 모듈만 있는 판을 여는 것은 이름이 거짓이다. 넣을 수 있는 판의 이름은 그대로라 기존 찾기(`name: '컴포넌트', exact: true`)가 그대로 선다 |
| 넣을 수 없는 판은 기억한 위층 탭을 안 읽고 안 쓴다 | 뷰 모드에서 «모듈» 로 고정해 보인 것이 편집 모드의 기억을 덮지 않게 |
| 넣을 수 있는가가 바뀌면 카드 판을 다시 마운트 + 넣기 직전에 그 값을 다시 본다 | 판이 이제 뷰 모드 · 강등에도 남으므로 끄는 중 · 다시 읽는 중에 넣을 수 없게 될 수 있다(전에는 판째 내려가 끌기가 끊겼다) |

**구조 트리의 «편집할 수 없는 판» 은 viewer 뿐이다** — 구조 트리는 뷰 모드에 없다(정본 «구조 트리는 편집 모드에서만»). 그래서 «editor 의 뷰 모드에서 트리 줄 `…` 의 «모듈로 저장…»» 은 설 자리가 없다. 설계의 결정(편집할 수 없는 판에도 연다)을 어기지 않는다 — 트리가 있는 편집할 수 없는 판(viewer)에 선다.
