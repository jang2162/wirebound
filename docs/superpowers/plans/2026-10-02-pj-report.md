## 고른 길 — 상자를 누가 여는가 · 통지를 누가 드는가

- **상자는 메뉴 트리가 `ShellDialog` 로 그린다**(셸의 `dialog` 상태에 싣지 않음). 보내기 · 잠금 · 다시 받기 · 이동이 트리 명령 훅에 있고 그 훅은 하나여야 한다(`busy` 잠금). 모달이라 셸의 상자와 함께 서지 않는다.
- **상자는 단축키 상자(`.wb-shell-tree-keys`)의 형제다**(`menu-tree.tsx` 의 `outside`). 재현: 상자를 단축키 상자 **안**에 그리는 변조에서 Chrome 이 상자 단추의 `Delete` 로 뒤 트리의 삭제 확인을 건다(`상자_안_Delete: 1` — 아래 B-M1). 모달은 뒤 화면의 누름 · 포커스를 막지만 React 합성 이벤트는 React 트리를 따라 버블된다. jsdom 도 같은 값(M1).
- **통지는 셸이 든다**(`usePageJsonNotices` — `routes/editor.tsx` 가 쥐고 `MenuTree` 의 `notices` 로 채우는 함수를 넘김). 처음엔 `headSlot` 처럼 하단 바 안 자리로 portal 했다가 걷었다 — 통지 줄은 비면 `:empty` 로 걷히는데 portal 의 자리 요소가 늘 있어 빈 통지 무리가 320px 를 쥔다(`shell.css` 의 `.wb-shell-footer-notices:empty` 주석이 말하는 고장).

## `ActionMenu` 의 아이콘 자리(뒤의 아이콘 트랙이 쓸 모양)

`ActionMenuItem.icon?: LucideIcon` — **컴포넌트**를 준다(그린 요소가 아니다). `ActionMenu` 가 `size={14}` · `strokeWidth={2}` · `aria-hidden="true"` · `className="wb-shell-action-menu-icon"`(글자 앞 6px · `vertical-align: -2px`)로 그린다. 색은 글자색(`currentColor` — 끈 항목 · 위험 항목 색을 받는다). 이름은 글자가 든다. 아이콘 없는 항목은 자리를 비우지 않는다(`action-menu.tsx` 머리말 «항목의 아이콘»). 상자 안 아이콘(파일 칸 24 · 카드 16 · 경고 14)은 그 자리 클래스로 색만 준다.

### 옮긴 판 — `tree-drag-review` «삭제 둘째 누름»

옛 판은 «나2» 줄 `…`의 «삭제» 밑에 페이지 JSON 칸이 있어 둘째 누름이 그것을 누르는지(가져오기 칸 · 내려받기)를 쟀다. 패널을 걷자 그 자리 밑은 트리 영역의 빈 칸이다(18 판 모두 `under` = `section:메뉴·페이지 트리`) — 삼키기(`action-menu.tsx` 의 `guardFollowingClick`)를 떼는 변조에 **두 판 다 초록**이었다(B-no-swallow: 실패 0). 그래서 그 판을 걷고, 목록이 아래 줄들 위에 뜨는 «가1» 줄로 새 판을 세웠다 — 카나리아: 누르기 전 «삭제» 가운데 밑이 트리의 줄(`under: 'row'`). 같은 변조로 새 판이 값으로 죽는다(`path: false` — 밑의 페이지로 옮겨 감). jsdom 쪽 소유자는 `test/shell/action-menu.test.tsx` «고른 뒤의 둘째 누름 …»(같은 변조로 `outside: 1`). 표의 첫 판(«삭제 두 번 누르기 — 더블클릭 …»)에서 `importOpen` · `downloads` 칸을 걷었다.

### 그 밖의 실측

- **viewer 훑기가 이제 메뉴 트리 단축키에 닿는다** — `handleKeyDown` 의 `SHORTCUTS.find` 뒤에 `console.log` 탐침을 심고 editor 대조를 돌려 702 줄(탐침은 바이트 복원). 머리말의 «editor 대조가 메뉴 트리 단축키에 한 번도 안 닿는다 — 페이지 JSON 패널이 대표를 바꾼다»가 거짓이 되어 지금 참인 문장과 다시 재는 법으로 고쳤다.
- jsdom 은 `showModal` 이 없어 뒤 화면의 `inert` 가 없다 — `view-mode` 의 «열어 둔 상자째 사라짐»은 모달 뒤의 모드 단추를 누르는 jsdom 만의 판이다(실브라우저에서 상자를 닫는 갈래는 역할 바뀜이다 — 케이스 머리말에 적음).

## 브리프와 달라진 것

1. **통지는 portal 이 아니라 셸이 든다** — 브리프는 «`notices` 슬롯 — `routes/editor.tsx` 가 채운다». 셸이 채우는 것은 그대로이고, 상태를 셸 훅(`usePageJsonNotices`)에 두어 트리가 콜백으로 채운다. 그 결과 훅의 `imported` · `dismissImported` 는 없다(`onImported` 로 바뀜). 까닭은 위 «고른 길».
2. **상자는 셸의 `dialog` 상태가 아니라 메뉴 트리가 그린다**(브리프가 길을 맡김) — 같은 `ShellDialog` 부품이다.
3. **내보내기 항목은 트리 판정 · 트리 `busy` 를 안 본다** — 읽기라서. 제 내보내기가 나가 있는 동안만 꺼진다(한 번에 하나).
4. 상자 제목은 «페이지 가져오기 — <메뉴> 메뉴로»(브리프 «… 로»를 «메뉴로»로 — 메뉴 이름의 받침과 무관).
5. 경고 접힘은 `<details>` 가 아니라 `aria-expanded` 단추(옛 패널 머리말의 근거 — jsdom 이 닫힌 `<details>` 의 자식을 숨기지 않는다).
6. **보낼 때 글자를 비우지 않는다**(옛 패널은 비웠다) — 브리프 «서버 거절: 고른 파일 · 글자를 그대로 둔 채». 성공하면 상자째 닫혀 사라진다.
7. **늦게 끝난 앞 파일 읽기를 버린다**(`readSeq`) — 옛 패널에도 있던 경주. 새 케이스 · M9.
8. 브리프에 없던 옮김: `tree-drag-review` 의 판(위), `viewer-readonly` 훑기(메뉴 줄 `+` 다시 열기 · 대화 상자 «취소» 안 누름 — 없으면 editor 대조가 «페이지 가져오기»에 못 닿는다: M17).
