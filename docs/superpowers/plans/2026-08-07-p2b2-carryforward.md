## P2b-3(구조 편집) 첫 태스크 전에 읽을 것

### 1. 편집이 지나는 길 — 계약 요약

**`ops`를 만들어 `useEditCommit`에 넘기면 나머지는 파이프라인이 한다.** P2b-3의 노드
추가·삭제·이동은 **`ops`를 만드는 방법만 다른 같은 경로**다.

- **낙관적 적용은 스토어가 한다.** `applyEdit(clientOpId, ops)`가 문서에 적용하고 큐에 넣는다.
  **로컬 적용이 실패하면 요청을 만들지 않는다**(D7) — 그것은 클라이언트가 만든 잘못된 `ops`다.
- **요청은 직렬화된다.** in-flight는 항상 하나이고 **펌프 가드가 스토어에 있다**
  (`EditorStore.#pumping`). **훅에 두면 안 된다** — `useEditCommit`을 부르는 자리가 둘이 되면
  각자 자기 플래그를 갖고 `maxInFlight`가 2가 되어 D6가 깨진다(실측: 같은 `clientOpId`가 두
  요청에 실렸다). `test/edit/undo-redo.test.tsx`가 그것을 고정한다.
- **어떤 실패든 재조회로 수렴한다**(D4). 409·422·네트워크·5xx 전부 같은 경로다. **`unauthenticated`만
  갈라져** 세션 무효화로 간다(재조회하지 않는다 — 하면 무한 시도가 된다).
- **`loadPage`가 페이지 상태를 서버 것으로 놓는 유일한 자리다.** 문서·`headSeq`·`openPageId`·
  선택뿐 아니라 **`pending`·undo·redo 스택까지 함께 재설정하고 버려진 pending을 돌려준다.**
  넷만 갈아 끼우던 판에서 **재조회 창의 편집이 고아로 남아 "취소됐다"고 알린 뒤 나중에 서버로
  나가는 결함**이 났다(실측). 새 복구 경로를 만들 때 이 자리를 지나게 하라.

### 2. `ops`를 만드는 법 — 갈래가 셋이다

계획서가 처음 두 갈래로 적었는데 **소스 실측이 반증했다.** `packages/schema`의 `resolveSlot`은
경로의 마지막 토큰만 남기고 따라 내려가므로:

| 노드 상태 | 써야 하는 op |
|---|---|
| `props`가 없다 | `add /…/props` 값 `{ <prop>: … }` — **통째로** |
| `props`가 있고 그 키도 있다 | `replace /…/props/<prop>` |
| `props`가 있고 **그 키가 없다** | `add /…/props/<prop>` — `replace`는 **던진다** |

`edit/ops.ts`의 `propOps`가 이 셋을 가른다. **세 번째를 빠뜨리면 "값이 없던 prop을 처음 켜는
편집"이 D7에 막혀 조용히 사라진다.**

통째 `add`의 `inverse`는 `[remove /…/props]` 하나이고, undo 왕복이 원본과 **완전히** 같다(빈
`props`가 남지 않는다 — 실측).

### 3. 스토어를 직접 읽지 마라 — 관문이 있다

`test/store-access-guard.ts`가 `document`·`headSeq`·`openPageId`의 직접 읽기를 잡는다.
합법 경로는 **`use-editor-store.tsx`의 `useOpenPage(pageId)`**이고, 새 필드가 필요하면
**그 파일에 관문을 더하는 것이 정당한 자리다**(가드의 위반 메시지가 그렇게 지목한다).

**가드가 잡는 것과 동작이 잡는 것은 다르다.** 가드는 "우회를 썼다"를 잡고, 동작 케이스는
"우회하면 무엇이 잘못되는가"를 잡는다 — 실측: 우회하면 **앞 페이지의 `ops`가 다음 페이지
경로로, 앞 페이지의 revision을 `baseSeq`로 달고** 나간다. 둘 다 있다.

**가드는 오탐을 낸다.** 페이지 필드와 같은 이름이 스토어가 아닌 것에 붙은 인라인 selector는
전부 걸린다(`(s) => s.pending.some((p) => p.headSeq < base)`). 걸렸는데 스토어 필드가 아니면
그 사실을 그 자리에 적고 넘어가라.

### 4. undo/redo가 기대는 것

- **`inverse`는 서버가 만든 그대로 되보낸다**(설계 §7.1). 클라이언트가 `invertOps`로 계산하지
  않는다. `test/edit/undo-redo.test.tsx`의 케이스가 로컬 계산 구현을 가른다(서버 대역이 자기
  문서에서 `inverse`를 만들어 클라이언트 사본과 값이 갈리게 설계돼 있다).
- **undo가 만든 revision은 redo 스택으로 간다.** `PendingEdit`의 `kind`가 ack 시점에 그것을 가른다.
- **적용 불가는 정상 흐름이다**(§7.3) — 스택에서 빼고 안내한 뒤 다음으로 넘어간다.
- **`applyEdit`은 `selectedNodeId`를 건드리지 않는다.** 그래서 **undo가 문서를 갈아 끼울 때
  속성 패널 위젯은 마운트된 채 남는다** — 컨트롤이 문서 값을 비추지 않고 로컬 state를 들면
  옛 값이 남는다. P2b-3이 새 컨트롤을 만들면 이 성질을 지켜야 한다.

### 5. 속성 패널 컨트롤의 규칙

- **텍스트·수·textarea는 blur/Enter에 커밋**하고 **값이 안 바뀌었으면 커밋하지 않는다**(D5).
  스위치·select는 조작 즉시다. **디바운스 타이머가 없다** — 테스트 결정성을 위해 그렇게 골랐다.
- **문서 값이 밖에서 바뀌면 초안을 버린다.** 그러지 않으면 undo 뒤 blur가 **되돌린 편집을 다시
  보낸다**(실측 결함이었다).
- **속성 패널은 오류 경계 밖이다.** `apps/web/src` 전체에서 경계는 캔버스의 `CanvasBoundary`
  하나뿐이다. 여기서 던지면 셸 전체가 흰 화면이다 — 적대적 값 열한 형태로 확인했다.
- 카탈로그의 control 일곱을 전부 덮는다. **테스트가 분모를 손으로 적지 않는다** —
  `listComponents()`를 훑어 대조하므로 여덟 번째가 생기면 거기서 죽는다.

## 알려진 손실 — 설계된 것과 그렇지 않은 것

### 타이핑 중 노드를 바꾸면 초안이 사라진다 (설계된 것, 다만 범위가 넓다)

`key={node.id}`로 노드가 바뀔 때 컨트롤을 갈아 끼우므로 커밋되지 않은 타이핑이 사라진다.

**처음 적은 근거("구조 트리로 고르면 버튼이 포커스를 받아 blur가 나므로 손실이 없다")는
클릭 경로에서 거짓이었다.** 잰 것은 `focus()`였고 사용자가 하는 것은 클릭이다 — jsdom은 클릭에
따른 포커스 이동을 구현하지 않아 `blur`가 나지 않는다. **실브라우저는 갈린다**: Chrome·Firefox는
`mousedown`에 버튼을 포커스하므로 커밋되고, **Safari/macOS는 포커스하지 않아 잃는다.**
그것은 알려진 플랫폼 차이지 **이 브랜치가 잰 값이 아니다.**

**받아들이기로 판정했다.** 닫으려면 "선택이 바뀔 때 초안을 커밋한다"는 별도 경로가 필요한데
D5(blur/Enter 커밋)를 넘고 P2b-2 범위 밖이다. **P2b-3 이후가 닫을 수 있다.**

## P3(WebSocket·리베이스)가 받을 것

**§7.3의 건너뛰기는 노드 삭제만 잡는다.** 재조회 뒤 undo 스택을 복원하지 않기로 한 근거가
이것이고, 리뷰가 실측했다:

| 상황 | 내 `inverse`를 적용하면 |
|---|---|
| 남이 값을 `A→C`로 바꾼 문서 | **던지지 않고 적용됨 → `["A"]`** — 남의 `C`가 사라진다 |
| 남이 노드를 지운 문서 | 던진다 — §7.3이 잡는다 |
| 내가 통째 `add`한 뒤 남이 그 `props`를 채운 문서에 내 `remove /…/props` | **던지지 않고 적용됨** — 남의 편집 둘이 함께 사라진다 |

즉 **값이 갈린 흔한 경우는 조용히 남의 편집을 덮는다.** 지금은 재조회 뒤 스택을 통째로 버려
그 경로를 막았지만, **P3가 리베이스를 넣으면 이 판정을 다시 봐야 한다** — 리베이스는 정확히
"남의 편집 위에 내 것을 얹는" 일이다.

`test/editor-harness.tsx`의 `CommitProbe`는 `useLocation` 기반이라 **주소가 그대로인 커밋을 못
본다.** 그 창을 재려면 `MutationObserver`를 써라(P2b-1 이월에서 이어짐).

## 이 브랜치에서 반복된 결함

**재현되지 않는 인과 문장이 다섯 났다.** 전부 리뷰가 잡았고, **다섯 다 같은 모양이다 —
잰 것과 다른 조건을 적었다.**

| # | 적은 것 | 실제로 잰 것 |
|---|---|---|
| 1 | "Provider를 라우트 안쪽에 두면 재마운트돼 순환이 난다" | 안쪽 배치를 재봤더니 **재마운트되지 않는다**(react-router가 같은 슬롯의 인스턴스를 보존). "재마운트→순환"은 참이었다 |
| 2 | "순서를 뒤집으면 문지기가 되튕긴다" | 뒤집기만 해서는 **안 튕긴다**(React가 같은 틱의 setState를 배치한다). 조건은 "확정이 이동보다 **한 틱 이상** 늦으면" |
| 3 | "이 케이스가 로컬 state 구현을 잡는다" | **0 사망.** 같은 파일의 다른 주석이 그것을 이미 반박하고 있었다 |
| 4 | "그 성질은 오늘 코드에서 관측할 수 없다" | **순차 경로에서만** 참. 배치하면 갈린다 |
| 5 | "구조 트리로 고르면 blur가 나 손실이 없다" | 잰 것은 `focus()`이고 **클릭으로는 blur가 나지 않는다** |

**완결성 어휘 사냥("전부"·"항상"·"유일")으로는 이 부류가 안 걸린다.** 다섯 다 인과 문장이었고,
어휘 사냥에 걸린 것들은 오히려 전부 측정된 참이었다. 그래서 웨이브 2부터 리뷰 브리프에
**인과 문장을 따로 뽑아 심어서 재라**를 넣었고, 그 뒤 세 건(3·4·5)이 그 규칙으로 잡혔다.

**규칙에 한 줄 더한다:**

> **인과 문장을 쓸 때는 그 X를 심어 Y를 관측한 뒤에 써라.** 특히 **자기 커밋이 만든 구조**에
> 대한 인과가 위험하다 — 다섯 중 넷이 "같은 커밋의 다른 파일이 바꿔 놓은 사실을 옛 관측대로
> 적은 것"이었다. 한 커밋 안에서도 규칙 4(*"같은 사실을 말하는 다른 곳을 전부 찾아 함께
> 고쳐라"*)가 필요하다.

### 곁가지로 배운 것

- **수정이 다른 방어의 하중을 없앨 수 있다.** 초안 버리기를 넣었더니 `key={node.id}`를 지켜
  주던 케이스가 0 사망이 됐다(구현자가 발견해 "값이 같은 두 노드" 케이스로 되살렸다).
  **고치고 나서 주변 하중을 다시 재라.**
- **테스트가 이름과 다른 것을 잴 수 있다.** 변이가 0 사망일 때 "그 시나리오에서는 스택이 이미
  비어 있어 다른 것만 재고 있었다"까지 진단해야 케이스를 옳게 고칠 수 있다.
- **재지 않은 것을 재지 않았다고 적으면 판정이 가능해진다.** X1의 UX 판정이 그랬다 — 리뷰가
  실브라우저 차이를 "알려진 차이지 내가 잰 값이 아니다"라고 구분해 적었기 때문에 그것을
  근거로 삼지 않을 수 있었다.
- **분모는 갱신하지 않으면 이월된다.** 파일 수를 웨이브 2 시점 값(64)으로 세 번 보고했고
  실제는 67이었다. 테스트 수는 매번 다시 셌는데 파일 수는 아니었다.
