## ① 더블클릭 넣기

### 바꾼 것

- `apps/web/src/palette/card-double-click.ts`(새 파일) — 몸통의 `onClick` 을 짓는 훅. 몸통에 닿은 `click` 둘을 짝짓는다(같은 카드 · `DOUBLE_CLICK_MS` 안 ·
  `DOUBLE_CLICK_SLOP` 안). 키보드 누름(`detail` 0) · 카드 안 조작 요소(단추 · 입력 · 링크 …)의 누름 · 카드 DOM 밖(portal)에서 버블된 누름은 세지 않는다.
- `component-palette.tsx` · `module-tab.tsx` — 카드 몸통에 그 훅을 달아 짝이 서면 «넣기» 단추와 같은 `add` 를 부른다(자리 판정 `palette-add.ts` · 연달아
  넣기 · 단추의 둘째 삼킴 그대로). 모듈 카드는 넣을 수 있는 판에만 단다.

### 결정

- **`dblclick` 이벤트가 아니라 `click` 짝이다.** 브라우저의 `dblclick` 은 누름 수로 서는데, 몸통을 끌어 놓은 자리에서 곧바로 누르면 OS 가 그 누름을
  더블클릭의 둘째로 셀 수 있다(CDP `clickCount: 2` 로 세운 판에서 `dblclick` 1 이 섰다). 끌기 장치가 끈 누름의 `click` 을 삼키므로 몸통에 닿은 `click`
  만 세면 그 판은 짝이 안 된다. 변조 D3(`detail >= 2` 면 넣기)가 그 차이를 보인다.
- 키보드는 그대로(«넣기» 단추). 홑클릭은 넣지 않는다.

## ② 페이지 정보 입력 스타일

### 바꾼 것

- `page-description.tsx` · `page-states.tsx` — 위 표의 칸 · 글 상자 넷에 `wb-shell-control`(«속성» 탭의 칸과 같은 클래스), 단추 다섯 자리에
  `wb-shell-panel-action`(패널의 글 단추)을 함께 단다. 제 클래스(자리 · 크기)는 그대로 둔다.

### 결정

- **새 규칙을 짓지 않고 «속성» 탭이 쓰는 클래스를 함께 단다.** 같은 값을 page-info 규칙에 옮겨 적으면 한쪽만 고쳐져 갈린다. 칸의 글 크기 · 줄 높이는
  제 규칙(뒤에 선다)이 이긴다 — 설명 상자의 `line-height: 1.6` 은 그대로다.
- 고친 뒤 값: 칸 · 글 상자 = `system-ui 13px` · `1px solid rgb(223,227,232)` · 모서리 4px · 여백 `3px 6px` · 글 `rgb(29,37,48)`(«속성» 탭 글 상자와 같음),

## ⑥ 페이지 JSON 내보내기 모달

### 고치기 전 판

페이지 줄 `…` 의 «JSON 내보내기» 가 곧바로 파일을 받았다(`downloadTextFile`) — 상자가 없다. 새 케이스 파일을 고치기 전 소스(⑥ 직전 `aad5a7b5` 의
`page-json-export.ts` · `menu-tree.tsx` · `page-json-notices.tsx`)로 돌린 판(변조 X0): 5 케이스 전부 빨강 — 상자가 안 서 `locator.waitFor` 30s 시간
초과(판이 안 섬 — 상자가 없다는 것이 고치기 전 값이다).

### 바꾼 것

- `page-json-export.ts` — 훅이 모달 상태(`view`: 불러오는 중 · 다 읽음(파일 이름 · 글) · 실패)를 든다. `run(pageId, title)` · `close()`. 읽는 중 닫으면 그 답을
  버린다(세대). `exporting`(항목 끔)은 읽는 동안이다. `settle`(열린 페이지의 보낸 편집을 기다림)은 그대로.
- `page-json-export-dialog.tsx`(새 파일) — `ShellDialog` 안: 읽는 동안 «불러오는 중…» · 다 읽으면 파일 이름 · 읽기 전용 글 상자(«내보낸 JSON») ·
  «클립보드에 복사» · «파일로 받기». 복사 성공 «클립보드에 복사했습니다»(`status`) · 실패 «복사하지 못했습니다 — 글 상자의 글을 골라 직접 복사하세요»
  (`alert`) + 글 상자 전체를 고르고 포커스. 읽기 실패는 상자 안 문장, 세션이 끊긴 실패는 `SignedOut`.
- `menu-tree.tsx` — 상자를 단축키 상자의 형제(`outside`)로 그린다(가져오기 상자와 같은 자리). 읽기라 편집할 수 없게 되어도 닫지 않는다.
- `page-json-notices.tsx` — 하단 바의 «내보내기 실패» 통지를 걷었다(가져온 결과만 남는다). `editor.tsx` · `shell.css` 주석, `shell.css` 에
  `.wb-shell-pagejson-copied`(초록 `#067647`).

### 결정

- **실패는 모달 안으로 옮겼다.** 실패하는 순간 상자가 떠 있다 — 하단 바로 보내면 뒤 화면은 막힌 채(모달) 상자에는 «불러오는 중…» 이 남는다. 실패 문장이
  설 자리가 둘이면 어느 쪽이 걷는지가 다시 갈린다. 그래서 하단 바 통지(`exportFailure` · «내보내기 실패 닫기» 단추)를 걷었다 — 그 이름을 세던 케이스
  `test/shell/icon-census.test.tsx` 의 `ICON_ONLY` 와 «통지» 수(2 → 1), 주석 둘(`build-test/editor-shell-modal.test.ts` · `palette-review.test.ts` 의 L-141)을 고쳤다.
- **바닥에 «닫기» 단추를 따로 두지 않는다.** 결정 기록은 «닫기» 를 상자 안 요소로 적었지만, `ShellDialog` 머리에 이미 «닫기»(아이콘 · 접근 이름 «닫기»)가
  있다. 같은 이름 둘은 playwright `getByRole(…, { name: '닫기' })` 를 strict 위반으로 만들고 같은 일을 하는 단추가 둘이 된다. 닫기는 머리 «닫기» · Escape.
- 받기 뒤에도 상자를 닫지 않는다(복사도 함께 할 수 있다). 상자 제목은 «JSON 내보내기 — <페이지 이름>».
- «내보내는 중 항목 끔» 은 지켰다 — 다만 읽는 동안 상자가 떠 있어 뒤 트리가 막혀(모달 `inert`) 사람이 그 항목에 닿을 길은 없다. 읽는 중 닫으면 곧바로
  다른 내보내기를 받는다(앞 읽기의 답은 버린다).
