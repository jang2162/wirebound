# CI 보고 — 조합 입력 · 선택지 · 자리표시자 — 1부(설계)

설계 문서: `docs/superpowers/specs/2026-10-24-compose-input-design.md`. 이번 디스패치는 설계만 했다 — 코드 · 정본은 안 고쳤다.

## 설계 요약

### 문제 1 — 조합 입력

| 결정 | 이유 |
| --- | --- |
| `Field` = 라벨(prop) + «값» 구역(몸통) · 새로 만들면 `Input` 하나가 든다(`initial`) | 흔한 꼴이 팔레트 한 걸음 그대로 · 같은 뜻의 컴포넌트가 둘로 갈리지 않는다 · 4단계 폼 표가 라벨 조각과 값 조각을 칸에 나눠 놓을 수 있다 |
| 조각 아홉 — `Input`(`kind` text · number · password) · `TextArea` · `Select` · `DateInput` · `TimeInput` · `CheckboxGroup` · `RadioGroup` · `Chip` · `Affix`(사이 글자 · `tone`) + 기존 `Button` | 설계서의 값 칸 꼴 전부가 이 줄 세우기로 선다(설계 문서 «조각 목록» 의 꼴 대응표). 날짜시간 · 숫자 전용 · 단일 체크박스 · 읽기 전용 값은 따로 안 둔다 |
| 세그먼트 · 체크 칩은 테마 변형(`RadioGroup.segment` · `CheckboxGroup.chip` · 기본테마의 `RadioGroup` 기본이 세그먼트) | 자료 모양이 같고 모양만 다르다 — 정본 «형태는 테마가 variant 로» (Q1) |
| 선택지 `options: { label, selected }[]` · 하나 고르는 타입은 `refine` · 상한 30 · 항목은 노드가 아니다 | 항목을 옮겨도 고른 것이 따라간다 · 배열 통째 교체 한 연산 |
| 패널 위젯 `optionList`(지금 `list-control.tsx` 를 넓힘) + 배열 위젯 전부에 옮기기(↑ ↓) | 지금 위젯에 옮기기가 없다 — `List.columns` 등도 함께 얻는다 |
| 폭 — 채우기는 몫(`weightRoom('Field')` → flex) · 고정 폭은 `size` 표지(short · medium · long) | 몫은 있는 장치 · 실제 길이는 테마 |
| `readonly` 상태 신설(`aria-readonly`) · `required` 는 `Field` 에만 | 설계서가 회색 readonly 와 딤드를 가른다 |
| 조건부 딤드 — 지금은 `disabled` 를 켠 판 + 코멘트, 7단계를 앞당기지 않는다 | 앞당기면 L · 7단계 설계 전체가 따라 온다 |
| 폼 규칙(`accepts` 없음 · lint `structural-gap`) 그대로 · 조각은 어디에나 선다 | 5단계 그리드 셀 · 결과 머리줄에서 조각이 `Field` 밖에 서야 한다 |
| `change` 는 기본 뷰에서 안 돈다(실제 입력이 없다 — 지금 `Field` 와 같은 판) · 이 단계에서 안 바꾼다 | 바꾸려면 트리거 → 이벤트 규칙을 정하는 별 트랙 |
| 문서 판 4 · `0029-compose-field` 가 `control` 을 조각으로 옮긴다(Q3) | `0028` 꼴 · S |

### 문제 2 — 자리표시자

| 결정 | 이유 |
| --- | --- |
| 이 컴포넌트만 그리기 prop(크기 · 바탕 · 테두리 꼴 · 테두리 색 · 모서리 · 글 색 · 글 크기 · 정렬 · 여백 · 그림 · 그림 맞춤)을 든다 — 봉투는 그대로 | 카탈로그 밖 요소를 그리는 탈출구 · 정본 원칙 문단에 예외 한 줄 |
| 색은 `#rrggbb` 자유 값(Q4) · 길이는 정수 px · 뷰가 `--wb-node-placeholder-*` 변수로 싣고 `wb-theme check` 가 테마가 값을 따르는지 잰다 | 자유 CSS 글자는 `url(…)` 바깥 요청 · 꾸밈 넘김을 연다 |
| 몸통 구역 하나(«내용») · 자식이 있으면 라벨이 안 선다 · 가로 줄 세우기 | 칩 · 배지를 지어 모듈로 저장 |
| 그림은 내용 주소 — `asset_blobs`(sha256 · bytea) + `project_assets` · `personal_assets` 소유 행 · 노드는 `image: <sha256>` | 권한은 소유 행이 가르고 복사는 바이트 없이 행 하나 · DB 라 compose 볼륨이 안 는다 |
| 올리기 editor 이상 · 읽기 viewer 이상 · 파일 5 MB · 프로젝트 200 MB · 사람 100 MB(환경 변수) · PNG · JPEG · WebP · GIF · SVG(Q7 — `CSP sandbox` · `nosniff`) | 문서 권한과 같은 축 |
| 다른 프로젝트로 붙이기 · 개인 모듈 저장 · 넣기 · 복사는 `claim` 라우트로 소유 행을 옮기고, 못 옮긴 그림은 비우고 말한다 · 봉투에 출처 프로젝트를 싣는다 | 해시를 안다고 읽을 수 없게 |
| 그림은 프로젝트 · 사람과 함께만 지운다(Q5) | 스냅샷 · 되돌리기 · 모듈이 가리킬 수 있다 |
| 번들은 그림을 `assets/images/` 에 싣고 렌더러 `assetUrl` 옵션 · SDK `useAsset` · PPTX 는 번들을 찍어 따로 없다 · MCP 도구는 안 더한다 | 캡처의 가짜 origin 이 번들 파일을 이미 다 내준다 |
| 패널 — 새 컨트롤 `color`(견본 · hex · 지우기) · `image`(고르기 · 끌어 놓기 · 그림 칸에서 붙여넣기 · 올린 그림에서 · 진행(XHR) · 실패 문장 · 잠금) | |

## 구현 나누기

- **CI-A 조합 입력(L)** 과 **CI-B 자리표시자(L ~ XL — B1 props · 몸통 M, B2 그림 L)** 를 다른 워크트리에서 나란히 돌린다. 서로의 산출물을 안 쓴다.
- **CI-A 를 먼저 병합한다.** 겹치는 곳은 `EditorControl` 한 줄 · SDK 판(1.4.0 → CI-B 1.5.0) · `system-admin` 판과 `checksums.json` · 갤러리 표본 · `marks.ts` 표 · `render.tsx` 한 줄씩 · `/llms.txt` 생성물이다. CI-B 의 rebase 는 판 번호 · checksum 새 줄 · 생성물 다시 내기로 기계적이다.
- **마이그레이션 번호를 미리 나눈다** — CI-A `0029-compose-field` · CI-B `0030-assets`. 병합 전 CI-B 워크트리 테스트 DB 의 `kysely_migration` 기록을 맞춘다.
- 개수 하한(`palette.test.ts` 카드 ≥ 17 등)은 타입이 늘기만 해 참으로 남는다 — 표본 수를 단언하는 자(`theme-kit` 의 `dev.test.ts` · `shots.test.ts`)는 각 트랙이 센다.

## 브리프와 다른 것

- 브리프 «5» 는 «검색폼의 칸 · 입력폼의 행이 `Field` 를 받는 지금 규칙(`accepts` · lint `structural-gap`)» 이라 했다. 지금 두 폼의 몸통 구역에는 `accepts` 가 없다(무엇이든 받는다) — `Field` 를 요구하는 것은 lint `structural-gap`(경고)뿐이다. 설계는 그 사실 위에 섰다(`git grep -n -A3 "name: 'body'" -- packages/schema/src/component/catalog/input.ts`).

## 게이트

코드 변경 없음 — 게이트 생략. 바뀐 파일은 이 보고와 설계 문서 둘이고 숨은 글자(U+2028 · 방향 제어 · 폭 없는 글자 · 제어 글자) 수는 둘 다 0 이다.

## 지침

고칠 지침 없음. 이번 차수에서 지침이 틀렸거나 빈 자리를 만나지 않았다.
