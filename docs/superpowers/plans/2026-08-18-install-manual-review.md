# 설치 매뉴얼 — 독립 리뷰

> 대상: 브랜치 `docs/install-manual` (`f64da4e`) · 워크트리 `.worktrees/docs-install-manual`
> 계획: `2026-08-18-install-manual.md` · 구현자 보고: `2026-08-18-install-manual-report.md`

**한 줄.** **구현자의 보고를 읽지 않은 채로 문서만 보고 세 번째로 세웠다** — 새 클론에서
처음부터 끝까지, 그리고 D4·D6·§7·§8·§9의 주장을 하나씩 다시 쟀다. **문서가 적은 값은 거의
전부 재현됐다.** 그러나 **문서가 스스로 내건 자**(*"적은 것은 전부 돌려 봤다"*)**를
어기는 문장이 넷** 나왔고, 그중 하나(`wireb`로 이유를 본다)는 **돌려 보면 그렇지 않다.**
게이트 넷은 내가 다시 돌려도 전부 **0**이고, 사용자 데이터는 **처음과 같다.**

**판정: 지금 그대로는 병합 불가.** 막는 것은 **넷뿐이고 전부 한 줄 고침**이며 값은 §4에
있다. 코드 변경(D4)은 **옳고 구분력도 있다** — 내가 다시 재서 확인했다.

## 0. 이 리뷰가 선 자리

- **문서만 보고 세웠다.** 구현자 보고서는 **모든 측정을 끝낸 뒤에** 열었다(§6에서 교차 확인).
- **무대는 새 클론이다.** `git clone --branch docs/install-manual` 로
  스크래치패드에 `fresh`를 만들었다 — `node_modules`·`dist`·`.env`가 없는 진짜 빈 체크아웃이고
  구현자의 워크트리를 안 건드린다.
- **워크트리에는 아무것도 안 썼다.** 리뷰 끝에 `git status`가 비어 있다(이 보고서 파일 하나 전).
- **공유 자원.** `docker compose down -v` 안 썼다. 컨테이너 새로 안 띄웠다. 포트 3001·5173 안 썼다
  (api **3021** · vite 5173 은 **내가 띄운 것이 유일한 리스너**였음을 `lsof`로 먼저 확인했다).

## 3. D4 — 코드 변경을 내가 다시 쟀다

**케이스 다섯을 끝에서 끝까지 다시 세웠다.** 무대는 새 클론 + api(포트 3021) + 페이지 하나짜리
프로젝트. 매번 `.env` 를 바꾸고 **서버를 다시 띄웠다**(§3 이 그러라고 한다).

| 케이스 | `.env` | export | `ppt/media` | preview |
|---|---|---|---|---|
| **A. 안 준다**(오늘의 길) | — | 200 · **8,356 B** | **1개** | `screenFailures=0` |
| **B. 빈 문자열** | `SCREEN_CHROMIUM_PATH=` | 200 · **8,356 B** | **1개** | `screenFailures=0` |
| **C. 캐시를 비우고 경로만 준다** | `PLAYWRIGHT_BROWSERS_PATH=/tmp/wb-empty-cache`<br>`SCREEN_CHROMIUM_PATH=…/chrome-headless-shell` | 200 · **8,356 B** | **1개** | `screenFailures=0` |
| **D. 틀린 경로** | `SCREEN_CHROMIUM_PATH=/usr/bin/chromium-없는경로` | 200 · **7,998 B** | **0개** | `screenFailures=1` · *"Failed to launch chromium because executable doesn't exist at /usr/bin/chromium-없는경로"* |
| **E. 브라우저가 아예 없다** | `PLAYWRIGHT_BROWSERS_PATH=/tmp/wb-empty-cache` | 200 · **7,998 B** | **0개** | `screenFailures=1` · *"Executable doesn't exist at /tmp/wb-empty-cache/chromium_headless_shell-1234/…"* |

**세 가지가 값으로 드러난다.**

1. **A 와 B 가 바이트까지 같다** — *"빈 문자열은 안 준 것과 같다"* 가 서버 수준에서 참이다.
2. **C 가 결정적이다.** E 가 *"그 캐시로는 못 띄운다"* 를 먼저 증명하고, 같은 캐시에 **경로만 더하니
   그림이 실렸다.** 새 변수가 **실제로 `chromium.launch()` 에 닿는다.**
3. **거짓 양성이 없다.** 멀쩡한 환경(A)은 변수를 안 줘도, 줘도(B) 오늘과 같다.
   게이트 넷도 전부 0 이다(§7).

### 틀린 경로를 주면 무엇이 보이나 — **조용히 전부 실패로 간다**

**D 와 E 의 관측이 구분되지 않는다.** 둘 다 HTTP **200**, 같은 **7,998 B**, `ppt/media` **0개**,
슬라이드는 **"화면 이미지가 실리지 않았습니다"** 하나뿐이다. 다른 것은 `export/preview` 의
`reason` 문자열 하나다.

**그리고 서버 로그에 아무 흔적이 없다.** 케이스 D 를 돌린 뒤 api 로그에서
`chromium|browser|screen|화면` 을 세면 **0**이고 `warn`·`error` 레벨 줄도 없다.

**여기에 함정이 하나 더 있다.** 케이스 D 는 `PLAYWRIGHT_BROWSERS_PATH` 를 안 걸었다 —
**캐시는 멀쩡한 상태였는데도 실패했다.** 즉 **명시 경로가 캐시를 이긴다.** 오타를 낸 사람이
§8.1 의 증상을 보고 §8.2 의 `install chromium` 을 돌리면 **아무것도 안 낸다**(이미 있으니까)
**그리고 여전히 실패한다.** → §4 **B4**

### 케이스의 구분력 — 변조해서 실증했다

**구현자의 워크트리가 아니라 새 클론에서** 프로덕션을 변조하고 되돌렸다.

| 변이 | 결과 |
|---|---|
| `main.ts` 를 `chromiumScreenRenderer()` 로 되돌린다 | **종료 1** — `× main.ts 가 config.screenChromiumPath 를 그리는 자에게 넘긴다` **하나만** 빨강(나머지 6 초록) |
| `config.ts` 의 빈 문자열 접기를 뺀다 | **종료 1** — `× 빈 문자열은 안 준 것과 같다` **하나만** 빨강(나머지 3 초록) |

**둘 다 정확히 하나씩 잡는다.** 베이스라인은 2 파일 · 11 케이스 전부 초록이었다.

**전달 자체는 기존 케이스가 이미 잰다** — `apps/api/build-test/screen-chromium.test.ts:227`
가 `chromiumScreenRenderer({ executablePath: '/tmp/wirebound-no-such-chromium' })` 로
**실패 방향**을 든다(이 브랜치가 안 건드린 파일이다). **성공 방향**(옳은 경로를 주면 그 실행 파일로
뜬다)은 **자동 케이스가 없다** — 내가 케이스 C 로 손으로 쟀다. 브라우저 둘이 필요한 자리라
케이스로 못 세우는 것이 이해되지만 **그 사실이 어디에도 안 적혀 있다**(낮음).

## 4. 고쳐야 하는 것 — **넷**

전부 **한 줄**이고 값은 여기 있다.

### B1. §8.1 — *"`wireb`로 내보내야 보인다"* 는 **돌려 보면 그렇지 않다** (README:377)

> **그래서 이유는 API 를 직접 부르거나 `wireb`로 내보내야 보인다.**

**관측.** 틀린 경로가 걸린 상태에서 문서가 §5 에 적은 그대로 불렀다:

```
$ wireb export --format pptx -o out
/…/impl/out 에 1개 파일을 썼습니다      ← 이것이 전부다
exit=0                                   ← 7,998 B 짜리 pptx 가 나온다
```

**이유를 한 글자도 안 낸다.**

**진단.** `packages/cli/src/commands/export.ts:104` 가 부르는 것은 **`/export` 하나**다 —
`export/preview` 를 안 부른다. 그래서 `screenFailures` 가 **CLI 에 도달할 길이 없다.**
`packages/cli/src` 전체에 `screenFailures`·`fontWarning` 이라는 문자열이 **없다.**

**왜 걸리나.** 이 문장은 §8.1 표가 *"에디터에는 아예 안 간다"* 를 말한 **직후의 탈출구**다.
파일만 받은 사람이 이유를 찾으려고 `wireb` 로 가면 **같은 파일을 한 번 더 받고 끝난다.**

**고침(값).** 이 문장에서 `wireb` 를 뺀다. 예:

> **그래서 이유는 `GET .../export/preview?format=pptx` 를 직접 불러야 보인다. `wireb export` 로도
> 안 보인다 — 그 명령은 `/export` 만 부르므로 `screenFailures` 를 받지 않는다(이 기계에서 쟀다:
> 실패 상태에서도 *"1개 파일을 썼습니다"* 와 종료 코드 0 뿐이다).**

### B2. §6.1 — `pnpm start` 가 **저장소 루트에 없다** (README:228)

> (이 기계에서 쟀다: `packages/*/dist`를 지우면 `pnpm start`가 위 문장과 함께 **종료 코드 1**, …)

**관측.**

```
$ pnpm start                    # 저장소 루트 — 문서가 사람을 세워 둔 자리
 ERR_PNPM_NO_SCRIPT_OR_SERVER  Missing script start or file server.js
exit=1
```

**루트 `package.json` 에 `start` 가 없다** — `build`·`test`·`test:watch`·`test:build`·`typecheck`
다섯뿐이다. `start` 는 `apps/api/package.json` 에만 있다.

**왜 걸리나.** **종료 코드가 양쪽 다 1 이다.** 재현해 본 사람은 *"1 이 나왔으니 문서가 맞다"* 고
읽고 넘어가는데, 실제로는 **완전히 다른 이유로 1** 이었다. 게다가 README 의 다른 모든 api 명령은
`pnpm --filter @wirebound/api …` 형태다 — 이 한 줄만 형태가 다르다.
(구현자 보고서 §3.3 은 **`pnpm start`(api)** 라고 적었다. **README 로 옮기면서 그 단서가 빠졌다.**)

**고침(값).** `pnpm start` → **`pnpm --filter @wirebound/api start`**.

### B3. §6.6 — **502 가 아니라 500** 이고, 가장 큰 신호가 빠졌다 (README:302)

> 네트워크 탭에서 `/api/...` 요청이 **502·연결 거부**면 프록시 대상이 틀린 것이고, **401**이면 …

**관측.** 프록시 대상(3001)에 아무도 없는 상태에서:

```
$ curl -o /dev/null -w '%{http_code}' http://localhost:5173/api/auth/me
500                      ← 본문 0 바이트
```

같은 순간 **vite 터미널이 이렇게 찍는다:**

```
2:26:14 PM [vite] http proxy error: /api/auth/me
Error: connect ECONNREFUSED 127.0.0.1:3001
```

**401 쪽은 맞다** — 프록시를 3021 로 고치자 미로그인 `/api/auth/me` 가 **401**, 로그인 **200**,
프로젝트 목록 **200** 으로 그대로 돌았다(§3 의 상자 주장도 이것으로 재현됐다).

**왜 걸리나.** 사람이 devtools 에서 502 를 찾다가 500 을 보면 *"프록시 문제가 아닌가 보다"* 로
샌다. 그리고 **틀린 대상을 이름까지 말해 주는 줄이 두 번째 터미널에 이미 떠 있는데** 문서가
그것을 안 가리킨다 — 브라우저 devtools 보다 이쪽이 훨씬 빠르다.

**고침(값).**

> **네트워크 탭에서 `/api/...` 요청이 500(본문 없음)이면 프록시 대상이 틀린 것이다.**
> **더 빠른 자리는 에디터를 띄운 터미널이다** — vite 가 `http proxy error: /api/auth/me` ·
> `Error: connect ECONNREFUSED 127.0.0.1:3001` 로 **틀린 대상을 이름까지 말한다.**
> **401**이면 서버는 붙었고 로그인만 안 된 것이다.

### B4. §8.3 — **틀린 경로를 준 사람이 빠져나올 길이 없다**

§8.3 은 *"비우면 기본 길로 돌아간다"* 와 *"고쳤으면 다시 띄워라"* 만 든다.
**값을 틀리게 적었을 때 무엇이 보이는지가 없다.**

**관측**(§3 케이스 D). `SCREEN_CHROMIUM_PATH` 에 없는 경로를 넣으면:

- `export` 는 **HTTP 200 · 7,998 B**, `ppt/media` **0개**, 슬라이드는 *"화면 이미지가 실리지 않았습니다"*
- **브라우저가 없을 때(케이스 E)와 관측이 구분되지 않는다**
- **서버 로그에 흔적 0** (`chromium|browser|screen|화면` 매치 0, warn/error 줄 0)
- **playwright 캐시가 멀쩡해도 실패한다** — 명시 경로가 캐시를 이긴다

**왜 걸리나.** **이 변수는 이 슬라이스가 새로 연 것이다.** 매뉴얼이 사람에게 손으로 경로를 적게
시켜 놓고, 그 손이 미끄러졌을 때의 관측을 안 적었다. 그 사람이 §8.1 을 펴면 *"브라우저가 없다"* 로
읽히고 §8.2 의 `install chromium` 을 돌린다 — **출력 없이 0** 이 나오고(이미 있으니까) **여전히
안 된다.** 매뉴얼 안에 갇힌다.

**고침(값).** §8.3 에 한 줄:

> **경로를 틀리게 적으면 브라우저가 없는 것과 똑같이 보인다** — 200 으로 파일이 나오고 슬라이드는
> *"화면 이미지가 실리지 않았습니다"* 뿐이며 **서버 로그에도 안 남는다.** 다른 것은
> `export/preview` 의 `reason` 하나다: *"Failed to launch chromium because executable doesn't
> exist at &lt;네가 적은 경로&gt;"*(이 기계에서 쟀다). **이 값은 8.2 의 캐시를 이기므로 `install
> chromium` 을 다시 돌려도 안 낫는다** — 먼저 이 줄부터 지워라.

## 5. 낮은 것 — 값과 함께 (병합을 막지 않는다)

**C1. §2 걸음 1 이 §6.3 을 안 가리킨다.**
§2 의 유일한 앞가리킴은 §6.1 이다. 그런데 **기계에 컨테이너가 이미 있으면 걸음 1 에서 바로
§6.3 을 만난다** — 나도 그랬다(새 클론 `fresh` 에서 `compose ps` 가 빈 표). §6.3 은 그 원인을
*"디렉터리 이름이 프로젝트 이름"* 이라고 정확히 적고 있지만 **표제가 "워크트리" 를 든다.**
둘째 체크아웃이면 무엇이든 같은 일이 난다. 걸음 1 옆에 `(이미 떠 있으면 6.3)` 한 마디면 된다.

**C2. §6.1 과 `apps/api/README.md` 가 거의 같은 문단을 든다 — D1 자신의 기준에 걸린다.**
D1 은 *"겹치는 문단이 생기면 그것이 두 벌이다"* 라고 못 박았다. `apps/api/README.md` 의
*"왜 `pnpm build` 가 이 서버의 전제인가"* 는 **README §6.1 의 원인 문단과 거의 문장 단위로
같다**(`tsx`·`exports`·`dist`·vitest alias·*"테스트는 통과하는데 서버만 안 뜬다"* 까지).
`build:watch` 한 줄도 양쪽에 있다. api 쪽이 이미 *"증상 문장과 조치는 최상위 README §6.1"* 이라고
가리키고 있으므로 **원인 문단도 가리키고 지우면 된다.**

**C3. `pnpm install` 이 내는 세 번째 메시지를 §6.2 가 안 든다.**
관측: `The following dependencies have build scripts that were ignored: esbuild`.
`WARN` 은 아니지만 처음 받는 사람에게는 **셋째 이상한 줄**이다. §6.2 는 둘만 든다.

**C4. §5.3 코드 4 는 맞지만, 자주 만나는 쪽은 코드 2 다.**
`.wirebound.json` 의 `server` 만 못 닿는 값으로 바꾸면 **코드 4 가 아니라 2** 가 나오고
메시지가 *"…에 쓸 자격이 없습니다. `wireb login` 을 먼저 실행하세요"* 로 **자격을 탓한다**
(자격이 `(server, projectId)` 로 매여 있어 네트워크를 타기 전에 끊긴다). 코드 4 는
**같은 주소의 서버가 죽었을 때** 나온다 — 그것은 내가 재현했다. CLI 성질이지 문서 오류는
아니지만, §5.3 이 한 줄 더 들면 사람이 덜 헤맨다.

**C5. 게이트가 사람에게 §8.2 와 **다른** 설치 명령을 말한다.**
브라우저가 없을 때 `pnpm test:build` 가 찍는 줄(`apps/api/build-test/screen-chromium.test.ts:57`):

```
[P10-2 스모크] 이 기계에 Chromium 이 없어 건너뛴다 — `npx playwright install chromium`
```

**§8.2 는 `node apps/api/node_modules/playwright-core/cli.js install chromium` 이 유일하게
되는 길이라고 적었다.** 이 저장소가 `playwright` 패키지를 일부러 안 들이는데 코드가 그것을
권한다. 코드는 이 브랜치가 안 건드린 자리지만, **매뉴얼이 브라우저 설치의 단일 진실이 되겠다고
한 이상** 이 어긋남을 한 줄로 흡수하거나 코드 쪽 문구를 맞추는 것이 옳다.

**C6. §5.1 의 되돌리기가 끝까지 안 지운다 — 그리고 이 기계에 그 잔재가 실제로 있었다.**
§5.1 은 *"되돌리려면 `pnpm uninstall --global @wirebound/cli @wirebound/mcp`"* 라고 적는다.
**돌려 봤다:** `PATH` 의 `~/Library/pnpm/wireb`·`wireb-mcp` 와 `node_modules` 항목은 지워지지만
**둘이 남는다.**

```
~/Library/pnpm/global/5/package.json      → pnpm.overrides 에 link: 항목이 그대로
~/Library/pnpm/global/5/node_modules/.bin → wireb · wireb-mcp 셸 스크립트가 그대로
```

**리뷰를 시작할 때 이 기계에 이미 그 잔재가 있었다** — overrides 가
`link:…/IdeaProjects/wirebound/.worktrees/docs-install-manual/packages/{cli,mcp}` 를 가리키고
있었고 `.bin` 파일 mtime 이 14:07(구현자의 T4 시각)이었다. **병합 뒤 워크트리를 지우면 그 링크는
죽은 경로를 가리킨다.** 내가 `overrides` 를 비우고 `.bin` 둘을 지워 **완전히 원상복구했다**
(`command -v wireb` → 없음).
문서에 `pnpm ls --global` 로 확인하라는 한 줄, 또는 남는 것이 있다는 사실 한 줄이 필요하다.

**C7. §8.1 이 "서버 로그에도 안 남는다" 를 안 든다.**
표가 *"에디터에는 아예 안 간다"* 까지는 말한다. **로그도 조용하다** — 운영자가 지켜보는
자리에도 아무것도 안 간다는 것이 값이다(케이스 D 에서 매치 0).

**C8. 사라진 정보 하나.** `apps/api/README.md` 에 있던 `pnpm test:build` 의
*"패키지 재빌드 포함, 수십 초"* 가 양쪽 어디에도 없다. README §9 는 *"받는 쪽이 받는 것"* 이라고만
한다. (내 실측: 워크트리에서 **10.99초** — 이미 빌드된 상태였다.)

**C9. 성공 방향의 자동 케이스가 없다는 것이 안 적혀 있다.**
`executablePath` 의 **실패** 방향은 기존 build-test 가 잰다. **옳은 경로를 주면 그 실행 파일로
뜬다**는 쪽은 케이스가 없다(브라우저 둘이 필요하다). 내가 손으로 쟀다(케이스 C). 이월 §3.6 에
한 줄이면 다음 사람이 안다.

## D2. B1 의 판정 — **동의한다**

구현자는 *"CLI 가 `export/preview` 를 더 부르면 브라우저를 두 번 띄운다"* 를 근거로 코드를

|---|---|

| `export?format=pptx` | **0.29초** |
| `export/preview?format=html` (화면을 안 그린다) | **0.04초** |

**미리보기가 화면을 그리는 쪽이 안 그리는 쪽보다 한 자릿수 무겁고 내려받기와 같은 급이다.**
그러므로 ⓐ 를 택하면 `wireb export` 한 번이 **모든 페이지를 두 번 그린다.** 이월 §3.4 가

**판정: 동의한다.** 오늘 할 수 있는 최선은 *"문서가 사실을 말하는 것"* 이고 그것을 했다.

**이월 §3.6 이 다음 사람에게 충분한가 — 충분하다.** 그 줄이 (i) 관측을 값으로,

**곁다리 관측 하나**(비차단 · 문서의 길 밖). §5.1 의 되돌리기 명령은 **㉯ 의 둘을 다 걸었을
때만** 돈다. 하나만 걸어 두고 그 명령을 치면 pnpm 이
`ERR_PNPM_CANNOT_REMOVE_MISSING_DEPS  Cannot remove '@wirebound/mcp'` 로 **통째로 실패하고
아무것도 안 지운다**(쟀다 — 그 뒤에도 `command -v wireb` 가 그대로였다). §5.1 은 둘을 함께
걸라고 적으므로 문서의 길 위에서는 안 만나는 자리다.
