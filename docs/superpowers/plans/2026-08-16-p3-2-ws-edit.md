# P3-2 WS 편집 전송 · ack · 리베이스 구현 계획

> **에이전트에게:** 태스크 단위로 실행한다. 각 태스크는 실패하는 케이스 → 최소 구현 →
> 통과 → 커밋의 순서를 지킨다.

**목표.** §7.1의 나머지 절반을 세운다. 이 슬라이스가 끝나면 *"편집이 WS로 나가고, 내 것은
ack로 정리되며, 남의 것은 **내 pending 위에 리베이스되어** 얹힌다"*가 참이 된다.

**§7.1:**

```
[클라] 속성 변경 → 로컬 낙관적 적용 → WS 전송 { pageId, baseSeq, ops[], clientOpId }
[서버] 권한 확인(editor+) → … → 룸 broadcast
[본인] ack(seq) 수신 → pending 큐에서 제거
[타인] ops 수신 → 자기 pending 위에 리베이스 적용
```

**P3-1은 서버가 알리는 것까지 했다.** 이 슬라이스는 **클라이언트가 보내는 것**이다.
③소프트 잠금(§7.2)이 남는다.

**스택.** `apps/api`(WS patch 프레임) · `apps/web`(전송·ack·리베이스) · vitest.

## 이 계획이 딛고 선 사실 — 전부 P3-1 이월에서 왔다

| # | 사실 | 어디 |
|---|---|---|
| 1 | **오늘 WS 경로 어디에도 `editor` 판정이 없다.** 핸드셰이크도 프레임 수신도 `viewer`다 — **받는 기준과 보내는 기준이 같은 함수 하나에 겹쳐 있다.** 그대로 쓰면 **뷰어가 patch를 낸다** | §1.1 |
| 2 | **`RoomConnection`은 역할을 안 들고 있고 `stillAllowed`는 `findMembership`이 돌려준 역할을 버린다** — 조회를 더하든, 역할을 돌려주게 하든, **최소 역할을 인자로 받게 하든** 셋 중 하나를 판정해야 한다(**셋째가 값이 있어 보인다**) | 〃 |
| 3 | **`parseClientFrame`이 오늘 `ping` 하나다.** 갈래가 늘면 zod로 옮긴다고 그 주석이 적었고, **`http/patch-ops.ts`가 이미 REST 본문의 zod 경계를 갖고 그 머리말이 *"P3가 그것을 그대로 import한다"*고 적었다** | 〃 |
| 4 | **`'deferred'` 갈래가 리베이스가 들어갈 자리다**(`store/editor-store.ts`). 오늘은 pending이 있으면 안 얹고 화면이 낡았다고 말한다 | §2.2 |
| 5 | **미룬 ops를 쌓아 두지 않은 것이 P3-1의 판정이고, 근거는 REST 전송이 `baseSeq` 일치를 요구해 저절로 수렴한다는 것이다** — **WS 전송이 그 전제를 바꾸면 이 판정도 바뀐다** | 〃 |
| 6 | **리베이스는 *"내가 seq n까지 전부 받았다"*를 전제하고, 지금 그것을 지키는 것은 `'gap'` 갈래다** — 지키는 방식이 **거절**이라 수렴을 편집자에게 떠넘긴다. **아무것도 안 내고 보고만 있는 사람은 스스로 수렴하지 않는다** | §2.4 |

| 9 | **자기 편집을 되받아 선 `'pending'` 낡음이 `ackEdit`으로 안 풀린다** | §4.5 |
| 10 | **인구조사가 새 `applyEdit` 호출자를 `src/` 어디에 두든 잡는다** | §1 |

## 확정한 결정

### D1. **patch 프레임은 `editor` 이상을 따로 요구한다**

사실 1·2. §10은 viewer를 *"조회 전용 — 편집·코멘트 모두 불가"*로 못박았다.

- **`stillAllowed`를 그대로 부르지 마라.**
- 이월이 권한 셋 중 **최소 역할을 인자로 받게 하는 쪽**을 값이 있다고 봤다 — 그러면
  *"받는 기준"*과 *"보내는 기준"*이 **같은 함수의 두 호출**로 남고 `roleAtLeast` 하나가
  계속 유일한 비교 지점이 된다. **재고 판정하라. 다른 답이 나으면 근거를 적어라.**
- **뷰어가 내면 거절되고 에디터가 내면 통과하는 케이스를 둬라.** `ws-auth.test.ts`의
  *"뷰어도 붙는다"* 옆이 자리다.

### D2. **프레임 규격을 zod로 옮기고, REST의 경계를 그대로 쓴다**

사실 3. **`http/patch-ops.ts`를 import한다 — 두 벌을 만들지 마라.**

- 두 벌이면 *"REST로는 되는데 WS로는 안 되는"* 입력이 생기고, 그 어긋남은 접속 방식에 따라
  갈린다. 이 저장소가 반복해서 닫아 온 자리다(`partitionIssues` · `gatePageImport`).
- **import할 수 없으면 왜인지 재서 적고, 같은 함수를 부르는 길을 찾아라.**

### D3. **리베이스가 이 슬라이스의 알맹이다**

`'deferred'`를 갈아 끼운다(사실 4).

- **전제를 `remoteStale === null`로 읽지 마라**(사실 7). 리베이스가 요구하는 것은
  *"빠짐없이 받았다"*이고, 그것을 지키는 것은 `'gap'` 갈래다(사실 6). **그 둘이 같은 값이
  아니라는 것을 케이스가 들게 하라.**
- **리베이스가 실패하는 경우가 있다.** JSON Patch는 경로 기반이라 남의 편집이 내 pending의
  경로를 지웠으면 적용되지 않는다. §7.3이 undo에 대해 같은 상태를 이렇게 정했다:
  *"에러가 아니라 **정상 흐름으로 처리한다** — 스택에서 제거하고 안내한 뒤 다음으로 넘어간다."*
  **같은 성질인지 판정하고, 같다면 같은 말로 다루어라.**
- **사실 5를 다시 판정하라.** *"미룬 ops를 쌓아 두지 않는다"*의 근거가 REST의 `baseSeq`
  일치였다. **WS 전송이 그 전제를 바꾸는가.**
- **`'deferred'` 케이스들이 죽는다**(`test/store/remote-change.test.ts`). **죽는 것이 맞다 —
  지우지 말고 명제를 바꿔라.** `'diverged'`·`'restored'`·`'gap'`은 남는다.

### D4. **ack가 pending을 정리한다 — 그리고 사실 9를 닫는다**

§7.1: *"본인 ack(seq) 수신 → pending 큐에서 제거."*

- **`clientOpId`로 짝을 짓는다**(§7.1의 프레임에 있다). 그것이 왕복하는 경로를 재라 —
  오늘 revision이 그것을 나르는지(**재라 #3**).
- **사실 9가 여기서 닫힌다** — 자기 편집을 되받아 선 `'pending'` 낡음이 `ackEdit`으로 안
  풀리던 것. **닫히는지 케이스로 확인하라.**

### D5. **REST 경로는 남고, 두 진입점이 같은 것을 쓴다**

사실 8. §7.4가 *"MCP의 `patch_page`는 WebSocket 대신 REST로 들어오지만, 그 뒤 파이프라인은
완전히 같다"*고 적었다.

- **`applyEdit`도 브로드캐스트도 같은 함수다.** 인구조사(사실 10)가 그것을 지킨다.
- **`warnings`를 WS 경로도 실어야 한다** — P4a-3이 *"한쪽만 나르면 사용자가 보는 것이 접속
  방식에 따라 갈린다"*고 못박았다.
- **`x-wb-connection-id`를 지우지 마라.** WS 경로는 연결 자체를 `exceptConnectionId`로 넘긴다.

### D6. **자동 재조회를 넣는다 — 자리는 `routes/editor.tsx`다**

이월 §2.4가 *"P3-2의 것"*이라며 자리까지 지목했다.

- **스토어가 자기 조회를 갖게 하지 마라** — 페이지를 여는 경로가 둘이 된다. **`loadPage`
  하나여야 한다.**
- `useRealtime`이 신호를 올리는 이음매를 만든다.
- **연결이 다시 붙은 것 자체가 신호일 수 있다** — 끊긴 동안의 프레임은 어차피 사라졌으므로
  `onStatus('open')`이 두 번째 이후일 때 다시 읽는 것이 갭을 기다리는 것보다 빠르다.
  **판정하고 근거를 적어라.**
- **사실 6의 *"보고만 있는 사람은 스스로 수렴하지 않는다"*가 이것으로 닫히는지 재라.**

### D7. **하나짜리로 재지 마라 — 이 슬라이스의 자리들**

| 자리 | 섞이면 |
|---|---|
| pending 여럿 × 남의 ops 여럿 | 리베이스가 순서를 잃어도 안 죽는다 |
| 연결 둘 이상 | 발신자에게 자기 것이 되돌아오는지, ack가 남에게 가는지 |
| 프로젝트 둘 | §10의 경계가 WS 편집 경로로 새는지 |
| `clientOpId` 여럿 | ack가 엉뚱한 pending을 지우는지 |

## 계획이 재지 않은 것

- **소프트 잠금** — P3-3. §7.2.

- **presence를 화면이 쓰는 것** — 이월 §4.2. **P3-3이 그 위에 선다.**
- **다중 인스턴스** — 이월 §5가 교체 비용을 목록으로 남겼다.
