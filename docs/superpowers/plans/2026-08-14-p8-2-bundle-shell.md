# P8-2 번들 구조 · 뷰어 셸 구현 계획

> **에이전트에게:** 태스크 단위로 실행한다. 각 태스크는 실패하는 케이스 → 최소 구현 →
> 통과 → 커밋의 순서를 지킨다.

**목표.** §11.3의 **번들 파일 트리**와 **뷰어 셸**을 세운다. 이 슬라이스가 끝나면
*"페이지 여럿을 트리 네비로 오가며 목업과 코멘트를 함께 본다"*가 파일만으로 참이 된다.

**§11.3:**

```
wirebound-export/
  index.html            트리 네비 + 뷰어 셸
  pages/
    관리자-회원-목록.html
  assets/
    theme.css           테마 컴파일 결과
    runtime.js          상호작용 런타임        ← P8-3
```

*"트리 네비게이션·목업·코멘트 **3분할이 웹 앱과 동일**하고, 상호작용도 동작한다."*

**§9의 뷰 모드:** 구조 트리가 접혀 **메뉴 트리가 전체를 쓰고**, 우측 탭이
**페이지 설명 / 코멘트 / 상호작용** 셋이다.

**스택.** `packages/exporter` · vitest. **서버·웹은 건드리지 않는다**(P8-3이 한다).

---

## 전역 제약

- **워크트리 안에서만 작업한다.**
- `pnpm test` · `pnpm typecheck` · `pnpm build`가 마지막에 전부 통과해야 한다.
  **종료 코드는 파이프 없이 따로 찍어라.**
- **게이트를 돌리기 전에 다른 세션이 돌고 있지 않은지 확인하라** — api 테스트가 Postgres
  하나(포트 5433)를 공유하고, `vitest`의 `singleFork`는 **서로 다른 프로세스에 적용되지
  않는다**(P7-3 이월 §10의 실측).
- **`git checkout --`을 쓰지 마라.** python 치환으로 심고 `finally`에서 원본 전문을 되쓴다.
  **`git diff`로 확인하지 마라** — 새 파일은 untracked라 늘 비어 있다.
- **0 사망이 나오면 그렇다고 보고해도 된다. 다만 원인을 단정하지 마라.** 못 죽였으면
  **겨냥을 바꿔 다시** 재라. **케이스가 구현과 무엇을 공유하는지 보라** — 같은 함수를 불러
  **함께 움직이는** 것과 로직을 베껴 **안 움직이는** 것, 두 방향 다 이 저장소에서 났다.
- **수를 산문에 적지 마라.** 세야 한다면 **케이스가 만들게 하라.**
- **단언을 주석에 적지 마라.**
- **문서에 실행되는 코드를 싣지 마라.** P8-1이 이월의 스니펫으로 실제 결함을 냈다 —
  **규칙은 함수로 두고 케이스가 잡게 한다**(그래서 `scriptJson`이 생겼다).
- **소스에 날 제어 바이트를 넣지 마라.**
- **설계 문서(`docs/superpowers/specs/*`)는 고치지 않는다.** 어긋나면 판정해 보고한다.
- **남이 잰 값은 귀속을 붙여 옮긴다.**

## 이 계획이 딛고 선 사실 — 전부 P8-1 이월에서 왔다

| # | 사실 | 어디 |
|---|---|---|
| 1 | **`exportPage({document,title,theme?,lang?}) → {html,css,errors}`.** 파일을 안 쓰고, 레이아웃을 합성 안 하고, 셸을 안 만들고, CSS를 HTML에 안 넣는다 | §1 |
| 2 | **`<head>`에 `style`·`script`·`link`가 0개인 것을 케이스가 지킨다.** P8-2가 거기 무엇을 넣으면 **그 케이스가 죽는다 — 알림이지 사고가 아니다** | §1 |
| 3 | **갈림 셋이 있고 `describeTree`가 그 셋만 접는다.** 새로 짜지 말고 `@wirebound/exporter/test-support`를 불러라 | §3·§3.1 |

| 5 | **`admin`은 카탈로그의 첫 구조와 다른 것을 하나도 안 고른다** — 구조 배선이 끊겨도 `admin`으로는 안 죽는다. **테마 하나로 재려거든 `admin`을 고르지 마라** | §3 |

뷰 모드에서 **설명·코멘트·상호작용 셋**이다.

## 확정한 결정

### D1. **번들도 파일 시스템을 모른다 — 파일 목록을 값으로 낸다**

P8-1 D1과 같은 규칙이다. 소비자가 셋이 될 것이기 때문이다(P8-3의 api 라우트 · P9의 CLI ·
테스트).

```
exportBundle(input) → { files: Array<{ path, content }>, errors }
```

`path`는 **번들 안의 상대 경로**(`index.html` · `pages/….html` · `assets/theme.css`).
쓰는 것은 P8-3이다.

### D2. **각 페이지 HTML이 셸을 통째로 갖는다 — `index.html`은 입구다**

§11.3의 파일 목록은 두 갈래로 읽힌다. **판정한다.**

| 갈래 | 왜 아닌가 / 왜인가 |
|---|---|
| `index.html`이 셸이고 페이지를 **iframe**으로 싣는다 | **`file://`에서 제약이 크다.** 그리고 iframe 안의 마커와 바깥 코멘트 목록을 잇는 것이 스크립트를 요구하는데 §11.3의 번들은 **서버가 없다**. 인쇄·찾기도 나빠진다 |
| **각 페이지가 셸을 갖는다** ✅ | **페이지 하나를 열면 그것만으로 완전하다** — 링크를 공유할 수 있고, P8-1의 `exportPage`가 이미 만든 것 위에 쌓인다 |

**대가는 중복이다.** 셸 마크업이 페이지 수만큼 반복된다 — **재서 보고하라**(페이지 하나당
바이트, 페이지가 늘 때 기울기). 값이 크면 그것이 P8-3의 판정거리다.

`index.html`은 **같은 셸에 첫 페이지를 담는다.** 리디렉트를 쓰지 마라 — `file://`에서
`meta refresh`는 되지만 뒤로 가기가 망가진다.

### D3. **3분할은 §9의 뷰 모드와 같다**

| 자리 | 무엇 |
|---|---|
| 좌측 | **메뉴·페이지 트리 전체**(§9 — 뷰 모드에서 구조 트리가 접힌다) |
| 중앙 | 목업 + **번호 마커** |
| 우측 | 탭 셋 — **페이지 설명 · 코멘트 · 상호작용** |

- **번호 마커는 문서가 든다**(P5-1 D1). `routes/comments.ts`의 D1이 *"문서만 봐도 마커를
  그릴 수 있어야 내보낸 HTML 번들(§11.3)이 그것을 그린다"*고 §11.3을 이름으로 지목했다 —
  **P8-2가 그 보장의 첫 소비자다.**
- **상호작용 탭은 `describeInteraction`의 문장을 그린다.** 실제 동작은 P8-3이다 —
  **문장화는 순수 함수라 런타임과 무관하다.**
- **탭 전환은 스크립트 없이 한다**(`<details>`·라디오+CSS 등). 판정하고 근거를 적어라 —
  스크립트를 쓰면 P8-3의 `runtime.js`와 자리가 겹친다.

### D4. **코멘트는 입력으로 받는다 — 어디서 오는지는 P8-3이 정한다**

P7-3 이월 §1이 코멘트 본문을 얻는 길 **셋**을 갈라 두었고 성질이 다르다(살아 있는 값 /
한 시점의 값 / 스냅샷의 *"그때"*). **순수 패키지가 그 정책을 갖지 않는다.**

- 입력이 코멘트를 든다: `nodeId` · `body` · **`authorName`·`createdAt`은 선택**.
- **선택인 것이 안 오면 안 그린다.** 자리를 비워 두지 말고 **없는 것으로 취급**하라 —
  §11.2 봉투로 만든 번들에는 애초에 없다.
- **문서에 `marker`가 있는데 그 노드를 가리키는 코멘트가 없거나 그 반대인 경우**가 있다
  (고아 마커·고아 코멘트. 경로가 셋이다 — P7-3 이월 §3). **무엇을 그릴지 판정하고 케이스로
  고정하라. 조용히 버리지 마라.**

### D5. **파일 이름은 순수 함수가 만들고 충돌을 결정적으로 푼다**

§11.3의 예시가 `관리자-회원-목록.html`이다 — **한글을 유지한다.**

판정하고 케이스로 고정할 것:

1. **위험한 문자**(`/` `\` `:` `*` `?` `"` `<` `>` `|` · 제어문자 · NUL)를 무엇으로 바꾸나.
2. **길이 상한** — 파일 시스템의 이름 상한이 있다(**재서 값을 적어라**). 자를 때 무엇을
   남기나.
3. **충돌** — 같은 이름이 둘이면. **결정적이어야 한다**(같은 입력이 같은 번들을 낸다).
4. **빈 이름·점으로 시작·예약어**(Windows의 `CON`·`NUL` 등)를 어떻게 하나.
5. **`file://`에서 한글 파일명 링크가 실제로 열리는지 재라** — 링크의 `href`를 어떻게 적어야
   하는지(퍼센트 인코딩)가 여기 걸린다. **재라 #3.**

### D6. **CSS는 링크로 건다**

§11.3의 예시가 `assets/theme.css`다. 링크면 이월 §5.1의 물음(`</style>`)이 **사라진다.**

- 페이지는 `pages/` 아래에 있으므로 `../assets/theme.css`, `index.html`은
  `assets/theme.css`. **경로 계산을 순수 함수가 하고 케이스가 잡게 하라.**
- **셸 자신의 CSS는 테마 CSS와 섞지 마라.** 테마 CSS는 §6.11의 여섯 `data-wb-*` 어휘를
  쓰고 셸은 자기 클래스를 쓴다 — 한 파일에 섞으면 *"테마가 이긴다"*는 순서 계약(사실 8)에
  셸이 끼어든다.
- **셸 CSS에 `[style]` 셀렉터를 넣지 마라**(사실 4). 넣으면 ㉢이 화면으로 보이고 접기를
  다시 판정해야 한다.

### D7. **레이아웃은 넣지 않는다 — 판정이고 근거를 남긴다**

이월 §4가 판정을 요구한 자리다.

- **오늘 `pages`에 레이아웃 컬럼이 없어** 모든 페이지가 같은 셸이다(P7-3 이월 §5).
- **`renderComposed`는 `renderDocument`와 같지 않다**(사실 7). 캔버스는 페이지 문서만
  그리고, **P8-1의 성과가 *"번들이 캔버스와 같다"***이다. 합성을 넣으면 그 성과가 깨진다.
- **그래서 번들의 페이지는 `exportPage`가 낸 것 그대로다.** 레이아웃 셸은 §4.4의 레이아웃
  에디터가 서고 `pages.layout_id`가 생긴 뒤 판정한다.

**보고서에 이 판정을 명시하라** — 이월 §4가 P8-2에게 넘긴 물음이다.

### D8. **갈림 셋을 다시 만나고, 케이스 둘이 먼저 죽는다**

사실 2와 6이 예고한 것이다. **죽으면 고쳐라 — 그것이 알림이다.**

- `<head>`에 `link`가 생기므로 사실 2의 케이스가 죽는다. **무엇을 허용할지 다시 적어라**
  (`<link rel=stylesheet>` 하나만인지, 개수도 세는지).
- 셸이 문서를 감싸므로 사실 6의 케이스가 죽는다. **감싸개가 무엇인지 명시적으로 고정하라** —
  *"아무것도 안 감싼다"*를 *"정확히 이것이 감싼다"*로 바꾼다. 그러지 않으면 그 축이 사라진다.
- **견주기는 `describeTree`를 그대로 쓴다**(사실 3). 새로 짜지 마라.
- **테마를 하나만 골라 재지 마라. `admin`은 특히 고르지 마라**(사실 5).

### D9. **`errors`를 삼키지 마라**

`exportPage`가 그리지 못한 노드를 `errors`로 낸다(사실 1). 번들이 그것을 모으고,
**번들 결과가 그것을 든다.** 화면(P8-3)이 무엇을 말할지는 그때 판정하지만, **여기서 값을
잃으면 그 판정이 불가능해진다.**
