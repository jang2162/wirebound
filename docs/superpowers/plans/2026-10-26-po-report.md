# PO 보고 — 6단계 설계(팝업 페이지 · 파일첨부 · 반복 행 입력 표)

설계만 하는 차수다 — 코드를 안 고쳤다. 설계 문서는 `docs/superpowers/specs/2026-10-26-popup-attach-repeat-design.md`(커밋 `a5261076`). 기준 main `afaf5687` · 워크트리 `feat/popup` · Node v24.21.0 · 자기 Postgres 5503(`pnpm db port postgres 5432` → `0.0.0.0:5503`).

## 바꾼 것

- 설계 문서 하나(위) · 이 보고. 정본 · 코드 · `.ruler` 는 안 고쳤다.

## 설계 요약 — 결정과 이유

| 물음 | 결정 | 이유 |
| --- | --- | --- |
| 팝업 페이지 모델 | **뿌리 타입 `Popup`** — 페이지 종류 = 문서 뿌리 타입. DB 열 없음. `Popup` 은 뿌리에만 선다(`Page` 와 같은 규칙) | 렌더러 · 번들 · 캡처 · 되돌리기 · 스냅샷 · 실시간이 문서 하나만 받는다. 웹의 뿌리 가드는 타입이 아니라 id 로 가른다(셈 — 설계 «지금 모델») |
| 제목 · 크기 · ✖ · 바닥 | `title` · `size`(small 480 · medium 720 · large 960) prop · ✖ 는 뷰 조각 `close` · 바닥 단추는 «바닥» 구역의 `Button` 노드 | 정한 것 A · 설계서 OD 는 ✖ 에 표지를 안 단다 |
| 지금 동작(잰 것) | 에디터 뷰 모드는 «… 모달 열기 규칙입니다. 이 화면에서는 모달을 열지 않습니다.» 만(`canvas.tsx` 의 `noticesOf` · 케이스 2 통과) · 번들은 `navigate` 와 같은 길로 그 페이지 파일로 옮김(`mount.tsx` 의 `onEvent` — 케이스는 `navigate` 만 잼) · PPTX 는 페이지마다 한 장 · `closeModal` 없음 | — |
| 보이는 모양 | 캔버스 · PPTX 는 **상자만**(설계서 꼴). 뷰 모드 · 번들의 `openModal` 은 **덮개 + 가운데 상자**(몸통만 굴림 · ✖ · Escape · `closeModal` 로 닫음 · 겹 다섯까지). 덮개 층은 `renderer` 의 `PopupLayer` 하나를 에디터 · 번들이 함께 쓴다 | 설계서가 상자만 그린다 · «렌더러가 하나뿐이라 어긋날 수 없다» |
| 닫기 | 새 액션 **`closeModal`**(대상 없음) — 정본 «5종» → «6종» | 바닥 «취소» 를 시연할 길이 없다 |
| 마이그레이션 | **`0033-modal-popup`** — `openModal` 이 하나로 풀리는 페이지를 `Popup` 으로(페이지 · 스냅샷 payload 의 페이지). 레이아웃 · 모듈 두 표는 해당 없음(뿌리가 늘 `Page` · 뿌리 없는 묶음). 문서 판 · `head_seq` 안 올림(좌표 그대로) | 지금 `openModal` 의 대상은 뜻으로 팝업이다 |
| 파일첨부 | **꼴만 그리는 `FileAttach`** — 파일 행은 prop 배열 `{ name, size }`(새 목록 위젯 `fileList`) · 단추 셋은 «단추» 구역 노드 · 한도 글은 `maxFiles` · `maxSize` 에서 짓고 수를 조각으로 감싸 테마가 빨갛게 | 설계서의 파일 행은 표본이다 · 선택지와 같은 판단(행은 컨트롤이 아니다) |
| 단순 파일 줄 | 지금 조각(`Button` + 읽기 전용 `Input`) | `0029` 가 옛 `file` 을 이미 그 꼴로 옮긴다 |
| 반복 행 표 | **같은 `DataGrid`** + 팔레트 프리셋 «반복 행 표»(`ComponentDef.presets`) | 5단계 설계가 같은 노드로 적었다 · 걸음 25 → 10(입력 칸 표) · 32 → 28(글 칸 표) |
| 좁은 창 | 상자 `min(크기, 창 − 여백)` · 화면 모드는 제 크기 · **팝업 크기가 폼 표 · 검색폼 접기 문턱 노릇**(작은 · 보통 팝업 안은 한 줄에 쌍 하나 — 정적 규칙, `@container` 없음) | 테마의 접기는 창 폭만 본다. `@container` 는 저장소에 0 |
| 테마 계약 | `check` 규칙 여덟(P1 ~ P4 · F1 ~ F4) — 규칙마다 그 규칙만 어기는 깨는 뷰 픽스처 · 표본 갈래(파일 0 · 2 · 한도 유무 · 바닥 유무) | 4단계 M1 · 5단계 M4 의 «자가 재는 척» 을 되풀이하지 않게 |
| 판 | SDK · 기본테마 1.8.0 · 문서 판 5 그대로 | 새 타입만 더한다 |

## 남은 것

- 사용자 답 여섯(위) — 답에 따라 설계의 갈래(`0033` 유무 · 프리셋 장치 유무 · 덮개 층 유무)가 정해진다.
- 사용자 개발 DB 에 `openModal` 대상 페이지가 몇인지는 안 쟀다(워커는 그 DB 를 안 읽는다) — Q2 (가)면 병합 전 덤프 뒤 `0033` 이 옮긴 수를 로그로 낸다.
- 설계가 «구현이 먼저 잰다» 로 넘긴 것: 뿌리 `Page` 를 붙이기 · 모듈 넣기 · 팔레트가 지금 어떻게 거르는지(`Popup` 도 같은 자리에서 걸러야 422 되싣기가 없다) · 기본테마 셀 안 입력의 높이 · 번들 페이지 데이터에 실린 팝업 문서의 무게.

## 지침

1. **무엇이 틀렸나** — 화면 문안을 바꿀 때 «옛 문안을 단언한 자리를 문장 전체와 그 조각으로 함께 센다» 는 규칙에 **셈 범위**가 없다. 저장소 전체로 세면 이력 문서(`docs/superpowers/*` — 고치지 않는 문서)가 옛 문안을 인용한 줄까지 세어 고칠 자리가 실제보다 많게 나온다(«모달로 열립니다» 4 → `docs` 를 빼면 2). 설계 · 보고를 커밋하면 그 문서가 다시 옛 문안을 인용해 수가 또 는다.
   - **어느 문서 어느 절** — `.ruler/30-delegation.md` 「워커에게 맡길 때 — wirebound」 의 ««전체가 죽는다»는 «이 케이스가 죽는다»가 아니다» 문단, «화면 문안을 바꾸면 옛 문안을 단언한 자리를 문장 전체와 그 조각으로 함께 센다» 문장 뒤.
   - **넣을 문장** — «그 셈은 이력 문서를 뺀다(`git grep -l -F '<문안>' -- ':!docs'`) — 설계 · 보고는 옛 문안을 인용한 채 고치지 않으므로 함께 세면 고칠 자리가 실제보다 많게 나오고, 그 셈을 적은 문서를 커밋하면 수가 또 는다.»
