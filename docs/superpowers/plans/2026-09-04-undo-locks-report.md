## (a) 고치기 전 실측

### 서버가 내는 값 — 진짜 api·진짜 WS 잠금

컨테이너(5434/3002)를 이 워크트리에서 띄우고 `apps/api/test` 하네스로 쟀다. 다른 계정이
WS 로 잠그고 `locks` 프레임으로 **선 것을 확인한 뒤** 편집을 냈다. `inverse` 는 서버가 준
그대로 되보냈다(설계 §7.1 — 클라이언트가 `invertOps` 를 부르지 않는다).

| # | 갈래 | 되돌리기가 내는 op | 서버 |
|---|---|---|---|
| ① | 내가 만든 노드를 남이 잠근 뒤 그 생성을 되돌린다 | `remove /root/children/2` | **423** |
| ② | 내가 고친 노드를 남이 잠근 뒤 그 편집을 되돌린다 | `replace /root/children/1/children/0/props/content` | **423** |
| ③ | 지운 노드를 되살리는데 그 자리의 **부모**가 잠겼다 | `add /root/children/1/children/0` | **423** |
| ③b | 되살리는 인덱스에 잠긴 **형제**가 앞당겨 와 있다 | `add /root/children/0` | **423** |
| ④ | **대조** — 잠금과 무관한 편집을 되돌린다 | `replace /root/children/0/children/0/props/content` | **200** |
| ⑤ | **형제 자리** — 내가 만든 노드의 형제가 잠겼다 | `remove /root/children/2` | **200** |

423 의 본문은 전부 `{"error":{"code":"locked","message":"…님이 편집 중인 영역입니다"}}` 다.

§3.14 의 표와 **같은 성질**이다 — 서버는 편집이 실제로 건드리는 포인터만 본다.

### 화면이 하는 것 — 셸째로 띄우고 WS 로 진짜 423 을 먹였다

| 잰 것 | 값 |
|---|---|
| 낙관 적용 | 붙었다 사라진다(캔버스가 되돌린 값으로 갔다가 재조회로 복귀) |
| 알림 | `보라님이 편집 중인 영역입니다 — 페이지를 서버 상태로 다시 불러왔고, 편집 1개가 취소됐습니다.` |
| **undo 스택** | **2 → 0** (redo 도 0). 되돌리기 버튼이 비활성이 된다 |
| 나간 요청 | 2 (죽을 요청이 실제로 서버까지 간다) |

**하나가 아니라 이력 전부를 잃는다.** 423 → `recover` → 재조회 → `loadPage` 가 두 스택을
비운다. 문장의 «1개» 는 pending 편집 수라 **잃은 이력 수를 말하지 않는다.** §3.14 의 구조
편집은 편집 하나를 잃었는데 이쪽은 이력 전부다.

### 입구

되돌리기 **단축키는 없다.** `panels/structure-tree.tsx` 의 `SHORTCUTS` 다섯은 전부 구조
조작(`Delete`·`Alt+↑↓`·`Alt+Shift+←→`·`Alt+Shift+I/P`)이고, 되돌리기의 입구는 셸 헤더
`편집 이력` 묶음의 버튼 둘뿐이다.

### 기존 계약이 이미 적고 있는 것 — 새로 짓지 않았다

- 설계 **§13 «잠금 충돌»**: *"UI 사전 차단이 1차 방어, 발생 시 **안내 후 재시도**"*
- 설계 **§7.3 «적용 불가»**: *"**그 사이 다른 사람이 대상 노드를 지운 경우다.** … 스택에서
  제거하고 … 다음 항목으로 넘어간다"* → 건너뛰기는 **영구** 불가에 대한 규칙이다
- 설계 **§13 «undo 대상 소실»**: *"그 항목만 스택에서 버리고 **나머지는 그대로 쓴다**"*

셋을 합치면 **막힌 항목은 버리지 않고 남긴다**가 이미 적혀 있다.

## (c) 물었나 진행했나 — 물었고, 답을 기다리는 동안 제안대로 만들었다

갈래 셋과 각각의 대가를 실측값과 함께 정리해 `orca orchestration ask` 로 물었다. **그 질문이
코디네이터에게 도착하지 않았다**(디스패치가 닫혀 큐가 비었다) — 코디네이터가 알려 줘서 터미널에
그대로 다시 적었고 거기서 답을 받았다. 답은 **B**(서버가 423 낼 것만 막는다)이고 부수 판단 둘도
동의를 받았다.

기다리는 동안 B 를 구현해 두었다 — A 로 뒤집혔으면 판정 입력만 바꾸면 되는 형태였다.

| 갈래 | 대가 |
|---|---|
| **A. 전부 막는다** | ④·⑤ 가 서버에서 **200** 인데 화면이 막는다. 잠금은 남이 편집하는 내내 서 있으므로 사실상 *"남이 편집 중이면 되돌리기 불가"* |
| **B. 서버가 423 낼 것만 막는다** ← 채택 | 과차단 0 · 과소차단 0 |
| **C. 안 막는다**(지금 판) | (a) 의 이력 통째 손실 |

**B 의 근거 — 규칙이 다른 것이 아니라 단위가 다르다.** 규칙은 «그 조작의 단위에 맞춘다»이다.
툴바는 단위가 «고른 노드»라 서버(«편집이 건드리는 포인터»)보다 엄격할 수밖에 없어 §3.14 가 그
대가를 받아들였다. 되돌리기에는 **선택이 없어** 단위가 곧 `inverse` ops 이고, 그것이 서버가
재는 바로 그 입력이다.

## (e) 새 케이스가 무엇을 재고 각각 혼자 죽는가

`apps/web/test/lock/undo-locks.test.tsx` — **케이스 11**. 서버 대역이 진짜
`findLockConflict` 를 든다(`toolbar-abilities.test.tsx` 와 같은 형태). **변조 열일곱** 건을
돌렸고 **열하나 전부 혼자 죽는 변조가 있다.**

| 케이스 | 혼자 죽이는 변조 |
|---|---|
| 잠긴 노드의 속성 편집은 되돌려지지 않는다 | 막기 **전에** 낙관 적용을 붙인다 |
| 되살릴 자리가 잠겼으면 삭제도 안 된다 | `add` 포인터를 판정에서 뺀다 |
| 다시 실행도 같은 자리에서 막힌다 | `kind === 'undo'` 일 때만 막는다 |
| 잠긴 서브트리 **밖**은 되돌려진다 | `replace` 가 섞이면 페이지 통째로 본다 |
| 형제 자리는 막지 않는다 | 포인터를 한 단계 **올려** 본다 |
| 내 잠금에는 안 막힌다 (D3) | `viewerUserId` 를 `''` 로 넘긴다 |
| 다른 페이지의 잠금은 안 막는다 | `pageId` 필터를 뺀다 |
| 막혀도 이력을 잃지 않는다 | 막을 때 그 항목을 한 번 더 쌓는다 |
| 잠금이 풀리면 그대로 되돌아간다 | `setLocks` 가 빈 목록을 무시한다 |
| 이름과 함께 말한다 | 건너뜀이 0 이어도 접두어를 붙인다 |
| 건너뛴 것도 함께 말한다 | 건너뛴 것을 스택에 남긴다 |

**넓게 죽는 변조 넷이 그 위에 겹친다.** 판정을 통째로 빼면 **7** 이 죽고, 채택하지 않은
갈래 A(«페이지에 남의 잠금이 하나라도») 로 바꾸면 **정확히 «안 막는다» 둘**이 죽는다 —
그것이 *"A 는 서버가 200 을 낼 것까지 막는다"* 의 실증이다.

### 5차의 «재는 척하는 케이스»를 한 번 만들었다가 지웠다

처음에는 §3.14 를 따라 **막다른 길 확인을 별도 케이스**로 두었다(모드 버튼 둘 · 다른 페이지
링크). **변조 열일곱 건 전부에서 한 번도 안 죽었다** — 이 슬라이스가 셸을 안 건드리기
때문이다. 그 단언을 죽는 케이스(`잠금이 풀리면 그대로 되돌아간다`) 안으로 옮겼다. 되돌리기의
진짜 막다른 길은 *"그 항목에 영영 못 닿는다"* 이고 그것을 재는 것은 두 번째 누름이다.

## (i) 이월 — 이번에 안 고쳤다

### B-1. 속성 패널이 잠금을 안 본다 — 그리고 상태줄이 그때 거짓말을 한다

**§3.14 가 닫은 것과 같은 모양의 구멍이 하나 더 있다.** 노드를 고른 **뒤에** 남이 그것을
잠그면(`setLocks` 는 선택을 안 건드린다 — §3.14 가 연 그 창) 속성 패널의 위젯이 **그대로
살아 있고**, 값을 치면 편집이 나간다.

| 잰 것 | 값 |
|---|---|
| 위젯이 살아 있나 | **그렇다** |
| 나간 op | `replace /root/children/0/props/content` |
| 서버 | **423** (위 갈래 ② 와 같은 모양) |
| undo 스택 | **2 → 0** |
| 그때 상태줄 | `보라님이 편집 중이라 고를 수도 **바꿀 수도** 없습니다` |

**그 문장이 지금 사실이 아니다.** §3.14 가 *"이제 둘 다 참이기 때문이다"* 라고 적으며 «바꿀
수도» 를 넣었는데, 그것이 참인 것은 **구조 툴바**에 대해서이고 속성 패널에는 거짓이다.
이월의 무게가 그것이다 — 구멍 하나가 아니라 **화면이 사용자에게 거짓을 말하고 있다.**

### B-2. «스택 몰살» 경로는 되돌리기로는 안 밟히지만 속성 패널로는 여전히 밟힌다

코디네이터가 추가로 요구한 측정이다. B 를 넣은 뒤 같은 판에서 둘을 나란히 쟀다.

| 무엇으로 | 서버가 본 요청 | 상태 코드 | undo 스택 |
|---|---|---|---|
| **되돌리기** | 2 | `[200, 200]` | **2 → 2** (안 밟힌다) |
| **속성 패널** | 3 | `[200, 200, **423**]` | **2 → 0** (밟힌다) |

즉 이 슬라이스는 되돌리기 쪽 입구를 닫았을 뿐이고, **`loadPage` 가 두 스택을 비우는 그
자체**는 그대로다. B-1 을 닫으면 이 입구도 함께 닫히지만, *"어떤 423 이든 이력을 통째로
잃는 것이 옳은가"* 는 별도 판단이다(설계 §13 은 undo 실패에 대해 *"그 항목만"* 이라고 적는다).
