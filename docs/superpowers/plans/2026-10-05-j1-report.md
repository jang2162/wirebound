## 2. 프레임 계약

```jsonc
{ "type": "menu-changed", "projectId": "…", "rev": 12, "actor": { "type": "user", "label": "앨리스" } }
```

- 트리를 안 싣는다 — 신호다. 받는 쪽은 `GET …/tree`(이제 `{ menu, rev }` — 번호와 행을 `REPEATABLE READ` 한 스냅숏에서 읽는다)로 다시 받는다.
- 낸 사람의 연결까지 룸 전체(받는 최소 역할 viewer — 방송이 보내기 전에 연결마다 세션 · 멤버십을 다시 본다). 연결 id 를 안 싣는다 — 낸 탭은 번호로
  넘긴다(서버가 지은 값).
- 웹: 셸이 본 가장 큰 번호를 트리에 넘긴다(`routes/editor.tsx`의 `menuRev`). 트리는 제 번호보다 크면 다시 받고(받는 중이면 합침) · 겹친 답은 번호로
  가르고(같으면 늦게 낸 조회의 답) · 다시 붙으면 한 번 받는다(`tree/use-tree-commands.tsx`의 `remoteRev` · `settles` · `refresh` · `resyncToken`).
- 계약 문서: `apps/api/README.md` 「실시간 (WebSocket)」의 표와 «트리 쓰기는 `menu-changed`를 낸다» · 「트리 응답 형태」. 정본: 설계서 「정방향
  흐름」의 «메뉴 트리도 실시간이다».

**두 연결의 차례**(CLAUDE.md «서로 다른 연결로 가는 두 메시지의 도착 순서에 기대는 판정은 앞섬을 재서 적는다»): 내 쓰기의 신호와 답 뒤 조회는
localhost 에서 2ms 차로 같은 때 닿는다 — 차례에 기대지 않는다. 신호가 먼저면 다시 받기가 둘(신호의 것 · 답 뒤의 것)이고 답은 번호로 가른다, 늦으면
하나다. 남의 신호 둘이 한 연결에 거꾸로 닿아도 셸은 가장 큰 번호만 든다.

**겹친 조회의 낡은 답**(jsdom · `apps/web/test/panels/menu-realtime.test.tsx` — 답을 손으로 놓아 차례를 정한다): 먼저 낸 조회(신호)가 큰 번호 5 를
먼저 답하고 나중 낸 조회(내 조작 뒤)가 작은 번호 4 를 늦게 답하면 4 를 버린다 · 반대로 먼저 낸 조회가 큰 번호를 늦게 답해도 그 답이 선다. «늦게 낸
조회의 답만»이었으면 둘 다 틀린다(변조 W1).

## 4. 열린 화면 처리

`tree/use-tree-commands.tsx`의 `reconcile` — **남의 변경으로 받은 트리에만**(신호 · 재연결 · 트리 조작의 404 뒤). 내 조작 뒤의 다시 받기는 그 조작이 스스로
맞춘다(지운 메뉴의 부모로 고름 · 지운 페이지면 뿌리로).

| 열린 것 | 대상이 사라졌다 | 대상이 남았다 |
|---|---|---|
| 줄의 행동 메뉴(`…` · `+`) | 그 줄이 트리에서 빠지며 함께 내려간다(실브라우저: 메뉴 0 · 알림 0) | 그대로 |
| 이름 · 새 메뉴 · 새 페이지 입력 | 닫는다 · 친 글이 있었으면(연 순간의 글과 다르면) 하단 바 «그 항목이 트리에서 사라져 친 이름을 쓰지 않았습니다» | 그대로 — 옮겨졌으면 새 자리에 친 글째 선다 |
| 고른 줄 · 두 번 누르기 확인 · 소속 메뉴 목록 | 고름을 풀고(주소의 페이지로) 둘을 닫는다 | 그대로 |
| 제목 충돌 통지 | 걷는다 | 그대로 |
| 연쇄 삭제 상자 | 닫는다 · 하단 바 «"…" 메뉴가 트리에서 사라져 삭제 상자를 닫았습니다» | 밑의 메뉴 · 페이지 **id 집합**이 바뀌었으면 새 목록으로 다시 서고 «목록이 바뀌었습니다 — 다시 확인하세요.»(409 와 같은 길 · 같은 문장). 이름만 바뀌면 그대로 |
| 열린 페이지 | 캔버스가 서버에 묻는다(`routes/editor.tsx`의 `goneCheck`) — 404 면 판을 비우고(구조 트리 · 속성 패널도 내린다) 버린 편집을 말하고 «대상을 찾을 수 없습니다». 있으면 판이 같을 때 아무것도 안 함 · 다르면 서버 판을 싣는다 | — |
| 가져오기 상자 | 안 닫는다 — 연 순간의 메뉴 id 로 보내고 서버의 거절을 상자 안에 보인다(원래 길) | — |

- 열린 페이지는 **앞 트리에 있던 것이 새 트리에 없을 때만** 묻는다(첫 트리에 없는 주소는 여는 조회가 이미 404 를 말했다). **내가 지운 열린 페이지는
  안 묻는다**(`ownRemoval` — 내 지움의 신호가 답보다 먼저 와 트리가 먼저 바뀐 판).
- **끄는 중**(실브라우저): 신호가 와도 쥔 줄의 끄는 표시가 남고, 놓는 판정은 새 트리로 한다(`drag/use-pointer-drag.ts`는 뗀 좌표로 `onOver`를 다시
  묻는다). `it.fails`였던 «번갈아 끌기»는 `it`이 됐다 — bob 이 끌기 전에 alice 의 차례를 본다(`[나3, 나1, 나2]`) · 서버 `[나3, 나2, 나1]`. 끄는 중 남이
  그 페이지를 지우면 줄이 빠지고 놓아도 요청이 없다(옛 판: 줄이 남고 404 하나).
- **받는 쪽**(`menu-cascade-delete.test.ts` «지운 페이지를 열어 둔 사람»): 속성 칸에 친 채 지우면(페이지 `DELETE` · 연쇄 둘 다) 곧바로 캔버스 «대상을
  찾을 수 없습니다» · 하단 바 «바뀐 선택 때문에 친 값을 쓰지 않았습니다» · 칸 0 · `patch-error` 없음 — 두 길이 같은 값이다. 열린 줄 메뉴는 줄과 함께
  닫힌다.
- **R3 의 «트리 조작의 404 뒤 다시 받기»**: 트리 조작(`run`)이 404 를 받으면 실패 문장은 남기고 트리를 다시 받는다(그 밖의 실패는 그대로 안 받는다).

## 9. 이월 후보

1. **열린 페이지가 함께 지워지면 상자 · 입력의 한 줄이 안 남는다** — «페이지가 사라짐»이 판을 비우며 하단 바도 비운다(`EditorStore.clearPage` —

3. **방 전체의 다시 받기 비용** — 신호마다 받는 화면이 트리 전체를 받는다(6 절). 차분 프레임(바뀐 메뉴 · 페이지만)은 순서 · 유실을 막는 장치를 새로
