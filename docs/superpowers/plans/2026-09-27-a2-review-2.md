## 1. F1 — fflate 목록 대조(`packages/themes/src/wbtheme/read.ts`)

fflate 0.8.3 `unzipSync` 를 다시 읽었다: 항목마다 **중앙 디렉터리의** 이름 · 압축 방식 · 압축 크기 `sc` · 원래 크기 `su` · 로컬 머리 오프셋을 쓰고, 로컬 머리에서는 이름 길이 · 확장 길이(데이터 시작 자리)만 읽는다. stored 는 `sc` 바이트를 자르고, deflate 는 `inflateSync(…, { out: new u8(su) })` — 버퍼를 준 판은 `resize` 가 꺼져 **넘치는 쓰기를 버린다**(버퍼를 안 늘린다).

### 1a · 1b — 로컬 머리 · 원래 크기

| 입력(`f1-inflate-probe.ts`) | 판정 | 실린 것 | `readWbtheme` 한 번 |
| --- | --- | --- | --- |
| A1 로컬 크기 `0xFFFFFFF0`, 중앙 7 (stored) | 받음 | `assets/a.png` 7 B | 1 ms · arrayBuffers +0.0 MB |
| A2 로컬 방식 8, 중앙 0 | 받음 | 7 B | 0 ms · +0.0 MB |
| B deflate(0 바이트 256 MB → 260,916 B), 중앙 원래 크기 1 × 항목 1 | 받음 | 1 B(잘림) | 342 ms · +0.0 MB |
| 같은 로컬을 항목 8 개가 가리킴 | 받음 | 1 B × 8 | 2,464 ms · +0.1 MB |
| 항목 40 개 | 받음 | 1 B × 40 | 12,286 ms · +0.1 MB |
| 항목 195 개(`max` 합 48.5 MB < 50 MB, zip 0.26 MB) | 받음 | 1 B × 195 | **59,189 ms** · +0.1 MB |
| 대응 전 소스 — 항목 1 · 8 · 40 | 받음 | 같음 | 345 · 2,416 · 12,103 ms |

- **판정:** 1a 재현 안 됨 — 판정(목록)과 푸는 것이 같은 칸(중앙)을 본다. 1b 메모리는 재현 안 됨 — `max(size, originalSize)` 를 넘는 버퍼는 안 잡힌다. **1b' 풀기 일은 원래 있던 길**, 무게 **중간** — fflate 는 원래 크기를 넘은 뒤에도 스트림을 끝까지 풀고(쓰기만 버린다), 업로드 하나(관리자 세션)가 api 의 이벤트 루프를 1 분 쥔다. 대응 전에는 원래 크기만 세어 항목 497 × 10 MB 스트림까지 받았다(재지 않음 — 항목당 가짜 출력 ≈ 10 GB 로 외삽하면 시간 단위) — `max` 가 폭을 줄였으나 닫지 않았다.
- **빨강 케이스:** 넣지 않았다 — 원래 있던 길이라 병합을 막지 않는 이월로 넘긴다. 잠글 판: 위 «항목 195» 를 `wbtheme-reader-divergence.test.ts` 의 짓개로 지어(`deflateRawSync(Buffer.alloc(256 MB), { level: 9 })` · `usize: 1` · `sameLocalAs`) «거절하거나 N 초 안에 끝난다» 로 단언한다.
- **고칠 방향:** deflate 항목은 fflate 의 스트리밍 `Inflate` 로 풀며 나온 바이트를 세어 원래 크기를 넘는 순간 멈추고 `bad-zip` 을 낸다.
- **한계:** 항목 195 판은 다른 vitest 실행과 겹친 채 쟀다 — 혼자 잰 항목 40 판(항목당 0.31 s)의 선형과 맞는다(195 × 0.31 ≈ 60 s). 한 기계 · Node 24.21.0.

### 1c — 세 겹을 한 겹씩

대응 보고 「F1」 의 변조 표는 «세 겹은 서로를 받친다 — 하나만 떼면 남은 겹이 막는다» 로 적었다. 한 겹씩 떼고 **그 겹만 겨누는 입력**을 찾았다.

| 뗀 겹 | 그 겹만 겨누는 입력이 있나 | 까닭 |
| --- | --- | --- |
| 목록 대조(M1) | 없다 | 두 수가 같고 로케이터가 없으면 판독기와 fflate 는 같은 끝 레코드 · 같은 수(`+8`=`+10`) · 같은 오프셋에서 같은 걸음(`46 + 이름 + 확장 + 주석`) · 같은 이름 규칙(비트 11)으로 읽는다. 판독기가 더 엄격하다(중앙 표지 · 끝 레코드를 넘는지) |
| 두 항목 수 거절(M4) | 없다 | 판독기는 `+10`, fflate 는 `+8` 개를 센다 — 둘이 다르면 두 목록의 길이가 늘 다르고 목록 대조가 막는다 |
| 로케이터 거절(M3) | **있다** | 목록 대조는 이름 · 차례 · 수만 견준다. 링크 판정의 외부 속성은 판독기의 디렉터리에서만 읽는다(fflate 는 안 준다). zip64 디렉터리가 **이름까지 같고** `theme.js` 를 링크(`0o120777`)로 적으면 목록이 같아 통과하고, 링크 판정은 판독기가 본 다른 디렉터리의 일반 파일 모드로 선다 |

- **값:** M3 판에서 위 입력이 받아진다 — `files.themeJs` 는 링크 대상 글자(`../../etc/passwd`). HEAD 는 로케이터로 `bad-zip`.
- **판정:** 대응 보고의 «하나만 떼면 남은 겹이 막는다» 는 M3 에서 참이 아니다 — 로케이터 거절은 외부 속성을 혼자 지킨다. 지금 코드는 막으므로 결함이 아니라 **잠그는 케이스가 없었던 것**이다, 무게 **낮음**(`readWbtheme` 은 바이트만 돌려주고, 링크를 따르는 것은 저장된 `.wbtheme` 을 zip64 를 읽는 도구로 푸는 쪽이다).
- **잠금 케이스**(초록): «zip64 로케이터가 이름이 같은 다른 중앙 디렉터리를 가리켜도 링크 판정은 fflate 가 읽는 디렉터리의 속성으로 선다». 옛 zip64 케이스와 같은 짓개를 쓰게 그 짓기를 `zip64Pointing` 로 옮겼다(옛 케이스의 입력 바이트는 같다). 짓개 `Entry` 에 `mode` 를 더했다.
- **변조**(백업 → 변조 → 실행 → `cmp` 복원, `wbtheme-reader-divergence` · `wbtheme` 두 파일 25 케이스):

| 변조 | 결과 |
| --- | --- |
| M3 로케이터 거절만 뗌 | **새 케이스 하나만** 죽음 — `expected { Object (manifest, themeJs, ...) } to be null` |
| M1 목록 대조만 뗌 | 25 초록 |
| M4 두 수 거절만 뗌 | 25 초록 |

- **고칠 자리(문장):** `read.ts` 의 `readWbtheme` 머리말 «손으로 읽는 중앙 디렉터리는 fflate 가 안 주는 외부 속성(링크 판정)만 얻고, 그 목록이 fflate 의 목록과 이름 · 차례 · 수까지 같아야 쓴다» 뒤에 «목록 대조는 외부 속성을 못 견주므로, 두 디렉터리가 이름까지 같은 zip64 판은 로케이터 거절이 혼자 막는다» 를 넣는다.

## 2. F2 — `font` · `shadow` 허용 문법(`packages/themes/src/manifest/tokens.ts`)

`checkTokenValue` 에 흔한 실제 값을 넣었다(`f2-probe.ts`), 거절된 것은 대응 전 소스와 견줬다(`f2-old.ts`).

- **받음 — 브리프가 든 값 전부:** `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, sans-serif` · `'Noto Sans KR', sans-serif` · `ui-monospace` · `0 1px 2px rgba(15,23,42,.06)` · `0 4px 12px rgb(0 0 0 / 10%)` · `inset 0 0 0 1px #e2e8f0` · `0 0 0 3px hsl(217 91% 60% / .35), 0 1px 2px #0000000f` · `none` · 음수(`0 -1px 2px …` · `-2px -2px 4px #000`) · `px` 없는 `0` · `em` · `rem`. 더 넣어 받은 것: GitHub · Bootstrap 의 시스템 글꼴 목록, 따옴표 없는 한글 이름(`맑은 고딕, sans-serif`), `"D'Amico Sans"`, 색이 앞에 온 그림자, 끝에 온 `inset`, `currentColor` · `transparent`, Tailwind v3 그림자 둘.
- **거절:**

| 값 | 지금 | 전 | 판정 |
| --- | --- | --- | --- |
| `0 .5rem 1rem rgba(0, 0, 0, .15)`(Bootstrap `$box-shadow`) | 거절 | 받음 | **결함 — 새 장치가 연 길, 중간** |
| `0 .125rem .25rem rgba(0,0,0,.075)`(Bootstrap `$box-shadow-sm`) | 거절 | 받음 | 같음 |
| `0 -.5px 1px #000` | 거절 | 받음 | 같음 |
| `0 1px 2px oklch(0% 0 0 / .1)` | 거절 | 받음 | 새 장치가 연 길, 낮음 — 색 토큰도 `oklch` 를 안 받는다(원래 그렇다) |
| `0 0 0 calc(3px + 1px) #93c5fd` | 거절 | 받음 | 새 장치가 연 길, 낮음 |
| `0 1PX 2PX #000` | 거절 | 받음 | 새 장치가 연 길, 낮음 |
| 색 `hsl(120deg 50% 50%)` | 거절 | 받음 | 대응 보고가 뜻하고 적은 거절, 낮음 |
| 길이 토큰 `.5rem` | 거절 | 거절 | 원래 있던 길 |

- **원인:** 그림자의 길이를 `LENGTH`(`0` 또는 `-?\d+(?:\.\d+)?` + 단위)로 잰다 — 앞에 숫자가 없는 소수를 못 받는다. 같은 식을 쓰는 `length` 토큰은 전부터 그랬다.
- **빨강 케이스**(`token-value-grammar.test.ts` «shadow 토큰 값 — 흔한 실제 값(A2 좁은 반증 2)», 3 건): 기본값과 받은 값 양쪽 — `expected [ 'token-default-type' ] to deeply equal []`.
- **고칠 방향:** `LENGTH` 의 수를 `-?(?:\d+(?:\.\d+)?|\.\d+)` 로 — `length` 토큰의 원래 있던 길도 함께 닫힌다. `oklch` · `calc` · 대문자 단위 · `deg` 를 받을지는 설계 판단이라 케이스로 안 잠갔다(받으면 색 토큰과 같이 받는다).
- **한계:** 받은 값이 선언 밖으로 새지 않는지는 대응이 실 Chrome 으로 쟀다 — 여기서는 거짓 빨강만 봤다.

| `evil.example:5391` · 빈 Host | 403 | 403 | 403 |
| `localhost:5391.evil.example` · `localhost:abc` · `localhost:5391:5391` | 403 | 403 | **200** |
| ` localhost` · `localhost `(Node 가 공백을 깎는다) | 200 | 200 | 200 |
| Host 없음 | 400 | 400 | 400(Node) |

- **판정:** 3a 재현 안 됨 — 셸이 받는 Host 는 `localhost` · `127.0.0.1` · `[::1]`(포트 유무 · 대소문자)뿐이고, DNS 재바인딩으로 남의 이름이 그 셋이 되는 길은 없다. 3b 낮음 — `isLocalHost` 머리말 «vite 가 지키는 `/frame.html` · `/@fs/…` 와 같은 판정이어야 한다» 가 두 꼴에서 참이 아니다: 대문자는 셸만 받고(브라우저는 Host 를 소문자로 보낸다 — 닿는 사람 없음), IP 꼴은 vite 만 받는다(서버가 `127.0.0.1` 에만 열려 그 이름들로 닿는 사람이 드물다). vite 가 `localhost:<포트>.evil.example` 에 200 을 주는 것은 vite 자체의 판정이고 브라우저가 못 보내는 Host 다.
- **고칠 자리(문장):** 머리말의 «같은 판정이어야 한다» 를 «vite 보다 좁다 — `*.localhost` · IP 꼴은 셸만 403, 대문자는 셸만 받는다(브라우저는 소문자로 보낸다)» 로.

### 3c · 3d — 좁힌 `fs.allow` 와 워크스페이스

빌드한 kit 의 `packTemplate` 으로 템플릿 zip 을 짓고(`pack.mjs` — 234,274 B) 스크래치에 두 워크스페이스를 세웠다: **pnpm**(`pnpm-workspace.yaml` · pnpm 10.33.0 — 의존의 실물은 뿌리의 `node_modules/.pnpm`) · **npm**(`workspaces` · npm 11.19.0 — 뿌리의 `node_modules` 로 올림, 테마 안에는 `node_modules` 가 없다). 템플릿은 `themes/my-theme` 에 풀었다. 설치한 kit 의 `wb-theme dev` 를 띄우고 Chrome(헤드리스)으로 열었다(`ws-dev-probe.mjs`).

| 판 | 칸 · 종류 · `data-wb-error` | 4xx | 글꼴 |
| --- | --- | --- | --- |
| pnpm · 템플릿 그대로 | 37 · 19 · 0 | 0 | — |
| npm · 템플릿 그대로 | 37 · 19 · 0 | 0 | — |
| pnpm · `@fontsource/inter` 를 더해 `import '@fontsource/inter/latin-400.css'` | 37 · 19 · 0 | **403 × 2**(`…/.pnpm/@fontsource+inter@5.3.0/…/files/inter-latin-400-normal.woff2` · `.woff`) | `Inter:error` |
| npm · 같음 | 37 · 19 · 0 | **403 × 2**(`<ws>/node_modules/@fontsource/inter/files/…`) | `Inter:error` |
| 두 판 · 설치한 kit 의 `fs.allow` 를 옛 판(`searchForWorkspaceRoot` 둘을 더함)으로 되돌림 | 37 · 19 · 0 | 0 | `Inter` 참 |

(두 판 모두 콘솔의 404 한 줄은 `/favicon.ico` 다.) 서버 로그: `The request url "…/files/inter-latin-400-normal.woff2" is outside of Vite serving allow list.` — 허용 목록은 kit 의 `dist/client` · 작성자 프로젝트 · vite 의 `dist/client` 셋이었다.

- **판정:** 3c 선다 — 설치판에서 SDK · react 는 cacheDir(`<프로젝트>/node_modules/.vite-wb-theme/deps`, 작성자 프로젝트 안)로 미리 묶여 `/@fs` 요청이 허용 목록 안에서만 났다. **3d 결함, 새 장치가 연 길, 중간** — 작성자 프로젝트가 워크스페이스 안에 있으면 올린 `node_modules` 의 패키지 CSS 가 `url()` 로 부르는 파일(글꼴 · 이미지)을 dev 가 403 으로 막는다. 같은 판의 `wb-theme build` 는 그 글꼴을 `assets/` 로 싣는다(npm 판 `.wbtheme` 57,734 B 에 `.woff2` · `.woff`). dev 에서만 글꼴이 안 보인다.
- **빨강 케이스**(`dev.test.ts` «작성자 프로젝트가 워크스페이스 안에 있으면 hoist 된 node_modules 의 CSS 가 부르는 글꼴도 받는다»): `.tmp` 안에 `pnpm-workspace.yaml` 을 둔 워크스페이스를 짓고, 그 뿌리의 `node_modules/wb-probe-font`(CSS + 글꼴 파일)를 픽스처 복사본이 import 한다. 카나리아는 갤러리가 서는 것 · 패키지 CSS 가 200 · 글꼴 요청이 나는 것. HEAD → `expected 403 to be 200`.
- **변조:** `src/dev.ts` 의 `fs.allow` 를 대응 전 판(`searchForWorkspaceRoot(root)` · `searchForWorkspaceRoot(client)` 를 더함)으로 되돌림 → 새 케이스 초록, 대응의 «/@fs 로 … 저장소 뿌리의 README 를 못 읽는다» 가 `expected 200 to be 403` 으로 죽음. 두 케이스는 서로 다른 성질을 잡는다 — 고침은 둘을 함께 초록으로 만들어야 한다. 복원 뒤 `dist` 를 다시 빌드했다.
- **고칠 방향:** `fs.allow` 에 `join(searchForWorkspaceRoot(root), 'node_modules')` 만 더한다(pnpm 의 `.pnpm` 도 그 안이다) — 저장소 안 판에서 README 는 여전히 밖이다.
- **한계:** vite 6.4.3 · Chrome 한 판. 이미지 패키지(CSS `background: url()`)는 같은 판정 길이라 안 쟀다. 대응 보고가 남긴 «저장소 안 판(링크한 SDK)이 좁힌 `fs.allow` 밖인데도 서는 까닭» 은 여기서도 재지 않았다 — 설치판은 미리 묶기로 선다는 것만 쟀다.
