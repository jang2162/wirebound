이 문서는 발행 시점의 기록이다(`docs/guideline/base/04-citation.md` 「이력 문서는 연대기 금지의 예외다」). 지금 참인 설계는 정본 `docs/superpowers/specs/2026-08-03-wirebound-design.md` 「끌어 놓기」가 갖는다.

**한 줄:** 끌기 장치(`drag/use-pointer-drag.ts`) 하나를 고쳐 입구 넷(카드 · 캔버스 손잡이 · 구조 트리 줄 · 메뉴 트리 줄)이 한꺼번에 펜 · 터치로 선다.
펜은 «끄는 동안 캔버스 iframe 을 `pointer-events: none`», 터치는 «길게 눌러(300ms · 8px 안) 끌기 시작 + 끌기가 서면 `touchmove` 의 스크롤을 막음».
실브라우저 값은 시스템 Chrome(`editor-stack.ts` 의 첫 후보 · 헤드리스) · vite dev · 창 1440×900. 펜 · 터치는 CDP 흉내다 — **실물 펜 · 터치 기기에서 같은지는 못 갈랐다**(이월 1).

## 1. 입구 × 포인터 — 고치기 전 · 뒤

입구는 `git grep usePointerDrag` 로 센 넷이다(`palette/component-palette.tsx` · `canvas/canvas-drag-handle.tsx` · `panels/structure-tree.tsx` · `panels/menu-tree.tsx` — 메뉴 줄 · 페이지 줄은 같은 훅 한 번). `use-canvas-marquee.ts` 는 이 훅이 아니다.
케이스 `apps/web/build-test/drag-pointer-kinds.test.ts`(실브라우저 17). 입구마다 «캔버스 문서 위를 지나 놓는다 → 끌기가 끝났는가(호스트 `pointerup` 1 · iframe 이 받은 move · up 0 · 이름표 · 들린 줄 0) → 결과(카드 · 손잡이는 서버 문서의 차례, 트리 줄은 이어서 다시 끌어 서버 값)».

| 입구 | 마우스 | 펜 — 고치기 전 | 터치 — 고치기 전 | 셋 다 — 고친 뒤 |
|---|---|---|---|---|
| 카드 | 초록 | 안 끝남: iframe 이 move 13 · up 1, 호스트 up 0, 이름표 남음, 편집 0 | `pointercancel` 1 · 호스트 up 0 · 편집 0 | 초록(터치는 길게 눌러 끔 · 카드 판은 안 밀림) |
| 캔버스 손잡이 | 초록 | iframe 이 move 6 · up 1, 호스트 up 0, 편집 0 | `pointercancel` 1 · 편집 0 | 초록(터치는 곧바로 끔) |
| 구조 트리 줄 | 초록 | iframe 이 move 10 · up 1, 줄이 들린 채 남음 → 다음 끌기가 무시됨 | `pointercancel` 1 · 편집 0 | 초록 |
| 메뉴 트리 줄(페이지) | 초록 | iframe 이 move 6 · up 1, 줄이 들린 채 남음 | `pointercancel` 1 · 쓰기 0 | 초록 |

터치로 쓸기(길게 누르지 않음) — 카드 판은 밀리고 끌기는 안 서며, 트리 줄은 안 끌린다: 고치기 전 · 뒤 모두 초록(스크롤을 지키는 대조군). 마우스 판의 기존 케이스(`tree-drag*` · `palette*` · `canvas-drop*` 등)는 그대로 초록이다.
캔버스 hover 표시: 캔버스 문서에는 포인터로 서는 hover 표시가 없다(`git grep` 로 `src/canvas` 에서 `pointermove` · `:hover` 처리는 사각형 고르기뿐) — 놓는 자리 판정은 마우스 케이스(미리보기 · 서버 차례)가 고친 뒤에도 같은 값임을 잠근다.

## 2. 고른 길과 그 까닭(값)

- **펜 — 캔버스 iframe 을 막는다**(`holdIframesInert`, 누른 순간 ~ 끝). 대안 «캔버스 문서에도 move · up 을 받아 호스트 좌표로 환산»은 `useCanvasDocument` 꼴 리스너 + 줌 · 스크롤 환산이 필요하다. 막으면 포인터가 iframe 밑의 호스트 요소로 가 캡처가 그대로 선다(값: 고친 뒤 iframe 이 받은 move · up 0 · 호스트 up 1). 놓을 자리 판정은 좌표로 iframe 문서를 직접 묻는 것이라(`canvas/canvas-drop.ts`) 영향이 없고 마우스 케이스가 같은 값이다. **마우스에도 같이 건다**(분기 없음).
- **막는 법은 인라인 style**이다. 처음에 `shell.css` 규칙(`.wb-shell-… .wb-shell-canvas-iframe`)으로 지었으나 `apps/web/test/shell-css.test.ts` 의 누수 검사가 결합자 선택자를 막아 `pnpm test` 가 14건 빨강이었다 — 인라인으로 바꿨다(훅이 막은 iframe 과 전 값을 `Map` 에 두고 센 수가 0 일 때 되돌림).
- **터치 — 길게 누름 + `touchmove` 기본 동작 막기.** `touch-action` 을 동적으로 바꾸는 길은 안 썼다: 현재 제스처에는 `pointerdown` 시점의 값이 고정이라 못 바꾼다(그렇게 읽었고, 길게 누른 뒤 스크롤을 막는 쪽이 값으로 섰다). `{ passive: false }` 의 `touchmove` 리스너를 **누른 때부터** 건다(window 의 `touchmove` 는 기본 passive). 끌기가 선 뒤에만 `preventDefault` 한다. 값: 터치 카드 · 줄 · 메뉴 케이스 초록, 변조(MT0)로 리스너를 걷으면 셋이 죽는다.
- **손잡이는 `touch-action: none` + `touchStart: 'now'`.** CDP 터치는 `touch-action` 이 없어도 `touchmove` 를 막아 끌리므로 css 는 변조(MC1)에 안 죽었다 — computed style 값(`none`)을 케이스가 직접 단언해 잠갔다(MC3 혼자 손잡이 케이스를 죽인다).
- 8px 허용치는 «움직임이 8px 을 넘으면 이 누름은 끌기가 아니다»(`TOUCH_HOLD_SLOP`). 쓸기 케이스는 이것이 없어도 초록이어서(브라우저가 `pointercancel` 로 끝냄) 따로 케이스를 세웠다 — «12px 움직인 뒤 멈춰 있어도 안 선다».
- 구조 · 메뉴 트리 줄은 캔버스에 못 놓는 줄이라(정본) «놓을 자리가 없는 곳에서 끝나는가»를 잰다. 이 끝나기 실패가 펜 결함의 본체다.

## 지침 보고

1. **`CLAUDE.md` «jsdom 값은 실브라우저 값이 아니다» 문단(CDP 펜 문장) 뒤에 넣을 문장:** «**펜으로 끄는 장치는 캔버스 iframe 을 `pointer-events: none` 으로 막는다**(`drag/use-pointer-drag.ts` «끄는 동안 캔버스 iframe 은 포인터를 안 받는다»). 그 막기는 **인라인 style** 이다 — `shell.css` 의 누수 검사(`apps/web/test/shell-css.test.ts`)가 결합자 선택자(`.a .b`)를 막아, 클래스로 거는 첫 길은 `pnpm test` 를 14건 빨갛게 했다.»
2. **같은 문단에 넣을 문장(터치):** «**터치 끌기는 길게 눌러 선다**(300ms · 8px). window 의 `touchmove` 는 기본이 passive 라 스크롤을 막으려면 `{ passive: false }` 로 **누른 때부터** 걸어야 하고, `touch-action` 은 현재 제스처에는 못 바꾼다. 판은 `Input.dispatchTouchEvent` + `hasTouch` 컨텍스트로 재고 호스트 `pointercancel` 수를 함께 센다.»
3. **`CLAUDE.md` 의 `pnpm test` 전량 게이트 문장에 넣을 문장:** «전량이 평소의 몇 배(M3: 376s → 3416s)로 길어지면 api 잠금 · viewer 케이스가 `STACK_TRACE_ERROR`(시간 초과)로 죽을 수 있다 — 단독 재실행으로 가르고, 가른 방법을 보고에 적는다.»
