## 2. 단축키 표 · 리스너 — `edit/editor-shortcuts.ts` · `edit/use-editor-shortcuts.ts` · `shell/editor-keys.tsx`

- 표 하나(`EDITOR_SHORTCUTS` — 15 명령) · `platformOf`(mac → Meta, 그 밖 → Ctrl, 엇갈린 쪽 안 섬) · 글자 키는 `key` 가 ASCII 글자 하나면 그것, 아니면
  `code`(한글 자판의 Ctrl+ㅋ = 되돌리기 · Dvorak 의 물리 `KeyZ` `;` 는 아님).
- 거르개 `shortcutsBlocked(event)` 하나를 키 · 클립보드 리스너가 함께 쓴다 — 조합 중 · 이미 받음(`defaultPrevented`) · 입력 표면(`isTypingSurface`) ·
  제 단축키 상자(`[data-wb-own-shortcuts]` — 메뉴 트리 상자에 붙였다) · 호스트의 `dialog[open]`.
- 리스너는 호스트 `document` 와 캔버스 iframe 문서에 건다(`useCanvasDocument` 의존). 편집 명령은 `editable`(편집 모드 && `canEdit`)일 때만, 그때만
  `preventDefault`.
- 셸 `EditorKeys` 가 명령을 잇는다 — 되돌리기 · 다시 실행은 `useEditCommit` 의 `undo` · `redo`(단추가 꺼진 판 `canUndo` 거짓이면 안 부른다), 삭제 ·
  순서 · 계층은 `useStructureCommands` 의 명령을 `abilities` 가 참일 때만, 선택 이동은 `edit/selection-move.ts`, `?` 는 `shell/shortcut-help.tsx`
  (`ShellDialog` — 표 + 클립보드 세 줄 + 구조 트리 상자의 두 줄).
- 구조 트리에는 고르개를 여는 두 단축키(Alt+Shift+I · P — `TREE_SHORTCUTS`)만 남았다 — 고르개가 그 트리의 명령 인스턴스 상태(`adding`)라서다.
- **`isTypingSurface` 를 창마다의 생성자로 고쳤다**(`panels/typing-surface.ts`) — 호스트 `instanceof HTMLElement` 라 캔버스 iframe 의 `<input>` 이
  표면이 아니었다(그 파일 머리말이 «iframe 을 그리게 되면 이 구멍이 열린다»고 적어 둔 구멍). 캔버스 리스너를 걸면서 열리는 길이라 이 트랙에서 닫았다.

## 3. 클립보드 · 붙이기 · 복제 · 잘라내기 — `edit/paste-ops.ts` · `edit/use-clipboard.ts`

- `pasteOps` — 기준 노드 바로 뒤 형제로 차례대로, 없거나 루트 · 문서에 없으면 루트 끝. 연산은 차례로 적용한 문서 위에서 잇는다. 부모가 자식을 안 받으면
  `+` 의 문장(`STRUCTURE_WHY_DISABLED.addInside`) · 200 초과면 `tooManyOpsNotice` · 넣은 뒤 새 `error` 면 그 이유. **붙인 노드의 `marker` 를 걷는다**
  (`stripMarkers`).
- `duplicateOps` — 노드마다 제 바로 뒤, 사본은 `prepareNodesForPaste`(keep 늘 참)로 새 id · `marker` 걷음. 루트 · 없는 노드는 «아래 추가»의 문장.
- `removeManyOps` — 차례로 적용한 문서 위 좌표 · 조상이 든 노드는 건너뜀 · 루트/없는 노드면 `null`.
- `useClipboard` — 호스트 · 캔버스의 `copy` · `cut` · `paste`. 거르개는 단축키와 같고, 복사 · 잘라내기는 **긁어 고른 글자가 있으면 그 글자의 복사**로 둔다.
  `clipboardData` 가 없으면 잘라내기가 지우지 않는다.
- 셸 — 붙이기: `readNodesEnvelope` → (봉투에 페이지 대상이 있으면 `getTree` 로 지금 프로젝트의 대상 목록) → `prepareNodesForPaste`(keep.node = 지금 문서에
  있음 · keep.page = `matchPageTargets`) → 기준 노드를 남이 잡았으면 상태줄 문장 → `pasteOps` → `editBlockedBy` 면 `lockedNotice` → `commitOps` → 넣은
  마지막 노드를 고름 → 뺀 수가 있으면 `droppedActionsNotice`. 복제도 같은 끝(`commitInsert`). 잘라내기는 삭제와 같은 판정(`abilities.remove`) · 같은 명령.

## 계획과 달라진 것

1. **`useEditCommit` 을 한 곳에서 부르는 길이 아니다** — 계획은 «훅을 두 번 부르지 않는다 — 전송 루프 가드가 하나여야 한다»였는데 in-flight 가드는 훅의
   `ref` 가 아니라 스토어(`#pumping`)가 들고, 그 훅은 이미 일곱 자리에서 불린다(`routes/editor.tsx` 의 `UndoTools` 머리말이 같은 사정을 적었다). 셸
   `EditorKeys` 가 한 번 더 부르고, «같은 함수»는 단추 판 · 키 판의 결과를 견주는 케이스로 잰다(2 절).
2. **구조 트리에 접는 줄이 없다** — «펼침 목록 함수»가 없어 보이는 차례 = 전위 순회다(`edit/selection-move.ts` 의 `visibleNodeOrder` — 트리가 줄로
   그리는 것과 같은 거름: 노드가 아닌 원소 · 빈 id 건너뜀).
3. **트리 Delete 의 «확인 → 바로 삭제» 전환은 없었다** — 원래 바로 지웠다(삭제 확인 인구조사).
4. `useEditorShortcuts` 의 `blocked: () => boolean` 을 두지 않았다 — 막는 조건(모달 · 메뉴 트리 상자)은 전부 DOM 에서 읽혀 `shortcutsBlocked(event)` 하나에
   두고 클립보드 리스너와 나눴다. 케이스용 `platform?` 을 더했다.
5. `useClipboard` 는 리스너만 들고 `copy` · `cut` · `paste` 콜백을 받는다(편집 · 통지는 셸) — 잘라내기는 «지울 수 있을 때만 봉투를 싣는다»로 콜백 하나다.
6. `prepareNodesForPaste` 의 `keep.page` 는 **페이지 대상 글자**(`page:메뉴/제목`)를 받는다 — 대상이 id 가 아니라 경로다. 빈(아직 안 고른) 대상은 «밖»이
   아니라 남긴다. `readNodesEnvelope` 에 케이스 이음매 `migrations` · `target` 을 더했다(`migrateDocument` 와 같은 꼴 — 마이그레이션이 0 개라 그것
   없이는 옛 version 갈래를 못 잰다).
7. **붙이기 · 복제가 `marker` 를 걷는다** — 계획에 없던 것. 코멘트가 따라가지 않는데 번호를 든 채 넣으면 한 페이지에 같은 번호가 둘이 된다.
8. **`isTypingSurface` 의 창 문제를 고쳤다** — 계획은 «그 함수 하나로 가른다»였고 그 함수가 캔버스 iframe 의 요소를 못 봤다(2 절).
9. 붙이기는 넣은 노드의 **마지막**을 고른다(하나만 고르는 판 — 이어 붙이면 차례로 선다). 루트를 고른 복사 · 잘라내기는 브라우저 기본, 루트 복제는
   «루트가 아닌 노드를 고르세요».
10. 페이지 대상이 든 봉투만 `getTree` 를 한 번 읽는다 — 이 화면에 페이지 목록을 든 곳이 메뉴 트리 훅의 상태뿐이다. 읽기가 실패하면 붙이지 않고
    «페이지 목록을 읽지 못해 붙이지 못했습니다»(대상을 모른 채 빼면 남길 동작까지 잃는다).
11. Cmd+A 는 표 · 도움말에 있고 `preventDefault` 하지만 E1 에서는 기준 노드가 그대로다(브리프대로) — 페이지 글자 전부 고르기가 에디터 위에서 안 선다.
12. 「권한 모델」의 «미리 묻는 자리»에 **키보드 삭제는 안 넣었다** — 키보드 삭제는 줄 `…` «삭제»와 같은 고르기 판정(`structureAbilities` 의 잠금 —
    `findLockConflict`)을 지나지 `lockConflictOfOps` 를 부르지 않는다. 그 목록은 «같은 함수(`lockConflictOfOps`)를 부르는 자리»라 넣으면 거짓이다.
13. 낡은 주석 셋을 고쳤다 — `store/editor-store.ts` 의 «되돌리기에는 막을 단축키가 아예 없다»(이제 Cmd+Z 가 있다 — 둘 다 같은 판정에 닿는다고 고쳤다) ·
    구조 트리의 `SHORTCUTS` 를 가리키던 `structure-toolbar.tsx` · 테스트 머리말들 · `typing-surface.ts` 머리말.
14. **«실패 케이스 먼저»를 다 지키지 못했다** — Task 1 의 봉투 케이스만 먼저 세워 빨강(모듈 없음)을 봤고, Task 2 · 3 은 구현을 먼저 쓰고 케이스를
    세웠다. 그 자리의 구분력은 위 변조 표가 잰다(그 케이스들이 고침을 뗀 판에서 값으로 죽는다). 처음부터 초록이던 기존 키 케이스(`structure-keyboard`
    등)는 표가 옮겨 간 뒤에도 같은 값을 잰다.

## 이월 후보

1. **뺀 동작 수의 통지가 «실패» 자리(`EditAlert` — `role="alert"`)에 선다** — 붙이기는 성공했는데 실패 통지 꼴이다. 정보 통지 자리(페이지 JSON 통지처럼)를

   말할지.
3. 선택 이동이 고른 줄을 트리 · 캔버스에서 보이게 스크롤하지 않는다.

확인이 다 «고른 것»에 대해 돈다. 줄 id 를 실으려면 두 트리의 명령 묶음이 줄마다의 판정을 따로 지어야 하고, 하나라도 빠지면 «연 줄의 이름 · 고른 노드의

### R4 — 같은 페이지 다시 싣기에 붙이기를 «옮겨»로 버림

판: 페이지 `[글 1, 글 2, 가기(navigate → 둘째)]` · «가기» Cmd+C → 캔버스 «글 1» → `GET …/tree` 를 붙잡고(4 ~ 6s) Cmd+V → 판마다의 사건. 칸은 서버 뿌리 자식 ·
하단 바.

| 판 | 고치기 전 | 고친 뒤 |
|---|---|---|
| V2 WS 끊고 재연결(끊긴 사이 bob 이 «글 1»을 고침 · 끊은 수 > 0 · bob 200) | `글 1 (bob),글 2,가기` · «붙이는 사이 페이지를 옮겨 붙이지 않았습니다…» | `글 1 (bob),가기,글 2,가기` · 다시 싣기의 «연결이 다시 붙어 … 되돌리기 이력이 초기화됐습니다» |

| L4 떠나 머묾 · 떠났다 돌아옴(앞 대응 케이스) | — | 그대로 안 붙음 · «옮겨» 한 줄 |

**고친 길.**

- **판 갈림을 «떠남»과 «같은 페이지 다시 실음»으로 가른다** — 스토어에 판을 연 세대 `pageOpenEpoch`(`#pageOpenEpoch`)를 두었다. 페이지를 열거나(다른 페이지 ·
  비운 뒤 다시 엶) 비울(`clearPage` · `reset`) 때만 오르고, 같은 페이지를 비우지 않고 다시 싣는 `loadPage`(재연결 재조회 · 복원 뒤 다시 읽기 · 수습)에서는 안
  오른다. 가르는 값은 `#selectionFor` 의 «다시 싣는 중»(같은 `openPageId` · 문서 있음)과 같다 — 화면은 여는 경로에서만 먼저 `clearPage` 를 부른다. 붙이기는
  이 세대로 견주고, 큐의 세대(`queueEpoch`)를 읽던 관문은 걷었다(읽는 자리가 붙이기 하나였다).
- **자리는 누른 때 고른 노드다** — 읽는 사이 다른 노드를 골라도 누른 자리에 붙고, 다시 실은 문서에 그 노드가 없으면 페이지 끝(spec 「붙이기」 자리 규칙).
  앞 판은 «끝나는 순간의 선택»이라 V5 에서 수습이 사본을 지워 선택이 빈 판이 페이지 끝에 붙었다(변조 M10 — `글 1,글 2,가기,가기`).
- **붙이기는 기다리는 사이 선 잃음을 치우지도 덮지도 않는다** — `commitOps(ops, { pressed })`(`CommitOptions` — 누른 때의 통지와 지금 통지가 다르고 잃음
  조각이면 안 치운다 · `sayAfterWait` 와 같은 판정을 `lossArrivedSince` 하나로 나눠 쓴다), 붙이지 못했다는 말(떠남 · 목록 읽기 실패)은 `tellLoss` 조각으로
  잇는다(`paste:<문장>` 열쇠 · 세기 `cancelled`). 붙인 뒤의 말(뺀 동작 수 · 잠금 · 이유)은 그 사이 잃음이 섰으면 조각으로, 아니면 하단 바 한 자리로 선다.
  그래서 V2 · V4b 의 «되돌리기 이력이 초기화됐습니다»도 붙인 뒤 남는다 — 앞 판은 붙이기의 편집이 그 통지를 치웠다(변조 M11 — 세 판 다 하단 바 빔).
- **떠난 판의 문장은 그대로 둔다**(«붙이는 사이 페이지를 옮겨 붙이지 않았습니다. 다시 붙여 넣으세요.») — 이제 떠난 판에만 서서 참이다. 브리프의
  «다른 페이지로 옮겨 붙이지 않았습니다»는 같은 뜻이라 문안을 안 바꿨다(문안을 바꾸면 L4 케이스 · 머리말의 조각 단언을 함께 고쳐야 한다).

**재지 않은 것.** 복원 뒤 다시 읽기가 페이지를 못 읽어 판을 비우는 갈래(`clearPage({ restoreReread: true })` — 복원으로 그 페이지가 사라진 판)도 «떠남»이라
그 사이의 붙이기는 «옮겨»로 말한다 — 페이지를 옮긴 것이 아니라 페이지가 없어진 판이다.
