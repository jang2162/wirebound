# P8-3 상호작용 런타임 구현 계획

> **에이전트에게:** 태스크 단위로 실행한다. 각 태스크는 실패하는 케이스 → 최소 구현 →
> 통과 → 커밋의 순서를 지킨다.

**목표.** §11.3의 `assets/runtime.js`를 세운다. 이 슬라이스가 끝나면 *"내보낸 번들에서
버튼을 누르면 웹 앱에서 누른 것과 같은 일이 일어난다"*가 참이 된다.

**§11.3:** *"트리 네비게이션·목업·코멘트 3분할이 웹 앱과 동일하고, **상호작용도 동작한다**."*
**§8.3:** *"내보낸 HTML 번들은 항상 뷰 모드다."*

**P8을 넷으로 나눈다.** ①exporter 코어 → ②번들 구조·뷰어 셸 → ③**런타임**(이 슬라이스) →
④내보내기 경로(api·웹·내려받기). ①②는 병합됐다.

**왜 ③과 ④를 가르나.** ④는 *"자리마다 제 것이 실렸는가"*가 **다섯 겹**이고(P8-2 이월 §10 —
프로젝트/코멘트/테마/스냅샷/zip 엔트리) 권한·zip·스냅샷 정책이 함께 온다. ③은 **순수
패키지 안에서 끝나고** 그 자체로 관측 가능하다.

**스택.** `packages/exporter` · `packages/renderer`(그대로 쓴다) · vitest.
**서버·웹은 건드리지 않는다.**

## 전역 제약

- **워크트리 안에서만 작업한다.**
- `pnpm test` · `pnpm typecheck` · `pnpm build`가 마지막에 전부 통과해야 한다.
  **종료 코드는 파이프 없이 따로 찍어라.**
- **게이트 전에 다른 vitest가 도는지 `ps`로 확인하라** — 다른 저장소의 것이라도 CPU를 나눠
  쓰면 api 타임아웃이 흔들린다(P8-2 이월 §12의 실측).
- **`git checkout --`을 쓰지 마라.** python 치환으로 심고 `finally`에서 원본 전문을 되쓴다.
- **0 사망이 나오면 그렇다고 보고해도 된다. 다만 원인을 단정하지 마라.** 못 죽였으면
  **겨냥을 바꿔 다시** 재라. **케이스가 구현과 무엇을 공유하는지 보라.**
- **자를 구현 파일에 두지 마라** — P8-2 이월 §11. 접두어·목록 같은 것이 `src`에 살면
  케이스가 그것을 import해 **함께 움직인다.**
- **하나짜리로 재지 마라** — P8-2 이월 §10. 페이지 하나·규칙 하나로 재면 *"자리 0"*이 되어
  섞여도 안 죽는다.
- **수를 산문에 적지 마라.** 세야 한다면 **케이스가 만들게 하라.**
- **단언을 주석에 적지 마라.**
- **문서에 실행되는 코드를 싣지 마라** — P8-1이 이월의 스니펫으로 실제 결함을 냈다.
- **소스에 날 제어 바이트를 넣지 마라.** census가 `docs/**`도 훑는다.
- **설계 문서(`docs/superpowers/specs/*`)는 고치지 않는다.** 어긋나면 판정해 보고한다.
- **남이 잰 값은 귀속을 붙여 옮긴다.**

## 확정한 결정

### D1. **런타임은 판정하지 않는다 — 내보내기가 판정하고 결과를 심는다**

사실 9가 P8-3에게 넘긴 물음이다. `runInteraction`이 카탈로그와 zod를 끌고 오고, **카탈로그가
없으면 깨진 규칙이 조용히 지나간다.**

| 후보 | 왜 아닌가 / 왜인가 |
|---|---|
| 런타임에 카탈로그를 싣는다 | `runtime.js`가 카탈로그+zod를 통째로 진다. 정적 번들의 자산 크기가 문서 수와 무관하게 커진다 |
| 런타임이 판정을 건너뛴다 | **침묵이 돌아온다.** 이 저장소가 여섯 번 만난 부류다 |
| **내보낼 때 판정하고 결과를 데이터로 심는다** ✅ | 번들은 **정적**이므로 판정 시점이 내보내기 시점인 것이 자연스럽다. 그리고 이 저장소의 규칙(*"판정을 두 벌 두지 마라"*)이 지켜진다 — 판정하는 코드가 하나다 |

**그래서 런타임이 받는 것은 *"이미 판정된 규칙"*이다.** 깨진 규칙은 내보내기가 걸러
`errors`에 담거나 데이터에 표시하고, **화면이 그것을 말한다**(무엇을 말할지는 판정하라).

**`runInteraction`을 안 쓴다는 뜻이 아니다.** 실행은 여전히 그 함수여야 한다(사실 1) —
**판정만 앞으로 옮긴다.** 그 둘을 어떻게 가를지가 이 슬라이스의 설계다.

### D2. **런타임은 고전 스크립트다 — `type="module"`을 쓰지 마라**

`file://`에서 모듈 스크립트는 CORS로 막힌다. **재라(재라 #6)** — 막히면 번들이 기본
배포 방식에서 통째로 죽는다.

그리고 **사실 3**: `cssRules`를 읽지 마라. **시트를 읽어 무언가를 판단하는 코드를 쓰지 마라.**

### D3. **런타임 파일을 어떻게 만드나 — 재고 판정하라**

| 후보 | 대가 |
|---|---|
| **별도 엔트리를 빌드해 문자열로 읽는다** | 타입 검사가 되고 `renderer`의 실행 코드를 그대로 쓴다. 대신 **빌드 순서**와 **`dist` 의존**이 생긴다 |
| 문자열 상수로 손으로 쓴다 | 타입 검사가 없고 케이스가 어렵다. **`renderInteraction`과 갈린다** |

**나는 앞쪽을 권한다** — *"실행은 같은 함수"*(사실 1)를 지키는 유일한 길로 보인다.
**다만 안 재고 쓴다. 재고 뒤집어도 된다** — 뒤집으면 근거를 적어라.

**`dist`가 로드되는지 지키는 케이스가 아직 없다**(P8-2 이월 §8). 이 슬라이스가 `dist`에
기대게 되면 **그 케이스가 필요해진다.**

### D4. **겹layer(번호 마커)를 그린다 — 기준은 문장화 쪽이다**

사실 4가 데이터를 실어 뒀고 사실 5가 함정을 지목했다.

- 코멘트 줄의 `data-wb-marker-for` ↔ 문서 노드의 `data-wb-id`를 이어 **그린 뒤에 잰다**
  (캔버스가 `getBoundingClientRect()`로 하는 것과 같다).
- **캔버스의 기준(`Number.isInteger`)을 그대로 옮기지 마라.** 번들의 코멘트 줄이 **문장화
  쪽(1 이상)**을 따랐으므로, 겹layer가 캔버스 기준을 쓰면 **같은 번들 안에서 두 줄이 갈린다.**
- **케이스로 고정하라** — 0·음수·비정수 marker를 담은 문서로 재라.

### D5. **스크립트가 없어도 번들이 쓸모 있어야 한다**

`file://`에서 JS가 꺼져 있거나 막힐 수 있다. P8-2가 세운 것(목업·트리·탭·코멘트)은 **전부
스크립트 없이** 동작한다.

**런타임이 더하는 것은 상호작용 동작과 겹layer뿐이어야 한다.** 그 둘이 없어도 나머지가
그대로인 것을 **케이스가 지켜라** — 런타임 파일을 뺀 판과 넣은 판을 견줘라.

**탭을 다시 만들지 마라**(사실 6).

### D6. **`navigate`·`openModal`은 링크가 된다**

사실 2가 P8의 답을 이미 적어 두었다. 타겟이 `"page:…"`이고 **번들에는 그 페이지의 파일이
있다.**

- **P8-2의 파일 이름 함수가 그 매핑을 안다**(`pageFileNames`). 그것을 쓰라 — 두 벌을 만들면
  링크가 실제 파일과 갈린다.
- **가리키는 페이지가 번들에 없으면** 무엇을 할지 판정하고 케이스로 고정하라. **조용히
  아무 일도 안 일어나게 두지 마라** — 그것이 이 저장소가 여섯 번 만난 부류다.

### D7. **`<script>` 0건 케이스의 명제를 바꾼다**

사실 7. **지우지 마라.** *"정확히 이것 하나를 낸다"*로 바꾼다 — P8-2가 P8-1의 케이스 둘에
한 것과 같다. 인라인 `<script>`가 아니라 **`assets/runtime.js`를 가리키는 것 하나**여야
한다(데이터를 인라인으로 심는다면 그것도 세어 명제에 넣어라).

### D8. **데이터를 심을 때 `scriptJson`을 부른다**

사실 8. **규칙을 베끼지 마라.**

### D9. **문장과 동작이 갈리지 않아야 한다**

우측 상호작용 탭의 문장은 `describeInteraction`이 만들고(P8-2), 동작은 런타임이 한다.
**사실 10을 다시 재라** — 그 뒤 슬라이스가 여럿 지났다.

**번들 안에서** 그 둘이 같은 규칙을 가리키는지 재라: 탭에 문장이 있는 규칙은 눌리고,
눌리는 규칙은 탭에 문장이 있어야 한다. **한쪽만 있는 규칙이 있으면 그것이 발견이다.**
