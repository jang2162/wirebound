## 위험 셋 — 먼저 잰 값

### 1. 빈 구역 칸이 `thead` · `tbody` 안에 설 때

실 Chrome(헤드리스 · `/Applications/Google Chrome.app`)에서 표 `thead` · `tbody` 끝에 `createElement` + `appendChild` 로 `div` 를 넣었다(React DOM 이 넣는 길 — 파서의 foster parenting 이 아니다).

| 무엇 | 값 |
| --- | --- |
| 부모 | `THEAD` · `TBODY` 그대로 — 표 밖으로 안 나간다 |
| 상자 | 둘 다 표 상자 안(`inside` 참) · 익명 행 + 익명 칸으로 감싸여 **첫 열 폭**(600px 표에서 227px) |
| `elementFromPoint`(칸 가운데) | 그 칸 |
| 접근성 트리 | `rowgroup › row › generic`(익명 행) |

- **«열» 구역은 몸통이라 빈 구역 칸이 안 선다**(빈 구역 칸은 이름 붙은 구역만 — `apps/web/src/canvas/empty-zones.tsx`). 표 안에 서는 칸은 «행»(`tbody`) 하나다.
- 에디터의 칸은 `span`(`inline-flex` · 최소 64 × 24)이라 첫 열 폭 안의 칩으로 선다 — 다른 구역 칩과 같은 꼴. `tr > td colspan` 꼴로 바꾸지 않는다.

## 찍는 판(PPTX — Q2)

- 표지 `<html data-wb-capture>` 와 SDK 의 찍는 판 시트 `CAPTURE_CSS`(`@layer wb-capture` — 스크롤 상자 `overflow: visible` · 고정 열 `position: static`)를 **찍는 도구가 함께 단다** — api 화면 그리기(`screen-render-chromium.ts` 의 `CAPTURE_INIT` — 채택한 시트 · 문서 뿌리가 서는 대로 표지)와 `wb-theme shots`(그리드 잣대 ③).
- **처음엔 기본 뷰 CSS 안에 층을 두었다가 뺐다** — jsdom 의 CSS 파서(rrweb-cssom 0.7 · 0.8)는 `@layer` 를 못 읽어 `Could not parse CSS stylesheet` 를 찍고 **시트를 통째로 버린다**: 에디터 · 번들의 jsdom 판이 기본 뷰 규칙 없이 돌았다(케이스는 초록 — 콘솔 오류만). `apps/web/src/canvas/canvas-iframe.tsx` 의 `HOLD_CSS` 가 같은 까닭으로 `insertRule` 을 쓴다. 기본 뷰 CSS 를 jsdom 시트로 읽어 규칙 수가 맨 위 블록 수와 같은지 보는 케이스를 세웠다(L1). api 가 react 없이 읽게 하위 경로 `@wirebound/theme-sdk/capture` 로도 낸다(`./version` 과 같은 꼴).
- 잰 값(실 Chromium · 뷰포트 720 · 배율 2): 열 10 × 셀 틀 160px 그리드 — 그림 폭 3200 초과 · 끝 열 색이 찍힌다(테마 없음 · 기본테마 1.7.0 둘 다). 같은 묶음의 그리드 없는 화면은 폭 1440 그대로. 열 12 × 80px 줄 50 — `2112×4427px` 로 넓이 상한(720 × 8192 px²)을 넘어 **그 장만** «페이지가 너무 커 화면을 그리지 않았습니다» 로 빠지고 나머지는 찍힌다(설계 «6» 의 셈 — 폭 2112 면 높이 2792 까지).
