## 결정과 이유

- **빈 구역 칸은 `tbody` 안 `span` 그대로**(위험 1) — 브라우저가 표 밖으로 안 끌어낸다. `tr > td colspan` 꼴은 행 구역만 다르게 그리는 갈래가 되어 안 바꿨다.
- **사본 비용은 설계를 바꿀 크기가 아니다**(위험 3).
- **`useGridHead` · `useGridRow` 는 `nodeId` 를 인자로 받는다** — 뷰 함수 몸은 `view()` 의 Provider 바깥이라 문맥 훅이 부모 노드의 값을 읽었다(배치가 행 · 열 뷰에 안 닿던 까닭).
- **`CAPTURE_CSS` 는 기본 뷰 CSS 밖 하위 경로로 낸다** — jsdom 이 `@layer` 를 못 읽어 시트를 통째로 버린다(«찍는 판» 절).
- **`0032` 는 판 4 문서를 전부 올리고 옛 기본값을 채운다**(«`0032`» 절).
- **저장된 테마 패키지는 카탈로그 검사를 빼고 읽는다** — 카탈로그에서 타입을 걷는 단계마다 그 앞 판 테마에 고정된 프로젝트의 내보내기가 통째로 테마를 잃는다. 내보내기만 `stored` 를 준다(올리기 · 빌드 · 시딩은 엄격).

## 위험 셋 — 먼저 잰 값

### 1. 빈 구역 칸이 `thead` · `tbody` 안에 설 때

실 Chrome(헤드리스 · `/Applications/Google Chrome.app`)에서 표 `thead` · `tbody` 끝에 `createElement` + `appendChild` 로 `div` 를 넣었다(React DOM 이 넣는 길 — 파서의 foster parenting 이 아니다).

| 무엇 | 값 |
| --- | --- |
| 부모 | `THEAD` · `TBODY` 그대로 — 표 밖으로 안 나간다 |
| 상자 | 둘 다 표 상자 안(`inside` 참) · 익명 행 + 익명 칸으로 감싸여 **첫 열 폭**(600px 표에서 227px) |
| `elementFromPoint`(칸 가운데) | 그 칸 |
| 접근성 트리 | `rowgroup › row › generic`(익명 행) |

- **«열» 구역은 몸통이라 빈 구역 칸이 안 선다**(빈 구역 칸은 이름 붙은 구역만 — `apps/web/src/canvas/empty-zones.tsx`). 표 안에 서는 칸은 «행»(`tbody`) 하나다.
- 에디터의 칸은 `span`(`inline-flex` · 최소 64 × 24)이라 첫 열 폭 안의 칩으로 선다 — 다른 구역 칩과 같은 꼴. `tr > td colspan` 꼴로 바꾸지 않는다.

### 2. 고정 열 `left` 이펙트 — 번들 · 캡처

`apps/web/build-test/data-grid.test.ts`(번들 · 화면 모드 `#wb-screen`)에서 둘째 고정 열의 `--wb-node-datagrid-left` 가 첫 열 폭과 같다 — 기본테마 `39px` = 39 · SDK 기본 CSS `30px` = 30(창 720 · 1280 · SDK 는 390 도). 번들 런타임에서도 레이아웃 이펙트가 돈다. 캡처(PPTX)는 찍는 판 시트가 고정을 풀어(`position: static`) 왼쪽 자리를 안 읽는다 — «찍는 판» 절.

### 3. 사본 비용(`apps/web/build-test/grid-editor.test.ts` «비용» — dev 번들 · 이 기계)

판을 열어(`goto`) 마지막 사본 줄이 서기까지 · 첫 열 «머리 이름» 을 고쳐 Enter 부터 캔버스 머리 칸이 새 이름이 되기까지(ms) · 그 사이 50ms 넘는 일(캔버스 창 포함)의 합. 두 판:

| 행 × 열 | 열기 | 머리 고치기 | 긴 작업 |
| --- | --- | --- | --- |
| 10 × 3 | 432 · 363 | 32 · 21 | 0 · 0 |
| 50 × 3 | 412 · 424 | 28 · 22 | 0 · 0 |
| 10 × 10 | 409 · 416 | 28 · 23 | 0 · 0 |
| 50 × 10 | 460 · 449 | 45 · 44 | 0 · 0 |

축마다 늘려도 열기는 거의 같고(판 세우기가 몫의 대부분) 고치기만 50 × 10 에서 두 배쯤이다 — 설계를 고칠 비용이 아니다. 긴 작업 0 은 관찰자가 50ms 넘는 일을 못 본 값이다(관찰자 자체의 카나리아는 없다 — 상한을 단언하지 않는 측정이라 그대로 적는다).
