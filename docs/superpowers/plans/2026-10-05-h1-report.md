## 2. 페이지를 가리키는 FK

다시 재는 법: `select conrelid::regclass, conname, confdeltype from pg_constraint where contype='f' and confrelid in ('pages'::regclass,'menu_nodes'::regclass)` 와 `information_schema.columns where column_name like '%page_id%'`.

| 표.열 | 가리키는 것 | ON DELETE | 연쇄 삭제가 하는 일 |
|---|---|---|---|
| `revisions.page_id` | `pages` | CASCADE | 페이지 행과 함께 간다(되살릴 수 없다 — 안전망 스냅샷으로도) |
| `comments.page_id` | `pages` | CASCADE | **먼저 `deletePageComments`** 로 지우며 키 있는 것의 묘비를 남긴다(CASCADE 에 맡기면 묘비 없이 사라진다) |
| `comment_tombstones.page_id` | — (FK 아님 · `project_id` 만 CASCADE) | — | 남는다(되살린 페이지의 같은 키 재전송을 막는다) |
| `page_seq_floors.page_id` | — (FK 아님 · `project_id` 만 CASCADE) | — | `deletePageRow` 안의 `recordPageSeqFloor` 가 마지막 번호를 남긴다 |
| `pages.menu_node_id` | `menu_nodes` | RESTRICT | 페이지를 먼저 지운다 |
| `menu_nodes.parent_id` | `menu_nodes` | RESTRICT | 깊은 것부터 한 행씩 지운다 |

소프트 잠금은 표가 아니다(룸의 메모리) — 페이지 삭제와 같이 손대지 않는다.

## 3. 삭제 차례(`services/menu-cascade.ts`)

1. `lockProjectForRestore` — 프로젝트 행 → 메뉴 → 페이지 → 레이아웃 → 코멘트(복원과 같은 함수). 서브트리만 잠그지 않는 까닭: 안전망 캡처의 지문이 프로젝트 전체를 보므로 서브트리 밖 편집 하나가 캡처를 깨뜨리고, 같은 잠금이면 복원의 «무엇이 막히나» 판단을 그대로 받는다.
2. `readMenuSubtree` — 없으면 404. 이어 **권한 재확인**(`recheckProjectRole` — editor) — 수를 견주기 전이다(기다리는 사이 빠진 사람에게 지금 수를 409 로 흘리지 않는다).
3. 화면이 본 수(`expect: { menus, pages }`)와 견준다 — 다르면 409 `menu-subtree-changed` · 이슈의 `subtree` 에 지금 수. 여기까지 쓰기 0.
4. `captureSnapshot` → `insertSnapshot`(안전망 — 첫 쓰기).
5. 페이지마다 `deletePageComments` → `deletePageRow`(번호 바닥) → 메뉴 깊은 것부터 → 남은 형제 `closeGap`.

본문 없는 `DELETE`(MCP · CLI · 옛 클라이언트)는 그대로 — 하위가 있으면 409. MCP · CLI 에는 메뉴 삭제 도구가 없다(`packages/mcp/src/tools.ts` · `packages/cli/src/commands/`) — 문서도 그대로다. 방송하지 않는다(페이지 `DELETE` 와 같다).

## 4. 경주 · 교착(`apps/api/test/menu-cascade-concurrency.test.ts`)

판마다 테스트 트랜잭션이 둘이 만날 행을 `FOR UPDATE` 로 쥐고, 앞 요청이 그 행의 줄(`pg_blocking_pids` 사슬)에 선 것을 본 뒤 뒤 요청을 쏘고, 둘 다 선 뒤 놓는다 — 놓은 뒤 받는 차례가 곧 줄의 차례다. 차례 둘 × 2 회. **교착(500)은 모든 판에서 0.**

| 겹친 쓰기 | 만나는 행 | 연쇄가 먼저 | 상대가 먼저 | 끝 상태 |
|---|---|---|---|---|
| 서브트리 안 페이지 추가 | 프로젝트 | 연쇄 200 · 추가 404 | 추가 201 · 연쇄 409(`{menus:1,pages:3}`) | 앞: 페이지 0 · 메뉴는 빈 메뉴만 / 뒤: 모두 남음 + 새 페이지 |
| 밖 → 안 메뉴 옮기기 | 프로젝트 | 연쇄 200 · 옮기기 404 | 옮기기 200 · 연쇄 409(`{menus:2,pages:2}`) | 앞: 빈 메뉴만 / 뒤: 메뉴 3 그대로 |
| 안 → 밖 메뉴 옮기기 | 프로젝트 | 연쇄 200 · 옮기기 404 | 옮기기 200 · 연쇄 409(`{menus:0,pages:1}`) | 앞: 빈 메뉴만 / 뒤: 페이지 2 그대로 |
| 같은 메뉴의 연쇄 둘 | 프로젝트 | 200 · 404 | (같음) | 안전망 1 개(404 는 안 씀) |
| 스냅샷 복원 | 프로젝트 | 둘 다 200 · 복원이 서브트리를 되살림 | 둘 다 200 · 연쇄가 뒤에 지움 | 차례대로 |
| 프로젝트 삭제 | 프로젝트 | 둘 다 성공(200 · 204) | 프로젝트 삭제 204 · 연쇄 404 | 메뉴 0 |
| 메뉴 이름 바꾸기(바탕) | 서브트리 메뉴 행 | 연쇄 200 · 이름 404 | 이름 200 · 연쇄 200 | 빈 메뉴만 |
| 페이지 이름 바꾸기(바탕) | 서브트리 페이지 행 | 연쇄 200 · 이름 404 | 이름 200 · 연쇄 200 | 페이지 0 |
| 페이지 편집(WS `patch`) | 서브트리 페이지 행 | 연쇄 200 · `patch-error` `not-found` | `patch-ack` · 연쇄 200 | 페이지 0 |
| 대조군(main 과 같은 길) — 본문 없는 빈 메뉴 삭제 ∥ 그 메뉴에 페이지 추가 | 프로젝트 | 204 · 404 | 201 · 409 | 이 길은 이 묶음이 안 바꿨다 |

더 잰 것 둘: **밖 페이지를 고치는 트랜잭션이 열려 있으면 연쇄가 그 커밋을 기다려 안전망에 싣는다**(줄에 섰다 = `true` · 안전망의 그 페이지 제목 = 고친 뒤 값). **수가 틀린 연쇄를 낸 editor 가 기다리는 사이 멤버에서 빠지면 409(지금 수) 가 아니라 거절이다**(멤버 삭제는 프로젝트 행을 안 잡아 그 사이 끝난다).

인구조사: `restore-lock-census` 에 연쇄 갈래 한 줄(**막힌다** — 같은 잠금이라 «막히지 않는 줄 목록»에 오르지 않는다) · `guard-in-lock` 의 `PROJECT_PROBES` 에 한 줄(holders `restore` · `tree`, 강등 판 포함 — 136 → 140) · `permission-matrix` 에 한 줄(owner · editor — 211 → 216).

## 5. 안전망 스냅샷

- 태그 `메뉴 "<제목>" 삭제 전 <capturedAt>` — 제목은 60 자 상한(UTF-16 길이)에 맞게 코드 포인트 단위로 줄이고 `…`. 설명 «메뉴 "X"와 하위 메뉴 N개 · 페이지 M개를 지우기 직전 상태 — 메뉴 <id>».
- 같은 밀리초 충돌은 409(다시 보내면 풀린다) — 복원의 안전망과 같은 판단.
- api 케이스(`menu-cascade-delete.test.ts` «지우기 직전 안전망 스냅샷을 찍고 — 그것으로 복원하면 서브트리가 되살아난다»): 목록에 보통 행으로 서고(태그 · 설명), 그것으로 복원하면 메뉴 넷 · 페이지 넷이 같은 id 로 돌아온다. 이력(`revisions`)은 안 돌아온다.
- 화면: 상자에 «지우기 직전 상태를 스냅샷으로 남깁니다 — 프로젝트 owner 가 그 스냅샷으로 되돌릴 수 있습니다.» 한 줄.
