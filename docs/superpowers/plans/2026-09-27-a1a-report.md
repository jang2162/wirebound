### Task 4 — 렌더러 테마 경로

- 실행: `packages/renderer` + `packages/theme-sdk` 22 파일 384/384(패리티 44 포함).
- 구분력(백업 `packages__renderer__src__view-host.tsx` · `…__render.tsx`, 바이트 비교 복원):

| 변조 | 죽은 케이스 | 실패 값 |
|---|---|---|
| ① `NodeBoundary` 걷고 `Guarded` 만 | «뷰가 던지면 그 노드만 폴백» · «던진 뒤 문서가 바뀌면 다시 그려 본다» | 렌더가 `Error: 테마 버그` 로 던짐(폴백 없음) |
| ② `setMissing(true)` 지움 | «Root 를 안 그린 뷰는 기본 뷰로» | `expected 'Root 없음' to be '기본'` |
| ③ `resolveVariant` 대신 `node.variant` | «manifest 에 없는 variant 는 defaultVariant» + 패리티 30(variantFrom 컴포넌트의 `data-wb-variant` 빠짐) | 31 실패 |
| ④ 경계의 리셋(`componentDidUpdate`) 떼기 | «던진 뒤 문서가 바뀌면 다시 그려 본다» | `data-wb-error` 가 남음 |

- 달라진 것:
  - `NodeBinding.attrs` 의 타입 — 계획의 `Record<string, string | undefined> & Partial<Record<'onClick'…>>` 는 만족할 수 없다(TS2322: 핸들러가 인덱스 시그니처의 `string` 에 안 맞는다). `Readonly<Record<string, string | 핸들러 | undefined>>` 로 두었다.
  - **노드 경계가 문서가 바뀌면 다시 그려 본다**(`resetKey = viewProps`) — 계획의 경계는 한 번 던지면 그 노드가 폴백에 갇힌다(편집으로 고쳐도 안 돌아온다). 케이스 «뷰가 던진 뒤 문서가 바뀌면 다시 그려 본다» 를 더했다(변조 ④).
  - 계획 Interfaces 의 `ViewHost.onViewError` 는 넣지 않았다 — 부르는 자리가 없다.
  - «Root 를 안 그린 뷰» 케이스를 `findByText` 대기 대신 동기 값 단언으로 — 레이아웃 이펙트의 다시 그리기는 RTL `render` 의 act 안에서 끝나고, 대기로 두면 변조가 타임아웃으로 죽는다.
  - 계획 테스트의 `Text` props `text` → 카탈로그의 이름 `content`.
  - 렌더러 devDependencies 에 `@testing-library/react` · `dom`, tsconfig `lib` 에 `DOM.Iterable`.

### Task 8 — 캔버스를 iframe · 뷰 경로로

- 실행: web 146 파일 2744/2744 · typecheck 0.
- 직접 조회 목록(`git grep -lE …` 계획의 명령): **20 파일 — 설계 탐침의 목록과 같다.** 문서 노드 조회를 하네스의 `canvasQuery` · `canvasQueryAll`(iframe 이 없으면 `null` · 빈 배열)로 기계적으로 바꿨다(19 파일). 외곽선 · 마커 · 배너 조회는 호스트 그대로. 표본 셋(`comment-panel` · `undo-restore-history` · `role-live`)을 열어 옳게 갈렸는지 봤다.
- 캔버스를 옮긴 직후 web 전량은 147 파일 중 111 실패, 치환 뒤 32 실패. 남은 것의 한 무리가 아래 첫째 결함이었다.
- **찾은 결함 — 빈 자리 클릭이 React 에 안 닿는다(Review Focus 3).** portal 의 컨테이너인 iframe `body` 는 React 가 그린 요소가 아니라서, `body`(또는 `html`)를 누른 클릭은 React 트리의 어느 핸들러에도 안 닿는다 — 선택이 안 풀렸다(치환 뒤 남은 32 실패 가운데 12 가 `deselect()` 로 «고른 것이 없는» 판을 세우는 케이스였다 — 나머지 20 은 옛 테마를 재던 케이스). `CanvasIframe` 에 `onBackgroundClick`(iframe 문서의 네이티브 `click` 리스너, 대상이 `body` · `html` 일 때)을 두고 캔버스가 편집 모드면 선택을 풀고 뷰 모드면 조작 시작(`beginGesture`)으로 받는다.
- 알림 줄 · 배너를 누른 것: 옛 코드에서 편집 모드의 배너 클릭은 선택을 풀었다(`nodeIdAt` 이 `null`). 새 코드도 같다(대상이 iframe 밖이면 `null`).
- 구분력(백업 `apps__web__src__canvas__canvas.tsx` · `…__canvas-iframe.tsx`):

| ② `nodeIdAt` 을 호스트 표면에서 멈춤 | 7 케이스(«노드를 누르면 그 노드가 선택된다» 등) | `expected null to be 'n-list'` 등 |

- 달라진 것:
