### S1 — 프로젝트 목록 응답에 멤버 수 · 최근 수정

- `apps/api/src/repos/projects.ts` `listProjectsForUser` 가 `memberCount` · `updatedAt` 을 싣는다. 질의 하나 — 두 칸은 상관 하위 질의
  (`project_members_pk` · `pages_project_menu_sort_idx` 의 앞머리 `project_id`).
  `updatedAt = greatest(projects.updated_at, (select max(pages.updated_at) …))` — 계획의 식 그대로다(ac 트랙의 `repos/admin-projects.ts` 와 같은 식).

  고쳤다(목록 + 두 칸 · 상세 + `themeRev`). 그 표를 재는 케이스가 없었다 — 머리말이 «임시 케이스» 실측만 적고 있었다. api
  `test/project-list-fields.test.ts` 의 «응답 넷의 키 집합» 이 이제 잰다.
- `http-client.ts` 관문 `projectList` 가 두 칸의 꼴(수 · 글자)을 본다. 웹 픽스처 열일곱 곳을 `test/helpers.tsx` 의 `listItem` · `LIST_ITEM_DEFAULTS`
  로 감쌌다. http-client 의 목록 케이스는 목록 모양 픽스처(`listed`)로 바꿨다 — 안 바꾸면 «id 가 빈 문자열이면 던진다» 같은 케이스가 두 칸이
  없어서 던지는 거짓 초록이 된다.

### S4 — 설정 · 계정 · 관리자 테마를 뼈대 안으로

- 셋을 뼈대에 넣고 설정 머리를 바꾼 것은 S2 커밋에 함께 들었다(위). 이 단계는 **설정 절 탭을 가로로**: `aria-orientation="horizontal"`, 탭 줄이 판 위(넘치면 줄
  안에서 민다), 판이 내용 칸 폭 전부. 키 규칙(←→ · ↑↓ · Home · End · 로빙 `tabIndex`) · `?section=` · owner 아니면 «위험 구역» 없음은 그대로다(계획 «그대로 초록»).
- `PageHead` 를 부르는 자리가 0 이 되어 `page-head.tsx` 를 걷었다(S2 — `q-ws.md` «요청 2»).
- 실브라우저: «설정 절 탭은 판 위의 가로 줄 …»(새) · «미리보기 틀이 뼈대 전 판보다 넓다».

## 결정

- **«최근 수정»은 계획의 식 그대로다** — 페이지 편집이 `pages.updated_at` 을 실제로 올린다(`writePageSchemaAtSeq` 의 `updated_at: now()`).
  api 케이스 «페이지 편집(ops 하나) 뒤 … 편집 전보다 늦고» 가 실커밋으로 잰다. 그래서 `max(revisions.created_at)` 으로 바꾸지 않았다.
- **S1 케이스는 실커밋 하네스(`withRealApi`)다.** 롤백 하네스(`withApi`)는 케이스 전체가 한 트랜잭션이라 `now()` 가 문장마다 같아
  «편집 뒤 더 늦다» 가 늘 거짓이다. ac 트랙이 같은 정의를 롤백 하네스로 재면 같은 데서 막힌다 — `q-ws.md` 에 적었다.
- **좁은 창(< 720px)은 위 줄 + «메뉴» 로 펴는 꼴이다**(`aria-expanded` · 목록 자신의 `data-folded`). 서랍(겹쳐 띄움)은 포커스 가두기 · 바깥 누름 · Escape 를
  따로 지어야 하고, 늘 펴 두면 관리자 칸 아홉이 390px 화면 반을 먹는다. 펴는 꼴은 흐름 안이라 Tab 차례가 문서 차례 그대로다. 문턱 720 은 사이드바 232px 를
  빼고 카드 하나(260px) + 여백이 넉넉한 폭.
- **뼈대는 창을 덮는 고정 상자다**(`.wb-shell` 과 같은 까닭 — `body` 의 UA 여백 8px 를 요소 선택자 없이 피한다). 그래서 문서가 아니라 뼈대 상자가 구른다.
  대가: 문서 `scrollWidth` 만 재는 자는 뼈대 안의 넘침을 못 본다 — `v4-settings-ui` 의 «가로 스크롤» 자가 그 꼴이라 뼈대 상자도 재게 고쳤다(변조 S2-B5 가 이제
  죽는다. 고치기 전 자로는 안 쟀다 — 문서가 안 넓어지므로 초록이었을 것이다).
- **관리자 «프로젝트» 칸과 «작업 공간» 의 «프로젝트» 가 같은 글이다** — 계약의 `label` 그대로 두고 두 묶음을 이름 있는 `nav`(«작업 공간» · «관리자»)로 갈랐다.
  케이스는 `nav` 로 좁혀 찾는다. 같은 까닭으로 픽스처 프로젝트 이름이 «프로젝트» 인 `known-user` 는 `current: false` 로 사이드바 칸을 뺐다.
- **«에디터 열기» 는 단추 꼴 링크**(`.wb-shell-settings-open`)다 — 주소가 있는 이동이라 새 탭으로 열 수 있어야 한다.
- **«준비 중» 화면의 몸은 `.wb-shell-settings`** 다 — M 트랙이 칸마다 갈아 끼운다.
- **역할 표지 · 역할 거름은 `.role` 가드를 넓힌다**(지침 «역할을 보이는 화면을 … 적으면 `role-access.test.ts` 의 경로 표를 먼저 센다»). 설계가 카드에 «내 역할» 과
  역할 거름을 요구해 넓혔다. 넓힌 폭은 글자 단위다 — 두 파일의 정해진 이름(`item.role` · `q.role` · `DEFAULT_QUERY.role` · `query.role`)만이고 같은 파일의 다른
  `.role` 읽기는 여전히 죽는다. 무엇을 열지는 계속 `projectAbilities` 하나다.
- **상대 시각의 «지금» 은 목록 상자가 설 때 한 번 잰다** — 검색어를 칠 때마다 «방금» 이 «1분 전» 으로 뛰지 않게. 30일부터는 지역 날짜(`YYYY-MM-DD`).
- **표지 · 거름의 역할 글은 영어 그대로**(owner · editor · viewer) — 멤버 절이 역할을 그 글로 보인다.
- **«새 프로젝트» 를 머리 오른쪽(`actions`)으로 옮겼다** — 위 줄은 거름이 차지한다.

## 지침

1. **무엇이 비었나** — 롤백 하네스(`withApi`)에서 `now()` 가 케이스 내내 같은 값이라 «쓰기 뒤 `updated_at` 이 늦다» 류 단언이 늘 거짓이다(S1 이 처음 밟았다).
   **어디** — `.ruler/` 의 wirebound 검증(`AGENTS.md` «검증 — wirebound» 「목 · 계측은 불린 수를 값으로 확인하고 …」 절). **넣을 문장** — «**`withApi` 는 케이스
   전체가 한 트랜잭션이라 `now()` 가 문장마다 같다** — 쓰기가 고치는 시각(`updated_at` 등)을 «앞보다 늦다» 로 재는 케이스는 `withRealApi` + `resetRealData`
   로 세운다(`apps/api/test/project-list-fields.test.ts`).»
2. **무엇이 비었나** — 에디터 밖 화면이 창을 덮는 고정 상자(`.wb-shell-workspace`) 안에 서면서 문서 `scrollWidth` 로 가로 넘침을 재는 자가 늘 0 을 낸다
   (`v4-settings-ui` 가 그 꼴이었다 — S2-B5). **어디** — 같은 파일 「수를 셀 때는 …」 덧붙임의 «화면 넘침은 요소 상자로만 세지 않는다» 항목. **넣을 문장** —
   «**에디터 밖 화면의 넘침은 문서가 아니라 뼈대 상자(`.wb-shell-workspace`)의 `scrollWidth` 로도 잰다** — 뼈대가 창을 덮는 고정 상자라 안이 넘쳐도 문서는
   안 넓어진다(`apps/web/build-test/workspace-layout.test.ts` 의 `overflow`).»
3. **무엇이 비었나** — 뼈대 사이드바가 `nav` · `list` · `listitem` · `link`(«프로젝트» · «계정» · 관리자 «프로젝트»)를 화면마다 더해, 범위 없이
   `getByRole('list')` · `getAllByRole('listitem')` · `getByRole('link', { name: '프로젝트' })` 로 찾던 케이스가 다른 값으로 죽거나 우연히 산다(`tokens` 의
   «멤버가 아닌 …» 은 사이드바 칸 둘을 토큰 줄 둘로 읽었다). **어디** — `AGENTS.md` «워커에게 맡길 때 — wirebound» 의 «입구 · 단추를 걷거나 더하는 트랙은 …»
   문단. **넣을 문장** — «**에디터 밖 화면의 케이스는 역할로 찾을 때 내용 칸(`.wb-shell-workspace-main`)이나 이름 있는 `nav`(«작업 공간» · «관리자»)로
   좁힌다** — 사이드바의 칸 목록이 같은 역할 · 같은 이름(«프로젝트»)을 갖는다.»
4. **무엇이 틀렸나** — 계획 S5 가 «정본 설계 「화면 사이의 길」» 을 가리키지만 그 절은 정본(`2026-08-03-wirebound-design.md`)에 없고 이력 spec
   (`2026-09-30-editor-shell-design.md`)에만 있다. 정본의 자리는 §9 «셸 밖의 화면» 이다. **어디** — 계획은 이력 문서라 고치지 않는다. 다음 계획을 쓸 때
   정본의 절 이름을 `git grep` 으로 세고 적는다(지침 «브리프 · 계획이 화면의 입구를 이름으로 적으면 …» 과 같은 잣대) — 새 문장은 필요 없다.
5. **새 문장은 필요 없다 — 있는 문장을 이 트랙이 늦게 지켰다.** «입구 · 단추를 걷거나 더하는 트랙은 이름 `git grep` 에 더해 실브라우저 전량을 게이트 전에
   한 번 돈다» 를 S2 에서 영향 파일 넷만 돌리고 게이트로 미뤘다. 게이트의 전량이 `editor-logout-edits` 를 잡았다 — 범위 없는 «더 보기» 는 이름 셈으로
   어느 화면의 단추인지 안 갈린다.
