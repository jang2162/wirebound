# WS(뼈대) 보고 — 트랙 S(S1 – S5)

브랜치 `feat/workspace-shell`, 기준 `20b398e2`. 계획 `docs/superpowers/plans/2026-10-31-workspace-admin.md` «트랙 S».

## 바꾼 것

### S1 — 프로젝트 목록 응답에 멤버 수 · 최근 수정

- `apps/api/src/repos/projects.ts` `listProjectsForUser` 가 `memberCount` · `updatedAt` 을 싣는다. 질의 하나 — 두 칸은 상관 하위 질의
  (`project_members_pk` · `pages_project_menu_sort_idx` 의 앞머리 `project_id`).
  `updatedAt = greatest(projects.updated_at, (select max(pages.updated_at) …))` — 계획의 식 그대로다(ac 트랙의 `repos/admin-projects.ts` 와 같은 식).
- 웹 `api/types.ts` 에 `ProjectListItem extends ProjectDetail { memberCount; updatedAt }`. `ProjectDetail` 머리말의 «응답 넷» 표를 키 집합 열로
  고쳤다(목록 + 두 칸 · 상세 + `themeRev`). 그 표를 재는 케이스가 없었다 — 머리말이 «임시 케이스» 실측만 적고 있었다. api
  `test/project-list-fields.test.ts` 의 «응답 넷의 키 집합» 이 이제 잰다.
- `http-client.ts` 관문 `projectList` 가 두 칸의 꼴(수 · 글자)을 본다. 웹 픽스처 열일곱 곳을 `test/helpers.tsx` 의 `listItem` · `LIST_ITEM_DEFAULTS`
  로 감쌌다. http-client 의 목록 케이스는 목록 모양 픽스처(`listed`)로 바꿨다 — 안 바꾸면 «id 가 빈 문자열이면 던진다» 같은 케이스가 두 칸이
  없어서 던지는 거짓 초록이 된다.

## 결정

- **«최근 수정»은 계획의 식 그대로다** — 페이지 편집이 `pages.updated_at` 을 실제로 올린다(`writePageSchemaAtSeq` 의 `updated_at: now()`).
  api 케이스 «페이지 편집(ops 하나) 뒤 … 편집 전보다 늦고» 가 실커밋으로 잰다. 그래서 `max(revisions.created_at)` 으로 바꾸지 않았다.
- **S1 케이스는 실커밋 하네스(`withRealApi`)다.** 롤백 하네스(`withApi`)는 케이스 전체가 한 트랜잭션이라 `now()` 가 문장마다 같아
  «편집 뒤 더 늦다» 가 늘 거짓이다. ac 트랙이 같은 정의를 롤백 하네스로 재면 같은 데서 막힌다 — `q-ws.md` 에 적었다.

## 잰 값

- 페이지 편집 전후의 `updatedAt`: 편집한 프로젝트만 늦어지고 다른 프로젝트는 같은 글자(실커밋, `project-list-fields.test.ts`).
- 구현 전 새 api 케이스 4/4 빨강(칸이 `undefined`).
