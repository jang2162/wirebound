## 결정

- **«최근 수정»은 계획의 식 그대로다** — 페이지 편집이 `pages.updated_at` 을 실제로 올린다(`writePageSchemaAtSeq` 의 `updated_at: now()`).
  api 케이스 «페이지 편집(ops 하나) 뒤 … 편집 전보다 늦고» 가 실커밋으로 잰다. 그래서 `max(revisions.created_at)` 으로 바꾸지 않았다.
- **S1 케이스는 실커밋 하네스(`withRealApi`)다.** 롤백 하네스(`withApi`)는 케이스 전체가 한 트랜잭션이라 `now()` 가 문장마다 같아
  «편집 뒤 더 늦다» 가 늘 거짓이다. ac 트랙이 같은 정의를 롤백 하네스로 재면 같은 데서 막힌다 — `q-ws.md` 에 적었다.
- **좁은 창(< 720px)은 위 줄 + «메뉴» 로 펴는 꼴이다**(`aria-expanded` · 목록 자신의 `data-folded`). 서랍(겹쳐 띄움)은 포커스 가두기 · 바깥 누름 · Escape 를
  따로 지어야 하고, 늘 펴 두면 관리자 칸 아홉이 390px 화면 반을 먹는다. 펴는 꼴은 흐름 안이라 Tab 차례가 문서 차례 그대로다. 문턱 720 은 사이드바 232px 를
  빼고 카드 하나(260px) + 여백이 넉넉한 폭.
- **뼈대는 창을 덮는 고정 상자다**(`.wb-shell` 과 같은 까닭 — `body` 의 UA 여백 8px 를 요소 선택자 없이 피한다). 그래서 문서가 아니라 뼈대 상자가 구른다.
  대가: 문서 `scrollWidth` 만 재는 자는 뼈대 안의 넘침을 못 본다 — `v4-settings-ui` 의 «가로 스크롤» 자가 그 꼴이라 뼈대 상자도 재게 고쳤다(변조 S2-B5 가 이제
  죽는다. 고치기 전 자로는 안 쟀다 — 문서가 안 넓어지므로 초록이었을 것이다).
- **관리자 «프로젝트» 칸과 «작업 공간» 의 «프로젝트» 가 같은 글이다** — 계약의 `label` 그대로 두고 두 묶음을 이름 있는 `nav`(«작업 공간» · «관리자»)로 갈랐다.
  케이스는 `nav` 로 좁혀 찾는다. 같은 까닭으로 픽스처 프로젝트 이름이 «프로젝트» 인 `known-user` 는 `current: false` 로 사이드바 칸을 뺐다.
- **«에디터 열기» 는 단추 꼴 링크**(`.wb-shell-settings-open`)다 — 주소가 있는 이동이라 새 탭으로 열 수 있어야 한다.
- **«준비 중» 화면의 몸은 `.wb-shell-settings`** 다 — M 트랙이 칸마다 갈아 끼운다.
