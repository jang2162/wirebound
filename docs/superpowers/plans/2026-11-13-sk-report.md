## 기준선

고치기 전 판은 워크트리가 아니라 **기준 커밋 사본**에서 잰다 — `git archive 8e2051d7` 을 스크래치에 풀고 `pnpm install --frozen-lockfile --prefer-offline` ·
`pnpm build` 로 세웠다(`apps/api/.env` 는 워크트리 것을 심링크 — Postgres 5462). 까닭: 시작할 때 기계 load 가 60 – 96(15 코어 · 한도 45)이라
게이트를 띄울 수 없었고, 워크트리에서 기다리면 그동안 아무것도 못 고친다. 사본의 `system-admin-1.8.0.wbtheme` sha256 은 `checksums.json` 의
1.8.0 줄(`d5e4a1e6…`)과 같다 — 같은 소스 · 같은 빌드다.

(값은 사본의 게이트가 끝나면 아래 「게이트」 절의 표에 함께 적는다.)

### 실브라우저 — 기대가 바뀌어 고친 기존 케이스 셋

| 변조 | 죽은 케이스 | 실패 값 | 실행 |

- **T3 · T3b 는 살았다.** `form-table.test.ts` «PPTX — … 칸 선이 가로 줄로 선다» 는 테두리 색인 가로 줄을 세는데, 넓은 입력칸 · 여러 줄 입력의
  테두리도 같은 토큰(`semantic.border`)이라 폭의 절반을 넘는 줄로 세진다 — 칸 선만 옅은 색으로 바꾼 T3 에서 줄 수가 문턱(8) 위에 남았다. 원래 있던
  성질이다(1.8.0 도 두 선이 같은 토큰이다). 칸 선과 입력 테두리를 함께 다른 토큰으로 바꾼 T3c 에서 `4 < 8` 로 그 케이스만 죽는다.
- T3b(테마 CSS 의 `:root` 값만 바꿈)가 산 까닭 — 번들은 테마 시트 뒤에 manifest 기본값으로 지은 토큰 시트를 싣는다. `:root` 의 값은 그 시트에 덮인다.
