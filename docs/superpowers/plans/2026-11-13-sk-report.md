## 결정

계획 · 브리프가 정하지 않았거나 다르게 간 자리다.

1. **그림자 토큰은 두 겹이다** — `shadow.md` = `0 1px 2px rgba(20,30,50,.06), 0 1px 1px rgba(20,30,50,.04)`. 토큰 문법이 쉼표 겹을 받는다
   (`packages/themes/test/token-value-grammar.test.ts` 의 `SHADOW_OK` 셋째 줄 · 빌드가 manifest 검증을 지났다).
2. **카드에 붙이기는 몸통 여백 0 + 자식 여백으로 했다** — 테두리 있는 카드의 몸통은 여백 0 이고 곧바로 든 노드가 제 여백 12px 을 갖는다. 폼 표 · 그리드 ·
   조회 폼만 여백 0 이라 카드에 붙는다 — **형제가 있어도 붙는다**(«홀로 든 것만» 은 끌기를 죽인다 — «결정 17»). `:has()` 없이 · 직계로 가른다. 겹선은 붙는
   쪽이 걷는다 — 폼 표 · 조회 폼은 오른쪽 · 아래 끝 칸의 선을 격자를 1px 넓혀 밀고 그 노드가 자른다(`overflow: hidden`), 그리드는 표의 바깥 선
   (`border-width: 0`)과 끝 줄의 아래 선을 걷는다. 머리줄 · 바닥이 없는 쪽은 `body:first-child` · `body:last-child` 로 알아 모서리를 카드 안쪽 모서리에
   맞춘다(그림만 바뀐다). **상세 표(`KeyValue`)는 안 붙였다** — 뿌리가 `<table>` 이라 넘친 선을 자를 상자가 없고 칸마다 사방 선이라 바깥 선만 걷을
   셀렉터가 없다. 여백 12px 을 지킨다.
3. **끝 줄까지 내려오는 세로 병합 칸의 아래 선은 남는다** — 카드에 붙은 그리드에서 끝 줄의 아래 선을 `tbody:last-child > tr:last-child` 로 걷는데, 앞 줄에서
   시작한 `rowSpan` 칸은 그 줄의 칸이 아니다. 그 칸 폭만큼 카드 테두리와 두 줄이 된다(원본 사이트도 같은 식 — `.adp-table tbody tr:last-child > *` — 이고
   병합 끝 칸에 따로 클래스를 붙인다. 테마는 DOM 을 못 바꾼다).
4. **세로로 쌓인 노드 사이에 8px 을 둔다** — 구역 · 탭 패널 · 팝업 몸통 · 테두리 없는 카드 몸통의 직계 자식이 자기 아래에 8px(`margin-bottom` · 위 여백 0)을
   갖는다(«결정 17»). 「참고 값」 은 «카드 사이 8px 인상» 만 적었다. 1.8.0 은 쌓인 노드가 맞붙어(0) `Flex` 로 감싸야 틈이 났다. `Flex` · `Grid` 의 틈도
   8px 이다(1.8.0 은 16 · 20px).
5. **칸 안의 `Text` 는 문단 여백을 걷었다** — 그리드 칸 · 결과 머리줄 · 필드 값 칸 · 카드 머리줄 · 폼 표 머리줄. `Text` 는 `<p>` · `<h1>` … 이라 브라우저 기본
   여백(글 크기만큼 위아래)을 갖고, 글 한 줄이 든 표 줄이 약 62px 이었다(입력칸이 든 줄은 47px — `wb-theme shots` 그림에서 잰 값). 걷은 뒤 약 37px 이다
   (칸 여백 8 + 글 한 줄 19.5 + 8 + 선). 1.8.0 에도 있던 여백이다.
6. **카드 · 탭의 조각 규칙을 직계(`>`)로 고쳤다** — 1.8.0 의 `[Card] [data-wb-part="header"]` · `[Tabs] [data-wb-part="list"]` 는 자손 셀렉터라 그 안에 든
   노드의 같은 이름 조각에 닿았다(탭 패널에 든 파일첨부의 목록 `table[data-wb-part="list"]` 이 `display: flex` · 카드에 든 폼 표의 `header` 에
   `margin-bottom`). 새 케이스 «카드 · 탭의 조각 규칙은 … 안 닿는다» 가 잠근다.
7. **줄무늬를 걷고 올려 둔 줄 바탕을 넣었다** — 「참고 값」 «줄 hover `canvas`». 짝수 줄 바탕은 행 꼴(음영 · 흐림)과 같은 색이라 둘이 안 갈린다.
8. **여러 줄 입력의 높이는 `max(120px, 줄 수 × 1.5em + 여백)`** — 「참고 값」 «최소 높이 120px» 과 `rows` prop 을 함께 지킨다. 줄 수 5 이하는 120px 이다
   (1.8.0 의 `rows: 2` 는 58px 이었다 — 원본 사이트에는 120px 아래의 여러 줄 입력이 없다).
9. **성공 색(`#308008`) 상수는 안 두었다** — 쓰는 규칙이 없다(카탈로그에 성공 색조가 없다). 안내 글 `#999999` 는 `--wb-text-placeholder` 로 두었다.
10. **`borderStrong`(`#666666`)은 단추 hover 테두리 · 체크 상자 테두리만 쓴다** — 1.8.0 이 그 토큰으로 긋던 자리(팝업 테두리 · 합계 행 윗선 · 고정 열 끝 선 ·
    자리표시자 점선)는 `border` 로 옮겼다. 새 값은 글 색에 가까운 짙은 회색이라 선에 쓰면 무겁다.
11. **탭은 밑줄 꼴 그대로다** — 원본 사이트의 탭(`.adp-tabs__tab.is-active`)은 고른 탭이 흰 바탕의 상자(위 · 좌우 테두리)다. 계획이 «고른 탭만 주색 밑줄
    (지금 케이스가 잠근다)» 로 정했고 구조 이름이 `Tabs:underline` 이라 계획을 따랐다. 값(13px · 굵기 500 · 고른 탭 700)은 원본과 같다.
12. **그리드 머리 칸에 줄바꿈 금지를 안 걸었다** — 원본은 `white-space: nowrap` 이다. 여기서는 열 폭(`size`)을 정한 열이 그 폭에서 낱말 단위로 꺾이는
    배치(SDK)를 지킨다. 단추도 같은 까닭으로 `nowrap` 을 안 걸었다(좁은 칸에서 넘친다).
13. **토큰 `semantic.canvas` 의 칸 이름을 «바탕 — 라벨 칸 · 옅은 구역» 으로 바꿨다** — 페이지 바탕이 흰 면이 되어 «바탕» 만으로는 무엇을 칠하는지 틀리게
    읽힌다. 키는 그대로다(케이스는 칸 이름을 `SYSTEM_ADMIN` 으로 읽는다).
14. **`max-width` 케이스의 거름을 다듬었다** — «`max-width` 를 거는 규칙마다 가로 여백 `auto`» 가 `max-width: none`(카드에 붙은 그리드가 SDK 의
    `max-width: 100%` 를 푼다)에도 `auto` 를 요구했다. `none` 은 가두는 값이 아니라 세지 않게 했다(변조 U21 — 유한한 `max-width` 는 여전히 죽는다).
15. **기준선은 기준 커밋 사본에서 쟀다**(「기준선」).
17. **배치를 바꾸는 규칙은 형제 구조로 가르지 않는다** — 처음 판은 쌓인 틈을 `* + *`(`margin-top: 8px`), 카드 붙이기를 «몸통에 홀로 든»
    (`:only-child`) 으로 지었다. 에디터는 끄는 동안 미리보기를 `display: none` 으로 **숨긴** 배치로 놓을 자리를 재는데(`apps/web/src/canvas/canvas-preview.ts`
    의 `withoutPreview`), 형제 셀렉터는 숨긴 요소도 형제로 센다. 탐침(`canvasHitAt` 의 `nodeHit` 에 상자를 찍는 줄을 끼우고 바이트 복원)으로 잰 값:
    탭 패널의 글 `n_t1` 이 첫 자식일 때 위끝 368.5 · 숨긴 미리보기 뒤일 때 363.5 — `* + *` 의 8px 이 `<p>` 의 기본 여백 13px 을 바꿔 쓴 5px 이다. 같은
    포인터(`y = 377.8`)에서 답이 «앞 ↔ 뒤» 로 뒤집히고, 캔버스가 다시 잴 때마다 다시 물어(`useAnnounceCanvasRemeasure`) 캔버스가
    `Maximum update depth exceeded` 로 죽었다(에디터 화면에서 캔버스가 통째로 사라진다). 고친 꼴: 쌓인 틈은 노드마다 **자기 아래**(`margin-bottom: 8px`
    — 원본 사이트 `_card.scss` 의 «카드 사이 간격은 인접 형제로 주지 않는다» 와 같은 식)이고 그릇의 아래 여백을 그만큼 줄였다(구역 12 → 4 · 좁은 구역 4 → 0
    · 탭 패널 8 → 0 · 팝업 몸통 12 → 4). 카드 몸통은 여백 0 이고 곧바로 든 노드가 제 여백 12px 을 갖는다 — 폼 표 · 그리드 · 조회 폼만 0 이라
    **형제가 있어도 붙는다**. 새 케이스 «배치를 바꾸는 규칙은 형제 구조로 안 가른다» 가 형제 셀렉터가 든 규칙의 속성을 그림만 바꾸는 것으로 묶는다(예외
    일곱 — 노드가 아닌 조각의 차례 다섯 · 1px 선 둘 · «남은 것»).
18. **좁은 구역(`compact`)의 아래 여백은 0 이다** — 위 4px · 아래 8px(마지막 노드의 자기 아래 여백)로 위아래가 다르다. 1.8.0 은 위아래 12px 이었다.
19. **커밋 단위** — 계획은 절마다 한 커밋이다. 문서 · 팝업 절은 한 커밋(`0971f945`)에 들었고, 화면을 보고 다듬은 것(칸 안 글의 여백 · 카드 제목 세로
    가운데 · 조회 폼의 빈 칸 아래 선)은 따로 한 커밋(`88ed3af1`)이다.

### 「참고 값」 과 원본 SCSS 를 견준 결과

「참고 값」 의 수 · 색은 SCSS 와 갈린 자리가 없다(`_tokens` · `_card` · `_field-grid` · `_form` · `_table` · `_search` · `_popup` 의 해당 선언을 줄마다
견줬다). SCSS 와 다르게 선 자리는 위 11 · 12 와 아래 셋이다 — 셋 다 카탈로그 · SDK 의 DOM 이 달라서다.

- 필수 별 — 원본은 `'*'`(굵게 · 틈 2px), 여기는 `"* "`(대체 글 비움). 1.8.0 의 접근성 계약(`packages/theme-kit/build-test/field-a11y.test.ts`)을 지킨다.
- 주 단추의 hover — 원본은 짙은 주색(`#0a64b4`)으로 채운다. 그 색의 토큰이 없어 주 단추는 hover 에 안 바뀐다.
- 조회 폼의 끝 줄 — 원본은 묶음이 줄을 채워 늘어나 빈 자리가 없다. 여기는 필드가 모자란 끝 줄에 라벨 바탕 없는 빈 칸이 선다(SDK 가 조회 폼에는 빈 쌍을
  안 낸다).

## 기준선

고치기 전 판은 워크트리가 아니라 **기준 커밋 사본**에서 잰다 — `git archive 8e2051d7` 을 스크래치에 풀고 `pnpm install --frozen-lockfile --prefer-offline` ·
`pnpm build` 로 세웠다(`apps/api/.env` 는 워크트리 것을 심링크 — Postgres 5462). 까닭: 시작할 때 기계 load 가 60 – 96(15 코어 · 한도 45)이라
게이트를 띄울 수 없었고, 워크트리에서 기다리면 그동안 아무것도 못 고친다. 사본의 `system-admin-1.8.0.wbtheme` sha256 은 `checksums.json` 의
1.8.0 줄(`d5e4a1e6…`)과 같다 — 같은 소스 · 같은 빌드다.

기준선의 값과 새 판의 값은 아래 「게이트」 절에 나란히 적는다.

**기준선을 세 번 띄웠다.** 첫 판(14:17 –)은 `pnpm test` 가 load 108 에서 api 프로젝트를 통째로 빼먹고 끝났고(파일 0 — forks 풀이 끊겼다), 그 뒤 단계는
기계가 잠든 시간(14:35 – 19:29 · 덮개 닫힘 · `pmset -g log` 의 Sleep 44 줄)에 겹쳤다 — 둘 다 «안 잰 것» 으로 버렸다. 둘째 판(19:32 –)의 `pnpm test` 는

## 남은 것

- **실브라우저 판은 그 기하에서만 고리를 잡는다** — 고친 테마 위에 옛 `* + *` 규칙을 되살린 변조(M1c)에 `zone-editor` 가 살았다(쌓인 틈이 «자기 아래»
  라 옛 기하가 안 돌아온다). 결함 꼴(형제 셀렉터로 배치를 바꿈)은 jsdom 인구조사가 잠근다(M1a · M2 가 죽였다). 형제 셀렉터 규칙을 다시 들일 때 그
  규칙이 만드는 기하에서 끌기 고리를 재는 실브라우저 판은 없다.
- **1px 차이가 남는 형제 규칙 둘** — 그리드 칸의 끝 칸 세로선 걷기(`:last-child`) · 카드에 붙은 그리드의 끝 줄 아래 선 걷기(`tbody:last-child >
  tr:last-child`). 끄는 동안 숨긴 미리보기 칸 · 줄이 끝에 서면 1px 이 달라진다 — 띠 경계에 정확히 걸친 포인터에서만 뒤집힐 수 있다. 못 쟀다.
- **에디터의 판정이 숨긴 미리보기의 형제 효과에 열려 있다** — 테마가 아니라 에디터의 성질이다(옛 판 테마 · 관리자가 올린 테마가 형제 셀렉터로 여백을
  바꾸면 같은 고리가 선다 — 1.8.0 은 `tr:nth-child(even)` 바탕색뿐이라 안 섰다). 닫는 길은 에디터 쪽(숨기는 대신 걷은 사본으로 재기 · 같은 포인터의
  답이 바뀌면 다시 묻지 않기) — 이 트랙(SDK · `apps/*/src` 불가침) 밖이다. **이월 후보 · 높음**(캔버스가 죽는다).
- **원본과 다르게 간 자리**(「결정」 11 · 12 와 「참고 값」 견줌의 셋) — 탭의 상자 꼴 · 머리 칸 줄바꿈 금지 · 주 단추 hover 의 짙은 주색.
- **이월** — 기존 프로젝트를 2.0.0 으로 올리기(고정 원칙 — 사람이 테마 설정에서 올린다) · Pretendard 글꼴 파일 싣기 · 헤더 · LNB 같은 셸 · 상세 표
  (`KeyValue`)를 카드에 붙이기(«결정 2»).

## 지침

1. **무엇이 틀렸나** — 테마 CSS 의 형제 셀렉터가 에디터 끌기를 죽일 수 있다는 것이 어디에도 없다. 테마 작성자(스타터 템플릿의 `SKILL.md` 를 읽는 사람 ·
   에이전트)는 `* + *` 같은 흔한 꼴을 쓴다.
   **어느 문서 어느 절** — `docs/superpowers/specs/2026-08-03-wirebound-design.md` §6 «테마는 코드 패키지다» 절(작성자 테마의 계약을 적는 자리)과
   `packages/theme-kit/template/SKILL.md`.
   **넣을 문장** — «배치(여백 · 크기 · 표시)를 바꾸는 테마 규칙은 형제 구조(`+` · `~` · `:first-child` · `:last-child` · `:only-child` · `:nth-*`)로
   가르지 않는다 — 에디터는 끄는 동안 배치 미리보기를 `display: none` 으로 숨긴 배치로 놓을 자리를 재는데 형제 셀렉터는 숨긴 요소도 형제로 세어, 미리보기가
   선 자리마다 숨긴 배치가 달라지면 같은 포인터에서 답이 뒤집혀 캔버스가 멈춘다. 색 · 모서리처럼 그림만 바꾸는 규칙은 괜찮다.» (이 트랙은 `packages/*`
   를 안 고쳐 템플릿에 넣지 않았다 · 정본은 넣지 않았다 — 판정은 코디네이터 몫.)
2. **무엇이 틀렸나** — 실브라우저 케이스가 «끌기 전에 잰 상자로 겨누기» 를 아직 여럿 한다(이번에 다섯 파일). `.ruler/20-verification.md` 의 «끄는 동안만
   서는 캔버스 그림 … `dragLayoutSettled` 뒤에 잰다» 문장은 «그림을 더하거나 키우는 변경» 을 조건으로 든다 — **테마가 노드 높이를 바꾸는 변경**도 같은
   케이스를 깬다.
   **어느 문서 어느 절** — `.ruler/20-verification.md` 의 «끄는 동안만 서는 캔버스 그림(빈 구역 칸 · 미리보기)을 더하거나 키우는 변경은 …» 문장.
   **넣을 문장** — 그 문장 끝에 «시스템 테마의 노드 높이(카드 머리줄 · 여백 · 글 줄)를 바꾸는 변경도 같다 — 칸이 미는 양이 테마마다 달라 끌기 전에 잰
