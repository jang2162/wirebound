## 2. 재라 표 일곱 — 각각 재서 판정

| 5 | viewer 권한이 맞다 | **참** | 번들이 담는 것 여섯을 세어 viewer가 화면에서 볼 수 있는지 하나씩 확인했다 — 문서·페이지 설명·코멘트(본문·작성자 이름·시각)·테마·메뉴 트리·상호작용 문장. **전부 이미 viewer가 읽는 엔드포인트에서 나온다.** 표는 `routes/export.ts` 머리말에 있다. **더 담는 것이 없다** |

## 3. D3 — `target`을 이었다. 그런데 재라 #2가 거짓이라 자리가 하나 더 필요했다

### 3.1 조립 규칙

**조상 메뉴 이름들 + 페이지 제목.** §8.1의 예(`page:관리자/회원/상세`)와 §11.3의 예시 파일
이름(`관리자-회원-목록.html`)이 둘 다 그 꼴로 읽힌다.

**트리를 한 번 도는 것이 순서이자 조상이다.** 둘을 따로 계산하면 *"남의 조상을 단 타겟"*이
생기는데 그 문자열은 그럴듯해서 아무도 못 걸러 낸다.

### 3.2 저작 화면과 같은 함수를 쓸 수 없었다 — **그 함수가 없다**

D3의 2번은 *"조립한다면 저작 화면이 타겟을 고를 때 쓰는 것과 같은 함수여야 한다"*였는데,
**저작 화면에 그런 함수가 없다**(재라 #2). 상호작용 탭은 페이지 경로를 **손으로 적게** 한다.

**그래서 자리를 하나로 만드는 대신 값을 흘려보냈다:** 내려받기 화면이 **페이지마다 서버가
조립한 타겟 문자열을 그대로 보인다.** 저작하는 사람은 그것을 복사해 상호작용 탭에 적는다.
조립하는 자리는 여전히 서버 하나이고, 화면은 그 결과를 **읽기만** 한다.

**남는 것:** 저작 화면이 그 목록에서 **고르게** 하는 것이 옳은 방향이다. 이월에 적었다.

### 3.3 못 이은 링크를 화면이 미리 말한다 (D3.4)

판정 규칙은 한 문장이고 `exportBundle`의 것과 같다 — **그 타겟을 든 페이지가 정확히
하나여야 링크가 생긴다.** 갈래가 둘이다:

| `reason` | 뜻 |
|---|---|
| `missing` | 그 타겟을 든 페이지가 번들에 없다 |
| `ambiguous` | 둘 이상이다 — **둘 다 링크를 잃는다** |

**빈 타겟은 세지 않는다.** 그것은 *"아직 안 골랐다"*이고 `schema`의 `checkPageAction`이 이미
저작 화면에서 말한다.

**파일 경로가 아니라 페이지 제목으로 말한다.** `errors[].path`는 번들 안의 파일 이름이고
`index.html`이 담는 첫 페이지의 오류에도 `pages/….html`이 붙는데(P8-3 이월 §1), 아직 압축을
풀지도 않은 사람에게 파일 이름은 아무것도 짚어 주지 못한다.

### 3.4 겹치는 타겟 (사실 3)

조립 규칙이 그 상태를 만들 수 있는 갈래가 둘이고, **둘 다 케이스가 든다:**

- 같은 메뉴 아래 같은 제목
- 제목에 든 `/`가 하위 메뉴 경로와 부딪히는 것 (`관리자/[회원/목록]` vs `관리자/회원/[목록]`)

**경로 구분자를 이스케이프하지 않았다.** P5-2 재라 #1이 타겟 형식을 강제하지 않기로
판정했고, 저작 화면은 이 문자열을 손으로 적는다 — 사람이 적을 수 없는 문자열을 만들면 그
자리에서 링크가 끊긴다. **대신 겹치면 화면이 말한다.**

## 4. D8 스모크 — **진짜 Chrome을 `file://`로 띄웠다**

### 4.1 어떻게 쟀나

**MCP 브라우저 둘 다 `file:` 프로토콜을 막는다**(claude-in-chrome은 *"Can't interact with
browser-internal or unparseable URLs"*, playwright는 *"Access to file: protocol is
blocked"*). 그래서 실제 Chrome을 헤드리스로 띄우고 **CDP로 직접 몰았다** — 콘솔·예외·로그를
전부 모으고 DOM에 진짜 클릭을 날렸다. `file://`이 이 산출물의 기본 배포 방식이므로 그 자리를
피해 재면 잰 것이 아니다.

절차: api 기동 → 메뉴 셋·페이지 넷·코멘트 일곱을 넣고 → 웹에서 내려받고 → 압축을 풀고 →
`index.html`을 `file://`로 열었다.

### 4.2 판정 스물 — 전부 통과, 콘솔 오류 0

| 무엇 | 결과 |
|---|---|
| 좌측 트리에 페이지 이름 넷이 뜬다 | ✓ |
| 3분할이 실제로 선다(그리드 컬럼 3) | ✓ |
| 첫 페이지 목업이 보인다 | ✓ |
| 코멘트 탭을 고를 수 있고 **그 페이지의** 코멘트가 보인다 | ✓ |
| 남의 페이지 코멘트는 **실리지도 않았다** | ✓ |
| 상호작용 탭을 고를 수 있고 문장이 실렸다 | ✓ |
| 트리로 옮기면 **제** 목업·**제** 코멘트가 나온다 | ✓ |
| 좌측 트리가 지금 페이지를 표시한다(`aria-current`) | ✓ |
| 버튼을 누르면 목록이 바뀐다(`setProp`) | ✓ |
| 링크를 누르면 그 페이지로 옮긴다(`navigate`) | ✓ |
| 숨기기를 누르면 사라진다(`setVisible`) | ✓ |
| 못 이은 링크를 누르면 **아무 데도 안 가고 말한다** | ✓ |
| 탭이 스크립트 없이 돈다(라디오) | ✓ |
| **콘솔 오류·경고** | **0** |

못 이은 링크를 눌렀을 때 상태줄이 낸 문장:
*"이 번들에 없는 페이지입니다: page:관리자/회원/등록"*

### 4.3 웹에서 내려받는 쪽

브라우저에서 로그인 → 설계서 열기 → `내보내기`를 누르면 요약이 뜬다. 실제로 본 것:

```
페이지 4장을 내보냅니다
[이어지지 않는 링크가 있습니다]
  page:관리자/회원/등록 — 목록에서 가리키는데 그 경로의 페이지가 없습니다
페이지 경로
  대시보드 — page:관리자/대시보드
  목록 — page:관리자/회원/목록
  상세 — page:관리자/회원/상세
  랜딩 — page:마케팅/랜딩
[wirebound-export-smoke-….zip 내려받기]
```

내려받기 링크의 `href`는 `/api/projects/<id>/export`, `download`는 서버가 준 이름
그대로다. **콘솔 오류 0.**

### 4.4 **스모크가 낸 발견 하나 — 좌측 트리에서 두 줄이 똑같았다**

**이것이 이 슬라이스에서 가장 값진 발견이다.**

번들의 좌측 트리가 페이지 **제목만** 들고 있었다. 서로 다른 메뉴에 같은 제목이 있으면:

| 잰 것(조상을 안 붙였을 때) | 값 |
|---|---|
| 좌측 트리 | `['목록', '목록']` — **구분할 수 없다** |
| 파일 이름 | `목록.html` · `목록-2.html` (자리 순서 접미사) |
| `<title>` | 둘 다 `목록` |
| 링크 | **멀쩡하다** — 타겟은 갈린다(`page:관리자/회원/목록` vs `page:관리자/권한/목록`) |

**링크가 멀쩡한 것이 이 발견을 조용하게 만든다** — 케이스도 초록이고 상호작용도 돈다.
읽는 사람만 두 줄 중 어느 것이 무엇인지 모른다.

**판정: 조상을 붙인다.** 이것은 **P8-2 이월 §2가 넘긴 판정 ②**(*"`<title>`·트리 이름·파일
이름이 같은 문자열이어야 하는가"*)에 **그렇다**로 답하는 것이다.

| 붙인 뒤 | 값 |
|---|---|
| 좌측 트리 | `관리자 회원 목록` · `관리자 권한 목록` |
| 파일 이름 | `관리자-회원-목록.html` · `관리자-권한-목록.html` — **§11.3의 예시와 같은 꼴** |
| `<title>` | `관리자 회원 목록` |

**`exportBundle`의 계약은 안 바꿨다.** api가 `BundlePage.title`에 조립한 문자열을 넘기는
것으로 끝난다.

**마디를 만드는 자리는 하나다(세어 확인했다).** `pathSegments` 하나를 `pageTarget`과
`pageBundleTitle`이 나눠 쓴다 — 그 파일 안에 **3건**(정의 1 + 호출 2), 그 파일 **밖에는
0건**이다. 경로를 만드는 자리가 둘이면 링크가 가리키는 것과 화면에 보이는 것이 갈린다.

**잇는 글자가 다르다:** 타겟은 `/`, 이름은 **공백**이다. 이름에 `/`를 쓰면 `pageFileNames`가
그것을 `-`로 접어 **화면과 파일이 다르게 읽힌다.** 공백이면 파일에서만 `-`가 된다.

**남는 것:** 트리는 여전히 **긴 이름의 평평한 목록**이지 계층이 아니다. §5와 이월에 갈라
적었다.

## 5. D2 — zip. 압축률을 재서 P8-2 이월 §4의 물음을 닫는다

### 5.1 `fflate`를 고른 근거

| 재고 본 것 | 런타임 의존 | 성질 |
|---|---|---|
| **`fflate`** | **0개** | MIT · 순수 JS(Node·브라우저) · 스트리밍 API도 있다 |
| `yazl` | `buffer-crc32` | Node 전용 |
| `jszip` | `lie`·`pako`·`setimmediate`·`readable-stream` | — |

**의존이 0인 것이 갈랐다.** 재라 #7의 표면 자체가 작아지고, P9의 CLI가 같은 번들을 파일로
쓸 때 같은 것을 쓸 수 있다.

**스트리밍은 오늘 안 쓴다.** `exportBundle`이 이미 파일 전부를 메모리의 문자열로 만들어
내므로 여기서만 흘려보내 봐야 최고 사용량이 안 줄어든다.

### 5.2 압축률 — **잘 먹는다. 페이지가 늘수록 더 먹는다**

| 페이지 수 | 푼 원본 | zip | 압축률 | 배수 | 응답 시간 |
|---|---|---|---|---|---|
| 4 | 56,823 B | 17,003 B | 29.9% | 3.34배 | — |
| 40 | 448,672 B | 76,555 B | 17.1% | 5.86배 | 67ms |
| 120 | 2,731,452 B | 271,865 B | 10.0% | 10.05배 | 170ms |

**페이지가 늘수록 압축이 더 먹는다.** D2의 대가(*"번들 전체가 페이지 수의 제곱"* — P8-2
이월 §4)를 만드는 것이 **페이지마다 반복되는 좌측 트리 마크업**인데, 그것이 정확히 DEFLATE가
물어뜯는 살이다.

**그래서 P8-2 이월 §4의 물음이 닫힌다.** *"트리를 조각으로 뺄 것인가 zip으로 충분한가"* →
**zip으로 충분하다.** 페이지 120장의 설계서가 **265KiB**로 오간다. 트리를 조각으로 빼면
스크립트 없이 트리가 안 보이게 되는데(그쪽 길 1의 대가), 그 대가를 치를 이유가 없다.

**자산은 페이지 수와 무관하다**(사실 9를 재서 확인했다): `shell.css` 5,269B ·
`theme.css` 16,963B · `runtime.js` 8,392B — 4장·40장·120장에서 **같은 값**이었다.

### 5.3 zip을 재다 알게 된 것 둘

**① UTF-8 이름 플래그는 엔트리마다 선다.** 앞 판의 케이스는 **첫 엔트리 하나**의 플래그를
봤는데 그것이 `index.html`(ASCII)이라 플래그가 0이었다. `fflate`는 이름에 ASCII 밖 글자가
있을 때만 세운다(규격대로다). **중앙 디렉터리를 읽어 엔트리마다 잰다** — 로컬 헤더를 앞에서
훑으면 압축된 본문 안의 우연한 서명이 가짜 엔트리를 만든다.

**② 잘게 쪼갠 파일 여럿으로 재면 압축본이 원본보다 커진다.** 엔트리마다의 머리말이 이긴다
(첫 시도에서 원본 6,270B → zip 11,512B였다). 압축이 이기는 것은 **페이지마다 트리 전부가
실리는 실제 번들의 모양**에서다 — 케이스의 픽스처를 그 모양으로 바꿨다.

### 5.4 **받는 쪽에서 잰 것 — macOS의 `unzip` CLI가 한글 이름을 깨뜨린다**

zip 자체는 옳다. 그런데 **받는 도구에 따라 갈린다:**

| 푸는 도구 | 결과 |
|---|---|
| Finder / `ditto -x -k` | **한글 이름이 그대로 산다** |
| Python `zipfile` | **산다** (플래그를 읽어 UTF-8로 푼다) |
| macOS 기본 `unzip` (Info-ZIP 6.00, 2009) | **깨진다** — `pages/?????٦????.html`, *"write error"*로 멈춘다 |

**우리 쪽 결함이 아니다** — 그 `unzip`이 general purpose bit flag의 11번 비트를 안 본다
(`-O UTF-8`도 Apple 빌드에서는 안 받는다). 다만 **터미널에서 푸는 사람이 실제로 만나는
상태**이므로 적어 둔다. 이름을 ASCII로 바꾸는 길은 안 골랐다 — §11.3의 예시가 한글이고
P8-2가 *"한글 유지"*를 재서 정했다(보고서 §3.2).

## 7. D6 — 내려받기 버튼이 조용히 성공하지 않는다

누르면 **먼저 무엇이 실릴지**를 보이고 내려받기는 그 다음이다. 화면이 말하는 것 넷:

| 무엇 | 언제 |
|---|---|
| 실릴 페이지 수 | 늘 |
| 그리지 못한 노드 — **페이지 이름으로** | `errors`가 있을 때 |
| 겹친 페이지 경로 | `duplicateTargets`가 있을 때 |
| 이어지지 않는 링크 — **갈래마다 다른 문장** | `brokenLinks`가 있을 때 |
| 페이지마다의 §8.1 경로 | 늘 (§3.2의 자리) |

**경고가 내려받기 링크보다 위에 있다.** 아래 두면 사람이 누르고 나서 본다.

**열 때 미리 부르지 않는다.** `getExportPreview`는 번들을 **실제로 만들어 본다**(프로젝트의
모든 페이지를 서버에서 그린다). 셸이 뜰 때마다 부르면 설계서를 여는 비용이 그만큼 는다.
**닫았다 다시 열면 다시 조회한다** — 이 화면이 말하는 것은 전부 *"지금 내보내면 무엇이
나오는가"*이고 낡은 답을 보이면 D6이 뒤집힌다.

### 7.1 **사실 5의 *"런타임이 꺼진 페이지"*는 말하지 않는다 — 판정이다**

한 노드를 여러 규칙이 서로 다른 prop으로 겨누면 미리 그릴 판이 곱으로 늘고, 상한을 넘으면
그 페이지의 런타임이 꺼진다(P8-3 이월 §9). 그 사실이 `exportBundle`의 `errors`에 안 담긴다.

**여기서 다시 세지 않는다.** 세려면 **그 상한을 두 벌로 갖게 되고**, 둘이 갈리는 날 화면이
거짓을 말한다. P8-3이 *"번들 자신이 말한다"*로 닫은 그대로 둔다(그 페이지의 상태 줄에 이유가
뜬다). **`errors`에 담을지는 `packages/exporter`를 고치는 사람의 자리다** — 이월에 적었다.

### 7.2 사실 6의 *"미리 그린 판에서만 난 렌더 오류"* — **이번에도 못 봤다**

P8-3 이월 §7이 *"오늘 그 경로로 값이 나오는 것을 본 적이 없다 — 나면 그것이 발견이다"*라고
적었다. **이 슬라이스에서도 0건이다.** 스모크의 네 페이지와 규모 시험의 120페이지 전부
`errors: []`였다. **발견이 아니라 여전히 안 보이는 것**이고, 그대로 열어 둔다.

## 8. 새 런타임 의존 — `apps/web`에 0, `apps/api`에 하나

`apps/web`이 쓴 것은 `<button>`·`<a download>`·`useState`뿐이다.

**`fetch` + blob으로 받지 않은 이유 둘:**

1. **번들 전체가 페이지 수의 제곱이다**(P8-2 이월 §4). 다 받아 메모리에 드는 것이 그대로
   비용이 된다 — 위 §5.2의 120장이 푼 상태로 2.6MiB다.
2. **`URL.createObjectURL`이 이 저장소의 테스트 환경(jsdom)에 없다** — 그 경로는 케이스가
   닿지 못한다.

앵커는 브라우저가 곧장 디스크로 흘려보내고 세션 쿠키(`httpOnly`)도 그대로 실린다.

**`exportUrl`이 `ApiClient`에 있는 이유:** 주소를 아는 자리가 하나여야 한다. 요청을 보내지
않으므로 `http-client.test.ts`의 경로 표에 들 수 없는데, **예외로 빼기만 하면 그 메서드는
아무것도 안 지킨다** — 그 주소를 따로 못박는 케이스를 뒀다(변이 M29가 그것을 확인했다).

### 9.2 살아남은 둘의 **진단** — 원인이 하나다

> **케이스가 재는 값이 변이가 바꾼 값과 *다른 자리*에서 나왔다.**

**M8(모든 페이지가 첫 페이지의 타겟을 든다).** 미리보기의 `brokenLinks`·`pages`는
`targetedPages`가 낸 값으로 세는데, **번들의 링크는 `exportBundle`에 넘긴
`BundlePage.target`으로 만들어진다.** 둘이 다른 값에서 나오므로 갈릴 수 있고, 실제로
변이를 심으니 **미리보기는 멀쩡한데 번들의 링크가 전부 죽어 있었다.** 아무 케이스도 그것을
안 보고 있었다.

**M14(테마를 안 싣는다).** 케이스가 `assets/theme.css`의 **길이가 0이 아닌 것**과
`themeId`가 `null`이 아닌 것을 봤다. 그런데 그 시트에는 **구조 기본 CSS**가 늘 들어 있어
테마가 없어도 길이가 0이 아니고, `themeId`는 또 다른 자리(`currentProjectTheme`)에서 온다.
**변이가 바꾼 것은 셋째 값(`exportBundle`에 넘기는 `theme`)이었다.**

## 10. 그 밖에 잰 것

### 10.1 `theme-boundaries.test.ts`의 한 케이스가 **혼자 돌리면 실패한다**

`재라 #11 — 깊이 1000도 500이 아니다`가 그 파일만 돌리면 500을 받아 실패하고, `pnpm test`
전량에서는 통과한다. **이 슬라이스의 변경 전(HEAD)에서도 같다** — 내 변경을 되돌려 놓고
재서 확인했다. 깊이 1000 재귀라 실행 맥락에 따라 스택이 갈리는 부류로 보이지만 **원인을
단정하지 않는다.** 게이트는 전량으로 도므로 오늘 막는 것은 없다. 이월에 적었다.

### 10.2 문서 순서와 화면 순서

번들의 좌측 트리 순서는 `apps/web`의 좌측 트리와 같다 — 형제는 `sortOrder`, 한 메뉴 안에서는
**그 메뉴의 페이지가 먼저이고 하위 메뉴가 뒤다**(`panels/menu-tree.tsx`가 그렇게 그린다).
§11.3의 *"웹 앱과 동일하다"*가 그 축에서 참이 되도록 맞췄고 케이스가 든다.

### 10.3 `buildMenuTree`가 페이지를 잃으면 멈춘다

그 함수는 고아 노드와 순환에 갇힌 노드를 **조용히 버린다**(제 머리말이 그렇게 적혀 있다).
버려진 페이지는 번들에서 말없이 빠진다. FK가 그 상태를 막고 있어 오늘 이 갈래는 닿지
않지만, 닿으면 사람이 봐야 한다 — 트리로 편 페이지 수가 `listPages`의 수와 다르면 던진다.
**조용히 빠지는 것이 이 산출물에서 가장 나쁜 실패다.**
