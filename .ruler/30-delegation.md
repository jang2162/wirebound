# 워커에게 맡길 때 — wirebound

공용 「메인 세션은 디스패치·판정·병합만 한다」(`base` 스택 `02-delegation.md`)와 「워커에게 브리프를 보낼 때」(`docs/guideline/base/09-worker-brief.md`) 위에 wirebound 가 더하는 것이다. 역할 분리 규칙은 그 둘과 여기에만 둔다 — 계획서·이월 문서는 사본을 두지 말고 이 자리를 가리킨다.

- **wirebound 에서 메인 세션 몫:** 워크트리 생성과 부트스트랩(「생성 직후 세팅」), 최상위 문서(`.ruler/*`·`docs/superpowers/plans/*`) 갱신.
- **워커 몫:** 구현, 리뷰, `pnpm test`·`pnpm typecheck` 실행, 수정의 구분력 실증, api 스모크.
- 리뷰어에게는 **무엇을 어떻게 확인할지 지목**한다 — 넓게 «봐 달라»고 하면 넓은 표면에 묻힌다.

**예외는 메인 세션만 조작할 수 있는 공유 자원이다** — 사용자가 켜 둔 IntelliJ·dev 서버와 **사용자의 데이터가 든 컨테이너·볼륨**이 그것이다(설계서가 사는 볼륨은 워커가 읽지도 쓰지도 않는다). **워크트리 자기 컨테이너는 그 예외가 아니다** — 워커가 자기 디렉터리에서 띄우고 끝나면 지운다(`README.md` 「워크트리를 여럿 띄울 때」 절). 이건 준비·조율이지 검증이 아니다. 지금 이 프로젝트의 검증은 전부 터미널로 끝나므로(`pnpm test`, `pnpm typecheck`, api 스모크) 메인 세션이 대신 확인할 이유가 없다. 워커가 쓸 수 없는 수단(예: 사용자 프로필에 붙은 브라우저 확장)이 검증에 필요해지면 그때 여기 적는다. **Docker VM 디스크도 그 공유 자원이다** — 차면 판 세우기가 `No space left on device` 로 죽고(실브라우저 `editor-stack` · api 의 테스트 DB), 떠 있던 워크트리 Postgres 는 재기동 때 WAL redo 에서 `Exited (1)` 로 멈춘다. 워커는 `docker run --rm alpine df -h /` 로 잰 값과 `docker system df` 를 붙여 코디네이터에게 올리고 이미지 · 볼륨을 지우지 않는다(볼륨에 사용자의 설계서가 있다). 그동안 DB 없는 일을 한다. 비운 뒤 `pnpm db up -d` · `pnpm db port postgres 5432` 로 자기 컨테이너를 다시 세운다.

**워커 터미널에 보내는 글은 셸을 거치지 않게 보낸다.** `orca terminal send --text "…"` 를 셸에서 치면 **글 안의 백틱이 명령으로 치환돼 메인 세션의 디렉터리(최상위)에서 돈다.** 글을 파일로 쓰고 `subprocess` 의 인자 배열로 넘긴다. 긴 글은 터미널 입력에서 잘릴 수 있으므로 **브리프 본문은 파일로 두고 «이 파일을 읽어라»만 보낸다.**

**스크립트를 heredoc 으로 넘길 때도 같다 — `<<'EOF'` 로 구분자에 따옴표를 친다.** 따옴표 없는 `<<EOF` 는 본문의 백틱과 `$` 를 치환해 식별자 인용(`` `이름` ``)을 명령으로 돌린다. 값을 넘겨야 하면 본문에 끼우지 말고 인자로 넘긴다.

**병렬 브랜치가 잰 수는 라운드의 수가 아니다.** 각 브랜치는 옆 브랜치가 더한 것을 못 본 기준선에서 잰다 — 한 브랜치의 수를 라운드의 수로 적으면 옆 브랜치의 몫이 빠진다. **뒤에 병합할 브랜치를 앞선 병합 위로 rebase 해 병합한 뒤의 수를 재거나**, 두 브랜치가 겹치지 않으면 **등식으로**(`기준 + 갑 + 을`) 적는다. **합친 판은 수만이 아니라 통과를 다시 잰다** — 한 트랙이 바꾼 동작이 다른 트랙 케이스의 판 만들기(픽스처가 기대는 동작)를 없애면 등식은 맞고 빨강이 난다(«제거가 토큰을 지운다»가 «제거로 비멤버 토큰을 만드는» 케이스를 깼다). 동작을 바꾸는 트랙의 브리프에 «이 동작으로 판을 만드는 다른 트랙의 케이스를 센다(그 라우트 · 함수를 부르는 테스트를 `git grep`)»를 적는다. **합친 판은 충돌이 난 파일과 함께 git 이 조용히 합친 파일도 `pnpm typecheck` 로 먼저 잰다** — 두 트랙이 같은 `describe` 에 같은 이름을 더하면 git 은 합치고 `tsc` 만 «Cannot redeclare» 로 잡는다(`packages/theme-kit/test/check.test.ts` 의 `EMPTY` — `docs/superpowers/plans/2026-10-27-rb-pob-report.md`). **한 트랙이 화면 이름 · 탭 이름 · 절 이름을 바꿨으면 합친 판에서 옛 이름을 `git grep -n -F '<옛 이름>' -- ':!docs/superpowers/plans'` 로 센다** — 다른 트랙이 그 이름을 새로 쓴 자리(설계서 문장 · 실브라우저 케이스의 `getByRole({ name })` · CSS 주석)는 충돌 없이 합쳐지고 타입 검사도 지난다(`docs/superpowers/plans/2026-11-03-mv-report.md` «1»). **충돌 덩이를 «둘 다» 로 풀 때는 이어 붙인 뒤 양쪽의 함수 · 주석 블록이 원본(`git show <쪽>:<파일>`)의 글자 그대로 들었는지 블록마다 견준다** — 덩이 밖 공통 줄(`/**` · 닫는 괄호)은 한쪽 몫만 남는다. **기준선 · 옆 브랜치의 수는 실행 없이 `vitest list --json` 으로 센다** — 그 판을 `git archive` 로 스크래치에 풀고 `node_modules` 를 워크트리 것으로 이은 뒤 그 판에서 `pnpm build`(수집이 `dist` 를 import 한다). api 프로젝트는 `globalSetup` 을 뗀 설정으로 돌려 테스트 DB 에 안 닿게 하고, `build` 프로젝트 · `vitest.browser.config.ts` 는 전제 검사(`editorStackPrerequisite` — `select 1`)가 서도록 `DATABASE_URL` 을 준다(안 주면 실브라우저가 한 파일로 센다). `list` 는 건너뛰는 판을 안 세어 실행 수 − 건너뜀이다(`docs/superpowers/plans/2026-10-24-rb-ci-b-report.md` 「수의 등식」). **출력은 `--json=<스크래치 경로>` 로 준다** — `--json` 뒤에 띄어 둔 첫 테스트 파일 경로를 vitest 가 출력 파일로 받아 그 테스트 파일을 목록 JSON 으로 덮어쓴다. 견줄 판들 사이에 `packages/*` · `system-themes/*` · `pnpm-lock.yaml` · `vitest*.config.ts` 의 `git diff --stat` 이 비면 사본 대신 자기 워크트리를 그 판으로 `git checkout --detach` 해 세고 브랜치로 돌아온다 — `dist` 가 같아 다시 빌드할 것이 없다(세는 동안 소스를 고치지 않는다 · 끝에 `git status` 가 깨끗하고 머리가 브랜치인지 본다).

**항목마다 커밋할 때 한 파일에 여러 항목이 얽히면 덩이를 골라 지은 중간 내용을 인덱스에 직접 올린다** — `git hash-object -w --stdin` · `git update-index --cacheinfo 100644,<sha>,<경로>`(대화형 `git add -p` 는 이 환경에서 못 쓴다). 작업 트리는 마지막 판 그대로 두고, 끝에 `git status` 가 깨끗한지(마지막 커밋 = 작업 트리) 본다.

**보안 경계를 반증하는 브리프는 «우회 기법을 찾아라» 가 아니라 «채널마다 소켓 수를 재라» 로 쓴다** — 우회 탐색으로 쓴 반증 세션은 탐침 설계와 잰 값을 문서로 옮기는 호출까지 안전 분류기에 막혀 멈췄다(`docs/superpowers/plans/2026-09-29-a5-review-2.md`). 막히면 워커는 같은 내용을 다시 시도하지 않는다 — 코디네이터가 터미널의 보고에서 값을 옮기고 남은 것을 계측 브리프로 다시 맡긴다. **입구 × 요청자 표에 더해, 남이 지을 수 있는 입력이 권한 있는 사람의 요청을 부르는 자리를 센다**(클립보드 봉투의 출처 · 주소의 쿼리 · 가져온 파일의 필드) — 그 자리는 요청자가 피해자라 표의 모든 칸이 맞아도 선다(붙여넣기 봉투의 `source.projectId` 가 두 프로젝트에 다 든 사람의 손으로 남의 그림을 옮겼다 — `docs/superpowers/plans/2026-10-24-rv-ci-b-report.md` H1).

**추적 파일 · 디렉터리를 걷는 브리프는 사용자가 칠 한 줄을 함께 적는다** — 자동 모드 분류기가 워커의 `git rm -r` 을(옮긴 뒤 `git add -u` 도) «되돌릴 수 없는 로컬 파괴» 로 막는다. 코디네이터가 디스패치 전에 `git -C <워크트리> rm -r -q <경로…>` 를 사용자에게 받아 두거나, 워커가 막히면 그 한 줄을 물음 파일에 적고 삭제와 무관한 일부터 한다(우회하지 않는다). 파일 하나의 `git rm`(`-r` 없음)도 막힌다. 걷을 목록은 브리프를 쓸 때 다 알 수 없으므로(빈 껍데기가 된 파일은 인구조사에서 나온다) 워커는 찾을 때마다 물음 파일에 한 줄로 모아 적고, 코디네이터는 사용자의 한 줄을 받기 전에 그 묶음이 끝났는지 묻는다. **같은 `git -C <워크트리> rm -q <경로…>` 를 코디네이터(메인 세션)가 치면 통과한다**(2026-10-23 — 워커가 막힌 것과 같은 꼴의 한 줄이 메인 세션에서는 돌았다). 사용자에게 받기 전에 코디네이터가 먼저 쳐 보고, 막히면 그때 사용자에게 넘긴다 — 지우는 대상이 그 워크트리의 추적 파일뿐인지(`git -C <워크트리> ls-files <경로>`) 먼저 본다.

**브리프의 «고쳐라»도 재현이 먼저다.** 리뷰가 코드로만 짚은 틈을 브리프가 «고쳐라»로 넘겨도, 워커는 먼저 재현하고 **재현이 안 되면 고치지 않고 원인과 함께 보고한다** — 재현 없이 고친 것은 무엇을 고쳤는지 아무도 모른다. 원래 성질을 잠그는 케이스는 세워도 된다(고치기 전에도 초록임을 적는다). 브리프에 이 기본값을 적어 두면 워커가 «고쳐라»와 «재현 먼저» 사이에서 멈추지 않는다. **브리프가 고칠 방향을 문장으로 주면, 그 문장 그대로 짠 판을 변조로 한 번 돌려 무엇이 죽는지 적게 한다** — 문구는 코디네이터가 코드를 안 읽고 쓴 요약이라, 그대로 짜면 기존 잠금을 죽이거나(«화면도 서버 판과 같아야»가 «보내지 않은 편집이 있어도 같은 판»을 죽였다) 한 판을 못 닫는다(«페이지 id 로 가름»이 떠났다 돌아온 판을 못 닫았다). 워커가 문구를 고쳐 보고하는 것을 재량에 맡기지 않는다. **고칠 방향이 기존 함수의 동작을 결과로 기대면(«그러면 X 가 …»), 브리프를 쓸 때 X 의 조건을 코드에서 한 줄 확인한다** — 창 얹기는 같은 페이지일 때만 돌아 «여는 id 를 적으면 얹힌다»가 그대로는 아무것도 얹지 않았다. **«라우트를 나누면 화면이 새로 선다» 에 기대는 방향은 그 라우트들의 element 최상위 꼴을 센다** — 같은 부품(틀 · 레이아웃)을 감싼 라우트 사이를 옮기면 React 가 재조정으로 그 부품의 상태를 이어 간다(관리자 칸 넷이 함께 쓰는 `apps/web/src/admin/admin-screen.tsx`). 화면마다 접혀야 하는 상태는 그 부품이 주소를 보고 거둔다(`apps/web/src/shell/workspace-layout.tsx` 의 `pathname`). **고칠 방향이 편집 묶음의 전제(`test`)면 리베이스가 그 경로를 어떻게 다시 짓는지 먼저 본다** — `apps/web/src/store/anchored-ops.ts` «자리의 셋» 은 노드를 가리키는 경로를 노드 id 로 다시 지어, 노드 id 를 견주는 `test` 는 늘 맞고 «이 목록의 id 차례» 는 목록을 든 부모 값 통째로만 묶인다(`docs/superpowers/plans/2026-10-26-fx-grb-report.md` «M3»). **브리프 · 계획이 화면의 입구(메뉴 · 단축키 · 팔레트)를 이름으로 적으면, 쓰기 전에 그 표면이 에디터에 있는지 `git grep` 으로 한 번 센다** — 없는 입구(«Cmd+K» · 캔버스 맥락 메뉴)를 적은 계획은 워커가 표면부터 새로 짓거나 빼야 하는 판단을 떠안는다. **세션 전용 라우트(`/api/admin` · `/api/auth` 아래)의 경로 파라미터를 `:projectId` 로 짓지 않는다** — 인증 훅은 그 이름의 파라미터를 가진 라우트에서 API 토큰을 받는다(`apps/api/src/auth/plugin.ts` 머리말 표). 계획 · 계약 표가 `:projectId` 로 적었어도 다른 이름(`:id`)으로 짓고(HTTP 경로는 같다), 그 토큰으로 401 인 케이스를 둔다(`apps/api/test/admin-projects.test.ts` «owner 넘기기는 세션 전용이다»). **놓을 자리의 규칙(받는 타입 · 설 자리 · 구역)을 재는 판은 부모를 바꾸는 입구를 `apps/web/src/edit/editor-shortcuts.ts` 의 `edits: true` 명령까지 센다** — 끌기 · 넣기 · 붙이기 · 모듈 넣기 밖에 들여쓰기 · 내어쓰기(Alt+Shift+← → · 도구모음 · 줄 행동)가 부모를 바꾼다. 그 입구가 `accepts` 를 안 보아 422 되싣기가 뒤에 줄 선 정상 편집까지 버렸다(`docs/superpowers/plans/2026-10-23-rv-ze-report.md` H1). **우측 탭에 저장 단추로 보내는 글 상자를 새로 세우는 브리프는 초안을 `PanelDraftsProvider` 에 들게 적고, 탭 왕복 · 모드 왕복 · 남이 그 대상을 지움 · 남이 같은 칸을 씀 넷을 실브라우저 판으로 재게 한다** — 상태 설명 상자가 초안을 `useState` 로 들고 상태 id 만 `test` 해 넷을 다 잃었다(`docs/superpowers/plans/2026-10-22-rv-pi-report.md` H1 – H3 · `panels/page-description.tsx` 머리말 «탭·모드를 오가도 초안이 남는다»). **브리프 · 계획이 prop 을 SDK 표지(`marks.ts`)로 적으면 그 prop 의 꼴을 본다** — 표지는 불리언 · enum 만이다(`packages/renderer/test/prop-marks.test.tsx` 의 규칙). 수 prop 의 «정했다» 는 조각 속성 · 변수로 가른다(`SearchForm.columns` 의 `searchFormFieldsAttrs`). **편집 모드의 «컴포넌트» 탭(처음 고른 탭)에 조회를 더하는 브리프는 «페이지를 열면 루트가 골라진다 — 그 조회가 모든 jsdom 에디터 케이스에서 돈다» 를 적는다** — `apps/web/test/helpers.tsx` 의 `fakeApi` 가 그 메서드를 `notStubbed` 로 던지면 alert · 통지를 세는 케이스가 한꺼번에 죽는다(코멘트 묶음을 더하자 88 건). 그 메서드의 기본값(빈 목록 등)을 둘지 정하게 한다(`listComments` 는 빈 목록이 기본이다). **역할을 보이는 화면을 브리프 · 설계안에 적으면 `apps/web/test/role-access.test.ts` 의 경로 표를 먼저 센다** — `.role` 읽기는 `projectAbilities(…)` 인자 자리만 허락되고 경로가 고정이라, 표시용 읽기도 가드의 규칙을 넓히는 결정이 된다. **고칠 방향이 트랙 경계를 넘는지도 센다** — 한쪽만 병합되면 전부 죽는 변경(웹이 새 op 을 보내는데 서버가 400)은 한 브랜치에서 원자적으로 넣고 트랙을 나눠 맡기지 않는다. **주소 · 연결로 가르는 고침은 모두가 한 주소인 판(같은 NAT · 앞단 뒤 설정 없음)에서 무엇이 되는지 센다** — «같은 주소에서 온 실패만 지운다»는 그 판에서 «전부 지운다»로 돌아가 막으려던 신호(계정 유무)가 그대로 섰다. **«X 를 안 지운다»는 두 판으로 읽힌다** — 제 몫까지 남기면 그 동작이 스스로 한 자리를 먹어 다른 신호를 연다. **상태를 지우는 동작이 «당사자에게만 보인다»고 적었으면 그 지움이 남의 다음 답(코드 · 남은 횟수)을 바꾸는지로 잰다** — 로그인 성공이 실패 기록을 지우자 한도 − 1 을 채워 둔 쪽이 뒤 두 번의 답으로 «주인이 로그인했다 = 있는 계정»을 읽었다(`apps/api/test/login-limit.test.ts` «성공은 남의 다음 답을 안 바꾼다»). **전송 형식 · 비용을 줄이라는 브리프는 먼저 그 값을 읽는 소비자를 세고, 비용이 어디서 나는지 한 번 갈라 잰다** — presence 명단은 읽는 자가 0 이었고 시간의 대부분은 바이트가 아니라 연결마다 재확인이었다. **비용을 재는 벤치는 입력의 축마다 한 값 이상을 둔다** — 잠금 판정 벤치가 남의 잠금을 하나만 두어 1.5–3ms 를 적었는데, 같은 하트비트가 남의 잠금 201 · 801 개에서 0.55s · 4.2s(동기 — 이벤트 루프와 페이지 행을 쥠)였다. 판정이 대상 × 남의 것을 도는 함수면 둘 다 늘린 판을 세운다(`apps/api/test/ws-lock-cost.test.ts`). **기록을 안 남기는 동작도 자료 구조의 차례(`Map` 에 넣은 차례 · LRU)를 바꾸면 남의 다음 답에 보인다** — 주인의 성공이 제 자리를 걷어도 그 키를 맨 뒤로 옮겨, 채우기 뒤에 그 키가 남는지로 «주인이 로그인했다»가 섰다. **지키는 조건을 문턱(«막힌 것은 안 버린다»)으로 세우면 문턱 바로 밑이 같은 값에 뚫린다** — 한도 − 1 까지 찬 키가 같은 채우기에 씻겼다. 기록 수의 순서로 세운다(`apps/api/src/auth/login-limit.ts` 의 `evictOne`). **끄는 장치는 입력이 그 장치를 이길 수 있는지부터 센다** — `*{transition:none!important}` 는 `!important` 를 실은 테마 값(더 구체적인 셀렉터)에 졌다. 입력이 `!important` 를 실을 수 있으면 끄기를 `@layer` 안에 둔다. **그 장치는 입력이 이길 수 있는 꼴(층 밖 `!important` · 층 안 `!important` · 더 구체적인 셀렉터)을 픽스처로 실은 케이스로 잠근다** — `!important` 가 없는 픽스처만 쓰면 층을 뗀 변조가 산다(`apps/web/build-test/theme-review.test.ts` «층 밖 !important …»). **오류 코드로 판을 가르는 문구는 OS 마다 잰다** — 소켓이 아닌 자리에 connect 하면 macOS 는 `ENOTSOCK`, Linux 는 `ECONNREFUSED` 다. 종류는 `lstat` 으로 먼저 가른다. **«못 쟀다» 를 뜻하는 센티널은 잰 값이 될 수 있는 수를 쓰지 않는다** — `measureRoom` 이 잰 값 0 이하를 0 으로 돌려줘 «못 쟀다»(창 높이 셈 갈래)로 읽혔고 판이 바닥까지 안 내려갔다(`apps/web/src/shell/sidebar-layout.ts`). 센티널을 쓰는 인자는 잰 값이 그 수에 닿는 갈래를 센다. **고치기 전 값이 필요한데 케이스가 이미 고친 소스에 맞춰 있으면 고침을 변조로 되돌려 같은 케이스를 돌린다** — 되돌림도 변조라 백업 · 바이트 비교로 복원한다(N18 이 M10 + M11 로 고치기 전 값을 얻었다). 그 케이스가 생성물(스냅숏 파일)과 견주면 생성물의 바뀐 줄도 같은 변조에서 고치기 전으로 되돌린다 — 고친 생성물을 둔 판은 무엇을 바꿔도 스냅숏 차이로 죽는다. 고치기 전 소스는 `HEAD` 가 아니라 트랙의 기준 커밋(`git merge-base main HEAD`)에서 꺼낸다 — 고침을 커밋한 뒤의 `git show HEAD:<파일>` 은 고친 판이라 고치기 전 판이 초록으로 나온다. 갈아 낀 파일에 고침의 표지(새 함수 이름)가 없는지 `grep -c` 로 한 번 센다. **리뷰가 «머리말 · 정본과 코드가 다르다» 로 짚은 항목은 정한 방향이 어느 쪽과 맞는지 먼저 가른다** — 방향이 코드 쪽이면 고침은 머리말 · 정본 문장이고, 케이스는 그 동작을 잠그되 «고치기 전 빨강» 이 없다고 보고에 적는다(`docs/superpowers/plans/2026-11-17-fx-vs-report.md` «결정» 1).

**브리프가 닫는 길을 예로 들면 그 길이 닿는 호출자부터 센다.** 재생 · 재전송 · 재시도에 기대는 길은 실제로 다시 보내는 쪽이 있을 때만 닫힌다 — «ops 재전송 때 재방송»은 다시 보내는 호출자가 0 이었다(웹도 MCP 도 안 보낸다). 케이스가 스스로 다시 보내면 호출자가 0 이어도 초록이다.

**막는 장치를 더하라는 브리프도 그 쓰기가 권한을 늘리는지 줄이는지 먼저 본다** — 권한을 줄이는 쓰기(자기 자격의 폐기 · 로그아웃)에 재확인을 걸면, 권한을 잃은 직후의 폐기가 롤백돼 거두려던 자격이 남는다. 그 쓰기 앞의 잃음은 막지도 묻지도 말고 **한도 있는 기다림**으로 줄인다 — 로그아웃은 보낸 편집의 답을 3s 까지 기다린 뒤 나간다(한도 뒤엔 그대로 나간다). **경보를 거두는 장치는 그 경보가 무엇을 가리키는지부터 센다** — 경보의 단추가 다시 읽는 것 전부(`routes/editor.tsx` 의 `restoredToken` 표)가 거두는 조건 안에 들어야 한다. 한 자원(페이지 번호)이 새것이라는 것으로 여러 자원의 경보를 거두면, 거짓 경보 하나를 지우고 나머지 자원의 조용한 낡음을 연다. 거두는 조건에 다시 읽기의 **시작 시점**을 넣는다 — 다시 읽는 자리 여럿이 서로 다른 때 시작하면(메뉴는 곧바로 · 페이지는 보낸 편집의 답 뒤) 가장 먼저 시작한 조회 뒤에 온 신호가 그 경보를 다시 세운다(`EditorStore.beginRestoreReread`). **답을 잃은 쓰기에 세운 경보는 그 쓰기가 사람의 다시 읽기보다 늦게 커밋되는 판을 센다** — 답을 잃었다는 것은 서버가 아직 처리 중일 수 있다는 뜻이라, 다시 읽어 경보가 걷힌 뒤 커밋되면 제 연결을 빼는 방송이 신호를 안 보내 조용히 낡는다. 요청을 붙잡아 끊고 같은 쿠키 · 같은 연결 id 로 나중에 다시 보내 잰다. 닫는 길은 방송에서 제 연결을 빼지 않고 받은 쪽이 알아보는 것이다 — **넘기는(경보를 안 세우는) 판정은 서버가 지은 값(안전망 스냅샷 id)으로만 한다.** 요청에 실어 방송이 되비치는 클라이언트 id 는 룸의 모두에게 보여 흉내 낼 수 있어, 답 전 신호를 미루는 데와 답 잃은 쓰기의 신호를 알아보는 데만 쓴다. **늦게 커밋되는 쓰기는 번호 프레임을 늦게 내지 않고 번호 프레임이 아닌 신호(`page-stale` — 번호는 비교 힌트로만 싣고 얹지 않는다)로 알린다** — 받는 쪽이 얹을 것이 없어 이음이 안 오염된다. 그 신호가 가리키는 자원 하나만 다시 읽는 단추로 푼다(복원처럼 여럿을 바꾸는 쓰기에 쓰면 단추가 거짓이 된다). **늦은 커밋의 신호를 내는 자리를 새로 세우면 «한도 안에 커밋이 확인됐는데 번호를 모르는» 갈래(`confirm` 이 `null`)도 센다** — 지켜보기만 세우면 그 갈래는 커밋됐는데 아무 신호도 없다(게시 «모름» 503 이 그랬다). 두 갈래가 같은 `onCommit` 을 부르게 한다(`apps/api/src/services/lost-commit.ts` 의 `runConfirmedTransaction`). **여러 자원을 함께 바꾸는 쓰기(복원)의 커밋 뒤 알림은 함수 하나로 두고 제때 · 늦은 길이 그것을 부른다** — 자원 하나짜리 신호(`page-stale`)로 대신하면 단추가 거짓이 되고, 두 벌로 두면 한 자원이 빠진 채 조용히 낡는다(`apps/api/src/routes/snapshots.ts` 의 `announceRestore`). **«없음»과 «모름»을 한 `null` 로 내는 확인은 둘을 가른다** — 문서를 안 바꾼 쓰기의 답 잃음이 «번호를 모른다»와 같은 신호를 내 거짓 경보를 세웠다. 거르는 자리는 응답 자리와 지켜보기가 함께 부르는 한 곳에 둔다(`apps/api/src/services/lost-commit.ts` 의 `NO_REVISION`). **번호 힌트를 싣는 신호는 받는 쪽 `headSeq` 가 오르는 자리를 전부 세고**(연속 번호 · 서버 판 통째 읽기뿐인지) **경보를 안 세워도 신호의 시점은 적는다.** **답을 기다리는 목록과 그 답을 받는 콜백이 서로 다른 것의 수명에 매이면 둘을 함께 끊는다** — 목록은 스토어에, 콜백은 셸에 매이면 셸이 내려갔다 다시 선 판(스토어를 다시 쓰는 라우트 안의 전환 · 뒤로 · 앞으로)에서 죽은 셸의 답이 산 스토어에 «내 것»을 적고 다시 읽기는 죽은 셸에서 돈다. 목록을 비우는 자리(`reset`)만 두면 id 를 안 보는 쓰기가 남는다 — 콜백을 세대로 거른다(`routes/editor.tsx` 의 `shellGeneration`). **답을 기다리며 미뤄 두는 장치에는 한도를 둔다** — 쓰기의 답에는 시간 한도가 없어 미룬 것이 끝없이 조용할 수 있다(`EditorStore` 의 `RESTORE_SIGNAL_WAIT_MS`). **경보 문장이 누가 했는지를 말하면 그것도 같은 잣대다** — 알아보는 목록 밖의 내 것(셸이 다시 섬 · 미룬 신호의 한도가 지남 · 같은 사람의 다른 탭)과 흉내 낸 id 는 남의 것과 같은 신호라, «다른 사람이 복원했습니다»가 그 판들에서 반만 맞았다. 가를 값(서버가 지은 id)이 없으면 누가 했는지 말하지 않는 문장을 쓴다(`shell/remote-alert.tsx` 의 `NOTICE`).

**«전체가 죽는다»는 «이 케이스가 죽는다»가 아니다.** 새 케이스를 여럿 세웠으면 **각각이 혼자 죽는 변조가 있는지**까지 확인하게 한다. 한 케이스가 **다른 케이스의 단언을 글자 그대로 복사**하고 있으면 어느 변조에서도 혼자 죽지 않는다 — 재는 척만 하고 아무것도 안 잠근다. *"규칙은 적혀 있는데 재는 것이 없다"* 의 뒤집힌 꼴이다. **변조가 케이스를 죽였으면 무엇으로 죽었는지 실패 값을 본다** — 질의 글자로 요청을 세우는 케이스(`holdQuery`)는 그 글자를 바꾸는 변조(`ORDER BY` 뗌)에 판이 안 서서 타임아웃으로 죽는다. 그것은 구분력이 아니다. 단언이 재는 값(교착 차 · 상태 코드)으로 죽은 것만 센다. **시간 상한을 단언하는 케이스는 느린 판이 뒤 단계를 끝없이 늦추기 전에 단언한다** — 하트비트 판정 시간과 그 뒤의 편집 지연을 끝에서 함께 단언하자 고치기 전 판정에서 편집 단계가 이벤트 루프에 갇혀 케이스가 값 없이 시간 초과로 죽었다. 단계마다 그 단계의 값을 그 자리에서 단언한다. **퇴행을 재는 케이스는 옛 증상 문장이 아니라 성질(화면 = 서버 · 서버 값)로 단언한다** — 고친 뒤 코드에서 고침만 떼면 옛 문장이 아니라 그 사이 더한 장치의 문장이 선다(배너 겨룸: 기다림을 떼자 «취소»가 아니라 «모름»이 서고 화면 ≠ 서버였다). 그 조각은 **매개변수 값에서도 걸린다** — 케이스가 싣는 값(노드 id · 본문)에 조각이 들면 재려던 질의가 아니라 그 값을 실은 질의에서 쏜다(`apps/api/test/pg-fault-proxy.ts` 머리말). 조각이 든 값을 싣지 않는다. **화면 문안을 바꾸면 옛 문안을 단언한 자리를 문장 전체와 그 조각으로 함께 센다** — 부재 단언(`queryByText(옛 문안)).toBeNull()`)은 안 고치면 늘 초록이고, 짧은 조각(`toContain('스냅샷을 복원')`)은 문장 전체로 센 `git grep` 에 안 걸린다. 그 셈은 이력 문서를 뺀다(`git grep -l -F '<문안>' -- ':!docs'`) — 설계 · 보고는 옛 문안을 인용한 채 고치지 않으므로 함께 세면 고칠 자리가 실제보다 많게 나오고, 그 셈을 적은 문서를 커밋하면 수가 또 는다(`docs/superpowers/plans/2026-10-26-po-report.md` 「지침」). 카나리아가 **변조가 바꾸는 판의 모양**(바닥에 닿은 칸 · 스크롤 유무)에 기대면 그 모양을 바꾸는 변조에서 카나리아가 먼저 죽는다 — 단언을 판 모양에 기대는 것과 안 기대는 것으로 갈라 케이스를 나누고, 안 기대는 쪽의 카나리아는 판 모양과 무관한 수(통지 수 · 칸 수)로 둔다(`apps/web/build-test/n36-notice-floor.test.ts` 의 접힘 케이스). **변조가 겨누지 않은 케이스를 함께 죽이면 변조를 고치기 전에 그 파일 실행의 콘솔 경고(React `same key` 등)를 센다** — 형제 칸 둘이 같은 `key` 를 나눠 쓰면 차례를 바꾸는 변조가 짝 짓기를 흔들어 다른 칸의 케이스가 죽는다. 그것은 변조의 몫이 아니라 소스의 결함이다(`apps/web/src/panels/property-panel.tsx` 의 몫 · 상태 보임 키). **vitest json 의 `failureMessages` 가 `Error: STACK_TRACE_ERROR` 로 시작하면 시간 한도로 죽은 것이다** — 구분력이 아니다. 붐비지 않을 때 그 변조만 다시 돌리거나 그 케이스에 한도를 준 뒤 센다(`docs/superpowers/plans/2026-10-26-poa-report.md` 「지침」).

**경주를 재는 케이스는 두 요청이 겹친 판만 센다.** `Promise.all` 로 던지기만 하면 붐빌 때 앞 요청이 커밋한 뒤 뒤 요청이 읽어 옳은 결과가 빨강이 된다. 테스트 트랜잭션으로 행을 쥐고, 쥔 백엔드의 pid 에서 `pg_blocking_pids` 를 사슬로 따라가 두 요청이 그 행에 줄 선 것을 본 뒤 놓는다(`withPageRowHeld`) — 줄이 안 서면 던진다. DB 전체의 못 받은 잠금을 세면 다른 행의 대기자까지 줄로 읽고, 사슬을 끊으면 첫 요청 뒤에 선 둘째를 못 센다. 흔들림을 재현하려면 기계가 아니라 **DB 컨테이너**를 붐비게 하되 **자기 컨테이너를 묶는다**(`docker update --cpus <n> <자기 컨테이너>` — 도커 VM 의 CPU 는 모든 워크트리 · 사용자 컨테이너가 나눠 쓴다. 되돌릴 때 `--cpus 0` 은 제한을 안 푼다 — VM 의 CPU 수를 준다). **인증이 요청마다 고치는 행(세션 `last_seen_at` · 토큰 `last_used_at`)은 문으로 쓰지 않는다** — 그 행을 쥐면 요청이 인증에서 서서 재려던 자리까지 안 간다. 트랜잭션 안의 한 질의 앞에서 세우려면 `apps/api/test/pg-fault-proxy.ts` 의 `holdQuery`(질의 글자로 붙잡고 푼다)를 쓴다. **재확인 자리의 순서를 재는 케이스는 요청을 먼저 쏘아 그 재확인 질의에 세운 뒤 상대를 쏜다** — 상대가 자격 행을 먼저 쥐면 요청은 인증에서 선다(`apps/api/test/guard-in-lock.test.ts` 의 `roleChangeAgainst`). 끝의 상태 코드가 가드의 것(404)인지 재확인의 것(401 · 403)인지로 닿았는지 가른다. **겹침의 문은 재려는 장치 앞의 다른 잠금(그 요청이 먼저 지나는 행)으로 세운다** — 재려는 장치(한도 자물쇠)를 문으로 쓰면 그 장치를 뗀 변조가 값이 아니라 판 카나리아(«줄 서지 않았다»)로 죽는다. 문을 놓은 뒤 둘이 함께 읽는 창은 그 쓰기의 커밋을 늦춰(`DEFERRABLE INITIALLY DEFERRED` 제약 트리거의 `pg_sleep`) 넓힌다(`apps/api/test/assets-race.test.ts`). **경주 창이 도구 안에 있으면 지연을 창 밖으로 크게 두거나 도구의 메서드를 감싸 창 안에 끼운다** — 몇 ms 지연으로 재현한 판은 같은 소스에서 통과와 거절이 섞여 자가 못 된다(`apps/api/build-test/screen-chromium.test.ts` 「잰 크기와 찍는 크기」 — `Page.prototype.screenshot` 을 감싸 잰 직후에 키움). **캡처 전에 크기를 재는 가드는 캡처가 크기를 다시 정하는 도구와 같은 상태에서 잰다** — 그 사이에 자라는 것은 페이지가 스스로 시작한 움직임(시트를 뒤에 얹으면 모든 값이 전이로 들어온다)과 늦은 글꼴이다. 잰 크기로 묶어 찍고, 찍은 뒤 다시 재서 커졌으면 실패로 낸다(묶기만 하면 위쪽만 잘린 그림이 «멀쩡한 한 장»으로 나간다). **`withRealApi` 케이스는 `beforeEach/afterEach(resetRealData)` 를 둔다** — 안 두면 같은 실행의 `withApi` 파일의 `signup` 이 `already-exists` 로 죽는다. 청소는 글자 그대로 `beforeEach(resetRealData)` · `afterEach(resetRealData)` 로 건다 — 인구조사(`apps/api/test/real-api-harness.test.ts`)가 그 글자를 센다. `withProxiedRealApi` 파일의 `afterEach(async () => …)` 꼴을 베끼면 `withRealApi` 를 쓰는 순간 전량에서 빨강이다. **두 사람의 겹침을 세울 때 한 사람이 조상(상태 영역 등)을 고른 채 남이 그 안을 고치는 판은 겹치지 않는다** — 고른 것의 잠금이 서브트리를 쥐어 남의 편집이 그 잠금이 풀릴 때까지(29.3s) 기다린다. 열어 둔 확인 상자 아래의 문서 변경은 같은 사람의 다른 탭(REST)으로 세운다.

**서로 다른 연결로 가는 두 메시지의 도착 순서에 기대는 판정은 앞섬(ms)을 재서 적는다.** localhost 는 두 연결의 지연 차가 0 이라 순서가 늘 보내는 순서다 — «대개 WS 프레임이 게시 응답보다 먼저»의 앞섬은 4–8ms 였고 WS 를 5ms 늦추자 뒤집혀 번호가 남의 노드에 붙었다. 한쪽 연결에 지연 프록시를 두고 뒤집히는 지연을 찾는다. 앞섬이 망의 흔들림(수 ms)보다 작으면 «대개»가 아니다. 방송(WS)과 그 쓰기의 REST 응답도 두 연결이다 — 방송은 연결마다 권한을 물은 뒤 보내 응답보다 늦을 수 있다(응답을 받은 순간 시작한 일이 그 방송보다 앞선다고 셈하지 않는다). 서버 → 브라우저 방향만 늦추는 도구는 `editor-stack.ts` 의 `startDownDelay` 다. **방송에서 제 연결을 빼는 판을 잴 때는 `joined`(연결 id)를 받은 뒤에 보낸다** — 그 전의 쓰기는 연결 id 없이 나가 제 방송을 받아 다른 판이 된다. **WS 를 늦춘 탭(`startWsDelay`)도 `joined` 를 받은 뒤에 누른다** — 그 전의 편집은 실시간 채널이 없어 REST 로 나가 늦춘 판을 안 잰다. 받은 프레임에서 `joined` 를 확인하고, 판이 섰는지는 `patch-error` → `patch-ack` 차례로 적는다. **«뒤에 줄 선 편집도 버려진다» 를 재는 판은 앞 편집과 다음 편집 사이의 기다림(통지 · 화면 `settle`)의 합을 늦춘 지연보다 짧게 둔다** — 길면 고치기 전 판에서도 거절 · 되싣기가 먼저 끝나 다음 편집이 줄 서지 않고, 케이스는 다른 값으로 죽어 그 판이 안 선 것이 안 보인다. 고침을 뗀 판에서 다음 편집이 실제로 버려지는지(서버 값)를 한 번 본다(`apps/web/build-test/zone-editor-review.test.ts` «H1» — 지연 2s · 통지 300ms). **REST 로 서버 값을 기다린 뒤 키를 누르는 케이스는 ack(WS)가 아직 안 닿은 판을 낸다** — 되돌리기 단추 · 화면 같은 상태를 기다린 뒤 누르거나, `startDownDelay` 판을 따로 세운다. **문서 편집 묶음에 `test` 를 더하는 고침의 경주 케이스는 `test` 만 막는 꼴(`replace` · `remove`)을 세운다** — 서버는 낡은 `baseSeq` 를 늘 `stale` 로 거절하고, `test` 를 돌리는 것은 남의 판 위로 다시 얹는 리베이스다. 칸을 만드는 `add` 는 리베이스의 전제(`store/anchored-ops.ts` 의 `premise.had`)가 따로 막아 `add` 판만 재면 `test` 를 뗀 변조가 산다(`apps/web/build-test/state-tree.test.ts` «남의 설명이 내 화면에 닿기 전에 …»). **전제를 칸 하나로 세우면 그 묶음이 읽어 베끼는 칸을 전부 센다** — 묶음이 노드를 통째로 베끼면(떼어 내기의 뒤 행 · 복제) 그 노드의 모든 칸이 전제다. 재현한 칸 하나만 `test` 로 묶으면 같은 판의 다른 칸(행 꼴 · 제 칸 글 · 보임)이 남의 고침을 말없이 걷는다(`docs/superpowers/plans/2026-10-26-rv-grb-report.md` H1). 칸마다 `test` 를 늘리지 말고 노드 값 하나를 `test` 한다 — 남이 없던 칸을 처음 단 판(보임 · 별칭을 처음 닮)은 없는 경로라 칸마다의 `test` 로 못 가르고, 노드 값 `test` 는 리베이스가 노드 id 로 경로를 다시 지어 남이 옮겨도 맞는다. 닿기 전 판은 칸마다 하나씩 세우고 **있던 칸을 바꾸는** 픽스처로 짓는다 — 그래야 칸 하나만 전제에서 뺀 변조가 그 판만 죽인다(`docs/superpowers/plans/2026-10-26-fx-grb-report.md` 변조 Y2). **리베이스가 끼는 겹침 판은 «서버에 닿음» 이 아니라 «그때의 서버 = 화면 · 늦춘 시간 뒤에도 서버 그대로» 로 기다린다** — 남의 쓰기가 먼저 서버에 서고 내 묶음은 그 프레임을 받은 뒤 리베이스되어 나가, 첫 «닿음» 은 내 묶음이 얹히기 전이다. 서버를 매번 다시 읽어 견주고, 걸음의 값을 그 기다림 뒤의 서버로 적는다(`apps/web/build-test/grid-row-actions.test.ts` «닿기 전»).

**교착을 잴 때는 누가 먼저 잡느냐를 뒤집은 판과 옛 판을 함께 세운다.** `ORDER BY` 없는 `FOR UPDATE` 는 행을 넣은 순서로 잡으므로 역할(먼저 만든 사람 · 나중 사람)을 한 방향으로만 세운 경주는 고리를 못 만들고 0 을 낸다 — 0 은 «고리 없음»이 아니라 «그 순서만 쟀다»다. 교착을 새 장치의 탓으로 적기 전에 **같은 경주를 그 장치를 뗀 판으로 한 번 더** 돌리고 장치와 무관한 대조군(owner 대신 editor 등)을 세운다 — 대조군의 수가 옛 · 새 같으면 고리는 원래 있던 것이다. 테스트 트랜잭션으로 행을 쥐는 결정론 판은 재려는 잠금 말고 다른 잠금까지 멈춰 세워 옛 판에서도 고리를 만들 수 있다 — 그 판의 대조군이 죽으면 판정에 쓰지 않는다. 대조군은 교착 수만이 아니라 **«줄에 섰는가»** 도 함께 적는다 — 새 장치를 뗀 판에서 줄이 안 서면 그 판이 장치에 닿았다는 증거이고, 둘 다 서거나 둘 다 안 서면 그 판은 장치를 안 쟀다. **고리가 셋 이상이면 하나를 붙잡고 나머지를 하나씩 보낸 판은 «정렬된 차례가 고리를 막는다» 를 못 잰다** — 뒤 요청이 앞 요청 뒤에 줄 서 첫 행을 함께 쥐지 못한다(`apps/api/test/pg-fault-proxy.ts` 의 붙잡기 칸이 하나다). 정렬을 떼는 변조가 사는지 한 번 돌려 적고, 살면 그 성질은 «못 잰 것» 으로 보고에 넘긴다(`docs/superpowers/plans/2026-10-31-rv-ac-report.md` V-D2).

**한 수정이 장치를 여럿 세우면 한 장치의 케이스를 다른 장치가 가릴 수 있다.** 케이스의 입력이 다른 장치의 문턱에 먼저 걸리면(한꺼번에 보낸 프레임이 줄 입구의 차례 검사에 걸려 트랜잭션을 안 연다) 재려던 장치를 떼도 초록이다 — 변조마다 «이 케이스의 입력이 그 장치에 실제로 닿는가»를 실패 값으로 확인하게 한다.

**한 에러 클래스가 이유 여럿을 나르면 단언은 이유까지 본다.** 거절을 `toThrow(그 클래스)` 로만 재면, 변조가 재려던 한도를 무너뜨려도 **같은 클래스의 다른 한도**가 그 자리에서 던져 초록이다(사람 한도를 재는데 전체 한도가 함께 차 있던 판). 케이스의 상태에서 다른 이유도 참인지 먼저 보고, 참이면 이유를 가르는 값(`scope` · 문장)을 단언한다.

**잠금 순서를 바꾸는 고침은 그 잠금을 «안 기다린다»고 적은 자리를 먼저 전부 센다** — `restore-lock-census` 의 «막히지 않는 줄의 목록이 고정돼 있다»(복원 중에 막히지 않는 쓰기의 정본) · `guard-in-lock` 의 «잠금에 쥐인 채 강등». 브리프가 짚은 판정 하나가 통과해도 그 밖의 판이 성질을 든다. **재확인이 잡는 자격 행(세션 · 토큰)의 순서를 바꾸는 고침은 그 자격으로 들어오는 쓰기 전부를 센다** — 자격 행은 쓰기마다 커밋 직전에 잡히므로, 그 앞에서 다른 행(owner 행 등)을 쥐는 쓰기가 하나라도 있으면 «자격 행 → 그 행»으로 잡는 새 쓰기와 고리를 만든다(토큰으로 멤버를 바꾸는 owner 를 그때 빼면 교착이었다). 대조군은 같은 쓰기를 세션으로 낸 판이다. **실패 갈래에 재확인을 더하는 고침도 이 셈에 든다** — 그 갈래의 요청이 재확인의 멤버 행 `FOR SHARE` 에서 owner 행 줄에 서게 되므로 «곧바로 끝난다» · «1s 안에 settle» 을 단언한 케이스(`guard-in-lock` 의 «이미 멤버인 사람을 다시 넣으면»)의 기대가 바뀐다. 그 케이스는 지키려던 성질(토큰 행을 안 잡는다)을 `pg_stat_activity` 의 대기 질의 + `pg_blocking_pids` 카나리아로 다시 잰다. **새 표를 쓰는 라우트를 더하면 `apps/api/test/guard-in-lock.test.ts` 의 분모와 상태 셈(그 프로젝트의 행을 읽는 함수)에 그 표를 함께 더한다** — 분모만 더하면 «강등이 없으면 상태가 바뀐다» 대조가 그 표의 변화를 못 본다.

**«자기 행을 잡고 → 재확인» 순서의 쓰기를 새로 세우면, 프로젝트 삭제가 그 표의 행을 CASCADE 전에 잡는지 먼저 본다**(`lockProjectMenuNodes` · `lockProjectPresets`) — 안 잡으면 CASCADE 가 멤버 행을 지운 뒤 그 행에 서서 재확인과 고리를 만든다. 재확인을 행 앞으로 옮기는 길은 **CASCADE 가 도는 순서**(FK 트리거 **이름**의 글자 순 — oid 자릿수에 따라 뒤집힌다)에 기대므로 고르지 않는다. 교착 판에는 CASCADE 순서를 뒤집은 판(FK drop · add)도 세운다.

**사용자 행을 잡는 쓰기(비밀번호 바꾸기 · 재설정)를 세우면 사용자 행을 읽는 재확인(`auth/admin.ts` 의 `recheckInstanceAdmin`)의 차례를 센다** — 같은 사람의 다른 세션이 낸 관리자 쓰기가 «그 세션 → 사용자 행», 바꾸기가 «사용자 행 → 그 세션 삭제» 로 잡으면 고리다. 그 재확인은 사용자 행을 먼저 잡는다(`recheckInstanceAdmin` 머리말 · `apps/api/test/auth-password-review.test.ts`). FK 검사의 `KEY SHARE` 는 `UPDATE`(비키 열)의 `FOR NO KEY UPDATE` 와 안 부딪혀 세지 않아도 된다. **행의 값으로 판정하는 확인(«견준 해시가 아직 그 해시일 때만»)은 그 행을 고치는 쓰기와 부딪히는 모드로 잡는다** — `FOR KEY SHARE` 는 커밋 안 된 `UPDATE`(비키 열)를 지나 옛 값을 읽어 그 쓰기의 뒷정리(세션 `DELETE`)와 커밋 사이에 끼어 남는다. `FOR SHARE` 는 그 커밋을 기다린 뒤 새 값으로 조건을 다시 본다(`apps/api/src/auth/session.ts` 의 `createLoginSession`). **«다른 세션을 끝낸다»는 그 쓰기의 커밋 뒤에 태어나는 세션을 센다** — 로그인은 트랜잭션 밖에서 견준 뒤 세션을 넣어, 견준 뒤 · 넣기 전에 커밋된 바꾸기를 지난다.

**버리는 조건을 세우는 장치는 그 조건이 서는 평범한 판을 먼저 센다** — «남이 끼면 멈춘다»는 남이 **내 뒤에** 한 번 고친 판(여럿이 쓰는 페이지의 흔한 판)에서도 서서 되돌리기를 전부 버렸다(`restoreUndoStack`). 고치기 전 소스와 같은 판을 견줘, 막으려던 판 밖에서 잃는 것이 있는지 적는다. **«맨 위가 X 면 묻는다»로 게이트를 세우면 한 누름이 맨 위를 지나 내려가는 길(건너뜀 루프)을 센다** — 게이트는 맨 위만 보는데 소비 루프는 건너뛴 뒤 아래 항목까지 쓴다(맨 위 세션 항목을 건너뛴 누름이 이력을 안 받은 복원 항목을 걷고 되돌리기 스택을 비웠다). 브리프 문장 «목록을 받은 판의 번호를 스토어에 넘긴다»는 그대로 짜면 프레임이 먼저 온 판에서 되돌리기가 남의 노드를 고쳤다 — 되짚기의 출발 문서와 출발 번호가 어긋났다.

**«거짓 빨강이라 안전하다»는 절반만 맞다.** 실패 방향이 거짓 빨강뿐인 자를 고치려고 파서를 손으로 쓰면 **거짓 초록이 가능한 설계로 바뀐다.** 자를 바꿀 때는 **실패 방향이 바뀌는지**를 먼저 묻는다. 그리고 **원문(글자)으로 재는 자는 뚫린다** — 설정·계약처럼 값이 있는 것은 **값으로 재고**, 그 값조차 함수면(임의의 콜백) **실물을 돌려서 잰다.** 판정을 테스트로 옮겨 적으면 판정이 두 벌이 되어 갈린다. **주석을 정규식으로 걷는 것도 손으로 쓴 파서다** — 줄 주석 속 `/*` 를 블록 시작으로 읽어 다음 `*/` 까지 코드째 지우므로 거짓 초록을 낸다. 소스를 읽는 자는 TypeScript 파서로 걷고(`@wirebound/test-support` 의 `stripComments` — 주석 구간만 공백으로 바꿔 원문 모양을 지키고, 이름 없이 넘기면 `.tsx` 로 먼저 읽는다), **파서도 구문 오류를 복구하며 코드를 지우므로** 구문 진단이 있으면 던진다. **주석을 걷고 다시 찍지 마라** — 프린터는 들여쓰기 · 줄바꿈을 바꿔 줄 모양에 거는 술어를 조용히 비게 한다. 걷은 자리는 공백으로 남으므로(`app./* */delete(` → `app.        delete(`) 자의 정규식은 `.` 양옆과 `(` 앞에도 `\s*` 를 둔다. **실물을 돌려 읽으면 탐침이 지난 한 갈래의 값만 나온다** — 요청에 따라 값을 고르는 함수는 탐침에 한쪽을 남기고 표와 맞아 지나가므로, 탐침은 알아보는 함수에만 대고 나머지는 못 알아본 것으로 죽게 한다(`apps/api/test/guarded-routes.ts`). **대역 · 주소 규칙도 글자 꼴이 아니라 그 대역이 덮는 값으로 잰다** — «`::ffff:` 로 시작하면 접두 ≥ 96»은 `::/64` · `0:0:0:0:0:ffff:10.0.0.0/8` 을 통과시키고 `::ffff:0:0/96`(= `0.0.0.0/0`)을 경계 안에 넣었다. 받아 준 값은 실물(`Fastify({ trustProxy })`)에 물려 대역 밖이 안 믿기는지 본다. **값도 누가 읽은 값인지 본다 — 판정을 내리는 판독기가 따로 있으면 그 판독기로 잰다** — Fastify 의 `trustProxy`(ipaddr.js)는 글자 `::a.b.c.d` 를 매핑(`::ffff:a.b.c.d`)으로 읽어, 값으로 잰 손 판독기가 받은 `::0.0.0.0/96` 이 IPv4 전부를 믿었다(`apps/api/src/config.ts` 의 `fastifyTrust` — Fastify 가 부르는 모듈로 IPv4 양 끝을 믿는지 잰다). **경로를 글자로 가리거나 거르는 장치도 라우터가 읽는 꼴로 잰다** — Fastify 의 라우터는 퍼센트 인코딩을 풀어 `/api/auth/%69nvites/<원문>` 을 `/api/auth/invites/:token` 으로 받는다(200 · `params` 에 원문). 인코딩 · 대소문자 · 겹친 빗금을 바꾼 판을 케이스에 싣고, 그 라우트에 닿는지(상태 코드)를 카나리아로 적는다(`apps/api/src/http/log-mask.ts` · `apps/api/test/rv-ac-link-exposure.test.ts`). **손 판독기를 피할 수 없으면 물을 점만 고르게 하고 판정은 실물에 맡긴다** — 목록의 합이 IPv4 전부인지는 구간 끝 + 1 과 0 만 실물 판독기(`compile(list)`)에 묻는다. 끝을 잘못 읽어도 거짓 빨강(기동 거절)으로만 틀린다(`apps/api/src/config.ts` 의 `trustsAllIPv4`). **포인터로 판정하는 장치는 포인터를 안 쓰는 오라클로 잰다** — 적용 사본에서 지킬 객체를 쥐고, 연산이 실제로 고르는 부모 객체가 그 안인지 · 지우는 값이 그것을 품는지로 센다(`packages/schema/test/lock-ops-identity.test.ts`). 판정과 같은 포인터 규칙으로 기대값을 짓는 표는 판정과 같은 데서 틀린다. **무작위 탐침은 고치기 전 소스에서 먼저 결함을 내는지 본다** — 새 · 옛 판정 모두에서 0 이면 «결함 없음»이 아니라 재려던 입력(적용되는 여러 연산 묶음)이 드물어 아무것도 안 잰 것일 수 있다. 카나리아로 판의 수(적용 성공 · 여러 연산 · 꼴마다 «건드림»)에 하한을 단언한다. **테마가 지나야 할 자(`wb-theme check` · `shots`)는 판정을 끄는 변조에 더해, 기본 뷰를 한 곳만 바꾼 테마 뷰(감싸는 요소 · 조각 이름 · 형제 자리)로 깬다** — 자가 세는 두 조건을 다 지나면서 계약(직계 · 조각)을 깨는 뷰가 넷 있었다(`docs/superpowers/plans/2026-10-25-rv-ft-report.md` M1).

**«자를 하나 더 얹으면 는다»가 아니다 — 사각이 겹치면 안 는다.** «이름을 보는 자»와 «값을 보는 자»를 겹쳐 둬도, **값을 보는 자가 심는 입력이 이름을 보는 자의 우회와 같은 것을 읽으면** 한 조각이 **둘 다** 통과한다 — 타입체크까지 통과하는 거짓 초록이 난다. 자를 더할 때 묻는 것은 «무엇을 더 잡나»가 아니라 **«이 자의 사각이 저 자의 사각과 겹치나»** 다.

**«자를 몇 판 지었나»가 멈출 때를 말한다.** 같은 축의 자가 판마다 뚫리면 한 판 더 짓는 대신 **못 재는 것을 그 자의 머리말에 적고 멈춘다.** 자를 고칠 때는 **원래 무엇을 고치려던 것이었는지**를 다시 본다 — **낮은 무게의 거짓 빨강 하나를 지우려다 거짓 초록 여럿을 얻는 거래는 하지 않는다.** 같은 뿌리의 결함이 수정마다 다른 창으로 옮겨 가면 창을 좁히지 말고 **뿌리(대개 서버의 판정 한 줄)를 고치는 트랙**으로 넘긴다.

**변조를 `git checkout` 으로 되돌리지 않게 한다 — 백업하고 바이트 비교로 복원하게 한다.** `git checkout` 으로 되돌리면 **커밋 전의 자기 고침까지 함께 날아간다.** `git checkout <파일>` 은 «내가 심은 한 줄»이 아니라 «그 파일의 커밋 안 된 전부»를 되돌린다. **백업 이름은 경로 전체로 짓는다** — basename 은 겹친다(`repos/members.ts` · `routes/members.ts`). 겹치면 뒤의 백업이 앞의 것을 덮고 바이트 비교도 그 백업과 하므로 틀린 복원이 통과한다. **한 변조가 같은 파일 여러 곳을 바꾸면 백업은 파일마다 한 번, 첫 바꿈 전에 뜬다** — 바꿈마다 같은 이름으로 뜨면 둘째 백업이 반쯤 바뀐 판을 덮고 바이트 비교도 그 판과 해 «같음» 으로 통과한다(`docs/superpowers/plans/2026-10-27-fx-pob-report.md` 「지침」). 끝의 `git status` 에 더해 `git diff --stat` 으로 바뀐 파일이 뜻한 것뿐인지 본다. **글자로 찾아 바꾸는 변조는 코드 자리를 고른다** — 첫 출현이 주석 안일 수 있다(식별자 인용). 블록 주석 안에 `/* … */` 를 끼우면 주석이 일찍 닫혀 구문 오류로 남의 케이스가 죽는다. 찾는 글자에 문맥(`return ` · `await `)을 붙여 한 곳만 맞게 하고 맞은 수가 1 인지 확인한다. **SDK · 렌더러 · 내보내기를 고친 뒤 실브라우저 번들 판(`openBundlePage` · `exportBundle`)은 `pnpm build` 뒤에 잰다** — `editor-stack` 의 api 가 `packages/*/dist` 를 읽어 빌드 전에는 앞 소스의 CSS 로 그린다. api `build-test` 는 별칭으로 소스를 읽어 빌드와 무관하다 — 고치기 전 · 뒤 값을 적을 때 어느 빌드로 쟀는지 함께 적는다. **에디터 뷰 모드 판도 같다** — `editor-stack` 의 vite 는 `@wirebound/*` 를 `dist` 로 풀어(`apps/web/vite.config.ts` 에 별칭이 없다), 렌더러 · SDK 를 고치거나 변조한 뒤의 캔버스 판도 `pnpm build` 뒤에 잰다(변조마다 빌드 · 복원 뒤 다시 빌드 — `docs/superpowers/plans/2026-11-17-vs-report.md` 실브라우저 변조 표). **빌드 산출물을 거치는 변조는 소스를 복원한 뒤 다시 빌드하고 다음 변조로 간다** — 바이트 비교 복원은 소스만 되돌려, 다음 변조가 앞 변조의 `dist`(테마 `.wbtheme` · 패키지 `dist`)를 물고 돌아 두 변조의 증상이 한 실패 값에 섞인다. **변조를 돌리다 멈춘 vitest 는 부모가 끝나도 남는다** — 끝에 `ps` 로 그 워크트리 경로의 `vitest` 를 세고 내린다. **무한 루프 · 걸림으로 내린 변조는 내린 그 자리에서 센다** — 끝까지 미루면 남은 일꾼이 그 사이의 시간 값을 모두 흐린다(고리 검사를 뗀 변조의 일꾼이 여섯 시간 100% CPU 로 남았다). **잠금을 더하는 변조를 잴 때 붙잡는 질의는 그 변조가 끼울 자리보다 앞이어야 한다** — 뒤의 문장을 붙잡으면 그 앞에 끼운 잠금은 붙잡히기 전에 잡혀 고리가 안 서고 변조가 산다(`apps/api/test/menu-changed.test.ts` 의 `RENAME_WRITE`). **JSX 속성으로 심는 변조는 그 요소의 spread(`{...bind}`) 뒤에 심는다** — 앞에 심은 `onPointerDown` 은 뒤의 spread 가 같은 이름을 실으면 덮여 아무것도 안 바뀐다. 변조가 «살았다»면 먼저 그 핸들러가 실제로 불렸는지 센다. **변조를 건 채 전량을 돌릴 때는 복원(`cp` · `cmp`)을 같은 명령줄 끝에 묶고 `run_in_background` 로 띄운다** — 전량을 foreground 로 부르면 120s 한도에 걸려 백그라운드로 넘어가고 그동안 소스는 변조된 채다. 끝날 때까지 그 소스를 만지지 않는다(만지면 변조를 지운다). **새 이름을 쓰는 변조는 그 import 도 같은 변조에서 바꾼다** — 안 바꾸면 `ReferenceError` 로 요청마다 500 이 나 케이스가 값이 아니라 500 으로 죽는다. **변조는 타입 검사를 지나는 꼴로 쓴다** — vitest 는 타입을 안 보아, 타입에 없는 칸을 읽는 변조(`v.hidden`)는 `undefined` 로 돌아 재려던 갈래가 아니라 다른 갈래를 잰다. 변조 글이 읽는 칸이 그 타입에 있는지 보고, 죽은 케이스가 그 변조로 죽을 케이스인지 실패 값으로 맞춘다(`docs/superpowers/plans/2026-10-20-fx-th-report.md` L4 M8). 변조가 죽인 케이스의 실패 값이 재려던 값인지 먼저 본다. **변조를 건 동안 같은 워크트리의 소스를 읽는 일(탐색 서브에이전트 · 인구조사)을 함께 돌리지 않는다** — 변조된 소스를 읽고 «고침이 없다» · 엉뚱한 줄 번호를 보고한다. 읽기를 겹쳐야 하면 `git show HEAD:<파일>` 이나 커밋된 사본을 읽게 한다. 같은 워크트리에서 배경 테스트 실행(영역 묶음 · 게이트)이 도는 동안에도 변조를 걸지 않는다 — vite dev · vitest 가 그 사이의 변조된 소스를 읽어 그 실행의 케이스가 변조로 죽는다. 겹쳤으면 그 판의 실패를 버리고 다시 돈다. **맞은 수가 기대와 달라 건너뛴 변조도 진행 줄에 같은 꼴로 낸다**(«S1 … 안 돎: 맞은 수 3») — 건너뛴 것을 요약 파일에만 적으면 진행을 지켜보는 쪽이 «돌았다» 로 읽는다. 여러 곳에 맞는 글자는 «몇째» 를 정해 그 줄만 바꾸고 그 줄 번호를 표에 적는다. **떼려는 장치가 판 만들기와 같은 길이면 그 장치가 서는 조건에만 변조를 건다** — 하트비트의 되잡기는 첫 잡기와 같은 `settle` 이라 그 알림을 통째로 떼면 픽스처의 `locksWith` 부터 «프레임이 차지 않았다»로 죽는다(구분력이 아니다). «`releasePages` 로 놓인 연결의 다음 `hold`» 처럼 그 장치만 서는 상태에 건다(`apps/api/test/late-commit-stale.test.ts` 머리말). **남의 편집을 재는 케이스의 변조는 «남의 것만» 막는다** — 열린 문서를 첫 판에 얼리면 내 편집 뒤 목록을 읽는 케이스까지 죽는다. 내 커밋을 부를 때 녹는 얼림으로 짓는다(`docs/superpowers/plans/2026-10-22-pi-report.md` 의 E2b). **캐시 우회를 떼는 변조는 캐시 길도 같은 입력을 넘기는지 본다** — 우회한 갈래만 값을 넘기면 우회를 뗀 변조가 «캐시가 옛 값을 냄» 이 아니라 «값이 빠짐» 으로 죽는다. 캐시 길에도 그 값을 넘기는 꼴로 짠다(`docs/superpowers/plans/2026-10-24-fx-ci-report.md` M3d).

**변이마다 전량을 돌리게 하지 않는다 — 그 변이가 겨누는 파일만 돌리고, 전량은 변이 집합 전체에 한 번.** 변이 N 종마다 web 전량을 돌리면 기계가 포화되고, 붐빔은 **타임아웃으로 죽는 거짓 빨강**까지 만든다. `vitest related` 는 대안이 못 된다 — 모듈 그래프가 촘촘해 web 파일의 절반가량을 고른다(다시 재는 법: `pnpm vitest related <파일> --run --reporter=json` 의 파일 수). 루트 `maxWorkers: '50%'` 는 **한 실행의 몫만** 묶으므로 워커 여럿이 동시에 전량을 돌리면 그 수만큼 다시 쌓인다 — 그런 라운드면 브리프에 `--maxWorkers=25%` 를 적는다. **전량 게이트는 한 기계에서 동시에 둘까지만 띄운다**(영역 게이트는 셈에 안 든다 — 표는 `README.md` 「트랙 게이트」). **띄우기 전과 끝난 뒤 `uptime` 의 load 를 상태 파일에 적는다** — 코어 수의 세 배를 넘으면 띄우지 않고 기다린다(다른 저장소의 부하 시험 · 빌드도 같은 기계를 쓴다). web 프로젝트 하나(`pnpm vitest run --project web`)도 같다 — 영역 게이트라 전량 슬롯에는 안 들지만, load 가 높으면 같은 파일이 한 일꾼 · 긴 한도로는 초록인데 시간 한도(`STACK_TRACE_ERROR`)로 죽는다(`docs/superpowers/plans/2026-10-31-fx-ws-report.md` 「게이트」). 혼자 다시 돌린 판도 load 가 높으면 기본 한도(web 프로젝트는 vitest 기본 5s)에 또 걸린다 — 그때는 `--testTimeout=30000` 으로 한 번 더 돌려 케이스 시간을 적고, 그 시간이 한도의 몇 분의 일인지로 «부하» 와 «느려진 코드» 를 가른다. 끝난 판의 파일 수를 프로젝트마다 기준선과 견주고, 한 프로젝트가 통째로 빠졌으면 그 판은 «안 잰 것» 이다 — unit · web 일꾼 하나의 RPC 시간 초과(`Timeout calling "onTaskUpdate"`)가 forks 풀을 끊어 `singleFork` 인 api 는 시작도 안 한다(로그의 `|api|` 줄 0 · 끝 줄은 «Errors N» 뿐). `pnpm test:build:serial` 도 같은 시간 초과로 첫 파일 뒤에 멈춘다 — 종료 1 · 실패 케이스 0 · `Errors 1` 로 끝나 실패 목록만 보면 «실패 없음» 이다. 파일 수를 기준선과 견주고, 모자라면 그 판은 안 잰 것이라 load 가 내려간 뒤 다시 돈다. 끝 줄의 `Test Files` 에서 통과 + 실패가 괄호 안 분모보다 적고 `Errors N` 이 붙으면 그 차이만큼의 파일은 안 돈 것이다 — 실행 중에 vitest 임시 SSR 파일이 사라진 `ENOENT … /ssr/…` 도 그 꼴이다(실패 셋만 보면 «셋이 빨강» 으로 읽힌다). 그 판의 실패를 결함으로 세지 말고 그 갈래를 다시 돈다(`docs/superpowers/plans/2026-11-18-eh-report.md` 「게이트」). 끊긴 판에서 «남은 파일» 만 골라 다시 돌릴 때는 그 판의 json 이 아니라 그 프로젝트의 include 글롭(`vitest.config.ts`)에 맞는 `git ls-files` 로 목록을 짓는다 — 끊긴 판의 json 은 모은 파일 일부만 실어, 그것으로 지은 «나머지» 에서 파일이 경고 없이 빠진다(`docs/superpowers/plans/2026-11-02-fx-pv-report.md` 「게이트」). `pnpm test:build:serial`(`test:build` 의 첫째 갈래)은 build 프로젝트가 파일을 차례로 돌리므로(`vitest.config.ts` — 파일마다 `packages/*` 를 재빌드해 나란히 돌면 서로의 dist 를 지운다) 워커 수를 안 적어도 된다. 둘째 갈래 `pnpm test:browser` 는 파일 병렬 워커 3 이 기본이고 `--maxWorkers` 로 덮는다. **한 워크트리 안에서 api 를 도는 vitest 는 한 번에 하나다** — 실행마다 global-setup 이 테스트 DB 의 마이그레이션을 내렸다 올려, 겹친 실행은 `relation "users" does not exist` 로 죽는다. 배경 탐침을 띄운 채 케이스를 돌리지 않는다. **부하판은 api 를 뺀 프로젝트로 겹친다**(`pnpm vitest run --project unit --project web …`) — `pnpm test` 셋을 겹치면 한 워크트리의 테스트 DB 를 셋이 내렸다 올려 api 가 깨진다. **전량 게이트가 도는 동안 탐침 파일을 테스트 글롭 안에 두지 않는다** — 수집이 끝나기 전이면 그 실행이 주워 가 수가 틀린다. 탐침은 스크래치패드에 쓰고 게이트가 끝난 뒤 들여놓는다. 탐침의 로그로 값을 읽는 변이는 `--reporter=default --reporter=json --outputFile.json=<경로>` 로 둘을 함께 준다 — json 만 주면 `console.log` 가 사라져 값 없는 초록이 된다. 변조가 죽인 칸을 보고에 옮길 때도 둘을 함께 준다 — json 보고서의 `failureMessages` 는 첫 줄만 실어 어느 칸이 바뀌었는지가 안 남는다. **긴 게이트는 `caffeinate -i` 아래에서 돌린다** — 배터리에서 덮개가 닫히면 기계가 잠들어 케이스가 시간 초과로 죽고, 그 판은 «실패»가 아니라 «안 잰 것»이다(`pmset -g log` 의 Sleep 줄로 가른다). **`caffeinate` 는 덮개를 닫은 잠듦(`Clamshell Sleep`)을 못 막는다** — 긴 게이트 · 변조 묶음이 끝나면 `pmset -g log | grep ' Sleep '` 의 시각을 실행 시각과 맞춰 보고, 겹친 판은 결과와 무관하게 다시 돌린다. **«잠듦 없음»도 그 시각을 맞춰 본 뒤에 적는다** — 확인 없이 적은 «잠듦 없음» 구간(376s → 3416s)에 덮개 · 열 비상 잠듦이 여섯 번 있었고, 그 판의 시간 초과 넷을 «부하»로 적었다. 변조 한 판의 시간이 다른 판의 몇 배면 먼저 잠듦을 본다. **게이트 체인은 스크립트 하나로 쓰고 `nohup nice -n 10 caffeinate -i <스크립트> & disown` 으로 띄운다** — `( … ) &` 로 띄우면 호출한 셸이 끝날 때 체인이 반쯤 죽은 채 남고, 다시 띄운 체인과 같은 테스트 DB 를 겹쳐 써 «데이터베이스와의 연결을 잃었습니다» 같은 거짓 빨강이 난다. 띄우기 전에 `ps` 로 같은 워크트리의 앞 체인이 없는지 세고, 상태 파일에 같은 줄이 두 번 쌓이면 체인이 둘이다. **멈출 때는 스크립트가 아니라 그 프로세스 그룹을 내린다**(띄울 때 `echo "$(ps -o pgid= -p $$ | tr -d ' ')" > <상태>` 로 **그룹 id** 를 적고 `kill -- -<pgid>` — `$$` 는 스크립트 셸의 pid 라, 띄운 셸이 만든 그룹의 id 와 다르다. 내린 뒤 `ps -eo pid,pgid,command | awk '$2==<pgid>'` 가 비었는지 본다) — 스크립트 셸만 내리면 돌던 갈래가 launchd 아래 고아로 남아 다음 판과 겹친다. 그룹째 내려도 vitest 일꾼이 그룹 밖(ppid 1)에 남는 판이 있다 — 내린 뒤 남았는지를 경로가 아니라 cwd 로 센다(`lsof -p <pid> -a -d cwd`). **게이트가 시간 상한 케이스 하나(`ws-lock-cost` 의 max < 100ms 등)로 빨강이면** 그 파일을 혼자 세 번 돌려 값을 적고 게이트를 한 번 다시 돈다 — 두 판 다 보고에 적는다. **합친 판의 실브라우저 빨강이 혼자 돌린 판에서 초록이면 같은 파일 넷을 동시에 두 번 띄워 다시 센다** — 부하에서만 서는 판은 대개 한 트랙이 다른 트랙 케이스의 판(첫 렌더 · 조회 차례)을 바꾼 것이다. 동시 판에서 재현되면 부하로 적지 말고 기전을 결정론 판(조회를 `page.route` 로 늦춤)으로 세운다(`docs/superpowers/plans/2026-11-03-mv-report.md` «3» — 혼자 3/3 초록 · 동시 3/8 빨강). **`pnpm test` 가 도는 동안 같은 기계에서 `editor-stack` 탐침(Chrome · vite · api 를 띄운다)을 겹치지 않는다** — 겹친 판에서 `edit-lost-commit` «503 이 한도 안에 난다»가 빨강이었다. 겹쳤으면 그것을 보고에 적고 전량을 다시 돈다. **api 파일을 낀 변조 묶음은 global-setup 이 시스템 테마를 변조된 `@wirebound/themes` · kit 소스로 빌드한다** — 테마 검사를 넓히는 변조는 판 세우기에서 죽어 실행 0 이 된다. 변조마다 실행 수를 적고, 0 이면 그 변조를 api 파일 없이 다시 돌린다. **브리프의 게이트는 건드릴 경로마다 `README.md` 「트랙 게이트」 표의 줄을 합쳐 적는다** — web 트랙이 `packages/*` 를 건드리면 그 패키지의 단위 · build 갈래도 든다(N20 이 `packages/renderer` · `theme-kit` · `exporter` 를 건드려 두 갈래를 더 돌렸다). **긴 트랙의 기준선 · 변조 결과는 잰 그 턴에 보고 파일(`docs/superpowers/plans/…-report.md`)로 옮긴다** — 스크래치패드는 `/private/tmp` 아래라 재부팅에 지워진다(기준선 json · 변조 표를 잃어 다시 재야 했다).

**jsdom 값은 실브라우저 값이 아니다 — 포커스·blur·클릭 순서에 관한 결함은 실브라우저로 재기 전에는 결함이 아니다.** **`getByRole` 은 `display: none` 으로 감춰진 요소를 못 찾는다 — 접힘 · 숨김 결함을 재는 실브라우저 케이스는 CSS 로 찾아 `waitFor({ state: 'attached' })` 뒤 가시성을 값으로 단언한다.** `getByRole(…).waitFor()` 는 감춰진 채 열린 입력을 «값 없는 시간 초과» 로 죽여 변조가 구분력이 아니다(`apps/web/build-test/n2-notices.test.ts` 의 접힌 좌측 F2). **jsdom 의 `fireEvent.click` 은 포커스를 옮기지 않아 blur 가 안 난다** — jsdom 에서 «탭을 누르면 친 글을 잃는다»로 보인 것이 실브라우저에서는 커밋되기도 하고, 실제 결함이기도 하다. **둘을 가르는 것은 실브라우저 측정뿐이다.** 워커에게 **jsdom 값과 실브라우저 값을 구분해 적게** 하고, 실브라우저를 흉내 내는 테스트 헬퍼를 세우면 **그 흉내를 실브라우저 표와 칸마다 대조**하게 한다(흉내도 거짓 초록을 낸다). **jsdom 은 포커스가 선 요소에 `disabled` 를 걸어도 포커스를 떨구지 않는다** — Chrome 은 `body` 로 떨군다. 잠긴 요소의 `blur()` 도 jsdom 에서는 아무 일도 안 해, 흉내는 잠기기 전(요청을 보내는 자리)에 `blur` 하고 잠긴 동안 `activeElement === body` 를 카나리아로 둔다(`apps/web/test/routes/project-crud.test.tsx` 의 `failWhileFocusLost`). **가짜 api 로 세운 판의 «시간 한도가 없다»는 실물 클라이언트로 다시 잰다** — 한도는 인터페이스(`api/client.ts`)가 아니라 구현(`api/http-client.ts` 의 `READ_DEADLINE_MS`)에 있어 가짜 api 판에서는 늘 «한도 없음»이다. 실물 `createHttpClient` 에 답하지 않는 `fetch` 를 물리고 가짜 시계로 잰다. **한 워크트리에서 한 에이전트가 소스를 고치는 동안 탐침을 돌리면 반쯤 고친 소스를 읽는다** — 탐침은 재는 경로의 diff 가 비었는지 보고 재거나 `git show HEAD:<파일>` 사본으로 재고, 어느 소스로 쟀는지 적는다. **한글 조합 중의 키는 CDP `Input.imeSetComposition` 으로 조합을 세워 잰다** — Chrome 은 조합 중의 Escape 를 `isComposing: true` 로 내고 모달 `<dialog>` 에 `cancel` 도 낸다(`cancel` 에는 `isComposing` 이 없다). jsdom 의 `compositionstart` 스텁은 그 차례를 흉내 내지 못한다(`apps/web/build-test/editor-shell-modal.test.ts`). **모달이 열린 동안 뒤 화면의 막힘은 `[inert]` 속성으로 재지 않는다** — `showModal` 의 inert 는 암묵이라 `closest('[inert]')` 가 늘 거짓이다. 누름은 `elementFromPoint`(배경막이면 `DIALOG`)와 실클릭 뒤의 상태로 잰다. **jsdom 흉내 이벤트는 흉내 낸 필드만 나른다** — `test/pointer-events.ts` 의 `PointerEvent` 가 `pointerId` 를 버리면 모든 이벤트가 같은 포인터로 보여 «다른 포인터» 가드를 뗀 변조가 산다. 가드가 새 필드를 읽으면 흉내에 그 필드를 브라우저 기본값으로 더한다. **헤드리스 Chrome 은 창을 잃는 판을 못 낸다** — 다른 탭을 앞으로 해도 `document.hasFocus()` 가 참이다. **CDP 터치(`Input.dispatchTouchEvent`)는 `touch-action` 기본값에서 첫 움직임에 `pointercancel` 을 낸다** — 터치 끌기 판은 그 값부터 적는다. 포인터 여럿은 마우스로 끄는 중 CDP 터치를 한 번 쳐서 잰다(`apps/web/build-test/tree-drag-review.test.ts`). **모달 `<dialog>` 안의 키 이벤트도 React 트리를 따라 그 상자를 그린 컴포넌트의 조상 `onKeyDown` 으로 버블된다** — 모달은 뒤 화면의 누름 · 포커스만 막는다. 단축키를 받는 상자 안에서 모달을 그리면 상자 단추에서 친 `Delete` 가 뒤 트리의 삭제 확인을 건다(Chrome · jsdom 같은 값). 모달은 단축키 상자의 형제로 그린다(`apps/web/src/shell/shell-dialog.tsx` 머리말 «상자 안의 키는 React 트리를 따라 버블된다»). **OS 파일 놓기는 CDP `Input.dispatchDragEvent`(`files`)로 잰다** — Chrome 은 핸들러 없는 자리에 놓인 파일을 현재 탭이 아니라 새 탭으로 연다. «에디터를 떠나는가»는 주소가 아니라 `context.pages()` 수로 센다(Firefox · Safari 는 현재 탭을 옮길 수 있다 — 이 기계에서 안 잰다). **클립보드 이벤트(`copy` · `cut` · `paste`)의 대상은 포커스가 아니라 고른 자리(캐럿)의 시작 요소다** — 캔버스 본문을 누른 뒤의 Cmd+V 대상은 테마의 `div` 다. 포커스로 가르는 거름은 대상이 아니라 그 문서의 `activeElement` 를 본다(`apps/web/src/edit/editor-shortcuts.ts` 의 `shortcutsBlocked`). **전역 키 리스너를 새로 걸면 키를 쓰는 위젯마다 그 위젯이 쓰는 키와 안 쓰는 키를 센다** — 열린 메뉴의 ← → 가 전역 명령이 되어 그 메뉴가 쥔 대상(«고른 노드»)을 바꿨고, 반대로 위젯이 모든 키를 쥐면 탭을 누른 뒤의 Delete 가 죽었다(`keyHeldByWidget`). **지운 뒤 다른 것을 고르는 명령은 키 반복 · 두 번 치기로 잰다** — 트리 상자 키는 포커스가 빠져 한 번에서 멈췄지만 전역 리스너는 막 골라진 부모를 이어 지운다(`apps/web/src/shell/editor-keys.tsx` 의 `run` — 키보드 삭제는 선택을 비운다). **스크롤바를 누르는 판은 이 기계(macOS)의 헤드리스 Chrome 에서 기본으로 못 잰다** — 오버레이 스크롤바라 폭이 0 이다. `chromium.launch` 에 `ignoreDefaultArgs: ['--hide-scrollbars']` 를 주고 그 상자에 `::-webkit-scrollbar { width: … }` 를 얹으면 고전 스크롤바가 `Input.imeSetComposition`)으로 잰다** — `apps/web/src/main.tsx` 의 `BrowserRouter` 는 위치 갱신을 전이(`startTransition`)로 해, `value` 를 주소에서 읽는 칸은 입력 이벤트 뒤 옛 값으로 되돌려져 조합이 걸음마다 굳고 빠른 입력의 글자를 잃는다. jsdom 의 `fireEvent.change` 한 번은 이것을 못 낸다. 글은 컴포넌트 상태로 들고 주소에는 싣기만 하며, 위치가 바뀔 때마다 주소의 글을 칸에 넣고, 조합 중(`compositionstart` ~ `compositionend`)에는 주소를 안 고친다 — 제 `replace` 가 늦게 닿아 칸을 되돌리는 판은 같은 전이 줄의 위치 갱신이 묶여 Chrome 에서 안 서므로, 그 판을 막는 거름은 재현되지 않는 장치다(`apps/web/src/routes/project-list.tsx` 의 `ProjectCards` · `apps/web/build-test/rv-ws-workspace.test.ts` «검색 칸에 한글을 …»). **jsdom 도 폼 제약(`required` · `min` · `max` · `pattern`)으로 제출을 막는다** — 제약이 제출을 먼저 막아 화면의 검사 문장이 안 선다(Chrome 은 말풍선을 띄운다). 화면이 범위를 문장으로 말하려면 폼에 `noValidate` 를 두고, 그 케이스는 범위 밖 값으로 «보내지 않고 문장» 을 함께 단언한다(`apps/web/src/admin/invites-section.tsx` 의 만들기 상자). **`editor-stack` 의 Chrome 은 bfcache 가 꺼져 있다** — Playwright 가 `--disable-back-forward-cache` 를 기본 인자로 준다. 다른 문서로 떠났다 «뒤로» 오는 판(지운 줄 안 화면 상태가 되살아나는가)은 `chromium.launch({ ignoreDefaultArgs: ['--disable-back-forward-cache'] })` 로 따로 띄운 브라우저에서 재고, bfcache 로 되살면 `load` 가 다시 안 오니 `goBack({ waitUntil: 'commit' })` 로 기다린다(`apps/web/build-test/rv-ad-admin.test.ts` «H3»). **jsdom 하네스(`renderEditor` · `openPage`)의 `apiOverrides` 스텁은 여는 때의 함수가 쥐인다** — 연 뒤 `board.api.x = …` 로 갈아 끼운 스텁은 안 불린다. 답을 바꾸려면 함수를 갈아 끼우지 말고 스텁이 읽는 변수(깃발 · 큐)를 바꾼다(`apps/web/test/codes/codes-screen.test.tsx` «사용처 조회가 실패하면 …» 의 `failing`).

**jsdom 은 좌표 · 상속 계산도 없다.** 확인 단추를 첫 단추 자리에 바꿔 그리는 화면은 **실브라우저 더블클릭**으로 재고, 첫 누름 뒤 그 좌표에 무엇이 서는지(`elementFromPoint`)를 폭마다 **왼끝 · 가운데 · 오른끝과 긴 문안**으로 적는다 — 가운데 한 점이 «취소가 선다»여도 가장자리에서는 확정이 섰다(«API 토큰» 전부 폐기가 연타 한 번에 지워졌다). `event.detail > 1` 을 버리는 가드는 따로 누른 두 번(각 `detail` 1)을 못 막으므로 배치와 가드를 각각 혼자 잰다. **뒤따르는 클릭을 삼키는 장치는 시간만으로 가르지 않는다** — 고른 항목이 연 확인 · 대화 상자를 곧바로 누르는 판을 먹는다. 첫 누름 자리를 함께 본다(`apps/web/src/shell/action-menu.tsx` 의 `DOUBLE_CLICK_SLOP`). `getComputedStyle` 은 상속 속성을 자식에게 물려 계산하지 않는다(`white-space` — 자식에서 빈 문자열) — 상속으로 덮인다는 주장은 실브라우저 값으로만 적는다. **jsdom 의 CSS 파서는 `@layer` 를 못 읽어 그 시트를 통째로 버린다** — 케이스는 초록이고 콘솔에 `Could not parse CSS stylesheet` 한 줄만 남는다. jsdom 이 읽는 CSS(SDK 기본 뷰 CSS · 캔버스 시트)에 `@layer` 를 두지 않는다 — 층이 필요한 시트는 따로 싣거나(`@wirebound/theme-sdk/capture` 의 `CAPTURE_CSS`) `insertRule` 로 넣는다(`apps/web/src/canvas/canvas-iframe.tsx` 의 `HOLD_CSS`). 기본 뷰 CSS 를 jsdom 시트로 읽어 규칙 수를 맨 위 블록 수와 견주는 케이스가 잠근다(`packages/renderer/test/default-view-props.test.tsx`). **jsdom 은 UA 기본 `display` 도 없다** — 접근 이름 계산이 안쪽 요소 앞뒤에 공백을 끼워, 이름이 든 단추 안에 새 인라인 요소를 넣으면 jsdom 이름만 Chrome 과 갈린다(`Flex ( 머리 줄 ) 가로`). 그 요소의 UA 기본값을 `apps/web/test/setup.ts` 에 둔다(지금 `bdi`) — node 환경 파일에는 `document` 가 없으니 가드한다. **판을 다시 싣거나 상태를 갈아 끼우는 단추를 새로 세우면, 그 클릭이 blur 로 내는 커밋과 단추의 요청이 서로 다른 연결로 겨룬다** — blur 커밋 칸에 친 채 눌러 두 요청의 앞섬(ms)을 재고, 한쪽 연결만 늦춘 판으로 뒤집히는지 본다(복원 배너 «다시 불러오기»: WS patch 가 GET 보다 8ms 앞 · WS 10ms 지연에 3/3 뒤집혀 «취소됐다»는 편집이 서버에 반영돼 있었다). **쓰기를 내는 메뉴 · 단추는 키 반복으로도 잰다** — 고른 항목이 닫히며 포커스를 «…» 로 돌리면 누른 채인 Enter 가 단추를 다시 눌러 메뉴를 열고 첫 항목을 고른다(`apps/web/build-test/rv-ad-admin.test.ts` «H2»). playwright 의 `keyboard.down` 을 거듭 부르면 반복(`autoRepeat`)으로 나간다. 서버 기록 수에 더해 **누른 동안 메뉴가 다시 선 수**(`role="menu"` 가 DOM 에 새로 선 횟수 — `MutationObserver`)를 센다 — 사슬이 고르는 첫 항목이 서버 편집을 안 내면(입력을 여는 항목) 서버 값은 그대로다(`apps/web/build-test/fx-ad-repeat.test.ts` «아래로»). **캔버스 노드를 누르는 실브라우저 판은 누를 점을 훑어 고른다** — 셸의 맨 위가 캔버스 iframe 이고(고른 노드 왼쪽 위 손잡이 · 오른쪽 패널이 안 덮음 — 창 1440 의 캔버스 칸은 페이지 폭 1280 보다 좁다) iframe 문서의 그 점의 가장 가까운 노드가 그 노드인 점이다(`apps/web/build-test/palette-chain.test.ts`). 이미 고른 노드를 다시 누르는 판은 «고름이 섰다» 를 기다림으로 못 가른다 — 점이 없으면 카나리아로 죽인다. **훑기 전에 대상을 `scrollIntoView` 로 들인다** — 창 밖의 칸은 `elementFromPoint` 가 `null` 이라 점이 없고, 카나리아가 결함 대신 «점 없음» 으로 죽는다(`apps/web/build-test/grid-row-pick.test.ts` 의 `pointOf`). **캔버스 사각형 판은 문서를 좁혀(뷰포트 폭 375) 덮을 상자 전체가 캔버스 칸 안에 서게 한다** — 1280 폭 문서의 전폭 노드(그리드 행 줄 · 글)를 덮는 사각형은 끝이 칸 밖이라 누름이 셸 겹(사이드바 · 칸 사이 손잡이)에 나 사각형이 안 선다(`apps/web/build-test/grid-marquee.test.ts`). **더블클릭으로 동작하는 장치는 끌기 뒤 누름을 `clickCount: 2` 로 낸 판으로 잰다** — CDP 마우스의 누름 수는 부르는 쪽이 정하고 브라우저는 그 값대로 `dblclick` 을 낸다. 끌기 장치가 끈 누름의 `click` 을 삼켜도 `dblclick` 은 서므로, `dblclick` 을 듣는 장치는 끌기 뒤 한 번 누른 손을 더블클릭으로 받는다. 몸통에 닿은 `click` 둘을 짝짓고 그 판을 케이스로 둔다(`apps/web/build-test/palette-double-click.test.ts` «끈 뒤의 누름»).

**실브라우저 판은 `apps/web/build-test/` 에 케이스로 잠근다** — `editor-stack.ts` 가 일회용 DB · api · vite · Chrome 을 빈 포트로 띄우고 거둔다(`pnpm test:browser`). 스크래치 스크립트로 잰 Chrome 값은 다음 차수가 다시 못 잰다 — 결함을 Chrome 으로 찾았으면 그 판을 이 자리로 옮기고, 고치기 전 소스를 끼워(백업 · 바이트 비교 복원) 빨강을 한 번 보인다. **리뷰가 스크래치 탐침으로 잰 판을 보고에 옮길 때는 값과 함께 탐침 원문(픽스처 · 좌표 · 점을 고른 식)을 옮긴다** — 다음 차수가 그 판을 케이스로 잠근다. 원문 없이 «칸 왼아래 점» 만 남은 판은 다시 지은 점이 다른 자리에 떨어져 카나리아가 먼저 죽었다(`docs/superpowers/plans/2026-10-27-fx-poa-report.md` «M3»). 트랙 게이트는 `README.md` 「게이트 — 무엇을 돌려 확인하나」 절의 «트랙 게이트» 표를 따른다 — `pnpm test:build` 의 둘째 갈래가 이 파일들이라(`export-bundle.test.ts` 만 첫째 갈래 `test:build:serial`) `test:browser` 를 함께 적지 않는다(Postgres 컨테이너가 떠 있어야 한다 — 없으면 건너뛰고 그 수를 적는다). 새 무거운 판을 새 vitest 프로젝트로 만들지 않는다 — `pnpm test` 는 `--project '!build'` 하나로 빼는데, 부정 패턴을 둘 주면 서로를 포함해 아무것도 안 빠진다. 끊김은 `startCutProxy`(고른 연결만 버림 · RST), 요청 둘 사이에 줄을 끼우려면 `queueRow` 로 판을 세운다. 이펙트 · 마운트 순서를 바꾼 트랙은 `EDITOR_STACK_BUNDLE=build pnpm test:browser`(운영 번들)도 돈다 — dev 는 `StrictMode` 로 이펙트가 두 번 돈다. **dev 번들의 실브라우저 판은 `StrictMode` 라 ref 콜백 · 이펙트가 두 번 돈다** — 그 자리에서 내는 줄 · 수(콘솔 줄 · 계측 호출)를 세는 케이스는 dev 판에서 두 배를 본다. 누름마다 한 번이어야 하는 것은 가드(`apps/web/src/drag/drag-debug.ts` 의 `once`)로 막고 수를 단언한다. **조회 실패 판을 `page.route` 로 세울 때 첫 요청만 끊지 않는다** — dev 번들은 마운트 이펙트가 두 번 돌아 둘째 요청이 판을 메운다. 그 경로 · 메서드의 요청을 전부 끊고 끊은 수 > 0 을 카나리아로 적는다(`apps/web/build-test/project-cards.test.ts` «… 목록 조회가 끊긴 판에서도 …»). **앞 차수의 판을 옮길 때는 고치기 전 소스의 빨강에 더해, HEAD 에서 그 고침만 떼는 변조를 돌린다** — 그 사이 들어온 장치가 가려 초록일 수 있다(떠남 기록이 큐 가드를 가려, 한 겹씩 떼면 초록 · 둘 다 떼야 빨강이었다). **서버에 닿기를 기다리는 폴은 실패 쪽 신호(건너뜀 · 거절 통지)도 끝 조건에 넣는다** — 번호만 기다리면 «10s 안에 안 섰다»로 죽어 무엇이 틀렸는지 값이 안 남는다(`editor-undo-restore.test.ts` 의 `landedOrSkipped`). 그 신호의 기준 수는 누르기 전에 센다 — 거절 프레임은 폴을 부르기 전에 닿을 수 있다(`apps/web/build-test/palette-preset.test.ts` 의 `landed`). **폴의 끝 조건에 누르는 순간 잠깐 서는 상태(답을 기다리며 닫혔다가 다시 서는 상자)를 넣지 않는다** — 고친 판도 변조 판도 같은 틈에서 끝나 «죽었다»가 구분력이 아니다. 답 뒤에만 서는 표지 · 서버 값으로 끝낸다(`apps/web/build-test/menu-cascade-delete.test.ts` «같은 수 · 다른 페이지»). **폴의 끝 조건에 단언할 값을 넣지 않는다** — 그 값을 깨는 변조가 단언 값이 아니라 시간 초과로 죽어 구분력이 안 남는다. 판이 섰다는 것(창 폭이 바뀌었다 · 줌이 실렸다)만 기다리고, 재는 값은 한 번 그린 뒤(두 프레임) 읽는다(`apps/web/build-test/editor-narrow-canvas.test.ts` 의 `settled`). **서버 문서를 글자로 견주는 폴 · 단언은 키 차례를 맞춘 뒤 견준다** — 서버는 JSONB 라 객체 키를 제 차례로 내, 보낸 값과 같은 문서가 `JSON.stringify` 로는 다르다. 키를 정렬해 짓는 글자(`apps/web/build-test/tree-items.test.ts` 의 `canon`)로 견주거나 `toEqual` 로 견준다. **트리 줄이 다른 부모로 옮겨졌는지는 화면 차례로 재지 않는다** — 메뉴의 하위 메뉴는 그 메뉴의 페이지들 뒤에 서서, «나» 뒤의 «다»를 «나» 밑으로 옮겨도 화면 차례가 같다. 줄을 품은 메뉴 줄로 잰다(`apps/web/build-test/menu-realtime.test.ts` 의 `parentRow`). **구조 트리 줄을 셀 때는 구조 트리 칸으로 좁힌다**(`.wb-shell-region[aria-label="구조 트리"] [data-tree-row]`) — `[data-tree-row]` 는 메뉴 트리 줄에도 붙는다. **`shownDrops` 의 `parent` · `prev` · `next` 는 캔버스 DOM 의 이웃이다** — 탭 패널의 몸통은 탭 아래로 읽히고, 구역 안의 노드는 그 부모의 모든 구역 · 몸통을 화면 차례로 이은 줄에서 이웃을 잡는다. 서버 문서와 견주는 자는 그 차례로 펴서 견준다(`apps/web/build-test/canvas-drop-review.test.ts` 의 `domOrder`). **빈 페이지의 캔버스 노드는 크기가 0 이라 `waitFor()`(기본 «보임»)가 안 선다** — 여는 판을 기다릴 때 `waitFor({ state: 'attached' })` 를 쓴다(같은 파일의 `openBob`). **긴 문서에서 «칸의 이 높이»를 겨눈 점은 노드 사이의 틈일 수 있다** — 틈은 문서 안의 바탕이라 페이지 끝으로 읽힌다. 노드 곁을 재려면 노드 상자의 띠(위 · 아래 25%)를 겨눈다. **섰다가 곧 거둬지는 통지를 판 카나리아로 쓸 때는 끝 화면이 아니라 DOM 에 선 횟수로 센다**(MutationObserver — `editor-marker-diverged.test.ts`) — 끝 화면만 보면 «판이 안 섰다»와 «섰다가 거뒀다»가 같은 값이다. **캔버스 문서는 same-origin iframe 이다 — 호스트 `document` · `window` 에 건 리스너는 캔버스 안의 `mousedown` · `keydown` · `pointermove` 를 못 받는다**(React 합성 이벤트는 portal 로 호스트 트리에 닿지만 네이티브 전역 리스너는 아니다). 전역 리스너를 새로 걸면 캔버스 문서에도 건다(`apps/web/src/canvas/canvas-document.tsx` 의 `useCanvasDocument` — 페이지를 옮기면 iframe 이 새로 서므로 이펙트의 의존에 둔다), 드래그는 `setPointerCapture` 로 붙잡는다. iframe 안 이벤트 대상은 그 창의 `Node` 라 호스트의 `instanceof Node` 가 거짓이다 — `nodeType` 으로 가른다. **고치기 전(main)과 같은 조작으로 견줄 때는** `git archive main | tar -x -C <스크래치>/main` 뒤 `pnpm install --frozen-lockfile --prefer-offline` · `pnpm build` 로 사본을 세우고 `apps/api/.env` 는 워크트리 것을 심링크한다 — 사본에는 `.git` 이 없어 `editorStackPrerequisite` 의 워크트리 가드가 서지 않으니, 심링크 대상이 워크트리 자기 포트인지 먼저 본다. 그 사본의 웹을 `editor-stack` 밖에서 띄우면 `vite --host 127.0.0.1` 을 준다 — 안 주면 `localhost`(IPv6)에만 떠 `127.0.0.1` 로 붙는 탐침 · 프록시가 못 닿는다. 케이스 파일은 문서 노드를 «iframe 이 있으면 그 안, 없으면 호스트» 에서 찾게 짜 두 트리에 같은 파일을 돌린다. **스크래치 탐침을 `tsx` 로 돌리면 esbuild 가 이름 붙은 함수에 `__name(…)` 을 끼워** `page.evaluate` · `addInitScript` 에 넘긴 함수가 페이지에서 `ReferenceError: __name is not defined` 로 죽는다(`addInitScript` 에서 죽으면 앱의 첫 렌더가 깨져 다른 판을 잰다) — 초기화 스크립트는 파일(`{ path }`)이나 문자열로 넘기고, `evaluate` 를 쓰는 탭에는 `globalThis.__name = globalThis.__name || ((f) => f)` 를 먼저 심는다. **`addInitScript` 는 문서 뿌리가 서기 전에 돈다** — `document.documentElement` 가 `null` 이라 뿌리에 속성 · 시트를 다는 초기화는 오류 없이 아무것도 안 한다. 뿌리가 서는 대로(`DOMContentLoaded`) 다시 달고, 그 줄만 뗀 변조로 잰다(`apps/api/src/services/screen-render-chromium.ts` 의 `CAPTURE_INIT`). **vitest 케이스에서 `page.evaluate` 에 넘긴 함수 안의 `import()` 는 `__vite_ssr_dynamic_import__` 로 바뀌어 페이지에서 죽는다** — 글로 넘긴다(`apps/web/build-test/layout-guides.test.ts` «자식 수백»). 글로 넘기는 함수(템플릿 문자열)의 정규식 · 문자열 이스케이프는 두 번 쓴다(`/\\s+/`) — 템플릿 문자열이 `\s` 를 `s` 로 풀어 오류 없이 다른 식이 된다. 넘긴 함수가 세는 값에 카나리아(알려진 글의 낱말 수)를 둔다(`docs/superpowers/plans/2026-10-25-fx-gr-report.md` 「지침」). **모달이 열린 동안 셸의 단추를 누르는 판은 상자를 닫는 걸음을 먼저 둔다** — 뒤 화면이 막혀 playwright 가 «다른 요소가 누름을 받는다»로 멈춘다(`apps/web/build-test/editor-restore-unanswered.test.ts`). **실브라우저 전량이 도는 동안 `apps/web/src` 를 고치지 않는다** — vite dev 가 뒤에 도는 파일에 고친 소스를 내줘 섞인 판이 된다. **playwright 의 `getByRole(…, { name })` 은 부분 일치다** — 같은 낱말을 이름에 품는 단추가 새로 서면(줄 행동 «… 더 보기») 기존 판이 `strict mode violation` 으로 판 만들기에서 죽는다. 셸의 고정 단추는 `exact: true` 로 찾는다. **단추는 보이는 글자가 아니라 접근 이름으로 찾는다** — 아이콘만 남은 단추는 글자가 없어 `textContent` 로 가르는 도우미가 이름은 그대로인데 죽는다(트리 줄 `+` · `…` 를 글리프로 가르던 `apps/web/test/panels/tree-row.ts` 의 `rowToggle` — 316 케이스). 셸의 아이콘 단추는 `aria-label` = `title` = 아이콘을 얹기 전의 글이다(`apps/web/src/shell/icons.ts` 머리말). 접근 이름을 새로 짓는 트랙은 그 이름을 조각으로 품는 기존 찾기를 `git grep` 으로 세고, 실브라우저 전량을 그 커밋에서 돈다. **한 판에서 같은 자리의 행동 메뉴 항목을 다시 누르면 앞 누름에서 `DOUBLE_CLICK_MS`(500ms)를 넘겨 누른다** — 포인터로 고른 항목 뒤 같은 자리(`DOUBLE_CLICK_SLOP` 안)의 클릭은 더블클릭의 둘째로 보고 삼켜(`apps/web/src/shell/action-menu.tsx`) 판 만들기가 다음 `waitFor` 의 시간 초과로 멈춘다 — 단언 값이 아니라 판이 안 선 것이다. **실브라우저 케이스가 응답 URL 의 부분 글자로 요청을 센다면 `apps/web/src` 에 새 파일을 더할 때 그 글자가 든 이름을 피한다** — Vite dev 가 소스 경로를 응답으로 내 가짜 요청 한 줄이 끼어 순서 단언이 빨강이 된다(`editor-restore-signal-order` 의 `/restore`). 새 파일을 더한 트랙은 URL 로 거르는 케이스의 응답 목록을 `git grep "url().includes"` 로 센다. **«포커스가 서면 …한다» 장치를 새로 걸면 포인터가 준 포커스를 먼저 센다** — 닫힌 목록 밑 줄의 삼켜진 둘째 클릭도 mousedown 으로 포커스는 준다(`tree-drag-review` «삭제 항목의 둘째 누름 …» 이 `confirm` 1 → 0 으로 죽었다). 키 · 코드가 준 포커스만 받게 `pointerdown` ~ `pointerup` 사이를 거른다(`panels/menu-tree.tsx` 의 `pointerFocus`). **포커스가 들면 화면을 바꾸는 장치는 그 안의 링크 · 이동 단추를 누른 판을 센다** — 누름의 포커스(`mousedown`)가 먼저 화면을 바꾸고, 그 뒤 `click` 이 데려간 대상이 바뀐 화면에서 가려진다(코멘트 묶음의 토큰 링크가 화면 상태를 바꿔 데려간 노드를 숨겼다 — `apps/web/src/panels/comment-panel.tsx` 의 `tokenLink`). 데려간 대상이 그 화면에서 숨는 픽스처로 실브라우저에서 잰다 — jsdom 의 `fireEvent.click` 은 포커스를 안 줘 그 차례가 안 선다. **사람의 몸짓을 시간으로 미루는 장치(더블클릭 간격 · 디바운스)는 간격 안에 다른 몸짓이 오는 판을 입구마다 센다** — 페이지 옮김 · 다른 고름 · 같은 값을 바꾸는 다른 입구 · 캔버스 누름 · 굴림. 미룬 일이 설 때의 렌더로 판정하면(최신 콜백을 ref 로 싣는 꼴) 그 사이의 몸짓이 판정의 입력이 되고, 값으로 견주는 다른 장치의 걷기도 설 때의 값을 기준으로 받아 빠진다 — 미룬 코멘트 묶음 고름이 트리에서 고른 노드를 500ms 뒤에 펼침으로 덮었고, 옮겨 간 페이지의 상태를 바꿨다(`docs/superpowers/plans/2026-11-14-rv2-cf-report.md` M-1 · M-2). 그 판이 막는 장치를 더 부르면 미루기 자체를 걷는 쪽을 먼저 본다(같은 보고 뒤 `docs/superpowers/plans/2026-11-17-fx2-cf-report.md`). 미루기를 남기면 그 누름 뒤 «그대로다» 를 곧바로 읽는 케이스를 센다 — 늦게 서는 동작을 못 봐 거름을 뗀 변조가 산다. 간격보다 넉넉히 뒤에 한 번 읽는다. **입구 · 단추를 걷거나 더하는 트랙은 이름 `git grep` 에 더해 실브라우저 전량을 게이트 전에 한 번 돈다** — 끝이 같은 이름의 첫 단추(`/추가$/` 의 `.first()`) · 역할 전부(`getByRole('tab')`) · 줄 상자 좌표(`x + 30`)로 찾는 판은 이름 인구조사에 안 걸리고, 같은 클래스 · 역할의 형제가 생기거나 줄 폭이 바뀌면 시간 초과 · `undefined` 로 죽는다(`action-menu-place` · `canvas-cost` · `tree-edge-scroll` · 우측 탭 클래스의 `.first()` 를 고른 탭으로 읽는 판 — `keyboard-holes` «우측 패널 탭» 은 탭을 앞에 더하자 정지점이 둘째로 갔다). **에디터 밖 화면의 케이스는 역할로 찾을 때 내용 칸(`.wb-shell-workspace-main`)이나 이름 있는 `nav`(«작업 공간» · «관리자»)로 좁힌다** — 뼈대 사이드바의 칸 목록이 같은 역할(`list` · `listitem` · `link`) · 같은 이름(«프로젝트»)을 가져, 범위 없이 찾던 케이스가 사이드바 칸을 제 줄로 읽는다. **행동 메뉴에 항목을 더하거나 빼면 목록 자리로 판을 세운 케이스를 센다** — 페이지 `…` 에 «상태 추가»를 더하자 «삭제» 가운데가 트리 마지막 줄 1px 밑으로 내려가 `tree-drag-review` «삭제 항목의 둘째 누름»의 판 카나리아(밑이 줄)가 죽었다. `git grep "name: '삭제'" apps/web/build-test` 로 세고, 고칠 때 공용 픽스처가 아니라 그 케이스의 판에 줄을 더한다(같은 파일의 다른 판이 «밑에 누를 것이 없다»에 기댄다). **트리에 줄을 새로 세우는 변경(구역 줄 · 상태 줄)은 트리 끌기 판의 겨눈 줄이 창 안 · 가장자리 자동 스크롤 띠 밖에 남는지 센다** — 줄이 늘면 겨눈 줄이 띠에 들어 끄는 동안 칸이 밀리고 표시가 한 줄 아래로 간다(`apps/web/build-test/canvas-drop-review.test.ts` 의 `armedOnRow`). 고칠 때는 그 판의 창 높이를 키우고 다른 판은 그대로 둔다. **끄는 동안만 서는 캔버스 그림(빈 구역 칸 · 미리보기)을 더하거나 키우는 변경은 끌기 전에 잰 상자로 겨누는 실브라우저 판을 센다** — 그림이 끌기 시작에 노드를 밀어 겨눈 점이 다른 노드 위로 간다(빈 구역 칸이 카드를 한 줄 남짓 키워 D1 · D2 판 일곱이 빨강이었다). 겨눌 상자는 `apps/web/build-test/editor-stack.ts` 의 `dragLayoutSettled` 뒤에 잰다(`canvas-drop-review.test.ts` 의 `grabTo` 는 함수를 받는다). 판을 고치기 전에 그 그림만 끈 판으로 원인이 그것 하나인지 가른다. 겨눌 점은 `dragLayoutSettled` 뒤 미리보기가 서기 **전에** 한 번 재고 그 자리에 머문다 — 미리보기가 선 뒤 다시 재면 미리보기가 민 대상을 따라가 포인터가 미리보기 위로 간다(«그 앞» 에 놓는 판 · `apps/web/build-test/grid-row-nested.test.ts` 의 `dragHandle`). 시스템 테마의 노드 높이(카드 머리줄 · 여백 · 글 줄)를 바꾸는 변경도 같다 — 칸이 미는 양이 테마마다 달라 끌기 전에 잰 가운데가 대상 밖이 된다(기본테마 2.0.0 에서 `canvas-drop` · `canvas-drop-review` · `canvas-preview` 다섯 판 — `docs/superpowers/plans/2026-11-13-sk-report.md` «기대가 바뀐 케이스»). **테마 CSS 가 배치(여백 · 크기 · 표시)를 형제 구조(`+` · `~` · `:*-child` · `:nth-*` · `:has()` · `:empty`)로 바꾸면 끄는 동안 캔버스가 죽을 수 있다** — 에디터는 미리보기를 `display: none` 으로 숨긴 배치로 놓을 자리를 재는데 형제 셀렉터는 숨긴 요소도 형제로 세어, 같은 포인터의 답이 뒤집히고 `Maximum update depth exceeded` 로 캔버스가 사라진다. 시스템 테마는 `system-themes/admin/test/admin.test.ts` «배치를 바꾸는 규칙은 형제 구조로 안 가른다» 와 `apps/web/build-test/admin-drag-sweep.test.ts` 가 잠근다 — 올린 테마에는 이 성질이 열려 있다(에디터 쪽 이월 · `docs/superpowers/plans/2026-11-13-sk-report.md` «결정» 17). **고치지 않고 이월하는 결함의 재현 케이스는 바라는 성질을 단언한 채 `it.fails` 로 커밋하고 머리말에 «고치면 `.fails` 를 뗀다» 를 적는다** — 빨강인 채 커밋하면 그 브랜치의 `pnpm test:browser` 전량이 늘 빨강이고, `it.fails` 는 결함이 있는 동안 초록 · 고치면 빨강이 되어 떼라고 알린다. `it.fails` 는 어디서 던져도 초록이라, `.fails` 를 붙이기 전 판(이미 붙였으면 `it` 으로 바꾼 임시 사본)을 한 번 돌려 실패 값이 바라는 성질의 단언에서 났는지 적는다 — 판 카나리아가 먼저 죽거나 시간 초과로 죽으면 결함을 안 재고도 «재현» 으로 남는다. 그 꼴은 `git show 273e64c2:apps/web/build-test/rv-pv-preview.test.ts` 의 머리말과 `it.fails` 케이스들에서 본다(지금 판은 고쳐 `it` 으로 바뀌었다). **실브라우저 케이스의 playwright 타입은 `playwright-core` 에서 가져온다**(`import type { Page } from 'playwright-core'`) — `playwright` 는 타입 검사에서만 «모듈 없음» 이고 vitest 는 타입 전용 import 를 지워 초록이다. 새 케이스 파일을 더한 커밋에서 `pnpm typecheck` 를 돈다. **에디터 뷰 모드의 «페이지 이동»(`navigate`)은 페이지를 안 옮긴다** — 알림 한 줄(«… 이 화면에서는 페이지를 옮기지 않습니다.»)만 선다. 뷰 모드 안에서 다른 페이지로 가는 판은 메뉴 트리 링크(`getByRole('link', { name, exact: true })`)로 세운다 — 번들은 그 단추가 다른 장 파일로 옮긴다(`docs/superpowers/plans/2026-11-17-rv-vs-report.md` 「1」).

**변조를 HMR 로 심어 실브라우저로 잴 때는 같은 판을 두 번 잰다** — 치환 직후 판은 옛 · 새 모듈 사이에 걸려 값이 흔들린다(스크린숏은 같은데 머리 높이가 갈렸다). 두 판이 갈리면 한 번 더 잰다.

**실브라우저로 끊김을 잴 때는 api 연결만 골라 끊는다.** 브라우저와 개발 서버 사이에 TCP 프록시를 두고 요청 줄(`GET /api/…/ws` · `PATCH …/ops`)이나 WS 프레임으로 골라 RST 한다 — 모든 소켓을 끊으면 HMR 이 페이지를 새로고침해 측정이 사라진다. `context.setOffline` 은 열린 WebSocket 을 안 끊어 끊김 판이 못 된다. **에디터의 편집은 WS(`patch` 프레임)로 나간다** — `page.route` 로 `…/ops` 를 가로채 편집 실패를 흉내 내면 가로챈 수 0 인 채 편집이 서버에 닿는다(REST 는 실시간 채널이 없을 때의 길이다 — `apps/web/src/edit/use-edit-commit.tsx`). 편집 실패는 `page.routeWebSocket` 으로 `patch` 프레임을 받아 `patch-error` 를 돌려주는 판으로 세우고, 가로챈 수를 카나리아로 적는다.

**좁은 반증은 앞 수정이 세운 장치만 겨눈다 — 그래야 멈출 때가 보인다.** 리뷰 대응이 새 장치를 세우면 그 장치**만** 겨눈 다음 리뷰가 **그 장치가 연 길**을 찾는다(예: 재전송에 연결 id 를 싣자 재기동을 넘어 남의 연결을 뺀다 · 판정을 가드 앞으로 옮기자 가드 앞 훅을 세는 자가 없다). 전량 리뷰를 다시 돌리면 그런 길은 넓은 표면에 묻힌다. **멈추는 기준은 «새 장치에서 높은 무게(인가 우회 · 남의 화면 · 데이터를 잃음 · 겹친 잠금)가 안 나왔다»** 다 — 낮은 것은 이월로 넘기고 병합한다. 대응이 **장치를 걷기만** 했거나 한 줄 면제처럼 작으면 다음 리뷰 없이 병합해도 된다 — 그 판단을 장부에 적는다. **폭주 · 반복을 줄이는 고침은 줄인 뒤 남은 것들의 마지막 값을 다시 잰다** — 폭주는 늘 가장 늦게 지은 값으로 끝나 추월을 가린다. 줄이면 먼저 지은 값이 마지막으로 남는 판이 드러난다(presence 방송을 K² 에서 2K 로 줄이자 나간 사람이 마지막 프레임으로 남았다 — 보내는 순간 짓게 했다). 반증 브리프에는 **«새 장치가 연 길인가 / 원래 있던 길인가»를 고치기 전 소스로 한 번 재서 가르게** 하고, 원래 있던 길은 병합을 막지 않는 이월로 넘긴다. **기다림을 세우는 고침은 그 기다림이 기다리는 값을 바꾸는 자리를 전부 센다** — 푸는 호출을 «오기를 기다리는 그 메시지»에만 걸면, 같은 값이 다른 길(내 요청의 응답 · 다른 응답)로 제 차례에 닿는 판에서 기다림이 한도까지 남는다(`EditorStore` 의 `'waiting'` 번호가 `ackEdit` 에서 안 풀렸다). **답을 버리는 자리(짝이 안 맞는 ack · 끊긴 조회)를 짚은 브리프는 그 뒤 루프가 무엇을 보내는지까지 재게 한다** — 비동기 루프는 답을 버린 뒤에도 이어 돌고, 만들 때 쥔 식별자(페이지 id)로 다음 일을 보낸다(편집 전송 루프가 앞 페이지의 버려진 ack 뒤 새 페이지 편집을 앞 페이지 경로로 내 서버가 받았다). 보내는 곳은 매 반복 큐의 주인에서 읽는다. **경쟁하는 답 가운데 하나만 싣게 하는 장치(세대 · 차례)를 세우면, 이기는 쪽이 «안 싣고 넘어간» 판에서 지는 쪽만 고칠 수 있던 상태가 남는지 센다** — 편집 실패 수습은 문서를 되돌리는 유일한 답인데, 재연결 재조회가 바탕만 견줘 «같다»로 판을 정하자 수습의 답이 버려져 거절된 편집이 화면에 남았다. **비동기 정리(수습 · 되돌림)가 «떠났으면 안 건드린다»를 지키는지는 가드가 첫 쓰기보다 앞에 있는지로 재고, 그 가드는 id 가 아니라 판으로 가른다** — 수습이 큐를 비운 뒤에야 «아직 열렸나»를 봐 옮겨 간 페이지의 편집을 말없이 비웠고, id 로 가르면 떠났다 돌아온 판에서 «안 떠났다»가 된다. 판을 갈아 끼울 때마다 오르는 수를 나갈 때 적어 두고 견준다. **입구 표가 있는 성질(판을 싣는 입구 · 편집을 내는 입구)을 닫는 장치는 «입구 × 값의 출처» 칸마다 판을 하나씩 세운다** — 한 입구만 재면 다른 입구의 앞선 가드가 장치에 닿기도 전에 돌려보내고(여는 조회는 판을 먼저 비워 프레임이 «열린 페이지 아님»으로 빠졌다), 머리말이 받는다고 적은 출처(프레임 · 내 ack · 번호 응답) 가운데 한 열이 빠지면 그 출처가 한 입구에서 조용히 샌다. **한 화면에 다른 문서를 실어 그리는 층(덮개 위 팝업 · 미리보기)은 그 문서 안의 요청도 같은 표로 푼다** — 표(번들 `hrefs` · 페이지 데이터)를 짓는 자리가 실린 문서까지 걷는지, 실린 문서 안의 요청마다(이동 · 열기 · 닫기) 판을 하나씩 세운다(`docs/superpowers/plans/2026-10-27-rv-poa-report.md` M1). **편집의 포인터를 판정에 넣을 때 그 좌표가 어느 문서의 것인지 센다** — RFC 6902 의 포인터는 앞 연산을 적용한 뒤 문서의 좌표이고 `move` 의 `path` 는 `from` 을 뺀 뒤 좌표다. 편집 전 문서의 경로와 견주는 판정은 앞 형제를 빼거나 넣은 묶음에 뚫린다(`packages/schema/test/lock-shifted-pointers.test.ts`). 판정 케이스에는 연산 하나짜리만이 아니라 앞 연산이 좌표를 미는 묶음을 싣는다. **포인터를 글자로 견주지 않는다** — 적용은 배열 번호를 `Number(token)` 으로 읽어 `01` · `1.0` · `+1` 도 `1` 이다. 판정은 적용과 같은 규칙으로 읽는다(`packages/schema/src/lock.ts` 의 `canonicalAt`). **버리던 것을 살리는 고침은 살아난 것이 뒤따르는 갈래(떠남 · 판째 버림 · 수습)에서 어떻게 끝나는지 센다** — 리베이스가 옮겨 살린 편집의 409 를 페이지를 옮긴 뒤 전송 루프가 말없이 넘겼다. **버린 것을 말하는 통지는 그 자리에서 버린 것을 전부 세고**(나간 것만 들면 함께 버린 안 보낸 것이 빠진다 · 버리는 자리가 여러 번 오면 합친다), **지우는 자리를 비켜 가게 만든 통지는 그 통지가 참이 아니게 되는 자리를 같이 센다**(새 편집만 푸는 통지는 편집을 못 내는 화면에서 셸이 사는 동안 남는다). **판정 사이에 기다림을 끼우면 기다림 앞의 판정을 기다림 뒤에 다시 부른다** — 기다리는 동안 떠남 · 리베이스 버림이 앞 판정의 전제를 바꾼다(409 뒤 번호 쓰기의 답을 기다리는 사이 떠나자 편집이 통지 없이 사라졌다). 앞 호출은 걷지 않는다 — 기다리지 않는 판은 앞 호출만 본다. **한도를 둔 확인을 여러 단계로 나누면 마감을 넘겨준다** — 단계마다 상수 한도를 새로 주면 한도가 단계 수만큼 곱해진다(잃은 COMMIT 확인이 결말 1s + 머리 1s 였다). 한도 단언을 좁히는 것만으로는 못 잰다 — 앞 단계가 한도 끝 가까이에서 성공해 뒤 단계에 닿은 판(뒤 단계의 질의를 붙잡음)을 세운다. **이력을 구간으로 받는 고침은 구멍이 여럿인 판을 센다** — 이미 가진 번호에서 구간을 끊으면 구멍마다 조회가 하나씩 들어, 둘이 번갈아 고친 페이지에서 회수 한도가 먼저 찬다. **고침에 반복(회차)을 넣거나 받는 때를 옮기면 그 반복이 둘째로 도는 판을 케이스로 세운다** — 한 번만 돌게 한 변조가 초록이면 반복을 재는 것이 없다. **«멈추고 받은 뒤 다시 시작한다»는 받은 뒤에도 모자란 판에서 또 멈추지 않는지 센다** — 받는 쪽에 한도(회수 · 서버에 없음)가 있으면 누를 때마다 같은 조회만 되풀이하고 아무것도 안 한다. 받은 뒤의 시작에는 «받을 만큼 받았다»를 싣는다(`EditorStore.startUndo` 의 `historyLoaded`). **화면을 내리는 동작(로그아웃)이 남길 말은 기다림의 앞뒤 차로 센다** — 기다림 뒤의 큐만 세면 그 사이 수습이 비운 편집과, 누르기 전에 시작해 아직 말하지 않은 수습의 몫이 빠진다(`EditorStore` 의 버림 누계). **«그 보내기가 거절됐다»를 «그 편집은 저장되지 않는다»로 읽지 않는다** — 큐에 남은 편집은 리베이스 뒤 다시 나갈 길이 열려 있어, 확정은 큐에서 빠진 뒤에만 선다(로그아웃 한 줄이 «거절»이라 말한 편집이 로그아웃 요청이 떠 있는 동안 다시 나가 커밋됐다 — `apps/web/build-test/editor-post-between.test.ts`). 거짓으로 읽히는 표시는 걷기 전에 하중부터 센다 — 몸체를 비워 죽는 케이스가 있으면 남기고 읽는 자리를 좁힌다. **통지를 지우는 조건은 입구를 세지 말고 세대에 매단다** — 사람이 바뀌는 입구마다 지우면 입구가 늘 때 빠진다(다른 탭 소식으로 들어온 사람이 나간 뒤 앞 사람의 로그아웃 한 줄이 로그인 화면에 다시 섰다). **도구의 기본 한도가 닿지 않는 호출에 기다림을 넣으면 그 단계만 한도 없이 남는다** — playwright 의 `page.evaluate` 는 `setDefaultTimeout` 을 안 받아, 그 안의 `document.fonts.ready` 가 한 장 한도(10s)를 넘겨 15s 를 기다리고 성공으로 끝났다(`apps/api/src/services/screen-render-chromium.ts` 의 `measure`). 기다림을 도구 호출 안으로 옮기는 고침은 그 호출이 한도를 받는지 먼저 본다. 정본 · README 에 «모든 입구가 …» 를 적을 때도 같다 — 그 성질을 지나는 입구를 `git grep`(그 검증 함수를 부르는 자리)으로 세고, 그 함수를 **안** 부르는 입구(저장된 값을 그대로 내주는 라우트 · 클라이언트의 모양 검사)가 있으면 문장을 입구마다 가른다.

**«혼자 안 죽는 케이스»가 늘 지울 것은 아니다.** 아무 변조에서도 안 죽으면 재는 척만 하는 것이라 지운다. 그런데 **죽기는 하는데 늘 남과 함께 죽는** 것은 다르다 — 그때는 **그 축을 소유하는 케이스를 이름으로 가리키게** 하고 남긴다. 그리고 **다시 잴 수 없는 수(«변조 몇 건» 같은 과거 실측의 흔적)는 자에서 뺀다** — 같은 수를 두 자리가 각각 적으면 그것도 두 벌이다. **성질 잠금 케이스가 그 성질을 부순 변조에 살아남으면** 케이스 머리말에 무엇을 못 재는지 적고 그 성질을 재는 케이스를 이름으로 가리킨다 — 같은 결과를 다른 길(뒤에 온 거절이 같은 통지를 다시 세움)이 만든다. **케이스 머리말의 «두 겹이 막는다 — 한 겹씩 떼면 초록»도 변조로 잰 뒤에 적는다** — 케이스가 기다림 지점으로 쓰는 상태(단추가 꺼질 때까지 기다림)는 그 상태를 만드는 겹의 단언이 되어 그 겹만 떼도 죽는다. 흉내 요소(같은 클래스의 `<p>`)로 세운 판은 부품이 고르는 **분기**(`role` · 종류에 따라 갈리는 갈래)를 흉내의 꼴로만 불러 한 갈래가 안 잰다 — 실제 부품으로 세운 케이스를 따로 두고 부품의 `role` 마다 판 하나씩 센다. **변조가 산 까닭을 «화면에 안 보이는 성질» 로 적기 전에 픽스처 밖 꼴로 한 번 잰다** — 꼴마다 «건드림» 카나리아를 둔 무작위 판이 그 자리다. 렌더러의 몫 자르기를 뗀 변조는 고정 픽스처에서 살아 «틈 0» 으로 적혔지만, 넓은 칸 뒤에 칸이 이어지는 꼴에서 값 칸이 1100px 움직였다(`docs/superpowers/plans/2026-10-25-rv-ft-report.md` L5).
