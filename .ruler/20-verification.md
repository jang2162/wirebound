# 검증 — wirebound

공용 「검증」(`base` 스택 `05-verification.md`) 위에 wirebound 가 더하는 것이다. 같은 제목의 절은 공용 절에 **덧붙는** 항목만 적는다.

## 「통과」를 보기 전에 몇 개가 실행됐는지 확인한다 — 덧붙임

- **정본 설계서(`docs/superpowers/specs/2026-08-03-wirebound-design.md`)를 고친 트랙의 게이트는 영역과 무관하게 전량 넷이다** — 그 문서를 읽는 케이스(`git grep -l "wirebound-design.md" -- '*.test.ts'`)가 `packages/mcp` · `packages/schema` 에 있다. web 트랙도 정본을 «지금 참인 것» 으로 고치므로 늘 놓친다(README 「트랙 게이트」 표).
- **건너뛴(skipped) 수도 적는다.** «없으면 건너뛰는» 자는 건너뛸 전제를 **실물로** 정한다 — 경로가 있는지가 아니라 띄워 보고(`apps/api/build-test/screen-chromium.test.ts` 의 `browserLaunches`). 경로로 정하면 문서대로 세운 기계에서 대부분을 건너뛴 채 통과로 끝난다.
- **셸은 zsh 다.** 따옴표 없는 `$VAR` 는 공백에서 안 쪼개져 테스트 경로 여럿이 한 경로로 읽히고 아무것도 안 돈다 — 배열(`"${T[@]}"`)을 쓴다. 줄바꿈 목록은 `F=("${(@f)$(…)}")` 배열로 받아 `"${F[@]}"` 로 넘긴다 — 따옴표 없는 `$F` 는 한 낱말이라 도구가 «대상 파일 없음» 으로 조용히 끝난다(`oxfmt` 는 `Expected at least one target file` 을 낸다). 그 배열을 heredoc 스크립트에 넘기는 명령은 에이전트 셸의 안전 검사가 못 읽어 거절한다 — 목록을 스크래치 파일에 쓰고 스크립트가 그 파일을 읽게 한다. 경로 목록을 `git add` 에 넘길 때도 같다 — 목록을 스크래치 파일에 쓰고 `git add --pathspec-from-file=<파일>` 로 넘긴다(`"${(@f)…}"` 배열 확장이 든 `git add` 를 안전 검사가 «rm 이 든지 읽을 수 없다» 로 거절했다). 테스트 경로 목록도 같다 — 그 배열 확장을 명령 줄에 쓴 `pnpm vitest run "${T[@]}"` 도 같은 문장으로 거절됐다(명령에 `rm` 이 없었다). 목록을 스크래치 파일에 쓰고 그 파일을 읽는 스크립트 파일로 부른다. `=` 로 시작하는 낱말은 명령 경로로 바뀌어 `echo =====` 가 명령 줄 전체를 죽인다 — 따옴표로 싼다. `${v:+-e X=$v}` 처럼 조건부로 인자 둘을 만드는 확장도 한 낱말이다 — docker 가 `-e " X=…"` 로 읽고 스모크가 대부분을 건너뛴 채 «통과»로 끝났다. `local -a args=(); [[ -n $v ]] && args=(-e "X=$v")` 로 배열을 만든다. 명령 여럿을 변수 하나에 담아 부르지 않는다(`P='docker … psql'; $P -c …` → `command not found`) — 함수로 만든다. 그 줄의 `;` 뒤 명령은 앞이 안 돌아도 돈다(재려던 조작은 안 되고 뒤의 `migrate:down` 만 돌았다). 변조 결과가 «0 사망»이면 실행 수부터 본다. 변수 바로 뒤의 `[…]` 는 배열 첨자로 읽혀 `bad math expression` 으로 죽는다 — `"${w}[^|]*"` 처럼 중괄호로 끊는다. 변수 바로 뒤의 `:` 도 수식어로 읽힌다 — `"$R:path"` 는 `bad substitution` 이다. `"${R}:path"` 로 끊는다. BSD `sed` 는 한글이 든 입력에서 `illegal byte sequence` 로 죽으니 한글을 가르는 센 일은 파이썬으로 한다. macOS `unzip` 은 한글 경로가 든 번들 zip 을 깨진 이름으로 풀다 «disk full?» 로 멈춘다 — 번들은 파이썬 `zipfile` 로 읽는다. 단계의 종료 코드는 그 명령 바로 뒤에 `rc=$?` 로 잡고 적는다 — `echo "$(date +%T) … $?"` 의 `$?` 는 명령 치환의 것이라 늘 0 이다(실패 10 인 단계가 `exit 0` 으로 적혔다). 단계 줄의 종료 코드만 보고 통과로 적지 말고 그 단계의 json 실패 수를 함께 센다.
- **게이트 · 변조 스크립트는 판의 런타임을 스스로 증명한다.** `cd` 뒤 `eval "$(mise env -s zsh)"` 를 두고 첫 줄에 `node -v` 를 상태 파일에 적는다 — 런타임이 다른 판은 결과와 무관하게 버린다. 신뢰 안 된 워크트리는 `mise` 가 설정을 거절해 PATH 의 다른 Node 가 잡히고(세팅 자체는 `10-worktree.md` 「생성 직후 세팅」 의 `mise trust && mise install`), Node 22 에서는 jsdom `Blob` 판정 넷(`apps/web/test/api/http-client.test.ts` · `theme-client.test.ts`)이 빨강이다. 판의 Node 를 안 적은 판은 뒤에서 못 가른다.
- **`-t` 로 좁힌 변조 실행의 실행 수는 `통과 + 실패` 로 적는다** — vitest json 의 `numTotalTests` 는 필터가 건너뛴 케이스까지 센다(120 케이스 파일에서 4 케이스를 돌려도 120). 실행 수 0 의 판정도 `통과 + 실패` 가 0 인지로 한다.
- **api 케이스의 `inject` 를 감싸는 도우미는 `payload` 를 `unknown` 으로 받지 않는다** — `inject` 오버로드 셋 어디에도 안 맞아 호출부의 `.statusCode` · `.json()` 이 전부 타입 오류인데, vitest 는 타입을 안 보아 케이스는 초록이다(`apps/api/test/snapshots.test.ts` 머리말). `Record<string, unknown>` 으로 받고, 공용 도우미를 세운 커밋에서 `pnpm typecheck` 를 한 번 돈다.
- **마이그레이션의 `down` 을 바꾸는 변조는 api 프로젝트로 판이 안 선다** — global-setup 이 `migrateToNone` 으로 모든 `down` 을 지나(`apps/api/test/global-setup.ts`) 빈 DB 에서도 거절하게 바꾼 변조는 판 세우기에서 죽어 실행 0 으로 끝난다. 그 `down` 의 «비면 내려간다» 는 변조 표에 «안 잼» 으로 적는다(`docs/superpowers/plans/2026-10-24-ci-a-report.md` D2).

## 숨은 글자를 이스케이프로 쓴 파일은 쓴 뒤 바이트로 센다

제어 · 방향 제어 · 폭 없는 글자 · 서로게이트를 `\uXXXX` 로 쓴 파일은 도구 입력 층이 날글자로 풀어 쓰는 판이 있다.

- **Why:** 정규식 리터럴 안의 날 U+2028 은 구문 오류이고, 케이스 · 문서에는 안 보이는 방향 제어 글자가 섞인다. 변조 스크립트의 찾는 글자가 날글자가 되어 맞은 수 0 으로 변조가 안 돌았다.
- **How to apply:** 커밋 전에 바뀐 파일에서 그 글자 범위를 파이썬으로 세고, 0 이 아니면 이스케이프로 되돌린다. 스크립트로 넘길 때는 `chr(92) + 'u2028'` 처럼 글자 조합으로 짓는다. 새 파일도 같다 — `heredoc` 로 쓴 새 파일도 날글자로 풀려 정규식 안의 U+2028 은 구문 오류가 된다. 문서(보고 · 계획 · 설계)에서 숨은 글자를 가리킬 때는 이스케이프 꼴이 아니라 이름(«U+202E»)으로 적는다 — 파일 도구가 이스케이프를 날글자로 풀어 문서 글을 뒤집는다. 스크래치 초안에서 옮겨 붙이는 글도 커밋 전에 같은 셈으로 센다.

## build 프로젝트에서는 `*.css?raw` 가 빈 글자다

루트 `vitest.config.ts` 의 `css.include` 는 unit 프로젝트에만 있어 `--project build` 에서 `theme.css?raw` 는 빈 글자로 읽힌다.

- **Why:** 빈 글자와 견주는 단언(`toContain(css.slice(0, 200))`)은 `toContain('')` 이 되어 늘 참이다 — system-admin build-test 가 그렇게 아무것도 안 쟀다.
- **How to apply:** build-test 에서 소스 CSS 가 필요하면 `readFileSync` 로 읽고 `length > 0` 카나리아를 함께 둔다. 빌드된 `theme.css` 는 줄인 글자라 소스와 글자로 견주지 않는다 — 토큰 기본값(`--wb-<키>: <값>;`)처럼 뜻이 같은 조각으로 잰다. **스크래치 탐침 설정도 같다** — 루트 설정에서 `resolve` · `esbuild` 만 실은 스크래치 설정은 `css.include` 가 없어 `ADMIN_V0_CSS` 같은 `?raw` CSS 가 빈 글자다(기본테마 CSS 없이 잰 판이 «세그먼트 규칙이 안 먹는다» 로 읽혔다 — `docs/superpowers/plans/2026-10-24-rv-ci-report.md` 「지침」). 탐침은 테마 CSS 를 `readFileSync` 로 읽고 `length > 0` 카나리아를 둔다. **테마 CSS 만 실은 정적 판은 토큰이 비어 크기가 실제와 다르다** — 테마 규칙은 `var(--wb-…)` 로 크기를 읽어, 토큰이 없으면 브라우저 기본값(16px)으로 잰다. `@wirebound/themes` 의 `tokensCss(manifest)` 를 먼저 싣고 잰다. **내보낸 번들(file://)의 시트는 CSSOM 으로 못 읽는다** — 번들 페이지에서 `document.styleSheets[…].cssRules` 는 file:// 시트에 `SecurityError` 를 던지고, 감싼 `try` 가 조용히 넘겨 «규칙 0 개 걷음» 인 채 원래 테마로 잰다(1.7.0 근사 판이 두 번 그렇게 섰다). 테마 규칙을 걷거나 바꾼 판은 번들의 `assets/theme/theme.css` 를 열기 전에 파일째 고치고(postcss), 걷은 규칙 수 · 남은 셀렉터 수를 카나리아로 적는다.

## `apps/*`·`packages/*`·`system-themes/*` 바로 밑에 `tsconfig*.json` 을 새로 두지 않는다

루트 `pnpm typecheck` 는 `tsc --build --force packages/*/tsconfig*.json apps/*/tsconfig*.json system-themes/*/tsconfig*.json` 이다 — **그 글롭에 걸리는 파일은 전부 빌드된다.**

- **Why:** 도구가 읽으려고 둔 설정(워커 로더용 tsconfig 등)이 그 이름이면 `pnpm typecheck` 가 그것까지 `tsc --build` 하고, `outDir` 이 없으면 **소스 옆에 `.js`·`.d.ts`·`.map` 을 수백 개 흘린다.** `git status` 에 뜨지만 수백 줄에 묻힌다.
- **How to apply:** 타입검사 · 빌드용이 아닌 tsconfig 는 그 글롭에 안 걸리는 이름(예: `export-worker.tsconfig.json`)으로 두고 `noEmit` 을 건다. **한 앱의 케이스가 다른 앱의 소스를 쓰려면 정적 `import` 대신 실행 때 경로로 싣는다**(`await import(fileURLToPath(new URL(…, import.meta.url)))` — `apps/web/build-test/form-primary-button.test.ts`). 정적 `import` 는 그 파일을 이 프로젝트의 빌드에 끌어들여 타입검사가 실패하면서도 소스 옆에 산출물을 흘린다 — `git status` 에 `.js` 가 뜨면 지우고 게이트를 다시 돈다.

## 타이머로 이벤트 루프 멈춤을 잴 때는 끝에서 한 번 더 잰다

`setInterval` 은 **다음에 불릴 때** 간격을 적는다.

- **Why:** 일의 **맨 끝**에 선 멈춤은 `clearInterval` 이 먼저 와서 적히지 않는다 — 그 자리를 멈추게 하는 변조가 살아남는다.
- **How to apply:** 재는 구간이 끝나는 자리에서 마지막 간격을 한 번 더 재서 최댓값에 넣는다.

## 목 · 계측은 불린 수를 값으로 확인하고, 재는 요청이 잴 대상을 건드리지 않게 한다

목 팩토리 · 감싼 함수가 **한 번도 안 불려도** 테스트는 오류 없이 돈다 — 그 목이 세는 수는 초기값에 머물러 «0 건»이 통과로 읽힌다. 재는 요청(폴링 · 헬스 체크 · 탐침)이 잴 대상과 연결 · 캐시 · 잠금을 나눠 쓰면 잴 현상을 스스로 없앤다.

- **Why:** api 프로젝트의 `setupFiles` 가 앱 모듈 그래프를 테스트 파일보다 먼저 적재하므로 테스트 파일의 `vi.mock` 은 이미 적재된 모듈에 닿지 않는다 — 잠금 경주의 «정확 표지 0»이 그렇게 나왔다. keep-alive 로 남은 연결이 `close()` 를 붙잡는 현상은 폴링이 같은 연결을 재사용하자 닫는 중인 서버가 그 연결을 끊어 사라졌다.
- **How to apply:** api 테스트에서 모듈 목이 필요하면 `vi.resetModules()` 뒤 `helpers` 를 동적으로 다시 적재한다(지금 그 꼴을 쓰는 파일은 없다 — 옛 예는 `git show 74528d6b:apps/api/test/theme-choose-gone.test.ts` 의 `vi.resetModules()` · `await import('./helpers')`. 그 꼴로 받은 `signup` 을 픽스처로 세는 자는 `apps/api/test/user-creation-census.test.ts`). 목 · 계측을 쓴 값은 **호출 수를 함께 적고**, 계측이 가르는지 **없애야 할 것을 되살린 변조**로 한 번 센다(0 이 아니게 나와야 한다). 세는 자에는 «재는 동안 0 이면 죽는» 카나리아를 둔다 — 세는 도구가 없는 기계에서 자가 0 과 0 을 견주게 된다(`ps` 가 없는 `node:22-slim` 에서 프로세스 수가 늘 0 이라 수명 케이스가 초록이었다). 탐침은 잴 대상과 **다른 연결 · 다른 세션**으로 보낸다. 스크래치 탐침이 체크아웃의 패키지를 직접 부르면(`kysely` 등) 맨 이름 `import` 는 스크래치에서 안 풀린다 — 체크아웃의 `apps/api/node_modules/<패키지>` 절대 경로로 동적 `import` 한다. 실브라우저 · 렌더러 탐침도 같다 — `fflate` 는 `apps/web/node_modules/fflate/esm/index.mjs`, `@testing-library/react` 는 `packages/renderer/node_modules/@testing-library/react` 의 절대 경로로 싣고, 스크래치 `.tsx` 의 JSX 는 `react/jsx-dev-runtime` 을 못 찾아 수집에서 죽으니 `.ts` 로 두고 `createElement` 로 지은 요소를 넘긴다(`docs/superpowers/plans/2026-10-27-rv-pob-report.md` 「잰 판의 수」). **스크래치 탐침을 테스트 글롭에 안 넣고 api 하네스로 돌리려면** 스크래치에 vitest 설정을 두고 `root` 를 체크아웃, `test.dir` 을 스크래치로, `globalSetup` · `setupFiles` 를 api 프로젝트의 것으로 준다(`resolve.alias` 는 루트 설정에서 읽어 싣는다) — 전량 게이트가 도는 중에도 그 실행이 탐침을 줍지 않는다. 하네스 없이 제 DB 를 만드는 스크래치 탐침은 테스트 DB 주소를 `.env` 글자로 읽지 말고 `apps/api/test/test-database-url.ts` 의 `resolveTestDatabaseUrl({ shellEnv: process.env, fileEnv: readApiEnvFile() })` 로 짓는다 — 워크트리의 `.env` 에는 `TEST_DATABASE_URL` 줄이 없을 수 있다(`POSTGRES_PORT` 에서 짓는다). 실브라우저 탐침(`editor-stack`)도 같다 — 스크래치 설정의 `root` 를 체크아웃으로 두고 루트 설정의 `build` 프로젝트에서 `esbuild` · `resolve` 를 실으며(`vitest.browser.config.ts` 와 같은 꼴), `editor-stack` 은 체크아웃의 절대 경로로 `import` 한다. 고치기 전 사본에 돌릴 때는 그 경로를 사본으로 바꾼 사본 파일을 쓴다. 고치기 **전** 값이 예상과 다르면 먼저 재는 자가 대상을 건드리는지 본다. **«잰 수 0» 을 문제로 세우는 자는 0 이 옳은 판과 대상을 못 찾은 판을 가른다** — 대상을 꼴 없이 한 번 더 찾아(가장 가까운 노드가 그 부모인 요소) 꼴로 찾은 수와 견주고, 둘이 다를 때만 문제로 낸다. «0 이면 문제» 는 좁은 창에서 라벨이 위로 가 잴 쌍이 없는 기본테마 390 판을 죽였다(`docs/superpowers/plans/2026-10-25-fx-ft-report.md` M1 «결정»). **`waitFor` 콜백 안에 DOM 을 바꾸는 읽기(메뉴를 열고 닫는 도우미)를 두지 않는다** — 단언이 끝내 안 서면 그 변경이 관찰자를 다시 깨워 마이크로태스크가 끝없이 돌고 시간 한도도 못 와 값 없이 멈춘다. DOM 을 안 바꾸는 값(불린 수)을 기다린 뒤 한 번 읽는다(`apps/web/test/panels/menu-crud.test.tsx` 의 `sent`). **«줄을 안 선다» 를 재는 케이스는 줄 섰는지의 값을 먼저 읽고, 붙잡은 쪽을 놓은 뒤에 답을 기다린다** — 놓기 전에 답을 기다리면 줄을 서게 만든 변조가 값(`'queued'`)이 아니라 시간 초과로 죽는다(`apps/api/test/rv-ac-deactivate-inflight.test.ts` 의 `settledOrQueued`). `pg_stat_activity` 로 다른 연결을 기다릴 때는 `pid <> pg_backend_pid()` 를 걸고, 트리거 · 함수 안의 잠은 `query` 글자가 아니라 `wait_event = 'PgSleep'` 으로 본다(`query` 는 최상위 문장이고 자기 조회문에 걸려 늘 1 을 센다). «읽은 값으로 뒤에 행동하는» 창을 넓힐 때는 그 질의의 **응답 바이트만** 늦춘다 — 잠금으로 읽기를 막으면 스냅숏이 대기 뒤에 잡혀 창이 사라진다. COMMIT 만 느리게 하려면 `DEFERRABLE INITIALLY DEFERRED` 제약 트리거에서 `pg_sleep` 을 부른다. **이벤트로 풀리는 상태를 잴 때는 판을 세우기 전에 앞 동작의 이벤트까지 받는다** — 결과가 보이는 것(파일의 글자 · 응답 본문)은 그 동작의 콜백이 돈 것이 아니다. 늦게 온 앞 이벤트가 재려던 장치 대신 상태를 풀면 그 장치를 뗀 변조에도 초록이다(`apps/api/test/log-destination.test.ts` 의 «공간이 차면»). **`WsProbe.waitForCount` 처럼 프레임이 N 개까지 안 찼다고 던지는 기다림으로 «신호가 안 간다» 를 재지 않는다** — 그 신호를 끈 변조가 값이 아니라 시간 초과로 죽는다. 커밋 같은 앞선 사건은 DB 값으로 기다리고, 프레임 목록은 던지지 않는 짧은 기다림 뒤 `toEqual` 로 견준다(`apps/api/test/late-commit-stale.test.ts` 의 `expectStale`). **`WsProbe.quiet()` 는 부른 뒤에 온 프레임만 낸다** — 방송은 응답을 안 기다려 응답보다 먼저 닿을 수 있다. 걸음 **앞에** `received.length` 를 적어 두고 창 뒤에 그 뒤를 센다(`apps/api/test/comments-changed.test.ts` 의 `mark`). **가득 찬 디스크를 `/dev/full` 로 흉내 내지 않는다** — `/dev/full` 은 0 바이트 쓰기도 ENOSPC 로 거절하지만 가득 찬 파일시스템은 0 바이트를 받고 1 바이트만 거절한다. 0 바이트로 살아 있는지 확인하는 코드는 두 판에서 다른 길로 간다(되풀이 멈춤은 tmpfs 로만 선다). tmpfs 판은 `apps/api/build-test/log-destination-full-disk.test.ts` 가 잰다(자식을 한 파일로 묶어 `docker cp` — 이미지는 받지 않고, 없으면 건너뛴다). **비멤버의 요청은 가드에서 끝나 재확인까지 못 간다** — 멤버십이 바뀌는 순간의 겹침은 가드의 멤버 조회(잠그지 않는 판) 앞에 세운다(`apps/api/test/guard-in-lock.test.ts` 의 `GUARD_MEMBERSHIP`). **가짜 시계로 재는 코드는 시계를 부를 때마다 찾게 둔다** — 기본 인자 `now = Date.now` 는 만든 순간의 진짜 함수를 쥐어, 앱을 세운 뒤 건 `vi.useFakeTimers({ toFake: ['Date'] })` 를 못 본다. `() => Date.now()` 로 둔다(`apps/api/src/auth/login-limit.ts` 의 `createLoginLimiter`). **`withApi` 는 케이스 전체가 한 트랜잭션이라 `now()` 가 문장마다 같다** — 쓰기가 고치는 시각(`updated_at` 등)을 «앞보다 늦다» 로 재는 단언은 늘 거짓이라, 그 케이스는 `withRealApi` + `resetRealData` 로 세운다(`apps/api/test/project-list-fields.test.ts` 머리말). **파일 권한으로 인가하는 입구(유닉스 소켓 · 공유 디렉터리)는 서버와 클라이언트가 둘 다 자리의 주인을 본다** — 서버만 막으면 공유 `/tmp` 에서 남이 먼저 만든 자리에 클라이언트가 붙어 본문을 넘기고 가짜 답을 믿는다(`apps/api/src/auth/unlock-socket.ts` 의 `privatePlaceProblem` — Linux 비루트 둘로 잰다). **«포트를 쥐었으니 같은 것이 없다»로 자리를 지우는 장치는 HOST 가 다른 판을 센다** — 남은 파일은 지우기 전에 붙어 본다. **스크래치패드 아래에는 유닉스 소켓을 못 연다**(경로 한도 macOS 103 · Linux 107 바이트) — `os.tmpdir()` 아래에 연다. **Node http 의 `requestTimeout` 은 `connectionsCheckingInterval`(기본 30s) 주기로만 검사된다** — 한도를 그보다 짧게 두면 주기를 함께 준다. **프로세스 여럿의 메모리는 RSS 합이 아니라 cgroup `memory.current` 로 잰다**(chromium 은 페이지를 나눠 RSS 합이 세 배로 나온다). **클라이언트 주소는 이 기계의 게시 포트로 못 잰다** — Colima 가 넘긴 요청은 전부 네트워크 게이트웨이 하나로 보인다. 앞단 뒤 주소 키는 같은 compose 네트워크에 고정 주소를 준 컨테이너 둘로 잰다. **일마다 따로 서는 시계(쉬는 시간 · 만료)를 재는 케이스는 일 여럿이 같은 때 끝난다고 기대지 않는다** — 붐빌 때 두 일의 끝이 그 시간보다 벌어져 앞 것이 먼저 만료된다. 그 시계만 가짜로 둔다 — `toFake` 에 `setImmediate` 를 넣지 않는다(일 경로의 양보가 그것이면 안 풀린다 · `apps/api/test/export-worker.test.ts` «쉬는 워커»). **목록의 수로 «끝냈다»를 재면 목록에서 빼고 안 끝내는 변조가 산다** — 끝내는 호출을 함께 센다. **가짜 origin(https)에서 바깥 요청 차단을 잴 때는 서버 적중만 세지 않는다** — 브라우저가 루프백 http 하위 요청을 스스로 막아(혼합 콘텐츠 · Local Network Access) 차단을 뗀 변조에도 초록이다. 차단이 끊은 주소(`Route.abort` 를 감싼 수)를 함께 세고, **`context.route` 가 아예 안 보는 채널**(WebSocket · WebRTC STUN/TURN · WebTransport · 공유 워커 · 서비스 워커)은 채널마다 다른 127.0.0.1 포트의 리스너가 받은 연결 · UDP 바이트로 센다(`apps/api/build-test/screen-sandbox-review.test.ts`). 헤드리스 셸과 전체 Chromium 은 같은 인자에 다르게 선다 — 운영 갈래 바이너리로도 잰다. **Fastify `inject` 는 요청 경로의 점 구간(`..` · `./` · `%2e`)을 라우팅 전에 WHATWG 규칙으로 풀어 서버가 받지 않는다** — 경로 우회를 재는 케이스는 `withRealApi` 위 원시 `node:http` 요청으로 보내고, 같은 길로 정확한 이름이 200 인 카나리아를 함께 둔다(`apps/api/test/theme-packages-read.test.ts`). **`HTMLElement.prototype.addEventListener` 를 엿보면 React 가 뿌리 · portal 컨테이너에 거는 모든 이벤트(캡처 포함)가 함께 잡힌다** — 그 요소에 건 것만 `mock.contexts[i] === 요소` 로 거른다(`apps/web/test/drag/drag-debug.test.tsx` «꺼진 판»). jsdom 의 `window.addEventListener` 를 `mockImplementation` 으로 감싸 `EventTarget.prototype.addEventListener.apply(window, …)` 로 넘기면 `not a valid instance of EventTarget` 으로 던진다 — 감싸지 말고 엿보기만 한다. **호출자를 스택으로 세는 계측은 `Error.stackTraceLimit` 를 올리고 센다**(기본 10 이 테스트 프레임을 자른다) — 서버 요청 안처럼 스택에 테스트 프레임이 안 남는 자리는 값(노드 id)으로 가르고, «프레임 없음» 이 남으면 그 수를 함께 적는다. **늦은 커밋 지켜보기의 꼬리를 붙잡을 때는 `holdQuery` 가 아니라 `swallowQueries('pg_xact_status(x)')` 다** — 지켜보기는 한 번 묻기에 1s 한도를 두고 연결째 버린 뒤 다시 묻는다. 붙잡기는 첫 묻기 하나만 잡아 꼬리가 1.5s 안에 나간다. 그 조각은 요청 안의 확인(`pg_xact_status($1::xid8)`)에 안 맞아 503 은 그대로 난다(`apps/api/test/late-commit-stale.test.ts` 의 `LATE_PROBE`). **키를 여러 포커스 자리에서 훑는 탐침은 자리마다 판을 되돌린다** — 앞 자리의 키가 뒤 자리의 판을 바꾼다(검색 칸의 Cmd+V 가 복사한 노드 JSON 을 검색어로 받아 카드가 0 이 되고 다음 자리의 `focus` 가 시간 초과로 죽었다). 자리를 옮기기 전에 칸을 비우고, 자리마다 그 판이 섰는지(카드 수)를 카나리아로 적는다. **행동 메뉴 항목의 끔과 꺼진 까닭이 다른 값에서 지어지면 케이스는 둘 다 단언한다** — 까닭 글(`apps/web/test/panels/tree-row.ts` 의 `rowReason`)만 보면 끔을 뗀 변조가 산다. `isOff` 를 함께 둔다(`apps/web/test/panels/grid-row-actions.test.tsx`). **대조군은 옳은 갈래와 그른 갈래가 다른 값을 내게 짓는다** — 되돌리기 판의 두 편집이 같은 수(열 수)를 바꾸면 «되돌리기 revision 을 되돌림» 과 «처음 편집을 되돌림» 이 같은 값이 되어 대조가 아무것도 안 가른다. 두 편집은 서로 다른 노드 · 다른 칸을 바꾼다(`docs/superpowers/plans/2026-10-26-rv-grb-report.md` M6). **기대값을 페이지에서 읽는 단언은 그 기대값이 잰 값에서 지어지지 않는지 본다** — 자식에 맞춰 줄어드는 그릇(덮개 틀 `[data-wb-popup-frame]`)의 폭은 늘 자식 폭이라 «폭 = min(크기, 그릇 폭)» 이 늘 참이다. 설 자리는 줄지 않는 조상(`[data-wb-popup-level]` 폭 − 여백)에서 읽고, 기대값을 바꾸는 변조(크기 480 → 500)로 한 번 죽인다(`apps/web/build-test/popup-attach.test.ts`). **pino 로그에서 값을 가리는 장치는 칸마다 센다** — 요청은 `req`, 오류는 `err`, 문장은 `msg` 시리얼라이저다. 문장 칸을 `hooks.logMethod` 로 덮지 않는다 — pino 가 문장 없이 오류만 실은 줄(`log.warn({ err })`)에 옮겨 적는 오류 문장은 메서드 인자가 아니라 그 훅을 지난다. `msg` 시리얼라이저는 `%s` 를 채운 뒤의 글자와 그 옮긴 문장을 다 받는다(`apps/api/src/http/log-mask.ts` 머리말).

## 스크래치패드를 `docker run -v` 로 붙이지 않는다

스크래치패드(`/private/tmp/…`)는 도커 런타임의 공유 경로가 아니다(이 기계의 런타임은 `docker context ls` 로 본다 — 지금은 Colima).

- **Why:** `-v` 로 붙이면 **오류 없이 빈 디렉터리**가 붙는다 — 탐침 스크립트가 파일을 못 찾고 출력 디렉터리가 빈 채 끝나, 아무것도 안 잰 판이 결과처럼 보인다.
- **How to apply:** 공유 경로는 런타임마다 다르니, 붙이기 전에 `docker run --rm -v <경로>:/m alpine ls /m` 가 빈 줄을 내는지 본다. 파일은 `docker create` → `docker cp` → `docker start -a` 로 넣고 뺀다. 저장소를 컨테이너에서 잴 때는 `git archive HEAD | docker run -i … tar xf -` 로 넘긴다 — 마운트가 비면 `packageManager` 를 못 읽은 corepack 이 다른 pnpm 을 받아 엉뚱한 곳에서 죽는다.

## 사람이 칠 셸 절차는 대화형 셸에 사람처럼 쳐서 잰다

`bash script.sh` 로 돌리면 사람이 칠 때 나는 일이 안 보인다.

- **Why:** README 의 비밀번호 재설정 절차가 스크립트로는 맞았는데, 대화형 셸에서는 붙여 넣은 다음 줄을 `read` 가 먹어 빈 비밀번호로 잠갔고 · 대화형 zsh 가 `#` 줄을 명령으로 읽어 구문 오류를 냈고 · Ctrl-D 에도 다음 줄이 돌아 빈 해시를 넣었다.
- **How to apply:**
  - pty 에 한 줄씩 친 판과 **통째로 붙여 넣은 판**(브래킷 · raw)을 함께 잰다. 통째로 붙여 넣은 판은 **한 번에 도착한 판**과 **조각으로 늦게 도착하는 판**(예: 16바이트/125ms)으로 나눈다 — 물음 전 입력을 시간 창으로 버리는 장치는 창 뒤에 온 줄을 답으로 먹고, 조각 경계에서 잘린 줄을 셸로 넘긴다.
  - 신호 판은 스크립트 프로세스 하나에만 보내지 말고 **전경 그룹째**(`kill -HUP -<pgid>`)로도 보낸다 — 부모(`tsx`)가 tty 를 되돌려 가리는 결함이 그룹 판에서만 보인다.
  - pty 하네스는 master 쓰기를 비차단으로 하고, 막히면 출력을 읽으며 기다린다 — 막는 쓰기는 되비춤 출력이 차는 순간 셸과 서로 기다린다. **조건을 기다리는 동안에도 master 를 읽는다** — 포트 · 헬스만 폴링하고 안 읽으면 zsh 가 명령 줄을 다 그리지 못해 명령이 안 돌고, 뒤에 보낸 줄과 함께 풀려 다른 판을 잰다. 명령이 돌기 시작했는지(서버 pid 의 부모가 그 셸인지)를 값으로 확인한다.
  - **pnpm 아래의 신호 판은 저장소 안에서 잰다** — 깔린 pnpm 판이 `packageManager` 와 다르면 바깥 pnpm 이 그 판을 자식으로 띄우고, 터미널이 닫혀도 서버에 SIGHUP 이 안 간다. 저장소 밖 빈 패키지로 만든 탐침은 받는다.
  - **기동 방식에 따라 스스로 닫히는 장치(부모 · 터미널 감시)는 부모가 먼저 끝나는 정상 기동을 전부 잰다** — `nohup … &` 뒤 셸 종료 · `disown` · 준비 대기 래퍼 · `docker exec` 래퍼 · 이중 fork · 서비스 관리자. «부모가 바뀌었다»만 보는 감시는 그 기동들에서 정상 서버를 1초 안에 껐다.
  - **터미널을 닫는 판은 신호로 흉내 내지 말고 pty master 를 닫아 잰다** — 닫힌 tty 로의 쓰기가 EIO 로 막혀, 흉내 판에서 초록인 서버가 영영 안 끝났다. 그리고 **같은 신호가 두 번 오는 것을 정상 경로로 센다** — `pnpm start` 아래에서 터미널의 Ctrl-C 하나가 node 에 두 번 닿는다(전경 그룹 + pnpm 의 되전달).
  - 값을 받는 절차는 셸 조각보다 **명령**으로 만든다 — 터미널에서 숨겨 받고, 물음 전에 와 있던 입력을 버리고, 서버와 같은 함수를 부른다(`apps/api/src/db/reset-password.ts`). 셸 조각으로 남겨야 하면 서브셸 `( … )` 하나로 묶고 `&&` 로 잇는다.

## 수를 셀 때는 두 번 세고 표본을 열어 본다 — 덧붙임

- **넷째 함정:** ④ **`\b` 는 도구마다 뜻이 다르다** — `git grep -E` 는 `\b` 를 지원하지 않아 조용히 적게 세고, `git grep -P` 는 한글을 낱말 글자로 봐 `F1이` 에서 경계가 안 서며, 파이썬 `re.ASCII` 와 node(JS) 정규식은 선다(JS 는 `u` 플래그를 줘도 ASCII 경계다). `git grep -E` 는 `\s` 도 지원하지 않아 그 식이 아무 줄에도 안 맞는다(오류 없음).
- `git grep` 이면 공백은 `-P` 나 `[[:space:]]*` 로 흡수한다.
- 단어 경계가 든 식은 `git grep -E` 로 세지 않는다(`-P` 를 쓴다). 두 방법으로 셀 때는 **경계의 뜻을 같게 맞추고**(파이썬이면 유니코드 기본값), 수가 갈리면 갈린 줄을 열어 본다.
- **다섯째 함정:** ⑤ **역할 하나로 센 목록은 다른 역할의 항목을 0 으로 센다** — 행동 메뉴 `sight` 가 `[role="menuitem"]` 만 세어 `menuitemradio` 목록(화면 상태 전환기 · 영역 표지)이 항목 0 · 덮임 0 으로 늘 초록이었다(`apps/web/build-test/action-menu-place.test.ts`). 자가 세는 역할 목록을 쓰는 곳의 역할 전부와 견주고, 목록마다 `items > 0` 카나리아를 둔다.
- **여섯째 함정:** ⑥ **이름으로 가르는 훑기는 이름이 같은 형제를 한 칸으로 센다** — 한 무리의 라디오 · 체크박스는 이름이 같고 글이 없어, 접근 이름을 열쇠로 쓴 훑기가 첫 하나만 누르고 나머지 칸에 안 닿았다(`apps/web/test/viewer-readonly-harness.tsx` 의 `keyOf` — `value` 를 열쇠에 넣는다). 훑기를 새 입력 꼴에 대면 그 꼴의 칸 수를 카나리아로 단언한다.
- **일곱째 함정:** ⑦ **픽스처 노드를 id 접두로 가르지 않는다** — 서버 · 에디터가 짓는 노드 id 도 `n_` 로 시작한다. 구역(`data-wb-zone`)이나 픽스처 id 목록으로 가른다(`apps/web/build-test/popup-layer.test.ts` 의 `focusedInPopup`). 
- **여덟째 함정:** ⑧ **카드 열쇠가 타입이라고 기대는 자는 프리셋 카드(«타입:프리셋 키»)를 빈 카드로 센다** — 축소판 셈(`apps/web/build-test/palette.test.ts` 의 `CARD_THUMBS`)이 카드 키를 `data-wb-component` 와 그대로 견줘 `DataGrid:repeatRows` 의 표본(`DataGrid` 노드)을 못 찾았다. 카드 키(`data-wb-palette-card` · `data-wb-palette-window` · `data-wb-palette-thumb`)를 타입과 견주는 자를 `git grep` 으로 세고 키의 `:` 앞으로 견주게 한다.
- **아홉째 함정:** ⑨ **잴 대상을 그 성질을 만드는 표지(클래스 · 속성)로 고르지 않는다** — 꺾임을 막는 `-nowrap` 조각으로 시각 칸을 고른 줄 셈은 그 클래스를 뗀 조각을 안 센다. 성질과 무관한 표지(그 값 전체를 감싼 상자 `.wb-shell-admin-when`)로 고르고, 표지를 뗀 변조로 한 번 센다(`apps/web/build-test/admin-screens.test.ts` 의 `measure`).
- **문자열 속이나 주석 밖을 셀 때는 줄 머리로 주석을 거르지 말고 파서로 센다** — 템플릿 문자열 안의 CSS 주석(`/* … */`)이 줄 머리 거르개에게는 주석으로 보여 통째로 빠진다(②의 한 꼴).
- **화면 넘침은 요소 상자로만 세지 않는다** — 끊을 자리 없는 낱말은 제 요소 상자 안에 선 채 글자만 넘치고(`overflow-wrap: normal`), `overflow: hidden` 조상은 넘친 글자를 잘라 숨겨 문서 `scrollWidth` 에도 안 뜬다. 글자 노드의 `Range.getClientRects()` 오른끝으로 잰다(`apps/web/build-test/theme-system-review.test.ts` 의 `TEXT_PAST_ROOT`). 넘침을 보일 표본 낱말은 끊을 자리 없는 영문으로 짓고 하이픈을 넣지 않는다 — Chrome 은 띄어 쓰지 않은 한글도 음절 사이에서 꺾어 한글 긴 낱말은 `overflow-wrap` 을 뗀 변조에도 안 넘치고, 하이픈이 있으면 그 뒤에서 줄을 바꿔 넘침이 사라진다(`apps/web/build-test/project-cards.test.ts` 의 `LONG_NAME`). **에디터 밖 화면의 넘침은 문서가 아니라 뼈대 상자(`.wb-shell-workspace`)의 `scrollWidth` 로도 잰다** — 뼈대가 창을 덮는 고정 상자라 안이 넘쳐도 문서는 안 넓어져 문서로 잰 넘침은 늘 0 이다(`apps/web/build-test/workspace-layout.test.ts` 의 `overflow`). **넘침을 일으키는 변조(최소 폭 · 고정 폭을 키움)는 넘칠 양을 그 판의 안쪽 여백보다 크게 짓는다** — 넘친 양이 여백 안에 떨어지면 창 · 뼈대 넘침이 0 이라 자가 아니라 변조가 약해서 산다(좁은 창의 내용 칸 `.wb-shell-workspace-main` 여백은 16px 이라, 카드 격자 최소 칸 260px 을 300px 으로 키운 변조는 창 320 에서 그 안에 떨어져 살았다 — `apps/web/build-test/rv-cd-cards.test.ts`).
- **열을 두는 배치(쌍 격자 · `Grid` · 열을 정한 조회 폼)의 넘침은 좁은 창 문턱 바로 위 폭과 PPTX 캡처 폭(720 — `apps/api/src/services/screen-render-chromium.ts` 의 뷰포트)에서도 잰다** — 문턱 위에서는 열 수가 그대로라 칸이 가장 좁다. 1280 · 390 만 잰 판은 2열 폼 표의 세그먼트가 옆 쌍으로 넘치는 것을 못 봤고, 그 꼴이 PPTX 에 그대로 실렸다(`docs/superpowers/plans/2026-10-25-rv-ft-report.md` M2 · M3).
- **«보이는 구간» 은 스크롤 상자와 창(뷰포트)이 겹친 곳으로 셈하고, 그 장치는 창보다 긴 상자 판과 창이 상자를 다 담는 높은 창 판(1280×1500 · 세로 모니터 1080×1920)을 둘 다 잰다** — 상자만 보면 상자가 창 아래로 뻗은 판에서 팝업이 창 밖(상자 가운데)에 서고, playwright 의 누름이 «… intercepts pointer events» 로 한도까지 돈다. 구름 · 창 크기 바뀜에만 다시 재는 장치는 아무것도 안 구르는 높은 창에서 내용 높이가 바뀌면(같은 iframe 에 다른 문서를 실음) 다시 안 재 낡은 구간에 선다 — 짧은 창 판은 상자가 늘 굴러 다시 재므로 이것을 못 본다(`apps/web/src/canvas/canvas-popups.tsx` 의 `usePopupArea` · `apps/web/build-test/theme-preview.test.ts` «팝업이 보이는 구간에 선다 …» · `apps/web/build-test/rv-pv-preview.test.ts` «H1 …»).

- **기본 뷰의 조각 이름 · 품는 꼴을 바꾸는 트랙은 앞 판 테마 CSS 가 그 조각을 무엇으로 꾸미는지 먼저 센다** — 테마는 조각을 이름으로 꾸며 둔다(`[data-wb-part="node"] { display: flex }`). 그 조각이 새 자식을 품게 바꾸면 고정된 프로젝트에서 새 자식이 그 꾸밈을 받는다. 옛 조각은 옛 뜻 그대로 두고 품는 상자에 새 이름을 준다 — 그러면 테마를 안 올려도 된다(`docs/superpowers/plans/2026-11-03-tr-report.md` 결정 3).- **카탈로그에서 타입을 걷거나 바꾸는 트랙도 앞 판 시스템 테마에 고정된 프로젝트로 내보낸다** — 저장된 manifest 가 걷힌 타입을 선언하면 패키지를 다시 읽는 자리가 패키지째 거절해, 번들 · PPTX 가 테마 없이 나갔다(캔버스는 멀쩡하다). 내보내기 미리보기의 `themeWarning` 이 빈지 본다(`docs/superpowers/plans/2026-10-25-gr2-report.md` «main 시딩 DB» · `readWbtheme` 의 `stored`).
- **뒤에 병합하는 트랙의 `checksums.json` 새 줄은 합친 판에서 다시 짓는다** — 그 트랙이 적은 sha256 은 앞 트랙이 빠진 빌드의 값이다. 합친 뒤 `pnpm build` 의 `.wbtheme` 을 `shasum -a 256` 으로 재어 적고, 배포 안 한 판이면 그 판 이름을 그대로 쓴다(`docs/superpowers/plans/2026-10-24-rb-ci-b-report.md` 「충돌을 푼 파일」). **같은 판 이름을 나눠 쓰는 두 트랙은 앞 트랙을 병합한 뒤 사용자 api 를 다시 띄우면 그 판이 사용자 개발 DB 에 시딩된다** — 뒤 트랙이 합친 판에서 다시 지은 sha256 은 그 행과 달라 api 기동이 `SystemThemeError`(«이미 올린 버전의 내용이 바뀌었습니다»)로 멈춘다. 병합 전 덤프를 뜬 뒤, 그 판을 쓰는 프로젝트가 없는지(`projects.theme_version`) 보고 그 행을 지우고 다시 띄운다(2026-10-27 PO-A · PO-B 의 1.8.0).
- **문서 · 보고에 싣는 셈 명령은 실은 그대로 한 번 돌린다** — `git grep` 의 옵션(`-A` · `-B` · `-c`)은 패턴 앞에 둔다. 패턴 뒤의 옵션은 리비전으로 읽혀 `fatal: unable to resolve revision` 으로 죽는다. 블록을 파일로 뽑아 `zsh <파일>` 로 돌리면 실은 글자 그대로 잰다(`docs/superpowers/plans/2026-10-25-gr-report.md` 「지침」).

- **`git grep` 의 경로 인자에 `*` 를 쓰면 그 글롭이 파일 경로 전체에 맞아야 한다** — `-- 'packages/*/src'` 는 그 아래 파일을 하나도 안 골라 0 건을 오류 없이 낸다. 디렉터리 아래를 고르려면 `'packages/*/src/**'` 나 글롭 없는 `packages` 를 쓴다. 0 이 나오면 글롭 없는 경로로 한 번 더 센다.
- **생성물을 정의와 대조하는 케이스는 손으로 쓴 글 속의 값을 못 잰다** — 손 글에 정의의 상수(패턴 · 한도)를 글자로 옮겨 적지 말고 그 상수를 읽어 싣는다. 리뷰는 그 상수를 바꾸는 변조로 대조 케이스가 죽는지 본다(`apps/web/config/llms-txt.ts` 의 `NODE_ID_PATTERN`).

- **목 · 픽스처 값을 바꾸기 전에 그 값을 단언하는 자리는 글자가 아니라 변조로 센다** — 같은 글자를 여러 목이 들면 글자 셈은 단언을 가까운 목의 몫으로 읽는다. 그 목의 값만 표지 글자(`'ZZ-목-이름'`)로 바꾸고 그 목을 가져오는 파일을 돌려 죽는 케이스 수를 적는다(`docs/superpowers/plans/2026-10-20-fx-th-report.md` L5 M9).
